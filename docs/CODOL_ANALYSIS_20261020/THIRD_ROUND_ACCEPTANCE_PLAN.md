# 第三轮验收方案

日期：2026-10-21（Asia/Shanghai）

本方案把“能启动”“能进入”“能互通”“能对战”“能长期运行”分开验收。任何一个低层通过都不能自动升级成高层通过。

## 1. 验收对象

1. 3.19 目标客户端。
2. 新 C 战斗服务器。
3. Auth/Lobby/booking/端点下发控制面。
4. 目标 FF/Zone/地图资产。
5. CoD4x、IW4X、2697、3.3.3.3 只作为对照实现，不参与目标通过的最终判定。

## 2. 证据状态

| 状态 | 含义 |
|---|---|
| PASS | 有目标版本字节、构建、测试和运行证据 |
| PARTIAL | 有部分实现或历史证据，未覆盖完整链路 |
| CONFLICT | 两源不一致，必须保留双方 |
| FAIL | 已运行且结果不符合预期 |
| UNKNOWN | 未采集、未反汇编或未构建 |
| OUT_OF_SCOPE | 已确认与目标版本无关 |

## 3. 验收门

### A. 构建门

- 源哈希、工具链和依赖固定；
- 产物 SHA-256 记录；
- 无网络下载或未锁依赖；
- 两次构建字节一致或差异原因明确。

### B. 启动门

- 单实例、固定端口、无残留；
- 启动、停止、崩溃恢复和日志可用；
- Auth/Lobby/Battle 进程边界可追踪。

### C. 协议门

- 3.19 目标握手完成；
- gamestate/configstrings 被客户端消费；
- 至少两帧 snapshot 和 ACK 对应；
- reliable command 可重放；
- 未知 opcode 不被 legacy 静默接住。

### D. 世界门

- 目标 FF/Zone 加载；
- CLIPMAP_MP、MAP_ENTS、ComWorld、physics 有版本哈希；
- 出生点、地面、台阶、斜面和阻挡可用于 trace。

### E. 移动门

- usercmd 输入可回放；
- 落体、地面吸附、台阶、贴墙和碰撞通过；
- 穿墙和无落地负例必须失败；
- 服务端与客户端预测差异有界。

### F. 快照门

- baseline、delta、帧历史、丢包恢复均测试；
- ACK 前不提交历史；
- 断线、重连、过期 baseline 有负测试。

### G. 对局门

- 单客户端最小对局闭环；
- 两客户端互相看见、命中、死亡、复活、计分；
- 回合开始、结束、重开和离开路径完整。

### H. 对照门

- 每个参考项目单独列出 D/A/L/W/F 证据等级；
- 低版本参考不得进入 release wire 表；
- 所有跨版本推断标记为参考或候选。

## 4. 关键验收命令与产物

| 测试 | 必须保留 |
|---|---|
| 构建 | 编译器版本、命令、日志、产物哈希 |
| 静态 | 输入哈希、反汇编范围、调用链、脚本版本 |
| 协议 | packet index、重组流、opcode、ACK、consumer trace |
| 世界 | 资产哈希、类型、引用、加载日志 |
| 移动 | 输入回放、trace、位置/速度/地面状态 |
| 快照 | 原始帧、baseline、delta、ACK、重放结果 |
| 对局 | 同 PID、时间戳、双方视角、状态 delta |
| 对照 | 参考来源、证据等级、拒绝原因 |

## 5. 放行结论

- 不允许用“进程启动”“端口监听”“能编码”“离线测试通过”替代对局验收。
- 不允许用 2697/3.3.3.3/1.1.1.13/CoD4x/IW4X 的通过结果替代 3.19 目标结果。
- 缺少外部证据只能将状态标为 UNKNOWN/PARTIAL，不能改成 PASS。
- 只有目标客户端、目标服务端、目标资产和同一 PID 的端到端证据同时成立，才能写“第三轮重构规格闭环”。
