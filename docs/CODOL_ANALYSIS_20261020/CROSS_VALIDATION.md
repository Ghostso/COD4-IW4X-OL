# 三项目交叉验证与全对象血缘分级

日期：2026-10-21（Asia/Shanghai）

状态：第三轮已启动；主线为 3.19 与全部对象的一对多交叉。证据完整度按现有材料封口，缺失项不用于补字节。

目标版本：CODOL 3.19.26.22 / Build 1649370。

## 0. 结构与裁决顺序

本轮不是五套服务器平均比较，而是：

1. 以 3.19 为中心，分别与 2697、3.3.3.3、1.1.1.13、CoD4x 21.2、IW4X 做一对一交叉；
2. 冻结 3.19 的证据边界；
3. 再比较其余对象之间的代码、架构、算法、线协议和资产格式关系。

证据等级固定为：

| 等级 | 判定 |
|---|---|
| D 直接代码派生 | 同文件、同数据结构、可追溯共同源的直接派生 |
| A 架构同构 | 生命周期、状态机、所有权、帧循环结构一致或近似 |
| L 算法同族 | 问题分解和算法结构相近，但不要求同一实现 |
| W 线协议一致 | opcode、framing、字段顺序、位宽、ACK 真的一致 |
| F 资产格式一致 | FF/zone/clipMap/mapEnts/model 等格式真的一致 |
| R 仅命名或数值相似 | 文件名、函数名、地址、常量或概念相似，不足以作为依据 |

任何跨项目结论必须先落到这五轴之一，不能只写“相似”“同源”或“可借鉴”。

1.1.1.13 与 CoD4x 的文件级派生关系已经量化：

## 1.1 血缘分级结论

| 比较对 | 最高可证等级 | 不能升级成什么 |
|---|---|---|
| 1.1.1.13 ↔ CoD4x | D 直接代码派生 | 不能升级成 3.19 直接来源 |
| 2697 ↔ 旧 CODOL 骨架 | D/P 同族移植候选 | 不能升级成 3.19 同构建 |
| 3.19 ↔ 2697 | P 同族前代，W 未闭 | 不能升级成线协议一致 |
| 3.19 ↔ 3.3.3.3 | A/L 同族架构与算法 | 不能升级成代码派生或 wire 一致 |
| 3.19 ↔ 1.1.1.13 | R/历史分支 | 不能升级成目标依据 |
| 3.19 ↔ CoD4x | A/L 引擎骨架和算法 | 不能升级成 CODOL 协议来源 |
| 3.19 ↔ IW4X | A/L 宿主边界和 IW4 结构 | 不能升级成 CODOL 服务端 |
| CoD4x ↔ IW4X | A/L 共享引擎概念 | 当前 src 没有直接代码派生证据 |
| 2697 ↔ 3.3.3.3 | A/L 同族不同版本 | 不能互相替代目标字段 |

分级含义：

- D 只允许用于相同版本或明确 fork 关系；
- A 允许用于模块边界和生命周期；
- L 允许用于算法重写和 fixture；
- W/F 只有在目标字节或目标资产证据存在时才能写成一致；
- R 不产生实现结论。

## 2. 3.19 与全部对象的一对多交叉

### 2.1 3.19 与 CoD4x 21.2

| 轴 | 判定 | 依据 | 可用方式 |
|---|---|---|---|
| D 直接代码派生 | 未发现 | 3.19 是加壳客户端和定制服务端链，CoD4x 是 CoD4 开源服务端 | 禁止按源码等价处理 |
| A 架构同构 | 部分 | 均有初始化、帧循环、客户端槽位、网络会话、snapshot 概念 | 可借骨架和测试结构 |
| L 算法同族 | 部分 | netchan、可靠命令、delta、trace、snapshot 思路可比较 | 借算法，不借常量 |
| W 线协议一致 | 未证明，默认否定 | 3.19 有目标定制的握手、记录层与数据字段；CoD4x 无同版本证据 | 禁止复制 opcode、字段和状态常量 |
| F 资产格式一致 | 未证明 | CoD4x 使用 CoD4 BSP/iwd；3.19 使用目标 FF/Zone 体系 | 只借加载器和校验设计 |

结论：CoD4x 使用价值集中在 **服务器工程骨架、状态所有权、delta 算法和测试方法**，不能作为 3.19 wire codec 的来源。

### 2.2 3.19 与 IW4X

| 轴 | 判定 | 依据 | 可用方式 |
|---|---|---|---|
| D 直接代码派生 | 未发现 | IW4X 是 MW2/IW4X 客户端扩展；其服务器行为依赖外部宿主 | 禁止当作 CODOL 服务端源码 |
| A 架构同构 | 中等 | extension/host 边界、OOB 分流、认证信封、scheduler、server demo 可参考 | 借宿主边界和版本门控 |
| L 算法同族 | 中等 | Huffman、RCon、session、demo、资产编排存在 | 借接口设计，不借宿主地址 |
| W 线协议一致 | 未证明 | MW2/IW4X 的协议和 CODOL 3.19 不是同一版本 | 禁止固定地址、结构体和字节复用 |
| F 资产格式一致 | 未证明 | iw4-open-formats 目标 IW4/WW2 资产，非 CODOL FF/Zone | 只参考 parser 分层 |

结论：IW4X 价值在 **客户端扩展与宿主边界工程学**；它没有独立服务器内核，不能作为 3.19 的服务端协议依据。

### 2.3 3.19 与 2697

| 轴 | 判定 | 依据 | 使用条件 |
|---|---|---|---|
| D 直接代码派生 | 证据等级为同族派生候选 | 2697 原生服务端有 codol_2697_* 写侧模块，客户端虽同族但不是同构建 | 所有字段先做版本差异 |
| A 架构同构 | 高 | 连接、gamestate、configstring、snapshot、reliable command 结构同族 | 可用于重构分层 |
| L 算法同族 | 高 | 旧 wire 与新 2697 writer 共用/派生痕迹可静态观察 | 算法可参考 |
| W 线协议一致 | 部分/未闭合 | 新通道存在旧版没有的 0x06 与可靠命令 0x02；客户端消费链未闭 | 不得直接绑定到 3.19 |
| F 资产格式一致 | 需版本核对 | 2697 脚本与 runtime-assets 属另一发行包 | 逐文件验证后才能使用 |

结论：2697 是第二优先的同族事实源。它可以解释服务端写侧和版本变化，不能替代 3.19 客户端证据。

## 3. 其余对象之间的交叉

### 3.1 CoD4x 与 IW4X

- 当前 src 没有共同文件路径，也没有可证的直接代码派生；
- 两者共享 Quake/CoD 引擎概念，属于架构同构和算法同族；
- CoD4x 是独立服务器实现，IW4X 是宿主扩展；
- 不能因为都实现 netchan 或 RCon 就视为同一协议栈。

### 3.2 2697 与 3.3.3.3

- 同为 CODOL 家族，但版本不同；
- 2697 有原生服务端二进制事实，3.3.3.3 有更完整的工程和源码证据；
- 二者可用于互相解释模块命名和控制面，但必须以版本差异表为前提；
- 任何一方都不能直接覆盖 3.19。

### 3.3 CoD4x 与 1.1.1.13

- README 明示 fork 关系；
- 当前 src 共同路径 896，完全相同 665；
- 结论是直接代码派生历史，但目标版本价值低；
- 只用于理解旧 C 服的 server skeleton。

### 3.4 2697 / 3.3.3.3 与 CoD4x/IW4X

- CODOL 服务端的连接、加密、记录层和业务结构与 CoD4x/IW4X 不同；
- 可参考服务器生命周期、断线恢复、队列和诊断；
- 不能替换 wire、entity、snapshot 和资产格式。
