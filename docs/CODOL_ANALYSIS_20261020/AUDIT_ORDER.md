# 全服务器审计顺序、覆盖模型与边界

日期：2026-10-21（Asia/Shanghai）

## 1. 任务范围

项目不再只审计“穿墙/无落地”这一条故障链。目标是形成可支撑战斗服务器重构的全服务器审计，覆盖源码、反汇编与恢复逻辑、二进制与依赖、资产格式、配置启动、网络协议、生命周期、状态机、游戏规则、测试与运行证据。

一个模块只有同时具备以下三列，才可标记为“可重构依据”：

| 列 | 必须回答 |
|---|---|
| 证据 | 直接读取了什么文件、函数、结构、字节或运行产物 |
| 实现归属 | 完整实现、部分实现、反汇编外壳、声明，或版本不对口 |
| 验证 | 是否构建、是否有测试、是否运行、是否与目标版本匹配 |

## 2. 用户指定的隔离顺序

1. **CODOL 自身全栈审计**：客户端 3.19、各 CODOL 战斗服构建、逆向文件、沙箱和运行证据。
2. **CoD4x 21.2 独立全栈审计**：只使用 CoD4x 自身源码、汇编、构建和文档。
3. **IW4X 独立全栈审计**：只使用 IW4X 自身源码、宿主二进制、依赖、资产和文档。
4. **三项目交叉验证**：前三项均完成后，才比较血缘、复用性和协议差异。

独立审计阶段不得用其他项目的结论补齐空白。所有缺口必须写明“缺什么、为什么缺、如何获取、获取后解除什么”。

## 3. 统一全栈覆盖矩阵

| 编号 | 审计域 | 最低检查内容 |
|---|---|---|

| C | 帧循环与线程 | 帧率、时间残差、线程所有权、定时器、回调 |

| F | 消息与传输 | 序列、ACK、重传、分片、压缩、加密、上限 |
| G | 地图与资产 | zone/fastfile、clipMap、mapEnts、静态模型和资源引用 |
| H | 世界与碰撞 | BSP/clip 树、brush、plane、trace、contents、出生校验 |
| I | 移动与控制 | usercmd、pmove、slidemove、台阶、斜坡、贴墙、地面吸附 |
| J | 实体与状态 | 实体池、链接、客户端/玩家状态、字段布局、增量规则 |
| K | 快照与复制 | 基线、delta、帧历史、可见性、发送节流、丢包恢复 |
| L | 游戏逻辑 | 出生、武器、命中、伤害、死亡、复活、记分、模式和回合 |
| M | 脚本与规则扩展 | GSC/Lua/VM、内置函数、脚本加载、事件与配置 |
| N | 配置与管理面 | cvar/dvar、控制台、RCON、管理命令、下载、权限 |

## 4. CODOL 对象隔离

全栈主文档：[C_SERVER_FULL_STACK_AUDIT.md](./C_SERVER_FULL_STACK_AUDIT.md)。

世界与碰撞专项：[C_SERVER_WORLD_COLLISION_AUDIT.md](./C_SERVER_WORLD_COLLISION_AUDIT.md)；它是证据专章，不是全服务器完成声明。

以下对象必须分别登记身份和版本，禁止混为一个“C 服”：

- 当前可见战斗服工程，包括 C# 工程；
- 用户所述 C 语言战斗服，若位于其他路径则单独登记；
- 1.1.1.13 的 CoD4x fork / 旧源码；
- 3.3.3.3 的 ol-mod 原生服务端参考；
- 2.6.9.7 的 2697 原生服务端二进制；
- 3.19.26.22 客户端及其运行证据；
- 本地全部逆向文件、抓包、日志、反汇编、脚本与实验产物。

每份材料必须判定对 3.19 的适用性：直接、间接、历史参考、无关或无法判断。

## 5. CoD4x 与 IW4X 的实现层

CoD4x 必须分开记录可读 C/C++ 服务器层与反汇编恢复的游玩、物理和游戏逻辑层，不能合并为单一源码完成度。

IW4X 必须分开记录 `iw4x-client` 扩展层、宿主 MW2/IW4 二进制层、依赖子模块与资产层，以及 dedicated 模式的宿主控制链。固定地址声明或未初始化子模块不构成完整审计。

## 6. 交叉验证与完成判据

第三轮交叉验证以 3.19 为唯一裁决轴：先完成 3.19 与全部对象的一对多比较，再比较 2697、3.3.3.3、1.1.1.13、CoD4x、IW4X 之间的剩余关系。独立审计中的缺口保留为证据边界，不再作为禁止启动第三轮的附加条件。比较层级固定为：直接代码派生、架构同构、算法同族、线协议一致、资产格式一致、仅名称或数值相似。

“全服务器审计完成”要求：

- A-S 所有域均有状态，不存在未登记模块；
- 每个实现文件都归入职责域，或注明无关理由；
- 关键调用链从入口追到行为出口；
- 协议、字段与状态表均有目标版本和证据来源；
- 构建、测试、运行验证分别记录；
- 所有空白都有具体获取方法，而不是泛写“待补”；
- 交叉阶段开始前三份独立审计已冻结版本与证据清单。
