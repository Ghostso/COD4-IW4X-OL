# 第三轮版本差异表

日期：2026-10-21（Asia/Shanghai）

本表把 3.19 作为目标轴。2697、3.3.3.3、1.1.1.13 是 CODOL 家族参考；CoD4x 与 IW4X 是外部架构参考。版本不同不自动表示算法不能用，也不表示线协议字段可以复用。

## 1. 版本总表

| 版本 | 世代/角色 | 形态 | 与 3.19 的关系 | 对重构的优先级 |
|---|---|---|---|---|
| 3.19.26.22 / 1649370 | 目标客户端 | 加壳 PE32 客户端与逆向产物 | 目标行为唯一裁决 | 最高 |
| 2.6.9.7 / 2697 | 同族前代原生服务端 | codol_dedrun.exe，无源码 | 直系前代写侧参考 | 同族第一参考 |
| 3.3.3.3 ol-mod | 同族后期 QA/服务端工程 | game_server、backend、localnetworking | 版本不符的同族架构 | 同族第二参考 |
| 1.1.1.13 | 旧 CODOL C 服移植 | CoD4x fork C/C++ | 历史分支 | 历史附录 |
| CoD4x 21.2 | CoD4/IW3 开放服务端 | C/C++ 与 asmsource | 外部工程骨架 | 算法/架构参考 |
| IW4X | MW2/IW4 扩展 | 注入式 DLL + 外部宿主 | 外部 IW4 边界参考 | 边界/算法参考 |

## 2. 3.19 与 2.6.9.7 / 2697

| 维度 | 3.19 | 2697 | 差异与处理 |
|---|---|---|---|
| 客户端身份 | Build 1649370 | 2.6.9.7 关联客户端 | 非同构建 |
| 服务端身份 | 目标 C 服源码/运行尚缺 | codol_dedrun.exe SHA 80816711... | 2697 只能是写侧事实源 |
| 消息通道 | 目标消费链未闭合 | 旧通道 + codol_2697_* 新写侧 | reader/writer 必须成对验证 |
| opcode | 需客户端证据 | 0x00/0x02/0x03/0x06 等新写侧现象 | 不得直接绑定 3.19 |
| gamestate | 消费未闭合 | 有注册门控与发布审计 | 只能作为结构线索 |
| configstring | 无完整映射 | 服务端写路径存在 | 需目标客户端索引验证 |
| snapshot | 目标帧边界未闭合 | writer 与 EOF 现象可观察 | delta 仍需 3.19 对照 |
| 资产 | FF/Zone 目标格式未完成导出 | runtime-assets/scripts 另一发行版本 | 禁止直接混用 |
| 控制面 | 3.19 的 Auth/Lobby/booking 证据分散 | 2697 注册门控与 loopback 工具 | 只参考控制边界 |

结论：2697 可以作为 3.19 的**同族前代行为对照**，但不能作为目标 wire 或资产直接来源。

## 3. 3.19 与 3.3.3.3 ol-mod

| 维度 | 3.19 | 3.3.3.3 | 差异与处理 |
|---|---|---|---|
| 世代 | 目标 3.19 | 3.3.3.3 QA/服务端工程 | 版本不同 |
| 服务端形态 | 需要重构 | game_server + backend + LocalNetworking | 可借模块边界 |
| 状态所有权 | 待完整定义 | 已有较完整分层 | 可借所有权模型 |
| NativePmove | 目标数据/常量缺 | 有原生绑定和双客户端运行记录 | 只能参考调用形态 |
| 快照 | 目标帧边界缺 | 有历史窗口和模式路径 | 不借字段 |
| 控制面 | Lobby/booking 目标链未闭 | 完整工程组织 | 可借进程边界 |
| 资产 | 目标资产未导出 | 目标版本资源不同 | 不直接复用 |

结论：ol-mod 是 3.3.3.3 的同族工程参考，不能当 3.19 实现。

## 4. 3.19 与 1.1.1.13

| 维度 | 3.19 | 1.1.1.13 | 处理 |
|---|---|---|---|
| 血统 | 目标分支 | CoD4x fork 的旧 CODOL 移植 | 历史 |
| 协议 | 目标定制 | 旧版 wire | 禁止直接套用 |
| 服务器骨架 | 可新写 | CoD4x 派生 | 只解释历史 |
| 资产 | 目标 FF/Zone | 旧资源与 BSP/包体系 | 禁止复用 |

结论：1.1.1.13 只保留历史说明，不进入最终重构字段表。

## 5. 3.19 与 CoD4x 21.2 / IW4X

| 维度 | CoD4x 21.2 | IW4X | 对 3.19 的正确用法 |
|---|---|---|---|
| 世代 | CoD4/IW3 | MW2/IW4 | 外部参考 |
| 服务器核心 | 独立服务端 | 宿主扩展 | 只借结构 |
| 网络 | UDP OOB/netchan/RCON | OOB/auth envelope/host netchan | 算法/边界 |
| 快照 | 有 delta/frame history | 宿主快照与 demo sink | 算法参考 |
| 世界 | BSP/clip/trace | 宿主 CM/PM | 不能套目标格式 |
| 状态字段 | CoD4 结构 | IW4/MW2 结构 | 不能套 3.19 |
| 构建 | 有源码，未构建 | 有源码，宿主/子模块未锁 | 不能宣称运行 |

结论：两套项目可以加速第三轮的工程设计和测试，但不能决定 3.19 的任何目标字节。

## 6. 需要保留的版本冲突

1. 1.1.1.13 副本中的 version.c 仍写 21.2，而 README 声明是 CoD4x 的 CODOL 1.1.1.13 fork；不能从版本号推断精确 fork commit。
2. 2697 原生服务端与 3.19 客户端不是同一构建，2697 的 writer 不等于 3.19 reader。
3. 3.3.3.3 代码和资产的版本晚于 3.19，不能假定字段不变。
4. CoD4x 与 IW4X 的 netchan 名称相似不代表线格式一致。
5. 任何以“同族”推导出的字段都必须回标为候选，直到 3.19 证据确认。
