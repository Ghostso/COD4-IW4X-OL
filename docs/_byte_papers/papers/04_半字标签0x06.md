## 1. 结论

```
0x06 <2 字节小端 uint16>
```

值域实测（267 个实例）：

| 值 | 次数 | 出现于 |
|---|---|---|
| 32 | 88 | 10/20 |
| 0 | 88 | 10/20 |
| 700 | 88 | 10/20 |
| 20000 | 3 | 80/203 |

## 2. 报文逐字节

### 2.1 `10/20`（14 字节，88 样本，全部同形）

```
偏移  字节                解释
00    10 00               字符串，空
02    08 00 00 00 00      u32 = 0
07    06 20 00            u16 = 32
0a    06 00 00            u16 = 0
0d    00                  终止
```

**算术校验**：`2 + 5 + 3 + 3 + 1 = 14` ✓

三个 u16 值：32、0、0。实测第二个和第三个恒为 0，
第一个恒为 32。

### 2.2 `80/173`（6 字节，88 样本）

```
00    10 00         空字符串
02    06 bc 02      u16 = 0x02bc = 700
05    00            终止
```

### 2.3 `80/203`（6 字节，3 样本）

```
00    10 00         空字符串
02    06 20 4e      u16 = 0x4e20 = 20000
05    00            终止
```

## 3. 判定过程

### 宽度

最初这一批报文（`10/20`、`80/173`、`80/203`）在语法校验里全部失败，
报错是 `unknown op 06`。

把它们单独拿出来后，发现三者的共同结构：

```
10 00 | 06 XX YY | 00
```

`10 00` 是空字符串，`00` 是终止符。
中间的 `06 XX YY` 正好 3 字节。

若 `06` 是标签、载荷 2 字节，则报文完整；若载荷是别的宽度，
报文中会剩残余字节，而实测剩余为 0。

**宽度 = 2 确立。**

### 字节序

- `06 bc 02` → 按小端 = 0x02bc = 700
- `06 20 4e` → 按小端 = 0x4e20 = 20000

两个值都是"整数且量级合理"（700、20000）。
按大端读则得 0xbc02 = 48130、0x204e = 8270 —— 也是整数，无法区分。

**判据来自 `10/20`**：`06 20 00` → 小端 = 32，大端 = 8192。

语料里这三个 u16 的位置是 `(32, 0, 0)`。
如果按大端读 `(8192, 0, 0)`，则 8192 这个值在同报文的其它地方
没有任何对应；而 32 恰好是**一个常见的轮询/超时周期**。

这不是强证据。真正的强证据来自**同族标签的一致性**：
`0x07`、`0x08`、`0x0a` 都已确认是小端（第 5、6、7 卷），
没有理由认为 `0x06` 会不同字节序。

---

## 4. 分布观察

`10/20` 的三个 u16 分别是 32、0、0。

这个三元组非常像"**某个配置序列**"：
- 第一个：周期或上限（32）
- 第二个：当前值（0）
- 第三个：累计值（0）

`80/173` 的 700 和 `80/203` 的 20000 则各自单独出现，
更像是"某个 ID 或状态码"。

**语义归属留到第 13 卷**。本卷只负责："这是 2 字节，
小端，无符号"。

---

## 5. 与相邻宽度的辨析

| 标签 | 宽度 | 值域样本 |
|---|---|---|
| `0x03` | 1 | 0..3 |
| `0x06` | 2 | 0, 32, 700, 20000 |
| `0x07` | 4（有符号） | 见第 5 卷 |
| `0x08` | 4（无符号） | 见第 6 卷 |

`0x06` 的实测最大值 20000 **超过了 1 字节上限**，
这直接排除"`0x06` 是 `0x03` 的别名"。

同时 20000 远小于 4 字节上限，不排除"`0x06` 也能写 4 字节" ——
但宽度已被 `10/20` 的算术锁死为 2，不会变。

---

## 6. 字节覆盖

| 字节 | 语义 | 证据强度 |
|---|---|---|
| `0x06` | u16 标签 | 强（267 例，三报文算术闭环） |
| 载荷 2 字节小端 | uint16 | 强（宽度），中（字节序靠同族推定） |

**盲区**：

1. **字节序没有直接反证**。目前靠"同族都是小端"推定。
   要拿到直接证据，需要一个"已知业务值"的 u16 来对照，
   例如玩家等级、地图编号。
2. **值 20000 只有 3 个样本**（80/203），且该 task 只出现过 3 次。
3. `0x06` 只出现在 3 个 task 上，覆盖面窄。
   不排除在其它路径上 `0x06` 有不同用法。
