> 对象：`codoMP_client_shipRetail.exe` 的 `.tp3` 只读数据段
> 地址：`0xdb5e80` 起约 1.4KB 的连续 C 字符串表
> 证据：`tools/dump_strtab.py`

**14 个模式，全部在 EXE 里硬编码。**

这解释了两件事：

1. 为什么磁盘上只有 7 种 `ff_init_common_gametype_*.ifs`
   （`zm` / `survival` / `coop` / `zombie_arena` / `dmz` / `hostage` / `asym`）
2. **其它 7 个（`zombie_hunter` / `zhunt_humanoid` / `zhunt_zombie` /
   `zombie_survival` / `zombie_champions` / `td` / `mp` 的其它变体）
   必然复用或从同一分卷派生**

## 3. `.ff` 的三代格式

```
IWffs100        ← 签名版？
IWff0100        ← 磁盘上实际用这个
IWffu100        ← 未签名版？
```

配合：

```
sha256
aes
1.1.4
```

**`aes 1.1.4` 是加密算法 + 版本。**

## 8. 对"改大厅"的意义

### ✅ 可改的（明文）

| 内容 | 位置 | 方式 |
|---|---|---|
| **模式列表** | EXE `0xdb5e80` 段 | 增删字符串条目 |
| **菜单状态文本** | EXE 多处 | 直接改字符串 |
| **分卷命名模板** | EXE | `patch_%s` / `localized_%s` |

### ⚠️ 需解锁的（AES）

| 内容 | 位置 |
|---|---|
| `common_mp.ff`（大厅逻辑） | `ff_init_common_mp_V111.ifs` |
| `common_gametype_*.ff`（模式逻辑） | `ff_init_common_gametype_*.ifs` |
| `ui/default.menu` | 在某个 `.ff` 里 |

---

## 9. ★ 关键推论

**"加模式" 有两种路径：**

**路径 A（无 AES）**：直接在 EXE 的模式表里加一个 `common_gametype_XXX`，
并准备对应的 `.ifs` 分卷。**但分卷内容是 AES 加密的，仍需密钥。**

**路径 B（完全绕开）**：如果某些 UI 元素是**由服务端下发的**
（例如 marketplace catalog、playlist），
那改服务端就能改 UI，**不需要动 `.ff`**。

**路径 B 需要验证**：playlist 是否来自服务端。
