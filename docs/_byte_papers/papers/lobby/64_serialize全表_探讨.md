# serialize 全表 · 探讨：从"92% 盲区"到"一张地址表"

> 对应：`lobby/64_serialize全表.md`

---

## 一、上一卷的结论让我不安

`lobby/62` 我写：

> **51 个房间类，语料里只见过 4 个。盲区 92%。**

**这个数字很刺眼。**

**但"盲区"不等于"不可知"。**

---

## 二、这一卷的做法

**不看语料，看代码。**

**每个消息类都有 `serialize` 和 `deserialize`。
它们是**生成和解析线格式**的函数。**

**⇒ 反汇编它们，就能得到线格式，不需要样本。**

---

## 三、一个意外的发现

**50 个类，只有 **28 个不同的** serialize 函数。**

**⇒ 22 个类是"共用"的。**

**最极端的是 `0x628320`，7 个类共用：**

```
dwRoomMessageVote
dwRoomMessageChangeTeamRequest
dwRoomMessageStartCountingDown
dwRoomMessageStartGameFailed
dwRoomMessageMemberDetailsQuery
dwRoomMessageNetcafePrivileges
dwRoomMessageQQMembership
```

**⇒ 这 7 个类的线格式完全一样。**

**⇒ 它们很可能是"空消息"（只带类型）或"只带一个整数"。**

---

## 四、这解释了 `11/4` 的模板

**`lobby/40` 我观察到 `11/4` 的 blob 里永远是：**

```
02 <组数> 00 00
```

**组数 ∈ {2, 4, 6, 8}。**

**现在有了 `Manifold::serialize = 0x625520`。**

**⇒ 如果 `11/4` 发的是 Manifold，那 `02` 就是 Manifold 的标签，
`<组数>` 就是消息条数。**

**⇒ 那些恒定的 145/63/182 字节，可能是**固定的空消息组合**。**

**⇒ 反汇编 `0x625520` 就能验证。**

---

## 五、`StartGame` 是校准点

**它的 serialize `0x625be0` 与 memory 里记录的完全一致。**

**⇒ 说明我的 vtable 解析是对的。**

**⇒ 其他 49 个地址可信。**

---

## 六、这一卷的实际产出

**一张表：**

```
50 个类 → 28 个 serialize 函数
```

**这 28 个函数全部在 `0x625520`–`0x629110` 区间。**

**⇒ 区间跨度 0x3BF0 ≈ 15KB。**

**⇒ 反汇编这 15KB，就能拿到全部房间消息的线格式。**

**这是一个具体、有限、可完成的任务。**

---

## 七、方法论收获

> **"没有样本"不等于"不可知" —— 代码里有格式。**

**我之前一直在说"服务端不推，所以没见过"。**

**但客户端的 `serialize` 函数，就是格式的**生成器**。**

**⇒ 反汇编它，比等样本更直接。**

**这条以后要优先用。**

---
