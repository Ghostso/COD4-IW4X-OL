## §0 十四条结论

1. ★★★★ **镜像段表是硬边界**：段2 `.tp3` `VSize=0xDBB1CC0`(230MB) / `RawSize=0x62000`(401KB) ⇒ **覆盖 0.2%**。段2 的"磁盘实测值"一律是文件空洞。
2. ★★★ **段0、段1 100% 覆盖** ⇒ 代码/vtable/RTTI/47 项跳转表/字段码名表 **全部可信**；138 的**结构/格式/流程**结论成立。
3. ★★★★★ **房间消息走 op6 或 op7**（同 handler `0xB7B300`），**不是 op5**。op5 才是邀请弹窗。
4. ★★★★★ **投递链完整版**：`0xB838A0` →(op6/7)`0xB7B300` → `[dwLobbyImp+0x4F0]` **vtable slot[6]=`0x7F1060`** → `0x7E7C90`(按 key 匹配) → `rec+0x25B8`=**`0x6371F0`** → 拆双 blob → **`0x637000`** → Manifold → 47 表 `0x634870`。
5. ★★★★★ **`0x6371F0` 收到的不是原始 dwRoom 报文**，是**装两个子 blob 的位流**：blob#1 = 47 表位流报文，blob#2 = 文本载荷（→`0x82E1408`）。
6. ★★★★ **线上包体（op6/7）** = `u64 key + u64 A + char[0x40] + Blob(0x13 u32 len 位流)`，位流内 = `blob#1 + blob#2`。
7. ★★★★★ **五层注册门**（§5）：`dwRoomImp::ctor`→分配槽→`0x7E7EE0`(要求 srpc 状态==2)→`0x7E7FA0`(写 `rec+0x01=1`)→`0x633FE0`(装四个回调)→`0x633DF0`(需一次性标志 + `rec+0x01`)→`0x7E8120`(订阅 opcode 0x13)。**任一层断开 ⇒ 三条派发全部静默跳过。**
8. ★★★ **`rec+0x10/+0x14`（key）的真实写点 = `0x7E7F26/0x7E7F29`**（注册参数），不是磁盘常量。
9. ★★★ **`rec+0x01` 的唯一写点 = `0x7E7FB0 mov byte [ecx+1],1`**，位于 `push 0x7E7FA0` 注册的回调里（`E8 call` 扫不到）。
10. ★★★ **`0x7E7910` 是槽分配器，不是注册器**：`word[rec]=1` ⇒ `+0x00=1,+0x01=0`，五个回调槽清零；`+0x01` 留待回调置 1。
11. ★★ **出站↔入站同构**：5 组写/读函数逐字段镜像；Manifold 两侧都带 64 位归属者 ID。
12. ★★ **线上裸包格式纠偏**：`Blob(0x13) + UInt32(0x08) + u32 len + 位流`；len=8 时呈 `13 08 08 00 00 00`，**第三个 `08` 是长度低字节，不是 channelID**。
13. ★★ **`0x82E1458` 47 项描述符表 0 写点**（四类扫描全 0 命中）；表长 **47** 不是 48。
14. ★★ **`0x45B`(1115) = 服务端错误码**，经 `0xA9AE30` 映射类别 `0x107`；`vt[0x58]` = 房间会话终止广播。

## §2 ★★★★★ 完整投递链（逐指令）

### 2.1 opcode → handler（76 项表 `0xB83744`）

```
op5 (0x05) → 0xB82DDD → call 0xB7B210 → slot[10] (0x7F20C0) → 0x808DC0  【邀请弹窗】
op6 (0x06) → 0xB82E03 → call 0xB7B300 → slot[6]  (0x7F1060) → 0x7E7C90  【房间消息】
op7 (0x07) → 0xB82E03 → 同上
op8/9      → 0xB82E29 → call 0xB7B4B0 → 0x7E7A50   【定向/成员同步】
```

★ **139 初稿把 `0xB7B210` 记成 op6，实际是 op5。** 依据：
```
0xB82DDD (op5) … 0xB82DF7  call 0xB7B210
0xB82E03 (op6) … 0xB82E1D  call 0xB7B300
0xB82E29 (op8,9)… 0xB82E47  call 0xB7B4B0
```
（`op3/op4` → `0xB82D89`，与 76 项表完全对应。）

```asm
0x7E7CD9  cmp byte [esi-0x25B7],0 ; je skip   ; rec+0x01 启用#2 ← ★由回调置 1
```

### 2.5 `0x6371F0`（8 参，`rec+0x25B8` 所指）

```asm
0x63722E  call 0x7E7970              ; 按 key 查回槽（A 若为 0 则用 arg1/arg2）
0x63724B  push edi/esi ; call 0x4F3F60   ; 用 (arg6=ptr, arg7=len) 建位流读取器
0x637280  call 0xB76AF0 → blob#1 (0x800) ; ★★ 47 表报文
0x63728F  [esi+0xC]-[esi+0x10]+[esi+8]==0 → 退出   ; 剩余位检查
0x6372AA  call 0xB76AF0 → blob#2          ; 文本载荷
```

## §5 ★★★★★ 五层注册门（本卷核心新增）

```
【第1层】0x62DEE0  dwRoomImp::ctor
  0x62DEEE  call 0x7E7910                ; 分配 srpc 槽
  0x62DEF3  mov [edi+0x1C], eax          ; room+0x1C = 槽号
  0x62DEF6  mov [eax+0x25C8], edi        ; ★ rec+0x25C8 = room 反指
  0x62DF84  call 0x7E7EE0(arg1, arg2)    ; ★ 真正的注册
  0x62DF8C  test al,al / jne 继续
  0x62DF95  call 0x633FE0                ; 失败 → 释放

【第2层】0x7E7EE0
  0x7E7EEE  call 0x803830        ; srpc 单例；0 ⇒ 失败
  0x7E7EFF  call 0xB7A670        ; ★ 状态；!=2 ⇒ 失败
  0x7E7F0F  call 0xB7A770        ; 会话对象；0 ⇒ 失败
  0x7E7F26  mov [esi+0x10], edx  ; ★★★ rec+0x10 = key.lo （注册参数）
  0x7E7F29  mov [esi+0x14], edi  ; ★★★ rec+0x14 = key.hi
  0x7E7F2C  call 0xB8FAB0        ; 发起订阅，返回 handle
  0x7E7F38  push 0x7E7FA0        ; ★ 成功回调
  0x7E7F5E  call 0x7FAA20        ; 提交

【第3层】0x7E7FA0（回调）
  0x7E7FA9  mov ecx,[eax+0x40]   ; 槽记录
  0x7E7FB0  mov byte [ecx+1], 1  ; ★★★ 此处 rec+0x01 = 1

【第4层】0x633FE0（room ∘→ 回调）
  0x633FEA  sub edx, 0xE374650 ; imul/sar ⇒ 索引
  0x634003  cmp eax,1 / ja 退出  ; 索引 0..1 有效
  0x63400E  mov eax,[ecx+0x25C8] ; room
  0x634012  cmp [eax+0x1C], ecx  ; 必须反指相等
  0x63401C  mov [ecx+0x25B8], 0x6371F0
  0x634026  mov [ecx+0x25BC], 0x6374E0
  0x634030  mov [ecx+0x25C0], 0x637520
  0x63403A  mov [ecx+0x25C4], 0x633D50
  0x634044  call 0x633DF0

【第5层】0x633DF0
  0x633DFE  cmp byte [room+0x284],0 → 一次性
  0x633E12  cmp byte [rec+0x01],0   ; ★ 需第3层已置 1
  0x633E18  push 0x634240
  0x633E1D  call 0x7E8120           ; 订阅 opcode 0x13
```

**⇒ 任一环断开，三条派发函数在第一条指令 `cmp byte [rec],0 / je skip` 处静默跳过。**
**⇒ 这就是"房间按钮无反应但客户端不报错"的完整机制解释。**

## §8 ★★ `0x45B`(1115) = 服务端错误码

```asm
0x633D53  mov eax,[ebp+8]
0x633D56  mov ecx,[eax+0x40]     ; rec
0x633D5A  mov esi,[ecx+0x25C8]   ; room
0x633D63  call 0x927100          ; = mov eax,[ecx+0x38]; ret
0x633D68  cmp eax,0x45B / jne 返回

```
同族 `0x7E81EF` 比的是 `0x44F`(1119)。分类器 `0xA9AE30`：`0x45B`→类别 `0x107`；相邻 `0x44F/0x457/0x45A/0x45C/0x460` 全落缺省。
字符串 `"1114"/"1115"/"1116"` @ `0xDB80C8/D0/D8`，由 `0x4BA43A/6F/A4` 以 `push name; call 0x7709F0` 注册。

## §12 诚实边界

1. **`0x45B` 的业务名未拿到**（已知服务端错误码、类别 `0x107`、串 `"1115"`）。
2. **`rec+0x18/+0x1C/+0x2C` 语义为推断**；第二条记录静态全 0 无法交叉验证。
3. **`0x7E79C0` 的 `[esi+0x25B0]` 读法**：实为 `rec+0x25C0`（esi=0xE374660=rec+0x10）——本卷已按此修正。
4. **`0x6371F0` 的 `[ebp+0x10/+0x14/+0x18]` 三槽语义未逐一追**（已知 `+0x1C`ptr / `+0x20`len）。
5. **`vt[0x58]` 在多数类里的实现未全解**；`InRoomEventHandler` 槽位算出的地址落在 AES-NI 代码里，与该 vtable 布局不符，**未定**。
6. **`0x808DC0` 的 `0x66EEC0/0x66F0C0` 体内格式未解**。
7. **op6/7 的完整消息体（`u64 A + u64 key + char[0x40] + blob`）未经真实流量验证**；本卷仅由 `0xB7B300` 的读取顺序得出。
8. 段2"文件空洞"判断基于 PE 段表；若该 PE 是 dump 产物，段表可能不反映原始布局（但段0/1 的 100% 覆盖与代码自洽，不影响结构结论）。

## §14 方法论

1. ★★★★ **查调用者要分三种边**：`E8 call`、表项（vtable/跳转表）、**`push <addr>`（回调注册）**。第三种是最大盲区。
2. ★★★★ **"磁盘实测值"先做段归属判定**（`VSize >> RawSize` 是机械信号）。
3. ★★★ **opcode↔handler 必须双向查**：`表[op]→handler` 与 `handler→call 目标` 两边对上才算。
4. ★★★ **多层门控要全列**：任一层都能让整条链静默失效；只报最外层会误导修复方向。
5. ★★ **"0 写点"要同时排除"扫描形态"和"扫描区域"两个盲区。**
6. ★★ **回调地址相同 ≠ 通道相同**：要看实参个数与解释方式。
7. ★★ **"空桩"要看两层**：终端回调空 ≠ handler 不读位流。
