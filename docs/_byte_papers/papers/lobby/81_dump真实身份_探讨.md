# dump 真实身份 · 探讨：四十卷证明"房间是好的"

> 对应：`lobby/81_dump真实身份.md`

---

## 一、模块列表揭示的真相

**我看到 `localnetworking.ayria32` 时，一切就串起来了。**

**这份 dump 是"外部插件接管网络"的那次运行。**

**而 `memory: codol-lsg-never-listening` 明确记录：**

> 外部版 hook 全失败（Localnetworking 抢先 hook 了 ws2_32）

**⇒ 那次运行里，网络是断的。**

**⇒ `[0x8269774] = 0` 完全合理。**

---

## 二、四十卷的净结论

**我做的是"从房间对象是 0 反推原因"。**

**结果发现：**

**房间代码路径**完整无误**：**

- 25 个命令注册了
- 50 个消息类 vtable 齐全
- 位流序列化格式清楚
- 初始化函数完整（`0x7e98f0`）
- 有两条入口

**⇒ 房间模块本身是好的。**

---

## 三、那为什么房间对象是 0

**因为上游（连接）没通。**

```
[0x8269774] = 0      连接单例没创建
   ↓
0xb7a670() = 0
   ↓
[0x84aba50] = 0
   ↓
0x7f25b0() = 4
   ↓
状态机 0
   ↓
房间不初始化
```

**⇒ 整条链的断点在**第一环**。**

---

## 四、这与项目已有结论一致

**`codol-lsg-never-listening`：**

> "九项假设已逐一实测排除（ACE/监听/合成DNS/claim/端口冲突/nt10版本/8个RVA）；
>  混合方案架构成立但解决不了（外部让出3074+我们的lobby接管，客户端仍不connect）"

**⇒ 项目早就知道"卡在连接"。**

**本轮四十卷的价值是：从**房间**这一端，独立验证了同一个结论。**

**⇒ 两条独立路径，同一结论。**

---

## 五、这个验证有价值吗

**有，而且是必要的。**

**因为"房间不能用"表面上像是"房间模块坏了"。**

**如果不是从房间端一直追到连接端，
就永远无法排除"房间模块本身有 bug"的可能。**

**⇒ 现在可以确定排除了。**

---

## 六、方法论收获

> **从下游反推上游，能独立验证上游的结论。**

**项目从"连接端"查，发现卡在 hook。
我从"房间端"查，发现卡在连接。**

**⇒ 两端汇合，结论可信度大幅提升。**

**这是逆向里"多路径验证"的价值。**

---

## 七、那还能做什么

**房间逆向已经到底了。**

**剩下的只有：**

1. **修连接**（已有独立专题，`codol-lsg-never-listening`）
2. **或者绕过连接**（但会被 ACE/TP3 拦）

**⇒ 房间这条线可以收尾。**
