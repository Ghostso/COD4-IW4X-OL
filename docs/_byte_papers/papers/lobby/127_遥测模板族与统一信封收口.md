# 127 · 遥测模板族与统一信封收口 —— 54 条模板、唯一信封、UIPage/UIClick 的格式来源

> 项目：使命召唤OL 大厅（build 1649370 / 3.19）
> 前卷：`123`（71/3·71/7 事件词表）、`124`（71/15 解压）、`126`（52 条模板总表）
> 本卷：**把 126 的两个缺口补上** ①模板到底有多少条、怎么被引用 ②`UIPage`/`UIClick` 的格式从哪来
> 证据：`tools/telemetry_census_final.py`、`tools/templ_ref_hunt.py`、`tools/envelope_full_table.py`、`tools/uipage_helper_640fd0.py`、`tools/dis_640fd0.py`

---

## §0 结论（四句）

1. **遥测事件模板真值 = 54 条**（126 的 52 条 + `ClientOfflinePackets` + `ClientOfflineLastPacket`）。
2. **没有 `{名字, 格式}` 注册表**：48/54 条模板串在镜像里**只有 1 个引用点**，是各事件自己的日志函数里的 `push imm32`。**模板是"就地内联"的，不是查表。**
3. **存在一个统一信封** `%s|${TIMESTAMP_PLACEHOLDER}|%u|%llu|%s|${CODOID(%s)}|%s`（`0x9C7044`），**全镜像只有 1 个引用点**（遥测队列冲刷 `0x241107`），且冲刷代码里 `push 0x192ada` = **1649370 = build 号**，直接证实信封第 3 字段就是 build。
4. **`UIPage`/`UIClick` 没有模板的原因找到了**：它们不走"模板 + printf"路径，而是**先把值格式化好，再调 `0x640FD0(事件名, 值)` 入队**。

## §1 54 条模板：一次穷举普查

### 1.1 普查口径

不看"名字后面必须跟 `|%`"，而是：**全镜像所有 NUL 串，形如 `Name|...`、`Name` 匹配 `[A-Z][A-Za-z0-9_]{2,40}`、且冒号后半段含 `%` 或 `${` 或为空**。

| 结果 | 数量 |
|---|---|
| 命中（含重名） | 76 |
| 去重后名字 | 74 |
| **真模板** | **54** |
| 假阳性（3 字母标识符 `TdO|`/`LvO|`/`D_q|`… 集中在 `0x196xxxx`、`0x230Cxxx`、`0x2314xxx`） | 20 |

### 1.2 126 漏掉的两条

```
0x9E1624  ClientOfflinePackets|%s
0x9E163C  ClientOfflineLastPacket|%s
```

★ 它们在 `ClientOffline`(`0x9E1604`) 后面紧挨着，混在 `_CODO_disconnect0/1/2.log`、`_co.tlg`、`_cop.tlg`、`_colp.tlg` 这一堆断线转储文件名里。
**⇒ 126 的 52 条不是全集，本卷把它补成 54。**

### 1.3 三条"只有格式、没有名字"的串（关键）

在 `0x9E1430..0x9E1604` 之间，夹着三条**不带事件名**的格式串：

| 偏移 | 串 | 项数 |
|---|---|---|
| `0x9E1450` | `%s%d|%llu|%llu|%d|%d|…|${ZONEID(%llu)}`（62 项） | 62 |
| `0x9E152C` | `%s|%u|%llu|%llu|${CODOID(%llu)}|%s` | 6 |
| `0x9E1560` | `%s|%u|%llu|%llu|${CODOID(%llu)}|%u|%u|…|${ZONEID(%llu)}`（16 项） | 16 |

- `0x9E1450` 的引用点：**`0x4025B5`，正好在 `ClientOfflineOOB` 的日志函数里**（`ClientOfflineOOB|${TIMESTAMP}|` 在 `0x9E1430`，引用点 `0x4025B0`）。
- ★★ **⇒ 这两条格式串是 `ClientOfflineOOB` 的续接片段**：`"ClientOfflineOOB|${TIMESTAMP}|"` + `"%s%d|%llu|…"` 拼起来才是完整模板。
- **这正是"模板可以由多段相邻字面量拼成"的直接证据**（MSVC 会把长格式串的相邻片段放在 `.rdata` 里，编译器再合并 —— 但这里它们没被合并，各自还是独立串）。

## §2 引用点普查：模板是内联的，不是查表

对 54 条模板串，各取其 `strFile + 0x400000` 的 4 字节 LE 指针，全镜像搜引用：

| 引用数 | 条数 | 例子 |
|---|---|---|
| **1** | 48 | 绝大多数 |
| 4 | 2 | `ChannelSubscriptionFail`（`0x77298` + `0x1A311C3` + `0x764C2D7` + `0x764C2EB`） |
| 12 | 1 | `OnBoarding`（`0x701C5` `0x7030B` `0x7625D` `0x77AB5` `0x1E69C9` `0x23F605` `0x28DCEB` `0x2B8015` `0x33DC81` `0x3DC289` `0x3DC822` `0x3DDE11`） |

**判定：不存在 `{name_ptr, fmt_ptr}` 的静态表。** 若存在，54 条模板的引用点会**成对相邻**（`name` 紧接 `fmt`）。实测引用点分散在 `0x0759CB`..`0x402D80`（**跨约 3.5 MB 代码**），彼此毫无规律。

★★ **⇒ 每条事件都有自己的日志函数，函数里 `push <整条模板串>`。遥测"表"是编译期摊平到调用点的，运行时不存在这张表。**

`OnBoarding` 12 个引用点说明它被多处 UI 路径复用（注册/引导弹窗/奖励领取…）；`ChannelSubscriptionFail` 4 个引用点里 3 个是副本（`0x1A311C3`、`0x764C2D7/2EB` 都在镜像后段，疑似其他模块或打包副本）。

## §3 统一信封 `0x9C7044`

```
%s|${TIMESTAMP_PLACEHOLDER}|%u|%llu|%s|${CODOID(%s)}|%s
 │        │                  │   │     │        │        └ 收尾字段
 │        │                  │   │     │        └ ${CODOID(账号)} 的包装
 │        │                  │   │     └ 第 5 字段(串)
 │        │                  │   └ 第 4 字段(u64)
 │        │                  └ 第 3 字段(u32)
 │        └ 时间占位符(运行时展开)
 └ 事件名
```

### 3.1 只有 1 个引用点

`0x241107`，在**遥测队列冲刷函数**（`0x641050`）里：

```
0x6410E0  mov esi,[0xc911f58]      ; 队列基址
0x6410E6  mov ecx,[esi+8]  push ecx
0x6410F7  call 0xb78b70            ; 取条目字段
0x6410FC  mov ecx,[esi+4]  push ecx
0x641101  push 0x192ada            ; ★ 1649370 = build
0x641107  push 0xdc7044            ; 信封格式
0x641112  push 0x400               ; 缓冲 1024
0x641118  call 0x774900            ; snprintf
0x641144  call 0x2404b0            ; 宏展开(见 128 卷)
```

★★★ **`push 0x192ada` = `push 1649370`** —— 信封第 3 字段（`%u`）是**硬编码的 build 号**。
这与语料完全对上：`UIPage`、`MatchMaking`、`UIFriendList`、`UIKeySetting`、`TimerError` 的第 3 字段**全是 `1649370`**。
⇒ 110 卷「`1649370` = build 号（`71/18` 88 次）」从此有了**代码侧铁证**，不再只是报文侧的统计推断。

### 3.2 走信封的 vs 走自家模板的

- **走信封**：`UIPage`（无模板，见 §4）、以及所有"队列里没带自己模板"的条目。
- **走自家模板**：54 条里有自己函数的那批（它们的函数里也顺带 `push` 了 `${TIMESTAMP_PLACEHOLDER}` 来做第 2 字段）。

**两者不冲突**：信封是"给只有 名字+值 的条目用的兜底格式"，54 条模板是"自带完整字段清单的条目"。

## §4 `UIPage` / `UIClick` 的格式来源 —— 缺口闭合

### 4.1 两个调用点（唯一）

`templ_ref_hunt` 式地找 `UIPage`(`0x9C7090`) / `UIClick`(`0x9C7088`) 的指针引用，各 **1 处**：

| 事件 | 串偏移 | 引用点 | 所在函数 |
|---|---|---|---|
| `UIClick` | `0x9C7088` | `0x2411C0` | `0x641180`（入口 `push ebp`） |
| `UIPage` | `0x9C7090` | `0x24125C` | `0x6411E0` |

两者都 `push <事件名>` 后 `call 0x640FD0`。

### 4.2 值是在调 `0x640FD0` **之前**格式化好的

`UIClick`（`0x641180`）：
```
0x6411A6  push 0xdc707c   ; '%d|%d|%s'      ← ★ 值格式
0x6411AB  call 0x774980   ; sprintf
0x6411B4  lea ecx,[ebp-4]; call 0xb75a50    ; 结果转 string
0x6411C0  push 0xdc7088   ; 'UIClick'
0x6411C5  call 0x640fd0   ; (name, value)
```

`UIPage`（`0x6411E0`）：
```
0x641242  push 0xdb0ca4   ; '%d'            ← ★ 值格式 = 页号
0x641247  call 0x774980
0x641258  lea ecx,[ebp-8]; push ecx
0x64125C  push 0xdc7090   ; 'UIPage'
0x641261  call 0x640fd0
0x641271  inc dword ptr [0x765ea7c]         ; 页计数自增（限流）
```

★★ **⇒ 原因清楚了**：`UIPage`/`UIClick` 的"格式串"在代码里，是 `'%d'`（`0x9C70F8` 附近的 `0xDB0CA4`）和 `'%d|%d|%s'`（`0x9C707C`）。
`126` 卷找不到它们的"事件名+字段清单"模板，是因为**它们根本没有那种模板**——它们只提供一个"值"。

### 4.3 `0x640FD0` 做了什么（结构级）

```
0x640FD3  mov eax,[0x849b88c]
0x640FDB  cmp [eax+0xc],0        ; 日志使能开关，关就返回
0x640FE2  cmp [0xc911f60],0x400  ; ★ 队列上限 1024 条，满就丢弃
0x640FEE  lea ecx,[ebp-0xc]; call 0xb75a40   ; 构造两个 string
0x640FFE  call 0x77ffb0          ; 取 tick
0x6400007 push [ebp+8]  → 0xb75b10  ; string1 = 事件名
0x640016  push [ebp+0xc] → 0xb75ad0  ; string2 = 值
0x64002F  call 0x6571d0          ; (全局 [0xc911f5c], tick) 入队
```

**语义**：`log_event(name, formatted_value)` —— 把"名字 + 已格式化值"压进遥测队列；队列满 1024 条则**静默丢弃**（`0x400` 的上限）。
★ 这与 124 卷「`71/15` 一批能压 652 条事件」完全一致：**一批最多 1024 条，超过就丢**。

## §5 与语料的逐条对账（13 个已触发事件）

规则：**实测项数 = 模板 `%` 指令数 + 1（事件名）**。

| 事件 | 模板项数 | 实测项数 | 判定 |
|---|---|---|---|
| MissingLocalizedString | 7 | 7 | ✅ |
| ClientLoadTime | 17 | 17 | ✅ |
| OnBoarding | 12 | 12 | ✅ |
| CreateRoom | 6 | 6 | ✅ |
| UserSettings | 11 | 11 | ✅ |
| MatchMaking | 11 | 11 | ✅ |
| UIFriendList | 7 | 7 | ✅ |
| MatchMakingJoin | 38 | 38 | ✅ |
| TimerError | 8 | 8 | ✅ |
| ChannelSubscriptionFail | 10 | 10 | ✅ |
| UIKeySetting | 7 | 7 | ✅ |
| **ClientLoadout** | **5** | **18** | ❌ |
| **LoadoutChangeEvent** | **5** | **17** | ❌ |

**11/13 精确命中。**

### 5.1 两条不中的解释

- 两条的模板都是最短款 `Name|%s|%llu|${CODOID(%llu)}|%d`（5 项）。
- 实测样本：
  ```
  ClientLoadout|${TIMESTAMP_OFFSET(-5)}|账号ID|${CODOID(账号ID)}|1|B01|0||0|||||||AddCharacter|1|1649370
  LoadoutChangeEvent|${TIMESTAMP}|账号ID|${CODOID(账号ID)}|1|B01|10001|25035,22142,|10028|25703,|…
  ```
- 前 5 项完全吻合模板；**第 6 项起是"配装明细"。**

★★ 镜像里有一条**续接片段** `0x9B7B88`：
```
|%s|%llu|%llu|${CODOID(%llu)}|%s|%s|%s|%u|%s|%d|%s|%s|%i|%s|%s      （15 项）
```
它紧跟在 `0x9B7B80 '0.0.0.0'` 之后、`0x9B7BC8 'LostDevice'` 之前 —— **不是孤立的**，是同一段 `.rdata` 里的格式片段。

**诚实边界**：5 + 15 − 重叠（`%s|%llu|${CODOID(%llu)}`）不足以精确凑出 18/17，缺口仍差 1~2 项。**本卷只能证明"这两条事件比模板长，且长出来的部分是配装明细"，不能证明它们的完整模板是哪一段。** 记为未闭合。
