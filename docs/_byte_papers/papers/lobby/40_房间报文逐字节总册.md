# 房间报文逐字节总册：`11/2`、`11/4`、`11/13`、`6/5`

> 用户要求：按字节级别全面逆向，每个字节一篇论文。
> 本篇是**房间四类报文的总册**，每个字段都有归属。
> 证据：`_byte_papers/corpus/corpus.json`（6848 条），`tools/room_*.py`

## 1. `11/13` · createRoom 请求 · **1 字节**

```
00
```

**样本：66 条，全部同形。**

| 偏移 | 字节 | 含义 |
|---|---|---|
| 0x00 | `00` | 终止符（空负载） |

**结论：`11/13` 是一个"无参数"请求 —— 客户端建房间时什么也不带。**

**所有房间参数都不在这里，而在 `11/4` 里。**

## 2. `11/2` · 房间查询 · **10 字节**

## 3. `11/4` · setRoomData · **37–267 字节**

**样本：261 条，130 种 blob 形态。**

### 3.1 外层结构（永远相同）

| 外偏移 | 标签 | 内容 |
|---|---|---|
| 0x00 | `0a` | u64 = **房间 ID** |
| 0x09 | `13` | blob 头 |
| 0x0a | `08` | 长度类型 |
| 0x0b–0x0e | u32 | blob 长度 N |
| 0x0f– | — | **blob 内容（N 字节）** |
| 0x0f+N | `08` | u32 |
| 0x10+N–0x13+N | `01 00 00 00` | 恒为 **1** |
| 0x14+N | `00` | 终止符 |

**房间 ID 的两种取值**：

| 值 | 出现次数 |
|---|---|
| `0x1122334455667788`（哨兵） | 约 90% |
| `0x6B4C2D0E` | 约 10% |

### 3.2 内层结构（blob）

**blob 首 4 字节 = 内容长度 N−4。**

**第 5 字节 = `0x02`（固定标签）**
**第 6 字节 = `g`（组数）∈ {2, 4, 6, 8}**
**第 7–8 字节 = `00 00`（固定）**

**⇒ 内层是"分组表"，`g` 是字段组数。**

### 3.3 ★ 逐字节恒定度（同长度样本）

| hdr | 样本数 | 同长度样本 | **恒定字节** | **变化字节** |
|---|---|---|---|---|
| `02 02` | 112 | 47（len=20） | 18 / 20 | **2（偏移 13、14）** |
| `02 04` | 56 | 16（len=145） | **145 / 145** | **0** |
| `02 06` | 17 | 15（len=63） | **63 / 63** | **0** |
| `02 08` | 10 | 6（len=182） | **182 / 182** | **0** |

**⇒ 同一房间 ID 下，blob 内容几乎完全固定。
只有 `02 02` 形态有 2 个字节变化。**

### 3.4 `02 02` 形态的完整字节表（20 字节）

```
+000  10 00 00 00     内容长度 = 16
+004  02 02 00 00     标签 02，组数 2，保留 00 00
+008  00 18 00 00
+012  00 d0 10 00     ← 偏移 13、14 在此附近变化
+016  00 00 00 00
```

**变化字节 13、14 的取值（实测）：**

| 值 | 含义（推测） |
|---|---|
| `d0 00` / `d0 10` | 0x00D0 / 0x10D0 |
| `a8 08` | 0x08A8 |

**这些数值量级在 0x0000–0x2000，像"配置索引/计时器"。**

## 4. `6/5` · ReadQueuedMessages · **13 字节**

**样本：160 条，**全部完全同形**。**

| 偏移 | 字节 | 解释 |
|---|---|---|
| 0x00 | `08` | u32 标签 |
| 0x01–0x04 | `00 00 00 00` | **offset = 0** |
| 0x05 | `08` | u32 标签 |
| 0x06–0x09 | `14 00 00 00` | **maxResults = 20** |
| 0x0a | `01` | bool 标签 |
| 0x0b | `01` | **consume = true** |
| 0x0c | `00` | 终止符 |

**这是"读排队消息"的经典参数三元组：
`(offset=0, maxResults=20, consume=true)`。**

**⇒ 客户端在轮询房间事件队列，每次取 20 条，取完即消费。**

## 5. 四类报文的关系

```
11/13  建房间（空请求）
   ↓ 服务端回 roomId + secondId
11/2   按 roomId 查询房间
11/4   设置房间数据（roomId + 分组表 blob）
6/5    轮询房间事件（offset/maxResults/consume）
6/14   matchmaking 命令（mmbook / mmstart / mmban）
```

**`6/5` 是"拉"，`11/4` 是"推"的载体（服务端回显）。**
