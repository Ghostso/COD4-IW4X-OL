## 三、★ 未知 1 的答案：那个 `WriteBits(8)` **不写任何业务位**

`0xB77B10` 的完整实现：

```asm
0xB77B10  push ebp / mov ebp,esp
0xB77B13  cmp byte ptr [ecx+0x21], 0     ; ★ 调试/统计标志
0xB77B17  je  0xB77B28                   ; → 为 0 时**直接返回，不写**
0xB77B19  mov eax, [ebp+8]               ; n
0xB77B1C  push 0
0xB77B1E  push 0x1F                      ; 位宽上限
0xB77B20  push 0                         ; ★ 值 = 0
0xB77B22  push eax                       ; n
0xB77B23  call 0xB77A70                  ; Core(cur, 0, 0x1F, 0, n)
```

而 `0xB77A70` 一进去：

```asm
0xB77A73  cmp byte ptr [ebp+0x14], 0     ; ★ 第 4 参 = 0
0xB77A82  je  0xB77AC3                   ; → 恒跳过跟踪分支
```

**⇒ `WriteBits(8)` 的实际效果：**

| 条件 | 行为 |
|---|---|
| `[ecx+0x21] == 0`（正常） | **什么都不写** |
| `[ecx+0x21] != 0`（调试） | 写 **8 个 0 位**（值=0） |

**⇒ 67 卷的「未知 1：8 位字段标签是什么」答案是：它不是字段标签，是一个「强制 8 位零填充」。**

**⇒ 「`StartGame` 用 `0x13`」那处是**另一个函数**（`0x625BE0` 系列），不是 Manifold。
`0x13` 是 `13` = 十进制 19 = **P2PInfo 类型号**，属于 `dwRoomMessageP2PInfo` 的 type，不是"字段类型码"。**

## 四、★ 未知 2 的答案：位流容器格式

**`dwRoomMessageManifold` 的完整位流：**

```
[3 位]  type & 0x7                (tag 高位)
[8 位]  type                       (完整类型号)
[8 位]  0x00                       ★ 零填充（调试模式下才真的写）
[32 位] count                      (链表条数)
-------------------------------------
每条:
  [1 位] 1                          (存在位)
  [1 位] 0xFF 或 0x00               (值存在/不存在)
  ... 后续字段由具体消息类补充
```

**位宽合计（count=0 时）= 3 + 8 + 8 + 32 = 51 位 = 7 字节（含填充）。**

**⇒ 这正是 67 卷说的「7 字节头」的来历。**

## 五、`6/5` 应答应该长什么样（服务端可直接实现）

**`6/5` = `InstantMessageService` 的"取排队消息"：**
```
请求: (offset=0, maxResults=20, consume=true)
应答: 位流，装着 N 条 dwRoomMessage（用 Manifold 包）
```

**⇒ 正确应答 = `Manifold 头(51位) + N × 每条位流`。**

**⇒ 当前服务端回空 TLV ACK ⇒ 客户端解不出 ⇒ 认为队列为空。**

**修法（服务端）：**
```python
# 6/5 应答应该是 Manifold 位流，不是 TLV ack
# 结构（本卷定案）：
#   WriteBits(3, type&7) + WriteBits(8, type) + WriteBits(8, 0) + WriteBits(32, count)
#   for each msg: WriteBits(1,1) + WriteBits(1,0xFF) + <msg 自有字段>
```

## 八、方法论

1. **★★★ 「需要样本」往往只是「没把 serialize 逐指令读完」。** `6/5` 悬了近百卷，本卷 20 分钟读完 `0x625520` 的 20 条指令就定案了。
2. **★★ `WriteBits(n)` 这种"只传位数不传值"的调用，要立刻怀疑它是"零填充/占位"。** 实测：`0xB77B10` 在正常路径下**什么都不写**。
3. **★★ 「不同消息用不同字段码」这种判断，要先确认那个字段是不是同一个函数的相邻指令。** `0x13` 属于另一个类。
4. **★ 位数要自己加。** `3+8+8+32 = 51 位 = 7 字节` —— 与 67 卷观察到的"7 字节头"对上，反向验证了结构。
