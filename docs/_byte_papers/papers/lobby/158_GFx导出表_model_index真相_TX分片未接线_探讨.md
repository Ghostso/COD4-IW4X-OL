## 二、`model_index`：我追了三层才追对

### 第一层（错的）：以为要填对参数

我最初想：「`model_index` 恒 0，那把它填成实体的 model 索引就好了。」

**这假设了 `model_index` 会被发出去。**

### 第二层：查发送路径

反查 `bw_write_entities`：

```c
case 0: put_u8(w, (uint8_t)(e->type & 0xFF));   // 只写 eType
case 1: bw_entity_origin(w, e->x, ...);         // x
case 2: bw_entity_origin(w, e->y, ...);         // y
default:bw_entity_origin(w, e->z, ...);         // z
```

**`model_index` 根本没有 case。** 它不在任何发送分支里。

### 第三层：查协议本身

反查实体字段表（63 个字段的 offset）：

```
4(eType), 8, 12, 16, 20, 24/28/32(origin), 36, 40, ... 268
```

**63 个字段里没有 model。**

⇒ **`entityState_s` 结构本身就没有「模型」这个概念。**

### 那模型从哪来

CODOL/IW4 的做法是：`entityState_t.number` 是一个**索引**，指向 `configstring[CS_MODELS + number]`，那里存模型名。

**所以：**

> **要显示实体，必须下发 configstring，而不是改 `model_index`。**

我差一点就去「把 model_index 改成对的索引」了。那样改完，**编译通过、日志显示 model_index=12、客户端依然什么都看不见**——因为那个值从不被序列化。

### 教训

> **★ 改一个值之前，先确认那个值有没有被判据读取。**
> 判据：它出现在哪条 `put_u8/write_*` 里？没有 ⇒ 改它等于改注释。

## 三、TX「512 天花板」：我把实现限制当成了协议限制

记忆里写着：

> TX 天花板：快照缓冲只有 512 字节。零售快照 7000~15000 字节。⇒ 最多约 10 个实体，要装必须先扩整条 TX 路径 + 分片（独立大工程）。

**「独立大工程」这四个字骗了我一年。**

真相：

```c
// battle.c:189
wr16(out + 14, (uint16_t)len);     // ← 帧长度字段是 u16，最大 65535
```

**协议支持 64 KB。**

```c
// netchan.c:32
if (length >= CODOL_NETCHAN_FRAGMENT_SIZE) {
    chan->unsent_fragments = 1;
    memcpy(chan->unsent_buffer, data, length);
    codol_netchan_transmit_next_fragment(...);   // ← 自动分片
```

**分片器早就写好了，带 `FRAGMENT_BIT`、`unsent_fragment_start`、`fragment_length`，接收侧也有重组（`CODOL_FAT_MAX_FRAGMENTS`）。**

只是：

```
grep codol_netchan_transmit  →  只有定义，0 个调用
```

而实际发送是 `svc->send(ctx, peer, frame, n)` —— **直接 socket 单发，绕过 netchan。**

### 教训

> **★ 记忆里的「独立大工程」要复核。** 写那句话时我可能只是「看到 512 就下结论」，没去 grep 有没有现成分片。
> 结果一个已经写好的能力，被我标成「大工程」搁置了一年。

这也是一条元教训：**「XX 是独立大工程」这种判断，比「XX 是多少字节」更需要证据。**

## 四、GFx 那 3579 个类：我一直在找一个不存在的东西

157 卷我写：

> 「GFx 33,496 符号 ↔ C++ 829 对象映射：未做（这是 UI 层最后一块，量大）」

我以为存在一个「符号 → 对象」的对照表，只是我没做出来。

**本卷看清了：没有这张表，也不需要有。**

- **Flash 侧** `codo.base:BaseMain` = AS3 **类**
- **C++ 侧** `AS_SetReadyState` = C++ 注册给 Flash 的**原生函数**

两者通过：

```asm
0x830B00(global, "flash.utils.getDefinitionByName")   // 运行时字符串反射
```

耦合。**静态上它们就是两个字符串集合，各自独立。**

978 个 Flash 短名里，被 C++ 调用的只是 133/136 卷那 62 个回调覆盖的那一小撮；剩下 900+ 是纯 Flash 内部类（布局、动画、数据模型），C++ 从不引用。

### 教训

> **★ 「量大」不等于「未解」。** 我因为「3579 个类」这个数量而不敢碰，于是把它标成「未做」。
> 实际只需要问一句「这两边有没有静态映射关系」，答案是「没有」，问题就消失了。

**数量大往往是「不需要做」的信号，不是「任务重」的信号。**

## 七、方法论（本卷新增五条）

1. **★★ 改一个值之前，先确认那个值有没有被判据读取。** 不在任何 `write_*` 里的字段，改了等于改注释。
2. **★ 「结构里没有」要用字段表反证**：把 63 个 offset 全列出来，比「我没找到」硬。
3. **★ 「独立大工程」这种判断需要证据。** 先 grep 有没有现成实现（本卷 `netchan` 有完整分片）。
4. **★ 「量大」往往是「不需要做」的信号。** 3579 个类之所以难，是因为我假设了映射存在。
5. **★★ 同一失败模式出现三次 ⇒ 项目级诊断。** 「写好了没接线」×3 ⇒ 瓶颈在接线。
