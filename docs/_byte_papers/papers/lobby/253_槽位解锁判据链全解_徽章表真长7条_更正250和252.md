## §0 结论

**本轮把「槽位解锁」这条链从"某张表"推到了完整判据链，并更正 250、252 各一处。**

1. **★★★★★ 表项格式完全定案**（`0x810B20`）：
   表项 = `{+0: key(A), +4: 存在标志, +5: 初始化标志, +8: 编码值(B)}`，**步进 12**；
   编码 `B = rol8(item) ^ A ^ [0xE4DD90]`。
   ★ `[0xE4DD90]` 是**运行时值**（本镜像 = `0x74BDDE03`），不是编译期常量。
2. **★★★★★ `0x80A5E0(item) → bool` = 「该项是否在已拥有表 `0x8269FC8` 里」**（线性扫，步进 12）。
3. **★★★★★ 槽位解锁的最终判据 = `0x5E3550(item)`**：
   `item == onboardCharacterID` **或** `OwnedContains(item)`。
4. **★★★★★ 答案（本轮目标）**：**已拥有表的装配代码从不读徽章表** ——
   全库只有 **4 张表**被 `lea reg,[reg*4+base]` 索引式访问，徽章表（4 个点）与已拥有表（18 个写入点）
   **地址区间零重叠**。⇒ 60220/60221 进不了 `0x8269FC8`，**不是"被某个条件滤掉"，而是这张表根本不参与**。
5. **★★★★ 更正 250**：徽章表 `0x8269B18` 真长 **7 条**（`0x8269B18..0x8269B60`），
   `0x8269B6C` 起是**另一张被独立引用的表**（`0x80A6C7 lea esi,[edi+0x8269B6C]`）。
   250 的「27 项 / 22 有效 / 20 已解锁」是**跨表越读**。
6. **★★★★ 更正 252 的手工读法**：`0x5E37F8 mov word [edi+4],bx` 里的 `edi` 是**调用者的出参记录指针**，
   不是黑名单数组 —— 那是"物品不可用"分支在**填结果记录**。`[0xC9113CC]` 的**名字（强制不可用表）保留**，
   但"写 0 到黑名单"这个机制描述作废。
7. **★★★ 252 的开项 #3「`0x826A550`（22 项）语义」闭合**：它是 **84 条**（7 组 × 12）的表 `0x826A548`，
   由 `0x5E3580` 扫描。

## §1 ★★★★★ 表项格式：`0x810B20` 全函数

```asm
0x810B20  push ebp / mov ebp,esp
0x810B24  push edi
0x810B25  mov  edi, eax                 ; ★ 参数: eax = item
0x810B27  test edi,edi / jle 0x810B7B   ; item <= 0 ⇒ 直接返回，不写
0x810B2B  cmp  byte [esi+5],0           ; ★ [+5] = 初始化标志
0x810B2F  je   0x810B36
0x810B31  cmp  dword [esi],0 / jne      ; 已有 key ⇒ 跳过惰性构造
0x810B36  lea ecx,[ebp-4] / call 0xB73FC0
0x810B3E  cmp  dword [esi],0 / jne 0x810B51
0x810B43  lea ecx,[ebp-4] / call 0xB73F40   ; ★ 惰性取 key
0x810B4B  mov  [esi],eax / test eax,eax / je 0x810B43
0x810B51  lea ecx,[ebp-4] / mov byte [esi+5],1
0x810B58  call 0x8435D0                  ; ★★ 空桩（哨兵桩 C3）——本行无副作用
0x810B5D  mov  eax,edi
0x810B5F  shl  eax,0x18
0x810B62  sar  edi,8
0x810B65  or   eax,edi                   ; ★ rol8(item) 的手写展开
0x810B67  xor  eax, dword [esi]          ; ★ ^ key([+0])
0x810B6A  xor  eax, dword [0xE4DD90]     ; ★ ^ 运行时种子
0x810B70  mov  byte [esi+4],1            ; ★ [+4] = 存在标志
0x810B74  mov  dword [esi+8],eax         ; ★ [+8] = 编码值
0x810B7A  ret
```

**⇒ 表项 `{+0: key, +4: 存在, +5: 已初始化, +8: 值}`，步进 12；`item = rol8⁻¹(值 ^ key ^ 种子)`。**

★★ 注意 `0x810B58 call 0x8435D0` 是**空桩**（`0x8435D0` = `C3`），此行无任何副作用 —— 这正是"写好了没接线"的又一例。

## §2 ★★★★★ 已拥有表与「已拥有」判据

### 2.1 `0x80A5E0(item) → bool`

```asm
0x80A5E8  mov  esi, [0x84ABB4C]     ; ★ 计数
0x80A5FB  mov  ecx, 0x8269FD0       ; ★ 首条记录的 [+8] 处 ⇒ 记录基址 0x8269FC8
0x80A600  cmp  byte [ecx-4],0 / je next     ; [+4] 存在标志
0x80A606  mov  eax,[ecx-8]                  ; [+0] key
0x80A609  xor  eax, edi                     ; edi = 种子
0x80A60B  xor  eax,[ecx]                    ; [+8]
0x80A60D  rol  eax,8
0x80A610  cmp  eax, ebx / je found          ; ebx = 参数 item
0x80A618  inc edx / add ecx,0xC / cmp edx,esi / jl
   found → al=1 ; 未命中 → al=0
```

**⇒ `0x80A5E0` = `OwnedTableContains(item)`。**

### 2.2 已拥有表 `0x8269FC8`（`count = [0x84ABB4C] = 32`，32 条全部 `+4=1, +5=1`）

```
21037 10049 60004 60049 60038 10015 20424 21176 10042 60214 60076 60080
60083 20257 20008 30059 30060 30061 10106 20380
```

★ **60220 / 60221 不在其中**（用条数 32 定界，不再跨读）。

### 2.3 谁在装配它

大初始化函数 `0x80A630..0x80BCxx`（**一个连续函数体、多返回点**，中间无 `CC CC` 填充），
含 18 处 `lea esi,[esi*4+0x8269FC8]` + `call 0x810B20`，源表**逐张写死**：

```
0x8269B6C 0x8269F80 0x8269AB8 0x8269BA8 0x8269BB4 0x8269BC0 0x8269EC0
0x8269ED8 0x8269AF4 0x8269B00 0x8269B0C 0x8269CC8 0x8269CD4 0x8269CE0
0x8269CEC 0x8269CF8 0x8269D04 0x8269D10
```

写入模式（`0x80B573`）：
```asm
0x80B596  cmp byte [ebx+0x8269B70],0 / je skip    ; 源表 +4 存在标志
0x80B59F  mov edi,[ebx+0x8269B6C] / xor edi,[ebx+0x8269B74] / xor edi,[0xE4DD90] / rol edi,8
0x80B5B4  test edi,edi / je skip
0x80B5B8  cmp esi,0x64 / jge skip                 ; ★ 上限 100
0x80B5BD  push edi / call 0x80A5E0                ; ★ 去重：已在表里就跳过
0x80B5CA  lea esi,[esi+esi*2] / lea esi,[esi*4+0x8269FC8]
0x80B5D4  mov eax,edi / call 0x810B20
0x80B5E1  inc [0x84ABB4C]
```

**⇒ 已拥有表 = 从 18 张"源表"逐项解码 → 去重（`0x80A5E0`）→ 追加。上限 100，实得 32。**

## §3 ★★★★★ 槽位解锁判据 = `0x5E3550`

```asm
0x5E3550  push ecx
0x5E3551  push 0 / push 0xDC3B84 / call 0x512120   ; 0xDC3B84 = "onboardCharacterID"
0x5E3560  cmp esi,eax / jne 0x5E3568
0x5E3564  mov al,1 / ret                           ; ★ item == onboardCharacterID ⇒ true
0x5E3568  test esi,esi / jle 0x5E357C              ; item <= 0 ⇒ false
0x5E356C  push esi / call 0x80A5E0                 ; ★★ OwnedContains(item)
0x5E3578  test al,al / jne 0x5E3564                ; 命中 ⇒ true
0x5E357C  xor al,al / ret                          ; 否则 false
```

**⇒ 「该槽位解锁」⟺ 「槽位所需的 item 已拥有」** —— **最终落到 `0x8269FC8` 这一张表上。**

### 3.1 物品可用性解析 `0x5E3760(edi=出参记录, esi=item)`

```asm
0x5E3774  cmp ecx,[0xC9113D4] / jbe next          ; ecx = 计数
0x5E3778  mov edx,[0xC9113CC]                     ; ★ 强制不可用 item 数组
0x5E3780  cmp esi,[edx+eax*4] / je 0x5E37F6       ; 命中 ⇒ 不可用分支
0x5E37B7  call 0x5E3550                           ; 已拥有?
0x5E37BC  test al,al / jne 0x5E37CD               ;  ⇒ 可用分支
0x5E37C1  call 0x5E3580                           ; 第二张表 0x826A548
0x5E37C9  test al,al / je 0x5E37F6                ; 未命中 ⇒ 不可用分支

可用分支 0x5E37CD: mov word [edi+4],1 ; [edi+0x28]=-1 ; [edi+8]=-1 ; [edi+0x10]=-1
不可用分支 0x5E37F6: mov word [edi+4],bx   (bx=0)
```

★★★ **`edi` 是调用者传进来的出参记录指针**（函数从头到尾未给 `edi` 赋值）⇒
`0x5E37F8` 是**在填一条 0x30 字节的结果记录**，**不是往全局黑名单数组里写 0**。

### 3.2 `0x5E3580` 与它的表 `0x826A548`（84 条）

```asm
0x5E35AE  call 0x4A9F60                            ; map 查询
0x5E35C0  mov esi, 0x826A550
内层: edx 0..11 循环，ecx += 0xC：cmp byte [ecx-4],0 / mov eax,[ecx-8] ^ [ecx] ^ [0xE4DD90] / rol 8
0x5E35E2  test eax,eax / jle next                  ; ★ 值必须 > 0
0x5E35E4  cmp ebx,eax / je 0x5E3608                ; ⇒ 返回 1
外层: esi += 0x90 ；cmp esi,0x826A940 / jl
```
**⇒ 表基址 `0x826A548`，7 组 × 12 = **84 条**，同一 `{key,标志,值}` 步进 12 格式。**
（252 卷开项「`0x826A550`（22 项）语义未定」⇒ **闭合：84 条，由 `0x5E3580` 扫描**。）

## §4 ★★★★★ 为什么 60220/60221 不在已拥有表（本轮目标）

全库扫 `lea reg,[reg*4+base]`（SIB scale=4、base=disp32）且 disp32 落在表区 —— **只有 4 张表**：

| 表 | 引用数 | 引用点 |
|---|---|---|
| `0x8269B18`（徽章表） | 4 | `0x50CB8D` `0x7D74EF` `0x7D7577` `0x80BD2B` |
| `0x8269C60`（8 条连号 60178..60185） | 3 | `0x7D2C73` `0x7DCE76` `0x80BD5B` |
| `0x8269D40`（7 条：28096 11755 12669 22971 26110 26149 26469） | 1 | `0x80B450` |
| `0x8269FC8`（已拥有表） | **18（全为写点）** | `0x80B5CD`…`0x80BB8C` |

**⇒ 徽章表的 4 个引用点全在 `0x50CBxx`/`0x7D74xx`/`0x7D75xx`/`0x80BD2B`；**
**已拥有表的 18 个写点全在 `0x80B5xx..0x80BBxx`。两组地址区间零重叠。**

★★★ **这不是"被某个条件滤掉"，而是「已拥有表的装配路径根本不读徽章表」。**
徽章表只被"按索引取该槽需要哪个 item"的 4 个访问器读（`WL_GetMarketItemIdForBadgeIndex` 族），
而"是否拥有"由 `0x5E3550 → 0x80A5E0 → 0x8269FC8` 判定。两张表各管一半，**永不交汇**。

## §5 ★★★★ 更正 250：徽章表真长 7 条

`0x8269B18` 逐条（步进 12）：

| idx | +4 | +5 | item | 说明 |
|---|---|---|---|---|
| 0 | 0 | 0 | — | 全零（槽 0 = 无徽章） |
| 1 | **1** | 1 | **60220** | `badge_unlock_1` |
| 2 | **1** | 1 | **60221** | `badge_unlock_2` |
| 3..6 | 0 | 0 | — | 无映射（`badge_unlock_3..6` 空） |

填充循环：
```asm
0x80B2C9  mov edi,1                    ; 索引从 1 起
0x80B2CE  mov esi,0x8269B24            ; idx1
0x80B2D4  push 0xDE6F4C                ; "badge_unlock_%d"
0x80B316  cmp esi,0x8269B6C / jl       ; ★ 到 idx6 停
```
`0x8269B18 + 7*12 = 0x8269B6C` —— 恰好是**下一张表**的基址（`0x80A6C7 lea esi,[edi+0x8269b6c]` 独立引用）。

**⇒ 250 的「27 项、22 有效、20 已解锁」是跨表越读。** 之所以"标志域界定表尾"失效，
是因为**下一张表是同一格式、同样的 0/1 标志域** —— 与 250 卷自己的方法论「分桶宽度须小于结构尺度」正好撞上。
本卷用**"下一张表的基址"**这个**硬边界**取代标志域启发式。

★ 反向验证：唯一的 `badge_unlock_%d` 调用序列只有一段，且索引由 `mov edi,1` 起步 ⇒ 槽位号域就是 1..6。

## §8 方法论

1. **★★★★★ 「下一张表的基址」是比"标志域"更硬的边界。** 250 卷用"标志只能是 0/1"界定表尾，
   遇到**同格式的下一张表**就失效了。本卷改用**代码里独立引用的基址**做硬边界。
2. **★★★★★ 「两张表元素重合」不等于"来源相同"。** 要看**代码区间是否重叠**：
   徽章表 4 个读点、已拥有表 18 个写点，地址区间零重叠 ⇒ **机械上不可能有搬运关系**。
3. **★★★★ 寄存器参数必须追到函数入口。** 252 读 `0x5E37F8 mov [edi+4],bx` 时假定 `edi` 指向全局数组；
   真相反：**`0x5E3760` 全函数从不给 `edi` 赋值 ⇒ 它是出参指针**。**判"写全局"之前先确认寄存器从哪来。**
4. **★★★ `call 0x8435D0` 出现在热路径上却无副作用** —— 空桩会被"看起来在主流程里"骗过去。
5. **★★★ 本轮净收益 = 把"为什么少了两个 item"从"某条件滤掉"改写为"两条链永不交汇"**，
   后者才是可落地的服务端修法（直接授予 60220/60221）。
