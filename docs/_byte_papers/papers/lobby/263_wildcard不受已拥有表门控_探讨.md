# 263 · 探讨：判据要连同"它管哪些调用点"一起交付

> 配套：`263_wildcard不受已拥有表门控_两链交集为空.md`

---

## 一、这一卷做的是一个"减法"

253 卷给出一条很干净的判据：

```
「该槽位解锁」⟺「所需 item 已拥有」
        ↓
0x5E3550(item) → 0x80A5E0(item) → 表 0x8269FC8
```

它甚至给了"修法"：让服务端直接授予 60220/60221。

259 卷接着发现 wildcard 表（`0x8269C60`）的 item `60178..60185` **也不在** `0x8269FC8`，
于是留下一个担心：

> "若 wildcard 槽位也走 `0x5E3550→0x80A5E0→0x8269FC8` 判据，
> 则由「wildcard 不可用」的另一类现场症状应能复现。"

**这个担心的形式是"若 P 则 Q"。本卷回答的是 P 的真假。**

P = "wildcard 槽位也走这条判据"。答案：**P 为假**。
因为这条判据的**入口函数是 `0x5E3760`**，而 wildcard 的消费链
（5 个函数）**一个都不在 `0x5E3760` 的 54 个调用者里**。

## 二、为什么"交集为空"比"我没看到它调用"强

弱版本是：**我在 wildcard 的消费者里没看到 `call 0x5E3760`。**
—— 这可以被三种情况解释：
1. 它真的不调用；
2. 它**间接**调用（经过某个 wrapper）；
3. 我的窗口/正则漏了。

强版本（本卷）是：
```
A = {调用 0x5E3760 的函数}        （54 个，全列出）
B = {调用 wildcard 访问器的函数}  （5 个，全列出）
A ∩ B = ∅
```
**B 里的每个函数都读完了整个函数体**（`a51_reach.py` 扫到函数尾），
确认它们不直接调用 `0x5E3760`；而 A 是被**全库 `E8` 索引**枚举的。

于是三种解释都被排掉：
1. 真的不调用（B 全读完）；
3. 不漏（B 只有 5 个，肉眼可数）；
2. 剩下的"间接"由 §3 的角度处理：**判据的入口是 `0x5E3760` 本身，
   只要 B 不进入这个入口，就谈不上"走这条判据"** ——
   间接链即使存在，也要先碰 `0x5E3760` 才算进入，而 B 不碰。

**"交集为空"把"我没看到"升级成了"结构上不可能"。**

## 三、真正可迁移的教训：判据的覆盖范围是它入口的调用点集合

253 交付的是**判据的公式**：

```
解锁(item) = item==onboardCharacterID || OwnedContains(item)
```

但它没交付的是**这个公式管哪些地方**。

一个公式 `f(x)` 写在函数 `0x5E3550` 里，**它只对"调用 `0x5E3550` 的地方"成立**。
而 `0x5E3550` 的**唯一**调用者是 `0x5E3760`，`0x5E3760` 有 54 个调用者 ——
**这 54 个就是这条判据的完整作用域。**

**wildcard 不在其中 ⇒ 判据不适用于它。**

这引出一条通用要求：

> **交付一条判据时，必须同时交付"它的入口函数"和"入口的调用点集合（作用域）"。
> 只给公式的判据，会在下一次遇到"另一个槽类型"时被错误外推。**

这与 235 卷「`reply+5` 极性是服务私有的，不要外推」是**同一条法则的两种形态**：
- 235：**一个字节的语义**是服务私有的；
- 263：**一条判据的适用域**是入口调用点私有的。

**两者都在说："你以为通用的东西，其实有作用域。"**

## 四、本卷自查

| 断言 | 怎么验的 |
|---|---|
| 交集 ∅ | `a53` 列 A(54) / B(5) 并求交 |
| B 的 5 个函数不进 `0x5E3760` | `a51` 扫完整函数体 |
| `0x80A450` = currentCharacterIndex | 内嵌 cvar 字符串 `0xDCAB98` |
| `0x5E4340` 14 类分派 | 跳表 `0x5E4768` 14 项逐项读出 |

## 五、还没验的（不许写成结论）

- **wildcard 是否另有一条"解锁/等级"门**：本卷只否证了 `0x5E3550/0x8269FC8` 这条路径。
  `WL_GetPick10LoadoutCount` 之类是否给 wildcard 计数/门槛，**未查**。
  **"不通过 A 路径"≠"没有任何门"。**
- `0x5E4340` 的 14 个类别**只知编号**，业务名（主武器/副武器/装具/…）未定。
- `0x80A450` 的 `[0x849B62C]` 兜底分支（当缓存为 -1 时）未展开。
