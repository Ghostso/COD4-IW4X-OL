# 228 探讨 · 一个模板顶一百次 grep

## 一、这轮的思路转换

本来我想"找开局按钮的 AS 回调"，直觉是去搜 AS 注册表（135/136 卷那条链）。

但那条链很绕：AS3 类名 → `getDefinitionByName` 反射 → C++ 对象 → vtable。

**换个做法**：先看一个**已知的回调**怎么写的。

`AS_SetReadyState` = `0x7CF850`（147 卷记录）。反汇编它：

```asm
mov edx, [ebp+8]
mov edx, [edx+0x10]
mov ecx, [0x82E13FC]      ; ← dwRoomImp 单例
movzx edx, byte [edx+0x10]
mov eax, [ecx]
mov eax, [eax + 0x84]     ; ← vt[33]
push edx
call eax
```

**5 条指令，一个模板。**

## 二、模板一旦拿到，枚举就是一次扫描

`[0x82E13FC]` 是模板的**唯一识别标志**（dwRoomImp 单例）。

扫它 → **302 处**。

这 302 处就是**"Flash 能触发的全部 dwRoomImp 方法"**。

★ 比追 AS 注册表快得多，而且**不会漏**：只要走这个模板，就一定会读 `[0x82E13FC]`。

## 三、顺手验证了一条旧结论

154 卷说 `vt[33]` = `0x6301A0` = SendReady。

`0x84 / 4 = 33` ✓，且 `0x7CF865` 读的正是 `[eax+0x84]`，取到 `0x6301A0` ✓。

**旧结论被独立复现了一次。**

## 四、对"开局"的意义

302 处里**没有一处**读 `[eax+0x13C]`（`0x632680`）。

这**独立佐证了 227 卷**：`0x632680` 是 booking 超时，不是 AS 能触发的动作。

⇒ **开局按钮走的肯定是别的槽**（在 `0x7CF8xx~0x7CFFxx` 那一片里）。

## 五、还没做完的

我列出了 302 处的**函数 → slot**，但**没有把每个 slot 的 AS 名字对上**。

要完成需要：

2. 每个 slot 的 vtable 函数与本卷的 vtable 表对齐
3. 结合 AS 注册链（135/136 卷）给每个 slot 配名字

★ 这是**下一轮**的活。

## 六、方法论

**★★★★★ 遇到"要从一大片代码里找某类函数"时，先反汇编一个已知样本，提炼出模板，再用模板的唯一标志扫全库。**

这比"按名字 grep / 按类名扫"都可靠 —— 因为模板是**结构性**的，不受命名影响。

★ 本轮如果按"搜 'StartGame' 字符串"或"搜 AS 名字"去找开局回调，很可能一个都找不到（AS 名字在 Flash 侧，C++ 侧只有槽号）。
