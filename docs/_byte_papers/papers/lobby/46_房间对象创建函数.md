## 3. `0xc3e9f5` 的真实身份

```asm
0xc3e9f5  mov edi,edi / push ebp / mov ebp,esp / sub esp,0x10
0xc3e9fd  jmp 0xc3ea0c
0xc3e9ff  push [ebp+8] / call 0xc4b5b4 / pop ecx
0xc3ea08  test eax,eax / je 0xc3ea1b
0xc3ea0c  push [ebp+8] / call 0xc3d280 / pop ecx
0xc3ea15  test eax,eax / je 0xc3e9ff
```

**两个被调函数：**

- `0xc3d280`：检查 `cmp ebx, -0x20; ja ...`，另有 `[0x19697c8]` 分支
- `0xc4b5b4`：`push [0x1969df8] / call [0xca82f0] / call eax`

**`0xc4b5b4` 的形态是"TLS/线程局部存储访问器"：
先取索引，再从表里取回调，再调用。**

**⇒ `0xc3e9f5` 是 CRT 的 `__CxxFrameHandler` / `_getptd` 一类，
不是业务逻辑的资源查找。**

---

## 4. 所以 `0x3a128` 不是资源 ID

**如果 `0xc3e9f5` 是 CRT 函数，那 `0x3a128` 就是它内部用的常量/掩码，
不是"资源索引"。**

**⇒ 创建房间对象实际上是无条件的（只要走到 `0x639d00`）。**

**⇒ 真正的关键变成：`0x639d00` 这个函数**什么时候被调用**。**
