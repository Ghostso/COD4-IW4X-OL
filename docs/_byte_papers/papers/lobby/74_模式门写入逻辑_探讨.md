## 一、这一卷看见了一个微妙的模式

```asm
mov eax, [0xe59d20]     ; 读旧值
sub eax, 3
je  → 写 4（大厅）
sub eax, 2              ; 再减 2，即总共 -5
jne → 不动
     写 6（游戏）
```

**它用**旧值**决定新值：**

```
旧 3 → 新 4
旧 5 → 新 6
```

**⇒ 这是一个"状态跃迁表"，只是用算术写的。**

**⇒ 而 3 和 5 都是"中间态"。**

---

## 二、这揭示了什么

**要进大厅（4），必须先到过 3。**

**要进游戏（6），必须先到过 5。**

**⇒ `[0xe59d20]` 的值域不是一个简单的枚举，
而是一条**单调递增的路径**：**

```
0 → … → 3 → 4     （大厅）
0 → … → 5 → 6     （游戏）
```

**⇒ 3 和 5 是"即将进入某界面"的预备态。**

---

## 三、实测停在 0

**⇒ 连第一个中间态都没到。**

**⇒ 这解释了为什么所有下游都是 0。**

---

## 四、与"6 秒必崩"的对照

**`memory: codol-iips-must-be-enabled` 说：**

> `enable_iips=0` ⇒ 6 秒必崩

**现在能推测：**

**"6 秒"是某个超时。如果在这 6 秒内 `[0xe59d20]` 到不了 3/4，
就崩溃。**

**⇒ 这与"状态停在 0"完全一致。**

**⇒ 这已经不是"房间的问题"，是"启动的问题"。**

**⇒ 从子系统问题上升到全局问题。**

## 六、十二层链的意义

**我现在有一条完整的、可验证的链：**

```
[0xe59d20] = 0
  → ...
  → [0x82e13fc] = 0
```

**中间 10 层，每层都有地址和判据。**

**⇒ 只要 `[0xe59d20]` 能到 4，整条链就会自动跑通。**

**⇒ 这是"一个变量决定一切"的实证。**

**⇒ `[0xe59d20]` 是合适的终点。**
