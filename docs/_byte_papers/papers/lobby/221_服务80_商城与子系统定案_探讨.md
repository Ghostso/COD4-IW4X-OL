# 服务 80 (Marketplace) · 探讨：常量是免费的符号，但也最容易骗人

> 对应：`lobby/221_服务80_商城与子系统定案.md`

---

## 一、这一卷最爽的一步：用常量把语料钉到代码

**语料里 `80/173` = `10 00 06 bc 02 00`（u16 700），`80/203` = `10 00 06 20 4e 00`（u16 20000）。**

**我不知道 700 / 20000 是什么。但我知道——客户端一定得把这两个数**放到指令里**才能发出去。**

**我直接搜字节：**

```
68 bc 02 00 00   (push 0x2bc = 700)   → 0x4A27BE, 0x4A29DC, 0x4A2AF0, 0x4A2C27
68 20 4e 00 00   (push 0x4e20 = 20000) → 0x4A9015, 0x4A9115
```

**⇒ 商城构造点全在 `0x4A2xxx`–`0x4A9xxx`。**

**这是「没有符号表也能定位代码」的标准打法：值→字面量→地址。**

---

## 二、差点骗到我的一次：把「通道号」当成「服务号」

**看到 `0x4A29A0` 结尾：**

```
push 0x6b   (107)
call 0x7FAA20
```

**我第一反应：`0x6b` = 107 = 服务 80 的 task 107！命名都对上了。**

**差点就这么写：「构造器直接把 task 号 107 传给发送器」。**

**但我去读了 `0x7FAA20 → 0x7FA800`：**

```
0x7FA83B  mov ecx,[ebp+8]                 ; = 传入的 0x6b
0x7FA83E  mov eax,[ecx*8 + 0xE4E20C]      ; ★ 拿去查表！
0x7FA848  add eax,0xE69CE0
```

**⇒ `0x6b` 是**表索引**，不是 task 号。**

**我又把所有观察到的立即数一起查表：**

```
0x5a→class4  0x5d→class3  0x6a→class3  0x6b→class4  0x85→class0
```

**class → {发超时, 收超时, 重发间隔, 重试}。这是一个**重试策略表**。**

**⇒ 「107」纯属巧合：一个**通道索引**恰好等于一个 task 号。**

**★ 教训（和 154 卷同源）：看到「立即数 == 某已知编号」时，**先查它被谁消费**。若它进了一张配置表，它就是索引，不是身份。**

## 三、另一个反直觉：「enable=0」却在发请求

**服务表 `0xE4E8F8` 里 `marketplace` 的 enable = **0**。**

**按直觉：没启用 ⇒ 不发请求。**

**但语料里 80 是全语料**第一大**服务（776 条）。**

**⇒ enable 位是「DW 服务状态上报开关」，不是「协议开关」。**

**★ 教训：一个布尔位的语义，由**读它的代码**定义，不由字段名定义。**

---

## 四、这一卷的高光：跨服务同型

**`80/154`（商城，58B）和 `93/131`（钱包，58B）：**

```
80/154: 10 00 | 08 01 | 08 ad 70 00 00 | …   (28845)
93/131: 10 00 | 08 01 | 08 4a 59 00 00 | …   (22858)
```

**逐字段同型，只差第 3 个 u32。**

**⇒ 商城与钱包**共用一套结构**。一个样本解两条服务。**

**★ 方法论：拿到新服务时，**先做「结构指纹」比对**（长度 + 标签序列），常能发现它是某已知结构的变体。**

---

## 五、我没解开的

- 哪个构造函数对应哪个 task 号：构造器和 task 号之间隔一层**回调**（`push 0x4A2A50` 之类），task 号不在常量面 ⇒ 写「静态不可达」。
- 700 / 20000 / `"1625160"` 的**名字**：值都定位到了，但没有「值→名」表。
- `80/119` 的时间戳：单调递增、秒级、2027 年——**语义是时间戳**够强，但**用途**没定位。

---

## 六、方法论价值

> **① 「常量落点」是静态 RE 的免费符号——值→字面量→地址。**
> **② 立即数 == 已知编号 ≠ 立即数是那个编号；查它的消费者。**
> **③ 布尔位的语义由读它的代码定义（`enable=0` 仍发请求）。**
> **④ 新服务先做结构指纹比对，常有「同型跨服务」红利。**
