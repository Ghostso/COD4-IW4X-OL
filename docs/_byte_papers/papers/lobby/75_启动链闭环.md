# ★★★★★ 启动链闭环：`0x6212c0` 是起点

> **这是大厅启动链真正的第一环**
> 承接 `lobby/74`，闭合整个环路

---

## 1. 模式门的写入（`0x62176b`–`0x621779`）

```asm
0x62176b  xor edx, edx
0x62176d  cmp byte ptr [ebp+8], dl   ; 参数（bool）
0x621770  mov ecx, esi
0x621772  setne dl                   ; dl = (param != 0)
0x621775  lea edx, [edx + edx + 3]   ; ★ edx = 2*bool + 3
0x621779  mov [0xe59d20], edx        ; ★ 写入模式
```

**⇒ 这个函数只会写 **3** 或 **5**。**

| 参数 | edx | 含义 |
|---|---|---|
| `false` | **3** | 准备进大厅 |
| `true` | **5** | 准备进游戏 |

**⇒ 这就是 `lobby/74` 里"旧值 3/5"的来源。**

---

## 2. ★ 唯一调用者：`0x7e9913`

**`0x6212c0`（函数起点）只有 2 个调用者：**

| 调用点 | 上下文 |
|---|---|
| `0x621ac6` | 自身模块内 |
| **`0x7e9913`** | **★ 大厅启动初始化** |

**`0x7e9913` 正是 `lobby/47` 里记录的：**

```asm
0x7e98f9  call 0x7e84a0
0x7e9907  push 1
0x7e9909  call 0xb76d80
0x7e9911  push 1
0x7e9913  call 0x6212c0      ; ★★★ 这里！
0x7e991b  call 0x7fa4c0
0x7e9920  call 0x7ef830
0x7e9925  mov byte [0xe374650], 0
0x7e992c  mov byte [0xe376c20], 0
0x7e9933  call 0x639d00      ; 创建房间对象
```

**⇒ `push 1` ⇒ 参数 = true ⇒ `[0xe59d20] = 5`（准备进游戏）**

**⇒ 在同一个初始化函数里，
后面紧接着创建房间对象。**

---

## 3. ★★ 完整环路

```
0x7e98f0（大厅初始化，被 0x808658 调用）
  ├─ 0x7e84a0
  ├─ 0xb76d80（若 [0xe85c28]==0）
  ├─ 0x6212c0(1)  → [0xe59d20] = 5      ★ 模式 = 5
  ├─ 0x7fa4c0
  ├─ 0x7ef830
  ├─ 清两个标志
  ├─ 0x639d00    → [0x82e13fc] 房间对象  ★ 直接创建！
  ├─ 0x4a1f60
  ├─ 0x642620
  └─ 0x4ab840
```

**⇒ 注意：房间对象在 `0x7e9933` 直接创建，
不依赖 `[0x849ba30] == 3`！**

---

## 4. 与 `lobby/51` 的矛盾

**`lobby/51` 说：**

```
0x808261  cmp [0x849ba30], 3
0x808268  jne 0x80852c           ; 跳过
```

**而 `0x808261` 在 `0x808240` 里，
`0x808240` 调用 `0x808650` → `0x7e98f0`。**

**⇒ 如果 `[0x849ba30] != 3`，`0x7e98f0` 就不会被调用。**

**⇒ 那 `0x6212c0` 也不会被调用。**

**⇒ 但 `0x6212c0` 是设置 `[0xe59d20]` 的唯一路径。**

---

## 5. ★★★ 这是一个循环依赖

```
[0x849ba30] == 3           ← 要求
        ↓ 才调用
0x7e98f0
        ↓ 其中
0x6212c0 → [0xe59d20] = 5
        ↓ 然后
[0xe59d20] ∈ {4,6} 才满足
        ↓ 但
[0xe59d20] = 5 不满足 {4,6}！
```

**⇒ 自相矛盾？！**

## 7. 更可能的解释

**`0x7e98f0` 有两个入口：**

- `0x808650`（在 `0x808240` 的 `[0x849ba30]==3` 分支里）
- **另一个（在 `0x80852c` 分支里）**

**⇒ `lobby/47` 说"唯一调用者 `0x808658`"，
但 `0x808658` 在 `0x808650` 内，
而 `0x808650` 可能被多处调用。**

**⇒ 需要重新查 `0x808650` 的调用者。**

## 8. 这一卷的净收获

**确定：**

1. **`0x6212c0(bool)` → 写 `[0xe59d20] = 3 或 5`**
2. **唯一业务调用者是 `0x7e9913`（大厅初始化）**
3. **传入参数是 `1` → 写 5**
4. **`0x7e9933` 紧随其后创建房间对象**

**⇒ 房间对象的创建**不依赖**`[0x849ba30]==3`，
而是在初始化函数里**直接**做。**

**⇒ `lobby/51` 的"三级闸门"可能是**另一个**子系统的门。**
