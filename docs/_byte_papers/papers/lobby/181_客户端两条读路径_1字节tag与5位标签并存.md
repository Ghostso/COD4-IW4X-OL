# 181 · 客户端有**两条**读路径 —— 信封层与 Manifold 层用的是不同标签宽度

> 卷次：181（房间类 · 消除"两套模型冲突"的误判）
> 结论：**`0x13` 在两条路径里宽度不同（1 字节 vs 5 位），但各自都自洽。`build_room_push` 没错。**

---

## §0 结论

| 路径 | 入口 | 标签宽度 | 谁用 |
|---|---|---|---|
| **A. Manifold 字段** | `0xB774E0` `R_TAG` | **5 位**，值 = clamp(n,0,31) | `6/5` 应答、`dwRoomMessage*` 序列化 |
| **B. blob 分帧** | `0xB76310` | **1 字节**，值 = 子类型 | `0x13` blob 内层（138/139 卷链） |

★★ **两者不是矛盾，是两层。**
`build_room_push` 走 B（`Buf(True)` 写 1 字节 tag）—— **正确**。
`build_manifold` 走 A（5 位标签）—— **也正确**。

---

## §1 B 路径的证据

### 1.1 `0xB76310` 第一条业务指令

```asm
0xB76324  cmp byte ptr [esi+0x18], 0     ; 有效性
0xB76331  mov edi, [esi+0x10]
0xB76334  push 1                          ; ★★★ 读 1 个字节
0xB76336  lea eax, [ebp-0x55]
0xB76339  push eax
0xB7633E  call 0xB75E80                   ; 读 N 字节
0xB7634D  movzx ecx, byte ptr [ebp-0x55]  ; ★ 读到的 1 字节 = 标签
0xB76354  cmp ecx, 0x16                   ; 与 0x16 比较
0xB76357  jne 0xB76430                    ; ≠0x16 走普通路径
```

★★ **`push 1` = 读 1 字节，不是 5 位。**

### 1.2 `0xB75E80` = 读 N 字节原语

```asm
0xB75E80  ...
0xB75E8A  add eax, [esi+8]     ; 缓冲基址
0xB75E8D  mov ecx, [esi+0x10]  ; 当前位置
0xB75E91  mov edi, [ebp+0xc]   ; ★ n 字节数
0xB75E94  sub eax, ecx         ; 剩余
0xB75E98  cmp edi, eax / ja    ; n > 剩余 → 失败
0xB75EA9  call 0xB783C0        ; 拷贝
```

**按字节操作，与位流无关。**

### 1.3 `buf(True)` 的标签常量与 B 路径吻合

```python
T_BOOL, T_U8, T_U16, T_I32 = 0x01, 0x03, 0x06, 0x07
T_U32, T_I64, T_U64        = 0x08, 0x09, 0x0A
T_STRING, T_BLOB, T_ARRAY  = 0x10, 0x13, 0x6C
```

| Buf 写 | 客户端 B 路径 | 一致 |
|---|---|---|
| `u32(8)` → `08 <4B>` | `0xB76310` 读到 `0x08` | ✅ |
| `u64(x)` → `0A <8B>` | 读到 `0x0A` | ✅ |
| `string` → `10 <len><bytes>` | 读到 `0x10` | ✅ |
| `blob(p)` → `13 <u32 len><p>` | 读到 `0x13` → `0xB76AF0` 处理 | ✅ |

### 1.4 A 路径（177/178 卷）回顾

```asm
0x625520  push 3  / call 0xB77B10    ; 5 位标签
0x6256C0  push 3  / call 0xB774E0    ; 读 5 位标签
```

## §2 为什么之前会觉得"冲突"

178 卷我推断出 `0x13 = 19` 是"5 位字段标签"。
而 `Buf` 里 `T_BLOB = 0x13` 是"1 字节类型标签"。

**同一个数值 0x13，两种宽度** —— 看起来矛盾。

真相：**`0x13` 在 A 路径里是"blob 字段的标签值（写在 5 位里）"，
在 B 路径里是"blob 块的类型字节（占 1 字节）"。**

两者都指向"这是一个 blob"，只是编码层不同。

★ 这是**语义相同、编码不同**，不是矛盾。

---

## §3 两个层次在协议里的位置

```
6/5 应答
  └─ Manifold 位流（A 路径，5 位标签）
       ├─ W_TAG(3) + type + W_TAG(8) + count
       └─ 每条 item：W_TAG(19) + W_TAG(8) + len + payload

房间信道推送（build_room_push）
  └─ ByteBuffer（B 路径，1 字节标签）
       ├─ u32(8)      → 08 xx xx xx xx
       ├─ u64(sender) → 0A ...
       ├─ string      → 10 ...
       ├─ u64(room)   → 0A ...
       ├─ blob(payload) → 13 <len> <payload 位流>   ← ★ 里面再嵌 Manifold
       └─ u32(0)      → 08 00000000
```

★★ **payload 里面嵌的就是 Manifold 位流。所以两层是嵌套关系。**

`build_room_push(…, build_startgame_payload(...))`：
```
B 层信封（1 字节 tag）
  └─ blob → 内含 A 层位流（5 位标签）的 StartGame 消息
```

## §4 结论与影响

| 组件 | 状态 |
|---|---|
| `build_manifold`（A 层） | ✅ 5 位标签 + LSB-first（177/178） |
| `BitWriter`（A 层写器） | ✅ 已移除伪头（180） |
| `build_room_push`（B 层信封） | ✅ 1 字节 tag，与 `0xB76310` 一致 |
| `Buf` 标签常量 | ✅ 与 B 路径逐项吻合 |

**B 层无需修改。**

---

## §5 诚实边界

1. **B 层只核了"标签宽度和分派"，没核每个 tag 的负载格式**（如 `string` 的长度前缀是 u32 还是变长）。
2. **没有真实样本**验证 B 层字节。
3. **`u32(0)` 结尾那个字段**（`ob.u32(0)`）在客户端 B 路径里对应哪一步，未定。
4. `0xB76310` 只处理 `0x16` 特殊分支（`cmp ecx,0x16`），**其余 tag 走 `0xB76430` 普通路径，未展开**。

---

## §6 方法论

1. **★★★ 同一个数值在不同层可以有不同宽度。** `0x13` 既是 5 位标签值（A）也是 1 字节类型（B）。看到"矛盾"先问"是不是两层"。
2. **★★★ 找入口要找到"第一条业务读取"，看它是 `push 1` 还是 `push 5`。** 这一条件就能区分两条路径。
3. **★★ 嵌套结构要标清层次。** B 层的 blob 负载里嵌 A 层位流——不标层次就会把两套编码混为一谈。
