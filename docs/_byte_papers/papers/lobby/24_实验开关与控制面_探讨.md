## 三、`.bak_dummy` 是什么

``` 
configs_s.info.bak_dummy    311 字节
market_ui.info.bak_dummy     16 字节
tlogconfig.info.bak_dummy    92 字节
```

**"dummy" = 占位。**

**做法可能是**：把一个文件替换成垃圾，跑一遍，看大厅还能不能进。

如果能进 → 这个文件不重要 → 保留 dummy 记录。

**所以 dummy 的大小，就是"当时试出来的最小可接受大小"。**

- `market_ui` 只需 16 字节 ← 几乎不读
- `whitelist` 30 字节
- `tlog` 92 字节
- `configs_s` 311 字节

## 五、方法论收获

> **"没有"也是证据。有残留的地方说明碰过；完全没有痕迹的地方说明没碰过。**

我看的是"有哪些文件"，但真正有用的是"哪些地方**没有**文件"。

- 有 `playlists` 的 7 个备份 → 这块碰得很深
- 有 `market_ui` 的 dummy → 这块验证过

**这个推理能立刻告诉我"下一步从哪开始不会重复劳动"。**
