# 204 · `0x7659F88` 槽数组不是房间类 —— 是 HTTPS/证书层（`"bw"` / `PEMacart.pem` / `CODOL/1.0`）

> 卷次：204（房间类 · 排除性结论，避免误入）
> 方法：`0x4F48D0` 里 `push 0xDC9C9C` → 读该地址 = ASCII `"bw"`
> 结论：`0x7659F88` 槽数组属于 **HTTPS/证书栈**，与房间类无关。

---

## §0 决定性证据

### 0.1 `0xDC9C9C` 附近的 ASCII

```
0xDC9C8C: 0x00455255  "URE\0"      → 拼成 "...SURE"
0xDC9C90: 0x00622B77  "w+b\0"
0xDC9C94: 0x00622B72  "r+b\0"
0xDC9C98: 0x00007472  "rt\0"
0xDC9C9C: 0x00006277  ★ "bw\0"     ← 0x4F48D0 push 的就是这个
0xDC9CA0: 0x004D4550  "PEM\0"
0xDC9CA4: 0x65636163  "cace"
0xDC9CA8: 0x702E7472  "rt.p"
0xDC9CAC: 0x00006D65  "em\0"       → 拼成 "PEMacart.pem"
0xDC9CB0: 0x4F444F43  "CODO"
0xDC9CB4: 0x2E312F4C  "L/1."
0xDC9CB8: 0x00000030  "0\0"        → 拼成 "CODOL/1.0"
```

★★★ **这是一组文件打开模式字符串 + 证书路径 + 产品标识：**
- `"w+b"` / `"r+b"` / `"rt"` / `"bw"` —— **fopen 模式**
- `"PEMacart.pem"` —— **证书文件名**
- `"CODOL/1.0"` —— **HTTP User-Agent**

### 0.2 `0x4F48D0` 的真实语义

```asm
0x4F48D9  push 0xDC9C9C        ; "bw"（fopen 模式）
0x4F48DE  push ebx             ; 文件名
0x4F48DF  call 0xC3D699        ; ★ fopen
0x4F48E4  mov edi, eax
0x4F48ED  push 0x10C           ; ★ alloc 268 字节
0x4F48F2  call 0xC3E9F5
0x4F48FC  test esi,esi / je
0x4F4904  call 0x769DE0        ; 初始化
```

★★ **`0x4F48D0` = "以 `"bw"` 模式打开文件 + 分配 268 字节对象"。**

⇒ **它是 HTTPS/TLS 客户端的证书文件读写，不是房间槽分配。**

## §5 方法论

1. **★★★ `push imm32` 的地址要读内容，不要当类型标识。** `0xDC9C9C` 看着像 vtable/COL，实际是 `"bw"` 字符串。
2. **★★ 一组相邻的 fopen 模式字符串 + 证书名 + UA ⇒ 判定为 HTTPS 层。**
3. **★★★ 大区（`0x4F4xxx`）里混着多个子系统，必须逐个排除。** 不能假设"同区就是同类"。
4. **★★ 记忆条目 `codol-room-subsystem-and-https-client-152` 已记录 HTTPS 客户端在 `[0x84ABB14]`，本卷补充 `0x7659F88` 是同族。**
