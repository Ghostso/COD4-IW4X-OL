# 位流读写器完整配对与 `6/5` 应答构造路径

> 承接 `lobby/67`
> 补齐两张表的第一张：读写器对

---

## 1. 位流 API 完整配对

| 方向 | 函数 | 作用 |
|---|---|---|
| **写** | `0xb77b10` | `writeBits(n)` |
| **写** | `0xb777c0` | `writeData(ptr, nbits)` |
| **读** | **`0xb774e0`** | **`readBits(n)`** |
| **读** | **`0xb772e0`** | **`readData(ptr, nbits)`** |

**⇒ 完全对称的四件套。**

**`0xb774e0` / `0xb772e0` 与 `memory: codol-dwroom-protocol-reversed`
记录的 `0xB77B10` / `0xB777C0` / `0xB774E0` 一致，新增了 `0xB772E0`。**

## 2. 基类反序列化（`0x627ce0`，`dwRoomMessage`）

```asm
0x627cec  push 3
0x627cf0  call readBits(3)          ; ★ 读 3 位
0x627cf5  test al, al
0x627cf7  je  0x627d19              ; 失败
0x627cf9  push 8
0x627cfb  lea ecx, [ebp+0xb]
0x627cff  push ecx
0x627d01  call readData(&buf, 8)    ; ★ 读 8 位（1 字节）
0x627d0a  movzx edx, byte [ebp+0xb]
0x627d0e  mov [edi+4], edx          ; ★ 存到 [obj+4]
0x627d12  mov al, 1 / ret
```

**⇒ 基类的读和写完全对称：**

```
写：writeBits(3) + writeData(&[obj+4], 8)
读：readBits(3)  + readData(&[obj+4], 8)
```

**⇒ 前 11 位是"3 位类型 + 8 位版本"。**

## 3. Manifold 反序列化（`0x6256c0`）

```asm
0x6256e4  push 3
0x6256f0  call readBits(3)
0x6256f9  push 8
0x625702  call readData(&buf, 8)
0x625711  movzx ecx, byte [esp+0x13]
0x625718  mov [ebx+4], ecx          ; 存 [obj+4]
...
0x625721  push 8
0x625725  call readBits(8)          ; ★ 读 8 位
```

**⇒ 结构与 serialize 对称。**

---

## 4. ★ 消息头的最终定义

```
位  0..2    : 3 位   类型码
位  3..10   : 8 位   [obj+4]（版本/标志）
位 11..18   : 8 位   第二个字段标签
位 19..50   : 32 位  第二个字段值 [obj+0x10]
```

**⇒ 每条 `dwRoomMessage` 至少 51 位。**

---

## 5. 关于"类型码表"的结论

**基类 `dwRoomMessage::deserialize` 读 3 位但**没有分派**。**

**⇒ 分派不在基类里。**

**⇒ 类型码由外层（Manifold 的链表节点）携带，或者由虚表决定。**

**⇒ 之前假设的"51 个类对应 51 个编号"可能不成立。**

**⇒ 更可能：类型由**对象类型**（vtable）决定，3 位只是版本/标志。**

---

## 6. 修正后的理解

```
序列化：
  外层：选定一个消息对象（已知类型）
  内层：writeBits(3) 写版本号 + 各字段
  反序列化：
  外层：从链表节点拿到对象指针（类型已知）
  内层：readBits(3) 校验版本
```

**⇒ "类型"不是线格式的一部分，是**对象本身的类型**。**

**⇒ 服务端推送时，必须**选对消息对象**，
然后调用它的 `serialize`。**

---

## 7. 这对构造 `6/5` 应答的意义

**要返回一条 `dwRoomMessageRoomInfo`，需要：**

1. 构造一个 `RoomInfo` 对象（类型已知）
2. 填充它的字段
3. 调用 `serialize`（`0x627ea0`）写入位流
4. 把位流装进 `6/5` 的应答

**⇒ 不需要"类型码表"，只需要"字段填充"。**

---

## 8. 下一张表：`RoomInfo` 的字段

**`serialize = 0x627ea0`，只有 0x40 字节（`0x627ea0` → `0x627ee0` 是 deserialize）。**

**⇒ 非常短，说明字段很少。**

**⇒ 反汇编它就能得到完整的 `RoomInfo` 线格式。**
