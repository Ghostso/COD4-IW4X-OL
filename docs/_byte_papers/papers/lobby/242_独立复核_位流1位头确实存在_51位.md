## §0 结论

**★★★★★ 239 卷（子代理）是对的。178–181 卷的「无 1 位头、50 位」结论作废。**

独立取得的机器指令证据：

1. **写侧** `0xB778E0`：`0xB7795E push 1` + `0xB77977 call 0xB777C0` ⇒ **无条件写 1 位**，值 = `[ebp+0xC]!=0 ? 0xFF : 0x00`。
2. **读侧** `0xB779A0`：`0xB77A36 push 1` + `0xB77A41 call 0xB777C0`（源 `[ebp-0xD]=AL=0`）⇒ **同样写 1 位 0**。
3. **房间类 3 个位流构造点全是 `push 0; push 0`** ⇒ flag=0 ⇒ **写的 1 位值 = 0x00**。
4. **`0xB777C0` = 通用写位函数**：`[ebp+0xC]` = **位数**，`[ebp+8]` = 源指针（内部 `0xB7785C mov eax,[ebp+0xC]` / `0xB777D0 shr edi,3` 求字节数）。

★ **⇒ 房间位流 = `[1 位=0][Manifold 头 50 位]` = 51 位，两侧一致。**

| # | 证据 | 强度 |
|---|---|---|
| ① | `0xB7795E push 1` / `0xB77977 call 0xB777C0`（写侧） | ★★★★★ |
| ② | `0xB77A36 push 1` / `0xB77A41 call 0xB777C0`（读侧） | ★★★★★ |
| ③ | `0xB7785C mov eax,[ebp+0xC]` ⇒ 第 3 参是位数 | ★★★★★ |
| ④ | 3 个构造点 `push 0; push 0` ⇒ flag=0 ⇒ 写 0x00 | ★★★★★ |

## §1 写侧：`0xB778E0` 的两个参数

```asm
0xB778E0  push ebp / mov ebp,esp / ... (SEH)
0xB77907  mov  esi, ecx
0xB7790E  mov  dword ptr [esi], 0xDB6AE4       ; 基类 vtable
0xB77917  mov  eax, [ebp + 8]                  ; ★ 参数1 = 容量（位数）
0xB7791A  test al, 7
0xB7791C  mov  ecx, ebx                        ; ebx = 0
0xB7791E  setne cl
0xB77921  shr  eax, 3                          ; 字节数
0xB77924  mov  dword ptr [esi], 0xD59834       ; ★ 派生 vtable
0xB77933  add  eax, ecx                        ; 向上取整
0xB77935  mov  [esi + 0xC], eax                ; 容量（字节）
0xB7793C  push eax / call 0xB74220             ; 分配
0xB77945  mov  [esi + 8], eax                  ; 缓冲指针

0xB77948  mov  al, byte ptr [ebp + 0xC]        ; ★★ 参数2 = flag
0xB7795B  mov  byte ptr [esi + 0x21], al       ; ★ 存进 +0x21（173 卷已定＝ctor 第2参）
0xB7795E  push 1                               ; ★★★ 位数 = 1
0xB77960  mov  ecx, esi
0xB77962  cmp  al, bl                          ; flag == 0 ?
0xB77964  je   0xB77970
0xB77966  lea  edx, [ebp - 0xD]
0xB77969  mov  byte ptr [ebp - 0xD], 0xFF      ; flag != 0 → 源 = 0xFF
0xB7796D  push edx
0xB7796E  jmp  0xB77977
0xB77970  lea  eax, [ebp - 0xE]
0xB77973  mov  byte ptr [ebp - 0xE], bl        ; flag == 0 → 源 = 0x00
0xB77976  push eax
0xB77977  call 0xB777C0                        ; ★★★ 写 1 位
0xB7797E  mov  dword ptr [esi + 0x1C], 1
```

★ **`0xB7795E push 1` 与 `0xB77977 call 0xB777C0` 之间的 `je/jmp` 只切换「源字节是 0xFF 还是 0x00」，不切换「写不写」。** ⇒ **无条件写 1 位。**

## §2 读侧：`0xB779A0` 也写 1 位

```asm
0xB779EC  mov  ebx, [ebp + 0xC]                ; 长度（位）
0xB779EF  lea  edi, [esi + 0x21]
0xB77A02  mov  byte ptr [edi], al              ; ★ +0x21 = 0（与写侧默认一致）
0xB77A04  cmp  byte ptr [ebp + 0x10], al       ; 参数3
0xB77A07  je   0xB77A36
0xB77A09  cmp  ebx, eax
0xB77A0B  je   0xB77A36
   ; ---- 有一份数据要拷贝 ----
0xB77A1F  call 0xB77710                        ; 拷贝字节
0xB77A24  push 1
0xB77A26  push edi
0xB77A27  mov  ecx, esi
0xB77A2F  call 0xB772E0                        ; 写另一段
   ; ---- 走默认路径 ----
0xB77A36  push 1                               ; ★★★ 位数 = 1
0xB77A38  lea  ecx, [ebp - 0xD]
0xB77A3C  mov  ecx, esi
0xB77A3E  mov  byte ptr [ebp - 0xD], al        ; ★ al = 0（来自 0xB779CD xor eax,eax）
0xB77A41  call 0xB777C0                        ; ★★★ 也写 1 位 0
0xB77A46  mov  edx, [ebp + 8]
0xB77A49  push ebx
0xB77A4A  push edx
0xB77A4D  call 0xB777C0                        ; 接着拷贝长度位
```

★ **读侧在「无数据可拷」分支（`je 0xB77A36`）里也 `push 1` + `call 0xB777C0` 写 1 位 0。**
★ **⇒ 读侧与写侧对称，都是 1 位前置头。239 卷「读侧不消费这 1 位」这个措辞需修正为「读侧也写 1 位（到它自己的新缓冲）」。**

## §3 `0xB777C0` 的参数语义（决定性）

```asm
0xB777C0  push ebp / mov ebp,esp
0xB777C3  mov  eax, dword ptr [ebp + 0xC]      ; ★ 参数3
0xB777C9  push ebx / push esi
0xB777CB  mov  esi, ecx                        ; this = 位流对象
0xB777CD  mov  ecx, [esi + 0x14]               ; 当前位偏移
0xB777D1  lea  edi, [eax + ecx - 1]
0xB777D5  shr  edi, 3                          ; ★ (位偏移+位数-1)/8 = 需要字节数
0xB777D8  cmp  edi, [esi + 0x10]
0xB777DB  jb   0xB777F9
0xB777DD  lea  eax, [edi + 1] / push eax
0xB777E4  call 0xB77560                        ; 扩容
...
0xB7785C  mov  eax, dword ptr [ebp + 0xC]      ; ★★ 参数3 = 剩余位数
0xB77860  shr  eax, 3
0xB77865  mov  eax, [ebp + 8]                  ; ★ 参数2 = 源指针
0xB77868  mov  al, byte ptr [edi + eax]        ; 取源字节
```

**⇒ 签名 = `writeBits(this, src_ptr, bit_count)`。**

★ **`0xB7795E push 1` 就是 `bit_count = 1`。结论无歧义。**

## §4 房间类三个构造点：flag 全为 0

| 调用点 | 指令序列 | flag |
|---|---|---|
| `0x62AC0F` | `0x62AC0B push ebx` / `0x62AC0C push ebx` (ebx=0) | **0** |
| `0x62C3AE` | `0x62C3A8 push 0` / `0x62C3AA push 0` | **0** |
| `0x6336C4` | `0x6336BE push 0` / `0x6336C0 push 0` | **0** |

★ **⇒ 房间位流的 1 位头**永远写 `0x00`**（不是 `0xFF`）。**

★★ **这与 173 卷「`push 0; push 0; call 0xB778E0` ⇒ `[+0x21]==0`」完全吻合** —— 173 卷当时只用 `+0x21` 去解释「`0xB77B10` 遇到 0 跳过」，**没想到 `+0x21` 同时决定了这 1 位头的值**。

## §9 方法论

1. **★★★★★ 子代理结论与旧结论冲突时，必须主对话独立重跑，不能凭「旧结论是我写的」就否决。** 本卷两次独立反汇编都支持子代理。
2. **★★★★ 「某函数内部跳过某个写」≠「整条链不写」。** 179 卷看到 `W_TAG` 内部跳过包装头，就断定"无 1 位头"——**但 ctor 里的 1 位写是另一处代码。**
3. **★★★ 位宽断言必须把「所有写位点」加起来。** 50 位是我把 `W_TAG(3)+W_VAL(8)+W_TAG(8)+W_VAL(32)` 相加得的，**漏了 ctor 那次 `push 1`**。
