# 344 探讨 — 这次证伪是怎么被推翻的

## 0. 我一开始差点写错

任务是"证伪客户端会发房间动作"。最省事的读法：
`chain.txt` 里 47 次 sendto 全是 gcloudvoice/BugTrace、19 次 connect 全是腾讯 CDN，
**没有一条是 127.0.0.2:3074** → 看上去"客户端什么都没发"。
这个读法是**错的**，原因是取证手段本身有洞：

- hook 只装了 `connect` 与 `sendto`（chain.txt 第 24–25 行）。
- 大厅是 **TCP**，写 TCP 走的是 `send` / `WSASend`，**没被 hook**。
- 于是 `chain.txt` 结构上**不可能**记录到任何房间帧。

**教训**：分母不能从"装了 hook 的 API 日志"里取，要先确认
"这条通道到底走哪个 API、那个 API 有没有被 hook"。否则"没找到"会被误读成"没有"。
（简令第 4 节最后一条：没找到 ≠ 证明没有。）

## 1. 真正的事实层是服务端日志

`lobby_srv.log` 解出 7152 帧 / 97 run / 55 种 (svc,task)，其中 11/4 共 220 条。
这一步立刻把"没发"打掉：**ready 族 57 条、room 族 163 条，字节俱在。**

如果不做全量而只看本轮的 `ONCE_20261103_151503`，会看到 **11/4 只有 1 条、且无应答**，
很容易又得出"只发了一次、没发 ready"的结论——**这也不对**：
本轮只是**停在了第一次 room 上**，不是客户端不想发。

## 2. 三次自我纠正

| 我先以为 | 实际 | 纠正依据 |
|---|---|---|
| chain.txt 里没有发往 3074 的包 ⇒ 客户端没发动作 | 取证手段缺失（TCP 未 hook） | 服务端解出 7152 帧 |
| 本轮 11/4 无 ready ⇒ ready 从不发出 | 49 个 run 里 47 个有 ready | `corr.py` 全量 |
| 11/4 无应答是客户端有门 | 是**服务端自己抛异常** | `reply_objects` 第 1105 行 `NameError` |

第三条是这一卷的核心。发现路径：
日志最后一行悬在 `#59 ... task=4` 且**没有** `-> ...` 说明行（其它每条都有）→
说明进程没走到 `reply_objects` 的返回 → 直接把该函数 import 出来对着真实 payload 跑 →
`NameError: name 'batch' is not defined`。

**这个 bug 的形态很典型**：不是逻辑错，是重构时删了绑定行、留下了游引用。
它不会在语法检查里暴露（Python 名字是运行时查的），只在**真的收到 11/4 时**炸。
所以历史上的 run 都能过（旧版有那一行），一旦换新版就全灭，而失败表现是"客户端没反应"，
极容易被误判回客户端。

## 3. 47/47 单向依赖说明什么

`ready_index > room_index`，且 room 被回显的 47 个 run 全部产出了 ready；
48 个没有 ready 的 run 全部没有那条被回显的 room。
这不是"相关"，这是**严格的前置关系**：
**服务端不回 room ⇒ 客户端的 ready 序列化器根本不会被调用。**

所以本轮的"ready 没出现"是**结果**，不是**原因**。

## 4. 为什么我没有直接改 kit

简令第 1.2 条：只写 `_rev_analysis\_r64_<N>\`、我的两篇论文、`_byte_papers\_pending_index\room64_<N>.md`。
`REF_LOBBY_KIT\*` 是受保护只读，且改 kit 属于"有副作用"。
所以我只复制了一份到 `_f64_05\patched_lobby_server.py`，用同样的 payload 证明修复有效，
**把改不改的决定留给用户**。

## 5. 还没解释的

- 本轮 `6/14`（mmbook/mmstart 聊天开局）、`21/5`（findSessions）**一次都没出现**，
  而旧 run 里这三者在 ready 之后紧接着出现。
  合理推断：它们排在 ready 之后，被同一个 break 截断。但**这是推断，不是实测**，
  要等修复后跑一轮才能确认。
- `0xBA0780(srpc)` 在实跑里的返回值没抓到（176 卷给了 5 种输出）。
  如果修复后仍卡门，这是下一个要抓的量。
- `11/4 room` 里 80/163 条长度前缀不吻合。族判定不受影响，但长度语义仍空着。

而且打断方式是一个一行就能修的运行时名字错误。
