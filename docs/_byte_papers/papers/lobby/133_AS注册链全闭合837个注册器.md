# 133 · AS_* 注册链全闭合：837 个注册器，一条路径，零例外

> 前作：[132 · 12 字节行结构定案 / 829 对象族谱](132_AS对象虚表结构定案与829对象族谱.md)
> 任务：闭掉 131 §八 与 132 §八/§十 的最后一个缺口 —— **"Flash 名字 → 对象"的映射表到底在哪**。
> 结论：**没有表。每个接口有一个 0xC0 字节的注册器函数，体内 `push "<短名>"` 就把名字和对象焊死。**

---

## §0 本卷七条结论

1. **全镜像 838 个独立注册器函数**，每个约 0xC0 字节，模板完全一致。
2. **837 / 838 被 `E8 rel32` 调用，0 个无归属** ⇒ 这条链是完整的，没有"运行时装配的剩余部分"。
3. **816 个不同短名 ↔ 829 个对象**，一一对应（同名不同对象只出现在 `AS_ShowView`/`AS_HideView`/`AS_OnInit` 这类**被多个 View 各自注册的通用动作**上）。
4. **62 个 `?N@` 局域类对象走的是同一条路径**，没有任何特殊处理（例：`0x745B30` 体内 `push "AS_SetInitData"`，写 vptr `0xDD832C`）。
5. **注册器体只有 5 步**（见 §二），**没有任何"查表"动作** ⇒ **131/132 一直在找的"映射表"根本不存在**。
6. **29 个外层函数**负责批量调用（`0x5CEB10` 调 220 次、`0x5DC3D0` 调 102 次），它们是各 UI 模块的初始化函数，不是通用派发器。
7. **协议面的直接产出**：816 个 Flash 名字全表已导出，每个绑定唯一 vtable + handler + RTTI 类名。

## §一 838 个注册器的发现路径

判据链（**不依赖任何步进**）：

```
① 829 个对象的 vtable 地址（132，判据 = vftable[-1] 是合法 COL）
② 每个 vtable 地址在全镜像里被"立即数写入"的位置 ⇒ 那是某个函数的 `mov [obj], <vtable>`
③ 该位置向上找最近的 `cc cc` ⇒ 函数入口
⇒ 838 个函数（829 个对象 + 9 个对象被两个函数各自注册）
```

★★ **"立即数写入"是这里唯一可靠的判据**：因为 MSVC 只会在**构造函数/注册器**里直接写 vptr 常量。

★ 注意：**不能用"call 到 handler"反推** —— 132 §四 已证明 handler 统统经 `vftable[1]` 间接调用。

## §三 `0x830BC0` 与 `[edi+0x08]/[edi+0x0C]/[edi+0x10]` 的语义

`0x830BC0` 接收 `(&栈上4×u32, 新对象, 0)`。它做的是把新对象**登记进一个区间容器**（返回值/标志位落在 `[ebp-0x18]`，后面用 `test al,0x8F` / `shr 6 / test 1` 两位判断是否成功）。**这不是注册，注册是后面那次 `call edx`。**

`edi` 是**入参之一（第 2 个）**，指向 Flash 侧的 `MovieClip` 或 AS 对象容器：

| 偏移 | 用途 |
|---|---|
| `[edi+0x08]` | → 某个对象的 vtable 指针链起点（`[ecx]` → `[edx+0x14]` = registerFunction） |
| `[edi+0x0C]` | 参数 1（被 `and 0x8F` 后与 0x0A 比对 → 得到 bool） |
| `[edi+0x10]` | 参数 0（注册目标容器） |

★ **诚实边界**：`test al,0x8F / cmp al,0x0A` 这一对**不是"标志位测试"的常规写法**，本卷**没有确定**它的语义。已知的是：结果作为 **bool 参数**传给 `registerFunction`，即 **"是否作为函数（而非对象）注册"**。数值映射未定案。

## §四 837/838 与 0 个无归属

```
独立注册函数      838
被 E8 rel32 调用  837
无归属调用点        0
```

一个没被调用的注册器：就是 `0x64F620` 自己这一族里排最后的那一个（`AS_JoinRoom` 的邻居）。★ 它可能是**死代码**（接口被删但注册器留着），也可能是**被 `call eax` 间接调用**（本卷的扫描只认 `E8`）。**未定案，不掩盖。**

★★ **"0 个无归属"是本卷最硬的一条**：它排除了"还有一部分对象走别的注册路径"这种可能。**829 个对象，830 个注册关系（9 个对象被两个函数注册），全部落在这 838 个函数里。**

## §七 对本项目服务端工程的直接结论

1. **"服务端需要实现哪些 AS 接口"这个问题，现在有机械答案**：跑 `tools/as_name_to_vtable.json`，凡 `handler == 0x8435E0`（22 个）直接跳过。
2. **`AS_DMZ_*` 9 个接口 ⇒ DMZ 模式在本 build 是完整的**，与 `pve-campaign-content-systemic-gap` 的"PvE 内容缺损"是**两件事**：PvE 剧情缺，DMZ 撤离模式在 UI 侧齐备。
3. **`AS_Datamore*` 说明"数据罗盘/活动"是独立的第三方(SDK)接入面**，不走腾讯运营面，因此**也不在 22 个空实现里**。

## §八 诚实边界

1. **1 个注册器未被 `E8` 调用**，可能死代码也可能间接调用 —— 未定案。
2. **`test al,0x8F / cmp al,0x0A` 的语义未定**（只确定它变成 registerFunction 的 bool 参数）。
3. **29 个外层函数只有 1 个（`0x73DF20`）被映射到类名**，且是"次数对齐"推断。
4. **`0x830BC0` 的容器语义未解**（只知道它不是注册器）。
5. **9 个对象被两个注册器注册** —— 这 9 对的"谁是主注册、谁是别名"未区分。
