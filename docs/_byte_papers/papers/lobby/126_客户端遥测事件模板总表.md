# 126 · 客户端遥测事件模板总表 —— 52 个事件的字段格式一次全解

> 项目：使命召唤OL 大厅（build 1649370 / 3.19）
> 前卷：`123`（`71/3`/`71/7` 事件词表）、`124`（`71/15` 解压出 652 事件）、`125`（8/3）
> 本卷：**不再从报文反推格式，直接从客户端镜像里把"事件名→printf 字段模板"整张表提出来**
> 证据：`telemetry_template_table.txt`、`telemetry_table_full.txt`、`telemetry_formats_full.txt`

---

## §0 结论

★ **客户端里有一张遥测事件模板表**：每个事件 = `事件名|%s|%u|%llu|${CODOID(%llu)}|...` 的 printf 格式串。
本卷提取出 **52 个事件模板**（`LHl` 是误命中）。

| 数量 | 说明 |
|---|---|
| 52 | 完整事件模板（名字 + 字段类型序列） |
| 1 | 误命中（`LHl`，来自无关二进制段） |

★★ **这句话最重要**：**遥测格式不是"报文里观察出来的"，是客户端自己写死的模板。**
所以 `123`/`124` 从报文里看到 `UIPage|${TIMESTAMP_OFFSET(-21)}|…|142`，只是**模板被填充后的实例**；模板本身在客户端里，本卷把它整个挖出来。

## §1 通用的前 3~5 个字段（所有事件共享）

看这 52 条模板，**开头几乎全是同一组**：

```
事件名 | %s | %llu | ${CODOID(%llu)} | ...
        │     │      └── 账号 ID
        │     └── 时间戳 / 序号
        └── 事件名或分类串
```

- **字段 1 `%s`**：分类/来源串（常见是 `TimerError` 那种"事件名回填"，或子类别）。
- **字段 2 `%llu`**：时间戳或自增序号。
- **字段 3 `${CODOID(%llu)}`**：账号 ID（`0xE7C8A98A6B4C2D0E` = 16701785630074219790）。
- 部分事件在字段 2 前多一个 `%u`（`TimerError|%s|%u|%llu|…`）或 `%llu|%llu`（双 ID）。

★ **⇒ 遥测是"统一信封 + 事件专属尾段"**：前几个字段是全局字段，后面是每个事件自己的。

## §3 对 123/124 卷的印证与补全

- **`UIPage` 不在 52 条模板里**（`0x9C7090` 只有裸 `UIPage` 串，没有 `|%s|…` 格式串）。
  ★ ⇒ `UIPage` 的格式是**运行时拼的**或走了另一张表；`123`/`124` 从报文观察到的 `UIPage|${TIMESTAMP_OFFSET(-N)}|session|account|${CODOID}|pageId` 是**实例**，模板本身未在这张表区。**诚实保留。**
- **`UIClick`（`0x9C7088`）也不在这张表里**——同上。
- **`ClientLogin`/`ClientOffline`/`ClientDisconnect`/`ClientReconnected`/`ClientSettingsGpu` 5 个** 全部命中 ⇒ `123` 卷的 `71/7` 词表**完全被客户端表证实**。
- **`ClientLoadTime`/`ClientLoadout`/`CreateRoom`/`OnBoarding`/`MissingLocalizedString`/`ChannelSubscriptionFail`/`UIFriendList`/`MatchMaking`/`MatchMakingJoin`/`TimerError`/`UserSettings`** 全部命中 ⇒ `71/3`/`71/15` 看到的都是这张表的实例。
- **新增了 `123`/`124` 没见过的 25 个事件**：`ClanCreate`/`ClanDismiss`/`ClanUpdate`/`ClanNameChange`/`ClanProfileUpdate`/`NameChange`/`UserWarning`/`SendLoudSpeaker`/`PreprocessGroupInfoResult`/`ChatMessageReport`/`ExpectedNetConfigStringMismatch`/`UIClickCount`/`UserComplaint`/`UIException`/`OperationEventXPGP`/`MapVote`/`UIKeySetting`/`UIInitialGameMode`/`ClientInvalidBuild`/`STUNServerPingResult`/`Chat`/`QuestionnaireResult`/`WarGodMatchMaking`/`WarGodMatchStart`/`WarGodMatchEnd`/`CreditRating`/`CreditRatingBlock`/`TencentCrossInit`/`GameMomentsEdit`/`ComError`/`ClientException`/`ClientOfflineOOB`/`UIFriendEvent`/`SkinnedModelExceeded`/`ProfileEvent`。

★★ **⇒ `71/*` 遥测的可发送事件全集 = 这 52 个（外加 UIPage/UIClick 两个运行时格式）。**

## §4 这张表最有用的几处（对改大厅）

1. **`ClientLogin` / `ClientDisconnect` / `ClientLoadTime` 的字段类型全给了** ⇒ 如果要伪造/重放遥测，字段顺序与类型（`%s`/`%llu`/`%d`/`%f`）全知，**可以直接构造合法事件行**。
2. **`${CODOID(...)}` / `${ZONEID(...)}` / `${TIMESTAMP}` / `${TIMESTAMP_OFFSET(-N)}` 是宏**，不是普通 printf —— 说明客户端有一层**遥测宏替换引擎**，把 ID 转成显示形式。
3. **`ComError`/`ClientException`/`ClientDisconnect` 最长（23/21/65 字段）** ⇒ 崩溃/断线诊断遥测字段极多，是"客户端把当时全部状态吐出去"的典型。
4. **`ChatMessageReport` 27 个 `%s`** ⇒ 举报消息时把完整上下文（双方名字、消息原文、环境）全带上。
