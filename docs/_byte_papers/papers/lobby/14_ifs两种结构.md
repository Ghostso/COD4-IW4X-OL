# `.ifs` 的两种结构：带清单 vs 裸载荷

> 证据：`tools/ifs_classify.py`（974 个文件全量）

---

## 1. 两类文件

按头 16KB 内是否出现 `IWff`：

| 类别 | 数量 | 特征 |
|---|---|---|
| **L**（清单型） | **636** | 0xac 起是明文清单，无 `IWff` |
| **F**（载荷型） | **338** | 0xac 或稍后出现 `IWff0100` |

**636 + 338 = 974。**

---

## 2. L 类的结构

```
0x00–0xAB   172 字节头部
0xAC–…      明文清单（`<name>.lst` + 一堆资源路径，\r\n 分隔）
…           0x00 填充
L-tail-16   16 字节校验
L-tail      tail 字节（全 01，长度 tail_len）
```

### 典型尺寸

| 尺寸 | 文件数 |
|---|---|
| 16417 | 59 |
| 32818 | 44 |
| 147625 | 24 |
| 82021 | 16 |
| 65620 | 15 |

**尺寸不是固定的**，但 `16417` 和 `32818` 很常见（= 16KB/32KB 块 + 头部）。

---

## 3. F 类的两种子形态

### F1：带清单 + 载荷（大文件）

```
ff_init_common_gametype_mp_V69.ifs (34.8 MB)
  0x00–0xAB   头部
  0xAC–0x147  清单（.lst + 2 个 .ff 路径）
  0x148       IWff0100
  0x160–      加密载荷
  L-tail      尾部表
```

### F2：裸载荷（小文件，32KB）

```
ff_dlc18_za_island_V36.1.ifs (32818 字节)
  0x00–0xAB   头部
  0xAC        直接就是 IWff0100   ← 没有清单
  0xC4–       载荷（32620 字节）
  L-2         尾部（2 字节）
```

**F2 是 F1 的"无清单"变体。**

---

## 4. 同尺寸不同类的证据

**122 个文件都是 32818 字节**，但：

- **78 个是 F 类**（0xac 直接是 `IWff`）
- **44 个是 L 类**（0xac 是明文清单）

**尺寸相同，内容完全不同。**

---

## 5. 这对"改大厅"意味着什么

### 好消息

- 636 个 L 类文件的内容是**完全明文的清单**
- 它们的资源索引**可直接读取、编辑**

### 坏消息

- 338 个 F 类文件含**加密载荷**
- `common_mp.ff`（大厅）和 `common_gametype_*.ff`（模式）**都在 F 类里**

---

## 6. F2 类的一个疑问

`ff_dlc18_za_island_V36.1.ifs` 只有 32620 字节载荷，
而 `ff_dlc18_za_island_V36.ifs` 有 64MB。

**同一内容有两个版本**：
- `.1` 后缀的是小的（32KB）
- 无后缀的是大的（64MB）

**可能**：
- `.1` 是补丁/差分包
- 或 `.1` 是清单占位（标 ${V36.1}$ 表示"V36 的第 1 次增补"）

**未证实。**
