# 151 · 容器语义验证 + 加密全局指针层

> 前序：150（帧更新与出站 vtable 全表）、149（三入队一真发）、147（消息泵 this=srpc）
> 性质：**按序验证三项未闭合**。① 容器函数语义（结论成立）；② `[0x331C0C8]` 身份；
> ③ 发现**加密全局指针层** —— 这解释了多处"找不到写点"。

## §0 十条结论

1. ★★★★★ **`0x654D60` = 链表迭代器推进**（`iter = iter->next`），**不是发送**。
2. ★★★★★ **`0x656A10` = 链表节点插入**（分配 `0x20` + 复制 5 dword + 挂链 + `count++`），**不是发送**。
   **⇒ 前几卷的「入队不出网」结论成立。**
3. ★★★★★ **`[0x331C0C8]` = XOR 加密的全局指针**（per-client 对象）。
   - 全镜像 **203 处引用**：`A1` 读 116 + `8B 0D/15/1D/35/3D` 读 82 + **写 2** + 其它 3
   - **掩码 `0xD362501F`**，每个全局有**独立**掩码
4. ★★★★★ **只有 2 个写点**：
   - **`0x5C85BF`**（设置）：`push 0x12A700` → `call 0x5C8330`（分配）→
     `xor eax,0xD362501F` → `mov [0x331C0C8], eax`
   - **`0x5C8AC0`**（清零）：末尾 `mov eax, 0xDBC09C` = 字符串 **`"$perLocalClient"`**
5. ★★★★★ **`0x5C8330(size)` = `VirtualAlloc` 封装**：
   ```asm
   0x5C8341  call [0xCA8164]              ; GetCurrentThreadId
   0x5C8347  cmp eax,[0x7886E94]
   0x5C835D  mov eax,[0x8168E84]
   0x5C8365  push 0x3000                  ; MEM_COMMIT|MEM_RESERVE
   0x5C8377  call [0xCA8204]              ; ★ VirtualAlloc
   0x5C8388  push 0xDDA4CC "universal\physicalmemory_dynamic_reserved.cpp"
   0x5C838D  call 0x77C500                ; 断言
   ```
6. ★★★★ **`0xC3EC10` = MSVC `rand()`**：
   ```asm
   0xC3EC10  call 0xC49080
   0xC3EC1A  imul eax,eax,0x343FD         ; ★ LCG 乘数
   0xC3EC20  add eax,0x269EC3             ; ★ LCG 增量
   0xC3EC25  mov [ecx+0x14],eax
   0xC3EC28  shr eax,0x10
   0xC3EC2B  and eax,0x7FFF               ; 返回 0..0x7FFF
   ```
7. ★★★★ **`0x5C8560` 段是「随机数 + 浮点」混淆**（`rand()` → `fild/fmul/fimul` →
   `0xC42D30`(cvttsd2si) → 4 次循环探测空槽）。
8. ★★★★ **一组加密全局被同一次清零**（`0x5C8A84..0x5C8AC0`）：
   `0x1C1D188 / 0x1C1D18C / 0x1C1D190 / 0x1C1D194 / 0x1C1D198 / 0x1C1D19C / 0x1C1D1A0 /
   0x1C1D1A4 / 0x34027F4 / 0x338139C / 0x3381398 / 0x76638F4 / 0x331C0C8`
9. ★★★ **另一个加密全局 `0x76638F4`**：`push 0xAA10` → 分配 → `xor eax,0x6891D1C7` → 存。
   **⇒ 每个全局独立掩码，确认是"加密指针表"。**
10. ★★★ **`0x632D90`（帧更新）读 `[0x331C0C8] ^ MASK` → `[obj+0x28]` → `call 0x7F4F10`**
    （host 状态查询）。

## §1 按序验证 1：容器函数语义

```asm
0x654D60  mov ecx,[edi]          ; edi = 迭代器指针
0x654D63  mov esi,eax            ; esi = out
0x654D65  mov eax,[ecx+0x14]     ; next = cur->next
0x654D68  test eax,eax / je 0x654D70
0x654D6C  mov [edi],eax          ; ★ iter = next
0x654D6E  pop esi / ret
```
**⇒ 纯链表迭代器推进。无发送。**

```asm
0x656A10  push ebp / mov ebp,esp
0x656A14  mov ebx,[ebp+8]        ; container
0x656A18  push 0x20 / call 0xB74220    ; 分配节点
0x656A28  mov eax,[edi] / mov [esi],eax
0x656A3A  mov eax,[edi+8] / mov [esi+8],eax
0x656A40  ... 复制到 [esi+0x14]
0x656A58  mov ecx,[ebp+0xC]      ; 参数 2
0x656A5F  mov edx,[ecx+0x18]
0x656A62  mov [eax+0x18],edx
0x656A65  mov [eax+0x1C],ecx
0x656A6F  mov [edx+0x1C],eax
0x656A72  mov [ecx+0x18],eax     ; ★ 挂链
0x656A75  inc dword [ebx+8]      ; ★ count++
0x656A7B  ret 8
```
**⇒ 纯链表节点插入。无发送。**

★★ **⇒ 149/150 卷「Ready / ChangeTeamRequest 入队后不出网」的结论成立。**

## §2 按序验证 2：`[0x331C0C8]` 的引用形态分布

| 形态 | 数量 |
|---|---|
| `mov eax,[0x331C0C8]` (`A1`) | **116** |
| `mov ecx,[...]` (`8B 0D`) | 27 |
| `mov edx,[...]` (`8B 15`) | 12 |
| `mov ebx,[...]` (`8B 1D`) | 9 |
| `mov esi,[...]` (`8B 35`) | 21 |
| `mov edi,[...]` (`8B 3D`) | 13 |
| **`mov [0x331C0C8], eax` (`A3`)** | **2** ★ |
| `mov dword [0x331C0C8], imm32` (`C7 05`) | 0 |
| `mov reg, 0x331C0C8`（取地址）| **0** |

**XOR 掩码 `0xD362501F` 的使用**：`xor eax` 125 + `xor ecx` 25 + `xor esi` 21 +
`xor edi` 12 + `xor edx` 12 + `xor ebx` 10 = **205 处**。

★ **⇒ 读用率 98%，写只有 2 处 ⇒ 这是"只设一次、处处读"的全局单例。**

## §4 `0x5C8330` = `VirtualAlloc` 封装

```asm
0x5C8330  push ebp / mov ebp,esp
0x5C8333  cmp byte [0x82C489C], 0
0x5C8341  call [0xCA8164]              ; GetCurrentThreadId
0x5C8347  cmp eax,[0x7886E94]
0x5C834D  sete al / test / je
0x5C8354  cmp dword [0x1D52CEC], 0
0x5C835D  mov eax,[0x8168E84]
0x5C8363  push 4
0x5C8365  push 0x3000                  ; MEM_COMMIT|MEM_RESERVE
0x5C836B  push ebx (size)
0x5C836E  push 0
0x5C8370  lea edi,[eax*20 + 0x8168E74] ; ★ 池数组
0x5C8377  call [0xCA8204]              ; ★ VirtualAlloc
0x5C837F  test esi,esi / jne
0x5C8383  push 0x1D3
0x5C8388  push 0xDDA4CC "universal\physicalmemory_dynamic_reserved.cpp"
0x5C838D  call 0x77C500                ; 断言
0x5C8395  mov [edi+4],esi
0x5C8398  mov [edi+0xC],ebx            ; 记录大小
0x5C83A0  call 0xC42DE0                ; memset
```

★ **源文件名 `physicalmemory_dynamic_reserved.cpp`** —— 这是内存保护/预留层，
**不是游戏逻辑代码**。

## §5 ★★★★ 本卷最重要的推论

**`[0x331C0C8]` 的写点在保护层代码（`0x5C85xx`）里，
使用了：① `VirtualAlloc` 封装；② `rand()` 加密掩码；③ 随机延迟。**

★★★ **这解释了一个反复出现的现象：某些全局的"写点"用常规扫描找不到。**

**判据**：如果一个全局有大量读、几乎没有写，且附近的代码出现
`rand()` / `VirtualAlloc` / 浮点混淆 —— **它的写点在保护层**。

## §6 诚实边界

1. **`[0x331C0C8]` 指向对象的"类身份"未定**（`+0x28` 是 handle，`0x12A700` 是大小）。
   dump 里该值为 `0xCE618743`，`^0xD362501F = 0x1D03D75C`，而该处内存**全 0**
   —— 与"未进房间"一致。
2. **`0x5C89C0` / `0x5C89BB`（跳转表其余分支）未全读**。
3. **`0x5C8560` 段的"随机延迟"用途未确证**（是延迟还是布局随机化）。
4. **`0x76638F4` / `0x34027F4` / `0x338139C` 等 12 个同组全局的身份未定**。
5. **未验证 `0x331C0C8` 是否与房间发送链有关**（唯一链接是帧更新的 `[obj+0x28]` → `0x7F4F10`）。

## §8 方法论

1. ★★★★★ **验证"某函数是不是发送"只需读它 6~10 条指令** —— 迭代器推进 vs 发送，一眼可辨。
2. ★★★★ **全局的"读/写比"是强信号**：200 读 2 写 ⇒ 单例，写点在初始化路径。
3. ★★★★ **`A3` / `A1` 形态（`mov eax,[imm]` / `mov [imm],eax`）容易被 `89 05` 扫描漏掉** ——
   **两种都要扫**。
4. ★★★ **`rand()` 的 LCG 常数 `0x343FD`/`0x269EC3` 是识别它的机械判据**。
5. ★★★ **`VirtualAlloc` + 源文件名断言 = 保护层代码的指纹**。
