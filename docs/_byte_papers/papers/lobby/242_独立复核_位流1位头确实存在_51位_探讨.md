## 二、我先做的是复核，不是采信

**子代理非权威。** 我按 AGENTS.md 的层级要求，自己反汇编了两遍：

### 写侧 `0xB778E0`

```asm
0xB7795E  push 1                    ; ← 位数
0xB77960  mov ecx, esi
0xB77962  cmp al, bl                ; ← al = flag（[ebp+0xC]）
0xB77964  je  0xB77970
0xB77969  mov byte [ebp-0xD], 0xFF  ; flag!=0 → 源 0xFF
...
0xB77973  mov byte [ebp-0xE], bl    ; flag==0 → 源 0x00
0xB77977  call 0xB777C0             ; ← 写
```

**`je` 只切换源字节，不切换"写不写"。无条件写 1 位。**

### 读侧 `0xB779A0`

```asm
0xB77A36  push 1
0xB779CD  xor eax, eax              ; ← al = 0
0xB77A3E  mov byte [ebp-0xD], al
0xB77A41  call 0xB777C0             ; ← 也写 1 位 0
```

**读侧也写。两侧对称。**

### `0xB777C0` 的第 3 参是位数

```asm
0xB777C3  mov eax, [ebp + 0xC]      ; 参数3
0xB777D1  lea edi, [eax + ecx - 1]
0xB777D5  shr edi, 3                ; (位偏移+位数-1)/8
0xB7785C  mov eax, [ebp + 0xC]      ; 再取参数3 = 剩余位数
```

**`push 1` 就是 `bit_count = 1`。无歧义。**

**⇒ 子代理对。我错了四卷。**

## 三、我错在哪一步

**179 卷的推理链：**

```
① 看到 0xB77A70 (W_TAG) 内部有个"包装头"分支
② 看到 0xB77B10 调用 0xB77A70 时 push 0 使第 4 参 = 0
③ ⇒ 该分支被跳过
④ ⇒ 无 1 位头
```

**③ 是对的。④ 是跳步。**

**"`W_TAG` 内部的包装头被跳过" ≠ "整条位流没有前置位"。**

因为**还有另一处代码**（位流对象 ctor `0xB778E0`）也在写位，只是它写的是**对象创建时的一次性前缀**，与 `W_TAG` 完全无关。

★ **我把「一个函数里没有」当成了「整条链没有」。** 这和 167 卷「文件名含房间的扫描会漏一半」、169 卷「没有样本要翻译成哪个函数处理它」是同一族错误：**搜索范围界定错，然后当成穷尽。**

如果我当时把它当成"我算的位数可能哪里漏了"，去把**所有写位点**列一遍，就能发现 ctor 里的 `push 1`。

## 五、位宽断言该怎么算

我 180 卷的算法：

```python
W_TAG(3)   # 5 位
W_VAL(8)   # 8 位
W_TAG(8)   # 5 位
W_VAL(32)  # 32 位
# 合计 50 位
```

**这个算法只统计了「我找到的那几个 W_ 调用」。**

**正确做法**：统计**位流对象从创建到发送之间，所有 `call 0xB777C0` / `0xB772E0` / `0xB77B10` 的 `bit_count` 参数之和**。

| 来源 | 位宽 | 我 180 卷有没有算 |
|---|---|---|
| ctor `0xB7795E push 1` | **1** | ❌ 漏 |
| `W_TAG(3)` | 5 | ✅ |
| `W_VAL(8)` | 8 | ✅ |
| `W_TAG(8)` | 5 | ✅ |
| `W_VAL(32)` | 32 | ✅ |
| **合计** | **51** | 我算成 50 |

★ **方法论：位宽断言必须「按执行顺序把每次写位调用加起来」，不能「把认识的 W_ 宏加起来」。** 前者是自底向上穷举，后者是凭记忆构造。
