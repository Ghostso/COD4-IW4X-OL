# 模式与菜单注册表 · 探讨：大厅的"骨架"原来是明文

> 对应：`lobby/17_模式与菜单注册表.md`

---

## 一、我原本以为所有逻辑都在加密的 `.ff` 里

`.ff` 载荷是 AES 加密的（`lobby/13`、`lobby/16`）。
所以第一反应是：**大厅的所有逻辑都在那些 `.ff` 里，必须解密才能改。**

---

## 二、然后我在 EXE 的只读段里找到了这张表

```
common_gametype_zm
common_gametype_survival
common_gametype_coop
common_gametype_zombie_arena
common_gametype_dmz
common_gametype_zombie_hunter
common_gametype_zhunt_humanoid
common_gametype_zhunt_zombie
common_gametype_zombie_survival
common_gametype_zombie_champions
common_gametype_td
common_gametype_mp
common_gametype_hostage
common_gametype_asym
```

**14 个模式名，纯 ASCII，就在 `0xdb5e80`。**

---

## 三、为什么这张表这么重要

**它说明"有哪些模式"这件事，不在加密的 `.ff` 里，而在 EXE 里。**

也就是说：

> 即使 `.ff` 全解不开，也能知道系统支持哪些模式，
> 并且**很可能可以增删这张表的条目来改变可用模式集合**。

**这把"改模式"的难度从"要 AES 密钥"降到了"改一段字符串表"。**

---

## 四、但也要小心

这张表可能只是"**资产名列表**"，不是"**UI 可选项列表**"。

两者区别：

- **资产名列表**：加载时按名字找 `.ff`，缺了就报错
- **UI 可选项列表**：决定菜单里显示多少个模式按钮

如果是前者，改它会**导致加载失败**，而不是"加一个新模式"。

**要确认它属于哪种，需要找它的读取点。**

---

## 五、`ui/default.menu` 是一个大发现

```
ui/default.menu
default_menu
```

**CoD 家族的 UI 是 `.menu` 文件**（Lua 风格的声明式菜单定义）。

`ui/default.menu` 很可能就是**大厅主菜单的源文件**。

如果它在某个 `.ff` 里，那还是需要解密。
但如果 `.menu` 文件是**明文**（CoD4 时代 `.menu` 是文本），那它可能在
L2 层（未加密）。

**这是一条待验证的路径。**

---

## 六、`aes 1.1.4` 这一行

```
sha256
IWffs100
aes
1.1.4
IWff0100
IWffu100
```

**`aes` + `1.1.4` 连在一起，是"算法 + 版本号"。**

这确认了加密算法就是 AES，版本 1.1.4（可能是某个库的版本）。

**这比"熵高所以是加密"强得多。**

---

## 七、方法论收获

> **"加密"不等于"全黑"。注册表/名字表往往在代码侧，不在数据侧。**

`.ff` 加密保护的是**内容**（模型、脚本、地图数据）。
但**"有哪些内容"**这种元信息，通常硬编码在可执行文件里。

**先找元信息，再找内容**，能大幅降低难度。
