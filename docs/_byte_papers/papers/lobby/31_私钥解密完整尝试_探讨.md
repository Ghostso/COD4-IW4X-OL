# 私钥解密完整尝试 · 探讨：16 个正确字节说明了什么，又误导了什么

> 对应：`lobby/31_私钥解密完整尝试.md`

---

## 一、16 个正确字节，既是证据也是陷阱

### 它是证据

```
磁盘密文: b2 2d ee f2 07 e1 b8 90 39 9b b8 43 a0 d3 b2 54
解密结果: IWffs100 00 00 00 00 6f 9e 1d 0c
```

**9 个可打印字符 + 7 个结构字节。**
随机命中的概率是 `2^-128`。

**所以 key 和 IV 至少对"第一块"是对的。**

### 它也是陷阱

**因为它让我以为整条链都对了。**

我花了大量时间在"为什么第 2 块开始错"，却一直没回头怀疑
"这个 16 字节的匹配本身可能是特殊构造的"。

---

## 二、如果真的全对，会发生什么

一个正确的 AES-CFB 实现，用正确的 key/IV/起点，会**全局正确**——
不只是第一块。

**第 1 块对、第 2 块错，只有三种可能：**

1. **不是 CFB**（但 CFB8/64/128、OFB、CTR 都试过）
2. **每块用不同 IV**（但换成前块密文/明文作 IV 也失败）
3. **我们对"第一块"的判定有误** —— 那 16 字节可能不是解密出来的

第 3 点最值得怀疑：

**如果明文头 `IWffs100` 恰好等于 `D(C0) XOR ...` 的某种特殊组合呢？**

概率极低，但不是零。

---

## 三、真正的矛盾

`cipher_setup` 的参数矛盾是硬的：

```
arg3 = [ebp-0x2c]   ← 这是栈地址
keylen = arg3
cmp keylen, 0x10    ← 会失败
```

**如果这条链真的跑起来，`setup` 会返回错误码。**

**所以要么：**
- `0xbc8640` 不是 `cipher_setup`
- 要么 `0x483a50` 根本没被调用过（死代码）

**第二种可能性很高。**

---

## 四、"死代码"假说

`0x483a50` 的唯一调用者是 `0x483bae`（在 `0x483b40` 里）。

`0x483b40` 是**初始化函数**。它调用链：

```
清零 → rep movsd 13 dword → zlib 结构初始化
    → 0x483a50 (AES 派生)
    → 0x791eb0 (zlib inflateInit2)
```

**如果这段初始化从未被调用，那么 `0x483a50` 就是死代码。**

**那 40 字节材料就不是 AES 密钥，而是别的东西。**

---

## 五、验证死代码假说

方法：在 dump 里找 `0x483b40` 的调用点。

如果**零调用** → 死代码 → 整条链作废。

如果**有调用** → 那问题在参数。

**这是下一轮的第一件事。**

---

## 六、这一轮的诚实评估

### 做到了

- 证明 `.ff` 有 256 字节 RSA 块
- 提取出 40 字节材料
- 证明材料能解出 16 字节正确明文
- 排除 8 类参数组合

### 没做到

- 完整解密任何 `.ff`
- 确认这条链是否被实际调用

### 不能说的话

> "`.ff` 已经解开了。"

**只能说："找到了入口，但入口后面还有一道门。"**

---

## 七、方法论收获

> **部分成功（16/16 字节）比完全失败更危险。**

完全失败会让你立刻换方向。
部分成功会让你相信"只差一点点"，从而在一个错误的方向上耗时。

**正确的做法：一旦发现"只有头部对、后面错"，立刻怀疑整个前提。**
