## §1 DML 标签表（本对话独立取得）

### 1.1 读器族的统一形态

```asm
0xB76890  push ebp / mov ebp,esp / push ecx / push esi
0xB76895  push 3                  ; ★ 标签号
0xB76899  call 0xB76310           ; 校验 tag（读 1 字节子类型）
0xB7689E  test al,al / je 失败
0xB768A2  push <字节数> / lea [ebp-4] / call 0xB75E80   ; 读定长
```

### 1.2 全表（**本卷独立枚举**）

| tag | 类型 | 读器 | 字节 | 备注 |
|---|---|---|---|---|
| `1` | bool | `0xB76850` | 1 | |
| `3` | u8 | `0xB76890` | 1 | |
| `6` | u16 | `0xB768D0` | 2 | |
| `7` | i32 | `0xB76910` | 4 | |
| **`8`** | **u32** | **`0xB761E0`** | 4 | ★ 最常用 |
| `10` (0xA) | u64 | `0xB769A0` | 8 | |
| **`13` (0xD)** | **f32** | **`0xB769F0`** | 4 | ★★ **子代理新发现，本卷确认** |
| `16` (0x10) | string | `0xB76A30` | 变长 | **NUL 结尾**（非长度前缀） |
| `19` (0x13) | blob | `0xB76AF0` | 变长 | 内嵌**长度字段自身的 u32 tag** |
| `23` (0x17) | ? | `0xB76BE0` | — | 未定 |

### 1.3 f32 的独立证据

```asm
0xB769F0  push 0xD                ; tag = 13
0xB769F9  call 0xB76310           ; 校验
0xB76A02  push 4 / lea [ebp-4] / call 0xB75E80   ; 读 4 字节
0xB76A13  fld  dword ptr [ebp - 4]   ; ★ 浮点加载
0xB76A19  fstp dword ptr [ecx]       ; ★ 浮点存储
```

★★ **`fld`/`fstp` 是浮点的铁证** ⇒ `0x0D` = f32。

★ 这与我在 171–229 卷一直使用的 `0D`=f32 假设**吻合**（此前未独立验证过）。

## §3 ★★★ 服务器边界（本轮最重要的综合）

### 3.1 两个"服务端"

| 服务端 | 地址 | 我们能否控制 | 承载 |
|---|---|---|---|
| **大厅服** | `127.0.0.2:3074` | ✅ 我们的 `lobby_server.py` | 登录、服务 3/4/6/8/9/10/11/12/21/28/29/68/71/80/93/102 |
| **HTTPS 认证服** | `formal-zone-auth.codol.qq.com` | ❌ **腾讯** | **booking 应答（`mmbook`）** |

★ 依据：151/152 卷（`[0x84ABB14]` = TLS 客户端，域名腾讯）+ 229 卷（`0x7F1110` 读该全局）。

### 3.2 booking 的真实通道

```
客户端 HTTPS booking
  → 腾讯 formal-zone-auth.codol.qq.com
  → 应答含 u64 + "mmbook accepted"
  → 0x7F1110 strcmp "mmbook"
  → 0x632680（门4/5 校验 u64、门6 校验串）
  → 构造 StartGame
```

★★★ **⇒ 房间开局依赖腾讯认证服务器，本地 3074 无法提供。**

★ 这**解释了**为什么前几轮"改 `lobby_server.py` 的 `mmbook` 分支"一直没有效果。
