## 二、本卷真正新增的两条

### (a) `memberCount = 0`（我这次才注意到）

```python
# 11/13 createRoom
ob.u64(ROOM_ID); ob.u32(0); ob.u32(18); ob.u64(ROOM_SECOND_ID)
#                            ↑ memberCount = 0
```

**房主创建的房间里，人数是 0。**

这行代码 160 卷我就读过，当时写的是「✅ 有对象」，**没注意这个 0 的含义**。

它是**整条链最早的错误点**——房间一创建，状态就已经不对了。

### (b) `roomId` 有两个不同表示

```python
# 11/13  → 0x1122334455667788     (u64)
# 21/5   → str((sid & 0x7FFFFFFF)|1) = "1449428873"   (十进制串)
```

**同一个房间，客户端从两条路径拿到两个 ID。**

源码注释自己说了后果：「否则 `_strtoui64(room.id) == last_kick_room_id` → 每次加入都被判被踢」。

**⇒ 可能一进房就被判被踢。**

## 三、关于 `security_key`，我要修正 163 卷

163 卷我说：**「客户端不用会话里的 key，用的是 ECDH 派生」**。

本卷查了客户端 ECDH 的输入：`0xBA05A0` 里是**硬编码的 24 字节曲线参数 + 6 个索引**（`0x90F542AD` / `0xE621A488` / …）。

**⇒ 确实不读会话里那 16B。**

**但**——`build_session_record` 里那个 16B 字段是客观存在的，大厅也在填。

**所以更准确的表述是**：

> 客户端 ECDH **不用**那 16B；
> 但那 16B 是干什么的，**本卷确定不了**。

**为什么确定不了（这是实测结论，不是偷懒）**：

- 会话记录里的 `0xD692ADAB`（query criterion）→ 镜像里 **0 命中**
- 会话记录里的 `0x0C0DE001`（room id 标记）→ 镜像里 **0 命中**

**⇒ 258 字节会话记录解码时没有常量锚点可用。它一定是位流/变长解码的。**

**所以这条的状态是「查过，确认无可定位锚点」，而不是「没查」。**

## 四、这五道闸门的因果顺序

```
① memberCount = 0                ← 房间一创建就错
      ↓
② roomId 两个表示                ← 进房/踢人判断可能误判
      ↓
③ ready 判据错（16B vs 2B）      ← 点准备，服务端识别不到
      ↓
④ game start 是三方抓包常量      ← 就算推了，内容也不对
      ↓
⑤ security_key 两边算法不同      ← 就算连上 28960，HMAC 也过不去
      ↓
   战斗服 0 收包
```

**最后那句「战斗服 0 收包」，源码注释里真的写着**：

```python
# codol_crypto.py:811-812
#   但 PvE coop 客户端仍停在"战斗开始", 战斗服 0 收包。
```

**⇒ 前人已经观察到这个现象，但归因到了「game start 数据不对」（只看到闸门④），没看到①③⑤。**

## 五、所以这一段「清楚了吗」

**清楚了，而且能给出确定的因果链。**

但要说清一件事：

> **「清楚」在这里 = 知道有五道闸门、知道每道在哪一行、知道它们串联。
> 不等于「知道每一道的正确值是什么」。**

具体：
- **① memberCount 该是几** → 逻辑上应是 1，**未验证**
- **② roomId 是否需一致** → **未验证**
- **③ ready 判据** → **已解（`02 18`），只差改代码**
- **④ game start 载荷** → **未解**
- **⑤ security_key 的正确算法** → **部分解**（客户端算法已明，战斗服要改成同款）

**⇒ 五道闸门里：1 道已解待改(③)，1 道部分解(⑤)，3 道未验证/未解(①②④)。**

## 六、方法论（本卷新增三条）

1. **★★ 分段查清 ≠ 整链清楚。** 五段各自「✅」，串起来是「五个闸门全关」。
   **每次收口一个环节，都该顺手问一句：它前后两端是谁？对上了吗？**
2. **★★ 「有对象」不等于「对象正确」。** 160 卷我判 `11/13` 是「✅ 有对象」，但没看 `memberCount=0` 的语义。
3. **★★ 查不到要给出「为什么查不到」的证据。** 本卷两个魔数 0 命中 ⇒ 证明「解码器无常量锚点」，这比说「没找到」强得多。
