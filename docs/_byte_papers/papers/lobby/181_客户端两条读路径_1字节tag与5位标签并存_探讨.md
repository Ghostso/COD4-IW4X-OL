# 181 探讨 · 我差点因为"同一个数字"又改错一版

## 一、这轮差点犯的错

178 卷我推出："`0x13` 是 **5 位字段标签**，值 19。"

这轮我检查 `build_room_push`，看到：

```python
T_BLOB = 0x13
def blob(self, p):
    self._t(T_BLOB)          # 写 1 个字节 0x13
```

**同一个 `0x13`，一处是 5 位，一处是 1 字节。**

我的第一反应是：**"有一处错了，得改。"**

差点就去改 `Buf` 的 blob 编码，或者改 `build_manifold` 的标签宽度。

## 二、停下来查了一步

我去看客户端**怎么读 `0x13`**，发现有两处：

```asm
; A 路径（Manifold 内部）
0x6256C0  push 3  / call 0xB774E0     → 读 5 位，值=3

; B 路径（blob 分帧）
0xB76310  push 1  / call 0xB75E80     → 读 1 字节
0xB7634D  movzx ecx, byte [ebp-0x55]
0xB76354  cmp ecx, 0x16
```

**两条路径，两个宽度。**

不是矛盾，是两层：

```
B 层：房间信道信封（1 字节 tag）
  └─ blob(0x13) 的负载
       └─ A 层：Manifold 位流（5 位标签）
```

**payload 里嵌的就是 Manifold。**

`build_room_push(..., build_startgame_payload(...))` 正是这样嵌套的。

## 三、如果我没查这一步

我会以为"两处冲突"，然后：

- 改 `Buf` 写成 5 位 → 信封层全废
- 或者改 `build_manifold` 写成 1 字节 → 位流层全废

**两种改法都会把本来正确的地方改成错的。**

★ 这比"没改"更糟。

## 四、教训

**同一个数值出现在两个地方，且宽度不同时，先问三个问题：**

1. 是不是两层嵌套？（本轮的答案：是）
2. 两处的读取入口是不是同一个函数？（`0xB774E0` vs `0xB76310`，不是）
3. 宽度差来自"设计"还是"错误"？（B 路径 `push 1` 明确读 1 字节，是设计）

**不要因为"数字一样"就假定"编码一样"。**

## 五、这轮的净收获

| 结论 | 状态 |
|---|---|
| A 层 `Manifold` = 5 位标签 + LSB-first | ✅（177/178/180） |
| B 层信封 = 1 字节 tag，与 `0xB76310` 一致 | ✅ **本轮确认** |
| 两层是**嵌套**关系（B 的 blob 装 A 的位流） | ✅ **本轮定清** |
| `build_room_push` | ✅ **无需修改** |

**找到了一条新的结构层次关系，且避免了一次错误修改。**

## 六、房间类的黑箱账（更新）

已静态闭合：

```
43 类写侧 / 线格式
srpc+0x4F4 = HMAC 会话对象
状态机 5 路输出
Manifold = 5 位标签 + LSB-first（无伪头）
信封层 = 1 字节 tag（与客户端一致）
两层嵌套关系
```

已找到并修掉的三处致命 bug：

```
1. ROOM_READY_BATCH 16B 常量（ol-mod 抓包）
2. _is_ready_bitstream 判据恒 False（漏 4 字节前缀）
3. BitWriter 伪 1 位 m_useDataTypes 头（整体错位）
```

**仍然无法闭合的（不是"没查"，是"类别不同"）：**

```
推送是否被客户端解析   → 需要 A/B 实机
格式是否真的对         → 需要真实样本
srpc 闸门开没开        → 需要运行时状态
```

## 七、关于"反复字节级扫荡到底"

这轮我做了三件事，都是"往上往下追到底"：

1. **往上**：从 `10 08 40 00 00` 追到 `kit_E8_OK/lobby_server.py:244` → 发现是自造常量（不是客户端数据）
2. **往下**：从 `0x625520` 追到 `0xB77B10` → `0xB77A70` → `0xB75D40`（位宽计算）→ 发现 4 参=0
3. **横向**：`0x13` 在两条路径的宽度 → 发现是两层嵌套

每一条都追到了"机器指令 + 参数取值"级别。

**但我要诚实说：这三条追完之后，房间类的"致命黑箱"数量没有减少。**

因为它们属于同一类——**编码层**。而致命黑箱在**行为层**：

> 客户端收到这条消息之后，到底做了什么？

这个问题，一条反汇编都回答不了。
