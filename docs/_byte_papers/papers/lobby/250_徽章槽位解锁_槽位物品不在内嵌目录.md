## §0 结论

1. **★★★★★ 徽章槽位与背包槽位是**同一套机制**：表驱动 item id + `0x5E3760` 拥有检查。**
2. **★★★★ 徽章 item id 表在 `0x8269B18`**（步进 12，共 27 项、22 项有效），解码式
   `item = rol32(B ^ A ^ [0xE4DD90], 8)`（`A=[+0]`、`B=[+8]`、`[+4]` 为存在标志）。
3. **★★★★ 22 个徽章槽位中 20 个已在库存**，缺 **2 个**：idx1 → item **60220**、idx2 → item **60221**。
4. **★★★★★ 四个「槽位解锁物品」（60027/60028/60220/60221）在 catalog / mkt_assets / 库存里**全都找不到**；catalog 的 600xx 段**正好在 60026 之后断开**。**

## §2 ★★★★★ `WL_GetMarketItemIdForBadgeIndex`（impl `0x7D7560`）

```asm
0x7D7560  push ebp / mov ebp,esp
0x7D7563  mov ecx, [ebp + 8]
0x7D7566  mov eax, [ecx + 0x10]
0x7D7569  mov eax, [eax + 0x10]        ; ★ badge 索引
0x7D756C  lea eax, [eax + eax*2]       ; eax = idx * 3
0x7D756F  cmp byte ptr [eax*4 + 0x8269B18 + 4], 0   ; ★ 存在标志
0x7D7577  lea eax, [eax*4 + 0x8269B18]              ; ★ 表基址（步进 12）
0x7D7580  je  0x7D7592                 ; 标志==0 → 返回 0
0x7D7582  mov edi, [eax + 8]
0x7D7585  xor edi, [eax]
0x7D7587  xor edi, [0xE4DD90]          ; ★ 种子
0x7D758D  rol edi, 8                   ; ★ 循环左移 8
0x7D7594  ... 写入返回对象
```

**⇒ 表项 = `{u32 A; u8 exists; u32 B}`，item id = `rol32(B ^ A ^ 0x74BDDE03, 8)`。**

## §8 方法论

1. **★★★★★ RTTI 名字表是"客户端意图"的索引。** 249 卷靠 `...ForLoadoutIndex`，本卷靠 `...ForBadgeIndex` —— **同一命名族 ⇒ 同一机制**，一次推断两次命中。
2. **★★★★ 表长度必须用「字段值域」界定，不能按固定步进一直读。** 徽章表读 27 项后 `[+4]` 变成 100（ASCII 字符），那是**后续字符串数据**；再往下读就会解出 `3185558132` 这种荒谬 item id。
3. **★★★★ 「不在目录里」不等于「不该有」。** 60027/60028 这类**槽位解锁物品**本来就不是商品，是服务端应直接授予的 item。**目录里没有是正常的，库存里没有才是 bug。**
4. **★★★ 断开点本身是证据。** catalog 的 600xx 段**正好在 60026 之后跳过 60027/60028** —— 这个"整齐的缺口"比"随机缺失"更能说明它们是另一类东西。
