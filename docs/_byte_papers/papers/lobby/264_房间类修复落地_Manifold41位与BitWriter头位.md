### 1.1 本轮独立取得的机器码证据

**写侧 ctor `0xB778E0`**（VA 直读）：

```asm

0xB7795B  mov   byte [esi+0x21], al       ; ★ +0x21 = flag（唯一写点）
0xB7795E  push  1                         ; 位数 = 1

0xB77964  je    0xB77970                  ;   flag=0 -> 源=0x00
0xB77966..6E  ... mov [ebp-0xD],0xFF      ;   flag!=0 -> 源=0xFF

0xB7797E  mov   dword [esi+0x1C], 1
```

**读侧 ctor `0xB779A0`**：

```asm
0xB779CD  xor   eax, eax
0xB77A02  mov   byte [edi], al            ; ★ +0x21 = 0  ← 不是第 3 参！
0xB77A04  cmp   byte [ebp+0x10], al       ; 第 3 参只决定分支
```

⇒ **读对象的 `+0x21` = 载荷第 0 位**。房间载荷第 0 位 = 0 ⇒ `+0x21=0`。

**`W_TAG` `0xB77B10` / `R_TAG` `0xB774E0` 的总开关**：

```asm
0xB77B13  cmp   byte [ecx+0x21], 0
0xB77B17  je    0xB77B28                  ; 写侧：==0 -> 直接 ret，一位不写
...
0xB774F0  cmp   byte [ecx+0x21], 0
0xB774F4  mov   al, 1
0xB774F6  je    0xB7754F                  ; 读侧：==0 -> 直接 al=1 返回，一位不读
```

### 1.2 41 位怎么来的

Manifold 写侧 `0x625520` 的执行序：`W_TAG(3)`、`W_VAL(type,8)`、`W_TAG(8)`、`W_VAL(count,32)`。
`+0x21==0` ⇒ 两个 `W_TAG` 共 10 位**全跳空**，只剩 8+32=40，加 ctor 头 1 位 = **41**。

| 场景 | `+0x21` | 组成 | 位 | 字节 |
|---|---|---|---|---|
| **房间服务端应答** | **0** | 1 + 8 + 32 | **41** | **6** |
| flag=1 消息（如 StartGame） | 非 0 | 1 + 5+8 + 5+32 | 51（Manifold 形态） | 7 |

## §2 R20 落地：`build_manifold`

`run_codol_001\runs\ROOMFIX_20261103_1239\kit\codol_crypto.py`：

```python
def build_manifold(msg_type, items=()):
    bits = []
    def wb(val, n):                      # LSB-first
        v = (val or 0) & ((1 << n) - 1)
        for k in range(n): bits.append((v >> k) & 1)
    cnt = len(items) if hasattr(items, "__len__") else 0
    wb(0, 1)          # ctor 1 位头 = 0（编解码总开关 OFF）
    wb(msg_type, 8)   # W_VAL(type,8)    （原 W_TAG(3) 已跳空）
    wb(cnt, 32)       # W_VAL(count,32)  （原 W_TAG(8) 已跳空）
    for it in (items or ()):
        ...           # 标签全跳空
```

| 模型 | 头位 | 位宽 | 字节 |
|---|---|---|---|
| R19（无头） | — | 867 | **109** |
| R21（头=1） | 1 | 868 | **109** |

两者都 `ceil(/8)=109`，**只靠字节数分不出来**。靠**位级对齐**分：

```
R21(头=1)：bit0=1(=+0x21) | bits1..5=tag3=3 ✓ | bits6..13=val=3 ✓
R19(无头)：客户端读 bit0..4 当 tag3 = 7 ✗（应为 3）
```

## §7 方法论

1. **★★★★★ 本地逆向内部冲突时，亲手重跑全部相关函数，不采信任何单卷。** 175/177/239/242/245 五个结论，本轮直读机器码定案 41 位。
2. **★★★★ `push imm` 要追到"它被谁消费"。** `0x637026 push 1` 是 ctor 第 3 参（只选分支），不是 `+0x21` 的写值。
3. **★★★★ 位宽必须把编码路径上每一次写位都列出来，包括被 `je` 跳过的。** 漏一个 `je`（`W_TAG` 的）就差 10 位。
4. **★★★★ 字节数相同 ≠ 位宽相同。** 本轮**两个**实例：867/868 都是 109B；41 位(6B) vs 其它补位可能同长。判据必须是**位级顺序**。
5. **★★★ "恢复被删的东西"也是修复。** R19 删一个 bit，字节数不变、脚本全绿，却是错位 bug。
6. **★★★ 只改副本 + 前后受保护哈希一致**，才谈得上"落地"。

### 8.1 复核①：vtable 归属**证实**，但「49 位」**证否**

- **证实**：`0xDC74F8` 前两槽 = `0x625520`(serialize) / `0x6256C0`(deserialize)，
  `0xDC751C` = `0x625BE0`(StartGame serialize) —— 与主对话一致（本轮独立读 vtable）。
  `0x637000` 构造的对象确为 Manifold（vt `0xDC74F8`），且 `0x637000` 是读路径
  （经 `0x6371F0`，注册于 `[roomObj+0x25B8]`，即房间信道报文处理器）。
- **证否**：主对话的读序漏了 `0x63706B`。容器在 `cmp eax,1` **之前**执行
  `b9 01 00 00 00`(`mov ecx,1`) + `89 4e 1c`(`mov [esi+0x1c],ecx`) —— **把读游标重置回 1**。
  随后 Manifold `0x6256C0` 从游标 1 起**重读同一个 8 位类型**。
  ⇒ 容器是「**peek 类型 → 回卷 → 交给专属反序列化器重读**」，**没有多出 8 位**。
  线上 = `[1 位头][type8][count32]` = **41 位 = 6 字节**。**R20 不改。**

原始字节（本轮 `tools\varef.py hex 0x637060 0x15`）：
```
54 00 0f b6 45 ff   b9 01 00 00 00  89 4e 1c  3b c1  0f 85 ...
                    mov  ecx,1       mov [esi+0x1c],ecx  cmp eax,ecx / jne
```
`0xB772E0` 的 `0xB773A6 add [edi+0x1c],esi` 证明 `[obj+0x1C]` 是**会前进的读游标**，
所以把它置 1 就是**回卷**，Manifold 重读 bits1..8。

★ **主对话已接受本驳回并自纠**（2026-11-03）：它重看 `0x63706B/0x6370C6` 两处同为
`mov dword [eax+0x1c],1`，确认是回卷，宣布其「49 位」作废。⇒ **R20 保持 41 位。**

### 8.3 R22（type==1?）—— 判定「静态不可达」，不改值

容器 `0x637000` 对 peek 到的 type 分流：**`type==1` → Manifold 读器 `0x6256C0`**
（`0x63706E cmp eax,1 / jne 0x63718D`；循环里 `0x637106` 同形）；
**`type!=1` → `0x634870`**。`0x634870` **自己也 peek+回卷**（`0x6348CE/0x6348D1`），
再走**两级分派**：

```
0x6348D8  mov   esi, [eax*4 + 0x82E1458]   ; 一级：type -> handler 指针（BSS，运行期填充）
0x6348E5  test  esi,esi / je 0x63494A      ;   槽为空 -> 回落二级
0x63494A  cmp   eax,0x2e / ja 0x636EBA     ; 二级：type > 0x2e(46)?
0x634953  jmp   dword [eax*4 + 0x636F3C]   ;   静态跳转表（[0]=0x636F02 仅清理）
```

★ **两级都真实存在**：`0x82E1458` = 一级（BSS，静态前 12 项全 0，运行期填）；
`0x636F3C` = 二级（**磁盘镜像里的静态跳转表**，`0x636F02/0x636EBA/0x63495A/…`）。
**171 卷「`cmp eax,0x2e / jmp [eax*4+0x636F3C]`」记述的是二级，完全正确**；
本轮找到的一级 `0x82E1458` 是**新增**，不是「替代」。（早期口述把它说成
「更正 0x636F3C 归属」是**过度更正**，已作废——两张表是先后两级，不是一错一对。）

⇒ **type=0 的落点**：先查运行期 `0x82E1458[0]`；**为空**则落 `0x636F3C[0]=0x636F02`（仅清理）。
即：**若回包真走这条路，type=0 的回包在运行时可能被静默丢弃**（清理而无处理）。
这是「静态不可达」的**事实补充**，不是改动依据。

- **硬事实**：`0x6256C0` 是**唯一** Manifold 读器，且**只有 type==1 能到它**。
  ⇒ **若 6/5 回包被当 Manifold 读，其 type 必须是 1**；现用 0 ⇒ 只会进
  `0x634870[0]`（一个**非读器** handler）。
- **未证死**：「6/5 回包是否经由 `0x637000`」。`0x637000` 的父级 `0x6371F0`
  是注册在 `[roomObj+0x25B8]`（唯一写点 `0x63401E`，另有 `0x7E794B`/`0x7FA401` 两个
  `mov [reg+0x25B8]` 待定）的房间报文处理器；任务回包→该处理器的绑定**只有间接证据**
  （`build_room_push` 注释里的 `0x7F1060→0x7E7C90→0x6371F0`），**未静态闭合**。
- **落到哪条**：按主对话三选一 ⇒ **（c）静态不可达**。**不改值**（纪律：不用猜的改）。
  写清条件：**若回包走容器，type 必须为 1，0 即「回包被丢弃」级缺陷**；是否走容器
