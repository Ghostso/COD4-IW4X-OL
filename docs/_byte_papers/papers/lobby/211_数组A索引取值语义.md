# 211 · 数组 A 索引 `[dwRoomImp+0xE360]` 的取值语义：`-1` = 无效，`0` = 首个，`≥0` = 有效槽

> 卷次：211（房间类 · 索引字段语义定案）
> 结论：`[+0xE360]` 有 7 个写点，取值 `0xFFFFFFFF`（无效）/ `0` / `idx`（有效）。

---

| 地址 | 写入值 | 函数 | 语义 |
|---|---|---|---|
| `0x62C0E8` | **`0xFFFFFFFF`** | `0x62BF10` | 标记无效 |
| `0x62CD76` | **`0`** | `0x62CD30` | 重置为 0 |
| `0x62DF5E` | **`0xFFFFFFFF`** | `0x62DEE0` | 标记无效 |

★ 3 个"动态写"集中在 `0x62F840` 和 `0x637720` 两个函数。

---

## §1 取值语义

| 值 | 含义 | 证据 |
|---|---|---|
| `0xFFFFFFFF` (-1) | **无有效槽** | 5 处清零都用 -1 |
| `0` | **第 0 槽** | `0x62CD76` / `0x62F975` |
| `1..49` | **有效槽** | `0x62F902` / `0x637720` |

★★ **`-1` 是"无"哨兵，与 `0xDEADBEEF` 同族（都是 debug 标记）。**

★ 注意：`0` 既是"重置值"又是"第 0 槽" —— **语义歧义**。
⇒ 需要看 `[+0xE360] == 0` 时是否走"无槽"分支。

---

## §2 `0x637720` = 核心索引管理器

```asm
0x63776A  mov dword [esi+0xE360], ebx    ; 写
0x637855  mov ecx, [esi+0xE360]          ; 读
0x63787E  mov dword [esi+0xE360], ecx    ; 写
0x6378AB  mov dword [esi+0xE360], ebx    ; 写
```

★ 同一函数里 3 次写 + 1 次读 ⇒ **它是"槽位分配/切换"函数**。

---

## §3 `0x62F840` 也管索引

```asm
0x62F902  mov dword [ebx+0xE360], eax    ; 设置
0x62F975  mov dword [ebx+0xE360], 0      ; 重置
0x62F984..0x62FB01  多次读
```

★ 这是 `0x62FB3E`（StartGame 构造点 1）所在函数！
⇒ **它先设索引，再构造 StartGame。**

## §5 对服务端的意义

★★★ **客户端有 50 个 matchmaking 槽，`[+0xE360]` 是"当前用哪个"。**

服务端发 StartGame 时，客户端会用它**当前索引**对应的槽来解析。
⇒ **如果服务端的 StartGame 内容与该槽的状态不匹配，解析就会失败或被丢弃。**

★ 这是"服务端无法凭格式正确就成功"的又一层原因。

## §6 方法论

1. **★★★ 索引字段的写点能直接给出"合法取值域"。** `-1` + `0` + 动态值 ⇒ `-1` 是哨兵。
2. **★★ 一个字段既是"重置值 0"又是"合法索引 0" ⇒ 必有额外的有效性判据。** 需查读取方。
3. **★★ 同一函数里 3 次写同一字段 ⇒ 它是状态机/分配器。**
