## §1 `0x632680` 是"收到 mmbook accepted 后开局"的虚函数

结合 214 卷的 6 道门：
```
门1 [esi+0x278] != 0
门2 clientState < 3
门3 [esi+0xE360] >= 0
门4 [ebp+8]  == MMI+0x168
门5 [ebp+0xC] == MMI+0x16C
门6 strcmp([ebp+0x14], "mmbook accepted")
```

★★★ **这是 `dwRoomImp` 的一个虚方法，由网络收包路径调用，参数是"推送报文解析出的 u64 + 字符串"。**

### 3.2 客户端要求

| 门 | 要求 | 服务端现状 |
|---|---|---|
| 1 | `[+0x278] != 0` | 客户端侧开关 |
| 2 | `clientState < 3` | 客户端侧状态 |
| 3 | `[+0xE360] >= 0` | 客户端侧索引 |
| **4** | **参数1 == MMI+0x168** | ❌ **服务端没提供 u64** |
| **5** | **参数2 == MMI+0x16C** | ❌ **服务端没提供** |
| **6** | 参数3 == `"mmbook accepted"` | ✅ 字符串对 |

★★★ **门 4/5 缺 u64 ID —— 这是最可能的根因。**

★ 但要确认 `[ebp+8]`/`[ebp+0xC]` 是否真的来自服务端推送。如果来自客户端自己（如 session id），则服务端无需提供。
