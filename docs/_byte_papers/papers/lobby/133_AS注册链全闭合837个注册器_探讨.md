# 133 探讨 · 我找了三卷的"表"，原来根本不存在

> 配套：[133 · AS_* 注册链全闭合](133_AS注册链全闭合837个注册器.md)
> 主题：**一个不存在的东西，最难证明它不存在。**

---

## 一、131、132 都在找同一张表

- **131 §八**：找到 `.rdata 0xDC2718` 的短名池，找到唯一引用点 `0x64F6A3`，写"注册器宿主对象未找到"。
- **132 §八**：再找一次，写"映射表本体没找到"。
- **132 §十 1**："短名 → 对象的映射表本体未找到"。

★★ **两卷、三次，我把同一个缺口写进"诚实边界"。每一次都是同一个预设：存在一张表。**

这张表**不存在。**

---

## 二、真相：名字、对象、vtable 在同一个函数里焊死

```
0x64F660  mov [eax], 0x00DC8910    ← 对象的 vtable（就是 132 那个 17 字节单元）
0x64F6A2  push 0x00DC2730          ← "JoinRoom"
0x64F6A8  call edx                 ← registerFunction(容器, "JoinRoom", 对象, bool)
```

**三者同处一个 0xB9 字节的函数。** 没有表，也不需要表 —— **每注册一个接口就生成一个函数**，名字是 `push` 立即数。

★★ **838 个注册器 = 838 次"手工焊死"。**

---

## 三、我为什么一直找不到

因为我在找**结构**：

> "应该有一个 `[名字指针][对象指针]` 的数组，像 116 卷的服务表那样。"

★★ **这个预设来自 116 卷的成功经验**（`0xA4E8F8` 的 `[name_ptr][enabled]` 20 项开关表）。我在一个"批量声明"的场景里见过表，就以为所有"名字 ↔ 对象"关系都应该是表。

**但这里是"逐个注册"，不是"批量声明"。**

★ 这和 115/116 卷「静态 `{102,名}` 直表已穷举证明不存在（运行时注册）」是**同一类**：号↔名可以不在静态面，因为运行时用代码建立。**我当时记了这条教训，但没有把它迁移到 AS_ 面上。**

---

## 四、破局靠的不是"找得更仔细"，是换了一个动作

我做了什么？

1. 先有 829 个 vtable（132 的判据）。
2. **对每个 vtable，找它被"立即数写入"的位置。**
3. 那个位置的函数 = 注册器。

★★ **"立即数写入 vtable" 这个动作本身就是注册器的指纹。** MSVC 只会在两类地方写 vptr 常量：构造函数、注册器。而这里两种情况合并成一种 —— **每个接口一个构造函数兼注册器**。

★ 判据是**行为指纹**，不是**结构形状**。这跟 130 卷"绝对立即数 0 引用判死活无效"是同一条线：**结构的引用计数不可靠，行为的位置才可靠**。

## 五、837 / 838 / 0 这个三元组

```
独立注册函数      838
被 E8 rel32 调用  837
无归属调用点        0
```

★★ **"0 个无归属"是本卷最硬的一条。**

它证明的不是"我找到了 837 个"，而是"**不存在第 839 个走别的路的对象**"。

★ 如果我只报"837 个被调用"，那是**正向证据**（我找到了这些）。加上"0 个无归属"，才是**反向证据**（没有漏网的）。**正向证据证明我找到了什么，反向证据证明我没漏掉什么。**

这个项目里我犯的几次错，都是只有正向证据：
- 124 卷：找到 `wfUD3"` 的字面出现，没查"有没有不该出现的"
- 126 卷：找到 RSA 私钥，没查"它是不是用在这"
- 131 卷：找到 806 行，没查"步进对不对"

★★ **⇒ 从现在起，任何"找到了 N 个"的结论，必须同时给出"多少个没归属"，否则不写。**

## 六、132 的 View 分组被独立验证

132 §八·补 从 RTTI 名里读出 `UiCppMatchSelectView::Init` 注册 28 个。

133 从**另一个方向**数：外层函数 `0x73DF20` 调用了 **28 次**注册器。

★★ **两套完全独立的证据（RTTI 局域类名 / 调用次数）给出同一个 28。**

★ 这是本卷唯一一次"互证"，也是我最有信心的一条。**但我在论文里写明它是"次数对齐推断，非直接证据"** —— 因为我没有把 `0x73DF20` 的入口与 `Init@UiCppMatchSelectView` 的地址直接对上（`::Init` 没有独立符号）。

★★ **强度足够的推断也要标注成推断。** 否则下一卷会把它当事实引用。

## 九、方法论（本卷新增）

1. ★★ **"找不到 X"要先问 X 该不该存在。** 表是**声明式**的产物；如果是**程序式注册**，就没有表。
2. ★★ **找注册器用"立即数写入 vptr"这个行为指纹**，不要找结构形状。
3. ★★ **任何"找到 N 个"必须配"多少没归属"**。正向证据 + 反向证据才构成闭合。
4. **同一事实的两套独立证据（RTTI 名 / 调用次数）互证，是最高强度**；但即使成立也要标注推断等级。
5. **局部事实不能升级成全局判断**（DMZ vs PvE）。
6. **旧卷的教训要跨域迁移**：116 的"运行时注册无静态表"早写过，我没有把它用到 AS_ 面。

## 十、这一卷最大的收获

**我连着三卷把"找不到"写进诚实边界，而没有去质疑这个"找不到"本身。**

★★ **"诚实边界"有时候是一种拖延** —— 它让我觉得我诚实地面对了缺口，于是不再深挖。**但如果缺口连续三卷都填不上，那不是缺口深，是我的预设错。**

★ 判断信号很明确：**同一个缺口出现三次以上 ⇒ 停下来检查"我要找的东西该不该存在"。**

★ 这个项目里，"找不到"被我连续记录过多次：
- 102 的 `{102,名}` 表 → 不存在（运行时注册）
- AS_ 的名字映射表 → 不存在（逐个注册器）
- `sendGpuLatchedSettings` 的命令处理器注册项 → 仍未找到（可能同样不存在，走 Cbuf）

★★ **前两个的解法完全一样：不是没找到，是它不长成我以为的样子。第三个大概率也是。**
