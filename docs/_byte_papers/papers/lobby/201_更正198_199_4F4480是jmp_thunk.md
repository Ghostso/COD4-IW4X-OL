# 201 · ★★★ 更正 198/199：`0x4F4480` 是 `jmp 0xB76E50` 的 thunk，不是析构函数

> 卷次：201（**第六次更正卷**）
> 方法：从函数起点反汇编，看到 `0x4F4480 jmp 0xB76E50` —— **只有 1 条指令**
> 结论：`0x4F4480` 是 thunk；我 198/199 卷"看到的析构"实际是 `0x4F4490`/`0x4F44A0` 的**错位反汇编**。

---

## §0 真相

```asm
0x4F4470  xor eax, eax / ret              ; 一个空函数
0x4F4473..0x4F447F  int3 ×13
0x4F4480  jmp 0xB76E50                    ; ★★★ 只有 1 条指令 = thunk
0x4F4485..0x4F448F  int3 ×11
0x4F4490  add ecx, 0x24 / jmp 0xB76E50    ; 另一个 thunk（+0x24）
0x4F4498..0x4F449F  int3 ×8
0x4F44A0  push ebx / push esi / ...       ; ★ 真正的函数体在这里
```

★★★ **`0x4F4480` 只有 `jmp 0xB76E50` 一条指令。**
我在 198/199 卷从 `0x4F4480` 起反汇编 0x200 字节，
**越过 `int3` 填充读到了 `0x4F44A0` 的函数体**，把它当成了 `0x4F4480` 的内容。

### 0.1 `0xB76E50` 是什么

```asm
0xB76E50  mov dword [ecx], 0xDEADBEEF
0xB76E56  ret
```

★ **销毁哨兵**：把一个字段写成 `0xDEADBEEF`（经典 debug 标记）。

⇒ `0x4F4480`（`jmp 0xB76E50`）= **把 `this+0` 写成 `0xDEADBEEF` 的 thunk**
⇒ `0x4F4490`（`add ecx,0x24; jmp`）= **把 `this+0x24` 写成 `0xDEADBEEF`**
⇒ 记忆条目 `codol-dwroom-msgtype-table` 提过 `DEADBEEF 销毁哨兵`，与此吻合。

---

## §1 真正的函数体在 `0x4F44A0`

```asm
0x4F44A0  push ebx / push esi / mov esi,ecx / push edi
0x4F44A5  lea ecx, [esi+0xD8] / call 0xB76E50   ; +0xD8 = 0xDEADBEEF
0x4F44B0  lea ecx, [esi+0x24] / call 0xB76E50   ; +0x24 = 0xDEADBEEF
0x4F44B8  mov eax, [esi+0x20] / mov edi, [esi+0x18]
0x4F44C4  ... call 0xB76E50（逐个，步进 0x84）
0x4F44D4  call 0xB74240（free ptr）
0x4F44DF  mov [esi+0x18], 0 / mov [esi+0x20], 0 / mov [esi+0x1C], 0
0x4F44E8  mov eax,[esi+0x10] / mov edi,[esi+0x08]
0x4F44F7  ... call 0xB75AC0（逐个，步进 4）
0x4F4504  call 0xB74240（free ptr）
0x4F4511  mov [esi+0x08], 0 / mov [esi+0x10], 0 / mov [esi+0x0C], 0
```

★ **这才是真正的析构函数**（`0x4F44A0`），它：
- 把 `+0xD8` / `+0x24` 打成 `0xDEADBEEF`
- 释放 `+0x18` 数组（元素 `0x84`）和 `+0x08` 数组（元素 `4`）

### 1.1 结构结论仍然成立（只是地址改了）

| 数组 | ptr | size | cap | 元素 | 地址 |
|---|---|---|---|---|---|
| A | `+0x18` | `+0x20` | `+0x1C` | `0x84` = 132 | ✅ 198 卷结论对 |
| B | `+0x08` | `+0x10` | `+0x0C` | `4` | ✅ 198 卷结论对 |

★ **198 卷的字段结构结论正确，只是"函数地址"标错了**（应是 `0x4F44A0` 不是 `0x4F4480`）。

## §2 但这个类仍然不是 MatchMakingInfo

`0x4F44A0` 操作的字段：`+0x08/+0x0C/+0x10`、`+0x18/+0x1C/+0x20`、`+0x24`、`+0xD8`
MMI ctor（`0x806B50`）初始化的：`+0x128`、`+0x1CC`、`+0x1B0~+0x1C8`、`+0x230`

★ **两组完全不重叠** ⇒ **`0x4F44A0` 确实不是 MMI**（199 卷结论保持）。

## §3 那 `0x4F44A0` 属于哪个类

★ `0x4F44A0` 在 `0x4F4010` 之后，**同属 0x4F4xxx 区但不同类**。

## §6 方法论

1. **★★★★★ 反汇编必须"从函数起点 + 遇 `ret` 即停"，不能"从某个地址读固定长度"。** 我从 `0x4F4480` 读 0x200 字节，越过 `int3` 填充读到了下一个函数。
2. **★★★ 看到 `int3` 填充必须停。** 它是函数边界标记。
3. **★★ `jmp <addr>` 单指令函数 = thunk。** 它本身不是逻辑。
4. **★★★ `0xDEADBEEF` 是销毁哨兵 —— 记忆条目 `codol-dwroom-msgtype-table` 已记录过。** 再次确认。
