# 连接状态查询 · 探讨：一个标志位决定一切

> 对应：`lobby/54_连接状态查询.md`

---

## 一、12 条指令，三个条件

```asm
mov ecx, [esi+0x4F4]      ; ① 连接对象
test ecx, ecx / je →0
call 0xba0780             ; ② 底层状态
cmp byte [esi+0x4F8], 0   ; ③ 认证标志
jne → return eax
cmp eax, 2 / jne → return eax
mov eax, 1                ; ★ 2 → 1
```

**最反直觉的是最后一行：`mov eax, 1`。**

**底层返回 2，但如果没有认证标志，就把它**降级**成 1。**

---

## 二、这个"降级"就是闸门

**如果只是"透传底层状态"，那连接完成就该返回 2。**

**但代码偏偏要在"未认证"时把 2 改成 1。**

**⇒ 这是一个明确的"未认证就不算连上"的设计。**

**⇒ `[esi+0x4F8]` 就是"认证成功"标志。**

---

## 三、与项目已有记录的吻合

`memory: codol-iips-must-be-enabled`：

> `enable_iips=0` ⇒ 6 秒必崩
> 改 1 后完整进大厅（`5E8=1→3`）

**现在的解释：**

```
enable_iips = 0
  ⇒ [esi+0x4F8] = 0（未认证）
  ⇒ 0xb7a670() 把 2 降级为 1
  ⇒ 0x8037d6 的 cmp esi,2 失败
  ⇒ [0x84aba50] 停在 0-4，到不了 5
  ⇒ 0x7f25b0() 返回 1 或 4，不是 3
  ⇒ [0x849ba34] 到不了 3
  ⇒ 房间不初始化
  ⇒ 6 秒崩（超时分支）
```

**⇒ 那条记录里的"改 enable_iips 就好"，本卷给出了完整机制。**

---

## 四、这条链的价值

**项目里有很多"改了就好了"的经验记录。**

**但"为什么改了就好"往往没有解释。**

**这次，`enable_iips=1` 的作用被追到了：
它让 `[esi+0x4F8]` 非 0，从而不被降级，从而进大厅。**

**⇒ 从"经验"变成"机制"。**

---

## 五、还差最后一小步

**`[esi+0x4F8]` 是谁写的？**

**如果它由 `enable_iips` dvar 直接决定，
那整条链就彻底闭合了。**

**⇒ 下一卷的任务。**

---

## 六、方法论收获

> **"降级"比"缺失"更能说明设计意图。**

**如果代码只是"返回 0 表示失败"，那只说明"没连上"。**

**但代码是"拿到了 2，却主动改成 1" ——
这说明作者明确区分了"连上"和"连上且通过校验"。**

**⇒ 这种"多一步判断"的地方，往往是真正的业务闸门。**

## 七、本轮的完整链（九层）

```
[esi+0x4F4] 连接对象
  [esi+0x4F8] 认证标志  ← 最后一个未知
    ↓
0xba0780() 底层状态
    ↓
0xb7a670() == 2
    ↓
[0x84aba50] == 5
    ↓
0x7f25b0() == 3
    ↓
[0x849ba34] == 3
    ↓
[0x849ba30] == 3
    ↓
房间初始化
```

**每一层都有地址、有条件、有反汇编证据。**
