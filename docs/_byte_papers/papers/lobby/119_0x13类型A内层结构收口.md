## §0 结论

`11/4` 的 `0x13` blob，剥掉外层 `[08][u32 内容长][内容]` 后，内层**严格二分两族**，本卷全部解出：

| 族 | 首字节 | 条数 | 结构 | 语义 |
|---|---|---|---|---|
| **room 族** | `0x02` | 195 | `[02][变体][长度字段 u32][u16 0][数据]` | **房间数据块**（含坐标 float32 + 回环端点 `127.0.0.1:28960`） |
| **ready 族** | `0x18` | 66 | `[10B 固定魔数][u16 递增计数][1B 标志][4B 0]` = 17B | **ready 就绪记录**（= 109 卷 `blob[4]==0x18` 判据的真身） |

★ **一句话**：`02 0X 00 00` 的 `02` 是**族标签**（room），`0X` 是**子变体**（02/04/06/08，偶数），`00 00` 是**长度字段的高字节**（该字段 `u32@[4:8] == (内容长-10)<<10`，等价 `u16@[5:7] == (内容长-10)×4`，**112/112 精确**）。它不是"类型码+元素数×2"，而是 `[族][变体][长度字段]` 的**三层头**。

## §1 room 族（`0x02`，195 条）：三层头 + 数据体

### 1.1 头部结构

```
inner := [02][变体 V][00 00][u32 长度字段][u16 二段][数据体]
           b0  b1      b2-b3   b4-b7          b8-b9     b10..
```

★ 实测：`u32@[4:8] == (内容长 - 10) << 10`，等价 `u16@[5:7] == (内容长 - 10) × 4`（112/112）。
`b8-b9`（u16）是**第二个字段**，本卷未定语义（值 ∈ {0x0080,0x00a8,0x00d0,0x00b8,0x00e0,0x00a0,0x0078} 等，与长度不完全线性）。

`blob_room_final.txt` / `blob_len_law_meaning.txt` 的关键验证：

| 变体 V | 条数 | `u32@[4:8]==(len-10)<<10` | `u16@[5:7]==(len-10)×4` |
|---|---|---|---|
| `0x02` | 112 | **112/112 精确相等** | **112/112 精确相等** |
| `0x04` | 56 | 不等（见 §1.3） | 不等 |
| `0x06` | 17 | 不等 | 不等 |
| `0x08` | 10 | 不等 | 不等 |

★★ **`V=0x02` 的长度律是铁证（两条等价表述，各 112/112 零例外）**：
- `u32@[4:8] == (内容长 - 10) << 10`
- `u16@[5:7] == (内容长 - 10) × 4`（即 `u32 = u16 << 8`，二者一致）

`(len-10)` 是**去掉 10 字节头后的数据体字节数**。所以头部第 4-7 字节（u32）是一个**与数据体字节数严格线性的长度字段**，标度因子 `<<10`（等价 u16 处 `×4`）。

★ **诚实边界（不要误标为"位长"）**：`×4` **不是**位长（位长应是 ×8）。这个长度字段的确切单位/标度语义（`<<10`、`×4` 的物理含义）**尚未确定**——它是"体字节数的一个固定线性函数"，但为什么是 `<<10` 而非 `<<3`（=×8，真位长），本卷不下结论。可能是某种定点/分片标度，也可能是数据体另有 4-bit 或分片语义。**已知的硬事实是这条线性关系 112/112 精确，足以证明它是"长度字段"而非"元素数"。**

### 1.2 数据体：float32 坐标 + 回环端点

`blob_room_deep.txt` 对 len=141 最常见形态做 u32/float dump，`blob_119_evidence.txt` 全量统计：

- **合理 float32**（`1e-2 ≤ |f| ≤ 1e5`）在 room 族里出现 **61 种值**，Top：
  ```
  3.0 ×322 / 2.0 ×141 / -2.0 ×138 / 2.45 ×41 / 1.0 ×38 / -6.0 ×32
  -42.35 ×24 / -384.0 ×19 / 1036.01 ×19 / -512.0 ×19
  ```
  ★ 这些是**坐标/角度/尺寸**量级（-512、-384、1036、-42.35 是典型世界坐标；3.0/2.0 是缩放/计数）。
- **`7f 00 00 01` = 127.0.0.1** 出现 **16 次**，其后 u16 = **`0x7120` = 28960**（**CoD 系列默认游戏端口**）。
  ```
  7f 00 00 01  20 71  =  127.0.0.1:28960
  ```
  ★★ 这是**房间数据里内嵌的游戏服务器回环端点**——与 `106` 卷 67 字节 P2P 表（`192.168.85.1`）同族思路：房间数据块携带"连到哪台游戏服"的地址。

### 1.3 变体 04/06/08 的第二层（诚实边界 + 本卷新增定位）

`V=0x04/06/08` 的 `u32@[4:8]` **不**等于 `(len-10)<<10`。它们恒为固定小值（`0x00003000` / `0x00002800` / `0x00004C00` / `0x00009800` / `0x00010C00`…），而 `len` 变化很大（26→241）。

**说明**：`V=04/06/08` 的头部长度字段 **不是"整块长度"**，而是**"某个子块的长度"**。

★ **本卷新增定位**（`blob_v468_layer2.txt`）：`V=04/06/08` 的数据体几乎全部以**同一个固定前缀**开头：

```
68 ab 5b ab 63 ab 03 ...
```

这个前缀与 `V=0x02` 的部分数据体（如 `len=141` 的 `02 04 ... 68 ab 5b ab 63 ab 03 00 00 00 98 03 00 00 ...`）**是同一组字节**。⇒ **`04/06/08` 不是"另一种头部"，而是"`02` 族数据体里再嵌了一层"——即 `V` 只是数据体内部另一维度的分类，不是顶层族。**

★★ **位流假说已证伪**（`blob_v468_bitstream.txt`）：把 `V=04/06/08` 的数据体按 dwRoomMessage 位流（12 标签词表）解，offset 0/3/5/8 全部在头几个 tag 就撞到非法 tag。**它不是已知的位流格式**，是**第三套未解的内层序列化**。

**诚实结论**：`V=02` 的整块长度律已钉死（112/112）；`V=04/06/08` 是"嵌在数据体里的第二层结构"，其内部序列化器**本卷未解**，只钉死了"共用前缀 `68 ab 5b ab 63 ab 03`"这一事实。这是 INDEX §七 #6 的**残留部分**（不再是"`02 0X 00 00` 未解"，而是"`0x02` 数据体第二层未解"）。

## §2 ready 族（`0x18`，66 条）：17 字节固定记录

### 2.1 精确模板（66/66 逐字节）

`blob_final_verify.txt` + `blob_ready_and_fam.txt`：

```
inner(17B) := [18 1c 5a 98 d6 14 53 91 cf 01]  [u16 计数]  [1B 标志]  [00 00 00 00]
              └──────── 10 字节固定魔数 ────────┘  b10-b11     b12        b13-b16
```

- **魔数 `18 1c 5a 98 d6 14 53 91 cf 01`：66/66 完全一致**（`magic distinct = 1`）。
- `[13:17] == 00 00 00 00`：66/66。
- `b12`（标志）：66 条里只有 `0`（65 条）与 `1`（1 条，`acb5 01`）。★ 注意 `acb5 01` 这条同时是 `[10:13]` 值域最大值 `46508` —— 该条 b12=1 是该记录唯一的"非默认"。
- **`u16@[10:11]` 是递增计数**：同 run 内相邻 ready 记录 **Δ=2**（`blob_ready_and_fam.txt` 8 个 run 全部 Δ∈{2}）。★ `Δ=2` 与 `b12` 的关系：u16 步长 2 意味着 **LSB 恒为 0**，即该 u16 的低位可能是"另一位"（b12）占用的位 —— **16 位字段实际可能是 15 位计数 + 1 位标志位的紧凑打包**（Δ=2 是 15 位计数的自然步长，而 b12 是该 u16 的 LSB 之外的另一位）。本卷不把"15 位计数"当作已证结论，但 `Δ=2` 只来自"末位恒 0"这一点，**与 b12=1 的那条一起看，支持"16 位 = 15 位计数 + 1 位独立标志"的读法**（可信度：中）。

### 2.2 与 109 卷 ready 判据的闭环

`109` 卷判"ready 真判据 = blob 长 21 且 `blob[4]==0x18`"。本卷验证（`blob_119_evidence.txt`）：

```
完整 blob len==21 的条数 = 66;  其中 blob[4]==0x18 的 = 66  ← 100% 一致
17 字节 inner 且首字节 0x18 = 66
```

★★ **完全闭环**：`blob[4]` 就是内层首字节 `0x18`（外层 `[u32 len]` 占 4 字节，所以 `blob[4]` = inner[0]）。`109` 卷那条"偶然正确"的判据，本卷给出**结构级解释**：`0x18` 是 **ready 族标签**，`blob[4]==0x18` 是"这是 ready 记录"的直接判据——不是偶然。

### 2.3 递增计数 Δ=2 的含义

`u16@[10:11]` 同 run 内 Δ=2，跨 run 值域 `17202..117540`。
★ 这是 **ready 序号/时间戳低 16 位**（每发一条 ready 计数 +2）。值域跨 run 不连续 ⇒ **运行时计数，不是常量**（与 `117` 卷 `31902622` 同类：运行时值，本地不可命名具体来源）。

## §3 为什么之前解不开（认知修正）

`09` 卷说"`02 是类型码，`0X` 是元素数×2"。本卷纠正：

| 旧解读 | 本卷真解 | 依据 |
|---|---|---|
| `02` = 类型码 | `02` = **族标签（room）** | 66 条 ready 用 `0x18` 做族标签 |
| `0X` = 元素数×2 | `0X` = **子变体**（02/04/06/08） | 与长度无关（V=02 时 `0X` 恒 02 但长度 12..145 变） |
| `00 00` = 保留 | `00 00` = **长度字段的高字节**（`u32@[4:8]=(len-10)<<10`） | 112/112 精确 |

**根因**：`09`/`msg11` 只看了 `V=0x02` 的**少数短样本**（12/16/20 字节），没做全量长度律回归。短样本里 `(len-10)×4` 恰好等于 8/24/40，看起来像"小偶数"，掩盖了它是**长度字段**的事实。

★ **方法论**：`0X` 这种"看起来像小整数"的字节，必须做**全量长度回归**（`u16 == (len-k)×c`？），才能判定它是"计数"还是"长度"。本卷靠 112/112 精确相等，把"元素数"假说证伪。

## §4 §七 #8「9 个连续 0x00」收口

`zero_run_and_ready.txt` 全语料零 run 分布：

```

run=53 ×43,  run=54 ×8   ← 全部在 11/4
```

**最长 54 连零，出现在 `11/4` 的 room 数据里**，上下文是：

```
7f 00 00 01 20 71 [00 ×50] 7f 00 00 01 20 71 01 08
```

★★ 这就是 **room 数据里的两个端点槽**（`127.0.0.1:28960` + 50 字节零填充 + 再来一个端点）。**"9 个连续 0"只是 50 字节零填充槽的一段**——它不是独立黑箱，是**定长端点槽的空值填充**（与 `106` 卷 P2P 表 `00 ff 00 ff 00 00` 空槽同族：定长槽位 + 零/哨兵填充）。

⇒ §七 #8 从"未逐条核对"降级为"**已解：定长槽位零填充**"。
