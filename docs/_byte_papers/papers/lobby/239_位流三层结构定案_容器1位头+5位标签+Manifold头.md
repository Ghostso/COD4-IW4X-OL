# 239 位流三层结构定案：容器 1 位头 + 5 位自描述标签 + 50/51 位 Manifold 头

## 一句话结论

**`0xB778E0` 位流对象构造函数在 `[esi+0x21]` 写入**第 2 个参数**后，**无条件**通过 `0xB777C0` 写 **1 个位**（值 = `flag?0xFF:0x00`）；因此**每一次房间位流都以前置 1 位开头**，`Manifold` 头 = **51 位（不是 50 位）**；`0xB779A0`（从缓冲区建的读侧）在 `[ebp+0x10]!=0 && len!=0` 时走「按位拷贝」分支，**自己不消费这 1 位**——1 位头是「写侧多写、读侧多读」的不对称，不是可选项。

---

## 证据表

### E1 — 位流对象构造函数 `0xB778E0`（写侧，参数 = (容量位, flag)）

| 地址 | 指令 | 操作数 | 语义 |
|---|---|---|---|
| `0xB778E0` | `push ebp; mov ebp,esp` | — | 函数起点（`0xB778D4..DF` 全 `CC`，边界确认） |
| `0xB77917` | `mov eax,[ebp+8]` | 参数1 = 容量（位） | 缓冲容量 |
| `0xB7791A` | `test al,7` / `setne cl` | — | `++(容量/8 向上取整)` 存 `[esi+0xC]` |
| `0xB77948` | `mov al,[ebp+0xC]` | **参数2 = flag** | |
| `0xB7795B` | `mov [esi+0x21], al` | **`+0x21` = 参数2** | ★ 唯一写点 |
| `0xB7795E` | `push 1` | 位宽=1 | |
| `0xB77962` | `cmp al,bl` (`bl=0`) | | |
| `0xB77966` | `lea edx,[ebp-0xD]` / `mov byte [ebp-0xD],0xFF` | flag!=0 分支 | **值为 0xFF** |
| `0xB77970` | `lea eax,[ebp-0xE]` / `mov byte [ebp-0xE],bl` | flag==0 分支 | **值为 0x00** |
| `0xB77977` | `call 0xB777C0` | `(ptr, 1)` | ★ **无条件写 1 位** |
| `0xB7797E` | `mov dword [esi+0x1C],1` | | 读/写游标置 1（跳过自己写的这 1 位） |

**关键**：`0xB77962` 的 `cmp al,bl` 只决定**写 0xFF 还是 0x00**，两条路径都汇合到 `0xB77977` 的 `call 0xB777C0`。**没有跳过整个写的分支**。

### E2 — 缓冲区构造函数 `0xB779A0`（读侧，参数 = (buf, 长度位, 是否带位流头)）

| 地址 | 指令 | 语义 |
|---|---|---|
| `0xB779EF` | `lea edi,[esi+0x21]` | `edi` 指向 `+0x21` |
| `0xB77A02` | `mov byte [edi], al` (`al=0`) | **`+0x21` 先清 0** |
| `0xB77A04` | `cmp byte [ebp+0x10], al` | 参数3 == 0 ? |
| `0xB77A09` | `cmp ebx, eax` | 长度 == 0 ? |
| `0xB77A0D..1F` | `test bl,7/setne/shr/add` → `push eax; push [ebp+8]; call 0xB77710` | **按位整体拷贝**（`0xB77710` = `memcpy` 后推进 `+0x1C`） |
| `0xB77A24..2F` | `push 1; push edi; mov ecx,esi; call 0xB772E0` | **读 1 位写回 `+0x21`** |
| `0xB77A36..4D` | `push 1; push 0; call 0xB777C0` → 再 `push ebx; push [ebp+8]; call 0xB777C0` | 无头分支：先写 1 位 0x00，再整体写 |

**★ 不对称**：带位流头（参数3!=0）时，`0xB77710` 把**整块**（含那 1 位头）按位拷入，`+0x1C` = 总位数；随后 `0xB772E0(1)` 读第 0 位并写 `+0x21`，`+0x1C` 变 1（已越过）。**读侧不跳过、只消费**，所以头位是双方共同的第 0 位。

### E3 — `W_TAG` / `R_TAG`：5 位自描述标签（196/177 卷模型确认 + 补边界）

| 地址 | 指令 | 语义 |
|---|---|---|
| `0xB77B10` | `cmp byte [ecx+0x21],0` / `je 0xB77B28` | **`+0x21==0` 时完全是空操作**（只 `pop/ret`） |
| `0xB77B19..23` | `push 0; push 0x1F; push 0; push param; call 0xB77A70` | 4 参：`(s, tag, min=0, max=0x1F, hdrflag=0)` |
| `0xB77A70` | `cmp byte [ebp+0x14],0` / `je 0xB77AC3` | hdrflag=0 ⇒ **跳过 12/8+32+8+32 的「范围头」** |
| `0xB77AC3..CF` | `sub ecx,edi`（max-min）→ `call 0xB75D40`（位宽）→ `mov eax,0` / `je` / `inc eax` | `bits = bitwidth(max-min)` = `bitwidth(31)` = **5** |
| `0xB77AE9..F5` | `sub ecx,edi`（值 clamp 到 [min,max]）→ `call 0xB777C0(ptr, bits)` | **写 5 位** |
| `0xB774E0` | `cmp byte [ecx+0x21],0` / `mov al,1` / `je 0xB7754F` | `+0x21==0` ⇒ **直接返回 true，不读** |
| `0xB77630`（内层） | `cmp [ebp+0x14],0` / `je` ... `call 0xB772E0(bits)` | 读 `bits(31)=5` 位 |
| `0xB7769A..A6` | `cmp edi,eax` / `jne` / `cmp ebx,ecx` / `je` → `call 0x8435D0` | **读到的值 != 期望 tag ⇒ 打到空桩哨兵**（不 assert，静默） |
| `0xB776EC` | `add ecx,edi` / `mov [edx],ecx` | 返回 **bool**（`0xB7754C mov al,bl`） |

### E4 — 位宽（LSB-first）由 `0xB777C0` 逐位写

| 地址 | 指令 | 语义 |
|---|---|---|
| `0xB77810` | `mov eax,[esi+0x14]` / `and eax,7` | 当前位偏移 |
| `0xB77832..44` | `or dl,0xFF; shl dl,cl; sar eax,cl; or dl,al` | 保留位掩码 `(0xFF<<(k+off))|(0xFF>>(8-off))` ⇒ **数据落在低位 ⇒ LSB-first**（178 卷确认） |
| `0xB778AC` | `add [esi+0x14], ecx` | 推进写游标 |

### E5 — 逐位仿真（本卷独立复现 `0xB777C0`）

脚本 `_rev_analysis\_p232room\sim3.py`，按 E1/E3/E4 逐指令还原：

| 场景 | flag | 位流（hex） | 位数 |
|---|---|---|---|
| `Ready(0x10, v=1)` | 0 | `20 02` | **10** |
| `Ready(0x10, v=1)` | 1 | `07 44 08` | **20** |
| `Ready(0x10, v=0)` | 0 | `20 00` | 10 |
| `Manifold(type=0x0B, count=0)` | 0 | `16 00 00 00 00 00` | **41**（6 B） |
| `Manifold(type=0x0B, count=0)` | 1 | `C7 02 02 00 00 00 00` | **51**（7 B） |
| `Manifold(0x0B, 1 item, len=2, data=1802)` | 0 | `16 02 00 00 00 08 00 00 00 60 08 00` | 90 |
| 同上 | 1 | `C7 02 0A 00 00 00 08 26 12 00 00 00 C0 10 00` | 115 |

**位数逐项对账**：
- `Ready` flag=0：`W_TAG(3)`=0 位 + `W_VAL(8)`=8 + **头 1** + `W_TAG(1)`=0 + `W_VAL(1)`=1 = **10 位**
- `Ready` flag=1：5+8+1+5+1 = **20 位**
- `Manifold` count=0 flag=0：**头 1** + `W_VAL(8)`=8 + `W_VAL(32)`=32 = **41 位**（无标签）
- `Manifold` count=0 flag=1：1+5+8+5+32 = **51 位**
- `Manifold` 1 条 flag=0：41 + `W_VAL(1)`(has=0) = 1 + `W_TAG(8)`=0 + `W_VAL(32 长度)`=32 + `2*8`=16 ⇒ 41+1+32+16 = **90** ✓
- 1 条 flag=1：51 + 5(存在位) + 5(tag 0x13) + 5(tag 8) + 32 + 16 = 114… 实测 115，差 1 位 = `W_VAL(1, 0xFF)` 那 1 位（`has=0` 也写 1 位）= 51+1+5+5+5+32+16 = **115** ✓

**★ 因此 177/178 卷「Manifold 头 = 50 位 / 7 字节」的 50 位不成立** —— 那是 `flag=0`（`+0x21=0`，所有标签全空）时的 41 位，或 flag=1 时 **51 位**。**没有任何一条路径产出 50 位**。真正对齐 7 字节的是 flag=1 的 51 位（51→56 位补零 = 7 字节），这也解释了「50 和 51 都补到 7 字节」为什么骗过了旧卷。

## 对旧卷的更正

| 旧卷 | 旧结论 | 更正 |
|---|---|---|
| 177 | Manifold 头 = `W_TAG(3)+W_VAL(8)+W_TAG(8)+W_VAL(32)` = **50 位** | 漏了**容器 1 位头**。正确：`1 + [5+8] + [5+32]` = **41 位(flag=0) / 51 位(flag=1)**。「50 位」不存在 |
| 178 | 「无 1 位 `m_useDataTypes` 头」 | **★ 有 1 位头**，但它在**容器构造函数**（`0xB778E0`/`0xB779A0`）里，不在 `0x625520`/`0x6256C0` 里。178 卷只看了序列化器，所以没看见它 |
| 175 | 「`6/5` 应答必须 7 字节」 | 7 字节只在 **flag=1** 时成立（51 位）。**flag=0 时是 6 字节（41 位）**。7 字节不是协议常量 |
| 176 | Manifold item = `[1][1][21][64][19位0x13][8子类型][32长度][len*8]` | 位宽写成「19 位」「21」「64」是把 **tag 值**当位宽。真位宽：`tag(5)+val(1)+tag(5)+val(32)+val(32)` 与 `tag(5)+tag(5)+val(32)+val(len*8)` |
