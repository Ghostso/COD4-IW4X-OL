# 141 探讨 · 追到底之后，我推翻的是自己 30 分钟前的结论

> 配套：[141 · 服务注册链追到底](141_服务注册链追到底_srpc单例与空串主键.md)
> 主题：**140 卷说"名字表静态为空、运行时注入"。141 卷追到底发现：不是没人填，是每张表只填一个空键。**

---

## 一、我原本的判断错在哪

140 卷 §3.4 写道：

> `dwLobbyImp` 的注册调用点全部 push 空串哨兵 `0xDAE091`，名字表在静态下是空的。
> 这是 140 的主要未闭合项。

**两处都错了：**

| 140 的说法 | 141 的实际 |
|---|---|
| 「`dwLobbyImp` 的注册调用点」 | **是 srpc 单例的注册调用点**（`ecx` 来自 `0x803830`） |
| 「空串哨兵 ⇒ 表为空 ⇒ 名字运行时注入」 | **空串是主键本身；每张表只有 1 个条目** |

★ **方向对了一半（确实没有 4 字符名字），但原因和归属全错。**

---

## 二、错在哪一步

我当时看到"68 个调用点全 push 同一个常量"，第一反应是"这是哨兵，说明没填名字"。

**我没有做那一步：去读那个常量指向的字节。**

一旦读了：
```
0x00DAE090  00 00 00 00 32 33 33 32 00 ...
            ↑
            0xDAE091 指向这里 = ""
```

**它就是空串。** 空串不是"缺失"，空串是**一个合法的键**。

★★ **教训：看到"统一常量"，先解码它，再判断它是不是哨兵。**

---

## 三、第二个错：把 this 认错了

我一直默认"`0xB80D90` 是 `dwLobbyImp` 的方法"。

实际：
```
0x4B0A55  call 0x803830       ; → [0x8269774]
0x4B0A5A  mov esi, eax
0x4B0A71  mov ecx, esi        ; ★ this = srpc 单例
0x4B0A73  call 0xB814B0
```

**所有 68 个注册调用点的 `ecx` 都是 `[0x8269774]`，不是 `dwLobbyImp`。**

而 `dwLobbyImp` 单例 `[0xE39B6E8]` 只是**被挂到 srpc 的 `+0x4F0`**（`0xB7A400`）。

★★ **教训：`ecx` 的来源就是 this 的身份。不看 `mov ecx, ...` 上一行，就会把方法归属搞错。**

---

## 四、第三个收获：一个对象 14 张哈希表

srpc ctor 里连续 14 次 `call 0xB7FC20`：

```
+0x008 +0x020 +0x0D4 +0x0F4 +0x114 +0x12C +0x144
+0x15C +0x174 +0x18C +0x1A4 +0x1BC +0x1D4 +0x1EC
```

而 `dwLobbyImp` 侧只注册 7 张（`+0x114/0x12C/0x144/0x174/0x18C/0x1BC/0x1EC`）。

**⇒ 另外 7 张由别的模块注册，路由靠"选哪张表"而非"表内哪个键"。**

★ **这解释了为什么"空串主键"能工作：每张表只有一个条目，同表内不需要区分。**

---

## 五、这一卷最硬的一条：类型号分配器

```asm
0xB82179  mov dword [esi+4], 0      ; srpc ctor: 计数器 = 0
0xB80E37  mov ecx, [ebx+4]          ; 注册时读
0xB80E3B  push ecx
0xB80E3E  call 0xB920E0             ; → node+4 = type_id
```

**`srpc+4` 就是类型号分配器。**

但我**没找到它的自增**：
- `0xB7A000..0xB8C000` 内 `inc dword [reg+4]` = 0 处
- `0xB920E0` 全文无 `+4` 写入

★★ **倾向结论：类型号恒为 0**，因为每张表只有一个条目，不需要区分。

★ 但我把它列进了「诚实边界」而不是结论 —— **没找到就是没找到**。

## 七、给修复的结论

1. **类型号 7/8 = 房间消息**（140 定案，141 未改动）。
2. **服务名不是字符串** —— 是「选哪张哈希表 + 空键」。服务端不需要拼名字。
3. **`srpc+4` 类型号**在静态下恒为 0（倾向），实际路由靠 `0xB83744[类型号-1]`。
4. **`0xB7A670 == 2` 是所有注册的前置条件**（141 又确认一次）。
