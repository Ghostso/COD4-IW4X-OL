# 256 · ★★★ `0xE39B6E8` 命令处理器单例（vtable `0xDE07A4`）：`0x7F1400` 的归属与分派层

> 卷次：256（房间类 · 分派层）
> 方法：找 `0x7F1400` 所在 vtable 的**基址写点**（`mov [obj], vt`）→ 得单例全局 → 追注册点
> 结论：`0x7F1400` 是**注册进 srpc 的命令处理器单例 `0xE39B6E8`（vtable `0xDE07A4`）的 `+0x68` 槽**。

---

## §0 vtable 基址 = `0xDE07A4`（不是 `0xDE07B4`）

`0x7F1400` 的 dword 位置在 `0xDE080C`。`0xDE080C - 0xDE07A4 = 0x68`。
写点：

```asm
0x7F0970  push ebx / push esi / push edi
0x7F0973  mov ecx,0xE39B6E8 / call 0xB965D0
0x7F097F  mov dword [0xE39B6E8],0xDE07A4    ; ★★ 装 vtable 基址
0x7F0989  mov dword [0xE39B6EC],0
0x7F0995  mov dword [0xE39B6F4],0
0x7F099B  mov esi,0xE39B6F8
0x7F09A0  lea edi,[ebx+0x13]                 ; 20 个对象
0x7F09A7  call 0xB97F20                       ;   每个 0xF8 字节
0x7F09AC  add esi,0xF8 / dec edi / jns
```

★ `[0xE39B6E8] = 0xDE07A4` ⇒ 该对象 vtable 基址 `0xDE07A4`，`0x7F1400` 在 `+0x68`。

## §2 注册点：它被写进 srpc 的 `+0x4F0`

```asm
; ---- 0xB7A400 本体（3 条指令）----
0xB7A400  push ebp / mov ebp,esp
0xB7A403  mov eax,[ebp+8]
0xB7A406  mov dword [ecx+0x4F0],eax     ; ★★★ srpc+0x4F0 = 参数
0xB7A40D  ret 4
; ---- 调用点 0x803840..0x803870 ----
0x80384C  call 0xB82130
0x803851  mov [0x8269774],eax           ; ★ srpc 单例
0x80385A  push 0xE39B6E8
0x80385F  mov ecx,eax
0x803861  call 0xB7A400                  ; ★ srpc+0x4F0 = 0xE39B6E8
```

★★ **`0xB7A400` 不是"注册 handler 表"，是"写 `srpc+0x4F0`"。**
`0x77C290`（192 卷退出清理）里 `push 0; call 0xB7A400` = 把 `srpc+0x4F0` 清零（断开处理器）。

★ 与 173 卷的 srpc 字段册并列：
| 偏移 | 含义 |
|---|---|
| `srpc+0x4F0` | **命令处理器对象 `0xE39B6E8`**（本卷） |
| `srpc+0x4F4` | HMAC 会话对象（173 卷） |
| `srpc+0x4F8` | 强制标志（173/176 卷） |

⇒ **srpc+0x4F0 是这个"房间/会话协议处理器"的挂点**；它非空 ⇒ 已装载房间协议。

### 2.1 进程方法 `0x7F0AF0`（另一处用到 `0xE39B6E8`）

`0x7EED00`（某 tick）`mov ecx,0xE39B6E8 / call 0x7F0AF0`。`0x7F0AF0`：
```asm
0x7F0AFD  call 0x803830                 ; srpc 惰性构造
0x7F0B0E  call 0xB7A670 / cmp eax,2     ; srpc 状态必须 ==2
0x7F0B1E  call 0xB7A770
0x7F0B30  cmp [edx],0x11 / add edx,0x50 ; 扫表 0xE56FFE0..0xE5713E0，找状态 0x11
0x7F0B82  call 0x7FAA20                 ; ★ 出口漏斗（236 卷）
0x7F0B93  mov al,1
```
⇒ `0x7F0AF0` 是"扫描待发状态（0x11）→ 走 `0x7FAA20` 漏斗发送"的**驱动方法**。

## §6 方法论

1. **★★★★ 找"某函数属于哪个对象"，比找"谁调用它"更根本：** 读它的 **vtable 基址写点**（`mov [obj], vt`）。
2. **★★★ vtable 基址 = "函数的 dword 位置 - 槽偏移"**，用已知槽偏移反推基址，再用写点验证。
3. **★★★ "HTTPS 回调"和"房间信道入口"若同处一条 vtable ⇒ 是同一个协议处理器对象，别当两个孤立函数。**
