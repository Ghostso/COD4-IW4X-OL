## §3 客户端构造点（地址级）

### 3.1 商城构造区段 = `0x4A2xxx`–`0x4A9xxx`

全库扫常量立即数（`68 xx xx xx xx` / `B8 xx xx xx xx`）：

```
push 700   (0x2bc): 0x4A27BE, 0x4A29DC, 0x4A2AF0, 0x4A2C27  ← 商城 700 类查询
push 20000 (0x4e20): 0x4A9015, 0x4A9115                        ← 商城 20000 类查询
mov  eax,"1625160" (0x82C4AA8): 0x4A7CA8, 0x4A7CBD → push 0x82C4AA8 于 0x4A7EE3/0x4A8122/0x4A9349
```

### 3.2 典型构造器 `0x4A29A0`

```
004A29A0  mov [0x297DAAC], eax                 ; 缓存参数
004A29AB  call 0x803830 / call 0xB7A670 / cmp eax,2 / jne 退出   ; ★ 认证闸门
004A29C6  push 0xDAE091                        ; 空串（全项目已知「空串哨兵」）
004A29CD  call 0xB81250                        ; 按名查对象
004A29DC  push 0x2bc (700)
004A29E1  push [0x297DAAC]
004A29E8  call 0xB87900                        ; ★ 请求构造器（tag 0x10/0x08…）
004A29F4  push 0x4A2A50 (回调) / … refcount …
004A2A13  push 0x6b (107)                      ; ★ 通道号
004A2A19  call 0x7FAA20                        ; ★ 出口漏斗
```
`: 0x4A29A0 → 请求(700) → 通道 0x6b（class 4：60 s/10 重试）`

### 3.3 分页目录构造器 `0x4A7E80`

```
004A7E8A  call 0x803830 / 0xB7A670==2          ; 认证闸门
004A7ED1  mov eax,[0x849B7E0]; mov edi,[eax+0xc]   ; ★ 每页条数
004A7EE2  push 0x82C4AA8                        ; ★ SKU "1625160" 的 std::string 对象
004A7EEB  push edi / lea edx,[esi+esi*2] / inc eax (页号) / lea eax,[edx*8+0x8C44528]
004A7F00  call 0xB86D10                         ; 构造分页查询
004A7F3A  mov eax,0x5a (90); call 0x7FABE0      ; ★ 通道 0x5a（class 4）
```
★ SKU 字面量 `"1625160"` 位于 `0x82C4AA8`（前 8 字节 `00…;07 00 00 00` = 长度 7，std::string 布局）。
★ 条数表 `[0x849B7E0+0xc]` 与页内数据基址 `0x8C44528`（步进 6×4）是**分页目录**结构。

### 3.4 类别 `20000` 构造器 `0x4A8FA0`

```
004A8FA0  call 0x803830 / 0xB7A670==2
004A8FF7  esi=0x88BA0D8; loop: call 0xB8CD90; add esi,0xb8 until 0x8C3C7D8   ; 清 0xb8 步进的对象表
004A9015  push 0x4e20 (20000)
004A901A  push 0x88BA0D8
004A902F  call 0xB87210                         ; 构造
004A9052  mov eax,0x5d (93); call 0x7FABE0      ; ★ 通道 0x5d（class 3）
```
★ **通道号 `0x5d`=93** ⇒ 「类别 20000 查询」走的通道与服务 93 邻接（商城/钱包同域）。

### 3.5 商城目录清单构造器 `0x4A7C80`

```
004A7C87  mov eax,[0x82C4A90] / [0x82C4A94] / [0x82C4AA0]   ; 三张目录表计数
004A7D15  loop 步进 0x7d0 (2000!) 从 0x8C500B8 取 {u32,u32}
004A7D40  loop 步进 0x18  从 0x8C44530
004A7D65  loop 步进 0x66c 从 0x86CFF78
004A7D86  call 0x4A7B60 (编码) / call 0xC3E8D0 (free)
```
★ **步进 `2000`** 与 `80/70`/`80/107` 的 `u32 2000` 同值 ⇒ `2000` 是**目录条数上限**类常量。

### 3.6 发送链（与 220 卷同一套）

```
0x803830(srpc) → 0xB7A670()==2（认证）→ 构造 → 0x7FAA20 / 0x7FAB70 / 0x7FABE0 → 0x7FA800
0x7FA800: 通道号 → [idx*8+0xE4E20C] → class → 0xE69CE0+class*16 = {发超时,收超时,重发间隔 2000,重试}
```
商城实际通道号：`0x5a`(90)、`0x5d`(93)、`0x6a`(106)、`0x6b`(107)、`0x85`(133)。

## §6 方法论

1. **常量是最好用的锚**：`push 0x2bc`/`push 0x4e20` 直接把「语料字段」钉到「客户端构造点」，无需符号。
2. **步进即语义**：`add ecx,0x7d0`(=2000) 与语料 `u32 2000` 同值 ⇒ 常量在「语料 / 客户端数据布局」两处复现，互为交叉验证。
3. **同型跨服务**：`80/154` ≡ `93/131`（58B 逐字段）⇒ 商城与钱包共用结构，一个样本可解两条服务。
4. **enable 位 ≠ 发不发请求**：服务表 `marketplace=0` 但请求高频 ⇒ 表位是「状态上报开关」，不是协议开关（更正直觉）。
5. **认证闸门先于构造**：所有构造器都以 `0xB7A670()==2` 开头 ⇒ 未认证时请求根本不构造（呼应 172/173 卷「出网卡在 srpc」）。
