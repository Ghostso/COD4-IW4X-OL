# 其余服务 · 探讨：一个 ID 在两种编码下的两种样子

> 对应：`lobby/61_其余服务逐字节总册.md`

---

## 一、最有价值的发现

**`4/13`、`8/1`、`68/3` 里都出现同一个 8 字节：**

```
0e 2d 4c 6b 8a a9 c8 e7
```

**按小端读是 `0x0E2D4C6B8AA9C8E7`。**

**而 `6/14 mmstart` 里的 `roomChatChannelID` 是 `1800154382`，
即 `0x6B4C2D0E`。**

**把 `0x0E2D4C6B` 的四个字节反过来，正是 `0x6B4C2D0E`。**

---

## 二、这意味着什么

**同一个 ID，在两种不同的编码里以不同字节序出现：**

| 位置 | 形态 | 字节序 |
|---|---|---|
| 二进制 TLV 字段（`0a`） | `0e 2d 4c 6b 8a a9 c8 e7` | 原序 |
| 文本命令（`roomChatChannelID`） | `1800154382` | 反转 |

**⇒ 客户端在拼文本命令时，把 u32 的四个字节反转了。**

---

## 三、这解释了一个长期困惑

**项目里 `6/14` 的 `roomChatChannelID` 一直是个谜：
为什么它等于 `1800154382`？**

**现在知道了：它是**同一个 ID 的文本形态**。**

**⇒ 不需要为它单独找含义，它就是玩家/房间 ID。**

---

## 四、`100` 这个常量的分布

**它出现在 6 个 task：**

```
3/48   u32 = 100
3/53   u32 = 100
9/5    u32 = 100
9/14   u32 = 100
29/10  u32 = 100
4/13   u32 = 100（4 条异常样本）
```

**6 个不同的 service，同一个值。**

**⇒ 这是某个**全局默认值**。**

**可能是：**

- 超时（100 秒？100 ms？）
- 分页大小
- 等级上限

**而 `4/13` 的主值是 `932`，只有 4 条是 `100`
⇒ `932` 是"正常值"，`100` 是"异常/降级值"。**

**⇒ `100` 很可能是"默认/未设置"的哨兵。**

---

## 五、`932` 与 `100` 的关系

```
4/4   932（88 条）  /  1006（1 条）
4/13  932（264 条） /  100（4 条）
```

**⇒ `932` 是主值，其他是异常。**

**`1006 = 932 + 74`，`100 = 一个小值`。**

**⇒ 可能是"账号等级"或"XP 分段"。**

---

## 六、`3/*` 三个 task 的骨架相同

```
3/46: 空串 | u64(0) | 空串 | u32(10) | u32(0)
3/48: 空串 | u64(0) | 空串 | u32(0)  | u32(100) | u32(0)
3/53: 空串 | u32(100) | u64(0) | 空串
```

**⇒ 都含"空串 + u64(0)"，但字段顺序和数量不同。**

**⇒ 可能是同一接口的三种调用形态。**

---

## 七、方法论收获

> **跨服务的"同值"是最强的关联线索。**

**`0x0E2D4C6B8AA9C8E7` 出现在 3 个 service。**

**`100` 出现在 6 个**。

**这些跨服务重复的值，比单个 task 内部的字段更能说明"它们属于同一个对象"。**
