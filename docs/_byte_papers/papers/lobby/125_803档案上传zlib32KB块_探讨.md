# 125 探讨 · "固定 32768 字节"这五个字，比任何字段名都值钱

> 配套：[125 · `8/3` 档案上传 = zlib 压缩的 32KB 固定档案块](125_803档案上传zlib32KB块.md)
> 性质：方法论复盘。**主题：长度本身就是结构证据。**

---

## 一、`8/3` 挂了很久，因为它"看起来不透明"

`8/3` 是"档案上传"，blob 长 761~1262，随机看着像二进制。`09` 卷说"blob 是 zlib 流（78 01）"，但**没有人真的把它解压开看过**。

`104` 卷只做了外层的 `u32×4 + blob + i32×125` 结构，blob 内部一直是黑的。

**这卷我只做了一件事：`zlib.decompress()`。**

## 二、解开的瞬间，最有价值的不是内容，是长度

解压出来的 32KB 内容，我看了一堆 u32，说实话没认出哪个字段是什么。

**但我注意到一件事：84 条，压缩前长度 761~1262 不等，压缩后统统 32768 字节。**

**这个"恒为 32768"比任何字段名都重要。**

它告诉我：**客户端的档案不是"变长字节流"，是一个固定大小的结构体。** 32768 字节 = 要么 `sizeof(profileStruct)`，要么一个固定槽数组的整块内存。

**推论立刻出来**：
- 压缩率会变（数值数据不好压，761~1262 波动）→ 这解释了 payload 长度波动；
- 但**结构大小恒定** → 序列化器其实只是把一块**定长内存**丢给 zlib。

**这是"用长度反推结构"**：我不需要知道每个字段叫什么，就能断定"它是一个定长结构，不是流"。

## 三、`0x1b97d354`：`104` 卷的"一一对应"终于有了机制

`104` 卷发现 `8/3` 的 `u32#4` 和 blob 内容"15↔15 一一对应"，但不知道**怎么对应**。

本卷：`payload` 第 4 个 u32 = `0x1b97d354`，解压后 `dec[0:4]` 也是 `0x1b97d354`。

**⇒ 那个 u32 就是"解压内容的第一个 u32"**（内容 ID / 校验）。**"一一对应"的机制是：它把解压块的头 4 字节抄到 payload 里当校验。**

★ 我第一次比对还比错了——用了偏移 12（裸 u32），结果 0/84。原因是 **TLV 每个值前有 `08` 标签**，u32 在偏移 1/6/11/16。**"读 TLV 不能按裸偏移"** 这个坑，我又踩了一下才想起。

## 四、顺带证明 zlib 真在客户端

查 `subscribe` 的时候，我撞进了一片字符串：

```
invalid window size
incorrect header check
oversubscribed dynamic bit lengths tree
incompatible version
```

**这是 zlib 的 12 条标准错误表**（`z_errmsg[]`）。

★★ **⇒ 客户端静态链入了 zlib**。这给 `8/3`（本卷）和 `71/15`（`124`）"用 zlib 解压"提供了**根本依据**：不是我猜它用 zlib，是**客户端里就有 zlib 库，连错误串都在**。

★ 顺便：`subscribe` 那三个命中其实是 `oversubscribed` 的子串——**又一个 ASCII 假阳性**（`124` 卷刚立过"假阳性防火墙"，这卷立刻又用上了）。

## 五、诚实的部分

- **32KB 的逐字段语义我完全没做。** 1160 个区段，我不知道哪个是等级、哪个是武器解锁、哪个是统计。**这需要逐字段 RE + 运行时对照，是一整卷的活。**
- 我说 `[12:3862)` 是"恒定模板"——但这是**同一账号的 84 条之间**恒定。**不同账号之间这 3850 字节是否也恒定，我不知道**（没有第二账号的 `8/3`，ACE 又挡着拿不到）。
- 档案里**没有 CODOID**，所以我推断"账号身份不在这个 32KB 块里"——但**它可能在压缩外面的 u64 字段**，我没去找。

**我没有为了"8/3 全解"把 32KB 说成已解。** 我只解了"它是什么"（zlib 定长 32KB），没解"每个字段是什么"。

## 六、方法论（可迁移）

1. **长度本身就是结构证据**："解压后恒为 N 字节" ⇒ 定长结构体，不是变长流。**不用认得字段就能判结构类型。**
2. **"一一对应"要追到机制**：`u32 == dec[0:4]` 才是"内容 ID"的实证，不是"看起来像"。
3. **TLV 值不能按裸偏移取**：每个值前有 `08` 标签，u32 在 1/6/11/16。
4. **找算法库的证据可以顺路拿**：查 `subscribe` 撞到 zlib 错误表 ⇒ 顺手证明 zlib 在客户端。
5. **ASCII 假阳性防火墙继续生效**：`subscribe` ⊂ `oversubscribed`。
