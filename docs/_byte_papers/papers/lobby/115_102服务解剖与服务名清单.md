## §1 `102/7`：50 槽位静态表

`tools/task_102c.py` / `task_102d.py`：

```
08 50 | [03 01 | 0a <i>] × 50 | 00
        key 恒 = 1
        val = 0,1,2,...,49（严格连续）
```
- 全语料 **371 条，0a 序列去重后 distinct=1**（每条都完全相同的 0..49）。
- ⇒ 这不是"查询结果"，是**固定的 50 槽位声明**。`08 50` = 元素数 50，每个元素 = `(key=1, val=槽位号)`。

## §2 `102/1`：N 个键位声明

```
08 0 | 08 N | [03 <key> | 0a 0] × N | 00
```
| 形态 | N | key 序列 | 值 | 条数 |
|---|---|---|---|---|
| 1 | 1 | `[3]` | `[0]` | 127 |
| 2 | 2 | `[1, 2]` | `[0, 0]` | 45 |

- 两种形态的区别：**声明 1 个键位（key=3）** 或 **2 个键位（key=1,2）**。
- 值恒 0 ⇒ 初始状态（未赋值）。
- ★ 形态选择（1 键 vs 2 键）可能与"是否处于某状态"有关（如单人 vs 组队），但语料无法区分。

## §3 `102/5` / `102/2`

- `102/5`：`08 2 | 03 1 | 03 2` —— 与 `102/1` 同族，`08 2` = 2 个元素，后跟 2 个 u8 值 `[1,2]`。
- `102/2`：`00` —— 空。

## §4 `102` 服务号在真实运行日志中的确认

`backups/GOLDEN_RUNTIME_20261019_1721/evidence/lobby_srv.log:168-199`：

```
★ 解密成功 #39 seq=39 hmac=OK marker=0x86 service=102 ver=0x03 task=7 declared=559
   -> UNMAPPED service=102 task=7 payload=556B -> 空 ACK
★ 解密成功 #40 seq=40 ... service=102 ver=0x03 task=1 declared=25
   -> UNMAPPED service=102 task=1 payload=22B
★ 解密成功 #46 seq=46 ... service=102 ver=0x03 task=1 declared=36
   -> UNMAPPED service=102 task=1 payload=33B
```

- `task=7 declared=559` ↔ 我们语料 `102/7` len=556（`declared = len+3`）**完全吻合**。
- `task=1 declared=25` ↔ `102/1` len=22；`declared=36` ↔ len=33。**逐条对上**。
- ⇒ `102` 是**真实协议服务**，不是解析噪声。

★ 我们的服务端对这 4 个 task **一律回空 ACK**（`UNMAPPED`），客户端**没有因此出问题**（大厅能进）。
这是**最强的行为证据**：`102/*` 是**可安全空应答**的服务——即使语义不明，不回也不会破坏大厅。
