### 1.1 唯一调用者

全库扫 `E8 rel32 → 0x5DE440`：**恰好 1 处** —— `0x7EC650`。

```asm
0x7EC631  mov  eax,[0x33E6A00]
0x7EC636  push 1
0x7EC638  push 0xDDFAD4          ; ★ "bad_items"
0x7EC63D  push 0xDDF818          ; ★ "ui_config"

0x7EC64A  test eax,eax / je
0x7EC64E  mov  ecx,eax
0x7EC650  call 0x5DE440          ; ★ 唯一调用点
```

**⇒ 253 的疑问闭合：`0x7EC650` 是 `0x5DE440` 的唯一调用者。**

### 1.2 全局的全部写点（分母）

扫 `[0xC9113CC]/[0xC9113D0]/[0xC9113D4]` 的原始 4 字节引用，逐条按操作码归类：

| 地址 | 操作 | 角色 |
|---|---|---|
| `0x5DE47B` `0x5DE481` `0x5DE487` | `89 1D` mov [abs],ebx(=0) | **解析器清零** |
| `0x5DE4E4` `0x5DE4F4` | `8B 15` 读 + `mov [eax],esi` | **解析器追加** |
| `0x5DE4F8` | `FF 05` inc [cnt] | **解析器计数++** |
| `0x6555B4` `0x6555BB` | `89 3D/89 35` | **扩容函数 `0x655540`**（realloc+拷贝+free） |
| `0xCA6080` `0xCA6085` `0xCA608A` | `A3` 系列 | **析构/清空函数 `0xCA6070`** |

```asm
0xCA6070  mov  eax,[0xC9113CC]    ; 只有这三个"外部"写点
0xCA6075  push eax / call 0xB74240 ; free
0xCA607D  mov  [0xC9113CC],0
0xCA6085  mov  [0xC9113D4],0

```
**⇒ 写点全集 = {解析 `0x5DE440`, 扩容 `0x655540`, 清空 `0xCA6070`}，无第四个。**
`bad_items` **完全由 dvar 驱动**（253/252 的命名成立）。

★ 253 自己承认「`[0xC9113CC]`/`[0xC9113D4]` 是否 dvar `bad_items` 的运行时数组」未独立验证 —— **本卷独立验证成立**。

## §2 ★★★★★ 253 开项②：两张表的语义 + `0x663D74C0` 伪造

### 2.1 `0x8269C60` = wildcard 物品表（8 条）

填充点（就在徽章表填充循环之前）：
```asm
0x80B27C  mov  esi, 0x8269C60       ; ★ 目标表
0x80B281  mov  ebx, 0xE572A0        ; ★ 8 元素字符串指针数组
loop:
  0x80B286  mov  eax,[ebx]
  0x80B288  test eax,eax / je ->0
  0x80B28C  cmp  byte [eax],0 / je ->0
  0x80B291  push eax / call 0x660B00  ; 名字解析
  0x80B29E  mov cx,[eax] / xor cx,[0xE5737C] / xor cx,ax / rol cx,4 / movzx eax,cx
  0x80B2B6  call 0x810B20             ; 写表项（标准 {key,存在,初始化,值} 步进12）
  0x80B2BB  add  ebx,4
  0x80B2BE  add  esi,0xC
  0x80B2C1  cmp  ebx,0xE572C0 / jl loop
```

`0xE572A0..0xE572BC` 逐条读出的字符串（脚本 `a13_ptrarr.py`）：

| idx | 字符串 | 表内 item |
|---|---|---|
| 0 | `wild_perk1_greed` | 60178 |
| 1 | `wild_perk2_greed` | 60179 |
| 2 | `wild_perk3_greed` | 60180 |
| 3 | `wild_overkill` | 60181 |
| 4 | `wild_primary_gunfighter` | 60182 |
| 5 | `wild_secondary_gunfighter` | 60183 |
| 6 | `wild_tactician` | 60184 |
| 7 | `wild_danger_close` | 60185 |

**⇒ `0x8269C60` = wildcard（职业技能替换）物品表。** 旁证：
- 访问器 `0x80BD50`（`idx→item`）/ `0x80BD80`（`item→idx`，默认返回 8）与
  `WL_GetMarketItemIdForBadgeIndex` 同形（步进 12 + `rol8(B^A^SEED)`）；
- 调用者 `0x7DCEC0` 内嵌字符串 **`onboard_ch_equip_wld`**（`wld`=wildcard）；

★ **新线索（未实机）**：`60178..60185` **全不在已拥有表 `0x8269FC8`**（对比 253 §2.2 的 32 条）。

### 2.2 ★★★★★ 更正：`0x663D74C0` 是伪造地址

253 §6 记载「`0x8269D40` 由 `0x80B450` 写入，源表地址 `[eax*4 + 0x663D74C0]` 超出镜像范围」。

**从函数起点 `0x80A630` 对齐反汇编**（`a5_bigfunc.py`）得到真正的填充循环：
```asm
0x80B400  mov  eax, [edi+4]         ; 内层计数
0x80B40F  mov  ecx, [edi+0xc]       ; ★ 源数组基址（运行期容器）
0x80B412  imul eax, ebx
0x80B415  mov  eax, [ecx + eax*8]   ; ★ 真源（8 字节步进）
0x80B421  push eax / call 0x660B00
0x80B42E  mov  dx,[eax] / xor dx,[0xE5737C] / xor dx,ax / rol dx,4 / movzx eax,dx
0x80B450  lea  esi, [esi*4 + 0x8269D40]
0x80B45D  call 0x810B20
```
**根本没有 `0x663D74C0`。** 证明（`a6_verify_phantom.py`）：
- `0x663D74C0` 的字节序列 `c0743d66` 全库只有 3 处：`0x4BDDCD` / `0x6606DA` / `0x80B42B`；
- 逐处对齐反汇编：**三处全都落在某条指令中间**（`0x80B42B` 落在 `add esp,4` 的尾字节）；
- 从 `0x80B428`（指令中间）起读，capstone 恰好把它还原成
  `les eax, ptr [eax*4 + 0x663d74c0]` —— 即 253 的证据来源。

**⇒ 这是 AGENTS.md「从函数起点读到 `ret`」这条方法论的又一处硬证据：
从指令中间起读会凭空造出一个"越界运行期地址"。** 位移 `c0 74 3d 66` 是
`83 C4 04`(add esp,4) / `85 C0`(test) / `74 3D`(je) / `66 ..` 四条指令字节**缝出来的**。

### 2.3 `0x8269D40` = `mp/uiAlternateModelWeapons.csv`

`0x80B3D1 push 0xDE7078`（=`"mp/uiAlternateModelWeapons.csv"`）→ `0x49CF30` 装载 →

**⇒ 表源是一张 CSV，不是运行期黑箱**（7 条：28096/11755/12669/22971/26110/26149/26469）。

`0x8269B18`（徽章槽 7）/ `0x8269B6C`（`coStartingLoadoutSetting.csv` 池 20）/

## §6 方法论

1. **★★★★★ 「运行期越界地址」出现时，先在指令中间找它。** `0x663D74C0` 是四条相邻指令
   的字节缝出来的 —— **从函数起点读到 `ret`** 不只是礼貌，它能把"黑箱运行期表"直接消掉。
   凡是"地址 > 镜像末"的 disp32，第一步就应是**用函数起点对齐复核**。
2. **★★★★★ 「唯一调用者」是一个可机械证否的命题。** 253 留成疑问，本卷用
   `E8 rel32` 全库扫一次就闭合 —— **疑问句要先看它是不是可以直接变成 grep。**
3. **★★★★ 字符串指针数组是表语义的最短路径。** `0x8269C60` 的 8 条 item 全无内嵌名字，
   但填充循环指向 `0xE572A0` 的指针数组，一串 `wild_*` 立刻定名 ——
   **表值本身可能被混淆，但"谁填它"的源指针通常没被混淆。**
4. **★★★ 「各表相位不同」不等于「格式不同」。** 同一块 0x8269B00..0x8269FE0 里
   5 张表步进 12 但基址互相错开（`0x8269B18`+12k vs `0x8269C60`+12k 差 4 字节）——
   **按固定网格 dump 会把相邻表混读**（这正是 250/253 表长之争的同一个坑）。
5. **★★★ 「记录是出参」与「记录是全局」必须分清。** `0x5E3760` 的 `edi` 由调用者给，
   且 6 个抽样调用点全是 `lea edi,[esp+X]` —— **同一条记录，语义从"数据库写"变成"函数返回"**
   （与 253 §4 的方法论同源，本卷在 54 个调用者上再次验证）。
