# 第 108 卷 · 报文方向判定 —— 全语料 6848 条都是"客户端 → 服务端"

> 承接 `lobby/107` 结尾提出的缺口：「这些报文是客户端上报还是服务端下发？」
> 本卷结案。**答案：全部是入站（客户端 → 服务端）。**
> 证据链三级，全部来自受保护资产的**只读源码**（未修改任何文件）。

## 1. 结论（先说）

```
corpus.json 的 6848 条 payload，100% 是客户端 → 服务端的入站报文。
里面没有任何一条是服务端的应答或推送。
```

**★ 因此，前几卷（102–107）分析出的所有"字节语义"，
  描述的都是"客户端在说什么"，不是"服务端该回什么"。**

**⇒ 这对我们的目标是**好消息**：
  我们本来就要**写服务端**去应答客户端。
  知道客户端说什么，正是写应答的前提。**

**⇒ 但也有一个**重要限制**：
  **corpus 里没有服务端的应答样本**，所以我们无法从 corpus 直接学到
  "应答该长什么样" —— 那必须从 `reply_objects`（参考实现）和逆向里拿。**

## 2. 证据一：唯一写入点在入站解密路径（代码级）

**`REF_LOBBY_KIT/lobby_server.py` 里，`lobby_tasks.bin` 只有一处写入：**

```python
# 第 1139-1146 行
if r["payload"]:
    log("       payload(%d): %s" % (len(r["payload"]), hexd(r["payload"][:96])))
    try:
        open(os.path.join(OUTDIR, "lobby_tasks.bin"), "ab").write(
            bytes([r["service"], r["task"]])
            + struct.pack("<I", len(r["payload"])) + r["payload"])
    except Exception:
        pass
objs, note, pushes = reply_objects(r["service"], r["task"], r["payload"])
```

**上下文（第 1114-1126 行）：**

```python
for fr in list(pending):
    r = cc.decrypt_task_frame(fr, sec["aes_out"], sec["hmac_out"])
    ...
    log("  ★ 解密成功 #%d seq=%d ... service=%d ... task=%d" ...)
```

**⇒ `r` 是 `decrypt_task_frame`（**解密收到的帧**）的产物。**
**⇒ `r["payload"]` 是**客户端发来的明文**。**
**⇒ 写进 `lobby_tasks.bin` 的就是它。**

**★ 而所有出站动作都是 `conn.sendall(...)`（第 1030/1165/1198/1289 行），
  **没有任何一个 sendall 之前写 `lobby_tasks.bin`**。**

**⇒ 这是代码级的硬证据：日志只记入站，不记出站。**

## 3. 证据二：`reply_objects` 的存在本身就证明了方向

**`reply_objects(service, task, plain)` 的签名是：**

```
输入：service, task, plain（客户端发来的 payload）
输出：(objects, note, pushes)   ← 服务端要发回去的东西
```

**⇒ 函数名 `reply_objects` = "构造应答对象"。**
**⇒ 如果 `plain` 是服务端发来的，就不需要"reply"。**

**★ 而且注释里反复出现"客户端发的"：**

```python
# 第 561 行
# ★★ 2026-10-06: 客户端**上传**玩家档案(名片/装备/统计都在里面)。

#      头部 35 字节 + blob(可 zlib) + 125 项 07 <i32> 尾清单。
#    之前一律回空 ACK -> 客户端发的档案被丢弃 -> 买的东西/装备不生效。

# 第 634 行
# ★ 21/1 createSession —— 2026-10-03 实测: 客户端进出房间时会发它(x1),

# 第 784 行
# ★ 2026-10-03 实测: 客户端确实发了 4 次, 其中一次 payload 就是那个 16B ready 批次。

# 第 842 行
# ★★ 实测(2026-10-03): 真实客户端发的是 "mmbook 1 <base64> 0"
```

**⇒ 参考实现的作者已经逐条标注了每个 service/task 是"客户端发的"。**

## 4. 证据三：corpus 的时序与内容自洽

**① 每个 run 内 `idx` 严格递增（0..N），是一个**单连接会话的接收顺序**。**
```
run=ONCE_20261026_143143  n=83  idx 0..82  严格递增=True
（全部 run 均如此）
```

**② 内容侧全部是"请求"特征：**
- `10/21` 请求 `mp_playlists_shipRetail_1.0.0.info`（**请求文件名**）
- `21/5` 带 playlist 参数（**查询条件**）
- `6/14` 带 `mmstart ... map <地图>`（**客户端告诉服务端它选了什么**）
- `8/3` 带 125 个 i32（**客户端上传自己的档案**）
- `11/13` 是**空 payload**（建房间请求无参数）

**⇒ 没有一条是"应答"形态（应答会带结果对象/状态码）。**

**③ 每个 run 里 `21/5` 出现 11 次、`6/14` 出现 11 次 —— 是**轮询**特征。**
**⇒ 客户端周期性发 `21/5`（查会话），服务端应答。轮询是客户端行为。**

## 7. ★★ 已实测：`6/14` 是 `mmbook`(127) / `mmstart`(64) / `mmban`(44)

首 4 字节 = u32 长度（235/235 == len(blob)-4，无例外）

  mmbook   ×127   ← 主流

**★ 参考实现说"主流是 mmbook"**对了**；说"不是 mmstart"**错了**（有 64 条）；

**⇒ 这正是"第三方参考必须全语料复核"的实例。**

## 7.1 ★★★ `mmbook` 的 base64 = `roomChatChannelID` 魔数（三条路径闭环）

**`mmbook` 只有两种取值：**

```
mmbook 796 AQAAAAAAAAA= 0   ×107  → b64 解码 = 01 00 00 00 00 00 00 00 = u64 1
mmbook 796 iHdmVUQzIhE= 0   × 20  → b64 解码 = 88 77 66 55 44 33 22 11 = u64 0x8877665544332211
```

**★ `0x8877665544332211` 小端读出 = `0x1122334455667788` = `107` 卷的 `roomChatChannelID` 魔数。**

**⇒ 三条**完全独立**的路径指向同一常量：**

| # | 形态 | 出处 | 次数 |
|---|---|---|---|
| 1 | 二进制 u64 (`0x0a`) | `107` 卷 | 298 |
| 2 | `mmstart` 明文 `roomChatChannelID 1234605616436508552` | `107` 卷 | 47 |
| 3 | **`mmbook` 的 base64 `iHdmVUQzIhE=`** | **本卷** | **20** |

**⇒ 语义：`mmbook <token> <base64(u64 channelId)> 0` = "我(token=796)要在频道 channelId 上预约"。**
**`AQAAAAAAAAA=` = 频道 1（靶场/单机默认）；`iHdmVUQzIhE=` = 线上默认频道。**

## 8. 对后续工作的影响（三条硬约束）

**① 所有 corpus 结论都是"C→S"，不能当"应答模板"用。**
**⇒ 写服务端应答时，必须去 `reply_objects` 找布局，不能抄 corpus。**

**② 要验证"应答是否被客户端接受"，必须**回放** corpus 里的请求 +
  参考实现的应答，而不是只分析 corpus。**

**③ 每个 service/task 的"应答对象"布局在 `reply_objects` 里有**注释级**说明，
  但**注释不是实测**（参考实现自己也标了很多"未验证"）。
  ⇒ 用之前要按 `AGENTS.md` 的可信度分级：本地逆向 > IW4X > CoD4X > 其他。**
  **`reply_objects` 属于"照抄 ol-mod/C#"的第三方，可信度最低档。**
  **⇒ 它的**布局注释**可以用作线索，但**不能当权威**。**
