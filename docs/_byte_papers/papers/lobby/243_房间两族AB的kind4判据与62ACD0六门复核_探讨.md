# 243 探讨：返回值域必须数完所有 ret —— 我差点把门4判成恒失败

## 判据

1. **函数的返回值域必须单独确认，不能从「调用点怎么比」反推。**
   - 错误做法：看到 `call 0xB7A670 / cmp eax,2 / jne fail`，就写「门要求状态==2」。
   - 正确做法：**读 `0xB7A670` 的每一个 `ret`**。它只有两个出口：`0xB7A67F`（`xor eax,eax`）和 `0xB7A694`（`mov eax,1`）+ `0xB7A699`（直接返回 `[esi+0x4F8]` 分支的 `eax`，而该分支只来自 `0xBA0780` 的返回值…）。
   
   **这里我要如实标注**：`0xB7A681 call 0xBA0780` 的返回值在 `+0x4F8!=0` 时**会原样返回**（`jne 0xB7A699` 跳过 `cmp eax,2`）。
   所以 `0xB7A670` 的返回值域其实是 **`{0, 1} ∪ 0xBA0780 的返回值**。
   但 `0xBA0780` 的返回值域是 `{1,2}`（176 卷：`+0xC8∈{1,2}→2`，其它→原值），**所以含 2**。
   ⇒ **门4 的 `cmp eax,2` 不是恒失败，而是「只在 `+0x4F8!=0` 时才可能通过」**。
   **我第一版写「恒失败」是错的。** 见下方自我推翻。

2. **「几道门」要数 `cmp/test`，不是数 `je`。** `0x62ACD0` 有 6 个 `cmp/test` 各自带 `je 0x62AE59`，所以「六道门」的计数是对的。

3. **两族的区别要用「参数从哪取」判定，不能用「函数名/注释」。**
   族 A 的 `kind` 在 `eax`（`0x62C38F mov edi,eax`），族 B 在 `[ebp+0x14]`（`0x62C876`）。
   **同名的 `kind==4` 判据，一个用寄存器一个用栈 —— 这是「看起来一样、实际不同」的典型。**

## 自我推翻记录

- **第一版（已写入论文 E4，需更正）**：我写「门4 的 `cmp eax,2` 与 `0xB7A670` 的布尔返回值冲突 ⇒ 恒失败 ⇒ 死代码」。
  **这是错的。** 我漏了 `0xB7A68D jne 0xB7A699` 这条「强制位放行」路径 —— 它**跳过** `cmp eax,2`，把 `0xBA0780` 的原值直接返回。
  而 `0xBA0780` 能返回 `2`（176 卷状态机）。所以门4 **可以**通过，条件是 `srpc+0x4F8 != 0`。
- **第二版**：我一度以为是「`0x62ACD0` 恒死」。现修正为：**门4 通过了当且仅当 `+0x4F8!=0`；若 `+0x4F8==0` 则 `0xB7A670` 返回 1/0 → `cmp eax,2` 恒不等 → 门4 失败**。
  所以「死函数」这个结论要看 `+0x4F8` 的运行时值 —— **静态只能给出条件**。

## 方法论

- **`ret` 的个数 = 返回值域的线索。** 一个函数有几个 `ret`，每个 `ret` 前 `eax` 被赋成什么，合起来就是返回值域。只看主路径会漏掉「提前返回的分支」。
- **`jne` 跳过的那个 `cmp`，本身就是一条"旁路"。** `0xB7A68D jne 0xB7A699` 把 `cmp eax,2` 整个绕过 —— 这种「跳过检查」的写法在防火墙/降级逻辑里很常见，**必须当成第一类公民记录**。
- **「甲卷说 N 道门」要自己数。** 172 卷说六道，我数也是六道 —— 但**其中一道（门5）是前一道的同义反复**（`0xB7A770` 内部第一件事就是 `call 0xB7A670 / cmp eax,2`）。**计数对 ≠ 每道都独立。**
- **两个族看起来对称时，先找不对称。** 族 A `eax`、族 B `[ebp+0x14]`；族 A 调 `0x7E8240`（5 参）、族 B 调 `0x7E8300`（6 参 + 内联常量1）。**对称的表象下每次都有实实在在的差异。**
