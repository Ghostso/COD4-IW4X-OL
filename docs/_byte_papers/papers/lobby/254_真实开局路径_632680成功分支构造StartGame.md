## §2 四个出口

| 出口 | 触发条件 | 行为 |
|---|---|---|
| **清状态** `0x6328EB` | 门 A/B/C 任一不过 | `[+0x3A048/4C]=0`，`memset(+0x3A050,0,0x40)` |
| **直接返回** `0x632916` | 门 D/E 不过 | 什么都不做 |
| **拒绝** `0x632712` | id 匹配但 MMI[idx]+0x168 不符，或超时未到 | dispatch `0x637930` |
| **超时** `0x632876` | 门 F 不过（非 "mmbook accepted"）且超时 | 构造 `0xDC7528` 消息（type=2/4），`vt+0x148` |
| **★成功** `0x632736` | 门 F 过 **且** MMI[idx]+0x168/16C == booking id | **构造 StartGame（`0xDC751C`）→ 序列化 → 发送** |

## §3 StartGame 消息的真实构造

```asm
0x6327E9  mov dword [esp+0x14],0xDC751C   ; StartGame 消息 vtable
0x6327E1  mov dword [esp+0x18],3
0x6327F1  mov [esp+0x1C],MMI[idx]         ; 元素指针放 [+0x10]
0x6327F5  call 0x62ABF0                   ; → msg.vt[0]=0x625BE0（StartGame::serialize）
0x6327FC  mov edx,[esi_vt+0x148]          ; 0x62C580
0x632809  call edx
```

- `0xDC751C[0] = 0x625BE0`（StartGame::serialize）、`0xDC751C[4] = 0x625CE0`（deserialize，P1 的读侧）。
- `0xDC7528`（超时分支）= `[0] 0x628320`（通用写）/ `[4] 0x625DB0`（通用读），**不是 StartGame**。
- `0x62ABF0` 用 `msg.vt[0]` 把消息序列化进位流（`0x62AC0B push ebx;push ebx` ⇒ 位流 `+0x21=0`）。
- `0x62C580` → `0x62C380(eax=kind=2)`：把位流包成帧并走 `0x656A10` / `0x7E8240` 出口。

★ 成功分支还调用了 `0x631E90`/`0x632070`/`0x631E50`（操作 `[edi+0x105F0]` 起、步进 `0x3E24` 的**玩家/装备槽**），
⇒ 它是**"真正开局"的完整流程**（选玩家 → 装配 → 发 StartGame），不是空壳。

## §4 起点：`room.startgame` 控制台命令**本地发起** booking

★★★ **开局链的"发起点"是一个控制台命令**（本轮新发现，非网络）：

控制台命令表里有一族 `room.*`（`0xDC6B80`）：
```
0xDC6B80 "room.join"  0xDC6B8C "room.leave"  0xDC6B98 "room.startgame"
0xDC6BA8 "room.say"   0xDC6BB4 "room.say2team" 0xDC6BC4 "room.test"  0xDC6BD0 "room.members"
```
注册点 `0x63A13C`（命令表 `0x33303B0`，`0x4F37A0` 查重 / `0x4F3820` 注销）：
```asm
0x63A13C  mov esi,0xDC6B98("room.startgame")
0x63A141  call 0x4F37A0
0x63A148  jne  0x63A16B                    ; 已存在则跳过
0x63A14A  mov [0xE9C6780],edi
0x63A155  mov [0xE9C6784],esi              ; name = "room.startgame"
0x63A15B  mov [0xE9C6788],0x6398A0         ; ★ handler = 0x6398A0
0x63A165  mov [0x33303B0],edi
```
handler `0x6398A0` → `call [dwRoomImp.vt+0x3C]`（= `0x62F840`，`[0xDC72B0]`）：
```asm
0x62F840  cmp byte [ebx+0x278],0 / je        ; 同门 A
0x62F867  cmp [0x76446B0],3 / jge            ; 同门 B
0x62F87B  cmp [ebx+0x105D8],[ebx+0x105FE]    ; 数量校验
; 否则：
0x62F902  mov [ebx+0xE360],eax               ; ★ 设 MMI 索引 = 参数
0x62F90E  lea edi,[eax+ebx+0x7470]           ; MMI[idx]
0x62F917  call 0x62F6F0                      ; ★★★ booking 请求构造器（"mmbook %d %s %d"）
```
★★★ ⇒ **`room.startgame <idx> <flag> <bool>` 会设置 MMI 索引并调用 `0x62F6F0` 构造 booking 请求**
（`0x62F6F0` = 244 卷 E2 的发送方，`0x62F7E0 push "mmbook"`）。

**完整开局链（本地发起版）**：
```
room.startgame（控制台/Flash）
  → dwRoomImp.vt+0x3C = 0x62F840（设 MMI[idx]）
  → 0x62F6F0（构造 "mmbook <id> ..."，经 vt+0x150 发）
  → 服务端应答
  → [0xE39B6E8].vt+0x68 = 0x7F1400（strncmp "mmbook"）
  → dwRoomImp.vt+0x13C = 0x632680（门6 = "mmbook accepted"）
  → 成功分支构造 StartGame（0xDC751C）并发送
```

★ 对照：`room.join` → handler `0x639890` → `dwRoomImp.vt+0x38` = `0x62F640`。

★★ **⇒ "真实开局路径"有两个端点**：**本地发起**（`room.startgame` → `0x62F840`，纯本地，可验证）
与**服务端完成**（`0x7F1400`→`0x632680` 成功分支）。**本地能把请求发出去，但"过关"取决于服务端应答。**

## §5 两个调用点（分母已穷举）

`0x632680` 的 dword 只出现在 `0xDC73B0` 与 `0xDC7850`（各一处，见 255 卷）；
`mov reg,[X+0x13C]; call reg` 全镜像 9 处，其中 `ecx` 为本对象的只有两处：

| 调用点 | 所在函数 | 参4（=门6 比较值） | 结果 |
|---|---|---|---|
| `0x632FC4` | FrameUpdate `0x632D90` | `0xDC69D4` = `"mmbook timedout"`（常量） | 恒走超时分支 |
| `0x7F156F` | HTTPS/session 应答分派 `0x7F1400` | `[esp+0xB0]` = 应答里解析出的文本 | **可为 `"mmbook accepted"` → 成功** |

★★ **⇒ 成功分支可达**，条件是**应答文本恰为 `"mmbook accepted"`**（本卷与 244 卷一致）。
227 卷"没有调用点"应改为：**唯一能把参4 传成 `"mmbook accepted"` 的调用点是 `0x7F156F`，而它要求服务端返回该字面量。**

## §8 方法论

1. **★★★★★ 只读到"跳转"不等于读完整条路径 —— 必须同时跟进"不跳"（fall-through）的那一条。** 227 卷栽在 `jne 0x632876`。
2. **★★★★ 反汇编要覆盖全部 `ret`，不是第一个 `ret`。** 本函数有 4 个 `ret 0x14`。
3. **★★★ 「唯一调用点传的值」只能证伪"该调用点能过门"，不能证伪"门本身无成功分支"。**
