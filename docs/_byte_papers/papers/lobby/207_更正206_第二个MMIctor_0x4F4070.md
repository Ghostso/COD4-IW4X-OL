## §1 第二个 MMI ctor：`0x4F4070`

```asm
0x4F4070  mov eax, [ecx+4]                  ; vbptr
0x4F4074  lea esi, [ecx + 0x230]            ; ★ 对象起点 = ecx+0x230
0x4F407A  mov dword [esi-0x230], 0xDC79F0   ; vtable#1 @ 对象+0
0x4F4084  mov dword [esi-0x228], 0xDC79FC   ; vtable#2 @ 对象+8
0x4F4091  mov dword [ecx+esi-0x22C], 0xDC7A08 ; vtable#3 @ 对象+4
0x4F409C  lea ecx, [esi-0x108]              ; ★ 构造 对象+0x128
0x4F40A2  call 0xB95AA0
0x4F40A7  mov ecx, esi
0x4F40AA  jmp 0xB757E0                      ; ★ 构造 对象+0x230
```

### 1.1 与 `0x4F4010` 的对比

| | `0x4F4010` | `0x4F4070` |
|---|---|---|
| 入参 `ecx` | 对象 + 0x230（尾指针） | 对象 + **0x230**（同） |
| 对象起点 | `lea edi,[ecx-0x230]` | `lea esi,[ecx+0x230]`?? |
| 构造 `+0x128` | `lea ecx,[edi+0x128]` | `lea ecx,[esi-0x108]` = `(ecx+0x230)-0x108` = `ecx+0x128` |
| 构造 `+0x230` | `lea ecx,[edi+0x230]` | `mov ecx,esi` = `ecx+0x230` |

★★ **两个函数的入参语义不同：**
- `0x4F4010`：`ecx` = **对象起点 + 0x230**（尾指针），对象起点 = `ecx - 0x230`
- `0x4F4070`：`ecx` = **对象起点**，对象终点 = `ecx + 0x230`

★ 但两者写 vtable 的相对位置相同（`+0`/`+8`/`+4`），构造的成员也相同（`+0x128`/`+0x230`）。

⇒ **两个都是 MMI ctor，只是调用约定/基址不同**（可能是不同继承层的 ctor）。

### 1.2 `0x4F4070` 的 `+0x230` 是"子对象终点"

`0x4F40AA jmp 0xB757E0`（tail call），`ecx = esi = 对象+0x230`。

★ 结合 199 卷：MMI ctor 在 `+0x230` 写 `0xDB6AE4`（bdReferencable）并 `call 0xB757E0`。

⇒ **`+0x230` 是 MMI 的尾部基类子对象（bdReferencable），有自己的 ctor `0xB757E0`。**

## §2 三个 vtable 位置复核

从两个 ctor 都一致：
```asm
mov [对象+0x00], 0xDC79F0

mov [对象+0x04], 0xDC7A08   ← 通过 vbptr 间接
```

★ 三个 vtable 在 `+0x00` / `+0x08` / `+0x04` —— 与 189/200 卷一致。

## §4 方法论

1. **★★★ 扫 hex 立即数用字节搜索（`struct.pack` + `find`），不用正则。** 正则位数容易错，字节搜索 100% 准。
2. **★★ 同一个类可以有多个 ctor（不同继承层/不同基址）。** `0x4F4010` 和 `0x4F4070` 都是 MMI ctor。
3. **★★★ `lea reg,[ecx±0x230]` 的符号决定"入参是尾指针还是起点"。**
4. **★★ 扫描结果为"零"时，必须用第二种方法（字节搜索）交叉验证。** 206 卷就是这样被抓出来的。
