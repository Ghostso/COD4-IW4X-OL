# `.tp3` 自解密指令变体的证据

> 对象：`codoMP_client_shipRetail.exe` 的可执行段
> 现象：capstone 在关键位置产生**错位反汇编**，但原始字节是合法 x86
> 证据：文件偏移 `0x5c03a`、`0x22ae9c`、`0x57888f` 三处原始字节

---

## 1. 现象

按 `.tp3` 节表线性反汇编，在 `0x45c030` 附近得到：

```
0x0045c030  65 00 11        add byte ptr gs:[ecx], dl
0x0045c033  2c 49           sub al, 0x49
0x0045c035  03 00           add eax, dword ptr [eax]
0x0045c037  3e 00 21        add byte ptr ds:[ecx], ah
0x0045c03a  6a 18           push 0x18
0x0045c03c  39 00           cmp dword ptr [eax], eax
0x0045c03e  b0 55           mov al, 0x55
0x0045c040  ec              in al, dx          ← 特权指令！
0x0045c041  52              push edx
0x0045c042  68 d4 5e db 00  push 0xdb5ed4      ← 正确
0x0045c047  e8 70 4c 20 00  call 0x660cbc
```

**`in al, dx` 是特权指令，用户态不可能执行。**

**说明前面几条是错位的**（从真实指令中间开始解）。

---

## 2. 原始字节的证据

文件偏移 `0x5c03a` 起：

```
6a 18 39 00 b0 55 ec 52 | 68 d4 5e db 00 | e8 70 4c 20 00
push 0x18  cmp [eax],eax mov al,0x55 in al,dx push edx
```

**`push 0xdb5ed4` 本身是绝对正确的**（`68` + 4 字节立即数）。

但它前面的字节，按 x86 解码是"合法但荒谬"的指令序列。

---

## 3. 三种解释

### 解释 A：反汇编线从错误位置开始

`.tp3` 节内的代码可能不是**连续**的 —— 中间有数据、有对齐填充、
或者有"跳转表"。

线性扫描一旦错位，后续全部错。

**这是最常见的原因。**

### 解释 B：`.tp3` 是"自解密代码"

`.tp3` 段名字本身暗示自定义格式（TP3 = TenProtect 3）。

它的代码可能在**加载后才被还原**，磁盘上的字节是"加密后的"。

### 解释 C：`.tp3` 使用了 capstone 不认识的指令变体

---

## 4. 哪个解释更可能

**证据偏向 A 或 B。**

判据：
- `push 0xdb5ed4` 是完整的、正确的
- 它周围的字节"看起来像代码"但逻辑不通
- 同一段里出现 `in al,dx`（特权指令）

**如果是 A（错位）**：只要从正确的位置开始，就能解对。
**如果是 B（自解密）**：磁盘上的字节根本不是真实指令。

---

## 5. 三处调用点

**`push 0xdb5ed4`（`aes` 字符串）在文件里出现 3 次：**

| 文件偏移 | VA（段 1） | 上下文 |
|---|---|---|
| `0x5c042` | `0x45c042` | 后面跟着 `call 0x660cbc` |
| `0x22aeab` | `0x62aeab` | 后面跟着 `call 0xc58ab9` |
| `0x57889f` | `0x97889f` | 后面跟着 `call 0xca3c2b` |

**这是"aes 字符串被使用"的直接证据。**

即：**EXE 里确实有代码在用 `aes` 这个词**（可能是查找算法、选择算法、
或打印日志）。

---

## 6. 这解释了为什么之前的 xref 全部失败

我用 capstone 的 `md.disasm()` 线性扫描，遇到错位点后就再也对不上。

**而原始 dword 搜索（`b.find(pack('<I', va))`）不受影响。**

### 教训

> **在 `.tp3` 这种自定义格式的代码段里，线性反汇编不可靠。
>  应该用"原始字节模式匹配"（`push imm32` / `mov reg, imm32`）来定位引用。**

`push imm32` 的编码是 `68 <4 字节小端>` —— **6 字节固定模式，不会错位。**
