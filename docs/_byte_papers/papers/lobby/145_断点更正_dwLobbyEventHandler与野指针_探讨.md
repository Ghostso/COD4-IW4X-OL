# 145 探讨 · 我用了四卷的错误类名，最后一卷才发现

> 配套：[145 · 断点更正与真根因](145_断点更正_dwLobbyEventHandler与野指针.md)
> 主题：**「dwLobbyImp」这个类根本不存在。我沿用了四卷的错误名字，直到脱壳后读 RTTI 才发现。**

---

## 一、错在哪

139 → 140 → 141 → 142 → 144，五卷里我一直写「`dwLobbyImp` 单例 `0xE39B6E8`」。

**脱壳后读它的 vtable `0xDE07A4`：**

```
vt[-1] → COL 0xE081F8 → type_info 0xE772C8 → name
= .?AVdwLobbyEventHandler@@
```

**它是 `dwLobbyEventHandler`。**

然后我把全镜像的 RTTI 扫了一遍找 `Imp@@`：

```
.?AVMyRoomEventHandler@dwPartyImp@@
.?AVMyRoomImp@dwPartyImp@@
.?AVdwPartyImp@@
.?AVdwRoomImp@@
```

**没有 `dwLobbyImp`。这个类不存在。**

---

## 二、名字是哪来的

★★★ **是从 ol-mod 的语境带进来的。**

AGENTS.md 白纸黑字写着：

> **ol-mod is NOT authoritative** —— 它自己 header 声明 targets 3.3.3.3，不是本 build。
> **Never copy its constants, field layouts, or protocol values into our implementation.**

**我犯的正是这条禁令：抄了它的类名。**

★ 而且这个错误**没有代价地传播了五卷** —— 因为静态分析只看到 `0xE39B6E8` 这个地址，
地址是对的，功能推断也是对的，**只有名字错了**。

---

## 三、名字错导致的下一个错

144 卷我写：

> **断点：`[dwLobbyImp+0x4F0] = 0`**
> 这是 `dwLobbyEventHandler` 指针，它**从未被创建**。

**两处都错了：**

1. `0xE39B6E8` 自己**就是** `dwLobbyEventHandler`，`+0x4F0` 不可能是"它的指针"
2. 真正的闸门是 **`+0x4F4`**（差 4 字节）

```asm
0xB8392C  cmp dword [esi+0x4F4], 0
0xB83933  je  0xB83ADE        ; ★ 这才是跳过消息分发的闸门
```

★★★ **我读了 `+0x4F0` 的写点（ctor/dtor 清零），却从没读 `+0x4F4` 的写点。**

而 `+0x4F4` 的写点里有 **`0xB81FFD mov [ebx+0x4F4], esi`** —— 唯一的非零赋值，
一眼就能看出「这里才是真正挂对象的地方」。

---

## 四、真根因：一个野指针

追到最底层：

```
[0x84ABB14] = 0x3AC8B310     ← 全局里的地址
0xB9A0E0  lea eax,[ecx+0x28]  ← 只加偏移，不校验
0xB82070 / 0xB81EF0           ← 拿它去建连接
0xB81FFD  mov [ebx+0x4F4], esi ← 没成功
```

然后读 `0x3AC8B310` 的内容：

```
+0x008 = 0x0776E035   ← 非法地址
+0x028 = 0xFFE0C1A2   ← 负数
+0x240 = 0x426E6A63   ← "cj nB" 文本
```

**这不是对象，是已释放或未初始化的堆内存。**

★★★ **`test esi,esi` 只能挡住 0，挡不住野指针。**

---

## 五、这一卷暴露的三个方法论问题

### 5.1 类名必须用 RTTI 验

**地址对、功能对、名字错** —— 这种错误最隐蔽，因为它不影响静态分析的每一步，
只影响你对"这是什么"的理解。

★★ **判据：任何类名都要能追到 `. ?AV...` 字符串。**

### 5.2 "对象未创建"要先确认是哪个对象

144 说「handler 从未创建」，实际 handler 存在（`+0x0C = 1`），
**缺的是它内部的连接对象**。

★★ **"未创建"必须指向具体字段，不能指向整个对象。**

### 5.3 闸门只差 4 字节，读错一个就全错

```
+0x4F0  ← 144 卷读的（不是闸门）
+0x4F4  ← 145 卷读的（真闸门）
```

★★ **找闸门的方法：扫 `cmp [reg+X], 0 / je` 的形态，而不是猜字段。**

## 八、给你的建议

如果要做下一次动态验证，**只需要确认一件事**：

> 进到房间之后，`dwLobbyEventHandler+0x4F4` 是不是还等于 0？

- **还是 0** ⇒ 本卷结论成立，要修的是连接建立路径
- **非 0** ⇒ dump 时机问题，房间消息链路本身是通的，要查别处

★ 这是**最便宜的一次验证**，一个 dump 就能定论。
