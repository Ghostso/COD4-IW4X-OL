## §2 修复

`kit/market_skus.py::_sku_obj`：删除两个无证据插入字段，字段序严格回到 `_sku_schema_as.SKU_AS_FIELDS`。

```diff
     b.u32(int(sku.get("duration", 0)))        # duration
-    b.u8(0)                                   # extra u8 in CODOL bdMarketplaceSku! (0x03)
     b.bool_(bool(sku.get("stackable", False)))# stackable
 ...
     b.bool_(False)                            # couponEnable
-    b.u32(0)                                  # extra u32 in CODOL bdMarketplaceSku! (0x08)
     b.bool_(False)                            # ignoreEntitlement
     b.u32(0)                                  # indexInProduct
     b.bool_(False)                            # ignoreDiscount
```

两个插入使其后全部字段错位；客户端 DML 逐值查类型 ⇒ 字段一错位，后面每个 tag 都对不上 ⇒ marketplace 整服务死（160 卷实测）。

## §7 方法论

1. **★★★★ 「正式副本」这个说法必须先拆成「哪一份」。** 仓库里同一文件有 3+ 份谱系时，「落地了吗」的答案随副本而变 —— 不先钉住基准，结论就是空的。
2. **★★★★ 带 `.tested_ok` 的实现 > 没有标记的实现。** 两份 19/21 字段实现并存时，选有实测哨兵标记的那份做交叉。
3. **★★★ 校验器要能判旧版错。** 本 run 的 T3 段同时证明「修复后 19 字段通过」与「旧版 21 字段可被识别」。
4. **★★ 清单过期 ≠ 文件被改。** 两处副本互相一致是判定「过期 vs 篡改」的关键；单看一处只会误报篡改。
5. **★★ 白名单里有、目录里没有 = 会静默跳过。** `run_frozen_chain_once.py` 的 `if is_file()` 让「缺失」不报错 —— 缺文件要在校验清单里显式列。
