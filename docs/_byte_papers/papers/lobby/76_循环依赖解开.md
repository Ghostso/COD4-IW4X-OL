# ★★★★★ 循环依赖解开：`0x7eebc0` 是枢纽

> **`lobby/75` 的"死循环"已解除**
> 证据：`0x621810`（函数起点）唯一调用者 `0x7eebc1`

---

## 1. 完整写入点清单（`[0xe59d20]`，6 处）

| 地址 | 值 | 上下文 |

## 2. ★ 关键：`0x621810` 的调用者

```
0x621ac0  mov [0xe59d20], edi
0x621ac6  call 0x6212c0
```

**`0x621810`（含 `0x621ac0` 的函数）唯一调用者：**

```
0x7eebc1
```

**而 `0x7eebc0` 正是状态机里被反复调用的函数：**

- `lobby/72`：状态 2 → `0x7ef266` 里调用
- `lobby/72`：状态 3 → `0x7ef271` 里调用
- `lobby/53`：状态 1 → `0x7ef1b3` 里调用

## 3. 循环依赖的解除

**`lobby/75` 的矛盾：**

```
[0x849ba30]==3 → 0x7e98f0 → 0x6212c0 → [0xe59d20]=5
                                          ↓
                                  [0xe59d20] ∉ {4,6}
                                          ↓
                              [0x849ba30] 到不了 3   ← 循环！
```

**但 `[0xe59d20]` 还有另一条路：**

```
0x7eebc0（状态机每帧都调）
   ↓
0x621810
   ↓
0x621ac0  [0xe59d20] = edi     ← ★ 直接赋值
```

**⇒ `[0xe59d20]` 由状态机的常规循环设置，不依赖 `0x7e98f0`。**

**⇒ 循环不成立。**

---

## 4. 完整的真实顺序

```
1. 状态机跑（0x7ef1xx）
2. 每帧调 0x7eebc0
3. 0x7eebc0 → 0x621810 → 0x621ac0 → [0xe59d20] = edi
4. 然后 0x6212c0(bool) → [0xe59d20] = 3 或 5
5. 下一帧 0x62186b 读旧值 3 → 写 4（大厅）
6. [0xe59d20] = 4
7. 0x622220() 通过
8. 状态 7 的三重判断通过
9. [0x849ba34] = 8 → 3
10. [0x849ba30] = 3
11. 0x808261 通过
12. 0x7e98f0 → 0x7e9933 → 房间对象
```

**⇒ 关键在步骤 3 的 `edi`。**

---

## 5. `edi` 是什么

**`0x621810` 是网络收包处理函数
（里面有 `push 0x81a55a0` + `call [0xca8190]` 加锁）。**

**⇒ `edi` 很可能来自"服务器下发的模式"或"本地界面状态"。**

**⇒ 这是 `[0xe59d20]` 的真正入口。**

## 7. 这一卷的净结论

**`[0xe59d20]` 有两个来源：**

1. **`0x6212c0(bool)` → 3/5**（初始化时）
2. **`0x621ac0` ← `edi`**（状态机循环）

**⇒ 第 2 条是常规路径，第 1 条是启动路径。**

**⇒ 两者都在 `0x7eebc0` 的下游。**
