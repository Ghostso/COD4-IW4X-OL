## 6. ★★ 魔数 C = `roomChatChannelID`，双形态坐实

**`0x1122334455667788` 这个值，**全语料以两种形态出现**：**

**① 二进制 u64（`0x0a` 标签，298 次）：**
```
11/4   ×228
21/1   ×35
21/12  ×26
11/2   ×9
```

**② 十进制明文（在 `6/14` 的 blob 里，47 次）：**

```
mmstart sv_resetServer; 2486 1; 3265 1; 2489 0; 2574 0; 2500 0;
g_gametype coop;  g_difficulty 0; ; map coop_training_mp_cargoship;
2654 M7-E8S6Client; roomChatChannelID 1234605616436508552;
```

**⇒ `roomChatChannelID 1234605616436508552` —— 字段名就在明文里！**

**★ 这是一个**决定性的闭环**：**
**- 二进制侧：`0x1122334455667788` 是 u64**
**- 明文侧：`roomChatChannelID 1234605616436508552`**
**- `1234605616436508552` 的十六进制**正是** `0x1122334455667788`**

**⇒ 两条独立路径（二进制解析 + 明文文本）指向同一个常量，且**明文直接给出了字段名**。**

**★ 而且 `0x1122334455667788` 是一个**人工构造的易读魔数**
  （11 22 33 44 55 66 77 88），说明这是**腾讯自己的占位/默认频道 ID**，
  不是真实分配的 ID。**

**⇒ 这解释了为什么它跨 4 个 task 出现：它是一个**全局默认值**。**

## 7. 魔数 A 与 B 的性质

**`0xD692ADAB`（237 次）与 `0x8D51E398`（36 次）：**

**⇒ 两者都**不是**易读魔数（不像 0x1122334455667788），
  也**不是** -1/0 这类哨兵。
  ⇒ 它们是**真实的哈希值或 ID**（每次会话可能变）。**

**★ 我查过：`0xD692ADAB` 在 21/5 里恒等于 159 次同一个值 —— 说明**同一次会话内不变**。
  这与"会话 ID"一致（一次会话一个值，跨会话会变）。**

**⇒ 但**不能确认**它是会话 ID：可能是账号哈希、房间哈希、或某个 CRC。
  **标注为未定，不猜。****

## 9. `0x07` 的标签/值歧义

**`0x07` 作为标签 12,634 次，非标签 856 次，比例 15:1。**

**⇒ 与 `0x01`（1:75）相反：`0x07` 主要是标签。**

**★ 为什么？因为 i32 字段**很少取值 7**（全语料 i32 值=7 的只有 6 个）。
  ⇒ 所以 `0x07` 字节几乎总是"标签"，不是"值"。**

**⇒ 这是"标签字节的取值域"决定的：
  一个标签值如果在"值域"里罕见，它作为标签的纯度就高。**

**★ 对照：`0x01` 既是常见值（1）又是标签 ⇒ 歧义大；
  `0x07` 是罕见值（7）但常见标签 ⇒ 歧义小。**

## 11. 可落地结论

**① `roomChatChannelID = 0x1122334455667788` 是一个**可安全替换的魔数**。**
**⇒ 它同时以二进制 u64 和明文十进制出现，改一处必须改两处（否则不一致）。**
**⇒ 这是"加/删/自定义"大厅时最直接的一个可控字段。**

**② 8/3 的 i32 只有 11 个值，且族 A（0x2711..0x277A）是稀疏 ID 表。**
**⇒ 如果要在 8/3 里加一个新配置，只需加一个新的 `0x2711` 段值。**

**③ `-695030357`(0xD692ADAB) 在 21/5 恒同值。**
**⇒ 它很可能是"当前会话/玩家"的标识；改它可能让客户端找不到对应对象。**

**④ i32 值域只有 59 种 ⇒ 如果客户端收到一个"新值"，行为未知。**
**⇒ 构造报文时优先复用这 59 个已知值。**
