## 一、最后的转折

上一卷我以为焦点是"`0x7e98f0` 是否被调用"。

这一卷反汇编 `0x808240`，在它的第 6 条指令就看到了：

```asm
0x808261  cmp dword ptr [0x849ba30], 3
0x808268  jne 0x80852c
```

**一个 `cmp ..., 3`。**

**然后实测：`[0x849ba30] = 0`。**

**整条链，断在这里。**

---

## 二、为什么这比之前所有发现都重要

**前面的发现都是"某个对象是 0"。**

**这个是"为什么那个对象是 0"。**

```
[0x849ba30] != 3
  ⇒ 跳过整段初始化
  ⇒ 房间对象不创建
  ⇒ 所有房间功能失效
```

**一个数字，解释了全部现象。**

---

## 三、与项目已有记录的对上

`memory: codol-iips-must-be-enabled` 里写着：

> 改成 `enable_iips=1` 后完整进大厅（**`5E8=1→3`**）

**那个 `1→3` 的跃迁，和这个 `==3` 的闸门，是同一件事。**

**⇒ `[0x849ba30]` 就是"已进入大厅"状态的另一处镜像。**

**⇒ 早先那条记录（`enable_iips`）和这条（房间闸门）是同一根因的两端。**

## 五、修复路径

**不是改对象，不是调命令。**

**是让 `[0x849ba30] == 3`。**

**而这个值的来源是"进入大厅"的状态跃迁。**

**⇒ 修复路径：**

```
enable_iips = 1          （已有记录）
  ↓
客户端完成 Auth
  ↓
状态跃迁到 3
  ↓
[0x849ba30] = 3
  ↓
房间初始化执行
  ↓
房间对象创建
  ↓
25 个命令可用
```

**⇒ 不需要打补丁，只需要让启动链走通。**

**这与项目规范（不改固化链）一致。**

## 六、三级闸门

**不止一个条件：**

```asm
0x808261  cmp [0x849ba30], 3        ← 一级：状态
0x808268  jne 0x80852c

0x808273  cmp byte [0x849ba3d], 0   ← 二级：标志
0x80827a  jne 0x80845f

0x808285  cmp eax, 5                ← 三级：索引
0x808288  ja  0x80845f
```

**实测四个值全为 0。**

**⇒ 一级都过不了，后面两级还谈不上。**
