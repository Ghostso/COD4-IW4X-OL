# 124 探讨 · 魔数 C 的第三张脸，和我自己制造的那个"黑箱"

> 配套：[124 · `71/15` 解压 + `wfUD3"` 假阳性](124_7115解压与wfUD3假阳性.md)
> 性质：方法论复盘。**主题：假阳性与"读法外衣"。**

---

## 一、我先承认一件事：`wfUD3"` 是我自己造的

`123` 卷我写"`68/3`/`21/1` 含 `wfUD3"` 疑似密文段"，把它列进 C 类真黑箱。

**这个黑箱是我用一条 ASCII 正则扫出来的**：`rb"[ -~]{5,}"`——只要是可打印字节连续 5 个以上就抓。

而魔数 C 的字节是 `88 77 66 55 44 33 22 11`。其中 `77 66 55 44 33 22` 这六个字节，**恰好**都是可打印 ASCII：`w f U D 3 "`。

**⇒ 我的正则把一段二进制魔数抓成了"可读字符串"**，然后我把它当成了"新的密文段"。

**这不是数据的问题，是工具的问题。** 而且是**我上一卷自己刚写过的教训**（"正则的字符类决定你能看见什么"）——我写下了这条教训，然后在下一卷**立刻又犯了它**。

## 二、怎么证伪的：不猜，数一数

我没有"看它像不像密文"。我做的是**计数对齐**：

```
字面 'wfUD3"' 出现次数      : {11/4:228, 21/1:35, 21/3:13, 11/2:9, 21/12:36}
真实字节 88 77 66 ... 出现次数: {11/4:228, 21/1:35, 21/3:13, 11/2:9, 21/12:36}
```

**两组数字逐 task 完全相同。** 如果 `wfUD3"` 是独立的密文段，它不可能和魔数 C 在**每一个 task 上**数量一模一样。

⇒ **`wfUD3"` ≡ 魔数 C 的子串。**

**"计数对齐"是最便宜的证伪手段**：不解释、不推理，只问"这两个东西是不是同一批"。**两个数字一模一样，就说明它们是同一个东西的两种写法。**

## 三、`71/15`：换个方向就开了

`123` 我觉得 `71/15` 是"二进制，162 distinct，未解"。

`124` 我看它的**开头**：`13 08 64 00 00 00 78 01 …`。

- `13 08 <u32 len>` = **blob 标签**（我们最熟的那个 `0x13`）；
- **`78 01` = zlib 头**。

**⇒ 它不是"二进制黑箱"，是一个被压缩的 blob。**

`zlib.decompress()` 一跑：**162/162 全部成功**，解出来是 **652 条遥测事件**（`UIPage`×505…）。

**我上一卷根本没有解压它，就判定"未解"。** 这是"看到高熵就当黑箱"的懒惰。

★ **教训**：**看到 `78 01`/`78 9c`/`78 da` 必须试解压。** 数据"看起来像二进制"不等于"解不开"——它可能只是被压过。

## 四、魔数 C 的第三张脸

这是本卷最有意思的地方。**同一个 `0x1122334455667788`，我们已经在三个完全不同的"外衣"下遇到过它：**

| 卷 | 外衣 | 我以为是什么 |
|---|---|---|
| `107` | 二进制 u64 `0x1122334455667788` | 频道 ID（对） |
| `122` | base64 文本 `iHdmVUQzIhE=` | 解出来是 `0x8877665544332211`（字节原样） |
| `124` | ASCII `wfUD3"` | 差点当成密文 |

**同一串字节 `88 77 66 55 44 33 22 11`，可以被：**
- 读成 u64 小端 → `0x8877665544332211`
- 读成 u64 大端 → `0x1122334455667788`
- base64 编码 → `iHdmVUQzIhE=`
- 读成 ASCII → `wfUD3"`（部分）

**四种外衣，一个本体。**

★★ **这就是 `118` 卷"黑箱先查旧卷"的深层原因**：不是"我忘了查"，而是**同一个东西会以完全不同的面貌出现，人眼根本认不出**。**必须用"字节串指纹"对账，不能用"数值/字符串"对账。**

## 五、给工具定一条硬规矩

本卷之后，我给所有 ASCII 扫描加一条自检：

> **任何"新发现的 ASCII 串"，先把它还原成字节，再用字节串去全库搜，看它的出现次数是否和某个已知魔数完全一致。**

如果一致 ⇒ 它是魔数的外衣，不是新东西。

**这是"假阳性防火墙"。** 没有它，我每写一次 ASCII 正则，就会多造一个假黑箱。

## 六、诚实的部分

- `71/15` 解压后的 652 条事件，我只给了事件名词表和 `UIPage` 的 pageId 分布，**没有逐条对时间线**（`${TIMESTAMP_OFFSET(-N)}` 的 N 值序列可能有会话内的先后语义）。
- `pageId` 的 28 种值（2..154）**我只知道是页面编号，没有映射到具体页面名**（那需要 UI 资源/`.ifs` 里的页面表）。
- `wfUD3"` 的证伪是**计数对齐**，我**没有解释**为什么魔数 C 会出现在这么多 task 里（那是 `107`/`109` 卷的课题，本卷不重复）。

## 七、方法论（可迁移）

1. **假阳性防火墙**：新 ASCII 串先还原成字节，按字节串全库对账，看是否等于已知魔数。
2. **计数对齐是最便宜的证伪**：两个东西在每个 task 上数量一致 ⇒ 它们是同一个东西。
3. **看到 `78 01`/`78 9c`/`78 da` 必须试解压**。"看着像二进制"≠"解不开"。
4. **同一字节串有多种外衣**（u64 小端/大端、b64、ASCII）——只认字节串指纹，不认数值/字符串。
