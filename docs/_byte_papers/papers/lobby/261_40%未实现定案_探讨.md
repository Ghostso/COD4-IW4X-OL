# 261 · 探讨：「未实现」是一个作者视角的词

> 配套：`261_40%未实现定案_46%遥测_其余常量通知.md`

---

## 一、232 写的那个句子

> "服务端只覆盖 31/55 个 (svc,task) = **40.4%(2767/6848) 走 UNMAPPED 空 ACK**，实机日志逐条证实"

这句话后来被引用了好几卷。它有一个隐含主语：

> "（**客户端发的这些**）**功能没被实现**（**这是不好的**）。"

两个隐含部分都不是数据给的：

1. **"未实现"** —— 这是**服务端源码作者**在 `lobby_server.py:1316` 里写下的一句话
   （字面：`"UNMAPPED ... 功能未实现"`）。它是**一个作者的判断**，不是协议事实。
2. **"这是不好的"** —— 引文里没有，是读者补的。40.4% 这个数字本身中性。

本卷把这个数字拆开，只做一件事：**问每一片"客户端发完之后，是否需要服务端回数据？"**

## 二、拆开后，第一大块是遥测

```
svc 71（10 个 task）= 1285 条 = 未覆盖的 46.4%
```

而这 1285 条的载荷是明文的：

```
71/7:  "ClientOffline|${TIMESTAMP}|1649370|0|0|6|..."
71/3:  "TimerErrors|${TIMESTAMP_OFFSET(-4)}|1649370|..."
       "ClientLoadout|${TIMESTAMP_OFFSET(-4)}|..."
```

**这是"客户端上报"，不是"客户端提问"。** 上报**语义上就不需要返回数据**。
服务端对它 `UNMAPPED → 空 ACK` 是**协议正确**的，不是"没实现"。

（服务端源码里还有一行注释：`"卡死 -> ClientException(service=71 task=7) -> 10053"` ——
意思是**以前试过对它"不回"**，结果客户端超时异常。现在的"回空 ACK"是**修过的**行为。
这佐证：**这里是"要不要应答"的问题，早就有答案了，只是没写进那 40.4% 的措辞里。**）

## 三、剩下的，几乎全是常量

把非 71 的未覆盖逐 (svc,task) 去重：

| distinct 载荷数 | task |
|---|---|
| **1**（纯常量） | `3/46` `3/48` `3/53` `9/5` `9/14` `10/20` `12/6` `28/4` `29/10` `68/8` `102/2` |
| 2~8 | `4/4` `4/13` `68/3` |

**12 个里 11 个的载荷只有一种取值**（`4/13` 290 条里 270 条同一取值）。

**一个"常量"载荷意味着什么？**
客户端发的是**它自己硬编码的一串**，它**不会去解析服务端回的字段** ——
因为如果它期待"服务端返回 X"，X 就应该出现在请求里才会变（至少在某些上下文里变）。

所以：**常量载荷 ⇒ 客户端不依赖服务端数据 ⇒ 空 ACK 不破坏它。**
（`12/6`、`102/2` 甚至只有 1 字节 `00` —— 连数据都没有，纯触发。）

**这是本卷唯一的新工具：用"载荷可变性"当"是否需要服务端数据"的静态代理判据。**
它**不需要运行时就成立**，因为它只用客户端的**发出**行为。

## 四、为什么"未实现率"这个框很危险

假设有人拿着 232 这句话去干活：

- 他会去 `lobby_server.py` **给这 20+ 个 (svc,task) 补分支**；
- 但大部分分支**没有"正确应答"可写**——因为客户端不发数据/不等数据；
- 他会**编一个应答**（就像 231/160 卷里"照抄 ol-mod"那样），
- 于是把一个**本来正确的空 ACK** 换成一个**被解析的错误应答** ——
  **功能从"正常"变成"坏"**，而且现场表现（"没反应"）和"服务端没实现"**一模一样**，
  极难定位。

**这正是 235 卷反复警告的事**（`reply+5` 极性是服务私有的，外推会把能用的服务改坏）。
本卷与 235 互补：235 说"别乱改判据"，本卷说"**先别急着判它该不该被实现**"。

## 五、本卷自查

| 断言 | 怎么验的 |
|---|---|
| 40.4% | `b3_gap.py` 逐字复算 |
| 遥测 46.4% | svc71 十片逐条累加 |
| 载荷为 ASCII 事件 | 语料 payload 逐条解 hex→ASCII |
| 常量载荷 | 逐 (svc,task) `distinct(payload)` 计数 |
| 4/13 = 核心 ID | `0a` 标签后 8 字节 → u64 = `0xE7C8A98A6B4C2D0E` |

## 六、还没验的（不许写成结论）

- **客户端是否读取这 20 个未覆盖 task 的应答体**：本卷只证"发的是常量"，
  没证"收到空 ACK 后不报错"。**这一项静态可做**（逐个找它们的 reply 回调），
  本卷时间不够，**明确留为下一步**，不得用"常量载荷"当成"一定安全"的结论。
- `71/15`（162 条二进制）只是**按族**归到遥测，未逐字节解。
- `28/4` 那个 519 字节常量块未解内容。
