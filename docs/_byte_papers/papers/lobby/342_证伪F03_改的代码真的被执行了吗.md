## §4 ★ 有两处"真的被重新生成"的东西 —— 但都不是代码

### 4.1 证书：每次运行都会重新签发

`run_all.py:701–705` 默认走 `make_certs()` → 调 `make_local_ca.ps1` → **重写** `_ca.pem / _leaf2.cer / _leaf2.key / _leaf2_chain.pem / _rsa.txt`。
实测哈希不等：

| 文件 | work | source |
|---|---|---|
| `_rsa.txt` | `F435976CB987…` | `A4FF58ECCE9F…` |
| `_ca.pem` | `FE2269E79346…` | `F13B55242BCF…` |
| `_leaf2.cer` | `77E4C57354DA…` | `DCFF045BDBA7…` |
| `_leaf2.key` | `D917A0ED103B…` | `197D851CAE8C…` |
| `_leaf2_chain.pem` | `27FF24999C8B…` | `D50575B0FF3E…` |

`postflight.work_hashes` 把新哈希记了下来，而 `source_manifest.json` 记的是旧哈希 —— **这是 `_rsa.txt` 等 5 项在 postflight/source 对照里必然 different 的唯一原因**，与代码无关。
★ 但这意味着：**若有人拿 `_leaf2.cer` 的 sha 去校验"跑的是不是我们那套"，会得到假阴性。** 证书不能当版本指纹。

### 4.2 受保护的"基准"本身在 15:14:40 被重建过

| 文件 | mtime |
|---|---|
| `CODOL_VERIFIED_GOLDEN_20261019\lobby_server.py` | **2026-11-03 15:14:15** |
| `CODOL_VERIFIED_GOLDEN_20261019\_run_once_hashes.json` | **2026-11-03 15:14:40** |

⇒ 本轮"kit == protected mirror == 基线清单"三绿，是在**清单从同一批文件重建之后**取得的，
**证明力弱于"清单先存在、后核对"**。这属于 271 卷"校验对象 == 执行对象"教训的延伸：
**清单由被执行的文件生成时，它只能证明"没在启动之后被改"，不能证明"启动前是我们想要的那份"。**

## §5 日志证据：跑的是新版（同一位点，前后对照）

`kit\lobby_srv.log` 中存在只有新版才可能输出的行：

```
line 38: [15:15:36]        -> 6/5 拉取(cursor=0,max=20,consume=1) -> Manifold 位流 count=0 (6 字节)
```

对照上一轮旧版（`runs\ONCE_20261103_150800\kit\lobby_srv.log`）：

```
line 38: [15:08:32]        -> 6/5 空应答(payload=13)
```

**位点相同（都是 seq=6 / service=6 / task=5 的第一条应答），文字不同。**
新版字符串 `"6/5 拉取(...) -> Manifold 位流 "` 在 `lobby_server.py:1200`，旧版文件里**不存在**；
且它只在 `if task == 5:`（1196–1201 行）分支里产生。

⇒ 这条日志**只能**由 `5652EC58` 那份 `lobby_server.py` 写出。**代码被执行，实证成立。**

同一日志另可见 `codol_crypto.build_manifold()` 的产物被当成应答对象（`对象=1`、82 字节应答），
即 import 到的是 `02F762FF…` 那份 `codol_crypto.py`（`def build_manifold` 仅此一份有所需签名）。
