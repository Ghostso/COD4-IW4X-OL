# 188 · 两个 49 元素数组的步进核查：元素起点 = `esi-8`，数组 B 起点 `+0x7B0`

> 卷次：188（房间类 · 186/187 卷的步进修正）
> 方法：注意"先 `sub esi,0x238` 再写 `[esi-8]`"的顺序
> 结论：**元素起点 = `esi-8`**，两个数组的基址与 186 卷算的不同。

---

## §0 两段初始化代码

### 0.1 数组 A（`0x637CFA..0x637D4D`）

```asm
0x637CFA  mov dword [ebp+8], 0x31        ; 计数 49
0x637D01  lea esi, [ebx + 0xE368]        ; 初始 esi
0x637D10  mov ecx, [esi - 0x23C]
0x637D16  sub esi, 0x238
0x637D1C  mov dword [esi - 8], 0xDC79F0  ; ★ vtable#1 在 esi-8
0x637D23  mov dword [esi],     0xDC79FC  ; vtable#2 在 esi
0x637D2C  lea ecx, [esi + 0x120]
0x637D32  mov [edx+esi-4], 0xDC7A08      ; vtable#3 在 esi-4
0x637D3A  call 0xB95AA0
0x637D3F  lea ecx, [esi + 0x228]
0x637D45  call 0xB757E0
0x637D4A  dec dword [ebp+8]
0x637D4D  jns 0x637D10
```

### 0.2 数组 B（`0x637D8D..0x637DDD`）

```asm
0x637D8D  mov dword [ebp+8], 0x31        ; 计数 49
0x637D94  lea esi, [ebx + 0x7238]
0x637DA0  mov edx, [esi - 0x23C]
0x637DA6  sub esi, 0x238
0x637DAC  mov dword [esi - 8], 0xDC79F0   ; vtable#1 在 esi-8
0x637DB3  mov dword [esi],     0xDC79FC   ; vtable#2 在 esi
0x637DBC  lea ecx, [esi + 0x120]
0x637DC2  mov [eax+esi-4], 0xDC7A08       ; vtable#3 在 esi-4
...
0x637DDA  dec dword [ebp+8]
0x637DDD  jns 0x637DA0
```

★★ **两段代码结构完全相同，只是初始 `esi` 差 `0xE368 - 0x7238 = 0x7130`。**

### 0.3 元素起点

写的是 `[esi-8]`（vtable#1）和 `[esi]`（vtable#2），相差 8。
⇒ **元素起点 = `esi - 8`**（vtable#1 在 +0，vtable#2 在 +8）。

| 数组 | 首次 esi（sub 后） | 元素起点 | 第 49 个元素起点 | 数组总跨度 |
|---|---|---|---|---|
| A | `0xE368 - 0x238 = 0xE130` | `0xE128` | `0xE130 - 48×0x238 = 0x7C10` | `0x7C10 ~ 0xE368` |
| B | `0x7238 - 0x238 = 0x7000` | `0x6FF8` | `0x7000 - 48×0x238 = 0x4AE0` | `0x4AE0 ~ 0x7238` |

★ 修正 186 卷：数组 B 起点 **`+0x4AE0`**（不是 `+0x7B8`），末元素起点 **`+0x6FF8`**（不是 `+0x7238`）。

### 0.4 与 `0x634B0D` 的对应

```asm
0x634AED  lea edi, [ebx + 0x7238]    ; = 数组 B 的"末尾之后"
0x634B0D  mov [ebp-0xC90], edi
```

★ `ebx+0x7238` 是数组 B **末尾之后的第一个字节**（`0x6FF8 + 0x238 = 0x7230`，还差 8 ——
实际 `0x6FF8 + 0x238 = 0x7230`，而 `0x7238 = 0x7230 + 8`。所以 `ebx+0x7238` 落在**最后一个元素 +0x8 处**）。

⇒ **`edi = 末元素的 `+0x8` 位置 = 第二基类子对象的起点**（vtable#2 所在）。

---

## §1 这解释了 187 卷的疑问

`0x625CE0` 的 `[this+8] = ebx+0x7238` = **末元素的 +8 位置 = 第二基类子对象指针**。

```asm
0x625CE0  mov eax, [esi+8]     ; = 第二基类子对象
0x625D2C  add eax, 0x18        ; → 该子对象的 +0x18
```

★ 所以 `+0x18` / `+0x118` 是**第二基类子对象内的字段**，而不是"MatchMakingInfo 主对象 +0x18"。

---

## §2 这使得 `0x806C90` 缺 `+0x18` 完全合理

`0x806C90`（vtable[0x0C]）是**主基类**的序列化器，它的 `esi = ecx` = 主基类子对象。
主基类看不到第二基类的 `+0x18`。

⇒ **没有矛盾，186 卷的"矛盾"是没区分基类子对象。**

## §5 方法论

1. **★★★ 「先 `sub reg,stride` 再写 `[reg-disp]`」说明元素起点要再减。** 186 卷我直接把首次 `esi` 当末尾，差了 8 字节。
2. **★★★ 两个结构相同的初始化循环，只差初始指针 ⇒ 是同一个类的两个数组。** 要问"为什么两份"。
3. **★★ 多重继承时，`[obj+8]` 可能是"第二基类子对象指针"，不是"第二个成员"。** 这解释了 187 的"字段缺失"。
4. **★★ 偏移矛盾先查"基类子对象"，再查"字段"。**
