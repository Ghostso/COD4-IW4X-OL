# ★★★ 房间对象的创建点：`0x639d19` → 构造函数 `0x62c000`

> 承接 `lobby/44`
> **找到了房间对象的创建链和触发条件。**

---

## 1. 创建代码（`0x639cf5`–`0x639d2b`）

```asm
0x639d03  push 0x3a128            ; ★ 参数
0x639d08  call 0xc3e9f5           ; 查找/设置某状态
0x639d0d  xor edi, edi
0x639d12  cmp eax, edi
0x639d14  je  0x639d25            ; 返回 0 → 不创建
0x639d16  push 1
0x639d18  push eax
0x639d19  call 0x62c000           ; ★ 构造函数
0x639d1e  mov [0x82e13fc], eax    ; ★ 存到全局
0x639d23  jmp 0x639d2b
0x639d25  mov [0x82e13fc], edi    ; 否则存 0
```

**⇒ `[0x82e13fc]` 只在 `0xc3e9f5(...)==非零` 时才被赋值。**

---

## 2. 构造函数 `0x62c000`

```asm
0x62c000  push ebp / mov ebp,esp
0x62c005  mov ebx, [ebp+8]        ; 对象指针
0x62c00c  mov [ebx+0x04], 0       ; 清零 7 个字段
0x62c00f  mov [ebx+0x08], 0
0x62c012  mov [ebx+0x0c], 0
0x62c015  mov [ebx+0x10], 0
0x62c018  mov [ebx+0x14], 0
0x62c01b  mov [ebx+0x18], 0
0x62c023  mov [ebx], 0xdc7274     ; ★ vtable
0x62c029  mov [ebx+0x1c], 0
0x62c01e  push 1
0x62c020  lea ecx, [ebx+0x20]     ; 构造子对象
...
```

**⇒ 对象布局：**

| 偏移 | 内容 |
|---|---|
| +0x00 | **vtable = `0xdc7274`** |
| +0x04..+0x18 | 6 个清零字段 |
| +0x1C | 0 |
| +0x20… | 子对象（`push 1` 参数） |

---

## 3. ★ vtable 在 `0xdc7274`

**`0xdc7274` 落在 `.tp3` 的只读段（`0xa16000`–`0xe5c8000`），
是一个可读的 vtable 指针表。**

**handler 里读的 `+0x38`（startgame）和 `+0xC0`（changemap）
就是从这张表取的。**

**⇒ 只要对象创建，这两条命令立刻可用。**

---

## 4. 触发条件：`0xc3e9f5(0x3a128)`

```asm
0xc3e9f5  push ebp / mov ebp,esp
0xc3e9fa  sub esp, 0x10
0xc3e9fd  jmp 0xc3ea0c
0xc3e9ff  push [ebp+8]
0xc3ea02  call 0xc4b5b4
0xc3ea07  pop ecx
0xc3ea08  test eax, eax
0xc3ea0a  je  0xc3ea1b
0xc3ea0c  push [ebp+8]
0xc3ea0f  call 0xc3d280
0xc3ea14  pop ecx
0xc3ea15  test eax, eax
0xc3ea17  je  0xc3e9ff
```

**这是一个"遍历/查找"循环，参数是 `0x3a128`。**

**`0x3a128` 是一个**资源 ID 或字符串 ID**。**

**⇒ 条件本质是：某个资源 `0x3a128` 必须存在/加载成功。**

---

## 5. 这意味着什么

**房间对象的创建不依赖网络，而依赖一个本地资源 `0x3a128`。**

**如果这个资源缺失，`0x62c000` 不会被调用，`[0x82e13fc]` 保持 0。**

**⇒ 这解释了为什么 302 处引用全部指向一个空对象。**

---

## 6. 与项目已有结论的统一

| 地址 | 状态 | 含义 |
|---|---|---|
| `[0x82E1518]`（dwRoomMatchUber） | 0 | 对象未创建 |
| `MyEventHandler` 实例数 | 0 | 回调未注册 |
| **`[0x82e13fc]`（room 对象）** | **0** | **对象未创建** |

**三个都是 0，但三个是不同层次：**

```
0x82e13fc  房间对象       ← 本轮找到创建点
0x82E1518  dwRoomMatchUber ← 已记录
MyEventHandler            ← 已记录
```

**⇒ 最底层是 `0x82e13fc`（房间对象），
它不创建，上面两个更不会创建。**

## 8. 字节级附录：对象的 7 个字段

构造时清零的偏移：`+0x04, +0x08, +0x0C, +0x10, +0x14, +0x18, +0x1C`

**共 7 个 4 字节字段 = 28 字节。**

**加上 vtable（4 字节）和子对象（从 `+0x20` 起），
对象头至少 36 字节。**

**这 7 个字段的填充者，就是房间状态的真正来源。**
