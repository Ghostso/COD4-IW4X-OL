# `.ff` 加密边界：本轮最终定位

> 承接 `lobby/36`、`lobby/37`

## 1. 两条独立的熵测量

| 对象 | 熵 | 0x00 占比 |
|---|---|---|
| `ff_init_common_gfx_V109.ifs` 内 `ui_mp.ff` 载荷 | **7.997** | 0.39% |
| `COD OL\main\mp_playlists.ff` 载荷 | **7.996** | 0.38% |

**两者都是 1/256 = 0.39% 的均匀随机分布。**

**⇒ `.ifs` 内的 `.ff` 和磁盘独立的 `.ff` 都是加密的。**

## 2. IFS 层负责什么

`IFS2.dll` 里的类名：

```
.?AVcb_glue@ifscompress@@
.?AVifscompress@@
.?AVIFSCompressedFile@@
.?AVifs_header_handler_interface@@
```

**`ifscompress` —— IFS 层做的是"压缩"，不是"加密"。**

**且 libtomcrypt 只含 `hashes/md5`、`hashes/sha1`、`pk/rsa`、`pk/ecc`，
没有任何对称加密**（`lobby/16` 已证）。

**⇒ IFS 层不解密 `.ff`。**

## 3. 加密边界图

```
磁盘 .ifs 文件
  │
  ├─ IFS 层（IFS2.dll）
  │    头部/清单解析（明文）
  │    扇区读取 + 压缩解包（ifscompress / bzip2）
  │    ★ 不改密文
  │
  ├─ .ff 载荷（熵 7.996，全密文）
  │
  ├─ IWff0100 分派器（0x483db0）
  │    只校验魔数 + 版本 461
  │    ★ 不解密（已证）
  │
  ├─ AES 解密循环（0x4834f0）
  │    被 0x1c4b700 门挡住
  │    ★ 对 IWff0100 永不执行（已证）
  │
  └─ 真正的解密位置
       ★ 未找到
```

## 4. 三个剩余候选（按可行性排序）

### 候选 A：TP3 保护层（最可能）

**依据：**

- EXE 的代码段叫 `.tp3`（TenProtect 3）
- `.tp3` 在磁盘上线性反汇编**错位**（`lobby/25`）
- 而内存镜像里代码是**连续正确**的
- **⇒ 磁盘代码被变换过，加载时才还原**

**同理，`.ff` 的载荷也可能由 TP3 在内存中解密。**

### 候选 B：VFS 的 RWFilter 链

`IIPSVFS.dll` 导出 9 个工厂，其中：

- `ICreateCoderRWFilter` —— 已读，半字节查表（不是 AES）
- `ICreateZlibRWFilter` —— 已读，纯 zlib

**但工厂能组合。** 可能存在"zlib + 加密"的组合过滤器，尚未在 `.data` 里找到实例。

### 候选 C：运行时内存

挂载后，`.ff` 在内存里可能是明文。
**但现有 dump 里 `0x1c51734`（AES key 槽）是 0，说明 dump 抓得太早。**
