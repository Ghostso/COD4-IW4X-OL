# 大厅与模式定义的分卷布局（`ff_*.ifs`）

> 对象：`ff_` 前缀的 `.ifs` 分卷，以及它们内部装载的 `.ff`
> 证据：`tools/ifs_ff_list.py`、直接字节读

---

## 1. 两类前缀

974 个 `.ifs` 分两大类：

| 前缀 | 含义 | 例 |
|---|---|---|
| **`lf_`** | **低清 / 资源分卷**（low fidelity） | `lf_hi_init_coop_training_mp_cargoship_V11.4.ifs` |
| **`ff_`** | **`.ff` 定义分卷**（fastfile） | `ff_init_common_gametype_mp_V69.ifs` |

`ff_*` 才是**逻辑内容**，`lf_*` 主要是贴图/音频/模型等资源。

## 4. 分卷命名规则

```
{lf|ff}[_hi]_{init|dlcN}_{[common|mp|zp|...]}_{name}[_sh][_V{major}[.{minor}]].ifs
```

**举例**：

| 名字 | 拆解 |
|---|---|
| `lf_hi_init_common_gametype_mp_V22.ifs` | 低清 / 高清 / 初始 / 通用 / 模式 / mp / 版本 22 |
| `ff_dlc19_clash_addon_mp_cross_fire_V26.ifs` | `.ff` / DLC19 / clash 附加 / mp / cross_fire / 版本 26 |
| `lf_dlc34_mp_battlecity_mountains_td_V1.ifs` | 低清 / DLC34 / mp / battlecity_mountains / td / 版本 1 |

**`_sh`** 后缀 = 小的贴图变体；**`_td`** = 某个变体。

## 6. 关键结论：模式可以"加"，也可以"删"

从布局看，**模式是独立分卷**：

- 一个模式 = 一个 `ff_init_common_gametype_<X>_V<n>.ifs`
- 其内容 = `common_gametype_<X>.ff`

**推论（未实测）**：

1. **删模式**：移除对应分卷 + 从 playlist 配置里删条目
2. **加模式**：新增一个模式分卷 + 在 playlist 里注册
3. **改模式**：替换 `common_gametype_<X>.ff` 内容

**门槛在 `.ff` 本体的格式（载荷加密）**，不在容器层。

---

## 7. 与大厅 UI 的关系

**大厅 UI 在 `common_mp.ff` 里**，而它在 `ff_init_common_mp_V111.ifs` 中。

要"加/删按钮、改页面"，需要：

1. 解出 `common_mp.ff` 的内容（越过载荷加密）
2. 理解 `.ff` 内的资产结构（菜单定义通常是一组 GSC/UI 脚本 + 资源索引）
3. 重新打包

**第 1 步是当前的最大障碍。**
