# 144 探讨 · 脱壳这条路走通了，而且第一次就把断点钉死了

> 配套：[144 · 脱壳成功](144_脱壳成功_运行时dump验证静态推断并锁定断点.md)
> 主题：**用户说"脱壳比较靠谱"。事实证明：不仅靠谱，而且一小时内就把四卷静态推断全部验证完，还锁定了故障根因。**

---

## 一、为什么脱壳这条路一开始就该走

我前四卷反复说"段2 覆盖 0.17%""数据在 BSS 空洞里"。

**但我从没问过：那些内存去哪了？**

答案是：**在进程里。** 而进程内存是可以读的——`ReadProcessMemory` 就够了，
不需要真正的 VMProtect 脱壳（那要模拟执行几百万条指令）。

★★★ **"脱壳"在这个场景里 = "读运行时内存"，不是"还原加密代码"。**

---

## 二、最有价值的一步：先查已有 dump

我没有立刻去跑游戏，而是先看 `run_codol_001\runs\` 里有什么。

**结果：三个现成的完整内存 dump。**

```
DUMP_20261031_194250   381 区  464.4 MB
DUMP_20261031_200456   728 区  463.2 MB
DUMP_20261031_221458   389 区  500.0 MB  ← 最高到 0x3ACF3000
```

★★★ **第三个刚好覆盖到 srpc 单例 `0x3AC89CB8`。**

如果我先去跑游戏，会浪费一整轮；如果只看前两个，会得出"读不到"的错误结论。

★★ **教训：动手前先盘库存。**

## 三、静态推断被运行时逐条验证

这是这一卷最爽的部分。我在 141 卷纯靠反汇编推出的东西：

| 静态推断 | 运行时实际 | 结果 |
|---|---|---|
| `dwLobbyImp` vtable = `0xDE07A4` | `0x00DE07A4` | ✅ |
| srpc vtable = `0xD599DC` | `0x00D599DC` | ✅ |
| 14 张哈希表偏移 | 14/14 全命中 | ✅ |
| 每表 1 个空串条目 | count=1（两表）| ✅ |
| `0x803861→0xB7A400` 绑定 | `srpc+0x4F0 = dwLobbyImp` | ✅ |
| `0x82E1458` 永不触发 | 运行时全 0 | ✅ |

★★★ **反汇编推出来的结构，一个字都没错。**

## 四、断点：`dwLobbyImp+0x4F0 = 0`

```
+0x4F0 = 0x00000000    ← dwLobbyEventHandler
```

**三个 dump，三次都是 0。**

然后我穷举了全镜像所有写 `[reg+0x4F0]` 的点：

```
0xB823FE  mov [esi+0x4F0], ebx   ← 构造函数，ebx = 0
0xBA92C0  mov [esi+0x4F0], edi   ← 析构函数，edi = 0
```

**只有清零，没有赋值。**

★★★ **"从未创建"是可以机械证明的 —— 穷举写点，全部为 0。**

---

## 五、这个断点解释了一切

```
dwLobbyImp+0x4F0 == 0
  → 0xB838A0 消息泵: cmp [edi+0x4F0], 0 / je 跳过
  → 所有 opcode 直接丢弃
  → 0x6371F0 房间消息处理器永不执行
  → rec+0x01 永远 0
  → 三条派发静默跳过
  → 房间按钮全部无反应，客户端不报错
```

**用户描述的"准备/改阵营/投票点了没反应"，机制完全对上。**

★ 而且这和记忆里 `codol-myhandler-never-created-root-cause`
（"MyEventHandler 实例=0 ⇒ 建房回调永不触发"）是**同一类故障**。

---

## 六、一个反直觉的中间结论

我一度以为断点是 `srpc+0x4F8 = 1`（降级标志）。

**仔细读 `0xB7A670` 才发现：**

```
cmp byte [esi+0x4F8], 0
jne 0xB7A699        ← +0x4F8 != 0 就跳过"强制返回 1"
```

`+0x4F8 = 1` ⇒ **返回底层值 2** ⇒ 注册条件**满足**。

★★★ **`+0x4F8 = 1` 不是故障，是"不要强制降级"的正常状态。**

我差点把一个正常值当成故障——**差一步就把结论带偏。**

---

## 七、还剩什么

1. **`dwLobbyEventHandler` 为什么没被创建** —— 知道"从未赋值"，不知道"创建函数在哪、为何没跑"
2. **哈希桶数组未捕获**（64 KB 页粒度漏掉）
3. **dump 时未进房间**（`+0x278 = 0`）

★ 第 1 项是**下一个要追的目标**，也是真正能修的地方。

---

## 八、方法论

1. ★★★★★ **"脱壳"可以只是"读运行时内存"** —— 不需要还原加密代码。
2. ★★★★ **动手前先盘库存**：已有 dump 可能直接够用。
3. ★★★★ **静态推断 + 运行时验证 = 双向闭环**，这次 6/6 全对。
4. ★★★★ **"从未创建"用穷举写点证明**，不是"没找到创建点"。
5. ★★★ **反直觉的值要先算清楚再下结论**（`+0x4F8 = 1` 是正常的）。
