# `dwRoomMessageP2PInfo`（类型 19）逐字节解剖：840 位里的每一个字节

> 承接 `lobby/94`（类型号表）、`lobby/97`（总图）
> 产物：`tools/const_payload_scan.py`、本卷新增的常量证据

---

## 1. 为什么单独立一卷

**`lobby/94` 才发现这个类（`dwroom_serializers.py` 漏收），
当时只能给出"840 位定长 + 67 字节固定 blob"这一句。**

**它的名字里有 "P2P"，而 memory 里 `codol-lsg-never-listening`
整条线都在说 P2P / 连接 / 监听失败。**

**⇒ 这是全项目**唯一一条与"P2P 连接参数"直接同名的报文**。
⇒ 必须逐字节拆开。**

## 2. 序列化全表（`0x627fc0`，逐条反汇编）

```
序号  tag    位宽     源              累计位
 1    0x03   8       [esi+4] 类型号=19    13
 2    0x15   32      [esi+8]             50
 3    0x13   blob    [esi+0x0C] 67 字节  578   (5+5+32+536)
 4    0x13   blob    [esi+0x4F]  8 字节  684   (5+5+32+ 64)
 5    0x15   32      [esi+0x58]          721
 6    0x15   64      [esi+0x60]          790
```

**等等，累计 790 而不是 840。重算：**

```
13 + 37 = 50
50 + (5+5+32+536) = 50 + 578 = 628
628 + (5+5+32+64) = 628 + 106 = 734
734 + 37 = 771
771 + 69 = 840 ✓
```

**⇒ 840 位 = 105 字节，与 `lobby/94` 一致。**

```
0x627f49  mov dword ptr [esi+4], 0x13      ← 类型号 = 19

0x627f56  mov dword ptr [esi+8], eax       ← 参数 1（32 位）
0x627f44  lea edi, [esi+0x4F]
0x627f59  call 0xb74060                    ← [esi+0x4F] = 01×8
0x627f64  lea eax, [esi+0x0C]
0x627f71  call 0xb74bc0                    ← 生成 67 字节 blob
0x627f76  push 8 / push 0xc7341d0 / push 8 / push edi
0x627f80  call 0xc3c603                    ← memcpy([esi+0x4F], 0xc7341d0, 8)
0x627f85  mov ecx, [ebp+8]
0x627f8b  call 0xb74700                    ← mov eax,[ecx+0x9C]; ret

0x627f67  mov dword ptr [esi+0x60], ecx    ← 参数 3（低 32 位）
```

**⇒ 完整对象布局：**

```
+0x5C    4      （对齐补齐）

```

## 4. ★★ 8 字节 blob = 常量，双路独立证据

**路径 A —— `0xb74060`：**

```
0xb74060  mov eax, ecx
0xb74062  mov ecx, 0x01010101
0xb74067  mov dword ptr [eax],   ecx
0xb74069  mov dword ptr [eax+4], ecx
0xb7406c  ret
```

**⇒ 把 `0x01010101` 写两遍 ⇒ 8 字节全是 `0x01`。**

**路径 B —— 静态常量 `0xc7341d0`：**

```
dump[0xc7341d0 : +8] = 01 01 01 01 01 01 01 01
```

**构造函数紧接着 `memcpy([esi+0x4F], 0xc7341d0, 8)`。**

**⇒ 两条路径写入**完全相同**的 8 字节。**

**⇒ ★★ 这是本项目第一次能**100% 确定**一条房间报文里的真实字节。**
**没有任何推断成分。**

## 5. 67 字节 blob 的来源（`0xb74bc0`）

**逐个字段看这个打包函数：**

```
0xb74bee  mov eax, [ebp+8]          ; 目标缓冲
0xb74c09  call 0xb75320             ; 构造子位流写器（栈上）
0xb74c20  loop:
0xb74c26    cmp ecx, [edi+0x10]     ; 遍历源对象
0xb74c2b    test bl, bl             ; 继续标志
0xb74c2f    mov ecx, [edi+8]        ; 源数组
0xb74c3f    add ecx, esi            ; + 步长
0xb74c62    push 0x43               ; ★ 每项 67 字节上限
0xb74c65    call 0xb75630           ; ★ 写一项（内部再分 2 位 + u16）
0xb74c74    inc [ebp-0xa4]
0xb74c7a    add esi, 0x88           ; ★ 源步长 136 字节
0xb74c80    cmp esi, 0x550          ; ★ 上限 1360 字节
0xb74c86    jb  loop
...
0xb74caf    mov dl, [edi+0x9c]      ; 一个 u8
0xb74cb5    push 1 / 0x43 / ...
0xb74cd5    call 0xb78350           ; 写 1 字节
```

**⇒ 语义：**

```
67 字节 = Σ_{i<N} ( 2 位 + u16 )  + 1 字节（[src+0x9C]）
```

**⇒ 外层循环步长 `0x88`(136) 字节、上限 `0x550`(1360) ⇒ 最多 10 项。**

**⇒ 这与同时在线玩家上限 10（5v5）完全吻合。**

**★ 这是"67 字节里装的是**对等玩家列表**"的直接结构证据。**

## 6. 67 字节的内部编码（`0xb75630` → `0xb77030` → `0xb78350`）

**这条链是"位写入器"：`0xb78350` 的第三个 out 参数做位偏移累加。**

```
0xb78362  lea ecx, [esi + edi]      ; new_off = off + nbits
0xb78367  mov dword ptr [edx], ecx  ; 回写 out 参数
...
0xb783a4  call 0xc3e400             ; ★ 按位写入（memcpy 形参，但 nbits 可非 8 倍数）
```

**沿链看到两个位宽常量：**

```
0xb7703f..0xb77052   push 4 ; call 0xb78350    ← 写 4 位
0xb77035             cmp word [ecx+0x80], 0x17 ; 若位流模式==0x17 则跳过
0xb7565e             push 2                    ← 写 2 位
0xb74cbe..0xb74cd5   push 1 ; push 0x43 ; call 0xb78350   ← 末项写 1 位
```

**⇒ 每一项经过 `4 位 + 2 位`（模式 0x17 时只 2 位），链尾写 `1 位`。**

**★ 诚实边界：这两个常量（4 与 2）我确实在指令里读到了，
但"它们是 nbits 而不是别的整型参数"这一步依赖对 `0xb78350` 形参顺序的判读，
而 `0xb78350` 有 6 个形参、`0xb75630` 有 6 条 push ——
**形参对应关系我没能完全钉死。***

**⇒ 所以 `67 字节 = N×(4+2) + 1 位` 这类算式我**不做**。**
**⇒ 本卷只确定：打包在**对等玩家数组上循环**（步长 0x88、上限 0x550 ⇒ 最多 10 项），
且每项走的是位写入而不是整字节拷贝。**

**⇒ 每项的具体位布局 = 下一卷的题目，本卷不下结论。**

## 7. 与其他消息的对比：P2PInfo 是唯一"发满定长"的 blob

**其余带 blob 的消息（`StartGame`）：**

```
0x13 0x08 <u32 = [eax+0x118]>  <n×8 位>
0x13 0x08 <u32 = 8>            <64 位>
0x13 0x08 <u32 = 0x10>         <128 位>
```

**⇒ 长度从**对象字段**取（`[eax+0x118]`）。**

**P2PInfo：**

```
0x13 0x08 <u32 = 0x43 立即数>  <536 位>
0x13 0x08 <u32 = 8     立即数>  <64 位>
```

**⇒ 长度是**编译期常量**。**

**⇒ 这是"固定容量缓冲"的写法，与 `StartGame` 的"变长"是两种设计。**

---

## 8. 与 P2P/连接线的关联（谨慎）

**memory `codol-lsg-never-listening`：外部 Localnetworking 方案
"让出 3074 + 我们的 lobby 接管，客户端仍不 connect"。**

**P2PInfo 是"把本机对等玩家表告诉对方"的报文。**

**⇒ 如果这条报文从未被正确发出，对等方就不知道我们的 P2P 地址。**

**⇒ 但这是**假设**，不是证据。**
**本卷只确定"结构 + 8 字节常量"，不宣称"它导致连接失败"。**
