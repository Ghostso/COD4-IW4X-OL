## §0 结论

1. **★★★ 每个 svc 有一个"宿主对象"工厂函数**（模板生成，前 24 条指令逐字节相同）：`0xB80D90`(svc 3) / `0xB81250`(svc 80) …
2. **★★★ svc 3 的 21 个 task 全在 `0x7FF5xx~0x8000xx` 区**，由一个共同入口 `0x7FF500` 派生，走 `0xB92140` 构造。
3. **★★ `0xB80D90` 有 25 个调用点，全部落在 `0x7FFxxx` 区** —— 该区就是服务 3 的客户端封装层。

## §1 ★★★ 宿主对象工厂族（24 条相同前置）

### 1.1 两个函数的逐字节对照

```asm
; 0xB80D90  (svc 3 的宿主 getter)
0xB80D90  push ebp / mov ebp,esp / push -1 / push 0xC8B753 / mov eax,fs:[0] / push eax
0xB80DA1  sub esp,0xC / push ebx / push esi / push edi
0xB80DA7  mov eax,[0xE3F240] / xor eax,ebp / push eax
0xB80DAF  lea eax,[ebp-0xC] / mov fs:[0],eax
0xB80DB8  mov ebx, ecx
0xB80DBA  xor esi, esi
0xB80DBF  call 0xB7A670            ; ★ 认证检查
0xB80DC4  cmp  eax, 2
0xB80DC7  je   0xB80DE4            ; ★ 通过 → 继续
0xB80DC9  call 0x8435D0            ; ★ 空桩（失败标记）
0xB80DCE  xor  eax, eax
...ret 4

; 0xB81250  (svc 80 的宿主 getter)
0xB81250  push ebp / mov ebp,esp / push -1 / push 0xC8B753   ← ★ 同一个 SEH cookie!
...完全相同到 0xB8127F call 0xB7A670 / cmp eax,2 / je 0xB812A4
```

★ **两个函数的 SEH cookie 都是 `0xC8B753`，前 24 条指令完全一致** ⇒ 同一模板实例化。

### 1.2 26 个工厂函数（各对应一个 svc）

这类函数在 `0xB80xxx~0xB81xxx` 区密集排列，每个负责「取某个服务的宿主对象」。`0xB81250`(svc 80) 与 `0xB80D90`(svc 3) 是两个样本。

## §2 ★★★ 服务 3 的客户端封装层：`0x7FF500` 区

### 2.1 共同入口 `0x7FF500`

```asm
0x7FF500  push ebp / mov ebp,esp / push ecx / push esi / push edi
0x7FF506  call 0x803830            ; srpc 单例
0x7FF50B  mov  esi, eax
0x7FF50D  test esi,esi / je 0x7FF52F
0x7FF511  mov  ecx, esi
0x7FF513  call 0xB7A670            ; ★ 认证 == 2 ?
0x7FF518  cmp  eax, 2
0x7FF51B  jne  0x7FF52F            ; ← 未认证直接返回 false
0x7FF51D  push 0xDAE091            ; ★ 空串哨兵
0x7FF522  mov  ecx, esi
0x7FF524  call 0xB80D90            ; ★★ 取 svc 3 宿主对象
0x7FF529  mov  esi, eax
0x7FF52D  jne  0x7FF537
0x7FF52F  xor  al, al / ret        ; 失败 → false
0x7FF537  sub  esp, 0x30
0x7FF53A  mov  ecx, esp
0x7FF53C  push 1
0x7FF53E  call 0xB85D60            ; 构造参数对象
0x7FF549  push eax                 ; 参数2
0x7FF54A  push ecx                 ; 参数1
0x7FF54B  lea  edx, [ebp-4]
0x7FF54E  push edx                 ; 输出
0x7FF54F  mov  ecx, esi
0x7FF551  call 0xB92140            ; ★★★ svc 3 的构造器（内含 task=0x1E）
0x7FF556  mov  ecx, [ebp-4]
0x7FF559  test ecx,ecx / je 0x7FF52F
0x7FF55D  push 0x8003E0            ; ★ 通道号 0x8003E0
...
0x7FF57F  push 0x3A                ; ★ svc = 58 ?? 需核（可能是后续调用的参数）
```

★ **`0xB92140` 是 svc 3 的一个 task 构造器（task=0x1E=30），与 §233 表的 `svc 3 task 30` 对上。**

### 2.2 `0xB92140` 的函数体（写侧）

```asm
0xB92140  ... 
0xB921A7  cmp dword ptr [ebp + 0x10], 0
0xB921AB  je  0xB92227
0xB921AD  push 0x80000             ; reserve
0xB921B2  push 0x400               ; bufsize
0xB921B7  push 0x1E                ; ★ task = 30
0xB921B9  push 3                   ; ★ svc = 3
0xB921BB  lea  ecx, [ebp - 0x44]
0xB921BE  call 0xBA72C0            ; ★ TaskBuilder
0xB921C3  lea  eax, [ebx + 8]
0xB921C6  push eax
0xB921CE  call 0xBA7250            ; 写入对象字段
0xB921D3  push 0x40 / push esi
0xB921D9  call 0xBA75D0            ; 写 0x40 字节缓冲
0xB921E1  lea  ecx, [ebp + 0x14]
0xB921E5  call 0xBA71C0            ; 写另一段
0xB921F6  mov  edx, [ebp + 0x10]
0xB921F9  mov  [ebp - 0x24], edx   ; 参数校验
0xB92205  call 0x8435D0            ; 失败桩
0xB92211  lea  eax, [ebp - 0x44]
0xB92215  push eax / push edi
0xB92216  call 0xB7A330            ; ★ 提交发送
0xB92222  call 0xBA7120            ; 析构
```

★ **这就是一个完整的 task 发送函数：TaskBuilder → 写字段 → `0xB7A330` 提交。**

`0xB7A330` 与 231 卷的出口漏斗 `0x7FAA20`/`0x7FAB70` 同族（`0xB7A330` 是更底层的 srpc 提交）。

## §3 服务 3 的 24 个 task 分布

从 233 §2.1 的表 + 本节：24 个 task（30..38, 46..53, 57, 63..66, 91, 92, 128）全部由 `0xB92xxx` 区的 24 个函数构造，这些函数**共享同一模板**：

```
0xB92140 (task 30)
0xB92260 (task 31?)   ← 0xB922DE 的 call site
0xB92380 (task 32?)   ← 0xB923F8
... 直到 0xB92C2B
```

★ **模板 = 上面 §2.2 的 12 条指令，只差 `push <task>` 的立即数。**

★ **⇒ 服务 3 是一组"同构查询"服务**：24 个 task 结构相同、只差 task 号和写入的字段对象。这与语料里 `3/46`、`3/48`、`3/53` 三种 payload **长度相近（24/29/19 字节）、字段同族**完全吻合（224 卷已记录）。

## §7 方法论

1. **★★★ 「相同 SEH cookie」是识别模板实例化的快判据。** `0xB80D90` 与 `0xB81250` 的 `push 0xC8B753` 完全一致 ⇒ 同源模板。**扫同一 cookie 立即数就能一次找全一整族函数。**
2. **★★★ 服务封装层有固定三段结构**：`0x803830`(srpc) → `0xB7A670()==2` → `0xB80xxx(空串)` 取宿主 → `0xB92xxx`(TaskBuilder + 写字段 + `0xB7A330` 提交)。**任何未知 svc 的客户端入口都可以按这个三段找。**
3. **★★ 「同构服务」的判据是「多个构造函数只差一个立即数」。** svc 3 的 24 个 task 就是这种情况，与语料里三种 payload 结构同族吻合。
