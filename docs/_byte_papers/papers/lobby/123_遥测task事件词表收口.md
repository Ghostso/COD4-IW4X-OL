## §1 `71/3`：客户端事件遥测流（18 种事件名）

`telemetry_events.txt`：

| 事件名 | 次数 | 语义 |
|---|---|---|
| `ClientLoadout` | 4355 | 客户端配装 |
| `LoadoutChangeEvent` | 336 | 配装变更 |
| `ClientLoadTime` | 85 | 客户端加载耗时 |
| `UIFriendList` | 83 | UI 好友列表 |
| `TimerError` | 82 | 计时器错误 |
| `ChannelSubscriptionFail` | 48 | **频道订阅失败** |
| `CreateRoom` | 25 | **建房（遥测事件！不是真建房）** |
| `MatchMaking` | 22 | 匹配 |
| `MatchMakingJoin` | 9 | 加入匹配 |
| `MissingLocalizedString` | 8 | 缺本地化串 |
| `UserSettings` | 2 | 用户设置 |
| `REWARD` | 2 | 奖励 |
| （武器/情报名 ×6，各 1 次） | 1 | 如 `WEAPON_INTEL_PACK`、`SF_MOLOTOVTDREWARD_MP_NAME` |

时间表达式种类：`TIMESTAMP_OFFSET`（4719 次）/ `TIMESTAMP`（336）/ `ZONEID`（8）。

★★ **`CreateRoom` 出现在 `71/3`（×25）——这正是 `pve-startgame-blocker` 记忆里"71/3 的 CreateRoom 是 TLog 不是开局"的**直接证据**。建房"事件"是遥测打点，不是 `11/13` 那种真建房。
★ `ChannelSubscriptionFail`（×48）**印证了 `06_05_事件订阅`记忆**：频道订阅会失败（服务端没真正实现 6/5 推送）。遥测自己在报这个失败。

**时间表达式语义**：
- `${TIMESTAMP_OFFSET(-N)}` = 当前时间戳减 N（相对事件时刻）
- `${TIMESTAMP}` = 绝对时间戳
- `${ZONEID}` = 时区/区域 id
- `${CODOID(x)}` = 把 u64 账号 ID 转 CODOID 表示

**最长样本（8061B）结构**：
```
TimerError|${TIMESTAMP_OFFSET(-4)}|1649370|16701785630074219790|${CODOID(...)}|0|0|0\n
ClientLoadout|${TIMESTAMP_OFFSET(-4)}|16701785630074219790|${CODOID(...)}|70|B01|10001|25035,22142,|...
```
⇒ **多条事件用 `\n` 分隔**，一条 payload 可以打包上百条事件。（这解释了 `71/3` 长度 105..8061 的跨度。）

## §4 §七 #2 的 B/C 类

### 4.1 B 类：固定常量（`distinct=1`）

`task_semantics_census.txt` 显示大量 task 是 `distinct=1`（全语料逐字节相同）：`3/46`/`3/48`/`3/53`、`6/5`、`8/1`、`9/5`/`9/14`、`10/20`、`29/10`、`68/8`、`71/9`/`71/10`/`71/13`/`71/20`、`80/*`、`93/1`、`102/2`/`102/5`/`102/7`。

**这些"结构无语义"的实质是：它们是固定请求模板**（每次报文逐字节相同）——语义已由 `114` 卷的 service/task 总表给出（生涯/好友/统计/商城…）。**字节层面已闭合；"业务语义"是 service/task 层的事，不是字节层黑箱。**

### 4.2 C 类：仍需真 RE（本卷已排除一个假阳性）

| task | 现象 | 说明 |
|---|---|---|
| `71/15` | 二进制，distinct=162 | 加密/压缩，非明文；**唯一真正未解的 §七 #2 项** |
| `12/6`、`11/13`、`8/2` | 单字节 `00` | 空/占位，语义 = "无内容" |
| `68/3`、`21/1`、`21/12` | 含 `M7-E8S6Client` + ~~`wfUD3"`~~ | ★ **`wfUD3"` 是假阳性**（见下） |

★★ **`wfUD3"` 假阳性更正**（`wfud3_confirm.txt`）：普查脚本的可读 ASCII 片段里出现 `wfUD3"`。追查发现它**不是密文**——是 **魔数 C 的字节 `88 77 66 55 44 33 22 11` 被 ASCII 正则误捕**：
```
0x77='w' 0x66='f' 0x55='U' 0x44='D' 0x33='3' 0x22='"'
```
证据：全语料里**字面 `wfUD3"` 的出现次数 == 真实字节 `88 77 66 55 44 33 22 11` 的出现次数**，逐 task 完全一致（`11/4`:228 / `21/1`:35 / `21/3`:13 / `11/2`:9 / `21/12`:36）。
★ **这是 `123` 探讨里"正则的字符类决定你能看见什么"的又一次现场兑现**——把高字节的魔数当成了可读串。

⇒ **§七 #2 的真黑箱只剩 `71/15` 一个**（二进制 162 distinct）。
