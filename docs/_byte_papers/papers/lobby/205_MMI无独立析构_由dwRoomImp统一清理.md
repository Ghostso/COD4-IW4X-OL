# 205 · `MatchMakingInfo` 无独立析构 —— 由容器 `dwRoomImp` 统一清理

> 卷次：205（房间类 · MMI 生命周期定稿）
> 方法：`0x806000-0x808000` 全区扫 `+0x230` / `+0x1CC` / `+0x128`，只有 2 个函数命中
> 结论：**MMI 只有 ctor + serialize，没有独立 dtor。**

---

## §0 全区扫描结果

```
func 0x00806B50:  ← ctor
    0x806B70  mov dword [esi+0x230], 0xDB6AE4
    0x806BA1  lea ecx, [esi+0x1CC]
    0x806BE4  lea edx, [esi+0x128]
func 0x00806F20:  ← serialize
    0x806F55  lea edx, [esi+0x128]
    0x807037  lea ecx, [esi+0x1CC]
```

★★ **只有这 2 个函数碰 MMI 的特征字段。没有第三个。**

⇒ **`MatchMakingInfo` 没有独立析构函数。**

---

## §1 这意味着什么

### 1.1 MMI 是"纯数据 + 少量方法"的类

- **ctor** `0x806B50`：初始化 vtable + 高区字段
- **serialize** `0x806F20` / `0x806C90`：网络收发
- **无 dtor**：析构由**容器**负责

### 1.2 容器 = `dwRoomImp`

`0x637D01` / `0x637D55` / `0x637D94` 三处初始化都在 `0x637C00` 里，
而 `0x637C00` 是 `dwRoomImp` 的初始化（同时初始化 `+0x3A098` 队列、`+0x106xx` 缓冲等）。

⇒ **MMI 数组/单例都是 `dwRoomImp` 的内嵌成员，由 `dwRoomImp` 的析构统一 `free`。**

★ 这解释了 `0x4F44A0`（那个含 132B 数组的析构）**不是 MMI 的** ——
MMI 根本不需要独立析构。

## §5 方法论

1. **★★★ "某个类没有独立析构"是合理设计 —— 内嵌成员由容器统一清理。** 不能因此认为"分析不完整"。
2. **★★ 找 dtor 的方法：全区扫特征字段，看有几个函数命中。** 只有 ctor + serialize ⇒ 无 dtor。
3. **★★ 容器初始化函数（`0x637C00`）同时初始化多个成员 ⇒ 那些成员都是内嵌的。**
