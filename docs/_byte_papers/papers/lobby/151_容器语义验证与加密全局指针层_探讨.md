# 151 探讨 · 一个"找不到写点"的全局，逼我看懂了保护层

> 配套：[151 · 容器语义验证 + 加密全局指针层](151_容器语义验证与加密全局指针层.md)
> 主题：**按序验证三项，前两项确认结论成立，第三项挖出了"加密全局指针层"——
> 它解释了之前多次遇到的"找不到写点"。**

## 一、验证 1：容器的两个函数，6 条指令定案

我担心 `0x654D60` 其实是"取出并发送"。读了 6 条：

```asm
0x654D60  mov ecx,[edi]        ; 迭代器
0x654D65  mov eax,[ecx+0x14]   ; next = cur->next
0x654D6C  mov [edi],eax        ; iter = next
```

**纯迭代器推进。**

`0x656A10` 读了 12 条：分配 + 复制 + 挂链 + `count++`。**纯插入。**

★★★ **⇒ 149/150 卷「入队不出网」的结论成立。这一项闭合了。**

---

## 二、验证 2/3：追一个全局，发现了整层机制

`[0x331C0C8]` 在 `0x632D90` 帧更新里被读，用来查 host 状态。

**追它的写点，得到一组反常数字：**

```
读: A1×116 + 8B 0D/15/1D/35/3D×82 = 198 处
写: A3×2                             ← 只有 2 处
取地址: 0 处
```

★★★ **200 读 : 2 写 ⇒ 单例，写点在初始化路径。**

然后我扫写点形态时**第一次漏了** —— 我扫的是 `89 05`（`mov [imm],eax`），
得到 **0 处**，差点得出"没有写点"的错误结论。

**补扫 `A3`（`mov [imm],eax` 的短形态）才拿到 2 处。**

★★★ **教训：`A1`/`A3` 与 `8B 05`/`89 05` 是等价指令的不同编码，
只扫一种会漏掉一半引用。**

## 三、写点长什么样

```asm
0x5C85AD  push 0x12A700
0x5C85B2  call 0x5C8330            ; 分配
0x5C85BA  xor eax, 0xD362501F      ; ★ 加密
0x5C85BF  mov [0x331C0C8], eax
```

**存的是 XOR 加密后的指针。** 每个全局有独立掩码（`0x76638F4` 用 `0x6891D1C7`）。

而分配函数 `0x5C8330`：

```asm
0x5C8365  push 0x3000              ; MEM_COMMIT|MEM_RESERVE
0x5C8377  call [0xCA8204]          ; ★ VirtualAlloc
0x5C8388  push 0xDDA4CC "universal\physicalmemory_dynamic_reserved.cpp"
```

★ **源文件名直接写在断言里** —— `physicalmemory_dynamic_reserved.cpp`。

**这不是游戏逻辑，是内存保护/预留层。**

## 四、"随机延迟"的指纹

设置点之前的代码：

```asm
0x5C8560  call 0xC3EC10            ; ★ MSVC rand()
0x5C8568  fild / fmul / fimul
0x5C857A  call 0xC42D30            ; cvttsd2si
0x5C8583  循环 4 次
```

`0xC3EC10` 是标准 `rand()`：

```asm
0xC3EC1A  imul eax,eax,0x343FD
0xC3EC20  add eax,0x269EC3
0xC3EC2B  and eax,0x7FFF
```

★★ **LCG 常数 `0x343FD`/`0x269EC3` 是识别 `rand()` 的机械判据。**

## 五、这一卷真正的收获：一条通用判据

**之前我多次写"找不到写点"：**
- `rec+0x1C = 0x12` 没有写点
- `0x82E1458` 描述符表没有写点
- `[0x331C0C8]` 一开始也没找到

**现在有了判据：**

> **如果一个全局「读很多、写几乎没有」，且附近出现
> `rand()` / `VirtualAlloc` / 浮点混淆 —— 它的写点在保护层。**

★ 这条能省掉很多轮"扫写点扫不到"的困惑。

## 六、顺带确认：13 个加密全局是一组

清零点 `0x5C8AC0` 的同一次操作里，**13 个全局被一起清零**：

```
0x1C1D188 / 0x1C1D18C / 0x1C1D190 / 0x1C1D194
0x1C1D198 / 0x1C1D19C / 0x1C1D1A0 / 0x1C1D1A4
0x34027F4 / 0x338139C / 0x3381398 / 0x76638F4 / 0x331C0C8
```

而末尾 `mov eax, 0xDBC09C` = 字符串 **`"$perLocalClient"`**。

★★ **⇒ 这是"per-client 资源指针表"，13 项，统一分配 + 统一清零。**

## 八、方法论

1. ★★★★★ **`A1`/`A3` 与 `8B 05`/`89 05` 都要扫** —— 只扫一种会漏一半。
2. ★★★★ **读/写比是强信号**：200 读 2 写 ⇒ 单例。
3. ★★★★ **"读多写少 + rand/VirtualAlloc"= 写点在保护层**。
4. ★★★ **LCG 常数 `0x343FD`/`0x269EC3` 是 `rand()` 的机械判据**。
5. ★★★ **断言里的源文件名是模块身份的免费线索**。
