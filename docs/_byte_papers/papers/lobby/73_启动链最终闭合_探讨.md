# 启动链最终闭合 · 探讨：终点是同一个变量

> 对应：`lobby/73_启动链最终闭合.md`

---

## 一、一个漂亮的收束

**我从 `lobby/40` 开始追房间，一路往上：**

```
报文 → 命令 → 对象 → 创建 → 调用 → 初始化
     → CRT → 销毁 → 闸门 → 状态机 → 登录阶段 → 连接
     → 连接单例 → 模式门
```

**结果发现：`lobby/55` 的"模式门" `[0xe59d20]`，
和 `lobby/73` 的 `0x622220()`，是**同一个变量**。**

**⇒ 链的两端接上了，形成一个闭环。**

---

## 二、这个闭环的意义

**我之前以为"模式门"是链的第 10 层，再往上还有。**

**现在发现：它既是顶层，也是状态 7 的判断条件之一。**

**⇒ 它不是"最后一个未知"，而是"整条链的枢纽"。**

---

## 三、`[0xe59d20]` 的三次出现

**1. `0x47008e`（`lobby/55`）
   —— 决定是否查连接状态**

**2. `0x622220`（`lobby/73`）
   —— 决定状态 7 能否进状态 8**

**3. `lobby/55` 记录的"模式门"**

**⇒ 三次出现，都在关键分支上。**

**⇒ 这是"应用当前处于哪个界面"的状态。**

---

## 四、实测值 0 的含义

**如果 `[0xe59d20]` = 0，意味着：**

- 不在大厅（4）
- 不在游戏（6）
- **未初始化**

**⇒ 客户端连"我在哪个界面"都还没确定。**

**⇒ 这比"登录失败"更早。**

---

## 五、这与 `enable_iips` 的关系

**`memory: codol-iips-must-be-enabled` 说改 `enable_iips=1` 后能进大厅。**

**`[0xe59d20]` 从 0 变成 4，很可能就发生在"进大厅"那一刻。**

**⇒ `enable_iips=1` → 连接建立 → 状态到 3 → `[0xe59d20] = 4`。**

**⇒ 或者是反过来的：`[0xe59d20] = 4` 之后才允许连接。**

**⇒ 需要查它的写入点才能确定因果。**

## 七、方法论收获

> **追根因追到最后，往往会回到一个"枢纽变量"。**

**这个变量不是"起点"，而是"多个分支共用的条件"。**

**⇒ 一旦找到它，整棵树就收拢成一个点。**

**这次是 `[0xe59d20]`。**

---

## 八、下一步

**查 `[0xe59d20]` 的写入点。**

**如果它是 `enable_iips` 的直接结果，整条链就彻底闭合。**

**否则，说明还有更上层的东西。**
