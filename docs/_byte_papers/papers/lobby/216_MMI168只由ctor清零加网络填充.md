# 216 · ★★★★ `MMI+0x168/0x16C` 只由 ctor 清零 + 网络反序列化填充 ⇒ 服务端必须提供 u64

> 卷次：216（房间类 · **开局失败根因定案**）
> 方法：`+0x168`/`+0x16C` 全库写点扫描（54/57 处），MMI 区只有 ctor 一处
> 结论：**`MMI+0x168/0x16C` 的唯一非零来源是 MMI 的网络反序列化 ⇒ 服务端必须下发这个 u64。**

---

## §0 全库写点统计

| 偏移 | 全库写点 | MMI 区（0x806xxx）写点 |
|---|---|---|
| `+0x168` | **54 处** | **仅 `0x806BA7`（ctor 清零）** |
| `+0x16C` | **57 处** | **仅 `0x806BAD`（ctor 清零）** |

★ `0x168`/`0x16C` 是极常见偏移（别的类大量使用），**必须按"函数所属类"筛**。

### 0.1 MMI 区的唯一两处

```asm
0x806BA7  mov dword [esi+0x168], 0    ; ctor 清零
0x806BAD  mov dword [esi+0x16C], 0    ; ctor 清零
```

★★★ **MMI 自己从不主动写 `+0x168/0x16C` 为非零值。**

⇒ 它们的非零值只能来自：
1. **`0x806F20` / `0x806C90` 的 deserialize**（`0xB76A30`/`0xB76910` 读进缓冲）
2. 或者外部 memcpy

★ 而 `0x806F20` 的 disp 集合含 `0x168`（195 卷确认）⇒ **是网络反序列化填充。**

---

## §1 完整因果链（定案）

```
服务端下发 mmbook accepted 推送
    ↓
客户端解析 → 3 个参数（u64 + 字符串）
    ↓
dwRoomImp 虚函数 0x632680
    ├ 门4: 参数1 == MMI+0x168   ← ★ MMI 从网络收到过这个值
    ├ 门5: 参数2 == MMI+0x16C   ← ★ 同上
    └ 门6: 参数3 == "mmbook accepted"
    ↓ 全过
构造 StartGame → 发送
```

★★★ **`MMI+0x168/0x16C` 是"之前某条网络消息带下来的对端 ID"。**

⇒ **服务端必须：(a) 先下发一条携带正确 u64 的消息（填充 MMI+0x168/16C）
      (b) 再下发 mmbook accepted，且参数匹配。**

★★★ **服务端推送体缺少 u64 ID —— 这极可能就是"房间开局失败"的根因。**

## §4 本卷确定结论

| 项 | 状态 |
|---|---|
| `MMI+0x168/0x16C` 在 MMI 区只有 ctor 清零 | ✅ |
| 非零值只能来自 MMI 网络反序列化 | ✅ `0x806F20` 读 `+0x168` |
| `MMI+0x168/16C` = 网络带来的 u64 | ✅ |
| 服务端推送缺 u64 | ⚠️ **强候选根因** |

## §6 方法论

1. **★★★★ 常见偏移（`0x168`/`0x16C`）的写点必须按"函数所属类"筛。** 54 处里只有 1 处属于 MMI。
