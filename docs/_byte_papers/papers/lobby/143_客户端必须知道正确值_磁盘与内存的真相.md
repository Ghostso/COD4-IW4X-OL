# 143 · 「客户端必须知道正确值」—— 它确实知道，但只在运行时

> 前序：142（类型号恒零）、141（服务注册链）、140（类型号定案）
> 性质：**磁盘 PE 与内存镜像的逐段对照**。本卷回答一个方法论质疑：
> **「客户端必须知道什么是正确的，所以这些数据一定在客户端文件里」—— 对不对？**

---

## §0 九条结论

1. ★★★★★ **质疑的前半句是对的，后半句不成立**：客户端确实知道正确值，
   但它是**运行时计算**出来的，磁盘文件里**不存在**这些值的明文。
2. ★★★★★ **磁盘 exe 的 `.text` 被 VMProtect 加密**：熵 **7.140**，`0xCC` 仅 **0.22%**；
   内存镜像解密后熵 **6.776**、`0xCC` **3.04%**。90 个 64KB 块**全部不同**。
3. ★★★★★ **真正的客户端是 `codoMP_client_shipRetail.exe`（7.8 MB）**，
   不是 `codoMP_client_shipRetailBase.dll`（57.5 MB）——后者是 **OpenCV 图像库**
   （338 个 RTTI 全是 `cv@@` / `Imf@@` / `std@@`，**零个游戏类**）。
4. ★★★★ **磁盘 exe 的 `.rdata` 未加密，43 个 `dwRoomMessage` RTTI 名完整存在**
   （VA `0xE6F094..0xE6F7FC`，file off `0x75B094..`，字节 `2e 3f 41 55` = `.?AU`）。
   **⇒ 类名在磁盘上可读，但 type_info / COL / vtable 结构体不在。**
5. ★★★★ **所有"运行时状态"地址都落在 `.tp3#3` 的空洞里**：
   `0x82E1458`（47 项描述符表）、`0x8269774`（srpc 单例）、`0xE39B6E8`（dwLobbyImp 单例）、
   `0xE374650`（srpc 记录表）、`0x82E1408`（文本载荷）—— 段内偏移 0x74CB458 起，**远超 RawSize 0x62000**。
6. ★★★ **`.tp3#3` 的 `VSize=0xDBB1CC0`（230 MB）/ `RawSize=0x62000`（401 KB）**，
   磁盘覆盖率 **0.17%**；内存镜像同为 **0.17%**（镜像里这段也是空洞）。
7. ★★★ **DLL 的 `.tvm0` 段熵 7.023**（1.9 MB → 虚拟 32 MB），同样是加密/压缩数据。
8. ★★ **`.ff` 资源文件全部 `IWff0100` 未加密**，但里面没有 `dwRoomMessage` 字符串
   —— 那些是代码符号，本就不该在资源里。
9. ★★ **内存镜像比磁盘 exe 多 3,227,648 字节的 `.text`**，这是 VMProtect 运行时解开的代码；
   但**这部分里也没有 `dwRoomMessage` 字符串**（x0）。

## §1 用户质疑的完整回应

> 「这三项直接在游戏客户端文件里找，本地客户端肯定有，
> 如果没有他要怎么知道什么是正确的」

### 1.1 前半句完全正确

**客户端当然知道什么是正确的** —— 否则它无法解析服务端下发的消息。
这是不可反驳的。

### 1.2 但"知道"≠"磁盘上写着"

客户端知道的方式是 **运行时构造**：

```
进程启动
 → VMProtect 解包 .text（熵 7.14 → 6.78）
 → 运行 0x7F0970 构造 dwLobbyImp 单例（写 vtable 0xDE07A4）
 → 运行 0x803830 构造 srpc 单例（写 vtable 0xD599DC、14 张哈希表）
 → 运行 68 个注册点，把 "" 作键写进哈希表
 → 运行时填入 0x82E1458 的 47 项描述符
```

**这些对象在磁盘上根本不存在** —— 它们是被 `0xE39B6E8` / `0x8269774` 这些**地址**指着的
BSS 空间，而 BSS 在文件里就是空洞（`.tp3#3` 覆盖 0.17%）。

### 1.3 反证：如果磁盘上有，为什么读不到？

我直接查了：

```
0x82E1458  tp3#3  段内偏移 0x74CB458  →  NO(空洞)
0x8269774  tp3#3  段内偏移 0x7453774  →  NO(空洞)
0xE39B6E8  tp3#3  段内偏移 0xD5856E8  →  NO(空洞)
0xE374650  tp3#3  段内偏移 0xD55E650  →  NO(空洞)
```

**段内偏移 0x74CB458 远超 RawSize 0x62000（401 KB）。**
这不是"我没找到"，是**文件里那一段物理上不存在**。

### 1.4 但名字确实在磁盘上

```
0xE6F094  tp3#3  段内偏移 0x59094  →  YES  file off 0x75B094
          bytes: 2e 3f 41 55 64 77 52 6f 6f 6d 4d 65 73 73 61 67   ".?AUdwRoomMessag"
```

**43 个 `dwRoomMessage` RTTI 名在磁盘 exe 的 `.rdata` 里完整存在**（`0xE6F094..0xE6F7FC`）。

★★★ **所以用户的直觉不是全错：名字在，结构体不在。**
名字是编译期常量（`.rdata`），结构体是运行时对象（BSS 空洞）。

## §2 磁盘 vs 内存：完整的量化对照

| | 磁盘 exe | 内存镜像 |
|---|---|---|
| 大小 | 7,841,344 B | 241,537,024 B |
| `.text` RawSize | `0x593000`（5.6 MB） | `0x8A7000`（8.7 MB） |
| `.text` 熵 | **7.140** | **6.776** |
| `.text` `0xCC` 占比 | **0.22%** | **3.04%** |
| 64 KB 块差异 | — | **90/89 块全不同** |
| 总体虚拟覆盖 | 3.24% | 4.57% |

**⇒ 磁盘 exe 的 `.text` 是 VMProtect 加密态；内存镜像是解密态。**

★ **内存镜像多出的 3,227,648 字节**是解包出来的代码，但其中 `dwRoomMessage` 出现 **0 次**
（字符串都在 `.rdata`，不在 `.text`）。

## §4 那"正确的值"到底从哪来

### 4.1 消息泵类型号（房间消息 = 7 或 8）

```
服务端下发 → 消息里带 4 字节服务名
 → 0xB7FAD0  FNV-1a(0x1000193) 算哈希
 → 在 srpc 的 14 张哈希表之一里查
 → 节点[0] = 类型号
 → 0xB82D42 dec → 0xB83744[类型号-1] → handler
```

**⇒ 类型号由「4 字节服务名」决定，而那个名字来自消息本身（运行时）。**

### 4.2 srpc 注册表类型号（恒 0）

141/142 已证：68 个注册点全用空串 `""` 作键，`srpc+4` 从不自增。
**⇒ 这个"类型号"根本不是协议字段，只是哈希节点的序号。**

### 4.3 47 项描述符表 `0x82E1458`

**磁盘上是空洞，运行时才填。** 142 已证：`if(esi) call esi` 对 type 0..46 永不触发。

## §5 所以，"必须在客户端文件里找"这条路的正确走法

| 想找的东西 | 磁盘上有没有 | 在哪 |
|---|---|---|
| 43 个 `dwRoomMessage` 类名 | ✅ 有 | `.rdata` @ `0xE6F094..` |
| 47 项表 handler 地址 | ✅ 有 | `.text`（加密，需解密或用内存镜像）|
| 类型号 7/8 的语义 | ✅ 有 | 140 已定案（表下标）|
| srpc 单例 / dwLobbyImp 单例的值 | ❌ 无 | BSS 空洞，运行时构造 |
| `0x82E1458` 描述符表内容 | ❌ 无 | BSS 空洞，运行时填 |
| `rec+0x01` 启用字节 | ❌ 无 | 运行时由回调置 1 |

**⇒ 静态可得的都拿到了；静态不可得的是运行时状态，不是"我没找到"。**

## §6 诚实边界

1. **VMProtect 加密的 `.text` 未解密**。内存镜像提供了解密视图，但内存镜像本身覆盖率仅 4.57%。
2. **`0xE6F094` 起的 43 个 RTTI 名的 type_info/COL/vtable 结构未找到**
   （磁盘 `.rdata` 里 name_ptr 反查 type_info 得 0 命中）—— 可能结构体在 `.tp3#3` 空洞里。
3. **DLL 的 `.tvm0` 段（1.9 MB，熵 7.023）未解**。
4. **未验证「4 字节服务名」的真实取值**（141 已证注册用空串，但消息里的名字仍未知）。

## §8 方法论

1. ★★★★★ **"客户端必须知道"是对的，但"知道"≠"磁盘上写着"** ——
   区分**编译期常量**（`.rdata`，可读）与**运行时对象**（BSS，文件里是空洞）。
2. ★★★★★ **判断"文件里有没有"要用段表算，不能用"搜不到"下结论**。
   `段内偏移 0x74CB458 vs RawSize 0x62000` 是一条减法就能证明的。
3. ★★★★ **同名的 `xxxBase.dll` 未必是主体** —— 57 MB 的 DLL 可能是 OpenCV。
   **看 RTTI 名比看大小可靠。**
4. ★★★ **熵是"加密与否"的机械判据**：7.14 vs 6.78，`0xCC` 0.22% vs 3.04%。
5. ★★★ **内存镜像是解密视图，但覆盖率可能远低于磁盘** —— 两者互补，不是替代。
