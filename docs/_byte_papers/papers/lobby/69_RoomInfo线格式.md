# `dwRoomMessageRoomInfo` 线格式（建房推送的第一条）

> **这是"建房必需的第一条推送"**
> 证据：`0x627ea0`（serialize）+ `0x624510`（主体）

---

## 1. 顶层：`0x627ea0`

```asm
0x627ea9  mov edi, [ebx]            ; 位流写入器
0x627ead  mov al, [esi+4]
0x627eb0  push 3
0x627eb7  call writeBits(3)         ; 3 位
0x627ebc  push 8
0x627ec4  call writeData(&[esi+4], 8)   ; 1 字节
0x627ec9  mov ecx, [esi+8]          ; ★ 参数字段
0x627ece  call 0x624510             ; ★ 写主体
```

**⇒ 消息头（11 位）+ 主体。**

---

## 2. 主体 `0x624510`

### 段 1：第一个 u16

```asm
0x62451f  push 0x10
0x624523  call writeBits(0x10)      ; ★ 16 位（固定值？）
0x624528  mov ecx, esi
0x62452a  call 0xb759a0             ; 取字符串长度
0x62452f  lea eax, [eax*8 + 8]      ; ★ 长度×8 + 8 位
0x624536  push eax
0x624539  call 0xc74510             ; 取数据指针
0x624541  call writeData(ptr, len*8+8)  ; ★ 写变长数据
```

**⇒ 结构：`16 位 + (len*8+8) 位数据`。**

**`0xc74510` 说明这是 `std::string` —— 取 c_str。**

**⇒ 这是一个**字符串字段**，编码为：
`16 位（长度？）+ (len*8+8) 位（内容 + 1 字节 NUL）`。**

### 段 2：第二个字符串

```asm
0x624546  mov ebx, [edi]
0x624548  push 0x10
0x62454c  call writeBits(0x10)      ; 16 位
0x624551  lea ecx, [esi+8]          ; ★ 第二个 string（+8）
0x624554  call 0xb759a0
0x624559  lea ecx, [eax*8 + 8]
0x624564  call 0xc74510
0x62456c  call writeData(...)
```

**⇒ 完全对称的第二个字符串字段。**

### 段 3：一个 u8

```asm
0x624571  movzx edx, byte [esi+0xc]  ; ★ 1 字节字段
0x624575  mov ebx, [edi]
...
```

**⇒ 第三个字段是 `[obj+0xC]` 的 1 字节。**

---

## 3. 已确定的字段布局

| 顺序 | 编码 | 内容 |
|---|---|---|
| 0 | `writeBits(3)` + `writeData(8)` | 消息头（版本） |
| 1 | `writeBits(0x10)` | 固定 16？ |
| 2 | `(len*8+8)` 位 | **字符串 1**（`[esi+0]`） |
| 3 | `writeBits(0x10)` | 固定 16？ |
| 4 | `(len*8+8)` 位 | **字符串 2**（`[esi+8]`） |
| 5 | 1 字节 | `[esi+0xC]` |
| … | — | 后续字段（未读完） |

**⇒ `RoomInfo` 至少包含**两个字符串 + 一个字节**。**

---

## 4. 两个字符串是什么

**`RoomInfo` 是"房间信息"。**

**两个字符串最可能是：**

1. **房间名**（用户可见的名字）
2. **房间描述 / 地图名 / 模式名**

**⇒ 这与 `mp_playlists` 里的 `name chinese` / `description chinese` 对应。**

---

## 5. `writeBits(0x10)` 的含义

**在写字符串前，先写一个固定的 `0x10 = 16`。**

**两种可能：**

### A. 字符串长度字段的位宽声明

**"接下来是一个 16 位长度"？**

**但紧接着是 `len*8+8` 的数据，没有单独的 16 位长度。**

### B. 字符串类型标签

**`0x10` 是"字符串"的类型码。**

**⇒ 与 ByteBuffer 里的 `0x10`（TSTRING）同值！**

**⇒ 两套序列化用了相同的类型码常量。**

---

## 6. `len*8+8` 的编码

**如果 `len` 是字符数：**

```
len=10 → 10*8+8 = 88 位 = 11 字节
```

**⇒ 10 个字符 + 1 个 NUL = 11 字节。**

**⇒ 完全合理。**

**⇒ 字符串编码是"内容 + NUL"，长度由 `len*8+8` 自动算出。**

---

## 7. 构造一条 RoomInfo 推送所需的全部信息

```
1. 位流写入器（由 6/5 应答的缓冲提供）
2. 消息对象（RoomInfo 实例）
3. 填充：
   [obj+4]   = 版本（u8）
   [obj+0]   = 字符串 1（房间名）
   [obj+8]   = 字符串 2（描述/地图）
   [obj+0xC] = 标志（u8）
   [obj+0x10]= 另一个字段（Manifold 里用过）
4. 调 serialize(0x627ea0)
5. 位流字节化 → 放进 6/5 应答
```

**⇒ 缺的只剩"位流字节化"这一步。**

---

## 8. 位流字节化的线索

**`writeBits` / `writeData` 写入的是 `0xb77b10` / `0xb777c0`。**

**⇒ 它们内部的 `ecx` 是"位流对象"。**

**⇒ 需要看这个对象的布局（缓冲区、当前位偏移）。**

**⇒ 反汇编 `0xb77b10` 即可。**

---

- `RoomInfo` 线格式 → **已解出**

**⇒ 只剩"位流字节化"一个技术点。**
