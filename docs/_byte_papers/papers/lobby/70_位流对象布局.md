## 1. 位流对象布局

**从 `0xb777c0`（writeData）反汇编提取：**

```asm
0xb777cd  mov ecx, [esi+0x14]      ; ★ 当前位偏移
0xb777d1  lea edi, [eax+ecx-1]     ; (nbits + bitpos - 1)
0xb777d5  shr edi, 3               ; /8 → 需要的字节数
0xb777d8  cmp edi, [esi+0x10]      ; 与容量比较
0xb777db  jb  0xb777f9             ; 够用 → 跳过扩容
0xb777e4  call 0xb77560            ; ★ 扩容
0xb777e9  mov edx, [esi+8]         ; ★ 缓冲区指针
0xb777ec  lea eax, [edi+1]
0xb777ef  mov [esi+0x10], eax      ; 更新容量
0xb777f5  mov byte [edi+edx], 0    ; 清零新字节
```

### 字段表

| 偏移 | 类型 | 含义 |
|---|---|---|
| `+0x04` | ? | ? |
| **`+0x08`** | **ptr** | **字节缓冲区** |
| `+0x0C` | ? | ? |
| **`+0x10`** | **u32** | **缓冲区容量（字节）** |
| **`+0x14`** | **u32** | **当前位偏移** |
| `+0x18` | ? | ? |
| **`+0x21`** | **u8** | **写入启用标志** |

## 2. `writeBits`（`0xb77b10`）

```asm
0xb77b13  cmp byte [ecx+0x21], 0
0xb77b17  je  0xb77b28              ; ★ 未启用 → 直接返回
0xb77b19  mov eax, [ebp+8]          ; nbits
0xb77b1c  push 0
0xb77b1e  push 0x1f                 ; 31
0xb77b20  push 0
0xb77b22  push eax
0xb77b23  call 0xb77a70             ; writeBitsCore(value, 0, 31, 0)
```

**⇒ `writeBits(n)` 等价于 `writeBitsCore(v, start=0, width=31, pad=0)`。**

**⇒ 写 31 位宽的 v（前面补 0）。**

**⇒ `[ecx+0x21]` 是"是否真的写"的开关。**

---

## 3. ★ 字节化规则

**从 `0xb777d5` 的 `shr edi, 3` 可以确定：**

```
需要的字节数 = ceil((当前位偏移 + 本次写入位数) / 8)
```

**⇒ 位流是"按位追加到字节缓冲区"，
不足一字节的部分留在最后一个字节里（位偏移 `+0x14` 记录）。**

**⇒ 缓冲区是**连续字节数组**，不是位数组。**

---

## 4. 完整的构造流程

```
1. 分配位流对象，设 +0x21 = 1（启用）
2. 调 serialize（例如 0x627ea0）
3. serialize 内部反复调 writeBits/writeData
4. 每次写：从 +0x14 的位偏移开始填字节
5. 写完：缓冲区在 [+0x08]，长度 = ceil(+0x14 / 8)
6. 把缓冲区放进 6/5 应答
```

## 5. 一条 `RoomInfo` 的确切字节

**以房间名 "test"（4 字符）、描述 "map1"（4 字符）为例：**

```
位 0..2     011                （版本 3）
位 3..10    00000001           （[obj+4] = 1）
位 11..26   0000000000010000   （0x10 字符串标签）
位 27..66   "test\0" 40 位
位 67..82   0000000000010000   （0x10 字符串标签）
位 83..122  "map1\0" 40 位
位 123..130  [obj+0xC]
...
```

**总长视后续字段而定。**

**⇒ 位流会被填充到字节边界（最后一个字节的高位补 0）。**
