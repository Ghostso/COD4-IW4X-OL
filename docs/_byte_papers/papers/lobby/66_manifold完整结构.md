# `Manifold::serialize` 完整结构：头 + 链表遍历

> 承接 `lobby/65`，读完整个函数

---

## 1. 完整流程

```asm
; ── 段 1：消息头 ──
0x625533  mov al, [edi+4]
0x625542  call writeBits(3)              ; 3 位
0x625550  call writeData(&[edi+4], 8)    ; 1 字节

0x625557  mov edx, [edi+0x10]
0x625562  call writeBits(8)              ; 8 位
0x625578  call writeData(&[edi+0x10], 0x20)  ; 4 字节

; ── 段 2：判空 ──
0x62557d  cmp dword [edi+0x10], 0
0x625581  je  0x6256a8                   ; 为 0 → 直接结束

; ── 段 3：遍历链表 ──
0x625595  mov edi, [edi+8]               ; ★ 下一个节点
0x625598  mov eax, [edi]
0x6255a2  add eax, 4
0x6255a6  call [0xca8128]                ; 引用计数/加锁
0x6255ac  mov eax, [edi+8]               ; 字段 A
0x6255b3  mov edi, [edi+0xc]             ; 字段 B
0x6255b6  or  eax, edi
0x6255bc  je  0x6255c2                   ; 两者都为 0 → bl=0
0x6255be  mov bl, 1                      ; 否则 bl=1

; ── 段 4：写 1 位存在标志 ──
0x6255c6  push 1
0x6255ca  call writeBits(1)              ; ★ 1 位
0x6255d3  test bl, bl
0x6255d5  je  0x6255e3
0x6255db  mov byte [esp+0x14], 0xFF      ; 存在 → 0xFF
0x6255e3  mov byte [esp+0x14], 0x00      ; 不存在 → 0x00
0x6255ed  call writeData(&flag, 1)       ; 写 1 位？(注意 push 1)
```

**⇒ 每个链表节点写：`1 位存在标志` + 条件值。**

---

## 2. 消息的完整位布局

```
位偏移  长度   内容
0       3      类型码（写死 3）
3       8      [obj+4]（版本/标志）
11      8      字段标签（写死 8）
19      32     [obj+0x10]（4 字节值）
─────────────────────────────────
51      1      ★ 链表是否非空
52      …      链表节点（循环）
```

**总头长 51 位 = 6.375 字节。**

---

## 3. 节点的"存在标志"设计

```asm
mov eax, [edi+8]     ; 字段 A
mov edi, [edi+0xc]   ; 字段 B
or  eax, edi
je  → bl = 0
```

**⇒ 只有 A 和 B**同时为 0**，节点才被标为"不存在"。**

**⇒ 这是一个"稀疏链表"编码：
空节点只写 1 位 0，非空节点写完整字段。**

**⇒ 这正是位流序列化的典型优化。**

---

## 4. ★ 回到 `11/4`

**`11/4` 的 blob 恒定部分：**

```
02 02 00 00 | 00 08 00 00 | ...
```

**按位展开（从 bit 0）：**

```
02 = 0000 0010
02 = 0000 0010
00 = 00000000
00 = 00000000
```

**前 3 位 = `000` = 0。**

**而 Manifold 要求前 3 位 = `011` = 3。**

**⇒ 确认：`11/4` 的 blob **不是** Manifold 的位流。**

---

## 5. 那 `11/4` 是什么

**重新审视 `lobby/40` 的观察：**

```
blob[0:4] = 内容长度（小端）      ← 明确是长度前缀
blob[4]   = 0x02
blob[5]   = 组数（2/4/6/8）
blob[6:8] = 00 00
```

**⇒ `02` + `<n>` 很可能是一个**自定义的分组头**，不是位流。**

**⇒ `11/4` 用的是"字节对齐的数组"，不是 `dwRoomMessage` 的位流。**

---

## 6. 两种序列化并存

**这个 build 里有两套序列化：**

| 体系 | 特征 | 出现 |
|---|---|---|
| **Demonware ByteBuffer** | 类型标签 TLV（`0x08`/`0x13`/…） | 大厅全部 payload |
| **位流（writeBits/writeData）** | 3 位类型 + 变长 | `dwRoomMessage` 系列 |

**⇒ `11/4` 属于前者（ByteBuffer），
`dwRoomMessage` 属于后者（位流）。**

**⇒ 它们是两个不同的通道！**

---

## 7. 这个发现的意义

**`memory: lobby-6-5-is-readqueuedmessages` 记录：**

> 房间事件真实载体是 `11/4` 回显 + **位流推送**

**现在能解释：**

- `11/4` 是 ByteBuffer（大厅通道）
- 位流推送是另一条通道
- **两者格式完全不同**

**⇒ 之前试图用 `11/4` 的格式去理解房间事件，方向就错了。**

---

## 8. 位流通道在哪

**`dwRoomMessage::serialize` 需要一个"位流写入器"，
它从 `[esi]` 取（参数 1）。**

**⇒ 这个写入器由谁提供？**

**地址 `0xb77b10` / `0xb777c0` 在 `0xb7xxxx` 段 ——
与 Demonware 连接层同段。**

**⇒ 位流通道走的是 Demonware 的独立连接，不是大厅 TCP。**
