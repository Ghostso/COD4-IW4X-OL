# 241 探讨：任务书给的名字可能是错的 —— 从 `AS_SetTeam` 到 `AS_ChangeTeam`

## 判据

1. **字段语义只能从「谁消费它」反推，不能从「参数叫什么」猜。**
   `0x6281A0` 的 4 个栈参没有任何名字。我的做法是：找到**唯一消费它们的地方** —— 分派 `[0x14]` 的 `0x636336`，
   它把这 4 个值分别与成员记录的 `+0x8C` / `+0x88` / `+0xB0` 比较。
   **`+0xB0` 那一路带 `cmp ... / je 跳过`（两个值相等就不推事件）** ⇒ 这就是「有没有变化」判定 ⇒ 字段是状态值不是命令。

2. **发现 `+0xC` 与 `+0x18` 是同一寄存器的判据**：
   ```
   0x6281AC  mov [eax+0xC], edx      ; edx = [ebp+0xC] = 参数2
   0x6281C5  mov [eax+0x18], edx     ; ★ 同一个 edx
   0x6281C8  mov [eax+0x1C], ecx     ; 参数4 -> 高位
   ```
   **不是「+0xC 和 +0x18 低半恰好相等」，而是「同一个变量写了两遍」。** 这个区别很重要：
   前者是巧合，后者是结构（u32 落在 u64 的低半）。

3. **「任务书说的这个名字在不在」必须用字节搜索证明，不能默认它存在。**
   任务书写的是 `AS_SetTeam(team)`。我做**全镜像 241,537,024 字节 `b"SetTeam"` 搜索** ⇒ 3 处，全在 Segment 2（Flash 导出区）。
   **`.text` 里 0 处。** 而 `'ChangeTeam'` 在 `.text` 的字符串表 `0xDDD5A4` 有 1 处引用（`0x7D1103`）。

## 误区与自我推翻记录

- **第一版：我写了「真正的改阵营入口是 `AS_SetTeam` → `0x62C5A0`」。** 这是把任务书的推测当结论。
  自我推翻的契机：我为了填 B2 去搜 `"SetTeam"`，发现 `.text` 里根本不存在。
- **第二版：我以为 `0x62C5A0` 就是 `AS_ChangeTeam`。** 也不对 —— `0x62C5A0` 的调用者是房间消息族（族 A/B），
  不是 AS 回调模板。真 AS 回调落在 `0x7D1080`（装 `0xDDD784` vtable + `push 0xDDD5A4`）。
- **第三版：我以为 `AS_ChangeTeam` 带 team 参数。** 读完 `0x7D1080` 全函数才发现：`and eax,0x8F / cmp al,0xA / sete`
  ⇒ **唯一参数是 bool**。**「改阵营」这个动作在 Flash 侧没有 team 编号**。

## 方法论

- **`push` 一个字符串常量 = 该函数的业务名。** `0x7D1102 push 0xDDD5A4` + `0xDDD5A4='ChangeTeam'` ⇒ 这个 native 函数就是 ChangeTeam。
  **比 RTTI 名更直接**（RTTI 有时被折叠）。
- **302 处同模板 ⇒ 可以拿一个已知样本反推全部。** `SetReadyState`（`0x7D0A00`）与 `ChangeTeam`（`0x7D1080`）**逐指令同构**，
  只有名字串不同。这证明「AS 回调派发」是统一模板，可以批量定位。
- **「客户端从不发某报文」要给分母。** 我说 `0x6281D0` 的 `E8` 调用点 = 0，分母是**全 `.tp3` 段 158,187 条 `E8`**（用 `blob.find(b"\xE8")` 逐字节扫 + 解 rel32）。没有分母的「没找到」不算证据。
- **`ret N` 的 N 就是栈参个数。** `0x6281A0 ret 0x10` ⇒ 4 个 4 字节栈参。`0x6281D0 ret 4` ⇒ 1 个。**这是免费的字段计数**。
