# 分卷布局 · 探讨：从"一坨 23GB"到"每个模式一个盒子"

> 对应：`lobby/12_分卷布局与模式定义.md`

---

## 一、最初看到的是什么

974 个 `.ifs`，23 GB，文件名一堆：

```
lf_hi_init_common_marketplace_10_V41.ifs
ff_init_common_gametype_mp_V69.ifs
lf_dlc34_mp_battlecity_mountains_td_V1.ifs
...
```

**看起来是随机的一堆。**

---

## 二、第一个突破：清单是明文的

打开任何一个低熵文件，0xac 处就是：

```
ff_init_common_gametype_mp.lst
client_shipRetail/chinese/common_gametype_mp.ff
client_shipRetail/chinese/localized_common_gametype_mp.ff
```

**于是"这个盒子里装了什么"变成了可读的。**

---

## 三、第二个突破：按 `.ff` 名归类

把所有清单里的 `.ff` 名拉出来，按前缀分组：

```
common_gametype_mp.ff
common_gametype_coop.ff
common_gametype_survival.ff
common_gametype_spy.ff
common_gametype_dmz.ff
common_gametype_hostage.ff
common_gametype_asym.ff
```

**七个模式，一一对应七个 `.ifs`。**

这不是"一个大的模式数据库"，是**"每个模式一个盒子"**。

---

## 四、第三个突破：大厅本体找到了

```
ff_init_common_mp_V111.ifs (77.8 MB)
  └─ common_mp.ff          ← 大厅
```

**"大厅"不是抽象概念，是一个具体的 `.ff` 文件。**

---

## 五、这改变了什么

如果不知道这个布局，想法会是：

> "大厅是一大坨，怎么改不知道。"

现在的想法是：

> "大厅 = `ff_init_common_mp_V111.ifs` 里的 `common_mp.ff`（一部分）。
>  要改，先把它拿出来，改完再放回去。"

**目标从"改整个游戏"变成了"改一个文件里的一个块"。**

---

## 六、但这也暴露了真正的障碍

分卷层完全清楚，**卡在 `.ff` 本体**：

- `.ff` 的载荷熵 7.96
- `IWff0100` 后的字节看起来是随机的
- 旧结论说"加密"

**所以真正的门槛是：`.ff` 能不能解出来。**

分卷布局只解决了"在哪里"，没解决"里面是什么"。

---

## 七、方法论收获

> **先解决"在哪"，再解决"是什么"。**

974 个文件，如果直接去猜"哪个是大厅"，会浪费时间。
但只做了一件事 —— 读清单 —— 就把布局全理清了。

**清单是廉价信息（16KB），但它给出的定位价值极高。**

这条原则可以推广：

- 先找目录/索引/清单
- 再解内容

---

## 八、下一步的优先级

1. **`.ff` 是否加密** —— 这决定了整个路线
2. 如果不加密，`common_mp.ff` 内部结构是什么
3. 如果加密，密钥在哪（`IIPSVFS.dll` 的 `CCoderRWFilter`）

**第 1 条是分水岭。**
