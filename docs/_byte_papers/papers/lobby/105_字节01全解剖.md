# 第 105 卷 · 字节 `0x01` 全解剖（25,187 次）—— 兼定 `0x03` 是 u8 而非"类型码"

> 承接 `lobby/102`（0x00）、`103`（0x70）、`104`（8/3）。
> 用户要求逐字节；本卷做 `0x01`，这是全语料**第四高频**字节。
> 复跑：见 §11

---

## 1. 总量与角色分账

```
0x01 全语料 25,187 次
  F (整型字段载荷)  22,039   87.5%
  B (blob 载荷)      2,936   11.7%
  L (长度前缀)         212    0.8%
  标签 / 字符串         0      0
```

**⇒ `0x01` 是**唯一一个**"既当标签、又当载荷、还当长度"的字节。**

**★ 但它 87.5% 的时间是"整型字段的值 = 1"。**
**⇒ 所以它首先是一个**数值**，其次才是标签。**

## 2. 关键统计：`0x01` 作为"值"的分布

**每个标签的"值恰为 1"的比例：**

| 标签 | 宽度 | 总数 | 值=1 | 比例 |
|---|---|---|---|---|
| **`0x01` bool** | 1B | 329 | **326** | **99.1%** |
| **`0x03` u8** | 1B | 18,970 | **18,760** | **98.9%** |
| `0x06` u16 | 2B | 267 | 0 | 0.0% |
| `0x07` i32 | 4B | 12,634 | 38 | 0.3% |
| `0x08` u32 | 4B | 6,369 | 1,710 | 26.8% |
| `0x0a` u64 | 8B | 20,525 | 691 | 3.4% |

**★ 三个硬事实：**

**① `0x01` bool 字段 99.1% 为 true，只有 3 次为 false。**
**② `0x03` u8 字段 98.9% 为 1。**
**③ `0x06` u16 字段**从不为 1**（0 次）—— 它是唯一"与 1 无关"的整型标签。**

## 3. `0x03` 的完整取值域 —— 只有 4 个值

**全语料 `0x03` u8 字段共 18,970 个，取值只有：**

```
value 1 : 18,760   (98.9%)
value 3 :    127   (0.7%)
value 2 :     80   (0.4%)
value 0 :      3   (0.02%)
不同取值个数: 4
```

**⇒ 一个 8 位字段，全语料只出现过 4 个不同值。**

**★ 这不是"数据"，这是**枚举/标志**。**

**非 1 值的来源全部定位：**

```
102/1  val=3  prev=08 next=0a  ×127   ← 08 08 03=03 0a  （22 字节报文）
102/1  val=2  prev=0a next=0a  ×45    ← ...03=02 0a... （33 字节报文）
102/5  val=2  prev=03 next=END ×19    ← 08 03=01 03=02
68/3   val=2  prev=10 next=13  ×16    ← 10 "" 0a 10 "" 03=02 13[22B]
93/131 val=0  prev=08 next=08  ×2
80/154 val=0  prev=08 next=08  ×1
```

**⇒ `0x03` 是一个**小计数器**，最大用到 3。**

**★ 具体证据（102/1 的三种报文）：**

```
22 字节:  08[4B] 08[4B] 03=03 0a[8B]           ← 单条目，序号=3
33 字节:  08[4B] 08[4B] 03=01 0a[8B] 03=02 0a[8B] ← 两条目，序号 1、2
22 字节:  08[4B] 08[4B] 03=03 0a[8B]           ← 同第一种
```

**⇒ `0x03` 的值 = **该条目的序号**（1、2、3），`0x0a` 紧跟其后是 u64 载荷。**

**★ 102/7 是同一结构的 50 次重复：`[03=01 0a[u64]] × 50`。
  注意 50 个条目的 `0x03` **全部 = 1**，不是 1..50。**
  **⇒ 说明 `0x03` 不是"数组下标"，而是"某种固定标志 = 1"。**

**⇒ 结合 102/1 的 1/2/3 和 102/7 的全 1，最合理解释：
  `0x03` 是**"该条目所属类型/槽位"**，不同 task 用它区分用途。**

## 4. `0x01` bool 字段：326 true / 3 false

**全部 `0x01` 标签字段的取值：**

```
bool = 1 : 326
bool = 0 :   3
```

**按 task：**

```
6/5   bool=1 ×160
80/70  bool=1 ×83
29/10  bool=1 ×83
93/131 bool=0 ×2     ← 唯一 false 的来源
80/154 bool=0 ×1     ← 唯一 false 的来源
```

**⇒ `0x01` bool 在 6/5、80/70、29/10 三个 task 里**恒为 true**。**

**★ 这 3 个 false 极其珍贵 —— 它们证明了 `0x01` 是**真的布尔**，
  而不是"恒为 1 的常量"。**

**⇒ 3 个 false 全部出现在 `93/131` 与 `80/154`，且都在元素 #5（共 13 个元素）。
  ⇒ 这两个 task 的第 6 个字段是一个"可关闭的开关"，本次会话里是关闭的。**

**★ 这是**可以实际操作的面**：
  如果这个 bool 控制某个功能（比如"是否显示某 UI 元素"），
  那把它从 0 改 1 就是一个可测的修改点。**

## 5. `0x06` u16 从不为 1 —— 一个"反向"线索

**`0x06` 共 267 个字段，值恰为 1 的 **0 个**。**

**⇒ 这是一个**结构性排除**：
  `0x06` 承载的不是"序号/标志"，而是"数值量"（如长度、时间、坐标）。**

**★ 顺便：`0x06` 的"全零率"是 33%（见 `lobby/102` §5），
  比 `0x07`(14.2%) 和 `0x08`(27.1%) 都高。
  ⇒ `0x06` 是一个**经常为 0、偶尔为大数、从不为 1** 的字段。**

**⇒ 典型的"可选数值参数"：不填时为 0，填了就是有意义的值。**
**（比如"最大人数"：0 = 用默认，N = 指定。）**

## 6. `0x01` 作为标签的语义

**`0x01` 在文法里是 `bool`（1 字节）。**

**★ 但注意：`0x01` 作为标签只出现 329 次，
  而作为"值"出现 25,187 - 329 ≈ 24,858 次。**

**⇒ 标签 329 次 vs 载荷 24,858 次，比例 1:75。**

**★ 这个比例说明：`0x01` 主要是"数据"，不是"结构"。**
**⇒ 所以在报文里看到 0x01，**第一反应应该是"值 1"，不是"bool 标签"。**
**⇒ 只有当前一个字节是"结束"状态（即文法期待一个标签）时，0x01 才是标签。**

## 7. `0x01` 在 blob 里（2,936 次）

**blob 内 `0x01` 的出现与 `0x00` 一样，是"结构化二进制"的一部分。**

**blob 内 top 上下文：**

```
00 <01> 08  ×791
0a <01> 00  ×691
00 <01> 01  ×428
00 <01> 00  ×416
01 <01> 00  ×345
```

**⇒ 全部是"小整数序列"里的 1，没有特殊结构。**

**★ 但有一处值得记：**
```
e6 <01> 13  ×160
```
**这是 8/3 里 `...e6 01 13...` 的模式 —— 160 次。
  结合 `104` 的结论（8/3 是 u32×4 + blob + i32×125），
  这里的 `01` 是某个 i32 的最低字节。**

## 8. `0x01` 作为长度前缀（212 次）

**`0x13 08 <u32 len>` 的 len 最低字节为 0x01 时 = 长度 1、257、513…**

**⇒ 212 次。全部是"1 字节 blob"或"257 字节 blob"。**

**★ 1 字节 blob 是"单字节标志块"，这是 68/3 的特征（`13 08 01 00 00 00 xx`）。**

## 9. 三字节对照（把 0x00/0x70/0xFF/0x01 放在一起）

| 字节 | 次数 | 主要身份 | 有语义？ |
|---|---|---|---|
| `0x00` | 257,126 | 整型高位零 | 结构冗余 |
| `0x01` | **25,187** | **值 1（bool true / 序号）** | **有（枚举）** |
| `0x70` | 1,848 | 字母 p | 无 |
| `0xFF` | 2,463 | -1 哨兵 / 空槽填充 | 有（哨兵） |

**★ 规律：**
**⇒ "高频 + 集中在整型字段" = 有语义（0x01）。**
**⇒ "高频 + 集中在字符串" = 文本（0x70 的 S 类）。**
**⇒ "高频 + 集中在 blob" = 数据/哨兵（0xFF）。**

## 10. 可落地结论

**① `0x03` 的取值域只有 {0,1,2,3}。**
**⇒ 如果我们构造报文，`0x03` 只能填这 4 个值，填别的会被客户端当异常。**

**② `0x01` bool 字段在 6/5、80/70、29/10 恒 true。**
**⇒ 这 3 个 task 的 bool 是"恒开"的，改它需要先知道它控制什么。**

**③ `0x06` u16 从不为 1。**
**⇒ 如果我们要伪造一个 u16 字段，避开 1（1 是一个"不可能值"）。**

**④ 3 个 bool=false 在 93/131 与 80/154 的元素 #5。**
**⇒ 这是**全语料唯一**的"false"，是研究 bool 语义的唯一样本。**
