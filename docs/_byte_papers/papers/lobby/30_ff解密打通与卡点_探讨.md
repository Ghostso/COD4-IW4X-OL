# `.ff` 解密打通与卡点 · 探讨：解出了 16 个字节，然后呢

> 对应：`lobby/30_ff解密打通与卡点.md`

---

## 一、先说我做对了什么

拿到私钥后，我做的第一件事不是"试着解密"，而是**先定位 RSA 密文在哪**。

方法：在 `.ff` 前 0x2000 字节里滑动 256 字节窗口，做 RSA 解密，
**只认 PKCS#1 v1.5 的严格填充**（`00 02` + ≥8 个非零 + `00`）。

```python
if m[0] == 0 and m[1] == 2:
    z = m.find(b"\x00", 2)
    if z > 10:   # 至少 8 字节随机非零
        → 命中
```

**第一次就中：偏移 `0x15`。**

这不是运气 —— **是被协议约束住的结果**：
- RSA 块必须是 256 字节（2048 位）
- PKCS#1 v1.5 填充必须严格满足格式
- 错误的窗口通过率是 1/65536

---

## 二、第二个证明：密钥是对的

解出的 40 字节：

```
da135e91c7981459a13ddc2aed3050ae
6dd9a7ce619bb6c5
ff6c10c6db650000149c1f0103000000
```

我一开始猜 key = 前 24、IV = 后 16。**用它对密文做 CFB128，得到：**

```
IWffs100\x00\x00\x00\x00o\x9e\x1d\x0c
```

**这是 16 字节完全正确的明文。**

概率论证：如果是随机碰出的，概率是 `2^-128`。
**所以 key 和 IV 都是对的。**

---

## 三、然后它坏了

从第 16 字节开始，全是随机字节。

我做了 **7 轮排除**：

| 轮次 | 假设 | 结果 |
|---|---|---|
| 1 | 密钥错 | 否（头对了） |
| 2 | IV 字节序错 | 否（5 种字节序，只有 raw 对） |
| 3 | 不是 CFB | 否（CFB8/64/128、OFB、CTR、ECB 全试） |
| 4 | CBC 链 | 否（用块 0 尾作块 1 的 IV，仍错） |
| 5 | 每块重置 | 否（重置后块 1 仍乱） |
| 6 | 正文压缩 | 否（全文件无 zlib/gzip/bzip2） |
| 7 | 密钥切片错 | 否（穷举 40 字节所有 24 字节窗口，只有 [0:24] 能回头） |

**全部排除。**

## 四、那一定是"参数映射"的问题

回到 `0x483a50` 的 `cipher_setup` 调用点：

```
0x483af3  push 0x1c2b2b8
0x483af8  push 0
0x483afa  push 0
0x483afc  push 0x18          ← 24
0x483afe  lea ecx,[ebp-0x2c] ← RSA 材料
0x483b01  push ecx
0x483b02  lea edx,[ebp-0x14]
0x483b05  push edx
0x483b06  push 0xdb5ed4      ← "aes"
0x483b0b  call 0xbc8780      ← find_cipher("aes") → eax
0x483b10  add esp,4
0x483b13  push eax
0x483b14  call 0xbc8640      ← cipher_setup
```

**问题在 `0x483b06`**：`push 0xdb5ed4` 是给 `find_cipher` 的，
不是给 `cipher_setup` 的。而 `0x483b10` 的 `add esp,4` 只清掉了它。

**那么 `0x483afc` 的 `push 0x18` 到 `cipher_setup` 之间差了几个参数？**

`cipher_setup` 的 6 个参数（从压栈顺序反推）：

```
arg1 = eax          (cipher index)
arg2 = [ebp-0x14]
arg3 = [ebp-0x2c]
arg4 = 24
arg5 = 0
arg6 = 0
arg7 = 0x1c2b2b8
```

**`arg2` 和 `arg3` 的位置，决定了谁是 key、谁是 keylen。**

代码里：
- `0xbc86e8` 用 `[ebp+0xc]`（= arg2 = `[ebp-0x14]`）作为**拷贝源**
- `0xbc86bc` 用 `[ebp+0x10]`（= arg3 = `[ebp-0x2c]`）作为 **keylen** 传给 setup

**`[ebp-0x2c]` 是内存地址，不可能当 keylen 用。**

**所以我的参数映射一定错了 —— 我把有 7 个参数的函数当 6 个读了。**

## 五、这一轮的价值

**我解出了 16 个字节，这不是"半成品"，而是一个"锚"。**

- 它证明密钥对
- 它证明算法是 CFB 族
- 它证明明文头是 `IWffs100`

**剩下的只是"把参数数清楚"。**

这一轮：
- **净收获**：4 条硬结论（RSA 位置、密钥结构、算法族、明文头）
