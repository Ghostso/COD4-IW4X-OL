## 一、你的质疑，我逐字拆开

> 「这三项直接在游戏客户端文件里找，本地客户端肯定有，
> 如果没有他要怎么知道什么是正确的」

这句话里有**两个命题**：

1. **「客户端必须知道正确值」** —— 100% 正确，无法反驳。
2. **「所以这些数据一定在客户端文件里」** —— **这个推论不成立**。

★★★ **客户端"知道"的方式有两种：编译期写死，或运行时算出来。**
只有第一种会留在文件里。

## 三、第二个发现：磁盘 exe 的代码是加密的

既然主体是 7.8 MB 的 exe，那它怎么可能装下整个游戏？

查熵：

```
磁盘 exe .text : 7.140 bits/byte  0xCC 占 0.22%
内存镜像 .text : 6.776 bits/byte  0xCC 占 3.04%
90 个 64KB 块全部不同
```

**⇒ 磁盘上是 VMProtect 加密态，内存里是解密态。**

★★★ **这解释了我一直以来的困惑：为什么磁盘 exe 只有 7.8 MB，却能跑起整个游戏。**

---

## 四、最关键的一步：用段表算，不用"搜不到"下结论

你说"文件里肯定有"，那我就不该说"我搜不到"。

**我改成了算术：**

```
段 .tp3#3:  VA=0xA16000  VSize=0xDBB1CC0  RawSize=0x62000
0x82E1458 段内偏移 = 0x74CB458
0x74CB458 > 0x62000  →  物理上不存在
```

**这不是"没找到"，是"文件里那一段物理上不存在"。**

★★★ **一条减法就能把"我没找到"变成"那里没有"。**

## 五、你的直觉有一半是对的——名字确实在

```
0xE6F094  tp3#3  段内偏移 0x59094  →  YES  file off 0x75B094
          bytes: 2e 3f 41 55 64 77 52 6f 6f 6d 4d 65 73 73 61 67
                 ".?AUdwRoomMessag"
```

**43 个 `dwRoomMessage` 类名，磁盘 exe 的 `.rdata` 里完整存在。**

★ 所以准确的说法是：

| | 磁盘上有 | 说明 |
|---|---|---|
| **类名**（编译期常量） | ✅ | `.rdata`，未加密 |
| **type_info/COL/vtable**（运行时对象） | ❌ | BSS 空洞 |
| **47 项描述符表内容** | ❌ | 运行时填 |

★★★ **名字在，结构体不在。** 这就是"客户端知道"和"文件里写着"的差别。

## 七、我这一卷真正学到的东西

### 7.1 "搜不到"和"不存在"是两回事

我前四卷反复说"段2 覆盖 0.2%"，但**从来没有真的去算过那些地址的段内偏移**。

这次算了：
```
0x74CB458  vs  RawSize 0x62000
```
**差了 300 倍。** 一眼就能看出来。

★★★ **我早该做这条减法。**

### 7.2 文件名会骗人

`codoMP_client_shipRetailBase.dll` —— 名字里带 `codoMP_client`，57 MB，
看起来就是游戏本体。

**实际是 OpenCV。**

★★ **判据应该是"里面有什么类"，不是"文件叫什么、多大"。**

### 7.3 你的质疑方式值得学

你不是说"你错了"，你说的是**"如果没有他要怎么知道什么是正确的"** ——
这是一个**逻辑必然性论证**，逼我去找一个能证伪或证实的点。

**如果我按这个思路早点查，"段2 空洞"这件事第一轮就能确认，不用拖四卷。**
