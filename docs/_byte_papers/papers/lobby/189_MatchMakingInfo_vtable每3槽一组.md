# 189 · `MatchMakingInfo` 的 vtable 结构定案：**每 3 槽一组**（2 函数 + 1 COL），三个视图错位 3

> 卷次：189（房间类 · 187/188 卷的 vtable 结构定案）
> 方法：对三个 vtable 做后缀对齐
> 结论：**`a[3:] == b`，`b[3:] == c`，`a[6:] == c`** ⇒ 同一槽序列的三个起点。

---

## §0 决定性对齐

```
a = 0xDC79F0: [806F20] [8072A0] [COL] [806C90] [B87DA0] [COL] [4F4010] [COL] [4F40B0] [B87DA0] ...
b = 0xDC79FC: [806C90] [B87DA0] [COL] [4F4010] [COL]   [4F40B0] [B87DA0] ...
c = 0xDC7A08: [4F4010] [COL]   [4F40B0] [B87DA0] ...
```

★★★ **`a[3:] == b[:]`，`b[3:] == c[:]`，`a[6:] == c[:]`** —— 完美对齐。

### 0.1 槽的模式

每 3 槽是一个"基类子对象接口块"：

```
[func_A] [func_B] [COL 指针]
```

- `a[0..2]` = `806F20` / `8072A0` / `COL(0xDF8498)`
- `a[3..5]` = `806C90` / `B87DA0` / `COL(0xDF8484)`
- `a[6..8]` = `4F4010` / `COL(0xDF83F4)` ... 等一下，`a[6]=4F4010`，`a[7]=COL(0xDF83F4)`，`a[8]=4F40B0`

★ 模式不完全是"2 函数 + 1 COL"。实际是：

```
a[0]=806F20  a[1]=8072A0  a[2]=COL  a[3]=806C90  a[4]=B87DA0  a[5]=COL
a[6]=4F4010  a[7]=COL     a[8]=4F40B0 a[9]=B87DA0 a[10]=4F40C0 a[11]=COL
```

**COL 指针穿插在函数之间**，间隔不固定。

但**核心事实成立**：三个 vtable 首尾相接、错位 3 槽。

### 0.2 为什么会有三个

`0x4F4021/0x4F4027/0x4F4031` 写了三个 vtable：

```asm
0x4F4021  mov [edi],     0xDC79F0
0x4F4027  mov [edi + 8], 0xDC79FC
0x4F4031  mov [ecx+edi+4], 0xDC7A08
```

★ 偏移 `+0`、`+8`、`+4`。

- `+0` → `0xDC79F0`（主视图，含 `806F20`/`8072A0`/`806C90`...）
- `+8` → `0xDC79FC`（跳过 `a[0..2]` 的三槽）
- `+4` → `0xDC7A08`（跳过 `a[0..5]` 的六槽）

⇒ **这是同一个类的三个"接口指针"**，指向同一槽序列的不同起点。
   ⇒ **`MatchMakingInfo` 实现了三个接口基类**（如 `ISerializable` / `IComparable` / `IExtensible`）。

### 1.1 那 `0x625CE0` 的 `[this+8]` 是什么

```asm
0x634B0D  mov [ebp-0xC90], edi     ; edi = ebx+0x7238
0x625CE0  mov eax, [esi+8]         ; = ebx+0x7238
0x625D2C  add eax, 0x18            ; → ebx+0x7238+0x18
```

★ `ebx+0x7238` = 数组 B **末尾之后的 +8 处**（元素起点 `0x6FF8`，末元素 `0x7230`，`0x7238 = 0x7230+8`）。

⇒ **`ebx+0x7238` 是"末元素的 `+8` 字段"** —— 即**第二个接口 vtable 指针的位置**。

再加 `0x18` ⇒ `ebx+0x7250` —— 落在**数组 B 之外**（数组末 `0x7238`）。

★★★ **所以 `0x634B0D` 的那条 `mov` 很可能不是在构造一个合法的 StartGame 消息** —— `edi` 指向的是"数组末尾之后"，不是任何元素内部。

⇒ **这条路径可能是错误/未使用分支**，或者我对 `ebx+0x7238` 的理解仍差一层。

## §4 方法论

1. **★★★ vtable 后缀对齐能一次性判定"是不是同一个类"。** `a[3:]==b` 比逐个槽比较更可靠。
2. **★★ vtable 指针可以写在 `+0`/`+4`/`+8`，不一定是"子对象起始"。** 这是接口指针，不是结构体。
3. **★★★★ 一个"看似合理"的链条（186→187→188→189）每推一步都出现新矛盾，说明起点假设可能错。** 本卷发现 `ebx+0x7238` 可能落在数组之外 —— 这必须直面。
4. **★★ 遇到"偏移落在数组外"，优先怀疑"我的步进/起点算错了"，其次怀疑"这条路径不活跃"。**
