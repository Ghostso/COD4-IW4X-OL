# 193 · 三个 `MatchMakingInfo` 区间精确定案（脚本验算，互不重叠）

> 卷次：193（房间类 · P3 完成）
> 方法：**用脚本算区间，不心算**（前三轮心算全错）
> 结论：A `[0x76A8,0xE360]` / B `[0x578,0x7230]` / C `[0x7238,0x7470]`，**三者互不重叠**，各 27832 字节。

## §0 精确区间（脚本输出）

| 区间 | 起点 | 终点 | 大小 | 来源 |
|---|---|---|---|---|
| **数组 A** | `+0x76A8` | `+0xE360` | `0x6CB8` = 27832 | `0x637D01 lea esi,[ebx+0xE368]` |
| **数组 B** | `+0x578` | `+0x7230` | `0x6CB8` = 27832 | `0x637D94 lea esi,[ebx+0x7238]` |
| **单例 C** | `+0x7238` | `+0x7470` | `0x238` = 568 | `0x637D55 mov [ebx+0x7238],vt` |

★★ **互不重叠**（脚本判定 A vs B / A vs C / B vs C 全部"不重叠"）。

### 0.1 关键细节：B 的终点 `+0x7230` 与 C 的起点 `+0x7238` 相差 **8 字节**

```
B 末元素尾 = 0x7230
C 起点     = 0x7238
间隙       = 0x7238 - 0x7230 = 8
```

★ 这 8 字节恰好是 **vtable#2 的偏移量**（`+8`）。

⇒ 说明布局是：
```
... [数组B 49×0x238] ... 0x7230
    [8 字节间隙]             0x7230~0x7238
    [单例 C 0x238]           0x7238~0x7470
```

★★ **这个"间隙"很可能是 C 的 `-8` 偏移槽**（vtable#1 写在 `[esi-8]` 处），
即 C 的**真正起点可能是 `0x7230`**，而我按 `0x7238` 算。
若 C 起点 = `0x7230`，则 B 与 C **紧邻无缝**。

★ 这与循环体 `mov [esi-8], 0xDC79F0` 完全一致 —— 元素起点 = `esi-8`。
对 C：`0x637D55 mov [ebx+0x7238], 0xDC79F0` 是**直接写 `+0x7238`**，不是 `[esi-8]`。
⇒ **C 的 vtable#1 在 `+0x7238`，所以 C 起点 = `+0x7238`**，间隙 8 字节真实存在。

## §2 `+0x7238`（单例 C）与 `StartGame` 的关系

`0x634AED lea edi, [ebx + 0x7238]` → `[this+8] = 单例 C`

而 `0x625CE0` 用 `[esi+8]` 读写 `+0x18 / +0x118 / +0x10 / +0x1CC`。

★ 但 `MatchMakingInfo` 的序列化器（`0x806F20` 读 `+0x128..+0x1F8`；`0x806C90` 读 `+0x120..+0x218`）
**都不含 `+0x18`**。

⇒ **单例 C（`MatchMakingInfo`）的 `+0x18` 是个"MMI 自己不用、只有 StartGame 用"的字段。**

### 2.1 这可以成立吗

★ 可以。`MatchMakingInfo` 是 0x238 字节的对象，`+0x18` 落在前 0x120 段（`0x806C90` 从 `+0x120` 才开始读）。
⇒ **`+0x00 ~ +0x11F` 这 288 字节是 MMI 的"低区"，`0x806C90`/`0x806F20` 都不碰。**

★★★ **结论：`MatchMakingInfo` 的低区（`+0x00 ~ +0x11F`）是"不透明数据区"，
`+0x18` 是其中的一段 256 字节缓冲，`+0x118` 是它的长度。**

⇒ **这是 `MatchMakingInfo` 的"外部注入块"** —— MMI 自己不解包，只原样传递。
