## 1. 为什么这个 DLL 是钥匙

它同时具备：

1. **未加壳**（普通 PE32，`.text/.rdata/.data/.rsrc/.reloc`）
2. **是 IFS 格式的实现者**（日志前缀 `IFS2LOG`）
3. **内含完整加密/压缩栈**：
   - `libtomcrypt`（MD5、SHA1、RSA、ECC）
   - `bzip2`
   - `ifscompress` 类（`cb_glue`、`ifscompress`、`IFSCompressedFile`）
4. **有完整的读写 API 符号**

## 4. 内部符号（关键字符串）

### 4.1 扇区模型

```
AllocateSectorBuffer failed!
AllocateSectorOffsets failed!
AllocateSectorChecksums failed!
WriteSectorChecksums failed!
WriteSectorOffsets failed!
Add the file sectors to the NIFS failed!
VERIFY_FILE_SECTOR_CRC_ERROR
wSectorSize:(512*2^%d)
```

**`.ifs` 是按"扇区"组织的**，扇区大小 = `512 * 2^n`。

### 4.2 完整性

```
VERIFY_FILE_MD5_ERROR
verify_file_md5 failed
MD5TablePos64:%d
MD5TableSize64:%d
dwMD5PieceSize:%d
MD5_BetTable:%s
MD5_HetTable:%s
MD5_IFSHeader:%s
MD5_PatchBaseTag:%s
MD5_PatchedTag:%s
md5 compare failed!
dwLength != ha->pHeader->dwMD5PieceSize
SFileVerifyFilePieceMD5
SFileVerifyFilePieceMD5Break
SFileVerifyFilePieceMD5FromFileTable
SFileCheckAllFileMD5
```

**MD5 贯穿整个 IFS 系统**，而且分"piece"（分片）。

### 4.3 文件条目

```
isdir[%d]FileName[%s] size[%d] compSize[%d] name_hash[%llu] md5[%s] offset %lld
```

**这是文件表的一项的格式**：

| 字段 | 说明 |
|---|---|
| `isdir` | 是否目录 |
| `FileName` | 名字 |
| `size` | 原大小 |
| `compSize` | **压缩后大小** |
| `name_hash` | **u64 名字哈希** |
| `md5` | **文件 MD5** |
| `offset` | 文件在 IFS 内的偏移 |

**`compSize` 的存在说明是"压缩"，不是"加密"。**

### 4.4 压缩

```
SFileSetDataCompression
unknown compression method
bzip2/libbzip2: internal error number %d
.?AVcb_glue@ifscompress@@
.?AVifscompress@@
.?AVIFSCompressedFile@@
```

**压缩方案是 bzip2**（不是 zlib）。

### 4.5 完整性 API

```
SFileLoadMd5 / SFileVerifyFilePieceMD5 / SFileCheckAllFileMD5
```

## 6. 结构推断（基于字符串）

```
.ifs 文件
 ├─ 头部 172 字节（已解，见 lobby/11）
 ├─ 清单区（明文 .lst + .ff 路径）
 ├─ 文件表（每项：name / size / compSize / name_hash / md5 / offset）
 ├─ 扇区缓冲区（payload 按 sector 组织）
 ├─ 扇区偏移表
 └─ 扇区校验表
```

**`tbl[4]`（尾部表起点）很可能就是"扇区偏移/校验表"。**
