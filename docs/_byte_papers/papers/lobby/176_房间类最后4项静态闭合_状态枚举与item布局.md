## §1 `0xBA0780` 的完整状态机

```asm
0xBA0780  cmp  dword ptr [ecx+0x644], 0
0xBA0787  mov  eax, dword ptr [ecx+0xC8]
0xBA078D  je   0xBA079F
          ; ---- 分支 A：[+0x644] != 0 ----
0xBA078F  cmp  eax, 2
0xBA0792  je   0xBA0799
0xBA0794  cmp  eax, 1
0xBA0797  jne  0xBA07B1        ; 既非 1 也非 2 -> 原样返回 eax
0xBA0799  mov  eax, 2          ; ★ 1 或 2 -> 归一化为 2
0xBA079E  ret
          ; ---- 分支 B：[+0x644] == 0 ----
0xBA079F  cmp  eax, 2
0xBA07A2  jne  0xBA07B1        ; 非 2 -> 原样返回
0xBA07A4  xor  eax, eax
0xBA07A6  cmp  dword ptr [ecx+0x5E8], 3
0xBA07AD  sete al              ; al = ([+0x5E8] == 3)
0xBA07B0  inc  eax             ; ★ 1 或 2
0xBA07B1  ret
```

### 1.1 语义表

| `[+0x644]` | `[+0xC8]` | `[+0x5E8]` | 返回 |
|---|---|---|---|
| 非 0 | 1 或 2 | 任意 | **2** |
| 非 0 | 其它 | 任意 | `[+0xC8]` 原值 |
| 0 | ≠ 2 | 任意 | `[+0xC8]` 原值 |
| 0 | 2 | == 3 | **2** |
| 0 | 2 | ≠ 3 | **1** |

★★ **`0xB7A670` 要的是 `== 2`**，所以：
- 分支 A 下，`[+0xC8] ∈ {1,2}` 就够；
- 分支 B 下，必须 `[+0xC8]==2` **且** `[+0x5E8]==3`。

### 1.2 三字段的初值与写点

| 字段 | ctor `0xBA2800` 初值 | 写点总数 | 唯一非零写点 |
|---|---|---|---|
| `+0x644` | `0xBA299C mov [esi+0x644], ebx`（`ebx=0`） | 9 | **`0xBA35EB` **（`ebx=1`） |
| `+0xC8` | `0xBA28D4 mov [esi+0xC8], ebx`（`ebx=0`） | 103（跨多个类） | — |
| `+0x5E8` | `0xBA2984 mov [esi+0x5E8], ebx`（`ebx=0`） | 3 | — |

★ `[+0xC8]` 的 103 个写点里绝大多数属于**别的类**（`0xC8` 是极常见偏移）。只有 `0xBA28D4` 在 `0xBA2800` ctor 内，能确认属于本对象。

### 1.3 `0x644` 的唯一置位路径

```
0xBA3590  （唯一的置 1 处）
0xBA3598  mov ebx, 1
0xBA35B0  call 0xB783C0            ; 解析（读某段位流/字符串）
0xBA35B8  test al,al / je 失败
0xBA35BC  cmp byte [ebp+0x13], bl  ; 解析结果 == 1 ?
0xBA35BF  je  0xBA35D7
0xBA35D7  cmp dword [esi+0x644], 0 ; 已经置过就不重复
0xBA35DE  jne 失败
0xBA35E2  call 0xBA3010            ; ★ 再做一次校验
0xBA35E7  test al,al / je 失败
0xBA35EB  mov [esi+0x644], ebx     ; ★★★ 置 1
```

**唯一调用者：`0xBA3B02`。**

⇒ `[+0x644]` 是一个**"某种握手/解析成功"的一次性标志**，置上之后 `0xBA0780` 走分支 A，宽松放行。

## §2 谁触发 `vt[0]` 写出 —— 结论：**没有 call 边，只有 vtable**

```python
0x6301A0 (SendReady)  数据引用 2 处: 0xDC72F8, 0xDC7798
0x62C5A0 (房间动作入队) 数据引用 0 处
0x62C380 (族 A)        数据引用 0 处
0x62C870 (族 B)        数据引用 0 处
```

### 2.1 三层调用结构

```
【第 3 层 · 定时器】FrameUpdate 0x632D90
    0x63346E  call 0x634340        ; 房间状态广播（150 卷）
        0x62C380 (族 A, kind==4 真发) / 0x62C870 (族 B)

【第 2 层 · 状态变化】0x634340 的三个调用者
    0x63346E <- 0x632D90  (FrameUpdate)      ★ 每帧
    0x6347F9 <- 0x634750
    0x634F5F <- 0x634870  (Manifold 分发器内，case 处理)

【第 1 层 · UI 动作】
    vt[0xDC72F8] = 0x6301A0 (SendReady)     ★ 由 vtable 调用
    vt[0xDC7798] = 0x6301A0
        └ 0x6301BF call 0x62C5A0 (房间动作专用入队，+0x3A098)
```

★★ **结论：`SendReady` 等 43 个写侧函数都是通过 vtable 被调用的，静态找不到 `call` 边。**
这是 **CPP→Flash 的反向调用**：Flash 侧触发 `AS_SetReadyState`，C++ 侧在 AS 回调注册表里找到 `0x7CF850`（147 卷），再由它 `mov ecx,[0x82E13FC]` 取 `dwRoomImp` 并 `vt[33]` 调到 `0x6301A0`。

**静态能到的最深处就是这个 vtable 槽 `0xDC72F8`。** 再往上是 Flash 运行时（AVM2），不在 PE 里。

## §3 `Manifold` item 的完整布局（读写两侧对称）

### 3.1 读侧 `0x4F3EB0`

```asm
0x4F3EB4  push 0x13 / call 0xB774E0      ; ★ 读 19 位（0x13 = 19，不是 13！）
0x4F3EC6  push 8    / call 0xB774E0      ; ★ 读 8 位
0x4F3ED5  push 0x20 / lea [ebp-4] / call 0xB772E0   ; ★ 读 32 位 → esi = 长度
0x4F3EF2  mov ecx,[edi+0x1C]             ; 当前位置
0x4F3F02  mov eax,[edx]                  ; 剩余位
0x4F3F04  cmp eax, esi / jb              ; 取 min(剩余, esi)
0x4F3F0A  add eax,eax ×3                 ; ★ ×8 = 位数
0x4F3F14  call 0xB772E0                  ; ★ 读 (min×8) 位 = 有效载荷
0x4F3F3E  mov [edi+0x1C], eax            ; 推进位置
```

### 3.2 写侧 `0x625520` 的 item 循环体（逐条对应）

```asm
0x6255C6  push 1    / call 0xB77B10      ; 1 位
0x6255CF  push 1    / push val / call 0xB777C0   ; 1 位值（0xFF / 0x00）
0x6255FE  push 0x15 / call 0xB77B10      ; 21 位（条件：`ecx|ecx != 0`）
0x625607  push 0x40 / push val / call 0xB777C0   ; 64 位值
0x625621  push 0x13 / call 0xB77B10      ; ★ 19 位
0x62562A  push 8    / call 0xB77B10      ; 8 位
0x625633  push 0x20 / push val / call 0xB777C0   ; 32 位 = [+0x10]
0x625645  lea ecx,[edi*8] / push / push ebx / call 0xB777C0  ; ★ edi×8 位 = [+8] 的内容
```

★★★ **读写完全对称**（读侧 `0x4F3EB0` 对应写侧 `0x625621` 起的四步）。

### 3.3 item 结构定案

```
item := [1 位 存在位]
        [1 位 值（0xFF=有值 / 0x00=无）]
        [21 位]                  ← 条件字段（`[+8]|+0xC] != 0` 时才有）
        [64 位 值]
        [19 位]                  ← ★ 0x13 = 19，恒 19 位
        [8 位 子类型]
        [32 位 length]           ← 载荷**字节数**
        [length × 8 位]          ← 载荷本体
```

★ **`0x13` 是 19，写成"13 位"是错的。** 这一条在初稿里写错过，已在 §3.1/§3.2 更正。

★ `0x4F3F0A` 连做 3 次 `add eax,eax` = ×8，证明 `length` 存的是**字节数**不是位数。

### 3.4 与 7 字节 header 的关系

```
Manifold := [3 位 tag][8 位 type][8 位 ?][32 位 count=条数]
            + count × item
```
- 头部 `51 位 = 7 字节`（175 卷）
- 每条 item = `1+1+[21]+64+19+8+32 + 8×length` 位

### 3.5 `0xB77B10` 与 `0xB777C0` 在两侧的对称跳过

```asm
0xB774E0（读）: cmp byte[ecx+0x21],0 / je 返回 True   → +0x21==0 时**不读**
0xB77B10（写）: cmp byte[ecx+0x21],0 / je ret         → +0x21==0 时**不写**
```

★★ **两侧用同一个 `+0x21` 做开关，是配对的。**

- 客户端**读** Manifold 应答时 `+0x21=1`（`0x637026 push 1`）⇒ 字段全部读
- 客户端**写**自己的消息时 `+0x21=0`（`0x62C3AA push 0`）⇒ 字段全部跳过

⇒ **服务端生成应答必须按 `+0x21=1` 的全字段格式写**（175 卷结论不变，只是这里补上了 `B77B10` 侧同样是"写 N 个 0 位"）。

## §5.5 修复落地：R16

按 §3 定案的 item 结构，重写了 `codol_crypto.build_manifold()` 的 item 编码：

```python
# 旧（错）：[1 存在][1 有值] + 按字节直塞
# 新（R16，按 176 卷）:
wb(1, 1)              # 存在位
wb(0xFF, 1)           # 有值位
wb(0x13, 19)          # ★ 19 位 tag（不是 13！）
wb(0, 8)              # 子类型（未知，填 0）
wb(len(it), 32)       # 长度 = 字节数
for byte in it:
    wb(byte, 8)
```

**位级对账（`verify5.py` ALL PASS）：**

| 输入 | 位宽 | 字节 |
|---|---|---|
| `(0, ())` | 51 | 7 |
| `(0x10, (b"\x01\x02",))` | 51 + 77 = 128 | **16** |
| `(0x10, (1,))` | 53 | 7 |

逐位断言：头 `[3 tag][8 type][8 0][32 count]` + item `[1][1][19=0x13][8][32=2][0x01][0x02]` 全部命中。

★★ **注意：R16 让 `count>0` 的应答从"结构不对"变成"结构正确但语义未定"** ——
`8 位子类型` 的取值域仍未定（§5 第 3 条），当前填 0。**这是本卷唯一带入代码的未定量。**

## §6 方法论

1. **★★★ 「找不到 call 边」不等于「没有调用者」。** vtable 槽是调用边的一种，`0x6301A0` 有 2 个数据引用 0 个 call。查调用者必须同时查 `E8 rel32` **和** `dd imm32` 数据引用。
2. **★★ 状态机函数要列全输入组合表，不要只写"返回 2"。** `0xBA0780` 有 5 种输出，只记一种就会误判。
3. **★★ 极常见偏移（如 `0xC8`）的写点扫描必须用「所在函数」筛。** 103 个写点里只有 1 个属于本对象。
4. **★★ 变长体的长度字段要确认单位。** `0x4F3F0A` 连做 3 次 `add eax,eax` = ×8，证明它存的是**字节数**不是位数。
5. **★★★ 十六进制立即数不要口算成十进制再写进论文。** `push 0x13` 是 **19**，我在初稿里写成"13 位"，靠读写两侧对账才发现。**同一结构的读写两侧互为校验**。
