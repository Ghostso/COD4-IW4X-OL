> 性质：方法论复盘。**主题：模板的"项数对不上"，多半是"你以为它在，其实它是拼出来的"。**

---

## 一、127 卷那个「差 1~2 项」我后来才发现是问错了

127 卷我写：`ClientLoadout` 模板 5 项、实测 18 项，续接片段 `0x9B7B88` 15 项，「5+15 凑不出 18，差 1~2 项，诚实记为未闭合」。

我当时**默认了两件事**：

1. 一条事件有**一条**模板；
2. 模板可以是**两段相邻字面量**（因为 `ClientOfflineOOB` 证明了）。

这两件事**都不对**。

### 1.1 本卷的做法

我这次没再去找"续接片段"，而是**把 `ClientLoadout` 的日志函数 `0x76B10` 从头反汇编完了**。

一看到 `push '|B0%d'` 后面紧接着 5 段 `push '%d,'`，我立刻明白了：**这不是模板，是一个格式化的构造过程**。

```
sprintf(buf, "ClientLoadout|%s|%llu|${CODOID(%llu)}|%d", ts, acct, codo, 1)
sprintf(buf+len, "|B0%d", slot)            // 槽位
for each weapon: sprintf(buf+len, "%d,", id)  // 5 个配件 ID
sprintf(buf+len, "|%d", n)                // 段数
...
```

**⇒ 127 卷「差 1~2 项」是这条构造在不同会话里段数/物品数不同造成的。不是"模板对不上"，是"根本没有模板"。**

### 1.2 这次教训很贵

**127 卷如果也去反汇编 `0x76B10`，就会当场发现。** 但我当时忙着做「项数对账」，直接放弃了「读代码」这条路。

**⇒ "项数对账"只能告诉你"对不对"，不能告诉你"为什么"。** 要对不上就得回去读代码，而不是换更复杂的对账方法（我找到续接片段那一刻，其实已经选错了方向）。

## 二、第四个入口，是差集告诉我的

我做了一件之前没做的事：**拿「NUL 模板普查」和「调用点普查」做双向差集**。

结果：
- 日志点有、NUL 普查没有：**0 条**
- NUL 普查有、日志点没有：19 条（11 假阳性 + 8 条真孤儿）

**⇒ 有 8 条模板从来没走过我发现的那三个入口。** 那它们怎么进队列？

顺着 `push 模板` 往下一看：

```
0x77DB10  push 模板
0x77DB15  lea edx,[esp+0x9f8]
0x77DB1C  push 0x1000     ← ★ 先 sprintf 到栈缓冲
0x77DB22  call 0x774900
...
0x77DB5D  push eax
0x77DB5E  call 0x63fc60   ← ★ 新入口
```

**⇒ `0x63FC60`。** 没有那条差集，我可能永远只认三个入口。

★★ **这是本卷最值钱的方法：两个普查做差集。**

理由：单个普查"看起来完整"（127 卷就说"54 条模板"、"2 个调用点"），但它的完整性**只有在和另一个不同口径的普查对比时才被检验**。差集不为空的地方，就是你理解缺一块的地方。

## 三、`'3370'` 和 `'268'` 这些「裸数字串」

`PreprocessGroupInfoResult` 的日志函数里压了 `'3370'`；`ChatMessageReport` 里压了 `'268'`、`'CODOL'`。

我一开始想当"魔数"去追，但**这里必须直接认**：

- `'3370'` 很可能是 zone id / 服务器编号（腾讯 CODOL 的区服编号常见 4 位）；
- `'268'` 很可能是通道 id 或消息类型。

**这两个我没有证据**，所以**只在表里标注了它出现在哪个函数里，没有给它们命名**。

★ 这是 126 卷「假阳性防火墙」的同类规则：**裸数字串只记录位置，不记录语义。** 语义要有第二条证据才能挂上去。

## 四、`UIClickCount` —— 名字骗了我一下

名字是 `UIClickCount`，我第一反应是：**它一定和 `UIClick` 一样走 C 入口 `0x640FD0(name, value)`。**

结果：**它走 D 入口 `0x63FC60`，而且模板第一项是 `%llu` 不是 `%s`。**

```
UIClickCount|%llu|${CODOID(%llu)}|%s|%u|%s|%d
```

★★ **⇒ 名字像的事件，通路不一定一样。** `UIClick`（点击事件）和 `UIClickCount`（点击计数）差一个词，但一个走 C、一个走 D，时间口径也不同。

**这也是本卷第二个「诚实缺口」**：`0xE6F30` 里压了 `'${TIMESTAMP}'`（`0xE716F`），但 `UIClickCount` 模板里**没有** `${TIMESTAMP}`。要么模板有另一份（我没找到），要么 `${TIMESTAMP}` 在该函数里被用作别的字段的实参。**我不猜。**

## 五、`0x63FC60` 剥换行，这一条解释了 124 卷的「\n 分隔」

124/123 卷说：`71/3` 一条 payload 里可以是**多条事件 `\n` 分隔**。

本卷在 `0x63FC60` 里看到：**它把 `0x0a` 和 `0x0d` 逐字节跳过**。

**⇒ 走 D 入口的事件，不可能在一个条目里是"多行"。** 多行只能来自"多个条目拼在 payload 里"，而不是"一个条目里带换行"。

★ 这是一个**便宜的互证**：两个不同卷的结论在一条 `cmp al, 0x0a` 上对上了。

**方法论**：读到"过滤某字节"的循环，**立刻问"过滤之后，谁在依赖这个字节"？** 答案往往在别的卷里。

## 六、`ClientException` 记完就关总开关

```
0x77DB5D  push eax
0x77DB5E  call 0x63fc60    ; 记录异常
0x77DB63  add esp,4
0x77DB66  mov byte [0xe5735b], 0   ; ★ 总开关置 0
```

同样的 `[0xe5735b]` 在 128 卷里是"引擎/登记器/冲刷器/断线转储"的前置门控。

★★ **⇒ 异常后遥测主动停用。** 这解释了两件事：

1. **124 卷里 `71/15` 162 个样本没有一条是"异常之后"的**——异常之后就不记了；
2. **为什么有些会话里遥测只到某个点**——那条 `ClientException` 就是终点。

这是我第一次在代码里看到"遥测会主动停"。**之前我一直以为遥测只有"队列满丢弃"一种。"

## 七、方法论（可迁移）

1. **两个不同口径的普查做差集。** 差集不为空 = 你缺一块。本卷就是靠这个找到第四个入口的。
2. **"项数对不上"回去读代码，不要发明更复杂的对账。** 模板项数只能判对错，不能判"为什么"。
3. **同一个结果可以由"相邻字面量"或"运行时循环追加"产生，二者必须分开。** `ClientOfflineOOB` 是前者，`ClientLoadout` 是后者。
4. **名字像 ≠ 通路一样。** `UIClickCount` 走 D 入口，`UIClick` 走 C 入口。
5. **裸数字串只记位置，不记语义。** `'3370'`/`'268'` 记录在哪个函数里压的，不给名字。
6. **读到"过滤某字节"的循环，回头问"谁在依赖它"。** 剥换行 → 解释了 124 卷的多行语义。
7. **写代码里看到的"置全局为 0"，别只当一个赋值。** `[0xe5735b]=0` 是本卷找到的"遥测主动停用"的机制。
