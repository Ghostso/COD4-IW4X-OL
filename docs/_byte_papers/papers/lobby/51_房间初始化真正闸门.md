# ★★★★★ 房间初始化的真正闸门：`[0x849ba30] == 3`

> **这是房间逆向的终点，也是整个项目的核心状态位**
> 承接 `lobby/40`–`50`

---

## 1. 闸门代码

```asm
0x808261  cmp dword ptr [0x849ba30], 3
0x808268  jne 0x80852c          ; ★ 不等于 3 → 跳过整段
0x80826e  call 0x8080c0
0x808273  cmp byte ptr [0x849ba3d], 0
0x80827a  jne 0x80845f
0x808280  mov eax, [0x84aba50]
0x808285  cmp eax, 5
0x808288  ja  0x80845f
...
（继续到 0x808650 → 0x7e98f0 → 0x639d00）
```

**`[0x849ba30]` 必须等于 `3`，才进入房间初始化分支。**

```
[0x849ba30] = 0
```

**（`client_runtime.bin` 偏移 `0x809ba30`）**

**⇒ 闸门关闭 ⇒ 房间对象不创建。**

## 4. 这个值是什么

**`[0x849ba30]` 与 `0x849ba3d`（byte）相邻，同一结构体。**

**`0x849ba30` 起来自一段 `0x849baxx` 的全局区，
很可能是"网络/会话状态机"的当前状态。**

**常见取值的推测：**

| 值 | 含义（推测） |
|---|---|
| 0 | 未初始化 / 离线 |
| 1 | 连接中 |
| 2 | 已连接 |
| **3** | **已进入大厅（就绪）** |

**⇒ 只有"已进入大厅"状态，才会初始化房间子系统。**

---

## 5. 与项目已有记录的关系

`memory: codol-iips-must-be-enabled`：

> 本体 6 秒必崩的根因 = `enable_iips=0`；
> 改成 1 后完整进大厅（`5E8=1→3`、Auth `10→11`、31 个 service 全应答）

**注意那个 `5E8=1→3` —— 状态从 1 变成 3！**

**⇒ `[0x849ba30]` 很可能就是同一个"状态 3"的另一处镜像。**

**⇒ 如果 `enable_iips=0`，状态停在 1 或 0，永远到不了 3。**

---

## 6. 这条链把两个问题合流了

```
enable_iips = 0
   ↓
不进大厅（状态 != 3）
   ↓
[0x849ba30] != 3
   ↓
房间初始化被跳过
   ↓
房间对象不存在
   ↓
房间功能全部失效
```

**⇒ "6 秒必崩"和"房间不能用"是同一个根因的两个表现。**

---

## 7. 修复方向（明确）

**不是改 `0x82e13fc`，不是调命令，而是让 `[0x849ba30] == 3`。**

**而这需要：**

1. `enable_iips = 1`（已有记录）
2. 完成进大厅的状态跃迁（`5E8 = 3`）

**⇒ 这两个条件在正确的启动链上会自动满足。**
