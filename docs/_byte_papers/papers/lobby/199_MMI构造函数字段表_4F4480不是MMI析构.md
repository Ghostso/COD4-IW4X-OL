## §2 检查：`0x4F4480` 是不是 MMI 的析构

`0x4F4480` 的特征：
```asm
0x4F44A5  lea ecx,[esi+0xD8] / call 0xB76E50
0x4F44B0  lea ecx,[esi+0x24] / call 0xB76E50
0x4F44B8  mov eax,[esi+0x20] / mov edi,[esi+0x18]  → free
0x4F44E8  mov eax,[esi+0x10] / mov edi,[esi+0x08]  → free
```

★ 与 MMI ctor（`0x806B50`）对比：
- MMI ctor 初始化 `+0x128`（64B）、`+0x1CC`（16B）、`+0x1B0~+0x1C8`
- `0x4F4480` 析构 `+0x18`/`+0x08`/`+0x24`/`+0xD8`

★★ **两组字段完全不重叠！**

⇒ **`0x4F4480` 不是 `MatchMakingInfo` 的析构**，是**另一个类**（碰巧在 0x4F4xxx 区）。

★ 这更正 198 卷的结论。

## §3 `0x4F4480` 属于哪个类

从字段布局：
```
+0x08 ptr / +0x10 size / +0x0C cap   数组（元素 4B）
+0x18 ptr / +0x20 size / +0x1C cap   数组（元素 0x84 = 132B）
+0x24 子对象（0xB76E50）
+0xD8 子对象（0xB76E50）
```

★ `0x84 = 132` 字节元素 —— 与"成员记录"尺寸接近。

⇒ **`0x4F4480` 可能是 `dwRoom` 或 `dwRoomImp` 的析构**（含成员列表数组）。

## §5 那 `MMI+0x18` 到底是什么（最终）

★★★ **MMI ctor 不初始化 `+0x18`** ⇒ 它是**未初始化的 POD 内存**。

⇒ **`dwRoomMessageStartGame` 把 `MMI+0x18` 当 256B 缓冲用，是因为它知道那块内存"没人用"。**

★ 这**不是类型混淆**，而是**"借用未初始化内存作临时缓冲"** —— 在 C++ 里属于未定义行为，
但在实际代码里常见（尤其是"反正要丢弃"的路径）。

---

## §6 方法论

1. **★★★ 构造函数 + 析构函数对账，能判定"是不是同一个类"。** 字段完全不重叠 ⇒ 不是。
2. **★★ ctor 不初始化的字段 = POD / 未使用 / 被外部填充。**
3. **★★★ 198 卷说 `+0x18` 是"动态数组指针"是对的（那是 `0x4F4480` 那个类），但那个类不是 MMI。** 两个类混了。
4. **★★ 元素大小 `0x84` = 132 是强指纹** —— 可用于识别是哪个类的数组。
