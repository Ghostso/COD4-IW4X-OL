## 二、这一版把"循环"写成 `× N`

**`MemberList` = 50 位 + N × (725 位 + 字符串)。**

**现在可以答上面三个问题：**

**- 50 位 = 2 个字段（槽位数 u8 + 成员数 u32）。**
**- 成员记录 725 位，字段表见 `member_record_fieldmap.txt`。**
**- 8 个成员时 ≈ 50 + 8×(725+8×名字长)。**

**⇒ 这才能拿去写服务端。**

## 三、最意外的发现是 `0x15`

**我一直以为 `0x15` 是某种"特殊类型"，
因为它出现得太多了（149 次，比 0x03 还多）。**

**但看完成员记录就明白了：**

```
0x15 → 16 位  [edi+0x94]
0x15 → 16 位  [edi+0x96]
0x15 → 8 位   [edi+0x98]
0x15 → 64 位  [edi+0xa0]
0x15 → 32 位  [edi+0x8c]
... 共 28 次，位宽 8/16/32/64 全有
```

**⇒ `0x15` 是"通用槽位"：后面紧跟一个位宽，位宽不固定。**

**⇒ 换句话说：`0x15` = "这里有一个字段，长度由下一个立即数决定"。**

**这解释了为什么它出现最多——它是默认的字段标记，
只有 `bool`(0x01)、`u8`(0x03) 这种高频短类型才单独留了编号。**

## 四、于是标签词表可以重新解释

| tag | 含义 | 依据 |
|---|---|---|
| `0x01` | bool 型字段（恒定 1 位） | 41 次全是 1 位 |
| `0x02` | 特殊 8 位字段 | 只在 RoomInfo/Join 出现，读侧断言 |
| `0x03` | u8 型字段（恒定 8 位） | 98 次全是 8 位 |
| `0x05` | u16 型（1 次） | — |
| `0x06` | u16 型字段 | 22 次全是 16 位 |
| `0x07` | i32 型字段 | 2 次全是 32 位 |
| `0x08` | u32 型字段 | 17 次全是 32 位 |
| `0x0a` | u64 型字段 | 8 次全是 64 位 |
| `0x0d` | float 型字段（32 位） | 14 次全是 32 位，源是 `fld dword` |

## 五、`0x0d` 是浮点，这是个新锚点

**我在 `0x624b88` 附近看到：**

```
0x624788  fld  dword ptr [esi+0x30]
0x62478b  push 0x0d
0x62478d  fstp dword ptr [ebp-8]
0x624790  call 0xb77b10
0x624795  fld  dword ptr [ebp-8]
0x624798  push 0x20
0x62479d  fstp dword ptr [ebp-0xc]
0x6247a3  call 0xb777c0
```

**⇒ `fld` → 转成整数形式 → `push 0x0d` → `writeData(32 位)`。**

**⇒ `0x0d` = float32，且是"先 fld 再从内存写出"——
所以 32 位是 IEEE 位模式，不是定点。**

**⇒ 这是标定"房间坐标/角度之类字段"的直接线索。**

## 六、`StartGame` 的"不一致"是我读漏了 helper 内部

**我一开始看到 `StartGame` ser=331 / der=139，差 192 位，
准备写一篇"客户端自己两侧都不同步"。**

**然后我去看了 `0x4f3eb0`：**

```
0x4f3ed5  push 0x20 / call readData(&n, 32)   ← 先读长度
0x4f3f04  cmp eax,esi                         ← 和 cap 比较
0x4f3f0a  add eax,eax ×3                      ← ×8
0x4f3f14  call 0xb772e0                       ← readData(buf, n*8)
```

**⇒ blob 读器是"读 u32 长度再读 n×8 位"。**

**写侧 `0x625be0` 也是"写 u32 长度再写 n×8 位"。**

**⇒ 两侧完全对称。所谓 -192 位，是我把这三块的**数据段**算成了"0"。**

**⇒ 幸好在写论文之前读了那个 helper。否则又是一条假结论。**

**这已经是这一轮第三次"先怀疑工具、后来发现是自己"了。**

## 七、方法论收获

> **判断"位长"之前先判断"有没有循环"。**
> **一个循环体位长 × N 才是结构；一个合计只是幻觉。**

**另一个：**

> **高频标签不等于"特殊标签"。`0x15` 之所以最多，
> 恰恰因为它是"没有特殊化"的默认通道。**
