## 二、所以这篇做了什么

子代理 C 声称两个关键结构：
1. **DML 标签表**（读 `0xB761E0`(u32) / `0xB76890`(u8) / …）
2. **新发现 `0x0D` = f32**

我**没有先读它的论文**，而是自己反汇编：

```asm
0xB769F0  push 0xD
0xB769F9  call 0xB76310
0xB76A02  push 4 / lea [ebp-4] / call 0xB75E80
0xB76A13  fld  dword ptr [ebp - 4]      ← 浮点加载
0xB76A19  fstp dword ptr [ecx]          ← 浮点存储
```

**`fld`/`fstp` ⇒ f32。确认。**

顺手把整张表都独立跑了一遍：

| tag | 类型 |
|---|---|
| 1 | bool |
| 3 | u8 |
| 6 | u16 |
| 7 | i32 |
| 8 | u32 |
| 10 | u64 |
| **13** | **f32** |
| 16 | string |
| 19 | blob |
| 23 | ? |

## 三、这张表还验证了我自己的假设

我在 171–229 卷里，一直用 `08`=u32、`0A`=u64、`10`=string、`13`=blob 来解 TLV。

**这些标签我这轮才第一次独立取得**（之前是从日志模式推的）。

⇒ **我自己的 20 多卷 TLV 假设，被一次独立反汇编验证了。**

## 四、但也有对不上的地方 —— 好在没有

我原本担心一件事：子代理 C 说 **`13 08 <u32 len>` 里的 `08` 是"长度字段自身的 tag"**，
而我在 171 卷里把它写成 **"tag 0x13 / sub 0x08 / u32 len"**。

看起来是两个说法。实际是**同一件事**：
- 我说 `08` 是 sub（子类型）
- 它说 `08` 是"长度字段的 tag"

两者都指"`0x13` 后面那个 `0x08`"。**表述不同，观察相同。**

★ 这种"看起来冲突、其实同义"的地方，必须在论文里写清楚，否则后人会以为有矛盾。
