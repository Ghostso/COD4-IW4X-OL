# 149 · 出站三条入队路径 + 一条真发路径：上下游收口

> 前序：148（房间按钮全链路）、147（消息泵 this=srpc）、146（真脱壳）
> 性质：**出站路径全解析 + 上下游收口**。本卷把 `0x62C870` 的
> `kind` 语义彻底解开，并给出**完整的出站路径分类**。

## §0 十二条结论

1. ★★★★★ **`0x62C870` 的 `kind` 分支在函数开头**：
   ```asm
   0x62C876  cmp dword [ebp+0x14], 4
   0x62C881  jne 0x62C99F          ; kind != 4 → 入队分支
   ```
2. ★★★★★ **`kind == 4` = 真发**：
   ```asm
   0x62C8BD  call edx              ; 消息 vt[0] 序列化
   0x62C8E0  mov dword [esi], 0xDB7154   ; bdByteBuffer
   0x62C8F0  mov dword [esi+8], 0x800
   0x62C93D  call 0x7E8300         ; ★★★★ 网络发送
   ```
3. ★★★★★ **`kind != 4` = 入队**：
   ```asm
   0x62C9FF  call edx              ; 序列化
   0x62CA17  mov edx,[eax+0x3A0D8]
   0x62CA1D  add eax, 0x3A0D4      ; ★ 容器
   0x62CA2B  call 0x656A10         ; 插入
   ```
4. ★★★★ **`0x62CA60` = 入队包装器**（`push 2` → `call 0x62C870`）。
5. ★★★★★ **三条独立的入队路径**：
   | 函数 | 目标容器 | 使用者 |
   |---|---|---|
   | `0x62C5A0` | `+0x3A098`（哈希表）| **房间动作**（Ready/ChangeTeam）|
   | `0x62C800` | `+0x3A0D4`（链表）| 通用 |
   | `0x62C870(kind≠4)` | `+0x3A0D4`（链表）| `0x62CA60` 包装 |
6. ★★★★★ **一条真发路径**：`0x62C870(kind=4)` → `0x7E8300`。
7. ★★★★★ **`0x634340` = `dwRoomImp` 房间状态广播**，内部**多处 kind=4 真发**：
   ```
   0x63451F/0x63453C  push 4 → call 0x62C870        （type 在 [ebp-0x230]）
   0x6345B4  type = 0x17 (RoomStateUpdated), vtable 0xDC7684
   0x6345FC  type = 0x3  (StartGame),        vtable 0xDC751C
   0x63461B/0x634626  push 4 → call 0x62C870        ★ 真发
   0x634677  call 0x62C380                          MemberInfoAdd (0xA)
   ```
8. ★★★★ **`0x634340` 由 `0x63346E` 调用**，位置在 `0x63342x` 处理 `+0x3A118` 队列之后。
9. ★★★★ **`0x6330xx` 依次访问 `+0x3A0D4`（链表）与 `+0x3A098`（哈希）** —— 两容器的统一调度点。
10. ★★★★ **`0x637C40` = `dwRoomImp::Reset`**：清空 `+0x3A104/0x3A108`、
    5 个 `+0x3A0F8` 槽、`+0x3A0B0`、`+0x3A098`、`+0x10784`、一串 std::string、
    以及 **51 条成员记录**（`+0xE368`，步进 `0x238`）。
11. ★★★ **`+0x3A098` 的 5 个访问点全部解析**：构造 `0x62C2A9` / 入队 `0x62C5BF` /
    遍历 `0x6330C7`·`0x633181` / 析构 `0x637C69`。**无一处通向 `0x62C870(4)`。**
12. ★★★ **`0x7E8300`（网络发送）全镜像唯一调用者是 `0x62C93D`** ——
    即所有出网流量都必须经过 `0x62C870(kind=4)`。

## §1 出站路径总图

### 1.0 ★★★★ 两族发送函数（同一模板，`kind` 位置不同）

```asm
0x62C380  push ebp / mov ebp,esp / and esp,0xFFFFFFF8 / sub esp,0x1C
0x62C390  mov edi, eax
0x62C392  push 0x24
0x62C394  cmp edi, 4                    ; ★ kind 在 eax（寄存器）
0x62C397  jne 0x62C4C0                  ; ≠4 → 入队

0x62C870  push ebp / mov ebp,esp / sub esp,0x1C
0x62C876  cmp dword [ebp+0x14], 4       ; ★ kind 在栈参
0x62C881  jne 0x62C99F                  ; ≠4 → 入队
```

**两族的 kind==4 都通向 `0x7E8300`。**

### 1.0b kind=2 包装器

```asm
0x62C590  push ebp / mov ebp,esp
0x62C593  mov eax,[ebp+8]
0x62C596  push eax
0x62C597  push ecx
0x62C598  mov eax, 2                    ; ★ kind = 2
0x62C59D  call 0x62C380                 ; 族 A

0x62CA60  push ebp / mov ebp,esp / and esp,0xFFFFFFF8
0x62CA6C  push 2                        ; ★ kind = 2
0x62CA73  call 0x62C870                 ; 族 B
```

### 1.0c 两族的调用者

| 族 | 调用者 | kind |
|---|---|---|
| **A** `0x62C380` | `0x62B6E1`（房间激活 `0x62B6xx`）| ? |
| | `0x62C58D`（= `0x62C590` 包装器）| 2 |
| | `0x632A51` | 4 |
| | `0x634677`（MemberInfoAdd）| 4 |
| **B** `0x62C870` | `0x62CA74`（= `0x62CA60` 包装器）| 2 |
| | `0x63453C` | 4 |
| | `0x634626`（StartGame）| 4 |

### 1.0d 第三种：`0x62C5A0`（房间动作专用）

**不加 kind 参数，直接入队到 `dwRoomImp+0x3A098`，无第二分支。**

## §5 上下游收口

### 5.1 上游（服务端 → 客户端）—— 已在 139–147 卷闭合

```
网络帧 → 0xB838A0(srpc 消息泵) → 0xB7B300(op6/7) → slot[6] 0x7F1060
 → 0x7E7C90(key 匹配, 2 条记录) → rec+0x25B8 = 0x6371F0
 → 双 blob → 0x637000 → 0x6256C0(Manifold) → 0x634870(47 项表)
```

### 5.2 下游（客户端 → 服务端）—— 本卷闭合

```
按钮 → AS_* → dwRoomImp 虚函数 → 构造 dwRoomMessage
        ├─ 房间动作 → 0x62C5A0 → 【入队 A: +0x3A098】   ← 静态未见出网
        └─ 状态广播 → 0x62C870(kind=4) → 0x7E8300 → 【网络】
```

### 5.3 关键事实

- **`0x7E8300` 全镜像唯一调用者 = `0x62C93D`（在 `0x62C870(kind=4)` 内）**
- **`+0x3A098` 的 5 个访问点无一处调用 `0x62C870`**
- **`0x62C5A0` 只有 4 个调用者，全是房间动作虚函数**

## §6 诚实边界

1. **「房间动作入队 → 出网」的路径仍未找到**。已排除：
   - `+0x3A098` 的 5 个访问点（构造/入队/遍历/析构）
   - `0x62C5A0` 的函数体（只序列化+插入）
   未排除：`0x6330xx` 遍历时的**匹配分支被释放**这一行为是否掩盖了别的动作。
2. **`0x656A10`（插入函数）与 `0x654D60`（取出函数）的真实语义未逐条验证** ——
   我是按调用上下文推断为"插入/取出"。
3. **`0x6330xx` 的函数边界未定**（起始可能在 `0x632F00` 之前）。
4. **`0x634340` 的完整分支（`0x634500` 之前与 `0x634700` 之后）未全读**。
5. **dump 时未进房间**（`clientState = 0`），无法验证这些容器在房间内的实际内容。

## §8 方法论

1. ★★★★★ **函数开头的 `cmp`/`jne` 就是分派点** —— `0x62C876 cmp [ebp+0x14],4` 一行定语义。
2. ★★★★★ **"唯一调用者"是最强的收敛点**：`0x7E8300` 只有 1 个调用者 ⇒ 所有出网必经 `0x62C870(4)`。
3. ★★★★ **容器访问点用 `add reg, imm32` + `lea reg,[reg+disp32]` 双形态扫**。
4. ★★★ **三个阶段（构造/入队/析构）的访问点要一起看**，才能确认容器没被别的路径用。
