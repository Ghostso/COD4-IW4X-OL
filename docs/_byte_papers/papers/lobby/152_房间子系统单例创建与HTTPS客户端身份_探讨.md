# 152 探讨 · 追一个写点，追出了一个域名

> 配套：[152 · 房间子系统单例创建 + HTTPS 客户端身份](152_房间子系统单例创建与HTTPS客户端身份.md)
> 主题：**用"读多写少 ⇒ 写点即创建点"这条判据，一口气定位了房间子系统的初始化，
> 并顺手更正了 147 卷一个跨三卷的误判。**

---

## 一、判据：读 299 次、写 1 次

`[0x82E13FC]`（dwRoomImp）的统计：

```
read  = 299
write = 1        ← @0x639D1E
```

**⇒ 写点就是创建点。**

顺着这一个地址，读到了整个函数 `0x639D00`：

```asm
push 0x3A128 ; call 0xC3E9F5 ; call 0x62C000 ; mov [0x82E13FC], eax   ; dwRoomImp
push 0x3A160 ; call 0xC3E9F5 ; call 0x638210 ; mov [0x82E1400], eax   ; 第二个
push 0x38    ; mov [esi],0xDC74E0           ; mov [0x82E1404], esi   ; dwInvitationImp
```

★★★ **一个初始化函数，一次拿到三个单例。** 而且 `0x3A128` 这个大小直接
和 139 卷记录的 `dwRoomImp` 大小吻合 —— 互相印证。

★ **⇒ `dwRoomImp` 总是存在**（299:1）⇒ **149/150 卷的"入队不出网"不是"对象没创建"造成的。**

---

## 二、顺手一查，撞见一个域名

`[0x84ABB14]` 也是 read=123 / write=1。追它的写点：

```asm
push 0x32D0                              ; 分配 13008 字节
push 0x81A76A8                           ; ★ "formal-zone-auth.codol.qq.com"
call 0xB99090
mov [0x84ABB14], eax
push 0xDC9CA4                            ; ★ "cacert.pem"
call 0xB9A100                            ; 加载 CA 证书
```

★★★ **字符串常量是最强的身份判据** ——
`formal-zone-auth.codol.qq.com` + `cacert.pem` ⇒ **无条件确定这是 HTTPS 客户端。**

---

## 三、这个发现更正了什么

147 卷我追过一条链：

```
0x7F3890 → 0x7F38D4 mov eax,[0x84ABB14]
         → 0x7F38F0 call 0xB9A0E0       ; lea eax,[ecx+0x28]
         → 0x7F3912 call 0xB82070       ; 我称它为"连接建立"
```

**当时我把它理解成"连游戏服务器"。**

**现在知道 `[0x84ABB14]` 是 HTTPS 客户端 ⇒ 那条链建立的是**腾讯认证连接**。**

★★★ **这解释了一个长期矛盾**：147 卷读到 `[0x84ABA7C] = 2`（我标为"已连接"），
但除了这个值之外，周边全都对不上 —— 因为那个「已连接」是**认证连接**的状态，
不是游戏服连接。

---

## 四、这一卷的方法论收益

### 4.1 「读多写少」这条判据非常实用

```
读 299 / 写 1  ⇒ 单例，写点=创建点
读 123 / 写 1  ⇒ 单例，写点=创建点
读   4 / 写 5  ⇒ 状态变量（不是单例）
```

★★ **一个比值就能分类全局变量的角色。**

### 4.2 一个初始化函数 = 一个子系统

`0x639D00` 一次创建 3 个单例 + 做全套初始化。
**读它整段，比分别追 3 个单例便宜得多。**

### 4.3 字符串常量胜过一切推断

我从 `0x639D00` 推断出 dwRoomImp（靠大小 `0x3A128` 吻合），
但从 `formal-zone-auth.codol.qq.com` 是**直接读出** HTTPS 客户端。
**后者不需要任何推断。**

## 五、这一卷**没有**闭合的

**房间动作（Ready/ChangeTeamRequest）的出网路径。**

本卷反而排除了一个新可能：**不是"房间对象未创建"**（它是 299:1 的单例，总在）。

**⇒ 缺口仍精确地停在：`0x62C5A0` 入队 `+0x3A098` → ? → `0x62C870(kind=4)`。**
