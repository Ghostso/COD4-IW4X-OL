# 252 探讨 · "bad_items" 这名字摆在那里，我先当了两卷"已拥有"

> 配套：`252_更正249_250_bad_items黑名单与真正的已拥有表.md`

---

## 一、我叫错了两卷的表

249 卷我写：

> **`0x5E3760` 在 `[0xC9113CC]` 的「已拥有列表」里线性查找；命中时 `0x5E37DB mov word [edi+4],1`。**

250 卷沿用同一说法。

**这一卷找到那张表是谁填的**：

```asm
0x7EC638  push 0xDDFAD4      ; "bad_items"
0x7EC63D  push 0xDDF818      ; "ui_config"
0x7EC642  call 0x50BC70      ; dvar 注册/查找
0x7EC650  call 0x5DE440      ; 解析逗号分隔 ID → 填入 [0xC9113CC]
```

**`bad_items`。**

**名字就写着"坏物品"。** 而我两卷都把它当成"已拥有"。

---

## 二、更糟的是，命中分支写的是 0

我 249 卷引用的那一行：

> 命中时 `0x5E37DB mov word [edi+4], 1`

**这一行属于「未命中」路径。** 命中路径是：

```asm
0x5E3783  je 0x5E37F6          ; 命中 → 跳走
...
0x5E37F6  mov [edi], esi
0x5E37F8  mov word ptr [edi+4], bx    ; ★ bx = 0
```

`bx` 在 `0x5E3770 xor ebx, ebx` 被置 0。**命中 ⇒ flag = 0（不可用）。**

**我把两条分支的归属搞反了，而且反了整整两卷。**

★ 这和 235 卷（`reply+5` 极性）、249 卷（`sete` 看错操作数）是**同一类错误的第三次**：
**只看了"我关心的那条指令"，没有把它放回所在分支。**

---

## 三、一个反例救了我

到这一卷我还在想："就算表名是 `bad_items`，也许它同时起'已拥有'的作用？"

**然后我 dump 了这张表**（运行时内容），并和库存对照：

```
库存 Items["121"] = 1            ✅
bad_items 表里有 121 吗           ❌
```

**`121` 在库存里、不在 `bad_items` 里 —— 这完全正常**（121 是买来的背包物品，不是"坏物品"）。

但如果 `[0xC9113CC]` 是"已拥有表"，**121 必须在里面**。**它不在 ⇒ 它不是已拥有表。**

★ **一个反例就把两个概念分开了。** 这比任何正面证据都干净。

---

## 四、真正的表找到了

顺着 `0x5E3760` 的**未命中**路径往下读：

```asm
0x5E37B7  call 0x5E3550          ; item == onboardCharacterID || 0x80A5E0(item)
0x5E37C1  call 0x5E3580          ; 扫表 0x826A550
```

而 `0x80A5E0`：

```asm
0x80A5E8  mov esi, [0x84ABB4C]   ; ★ 计数来自运行时变量
0x80A5FB  mov ecx, 0x8269FD0     ; ★ 表 0x8269FC8
```

**`0x8269FC8` —— dump 出来 32 项，`121` 不在，`60027/60028` 不在。**

**这才是「已拥有表」。**

---

## 五、但这一卷没把问题解决，反而揭了新的

我原以为修复是"让服务端把 60027/60028 发进库存"。现在看：

**这张"已拥有表"不是从库存建的。** 它由 `0x80B5xx` 族从**源表**搬运：

```asm
0x80B5A6  mov ebx, 0x8269B74     ; 源表
0x80B5BE  call 0x80A5E0          ; 去重
0x80B5D6  call 0x810B20          ; 追加
```

**⇒ 服务端发库存，不会写进这张表。** 249/250 卷那条修复路线**前提不成立**。

★ **这一卷的净收益是：把一个错误的修复方向掐掉了。** 不是找到答案，是**排除了一个假答案**。

---

## 六、留下一个真正的突破口

徽章槽 idx1/idx2 的 item **60220/60221**：

- **在徽章源表 `0x8269B18` 里**（250 卷已证）✅
- **不在已拥有表 `0x8269FC8` 里** ❌

**它俩明明在源表里，却没被搬过去。**

搬运循环的条件是：`item != 0` `&& count < 100` `&& 不在已拥有表`。**这三条都不会滤掉 60220。**

**⇒ 说明还有我没看到的过滤条件，或者它们来自另一张没被扫的源表。**

**这是下一卷该做的事，而且地址明确。**
