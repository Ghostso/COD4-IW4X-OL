# 模式门 `[0xe59d20]` 的写入逻辑（整条链的起点）

> **这是大厅启动链的最顶层**
> 证据：`client_runtime.bin`，`0x62186b`–`0x62189a`

---

## 1. 完整分支

```asm
0x62183c  mov esi, eax               ; 某个会话对象
0x62184a  call 0xbac370              ; ★ 返回 [esi+0x1F4]
0x62184f  cmp eax, 1
0x621852  jne 0x62185b
0x621856  call 0xbad810              ; 状态 1 时调用

0x62185d  call 0xbac370              ; 再取
0x621862  cmp eax, 2
0x621865  jne 0x621a5e               ; 不是 2 → 另一分支

0x62186b  mov eax, [0xe59d20]        ; ★ 当前模式
0x621870  sub eax, 3                 ; eax -= 3
0x621873  je  0x62188b               ; == 3 → 走大厅
0x621875  sub eax, 2                 ; eax -= 2（总共 -5）
0x621878  jne 0x62189f               ; != 5 → 不动
0x62187a  call 0x802cc0
0x62187f  mov [0xe59d20], 6          ; ★ 模式 = 6（游戏）

0x62188b  call 0x802cc0
0x621890  mov [0xe59d20], 4          ; ★ 模式 = 4（大厅）
0x62189a  call 0x621db0
```

---

## 2. 判据

**`0xbac370()` = `[obj+0x1F4]`（一个整数字段）。**

**当它 == 2 时，才处理模式切换：**

```
[0xe59d20] == 3  →  模式 = 4（大厅）
[0xe59d20] == 5  →  模式 = 6（游戏）
其他              →  不变
```

**⇒ `[obj+0x1F4]` 是"会话阶段"，等于 2 表示"已进入某个场景"。**

---

## 3. ★ 起点是 `[0xe59d20] == 3` 或 `5`

**注意这个逻辑很微妙：**

**它读 `[0xe59d20]` 的**旧值**，用旧值决定新值。**

```
旧 = 3  →  新 = 4（大厅）
旧 = 5  →  新 = 6（游戏）
```

**⇒ 在切到 4 之前，`[0xe59d20]` 必须先到过 **3**。**

**⇒ 3 是一个中间态。**

---

## 4. 那 3 从哪来

**前面 `0x621870 sub eax, 3` 说明 3 是个有效的旧值。**

**⇒ 需要查 `[0xe59d20] = 3` 的写入点。**

**从全量写入点看：**

| 地址 | 写入值 |
|---|---|
| `0x6217a9` | 0 |
| `0x62187f` | **6** |
| `0x621890` | **4** |
| `0x6217dc` | eax（变量） |
| `0x621779` | edx（变量） |
| `0x621ac0` | edi（变量） |

**⇒ 3 只能来自 `0x6217dc` / `0x621779` / `0x621ac0` 之一的变量写入。**

---

## 5. 完整因果链（最终版）

```
某会话阶段 [obj+0x1F4] == 2
        ↓
读 [0xe59d20] 旧值
        ↓
旧 == 3  →  0x621890 写 4（大厅）
旧 == 5  →  0x62187f 写 6（游戏）
        ↓
[0xe59d20] = 4（大厅模式）
        ↓
0x622220() 返回 1
        ↓
状态 7 的第三重判断通过
        ↓
[0x849ba34] = 8 → 0x7ef3fe → 3
        ↓
[0x849ba30] = 3
        ↓
房间初始化 → 房间对象
```

**十二层，全部有地址。**

---

## 6. 实测

| 变量 | 实测 | 要求 |
|---|---|---|
| `[0xe59d20]` | **0** | 先到 3，再到 4 |
| `[0x849ba34]` | 0 | 3 |
| `[0x82e13fc]` | 0 | != 0 |

**⇒ `[0xe59d20]` 停在 0，从未到过 3。**

**⇒ 连"中间态"都没进入。**

---

## 7. 这意味着什么

**`[0xe59d20] = 0` 表示"应用还没决定要显示什么"。**

**⇒ 这不是"登录失败"，是"更早的启动阶段"。**

**⇒ 与 `memory: codol-iips-must-be-enabled` 的"6 秒必崩"吻合：
启动在更早的地方就停了。**

---

## 8. 整条链的完整总结

**从 `lobby/40` 到 `lobby/74`，共 35 卷，追出了一条 12 层的启动链：**

```
1.  [0xe59d20]           应用模式          = 0（实测）
2.  0x622220()           模式门            → 需要 4/6
3.  0x803830()           连接单例
4.  [conn+0x4F8]         认证标志
5.  0xb7a670()           连接状态 == 2
6.  [0x84aba50]          登录阶段 == 5
7.  0x7f25b0()           大厅状态 == 3
8.  [0x849ba34] = 8      状态 8
9.  [0x849ba34] = 3      提交
10. [0x849ba30] = 3      镜像
11. 0x808261             房间闸门
12. [0x82e13fc]          房间对象
```

**每一层都能在反汇编里指着看，
每一层都有实测值，
每一层都能单独验证。**
