# 227 · ★★★★★ 决定性更正：`0x632680` 是「booking 超时检测」函数，**不是开局函数**

> 卷次：227（房间类 · **第八次更正，也是本轮最重要的结论**）
> 方法：找 `0x632680` 的两跳虚调用点 → 读调用者传的实际参数
> 结论：**唯一调用者在 FrameUpdate，传的参数3 是 `"mmbook timedout"`，门6 恒不等。**

---

## §0 唯一调用点

`mov reg,[X+0x13C] / call reg` 全镜像共 **7 处**，但只有 **1 处操作 `dwRoomImp`**：

```asm
; ---- 0x632D90 FrameUpdate 内 ----
0x632F95  mov  edx, [0x82E1428]
0x632F9B  fild dword [edx+0xC]            ; 取某计时值
0x632F9E  fcompp
0x632FA0  fnstsw ax
0x632FA2  test ah, 5                      ; ★ 浮点比较 -> 是否超时
0x632FA5  jp   0x632FCF                   ; 未超时 -> 跳过
0x632FA7  mov  edx, [ebx + 0x3A04C]        ; 参数2 = 对端ID高32
0x632FAD  mov  eax, [ebx]                  ; eax = dwRoomImp->vtable
0x632FAF  push 0xF                         ; 参数3 长度 = 15
0x632FB1  push 0xDC69D4                    ; ★★★ "mmbook timedout"
0x632FB6  lea  ecx, [ebx + 0x3A050]
0x632FBD  mov  ecx, [ebx + 0x3A048]        ; 参数1 = 对端ID低32
0x632FC3  push edx
0x632FC4  mov  edx, [eax + 0x13C]          ; ★ 取 0x632680
0x632FCA  push ecx
0x632FCB  mov  ecx, ebx                    ; this = dwRoomImp
0x632FCD  call edx                         ; ★★★ 调用
```

**其余 6 处**（`0x83DB0E`/`0x84C254`/`0x84DF6D`/`0x84E1C1`/`0x89D261`/`0xC63E3F`）
的对象都**不是** `dwRoomImp`（`ecx` 来自别的数组/对象）。

而唯一调用者传的是 `"mmbook timedout"` ⇒ 永远不相等 ⇒ 恒走 `0x632876` 分支。**

|---|---|---|

### 3.1 门4/5 为什么恒真

```asm
0x632FBD  mov ecx, [ebx + 0x3A048]   ; 参数1 ← 自己的字段
0x632FCA  push ecx
0x632FC4  mov edx, [eax + 0x13C]
...
0x6326B9  cmp eax, [esi + 0x3A048]   ; 门4：参数1 == 自己的字段
```

**传进去的就是自己的字段 ⇒ 比较必然相等。**

## §4 真正的开局路径在哪

★★★ **"mmbook accepted" 那条路（门6 通过）在当前 build 里没有调用点。**

⇒ **客户端从不因为收到 "mmbook accepted" 而开局。**

★ 可能的真实开局触发：
1. `0x632876`（timeout 分支）里的后续逻辑
2. 或另一条完全不同的路径（如 `0x6301A0` SendReady 的 vtable 槽链）
3. 或由 Flash 直接触发某个非虚函数

**本卷未定。** 但**已排除 213–216 卷的路径**。

## §6 方法论

1. **★★★★★ 找到虚函数后，必须追到"调用者实际传的参数值"。** 只看被调函数的 `strcmp(参数, 常量)` 会误判——常量是什么、参数实际是什么，必须分别读。
2. **★★★★ 两跳虚调用（`mov reg,[X+disp]; call reg`）`call [reg+disp]` 扫不到，必须单独扫。**
3. **★★★★ 「参数 == 自己的字段」⇒ 该门恒真。** 门4/5 就是这样，216 卷据此推出的"服务端必须提供 u64"完全错。
4. **★★★ 同一偏移（`+0x13C`）在多个类里都有虚函数，必须确认 `ecx` 来自哪个对象。**
