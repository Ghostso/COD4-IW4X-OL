# 120 探讨 · 一个标签，两个语义：别给容器的"尾巴"起统一名字

> 配套：[120 · `0x6b`/`0x6c` 尾部 u32 语义收口](120_数组尾部u32语义收口.md)
> 性质：方法论复盘。**主题：容器标签 vs 业务字段。**

---

## 一、这条黑箱挂很久了

`INDEX §七 #5` 写着：「`0x6b`/`0x6c` 尾部 u32 语义未定（`28/1` 已部分解出：类型 1 时是关卡 ID）」。

我一开始也想"给它起个名"——"尾部 u32 = 元素总数"。因为 `113` 卷发现 `0x6c` 的 body 首 u32 恒等于元素数，那尾部 u32 大概率也是某种"数"。

**这个"起名冲动"是错的。** 本卷跑完发现：`0x6b` 的 tail 是 `N-1`，`0x6c` 的 tail 是"领域容量"。**根本不是同一个东西。**

## 二、我怎么发现的：不猜，全量分类

我没写"尾部 u32 是 X"的假设，而是**把 362 条全部按 `(svc/task, tag, byteLen, bodyFirst, tail)` 分桶**，然后问：**每个桶里 `tail` 和已知量是什么关系？**

结果桶非常干净：

```
21/5  tag=6B  bl=4  bf=1  tail=0     ×159   ← tail 恒 = bf-1
28/1  tag=6C  bl=4  bf=1  tail=131   ×25    ← tail = PvE 关卡总数
28/1  tag=6C  bl=8  bf=2  tail=5     ×24    ← tail = PvE 关卡总数(另一局)
28/4  tag=6C  bl=508 bf=127 tail=263 ×94    ← tail = 内容槽总数
28/1  tag=6C  bl=0  bf=—  tail=0     ×43    ← 空数组
```

**分桶之后，"统一名字"的幻想自动破灭。** 一个桶里是"索引-1"，另一个桶里是"容量"。你没法用一个词盖住。

## 三、这一卷最重要的结论其实是"不存在统一语义"

我最后在 §2.3 写的不是"尾部 u32 = X"，而是：

> **Demonware 的容器标签只保证"怎么读"，不保证"尾部字段是什么"。**

这句话把 `09` 卷的"`0x13` 内层格式属于业务"**推广到了数组标签**。

**⇒ 传输层的容器只负责"定界"，容器里装的含义属于业务。** `0x13` 是这样，`0x6b`/`0x6c` 也是这样。

**这是同一个规律的第二次确认。** 第一次是 `0x13`（内层是 mmstart/明文/zlib，随 task 变），这次是 `0x6b`/`0x6c` 的尾部（随 task 变）。

## 四、`body首u32 == byteLen/4`：一个冗余字段

这条虽然简单，但写出来很硬：**`0x6b` 159/159 + `0x6c` 160/160 零例外。**

它为什么重要？因为它告诉我们 `body` 的**真结构**：

```
body := [u32 N = byteLen/4] [N-1 个元素]
        ↑ 冗余自描述头，不是第 0 个数据元素
```

**手工构造报文的人最容易踩的坑**：把 `N` 当成第一个数据元素。比如 `28/1`，`bl=8`、`bf=2`，真实数据只有**一个**元素（选中关卡），`bf=2` 只是"我这里面有 2 个 u32"。

**这直接改写 §3 的可构造模板**：`6c 08 <8> <2> <id1> <id2> <tail>` 里，`id1`/`id2` 是**真数据**（选中索引可能有两个），`2` 是自描述头。**不写 `2`，客户端就解析错位。**

## 五、诚实的部分

- `0x6b` 的 `tail = N-1` 是 159/159，**硬**。
- `0x6c` 的 `tail = 容量` 是**语义推断**（131/5/263 都是"选项/内容总数"），**中强硬**——但"为什么 `28/1` 有 131 和 5 两种容量"（不同模式？不同 DLC？）我没查清。
- **`28/1` 的 `tail=203/214/190/9/1` 那几个单例**，我归到"各局可选总数不同"，但**没有逐个对账**。

**我没有为了漂亮把 `0x6c` 的 tail 也叫"索引"或"长度"**——那是硬套。**分桶能分开的，就不要合并。**

## 六、方法论（可迁移）

1. **容器标签的尾部字段，先分桶再起名。** `(svc/task, tag, byteLen, bodyFirst, tail)` 五元组一分，语义分裂立刻可见。
2. **"容器只保证语法，不保证语义"是跨标签规律。** `0x13`（`09` 卷）和 `0x6b`/`0x6c`（本卷）是同一规律的两次确认。
3. **冗余自描述头是构造报文的地雷。** `body` 首 u32 不是数据，是"我里面有多少个"。手工构造必须先写它。
