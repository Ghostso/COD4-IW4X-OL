## §1 ★★★★ `0x7F1110` 的真实身份（推翻我方 229 卷）

```asm
0x7F1110  push ebp / mov ebp,esp
0x7F1113  mov  ecx, [0x84ABB08]        ; HTTPS 会话 A
0x7F1119  test ecx,ecx
0x7F111B  jne  0x7F1127
0x7F111D  mov  ecx, [0x84ABB14]        ; HTTPS 会话 B
0x7F1123  test ecx,ecx
0x7F1125  je   0x7F115B                ; 两个都空 → 直接返回
0x7F1127  push esi / call 0xB9A0F0     ; 取连接对象
0x7F112D  mov  ecx, [eax + 0x20]       ; 连接 id 高
0x7F1130  mov  edx, [ebp + 0x10]       ; 参数
0x7F1133  mov  eax, [eax + 0x24]       ; 连接 id 低
0x7F1137  cmp  [edx + 8], ecx          ; ★ 身份比对
0x7F113A  jne  0x7F115B                ; 不匹配 → 返回
0x7F113C  cmp  [edx + 0xC], eax
0x7F113F  jne  0x7F115B
0x7F1141  mov  ecx, [0x82E1400]
0x7F1147  mov  edx, [ecx]
0x7F1149  mov  eax, [edx + 0x38]
0x7F114C  call eax                     ; ★ 虚调用 #1（槽 0x38）
0x7F114E  mov  ecx, [0x82E1400]
0x7F1154  mov  edx, [ecx]
0x7F1156  mov  eax, [edx + 8]
0x7F1159  call eax                     ; ★ 虚调用 #2（槽 0x08）
0x7F115B  pop ebp
0x7F115C  ret  0x14                    ; ★★★ 短函数，ret 0x14
```

★★ **这完全符合子代理 244 卷的判断**：它是一个**HTTPS 连接身份匹配后的通知回调**（`ret 0x14` = 5 个栈参数），**不是 booking 分派器**。

★ **我方 229 卷**曾把 `0x7F1110` 说成「booking 的调用者入口」，依据是它读了 `[0x84ABB08]`/`[0x84ABB14]`（HTTPS 客户端）。**那两条读是真的，但结论错了 —— 读 HTTPS 会话不等于"处理 booking 应答"。**

★★ **这是 229 卷的一个"依据对、结论错"**：我用「入口读了 HTTPS 全局」推「它是 HTTPS booking 处理入口」，**没有读函数体看它到底做了什么**。

## §2 门 6 参3 的来源（关键待验项）

子代理称：门 6 的 `strcmp(参3, "mmbook accepted")` 的**参3 是 `0x7F3440` 填的动态应答串**。

**我方独立验证：机制成立，但子代理对 `0x7F3440` 的身份描述不准 —— 它是 strcmp 封装，不是应答解析器。**

### 门 6 参数的完整来源链（本卷独立取得）

```asm
; --- (1) 用 blob 读取器解析 HTTPS 应答（0x7F1400 内）---
0x7F147B  call 0xB76AF0                    ; blob 读取器
0x7F1484  mov  byte ptr [esp+0x13], al     ; 解析成功标志
0x7F14AE  call 0xB76AF0                    ; 再读一段
0x7F14D6  mov  eax, [esp+0x18]             ; 应答长度
0x7F14DA  mov  byte ptr [esp+eax+0xB0], 0  ; 栈缓冲置 NUL 结尾
0x7F14E2  lea  ebx, [esp+0xB0]             ; ebx = 应答文本指针
0x7F14E9  mov  dword ptr [esp+0x14], eax   ; 长度存 [esp+0x14]
0x7F14ED  cmp  dword ptr [esp+0x14], 0
0x7F14F2  jne  0x7F152F                    ; 非空 -> strcmp 分支

; --- (2) 传给 dwRoomImp vt+0x13C = 0x632680 ---
0x7F1562  push edx        ; 参5
0x7F1563  push ebx        ; 参4 = ★应答文本指针 [esp+0xB0]
0x7F1566  push edx (edi)  ; 参3
0x7F156A  push [ebp+0xc]  ; 参2
0x7F156E  push [ebp+8]    ; 参1
0x7F156F  call eax        ; vt+0x13C
```

### 已确认 / 修正

| 项 | 状态 |
|---|---|
| `0x7F1400` 内存在「栈缓冲 + NUL 结尾 + 长度」的应答文本 | ✅ `0x7F14DA` / `0x7F14E2` / `0x7F14E9` |
| 文本经 `0xB76AF0`（blob 读取器）从 HTTPS 应答解出 | ✅ `0x7F147B` / `0x7F14AE` |
| **`0x7F3440` 是 strcmp 封装，不是应答解析器** | ✅ `0x7F3440 mov ecx,0xDE0A0C` = `"HostUser"`，逐字符比对后拷贝 |
| `0xDE076C` = `"mmrsv"`（子代理提到的另一分支） | ✅ 已确认 |
| **门 6 参3 是不是应答字符串本身** | ⚠ **与子代理描述不同**：应答文本在**参4**(`ebx`)，参3 是 `edi` |

★★ **⇒ 子代理「参3 是 `0x7F3440` 填的动态应答串」这句不准确。** 准确表述：**应答文本在栈缓冲 `[esp+0xB0]`，作为第 4 个参数传给 `0x632680`；`0x7F3440` 是拿它跟 `"HostUser"` 比的 strcmp 封装。**

★★★ **但「客户端拿 HTTPS 应答文本去和常量比对，不回精确值就失败」这个机制性结论仍然成立** —— 只是本卷确认的比对常量是 `"HostUser"`，而 `"mmbook accepted"` 的比对在 `0x632680` 的门 6 里（227 卷已验）。**两处比对是两个不同的门，子代理把两者合并了。**
