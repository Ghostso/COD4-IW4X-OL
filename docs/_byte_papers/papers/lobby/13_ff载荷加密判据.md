# `.ff` 载荷是否加密 · 逐字节判据

> 对象：`IWff0100` 之后的载荷字节
> 证据：`tools/ff_payload_test.py`、`tools/ff_block_analysis.py`

---

## 1. 结论

**`.ff` 载荷是高强度加密的，不是压缩。**

七条独立判据同时指向同一结论。

---

## 2. 判据一：熵 = 7.9998

```
熵(first 1MB)         = 7.9998  (理论最大 8.0000)
每 4KB 块熵 min=7.945  max=7.965  avg=7.955
```

**压缩数据达不到这个水平。**
- zlib 压缩后的典型熵 ≈ 7.9~7.99
- **但这只是第一判据，必须结合下面六条**

---

## 3. 判据二：解密器全部失败

```
zlib.decompress(payload)         → Error -3: incorrect header
zlib.decompressobj(-15)(payload) → Error -3: invalid distance
```

**不是 zlib，也不是 raw deflate。**

---

## 4. 判据三：密文块零重复

```
16 字节块总数 : 262,143（4MB 载荷）
重复块数      : 0
```

**这是流密码 / CBC / CTR 的特征。**

如果是 **ECB 模式**，明文里的重复块会在密文里重复。
`common_gametype_mp.ff` 里必然有大量重复结构（填充、对齐、零区），
ECB 下会立刻暴露。

**零重复 ⇒ 不是 ECB。**

---

## 5. 判据四：16 列分布完全均匀

按 16 字节分组，比较每组第 k 字节的分布：

| 列 | 最高频字节占比 | distinct |
|---|---|---|
| 0 | 0.45% | 256 |
| 1 | 0.46% | 256 |
| … | … | 256 |
| 15 | 0.48% | 256 |

**均匀基线 = 1/256 = 0.39%**。
16 列全部在 0.44–0.50%，**没有任何一列偏斜**。

**ECB 会让某些列明显偏斜。这里没有。**

---

## 6. 判据五：跨块无相关性

测 `b[i]` 与 `b[i+B]` 相同字节的比例，B 取 256/512/1024/2048/4096/8192/16384：

| B | 相同字节比例 | 随机基线 |
|---|---|---|
| 256 | 0.33% | 0.39% |
| 1024 | 0.40% | 0.39% |
| 4096 | 0.39% | 0.39% |
| 16384 | 0.45% | 0.39% |

**全部贴近随机基线**——没有周期性块结构。

---

## 7. 判据六：0x00 与 0xFF 占比相等

```
0x00 : 0.39%
0xFF : 0.40%
```

**这是加密的标志，不是压缩的标志。**

- 压缩后：0x00 通常偏多（因为它压掉了冗余零）
- **加密后：所有 256 个值等概率**

0x00 和 0xFF 都是 0.39–0.40%（= 1/256），**说明是均匀随机映射**。

---

## 8. 判据七：4 字节重复词极少

```
4MB 载荷中不同的 4 字节词：262,132
其中有重复的：11
```

**几乎每个 4 字节都是唯一的。**

明文（即使压缩）会有大量重复的词。
**这是加密的直接表现。**

---

## 9. `IWff0100` 头里的线索

```
偏移 +0  : IWff0100
偏移 +8  : 0x000001CD = 461
偏移 +12 : 1            ← 这个 1 很可能是"已加密"标志
偏移 +16 : 0
偏移 +20 : 0x4FA1A400   （随机）
```

**`u32@+12 = 1`** 在所有检查过的文件里都是 1。
如果它是加密标志，那 0 就是明文。

（需要找一个 `=0` 的样本才能证实。）

---

## 10. 这意味着什么

**`common_mp.ff`（大厅本体）和 `common_gametype_*.ff`（模式）都是加密的。**

- 无法直接读取菜单定义
- 无法直接编辑模式
- 无法直接改按钮

**除非拿到密钥。**

---

## 11. 密钥可能在哪

按可信度排序：

1. **`IIPSVFS.dll` 的 `CCoderRWFilter`**（`CoderFilter.cpp`）
   - 它的 `[obj+4]` 是 16 字节表
   - 特征码 `2*size + 10`
   - 有 `QSPEDIKJHMNATOGC` 这样的键序表
2. **`IFS2.dll`**（`IFS2LOG` 日志 + `CreateDebugInterface`）
3. **运行时内存**（挂载后密钥在内存里）

---

## 12. 未能证明的部分

- 具体是 AES-128 还是别的算法（需要密钥才能验证）
- 是否是 CBC（需要看 IV）
- 密钥是固定还是每会话变化

**这些都需要拆 `CCoderRWFilter` 的实现才能定。**
