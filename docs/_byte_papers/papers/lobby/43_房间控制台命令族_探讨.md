# 房间控制台命令族 · 探讨：比改报文更底层的入口

> 对应：`lobby/43_房间控制台命令族.md`

## 一、意外发现

我在找 `mmstart` 模板时，模板后面紧跟的是：

```
room.create
room.list
room.join
room.leave
room.startgame
room.say
room.say2team
room.test
room.members
room.servers
room.changeteam
room.balance
room.jumpgame
room.changemap
```

**13 个房间命令 + 8 个 party 命令 + 4 个匹配命令。**

**这不是偶然相邻 —— 它们是同一个命令注册表。**

---

## 二、为什么这比报文更重要

**报文层（`11/*`、`6/*`）是"客户端发出什么"。**

**命令层是"客户端能做什么"。**

**如果这些命令可以从脚本调用，那就不需要构造报文 ——
直接调 `room.changemap` 就行。**

**这相当于从"模拟客户端"变成"指挥客户端"。**

---

## 三、`room.changemap` 的价值

**在语料里，我没有找到任何"换地图"的报文。**

**唯一的换地图方式是 `6/14 mmstart ... map xxx` —— 但那是在开始游戏时。**

**如果 `room.changemap` 存在且在房间内可用，
就能在"等待开局"时换地图。**

**这正是"完全自定义"需要的能力。**

---

## 四、`room.test` 是个信号

**命令表里有一个 `room.test`。**

**开发期命令留在了正式版里。**

**⇒ 这批命令不是"给玩家看的"，是"给开发者用的"。**

**⇒ 说明它们可能在某种条件下仍然可用。**

---

## 五、`MatchMakingJoin` 的 12 个字段

```
MatchMakingJoin|%s|%u|%d|%llu|%llu|%llu|%d|%d|%d|%d|%d|%d|%d
```

**我开始数：`%s` + `%u` + `%d` + `%llu×3` + `%d×6` = 12。**

**而 `mmstart` 里有 6 个数字 dvar。**

**数量对上了。**

**⇒ 那 6 个数字（2486/2489/2500/2574/3265/2810）
很可能就是这 6 个 `%d` 的值，被同时写进了日志和命令。**

**这给"它们是什么"提供了一个验证路径：
如果能在日志里找到 `MatchMakingJoin|...` 的完整行，
就能看到这 6 个数在上下文里的位置。**

## 七、一个具体的可行动项

**`room.*` 命令如果能在 UI 脚本层调用（通过 `exec`），
就可以：

```
exec "room.changemap mp_nuked"
exec "room.startgame"
```

**这需要：**

1. UI 脚本的执行能力（`0x00DAA400` 表里的 `exec`）
2. 命令的参数格式

**第 1 条项目里已有（`memory: codol-developer-interfaces-inventory`）。
第 2 条需要反汇编命令注册点。**

## 八、方法论收获

> **找 A 的时候，看看 A 旁边有什么。**

我找 `mmstart` 的模板串，
结果在它旁边找到了整个命令家族。

**字符串表是连续存放的，相邻的往往同属一个子系统。**

**这是"读字符串表"相比"按名字搜"的优势：
后者只能找到你想到的东西，前者能看到结构。**
