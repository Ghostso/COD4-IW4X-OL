# ★★★★ `.ff` 解密链全图：从 RSA 私钥到 AES 块解密

> **这是"谁来解密 `.ff`"的完整答案**
> 证据：`client_runtime.bin` 反汇编 + 已提取的 RSA 私钥
> 关联：`lobby/26`（私钥）、`lobby/27`（派生）、`lobby/28`（rsa_decrypt_key）

---

## 1. 三个函数，一条链

```
0x483b40   初始化（zlib + AES 上下文）
0x483a50     ★ AES 密钥派生（RSA 解密）
0x4834f0     ★ AES 块解密（消费端）
```

---

## 2. `0x4834f0`：真正的解密循环

### 2.1 缓冲结构

```
0x1c4f730   已填充字节数
0x1c4f734   0x2000 字节缓冲（8192）
0x1c4f6f4   某种状态标志
```

**块大小固定 0x2000（8192 字节）。**

### 2.2 填充

```
0x483520  cmp ecx, 0x2000            ; 满了吗
0x483526  jae 0x48399d
0x48352c  mov esi, [edi+4]           ; 可用输入
0x483534  sub eax, ecx               ; 剩余空间
0x483540  lea ecx, [ecx+0x1c4f734]   ; 写入位置
0x483547  call 0xc427f0              ; memcpy
0x483551  add [edi+8], esi           ; 推进读取指针
0x48355b  add [0x1c4f730], esi       ; 累计字节
```

### 2.3 ★ 满块后解密

```
0x483563  cmp eax, 0x2000
0x483568  jb 0x483a10                ; 未满，回去继续填
0x48356e  mov ecx, [0x1c4f6f4]       ; 状态
0x483574  push 0x1c2b2b8             ; ★ 输出结构
0x483579  push 0x10                  ; ★ 16 字节
0x48357b  test ecx, ecx
0x48357d  jne 0x483787
0x483583  push 0x1c51734             ; ★★ AES 密钥
0x483588  call 0xbc5f60              ; ★ AES 初始化（key → ctx）
0x48358d  add esp, 0xc
0x483590  push 0x1c2b2b8             ; 输出
0x483595  push 0x2000                ; 长度 8192
0x48359a  push 0x1c4f734             ; 输入（密文）
0x48359f  push 0x1c4f734             ; 输出（原地）
0x4835a4  call 0xbc8840              ; ★ 块解密
0x4835a9  add esp, 0x10
```

**这是核心：**

```
每满 8192 字节：
  1. 用全局密钥 0x1c51734（16B）初始化 AES ctx
  2. 对 0x1c4f734 的 8192 字节原地解密
```

### 2.4 `0xbc5f60` 的身份

```
0xbc5f64  mov esi, [ebp+0x10]      ; 第 3 参数 = cipher 描述符
0xbc5f67  mov eax, [esi]
0xbc5f6a  call 0xbca340            ; cipher_is_valid
0xbc5f76  mov eax, [ebp+0xc]       ; 第 2 参数
0xbc5f79  cmp eax, [esi+4]         ; 与描述符的块长比较
0xbc5f87  mov edi, [ebp+8]         ; 第 1 参数
0xbc5f8b  lea ecx, [esi+0x14]
0xbc5f90  call 0xc427f0            ; memcpy(密钥 → [esi+0x14])
0xbc5fa7  mov ecx, [edx+0xe8786c]  ; 描述符 +0x1c 的函数
0xbc5fb6  call ecx                 ; ★ set_key
```

**结论：`0xbc5f60(ctx, len, descriptor)` = 把密钥拷进 ctx 并调度。**

**调用点传的 `0x10`（16 字节）与 AES-128 密钥长度一致。**

## 3. `0x483a50`：密钥从 RSA 解密得到

（详见 `lobby/27`、`lobby/28`）

```
RSA私钥(0xdac4b0, 1187B DER)
   ↓ rsa_decrypt_key_ex(密文=[ebp-0x130], 256B, pad=PKCS1v15, hash=sha256)
明文 [ebp-0x2c]（≤40B）
   ↓ cipher_setup / 提取
AES 密钥 16B
   ↓ memcpy
全局 0x1c51734
```

---

## 4. 完整解密流程

```
.ifs 文件
  ↓ 176 字节头 + 清单（明文）
  ↓ 扇区数据
8192 字节密文块
  ↓ AES-128 解密（密钥 = 0x1c51734）
8192 字节明文（可能是 zlib 压缩）
  ↓ zlib inflate（0x791eb0 = inflateInit2）
.ff 内容
```

**注意：`0x483b40` 里同时初始化了 zlib（`0x791eb0`），
所以"先 AES 解密，再 zlib 解压"是完整的两步。**

## 6. 仍缺的一环：那 256 字节密文

RSA 解密需要 256 字节密文（`[ebp-0x130]`）。

**它来自哪里，还没确定。**

两种可能：

1. **从 `.ff` 或 `.ifs` 文件的某个固定位置读**（可离线复算）
2. **服务端下发**（需要抓会话包）

**但即使不知道密文来源，我们已经有私钥 —— 
只要能拿到那 256 字节，就能算出 AES 密钥。**
