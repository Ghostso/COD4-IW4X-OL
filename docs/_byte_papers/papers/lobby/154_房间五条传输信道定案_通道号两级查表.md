# 154 · 房间侧五条传输信道定案：`push imm` 不是「类型号」而是**传输通道号**，映射表 `0xE4E20C → 0xE69CE0`

> 卷次：154（lobby 线路）
> 前置：153（本卷的「未闭合项 1」就是本卷要回答的问题）
> 关联：139（五层注册门 `0x7E7910`）、147（消息泵）、152（房间子系统）

---

## 一、问题回顾（153 卷遗留）

153 卷结尾写：

> 「`0x7E7xxx` 六函数（`0x7E7EE0` push `0x13`=P2PInfo 等）直接调 `0x7FAA20`，与两建包器的**信道分工**未逐条对账。」

本卷对账完成，并**更正 153 卷一个误读**：`push 0x13` **不是**「传输 type = 19 = P2PInfo」。它是**通道下标**，进 `[0xE4E20C + idx*8]` 查「通道类」，再进 `[0xE69CE0 + class*0x10]` 取该类的**超时/重试四元组**。

## 二、漏斗 `0x7FAA20` 的参数语义（逐指令）

```asm
0x7FAA20  push ebp / mov ebp,esp / and esp,0xFFFFFFF8
0x7FAA26  mov edx, [ebp+0x10]        ; 第 2 个栈参
0x7FAA29  push 0 / push 0
0x7FAA2D  push eax                   ; 寄存器参数 eax
0x7FAA2E  push ecx                   ; 寄存器参数 ecx
0x7FAA2F  push 0 / push 0
0x7FAA33  push 0x8435D0              ; ★ 完成回调 = 空桩 (C3)
0x7FAA38  push edx
0x7FAA39  push ecx
0x7FAA3A  mov ecx, [ebp+0xc]
0x7FAA3D  mov eax, esp
0x7FAA3F  mov [eax], ecx             ; 第 3 个栈参（引用计数智能指针）
0x7FAA52  mov edx, [ebp+8]           ; ★★★ 第 1 个栈参 = 通道号
0x7FAA55  push edx
0x7FAA56  call 0x7FA800
```

**调用侧形态**（`0x7E82XX`）：

```asm
0x7E82...  push <通道号>     ; 例：0x16
0x7E82BE   mov eax, <回调/对象>
0x7E82C0   mov ecx, <this>
0x7E82C2   call 0x7FAA20
```

⇒ **`[ebp+8]` = 通道号**。这是全卷的关键：**`push imm32` 的值域不是消息类型，是通道号。**

## 三、`0x7FA800`：通道号 → 类 → 参数，两级查表

```asm
0x7FA83B  mov ecx, dword ptr [ebp+8]        ; = 通道号
0x7FA83E  mov eax, dword ptr [ecx*8 + 0xE4E20C]   ; ★ 一级表：通道号 → 类
0x7FA845  shl eax, 4                        ; × 0x10
0x7FA848  add eax, 0xE69CE0                 ; ★ 二级表：类 → 参数行
0x7FA84D  mov esi, 0xE56FFE0                ; 通道槽表（步进 0x50）
0x7FA852  cmp dword ptr [esi], 0 / je 0x7FA920   ; 找空槽
0x7FA85B  add esi, 0x50
0x7FA85E  cmp esi, 0xE5713E0                ; 表尾 ⇒ (0xE5713E0-0xE56FFE0)/0x50 = 64 槽
```

一级表 `0xE4E20C`（stride **8**，`u32` 低半 = 类）：

一级表 `0xE4E20C`（stride **8**，`u32` 低半 = 类；实测共 **139 项**，类分布 `0:108 / 3:22 / 4:5 / 1:3 / 2:1`）：

| 通道 | 类 | 第二字段 |
|---|---|---|
| 0x01 | 0 | 13 |
| 0x02 | **1** | 13 |
| 0x03 | **1** | 13 |
| 0x04..0x0F | 0 | 5 |
| 0x10..0x16 | 0 | 10 |
| 0x17..0x1A | 0 | 12 |
| 0x1B..0x20 | 0 | 7 |
| 0x21 | 0 | 10 |
| 0x22..0x26 | 0 | 9 |
| … | | |
| 0x56..0x5F | **3 / 4** | 8 |

> ★ **只有 `0x02`/`0x03` 用类 1（25000ms + 重试 10 次）**；`0x56/0x57/0x5C..0x5F` 类 3，`0x58..0x5B` 类 4（60000ms + 重试 10）。房间五通道 `0x13..0x17` **全是类 0**（25000ms + 重试 5）。

二级表 `0xE69CE0`（stride **0x10**，四 dword，**只有 5 行，类 0..4**）：

| 类 | 字段1 | 字段2 | 字段3 | 字段4 |
|---|---|---|---|---|
| 0 | `0x61A8`(25000) | `0x61A8`(25000) | `0x7D0`(2000) | 5 |
| 1 | `0x61A8` | `0x61A8` | `0x7D0` | **10** |
| 2 | `0x61A8` | `0x61A8` | `0x7D0` | 5 |
| 3 | `0xEA60`(60000) | `0xEA60` | `0x7D0` | 5 |
| 4 | `0xEA60` | `0xEA60` | `0x7D0` | **10** |

⇒ **四元组 = {发超时 ms, 收超时 ms, 重发间隔 ms, 重试次数}**。类 1/4 是「重试 10 次」的**可靠通道**；类 0/2/3 是「重试 5 次」。

> **类值域 0..4 有硬证**：`0x7FA5CF cmp eax,4 / ja 0x7FA570`（超界即跳过）。再加一级表实测最大值 = 4（穷举 139 项），二者互证。
>
> ⚠ **`0xE69D30` 不是本表第 6 行**（本文早期草稿误列为「类 5 = 四个指针」）。它是**另一张哈希表结构的起点**，由 `0xC95B50` 初始化（`mov dword [0xE69D30],0xDE1404` 等四条 + `0xE69F84` 计数 + `0xE69D50` 桶数组）。不要把它并进来。

> 这两个常数 `0x61A8`(25000ms) 与 `0xEA60`(60000ms) 是**唯一**区分「普通 / 长超时」的量纲证据。

## 四、房间侧五条通道（对账 153 卷的「六函数」）

| 通道 | 发送函数 | 段构建器 | 完成回调 | 调用者 |
|---|---|---|---|---|
| **0x13** | `0x7E7EE0` | `0xB8FAB0` | `0x7E7FA0` | `0x62DF84`（`0x62DEE0` 建连接后） |
| **0x14** | `0x7E7FD0` | `0xB8EFB0` | `0x7E8090` | `0x633EEC`（`0x633E??` 房间状态） |
| **0x15** | `0x7E8120` | `0xB8E9D0` | `0x7E81D0` | `0x629BF4`/`0x629D28`/`0x629DFD`/`0x629EF5`/`0x62F539`/`0x633E1D` |
| **0x16** | `0x7E8240` | `0xB8ED40`（5 段） | `0x7E8210` | `0x62B800`/`0x62C45A`/`0x633839` |
| **0x16** | `0x7E8300` | `0xB8EE70`（6 段） | `0x7E8210` | `0x62C93D`（**唯一**） |
| **0x17** | `0x7E83D0` | `0xB8EAE0` | **`0x8435D0`（空桩）** | `0x6384BC`（`0x6384A0`） |

**五条通道 = 0x13 / 0x14 / 0x15 / 0x16 / 0x17。** 其中 **0x16 有两个建包器**（5 段与 6 段），这解释了 152/153 卷「为什么会有两个孪生建包器」——**它们是同一条通道上的「短包 / 长包」两个变体**，而不是两条通道。

> **更正 153 卷**：「`0x7E8240` 与 `0x7E8300` 是两条入口」应精确为：**同一通道 0x16 的两个建包器**，区别只在段数（5 vs 6），共用同一完成回调 `0x7E8210`。

### 4.1 逐条结构证据

**0x13 = `0x7E7EE0`**（房间加入 / 成员表上报）：

```asm
0x7E7EE0  call 0x7E7D30                  ; ★ 清表：0x2580 字节 + 100 项 × 0x60 + 0x30 头
0x7E7EF3  srpc 存在 / state==2 / session!=0
0x7E7F1E  push [ebp+0xC] / push [ebp+8]
0x7E7F2C  call 0xB8FAB0                  ; 建包
0x7E7F38  push 0x7E7FA0                  ; 完成回调
0x7E7F45  mov edi, 0x633FE0              ; ★ 失败回退
0x7E7F58  push 0x13                      ; ★ 通道 0x13
0x7E7F5E  call 0x7FAA20
```

`0x7E7D30` 清 **100 项 × 0x60** 成员槽 + **0x30** 字节头 —— 与 153 卷 `0x62ACD0` 的「成员记录步进 **0x60**、基址 `+0x40`」**完全一致**，互为印证。

**0x14 = `0x7E7FD0`**：

```asm
0x7E8002  mov edx,[esi+0x14] / lea ecx,[esi+0x38] / push 0x64   ; ★ 100 项 × (esi+0x38)
0x7E8017  call 0xB8EFB0
0x7E8024  push 0x7E8090 / mov edi, 0x633D90
0x7E8045  push 0x14                      ; ★ 通道 0x14
0x7E804B  call 0x7FAA20
```

**0x15 = `0x7E8120`**（六个调用者，房间状态机族）：

```asm
0x7E815D  call 0xB8E9D0
0x7E816A  push 0x7E81D0 / push [ebp+8]
0x7E8189  push 0x15                      ; ★ 通道 0x15
0x7E818D  call 0x7FAA20
```

**0x17 = `0x7E83D0`**（唯一用**空回调**的一条）：

```asm
0x7E8415  call 0xB8EAE0
0x7E8427  push 0x8435D0                  ; ★ 空桩，无回调
0x7E8444  push 0x17                      ; ★ 通道 0x17
0x7E844A  call 0x7FAA20
```

> **判据**：**0x17 是「发了不管」的通道**（fire-and-forget）。其余四条都有真实完成回调（0x7E7FA0/0x7E8090/0x7E81D0/0x7E8210）。

## 五、通道槽：`0xE56FFE0 .. 0xE5713E0`，64 槽 × 0x50

```asm
0x7FA84D  mov esi, 0xE56FFE0
0x7FA852  cmp dword ptr [esi], 0 / je 0x7FA920    ; 找第一个空槽
0x7FA85B  add esi, 0x50
0x7FA85E  cmp esi, 0xE5713E0 / jl 0x7FA852
0x7FA866  ... 满槽 ⇒ 走 0x7FA920
0x7FA8A8  call 0x7FA640                            ; 空槽 ⇒ 填槽 + 入队
```

`(0xE5713E0 - 0xE56FFE0) / 0x50 = 64`。**64 个同时挂起的发送槽**。

### 5.1 槽记录结构（`0x7FA640` 填充）

```asm
0x7FA653  cmp dword ptr [0x849b5cc], 0    ; 一次性取 boot 时刻
0x7FA669  lea ecx,[ebp-8] / call [0xca812c]  ; QueryPerformanceCounter
0x7FA693  call edi (=0xca84c8)            ; 取当前 tick
0x7FA695  sub eax,[0x81aa118]             ; now - boot
0x7FA69E  mov [esi+8], eax                ; +0x08 = 相对启动时刻（ms）
0x7FA6A5  add eax, 0x3A98                 ; +0x3A98 = 15000
0x7FA6A9  mov [esi+0xC], eax              ; +0x0C = 截止 = now + 15000ms
0x7FA6AB  mov edx,[ebp+0x28] / mov [esi+0x14],edx
0x7FA6B2  mov [esi+0x18], ...             ; 标志位
0x7FA6C0  mov [esi+0x20], ...
0x7FA6D4.. 拷贝 [ebp+0xC] 智能指针 → esi+0x28
```

⇒ **每个待发槽自带 15 秒硬截止**（`0x3A98`）。这是「发包超时」这一行为的静态根据。

## 六、会话层钩子（`0x7FA800` 开头）

```asm
0x7FA80F  call dword ptr [0xca8164]       ; GetCurrentThreadId
0x7FA815  cmp eax, [0x7886e68] / je 0x7FA83B
0x7FA81D  mov eax, [0x7644694]            ; ★ 会话槽索引
0x7FA826  imul eax, eax, 0x114            ; ★ 会话结构 0x114 字节
0x7FA82C  mov eax, [eax+0x7659F88]        ; ★ 会话对象表基址
0x7FA836  mov eax, [edx+0x24] / call eax  ; ★ vt[0x24] = 发送前钩子
```

**只有「当前线程 ≠ 主线程」时才调 `vt[0x24]`**（`je 0x7FA83B` 跳过）⇒ 这是一个**跨线程唤醒**：网络线程发消息时先踢主线程一次。

`0x7659F88 + idx*0x114` 是**会话对象表**（不是 153 卷写的「单会话」）；索引来自 `[0x7644694]`，即**当前活动会话槽**。

## 七、全镜像漏斗分布（106 个调用点）

实测 `call 0x7FAA20` 共 **106 处**，`push imm` 值域覆盖 `0x01..0xA7` 共 80+ 个通道号。

| 区域 | 用途 |
|---|---|
| `0x401xxx..0x4Bxxxx` | 战斗/引擎侧（大量） |
| `0x63Exxx..0x642xxx` | **遥测**（129 卷 65 个日志点所在区） |
| `0x7E7xxx..0x7E84xx` | ★ **房间五通道（本卷）** |
| `0x7EFxxx..0x81xxxx` | 大厅/Demonware 服务 |

⇒ **`0x7FAA20` 是全客户端唯一的 UDP 发送出口**（106 个调用点，覆盖战斗、遥测、房间、大厅）。这比 153 卷「≈110」的估计精确到 **106**。

## 九、未闭合

1. `0xE69D30` 是**另一张哈希表**（`0xC95B50` 初始化：四键指针 `0xDE1404/0xDE1420/0xDE1410/0xDE1428` + 计数 `0xE69F84` + 桶 `0xE69D50`），与通道类表无关。其键值语义未解。
2. 通道号 `0x02/0x03` 用类 1（25000ms + 重试 **10**）—— 这两个是**高可靠通道**（疑似 Demonware 主信道），本卷未追它们是哪条服务。
3. `0x7FA640` 的 `+0x38..+0x40` 段（`[ebp+0x18]`/`[ebp+0x1C]`/`[ebp+0x20]`/`[ebp+0x24]`）语义未解。
4. ★ `0x7FA560` = **通道参数运行时覆盖加载器**：读 dvar `dw_task_timing_overrides`（`0xDE1190`）字符串，格式 `"%d,%d,%d,%d"`（`0xDE11AC`），写回 `0xE69CE0 + cls*0x10`（`0x7FA604/0x7FA60F/0x7FA61A/0x7FA628` 四个字段）。**⇒ 上表所有超时/重试值都是默认值，可被 dvar 覆盖。** 该 dvar 的实际取值未查。

## 十、方法论

1. **`push imm32` 先当「下标」试，不要先当「类型」**：153 卷直接把它读成传输 type 就错了。破解方式 = 沿 `mov reg,[idx*stride + table]` 找到 `table`，读 stride 与相邻行。
2. **两级查表（index → class → row）在 Demonware 里是常态**：`0xE4E20C`（stride 8）→ `0xE69CE0`（stride 0x10）。看到 `shl eax,4` + `add eax,基址` 就要想到「类 → 参数行」。
3. **完成回调是不是 `0x8435D0`，直接判「有无确认」**：0x17 用它 ⇒ fire-and-forget；其余用它以外的 ⇒ 有 ACK 路径。
4. **超时常数是最好的量纲证据**：`0x61A8`=25000、`0xEA60`=60000、`0x3A98`=15000、`0x7D0`=2000。数字对不上 ms 就别硬解释。
5. **「同一函数名两个地址」先查回调是否相同**：`0x7E8240`/`0x7E8300` 共用 `0x7E8210` ⇒ 同通道的两个变体，不是两条通路。
