## 1. 函数结构

```asm
0x621810  push ebp / mov ebp,esp
0x621813  mov eax, 0x2024 / call 0xc43280   ; 分配栈 0x2024（8KB+）
0x62181d  ... 栈保护 cookie
0x621830  push 0x81a5558

0x621837  call 0x643300                     ; ★ 取会话对象
```

**⇒ `0x621ac0` 写入的 `edi` **恒为 0**。**

**⇒ 那条路径实际上是"模式复位到 0"，不是"设为界面态"。**

## 3. ★ 完整的模式写入逻辑

| 条件 | 写入 | 含义 |
|---|---|---|
| `[0xe59d20] == 3` | **4** | 进大厅 |
| `[0xe59d20] == 5` | **6** | 进游戏 |
| 错误码 -1/-2/-3 | **0** | 复位 |
| `0x6212c0(bool)` | **3 / 5** | 设置预备态 |

**⇒ `[0xe59d20]` 的四个可能值：0 / 3 / 4 / 5 / 6。**

---

## 4. ★★ 关键：`0x6212c0` 是唯一的"3/5"来源

**而 `0x6212c0` 的唯一业务调用者是 `0x7e9913`（大厅初始化）。**

**⇒ 要进大厅，必须先执行 `0x7e98f0`（大厅初始化）。**

**⇒ 而 `0x7e98f0` 需要 `[0x849ba30] == 3`。**

**⇒ 循环仍然存在！**

---

## 5. 那到底怎么启动的

**这里必须重新审视 `lobby/51` 的观察。**

**`lobby/51` 我看到：**

```
0x808261  cmp [0x849ba30], 3
0x808268  jne 0x80852c
```

**而 `0x80852c` 是 `pop/ret`（直接返回）。**

**⇒ 如果 `[0x849ba30] != 3`，`0x808240` 直接返回，
不会调 `0x808650`。**

**⇒ 但 `0x808240` 是主循环里每帧调的。**

**⇒ 每帧都返回，说明永远不进大厅。**

---

## 6. 死循环的真相

**所以确实存在一个**启动死结**：**

```
[0x849ba30] 需要 == 3        才执行初始化
        ↑
初始化（0x7e98f0）里的 0x6212c0(1) 才设置 [0xe59d20] = 5
        ↑
[0xe59d20] 需要是 3 或 5，0x62186b 才能推到 4/6
        ↑
[0x622220] 需要 [0xe59d20] ∈ {4,6}
        ↑
状态 7 需要它
        ↑
[0x849ba34] = 8 → 3
        ↑
[0x849ba30] = 3
```

**⇒ 完美循环。**

---

## 7. 唯一的出路

**一定有某个地方能**绕过**这个循环。**

**三个候选：**

1. **`0x849ba30` 有别的写入路径**（不只 `0x7ef0f6` 同步）
2. **`0x7e98f0` 有别的调用者**（不只 `0x808650`）
3. **`[0xe59d20]` 在启动早期由别处设成 4**
   （例如命令行 `+set`、配置文件、或另一种初始化）

**第 3 个最可能。**

**因为 `memory: codol-iips-must-be-enabled` 说改 `enable_iips` 就能进大厅 ——
说明 `[0xe59d20]` 或它的上游可以被配置改变。**
