## 一、你这一问戳破的，是一个 15 卷的思维定式

我上一轮说：

> 「服务端回包一次都没抓到 —— 纯静态逆向永远闭不了，必须抓包。」

**你回答：「服务端是我们写的，所以大厅服务器的回包你不知道吗」**

这一句让我意识到：**我根本没去看 `lobby_server.py`。**

我当时的心理活动（回看自己）：我在做「客户端逆向」这个任务，所以把「协议的另一半」自动归类成「外部世界」。而实际上那一半是我方源码，**76 KB，一直躺在 `REF_LOBBY_KIT\` 里**。

### 这个错误的形状

它不是我算错了什么，是**任务框架设错了**：

- 逆向一个买来的/下载的客户端 ⇒ 服务端回包确实是外部未知，需要抓包。
- **但我们同时拥有客户端和服务端** ⇒ 协议两端都是自己的，没有「外部」。

我连续 15 卷在做前者，条件反射地把后者也当成了前者。

> **★ 教训：每次说「需要抓包才能知道」之前，先问一句「这一方是不是我们自己写的」。**
> 如果是自己写的，「不知道」意味着「我没去读自己的代码」，而不是「样本不够」。

## 二、但读完源码，我发现一个更严重的问题

我本来只想把「服务端回包」补进台账，写完就完事。

结果一 grep，**60 处 `ol-mod` / `三方` / `照抄`。**

而 AGENTS.md 第一条强制规则就写着：

> **ol-mod is NOT authoritative.** Never copy its constants, field layouts, or protocol values.
> It targets a different build: "3.3.3.3 ends a server message with 6; **OLfinal** ends it with 5".

**这份服务端恰恰是在大规模照抄它。**

### 更刺的是：源码自己记着三次翻车

| 位置 | 翻车现象 |
|---|---|
| 商城 SKU 页 | 「客户端反序列化不了的应答会让**整个 marketplace 服务死掉**（变灰且本会话不再恢复）」 |
| 11/4 频道回显 | 「推了客户端没发过的 16B 常量 → **同秒 reset**，4 次复现」 |
| 商城购买 | 「我们多回了一个余额对象 → 客户端当别的东西解析 → **点了没反应**」 |

**三次都是「照抄兄弟作品字段序」直接导致的。**

而 AGENTS.md 那句「ol-mod 非权威」，正是为了防这个。**规则写在最前面，代码里却抄了 60 处。**

## 三、「有源码」和「是对的」是两件事

这是我这一轮最重要的区分：

| | 解决什么 | 靠什么 |
|---|---|---|
| **有源码** | 知道「服务端发了什么字节」 | 读代码 |
| **对齐客户端** | 知道「这些字节对不对」 | 读客户端解码器，逐字段对 |

**我上一轮把「没有台账」当成了问题。其实台账一直有（就是源码）。真正的问题是：这些台账上的数字，对不对？**

而「对不对」的判据，AGENTS.md 也给了：**本地逆向 > IW4X > CoD4X > 其他**。
- 服务端分支如果是「照抄三方」⇒ **最低等级，不可信**。
- 要升到「可信」，必须**在客户端镜像里找到对应解码器，逐字段对上**。

**⇒ 这件事纯静态可做。** 客户端就在我们手上，解码器就在镜像里。

## 四、一个具体的好消息，和一个坏消息

`21/5 findSessions` 这条最关键的分支，**不是照抄的**：

```python
_pl = _vals[2] if len(_vals) >= 3 else None      # 从客户端请求里解析 playlist
is_pve = _pl in PVE_PLAYLIST_IDS
objs = [cc.build_mission_session_object(not is_pve, playlist=_pl, ...)]
```

它**回填客户端发来的 playlist**，而不是写死。这是对的做法。

**好消息**：157 卷刚把 116 条 playlist 明文（含中文名）全解出来，这条分支现在有 ground truth 可对账了。

**坏消息**：我对了一下，直接炸出一个硬缺陷。

```python
PVE_PLAYLIST_IDS = {10}       # lobby_server.py:283
```

**只有一个元素。**

而 157 卷的明文里，PvE 家族至少有 **22 条**：

```
23类(生存)：10 112 86 113 / 12 116 90 117 / 109 155
Evacuation：7 9 17
Survival Ambush：91
20类(丧尸)：69 130 157 135 140 143
26类(丧尸生存)：151 147
28类：175
```

**⇒ 服务端只把 `10` 当 PvE，其余 21+ 条全部走「靶场」分支（`GameType=0x1000007, MaxPlayers=1`）。**

这就是「选剧情任务进不去」的真正根因 —— **不是网络问题，不是握手问题，是服务端把一个 22 条的集合写成了 1 条。**

源码注释写得很清楚：

> 「★ 2026-10-07: playlist=10 是客户端实测的 PvE 剧情任务入口。」

**当时只实测到一条，就写成了集合。** 而 157 卷的明文一直在那儿，随时能补全。

### 这一条最能说明本卷的意义

我 159 卷说「服务端应答不是黑箱」。**对，但正因为不是黑箱，它的错误才可被静态查出。**

- 如果它是外部黑箱 ⇒ 只能抓包试错。
- 它是我们自己的代码 ⇒ **把客户端明文拿来一对，缺陷当场现形。**

**⇒ 「有源码」的真正价值，不是「知道了」，而是「可对账」。**
