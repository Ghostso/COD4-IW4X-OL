# 112 · 探讨：两个魔数，两种命运

> 配套：[112_魔数AB定名.md](112_魔数AB定名.md)

---

## 一、A 和 B 一开始被我当成"同一类东西"，这是错的

前面几卷我把 `0xD692ADAB`（A）和 `0x8D51E398`（B）并列写成"两魔数、语义未定"，
因为它们都出现在 `21/1` / `21/12` 里、都是恒定 i32、都不像 ID。**并列是错的**——
这一卷证明它们**命运完全相反**：

- A 是 **build 派生**的 query criterion（3.3.3.3 是 `0xD6F01F9B`，3.19 是 `0xD692ADAB`）。
- B 是 **跨 build 稳定**的协议常量（两个 build 都是 `0x8D51E398`）。

把这两个放进同一行表格，本身就是一种认知偷懒。**"都是魔数"不等于"同一类魔数"**。

## 二、权威参照救了我一次

如果只靠自己语料，我最多能说"A 是恒定 i32、位置在 playlist 后面"，永远推不出"query criterion"这个名字。
是 `SessionDescriptor.cs:147` 那行 `// 4 query criterion` 直接给了答案。

这里有个微妙之处：按 AGENTS.md 的可信度分级，**本地逆向 > IW4X > CoD4X > 其它**，ol-mod 是"其它"、
最低级。但这次 `SessionDescriptor.cs` 不是 ol-mod——它是**我们自己的战斗服源码**，而且它的字节来自
`REF_LOBBY_KIT/codol_crypto.py`（本地冻结参考实现）。所以我用它是**合规**的：它本质是"我们自己的
本地逆向产物的下游"。

而 ol-mod 的 `CodolGameplayProbeTests.py` 我只用来**做交叉验证**（确认 B 跨 build 稳定、确认 A 位置），
**没有**把它的 `0xD6F01F9B` 抄进我们的实现。这正是 AGENTS.md 要求的：ol-mod 只做"同族参考"，不抄常量。
**结果刚好证明这条规矩是对的**——如果抄了 `0xD6F01F9B`，我们 3.19 客户端会直接拒收。

## 三、"高 16 位相同、低 16 位不同"这个细节

A 的两个值 `0xD6F01F9B` 和 `0xD692ADAB`，高 16 位都是 `0xD6`。这不是巧合。
它暗示 query criterion 的编码是"**`0xD6` 前缀 + 某 16 位 build/协议标识**"。`0xD6` 可能是
Demonware matchmaking 的一个命名空间前缀，后 16 位是版本区分。

如果这个推测成立，那我们可以**反推**：不同 CODOL build 的 query criterion 应该都在 `0xD6xxxx` 里。
这是一个可验证的预测——将来若拿到别的 build 抓包，看 criterion 是不是 `0xD6` 开头，就能验证或推翻。
**把推测写成可证伪的预测**，比写成"可能是版本号"有用得多。

## 四、B 我为什么停在"未定"而不硬编一个名字

B 的位置很确定（会话描述符尾、`0xDEADC0DE` 之前、ID 之后），跨 build 稳定，
但它到底是"security key 的一半"、"会话类型标志"还是"某个固定 GUID"，我没有证据。
我查了 72 种哈希组合全落空，说明它不是"派生值"，是"独立常量"。

我本可以猜一个名字（比如"session magic"），但那样就违反了前几卷反复强调的纪律：
**假的定名比诚实的未定危害大**。B 的正确定名需要拿到客户端里读这个字段的代码，或者找到
它参与比较的地方。目前 `magic_bin.py` 在客户端 EXE 里搜 `abad92d6`/`98e3518d` 都是 0 命中——
说明这两个常量**不是以立即数形式硬编码在 EXE 里**，而是**运行时从服务端报文读进来的**。
这本身就是个有价值的结论：**A、B 是服务端下发的值，客户端只是回显/转发**。

## 五、这卷最硬的收获：一个"不能抄"的活教材

前面几卷反复说"ol-mod 不是 3.19、不能抄常量"，但都是原则性的。这一卷是**具体的、可验证的**：
ol-mod 的 `0xD6F01F9B` 和我们的 `0xD692ADAB` 在**同一个位置、同一个语义、不同的值**。
这就是"照抄会翻车"的活标本。

我把这个写进结论，不是为了自我表扬，而是因为它是一颗**随时会被人踩的地雷**——
下一个人如果看到 ol-mod 有 `0xD6F01F9B` 就抄过来，会浪费一整个 run 去查"为什么客户端不返回会话"。
这颗雷现在被拆了。

## 六、下一步

B 的确切语义需要**客户端读侧代码**。可行路径：
1. 在客户端 EXE 里搜 `0x8D51E398` 的**读取/比较点**（不是立即数，而是从报文偏移读出的位置）——难度高。
2. 从 `21/1` 的两个变体（self vs other-player，见 `p21_blobs.py`）入手：B 只出现在 self 变体里，
   也许它和"自己 vs 别人"的会话描述有关。

A 已经可以关掉（query criterion，build 派生，用法明确）。B 留一个诚实的"位置已定、名字未定"，
标记在 112 §6 状态表里，下一卷继续。
