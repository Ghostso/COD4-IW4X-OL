## 1. `0x622220()` 的真相

```asm
0x622220  mov eax, [0xe59d20]      ; ★★★ 就是 lobby/55 的模式门
0x622225  cmp eax, 4
0x622228  je  0x622232
0x62222a  cmp eax, 6
0x62222d  je  0x622232
0x62222f  xor eax, eax / ret        ; 返回 0
0x622232  mov eax, 1 / ret          ; 返回 1
```

**⇒ `0x622220()` = `[0xe59d20] ∈ {4, 6}`。**

**⇒ 和 `lobby/55` 里发现的"模式门"是**同一个变量**。**

**⇒ 整条链的两端接上了。**

## 2. 状态 7 的完整分支（`0x7ef357`）

```asm
0x7ef357  cmp eax, 3                ; eax = 0x7f25b0() 的返回值
0x7ef35a  jne 0x7ef37e
0x7ef35c  call 0x803780             ; 设置登录阶段 = 5
0x7ef361  call 0x622220             ; ★ 检查模式 ∈ {4,6}
0x7ef366  test al, al
0x7ef368  je  0x7ef41b              ; 模式不对 → 退出
0x7ef36e  mov [0x849ba34], 8        ; ★ 进入状态 8
```

**⇒ 状态 7 的三重条件：**

1. `0x7f25b0() == 3`（连接就绪）
2. `0x803780()` 成功（登录阶段 5）
3. **`[0xe59d20] ∈ {4, 6}`**（当前在"大厅/游戏"模式）

## 6. `[0xe59d20]` 是什么

**它同时出现在：**
- `0x622220`（模式门）
- `0x47008e`（`lobby/55` 里"决定是否查连接状态"）

**⇒ 这是"当前应用模式/场景"的全局变量。**

**取值推测：**

| 值 | 含义 |
|---|---|
| 0 | 未初始化/启动中 |
| 4 | 大厅 |
| 6 | 游戏中 |

**⇒ 实测 0 ⇒ 连"大厅模式"都没进入。**

---

## 7. 结论

**大厅房间功能失效的完整原因：**

> **`[0xe59d20]`（应用模式）停在 0，
>  所以状态 7 的第三重判断永远失败，
>  所以永远进不了状态 8，
>  所以 `[0x849ba34]` 永远不是 3，
>  所以房间对象永远不创建。**

**⇒ 一个变量，解释全部。**
