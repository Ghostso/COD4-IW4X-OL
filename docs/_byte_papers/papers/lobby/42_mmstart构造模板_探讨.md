# `mmstart` 构造模板 · 探讨：格式串是"逆向者的作弊码"

> 对应：`lobby/42_mmstart构造模板.md`

---

## 一、这一卷找到的东西，比反汇编一千行都值

**EXE 里有一条 `printf`/`sprintf` 的**格式串**：**

```
"mmstart sv_resetServer; 2486 %d; 3265 %d; 2489 %d; 2574 %d; "
"0; 2500 0; %s; %s 2810 %d; sv_post_options %s; map %s; roomC..."
```

**⇒ 它把"参数顺序"直接写成了人类可读的文本。**

**⇒ 不需要推断字段顺序，格式串告诉你了。**

---

## 二、为什么格式串是最强的证据

**因为格式串是**程序自己写出来的**——它必须和实际拼接顺序完全一致，
否则程序自己就错了。**

**⇒ 这是"程序的自我描述"，可信度极高。**

**⇒ 和"从汇编推顺序"（可能出错）完全不同。**

---

## 三、`2486/3265/2489/2574/2500` 这五个数字

**它们看起来像 dvar 编号。**

**memory 里记着"5 个 dvar 编号未对应"（`2486/3265/2489/2574/2500`）。**

**⇒ 本卷给它们定了位置（在 `mmstart` 的第 1–5 个 `%d`），
但没定语义（每个编号控制什么）。**

**⇒ 这是一个"位置已定、语义待定"的典型。
如果将来能从 dvar 表里找到这些编号的名字，就全通了。**

---

## 四、方法论收获

> **先在 EXE 里搜格式串/调试串/错误串，再考虑反汇编。
> 前者是"程序的自白"，后者是"我的推断"。**

**⇒ 本轮的 `lobby/92` 就是同一种思路：
与其猜 36 个字段的名字，不如把源偏移记下来，
再去找 UI/GSC 里的字段名。**
