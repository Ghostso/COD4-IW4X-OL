# `IFS2.dll` · 探讨：一份反汇编清单暴露了整个系统的思路

> 对应：`lobby/16_IFS2库逐层解剖.md`

---

## 一、我原本想找的是"密钥"

打开 `IFS2.dll`，目标很明确：找 AES 密钥。

**结果没找到密钥，但找到了更有价值的东西：整套系统的设计。**

---

## 二、字符串是"需求文档"

在任何二进制里，`printf` 格式串和日志串，都是最诚实的文档。

`IFS2.dll` 里的：

```
AllocateSectorBuffer failed!
AllocateSectorOffsets failed!
AllocateSectorChecksums failed!
WriteSectorChecksums failed!
WriteSectorOffsets failed!
WriteIFSDataMD5 failed!
Add the file sectors to the NIFS failed!
```

**把这几条按顺序读，就是 `.ifs` 的写入流程：**

1. 分配扇区缓冲
2. 分配扇区偏移表
3. 分配扇区校验表
4. 写数据
5. 写扇区校验
6. 写扇区偏移
7. 写 MD5
8. 完成

**不需要反汇编，日志串已经告诉你结构了。**

---

## 三、最有价值的一行

```
isdir[%d]FileName[%s] size[%d] compSize[%d] name_hash[%llu] md5[%s] offset %lld
```

**这是文件表一项的完整字段格式：**

| 字段 | 类型 | 含义 |
|---|---|---|
| `isdir` | int | 是否目录 |
| `FileName` | str | 名字 |
| `size` | int | 原始大小 |
| `compSize` | int | **压缩后大小** |
| `name_hash` | u64 | 名字哈希 |
| `md5` | str | **文件 MD5** |
| `offset` | i64 | 在 IFS 内的偏移 |

**`compSize` 这一项直接否定了"加密"假说 —— 如果有加密，应该叫 `encSize`。**

---

## 四、加密库的真相

libtomcrypt 的路径只出现这些：

```
libtomcrypt\src\hashes\md5.c
libtomcrypt\src\hashes\sha1.c
libtomcrypt\src\math\ltm_desc.c
libtomcrypt\src\pk\ecc\*.c
libtomcrypt\src\pk\rsa\*.c
libtomcrypt\src\misc\crypt_register_hash.c
libtomcrypt\src\math\rand_prime.c
libtomcrypt\src\misc\zeromem.c
```

**全是 hash（md5/sha1）和公钥（rsa/ecc）。**

**没有 `ciphers/` 目录。**

**⇒ libtomcrypt 只被用来做校验和签名，不用于加密数据。**

这是个重要结论：**IFS 层本身没有对称加密。**

---

## 五、那 `.ff` 的 7.9998 熵是什么

既然 IFS 层不加密，那 `.ff` 的随机性来自**上游**。

`IWff0100` 是 `.ff` 自己的格式头，`aes` 是客户端 EXE 里的字符串。

**所以：`.ff` 在被打包进 `.ifs` 之前就已经是 AES 加密的了。**

**IFS 只是把已经加密的 `.ff` 当一个 blob 装进扇区。**

---

## 六、这改变了攻击面

如果 `.ff` 是 IFS 层加密的，那密钥应该在 IFS 库里。

**但密钥不在 IFS 库里** ⇒ `.ff` 是**打包工具**加密的。

**所以密钥可能在：**
1. 打包工具（不在磁盘上）
2. 客户端运行时（内存里）
3. 从服务端下发

**第 3 条最可能** —— 因为 `15` 卷里我们发现服务端下发 playlist，
说明客户端并不完全信任磁盘内容。

---

## 七、方法论收获

> **日志字符串是需求的自由文档。**

在反汇编之前，先把所有 `printf`/`log` 格式串读一遍。

它们告诉你：
- 有哪些字段（`FileName size compSize md5 offset`）
- 有哪些流程（`Allocate → Write → Finish`）
- 有哪些错误分支（`VERIFY_FILE_MD5_ERROR`）

**`IFS2.dll` 的 601KB 里，最有信息量的就是这些字符串。**
