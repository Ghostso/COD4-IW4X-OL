# 129 · 遥测的四个入队入口与 65 个日志点全表 —— 49 个事件、8 条孤儿模板归属

> 项目：使命召唤OL 大厅（build 1649370 / 3.19）
> 前卷：`123`（事件词表）、`124`（71/15）、`126`（52→54 模板）、`127`（信封+UIPage）、`128`（宏引擎）
> 本卷：**127 卷「`ClientLoadout`/`LoadoutChangeEvent` 未闭合」+ 128 卷两条未闭合点，一次收口**
> 证据：`tools/callsite_finder.py`、`tools/telemetry_site_census.py`、`tools/template_vs_sites_diff.py`、`tools/orphan_template_hunt.py`、`tools/corpus_prefix_reconcile.py`

## §0 结论（六句）

1. **遥测入队入口有四个，不是三个**：`0x640190`（模板直入）、`0x6404B0`（登记器，可运行时拼串）、`0x640FD0`（`log_event(名,值)`）、**`0x63FC60`（整串直入，后发现的第四个）**。
2. **全镜像 65 个日志点，覆盖 49 个不同事件**。其中 `0x6404B0` 56 点（40 事件）、`0x640190` 7 点（7 事件）、`0x63FC60` 7 点（7 事件，其中 6 点是孤儿）、`0x640FD0` 2 点（0 事件，只有 UIPage/UIClick）。
3. **★★ `ClientLoadout` / `LoadoutChangeEvent` 的缺口不是模板，是运行时循环追加**：`0x76B10`/`0x75950` 里 `push '|B0%d'` → 然后 5×`'%d,'`/`'|%d'` 逐段 sprintf 追加。
4. **★★ 8 条「孤儿模板」全部归属**：它们**不走三个标准入口**，各自 `sprintf` 成整串后交 **`0x63FC60`**；并且**全部用 `${TIMESTAMP}` 绝对时间 + MAC `D4-93-90-18-55-10`**。
5. **★★ `0x63FC60` 会剥离 `\n`/`\r`**（`0x63FCBB`/`0x63FCBF`），1 KB 上限 `0x1fff`、栈缓冲 `0x200c`；总开关 `[0xe5735b]==0` 时**直接返回**。
6. **★★ `ClientException` 记录后立刻把总开关 `[0xe5735b]` 置 0**（`0x77DB66`）——**异常后遥测自关闭**。这是首次在代码里看到的「遥测主动停用」路径。

## §1 为什么 127 卷闭合不了这两条事件

127 卷的判断是：「模板只有 5 项，实测 18/17 项 ⇒ 长出来的部分是配装明细，但续接片段 `0x9B7B88` 凑不上」。

**本卷把 `0x76B10`（`ClientLoadout`）整个反汇编了一看就明白**：

```
0x076BBA  push '${TIMESTAMP_PLACEHOLDER}'
0x076BBF  push 'ClientLoadout|%s|%llu|${CODOID(%llu)}|%d'   ← 5 项，前缀
...
0x076BE1  push '|B0%d'                                            ← ★ 追加 1 段
0x076C21  push '|%d'      ×N                                      ← ★ 逐段追加
0x076C8F  push '%d,'      ×5   （每段里 5 个逗号分隔的数）
0x076CD8  push '|%d'
0x076D40  push '%d,'      ×5
0x076DD0  push '%d,'      ×5
0x076E50  push '%d,'      ×5
0x076F75  push '%d,'      ×5
0x077005  push '|%d'
0x077027  push '|%d'
```

⇒ **配装明细不是一条模板，是一个「前缀 + 循环追加」的构造**。这就是为什么 127 卷用「模板项数 = `%` 数 + 1」永远凑不出来——**那条模板根本不存在**。

`LoadoutChangeEvent`（`0x75950`）同构，只是多一个 `'prestige'` 和 `'|B0%d'` + 更多 `'|%d'` 段。

★★ **⇒ 127 卷的「未闭合」是对的，但成因判错了**：不是"续接片段没找到"，是**续接根本不是静态片段**。

★ 旁证：`ClientOfflineOOB`（127 卷发现的两段拼接）是**连续两段字面量**（`0x9E1430` + `0x9E1450` 相邻），而这两条是**运行时跨几十条指令逐段 sprintf**。**两种合成方式都存在，不能混为一谈。**

## §2 四个入口的分工

| 入口 | 地址 | 签名 | 调用点 | 事件数 | 特点 |
|---|---|---|---|---|---|
| **A 模板直入** | `0x640190` | `(buf, ?, tid, ctx, flag)` `ret 0x14` | **7** | 7 | 条目从 `[ebp+8]` 拷；单条完整模板；**不做 IP/TS 替换**（占位符原样进队） |
| **B 登记器** | `0x6404B0` | `(buf, ?, ?, ?, ?, ?)` ≈ 6 参 | **56** | 40 | 秒×1000、时间基准、缺省偏移 `0x1388`；**先 snprintf 再登记**，支持运行时拼串 |
| **C log_event** | `0x640FD0` | `(name, formatted_value)` | **2** | 0 | `UIPage`/`UIClick`；队列上限 1024 |
| **D 整串直入** | `0x63FC60` | `(char*)` | **7** | 7 | 拷 `0x1fff`、**剥 `\n\r`**、总开关门控、1 KB 栈缓冲 |

### 2.1 A 入口：`0x640190`

```
0x640107  push eax              ; 入参
0x640108  mov ecx, esi
0x64010A  call 0xb75a50         ; 转 string
0x64010F  cmp dword [0x849b5cc],0 ; 已初始化?
0x640125  mov [esi+0x18], cl    ; +0x18 = 1B flag
0x64012B  mov [esi+0x14], 3     ; ★ +0x14 = 3（类型/来源 = 3）
0x640132  mov [esi+4],  edx     ; +0x4
0x640135  mov [esi+8],  eax     ; +0x8
0x640138  mov [esi+0xc],  ecx   ; +0xc
0x64013D  call edi              ; 取 tick → [0x81aa118]  首次调用初始化基准
0x640143  mov [0x81aa118], eax
0x640148  call [0xca812c]       ; 取 64 位时间 → [0x81aa110]/[0x81aa114]
0x64015F  mov [0x849b5cc], 1
0x640169  call edi / sub [0x81aa118]  → [esi+0x10]   ; ★ +0x10 = 相对 tick
0x640177  mov [esi+0x19], dl    ; +0x19 = 第二个 1B
0x640180  ret 0x14              ; 5 个 4 字节参数
```
**条目布局**：`+0x04 / +0x08 / +0x0C`（3 个 u32）、`+0x10` 相对 tick、`+0x14`=3、`+0x18`/`+0x19` 两个 flag。

### 2.2 B 入口：`0x6404B0` 补完（127 卷 §1.2 的延伸）

127 卷已写：秒×1000、缺省偏移 `0x1388`=5000ms。本卷补：
- `0x64057E call 0xb75990`：对**已 snprintf 好的整串**做 3 次 `'${CLIENT_IP_PLACEHOLDER}'` 查找（`0x640590..0x6405A0`），命中则把该串**再交给** `0x641300` 做替换。
- 时间基准组 `[0xc911f4c/50]` vs `[0xc8e4054/58]` 的选择就发生在这里。

### 2.3 D 入口：`0x63FC60`

```
0x63FC77  cmp byte [0xe5735b], 0
0x63FC84  je 0x63fdd2          ; ★ 总开关关 ⇒ 直接返回，不记
0x63FC8A  push 0x1fff / push eax / lea eax,[ebp-0x200c]
0x63FC97  call 0xc3c740        ; 限长拷贝到 1KB 栈缓冲
0x63FCB0..0x63FD13 循环:       ; ★ 逐字节拷，跳过 0x0a('\n') 和 0x0d('\r')
```
★★ **⇒ 走 D 入口的事件在日志里是"单行"的**，换行被吃掉。这解释了为什么 `ClientOffline`（`0x9E1604 'ClientOffline|${TIMESTAMP}|%s'`，走 B）在 124 卷里是 `\n` 分隔的多事件，而 `UserComplaint` 这类走 D 的是单串。

### 2.4 C 入口：只有 2 个调用点

`0x640FD0` 全镜像调用点 = `0x2411C5`(UIClick) / `0x241261`(UIPage)。
**⇒ 127 卷的「UIPage/UIClick 走信封」是全局唯一的两处**：没有任何其他事件走"名+值"这条路。

## §4 8 条孤儿模板归属（一次全部收口）

`template_vs_sites_diff.py` 的差集显示：**NUL 普查有模板、但不在 65 个日志点里的 = 19 条**，其中 **11 条是 `0x196xxxx` 假阳性**（`TdO`/`LvO`/`D_q`/`DJS`/`DFY`/`HdS`/`T8S`/`TWY`/`DzS`/`L7X`/`X3l` —— 都是 3 字母标识符，与 127 卷假阳性清单同一族，只不过这次落在大范围而非窄带），**真孤儿 8 条**：

| # | 模板 | 串 | 引用点 | 函数 | 去向 |
|---|---|---|---|---|---|
| 1 | `ClientException` | `0x9DBA48` | `0x77DB10` | `0x37D960` | **D** |
| 2 | `ClientOfflineOOB` | `0x9E1430` | `0x4025B0` | `0x401A50` | **D** |
| 3 | `ComError` | `0x9DB670` | `0x37C243` | `0x37BFA0` | **D** |
| 4 | `GameMomentsEdit` | `0x9D9768` | `0x357AFB` | `0x357A40` | **D** |
| 5 | `QuestionnaireResult` | `0x9D5458` | `0x32BA5B` | `0x32B960` | **D** |
| 6 | `UIClickCount` | `0x9B8C78` | `0x0E7178` | `0xE6F30` | **D**（`0x4E6E61`） |
| 7 | `UserComplaint` | `0x9C2458` | `0x1D3997` | `0x1D3790` | **D** |
| 8 | （`ClientOfflineOOB` 的重叠计入） | — | — | — | — |

★ 注意 #6 `UIClickCount` —— 名字里有 `ClickCount`，让人以为是 UIClick 的兄弟走 C 入口。**实际它走 D 入口**，而且它的模板**第一个字段是 `%llu`（没有 `%s` 事件名+时间）**：
```
UIClickCount|%llu|${CODOID(%llu)}|%s|%u|%s|%d
            ↑ 第 1 个 %llu 就是"计数"
```
★★ **⇒ `UIClickCount` 不用 `${TIMESTAMP}` 压栈，但它的函数 `0xE6F30` 里确实压了 `'${TIMESTAMP}'`（`0xE716F`）** —— 说明 `%llu` 位置由调用方传入，而 `${TIMESTAMP}` 可能用在别处（或该模板在此函数里被复用了另一种拼法）。**这是本卷唯一一处口径不明确，记为诚实缺口。**

## §5 A/B/D 三个入口的「时间口径」归纳

| 入口 | TS 形式 | 含义 |
|---|---|---|
| **B**（登记器，56 点） | `${TIMESTAMP_PLACEHOLDER}` 压栈 → 引擎展开为 `${TIMESTAMP_OFFSET(-N)}` | **相对秒**（N 从条目 tick 算） |
| **A**（直入，7 点） | 同 B（除 `STUNServerPingResult`/`TencentCrossInit` 用 `${TIMESTAMP}`） | 相对秒 |
| **D**（整串，7 点） | 模板里**内联 `${TIMESTAMP}`** | **绝对时间** |

★★ **⇒ `128` 卷说的「8 个事件用 `${TIMESTAMP}` 绝对时间」现在精确了**：不是"8 个函数"，是**D 入口全部 + A 入口 2 个**。

## §6 条目结构与队列的关系（A 入口的 `[esi+0x14]=3`）

`0x640190` 写 `[esi+0x14] = 3`。这是条目里唯一的**常量类型字段**。
★ 与 `0x641050` 冲刷时 `call 0xb78b70`（`0x6410F7`）、`0xb77280`（`0xB7D68`）取 `[条目+0x20]/[条目+0x24]` 对照，**`+0x14=3` 极可能是"来源=游戏内"而不是"类型=3"** —— **未定，记账，不冒充。**
