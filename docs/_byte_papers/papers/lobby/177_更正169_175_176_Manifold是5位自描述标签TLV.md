# 177 · ★★★ 更正 169/175/176：Manifold 位流不是「n 位」，是「5 位自描述字段标签」TLV

> 卷次：177（**更正卷** —— 推翻 169、175、176 三卷的位流模型）
> 方法：把 `0xB77B10` / `0xB774E0` 的**完整实现**读完，而不是只读开头 5 条指令
> 结论：`push 3` / `push 8` / `push 19` / `push 21` 是**字段标签的取值**，不是位宽。**位宽恒为 5**。

---

## §0 结论

```
W_TAG(stream, n) → 写 5 位，值 = min(n, 31)          [0xB77B10]
W_VAL(stream, ptr, k) → 写 k 位                      [0xB777C0]
R_TAG(stream, n) → 读 5 位，返回 bool(读值 == n)      [0xB774E0]
R_VAL(stream, ptr, k) → 读 k 位                      [0xB772E0]
```

**Manifold 头部 = `W_TAG(3) + W_VAL(type,8) + W_TAG(8) + W_VAL(count,32)` = 50 位**

真相是：`push imm` 是 `W_TAG` 的 `n` 参数，`W_TAG` **内部固定用 5 位**把 `min(n,31)` 写出去。

## §2 证据链（第一权威）

### 2.1 `0xB77B10` 完整（10 条指令，不是 5 条）

```asm
0xB77B10  push ebp / mov ebp,esp
0xB77B13  cmp  byte ptr [ecx+0x21], 0
0xB77B17  je   0xB77B28                 ; +0x21==0 → 什么都不写
0xB77B19  mov  eax, dword ptr [ebp+8]   ; ★ n
0xB77B1C  push 0                        ;   参数5 = 0
0xB77B1E  push 0x1F                     ; ★★★ 参数4 = 0x1F = 31
0xB77B20  push 0                        ;   参数3 = 0
0xB77B22  push eax                      ; ★ 参数2 = n
0xB77B23  call 0xB77A70                 ;   → core(stream, n, 0, 31, 0)
0xB77B28  pop ebp / ret 4
```

### 2.2 `0xB77A70`（core）关键 4 行

```asm
0xB77AC3  mov  ecx, ebx        ; ebx = 参数4 = 31
0xB77AC5  sub  ecx, edi        ; edi = 参数3 = 0  ⇒ ecx = 31
0xB77AC7  mov  eax, 0
0xB77ACC  je   0xB77AD8        ; ecx==0 → eax 保持 0
0xB77ACF  call 0xB75D40        ; ★ 位宽计算
0xB77AD7  inc  eax             ; ★ eax = 位宽(31) + 1 = 5 + 1 = 6？
```

★ 但 `0xB77AF5 call 0xB777C0(s, &值, eax)` 里 `eax` 已重新赋值：
```asm
0xB77AD8  mov  ecx, [ebp+8]    ; 参数2 = n
0xB77ADB  cmp  ecx, ebx / jbe  ; n <= 31 ?
0xB77ADF  mov  ecx, ebx        ; 否 → ecx = 31
0xB77AE3  cmp  ecx, edi / jae  ; n >= 0 ?
0xB77AE7  mov  ecx, edi        ; 否 → ecx = 0
0xB77AE9  sub  ecx, edi        ; ★ ecx = min(n,31) - 0 = min(n,31)
0xB77AEB  push eax             ; ★ 位数 = 上面那个 inc 后的值
0xB77AEF  mov  [ebp+0x14], ecx ; ★ 值 = min(n,31)
0xB77AF5  call 0xB777C0        ;   写
```

### 2.3 `0xB75D40` = 位宽（我实测过）

```asm
0xB75D40  mov eax,[ebp+8]      ; = 31
          ; 一串 test/shr 找最高有效位位置
          ; bits_of(31) = 5
```

**⇒ `0xB77B10(s, n)` = 写 **5 位**，值 = `min(n,31)`。** `n` 最大 31，超出被钳到 31 —— 所以 `push 0x1F` 的钳位上限恰好对应"5 位能表示 0..31"。

### 2.4 ★★ 决定性证据：读侧把返回值当 bool 检查

```asm
0x6256F0  call 0xB774E0        ; R_TAG(3)
0x6256F5  test al, al          ; ★ 检查返回值
0x6256F7  je   0x62570F        ;   为 0 → 失败
0x6256FF  call 0xB772E0        ; R_VAL(8)
0x625707  test al, al / je     ; ★ 再检查
0x625725  call 0xB774E0        ; R_TAG(8)
0x62572A  test al, al / je     ; ★ 再检查
```

★★★ **如果 `R_TAG` 只是"读 n 位"，它的返回值毫无意义（读多少位不产生 bool）。**
只有"**读 5 位并与期望标签比较**"才需要返 bool 让调用方失败退出。

而 `0xB774E0` 内部确实：
```asm
0xB774F0  cmp byte ptr [ecx+0x21], 0
0xB774F4  mov al, 1            ; ★ 默认返回 True
0xB774F6  je  0xB7754F         ; +0x21==0 → 直接返回 True（不读、恒匹配）
0xB77509  call 0xB77630        ; 读
0xB77517  mov esi, [ebp-0x58]  ; 读到的值
0xB7751A  cmp esi, eax         ; eax = 期望 n
0xB7751C  sete bl              ; ★ bl = (读值 == n)
```

**⇒ `R_TAG(s, n)` = 读 5 位，返回 `读值 == n`。完全坐实。**

### 2.5 写侧 / 读侧 push 序列逐项对称

| 写侧 `0x625520` | 读侧 `0x6256C0` |
|---|---|
| `call 0xB77B10` (W_TAG) | `call 0xB774E0` (R_TAG) |
| `call 0xB777C0` (W_VAL) | `call 0xB772E0` (R_VAL) |
| `call 0xB77B10` (W_TAG) | `call 0xB774E0` (R_TAG) |
| `push 0x20` + `call 0xB777C0` | `push 0x20` + `call 0xB772E0` |

item 段同样逐项对称（见 §3）。

## §3 Manifold 完整结构（定稿）

### 3.1 头部（50 位）

```
W_TAG(3)         5 位
W_VAL(type, 8)   8 位
W_TAG(8)         5 位
W_VAL(count, 32) 32 位
                ─────
                50 位
```

### 3.2 每条 item

```
无附加值（客户端常规路径）:
    W_TAG(1)              5 位
    W_VAL(has_value, 1)   1 位
    W_TAG(19)             5 位
    W_TAG(8)              5 位
    W_VAL(len, 32)       32 位     ← 载荷**字节数**
    W_VAL(payload, len*8) len*8 位
                        ─────────
                        48 + len*8 位

有附加值（`eax|ecx != 0` 分支）:
    + W_TAG(21) 5 位 + W_VAL(x, 64) 64 位     = 额外 69 位
```

★ `0x13` = 19 是**标签值**写在 5 位里，不是"19 位"。

### 3.3 长度单位

`0x4F3F0A  add eax,eax` ×3 = **×8** ⇒ `len` 是**字节数**。（这条 176 卷是对的。）

## §5 诚实边界

1. **没有真实 6/5 位流样本可对账。** 全部 33 个 run 的 6/5 应答都是"对象=0"（空 TLV ACK），客户端从未收到过 Manifold 位流。所以本卷模型**只有静态证据，无字节级实机验证**。
2. **`W_VAL` 的位序（MSB-first）** 是从 `0xB777C0` 的移位方向推断的，未与真实样本对账。
3. **`count` 之后是否还有终止标记** 未证（读侧 `0x655930` / `0x656750` 是链表推进，未展开）。

★★ **强度评估**：
- 「5 位标签」：**强**（读侧 bool 检查 + 读写对称 + `0x1F` 钳位三重印证）
- 「50 位头」：**强**（由 5+8+5+32 直接推出）
- 「item 48+len×8」：**中**（对称性支持，但 21 段的条件判断 `eax|ecx` 未完全展开）
- 「MSB-first」：**弱**（仅反汇编推断）

## §6 方法论

1. **★★★ 只读函数开头 = 必然误判。** 169 卷读了 `0xB77B10` 的前 6 条就断言"什么都不写"。这个函数**第 10 条**才是 `call core`。**必须读到 `ret`。**
2. **★★★ `push imm` 不一定是位宽。** 先看它被 push 给了谁；如果收方内部还有一次"钳位 + 转位宽"，那它就是**值**。
3. **★★★ 读侧对返回值的检查方式是判定语义的钥匙。** `test al,al / je fail` 说明它返 bool，不是返数据。
4. **★★ 读写两侧的 push 序列要逐项列表对比。** 对称 ⇒ 模型正确；不对称 ⇒ 一定有一侧读错。
5. **★★ 钳位上限暴露位宽。** `push 0x1F` 作为上界 ⇒ 目标字段恰好 5 位（0..31）。
