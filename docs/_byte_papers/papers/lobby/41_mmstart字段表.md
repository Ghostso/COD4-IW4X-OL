# `6/14` `mmstart` 命令的完整字段表

> **这是房间参数的唯一真正载体**
> 证据：`tools/room_mmstart_fields2.py`（64 条 mmstart，21 种 blob）

---

## 1. 命令格式

```
mmstart <键> <值>; <键> <值>; ... ;
```

**分隔符：`;`（分号）+ 空格。**

**内层结构**：`u32 文本长度 | 文本`（无 NUL 结尾）。

---

## 3. 六种地图

```
coop_training_mp_cargoship      ×26
coop_train_mp_firingrange       ×10
mp_nuked                         ×3
coop_chopper_mp_suburbs          ×2
coop_take_mp_fav_tropical        ×2
coop_escape_mp_storm_spring      ×1
```

**全部是 `coop_*` / `mp_*` 命名，与 `mp_playlists` 里的地图键一致。**

## 4. `roomChatChannelID` 的三种取值

| 值 | 次数 | 备注 |
|---|---|---|
| `1234605616436508552` | 47 | = `0x1122334455667788`（**同一哨兵！**） |
| `0` | 13 | 未加入（多数是靶场训练） |
| `1800154382` | 4 | = `0x6B4C2D0E` |

**`1234605616436508552` 转十六进制正是 `0x1122334455667788`。**

**⇒ 房间 ID 和聊天频道 ID 用的是同一个哨兵值。**

---

## 5. `start_map_rotate_once` 的 0–7

20 条里覆盖了 `0,1,2,3,4,5,6,7`。

**这是一个 0–7 的索引，与 `playlist 37` 配对出现。**

**⇒ 含义：从 playlist 37 里选第 N 张地图。**

---

## 6. 两种模式的分野

### 形态 A：直指定地图（44 条）

```
g_gametype coop / train
map coop_training_mp_cargoship
g_difficulty 0
2654 M7-E8S6Client
```

**⇒ 直接指定 `map`，用于靶场/训练/coop 关卡。**

### 形态 B：按 playlist（20 条）

```
playlist 37
start_map_rotate_once 3
roomChatChannelID 1234605616436508552
```

**⇒ 不指定 map，而是"从 playlist 37 的第 3 张图开始"。**

**这是"正常匹配/多人房间"的路径。**

## 7. 数字键的含义推测

`2486 / 2489 / 2500 / 2574 / 3265 / 2810` 这些**纯数字键**是 dvar 的
**哈希编号**（不是名字）。

| 键 | 取值 | 与形态的相关性 |
|---|---|---|
| `2486` | 1（形态B）/ 0（形态A） | 与 playlist 方式强相关 |
| `2489` | 0（形态A）/ 1（形态B） | 同上 |
| `2500` | 恒 0 | 无区分 |
| `2574` | 0（形态A）/ 2（形态B） | 同上 |
| `3265` | 1 / 6 / 18 | 与地图类型相关 |

**`2486/2489/2574` 三个值在两种形态里同时翻转
⇒ 它们很可能是同一组开关的三个位。**

---

## 8. 可改清单

| 目标 | 改哪个键 | 风险 |
|---|---|---|
| 换地图 | `map` | 低（形态 A） |
| 换 playlist 内序号 | `start_map_rotate_once` | 低（形态 B） |
| 换对局类型 | `playlist` | 中（37 是唯一值，换别的可能没数据） |
| 换难度 | `g_difficulty` | 低 |
| 换模式 | `g_gametype` | 中（`coop`/`train`，别的需验证） |
| 改聊天频道 | `roomChatChannelID` | 低 |

## 9. 与 `11/4` 的关系

`11/4`（setRoomData）发的是**恒定模板**（`lobby/40` 已证）。

**`6/14 mmstart` 才是"用户实际选择"的载体。**

**流程：**

```
1. 用户在大厅选模式/地图
2. 客户端发 6/14 mmstart（带 playlist 37 + 地图序号）
3. 同时发 11/4（房间默认模板）
4. 服务端据此分配战斗服 + 地图
```
