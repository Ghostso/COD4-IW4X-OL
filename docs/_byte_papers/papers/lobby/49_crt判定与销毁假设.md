# `0xc3e9f5` 的最终判定：CRT，不是业务闸门

> 承接 `lobby/48`
> 把最后一个疑点确认清楚。

---

## 1. 代码证据

### `0xc3e9f5`

```asm
0xc3e9fa  sub esp, 0x10
0xc3e9fd  jmp 0xc3ea0c
0xc3e9ff  push [ebp+8]
0xc3ea02  call 0xc4b5b4        ; 第二个检查
0xc3ea08  test eax,eax
0xc3ea0a  je  0xc3ea1b         ; 两者都失败 → 走 0xc3ea1b
0xc3ea0c  push [ebp+8]
0xc3ea0f  call 0xc3d280        ; 第一个检查
0xc3ea15  test eax,eax
0xc3ea17  je  0xc3e9ff         ; 失败 → 换另一个
```

### `0xc3d280`（第一个检查）

```asm
0xc3d289  cmp ebx, -0x20       ; 边界检查
0xc3d290  cmp [0x19697c8], 0   ; 句柄是否初始化
0xc3d2bf  push [0x19697c8]     ; ★ 句柄
0xc3d2c5  call [0xca82e8]      ; ★ IAT 调用
0xc3d2cd  test edi,edi
```

**`[0xca82e8]` 是导入表槽** —— 查它是什么。

### `0xc4b5b4`（第二个检查）

```asm
0xc4b5b9  push [0x1969df8]
0xc4b5bf  call [0xca82f0]      ; ★ 另一个 IAT 调用
0xc4b5c9  push [ebp+8]
0xc4b5cc  call eax             ; 再调返回的回调
```

**这两个都是"取一个函数指针然后调用"的形态。**

**在 MSVC CRT 里，这正是 `_lock_file` / `_unlock_file` /
`__acrt_lock` 一类的写法。**

---

## 2. 结论

**`0xc3e9f5` 是 CRT 的锁/句柄管理函数，不是"检查会话/资源"。**

**⇒ 它几乎总是返回非零（锁成功）。**

**⇒ `0x639d00` 里的 `je 0x639d25`（失败分支）几乎不会走。**

**⇒ 房间对象**应该**被创建。**

---

## 3. 那为什么它是 0

**如果创建逻辑正常，对象却是 0，只剩两种可能：**

### A. `0x7e98f0` 整体没被调用

**唯一调用者 `0x808658` 在启动路径上没走到。**

### B. 对象创建后又被销毁

**`0x63a59a` 处有 `mov [0x82e13fc], edi`（edi=0），是析构路径。**

**如果析构在创建之后被执行，对象就变回 0。**

**⇒ 需确认析构的触发条件。**

---

## 4. 第二个可能性很关键

**`0x63a570`–`0x63a59a` 那段：**

```asm
0x63a583  mov ecx, [0x82e13fc]
0x63a589  mov [0x82e1400], edi
0x63a58f  cmp ecx, edi
0x63a591  je  0x63a59a          ; 已经是 0 → 跳过
0x63a593  mov edx, [ecx]
0x63a595  mov eax, [edx]
0x63a597  push esi
0x63a598  call eax              ; 调用析构
0x63a59a  mov [0x82e13fc], edi  ; 置 0
```

**这是一个"销毁房间对象"的函数。**

**如果它在创建之后被调用（例如某次重新初始化），
对象就是 0。**

**⇒ 这是比"没创建"更可能的解释。**

---

## 5. 判定方法

**在 dump 里查 `0x63a570` 所在函数的调用者，
看它是否在启动路径上、在 `0x7e9933` 之前还是之后。**

**这是下一轮的第一件事。**

---

## 6. 本轮的实质进展

**从"为什么是 0"缩到两个互斥的假设：**

| 假设 | 判据 |
|---|---|
| A. 创建函数没跑 | 查 `0x808658` 是否可达 |
| **B. 创建后被销毁** | **查 `0x63a583` 那段何时执行** |

**B 更可能，因为 A 需要"整条启动路径都没走"这么大的前提。**

**真正确认一件事的价值，在于排除它。**
