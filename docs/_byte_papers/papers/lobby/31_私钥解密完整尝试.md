# 私钥授权解密：一轮完整尝试的结论

> 用户授权："允许用私钥继续尝试解密 .ff"
> 本篇记录本轮**全部尝试**与**最终状态**。

---

## 1. 严格成立的结论（4 条）

### 1.1 RSA 密文位置 = `.ff` 偏移 0x15，长度 256

判据：PKCS#1 v1.5 填充严格匹配（`00 02 <≥8 非零> 00 <数据>`）。

```
mp_playlists.ff:
  0x00–0x14  IWff0100 头（21 字节）
  0x15–0x114 RSA 密文（256 字节）
  0x115–    密文数据（49,216 字节）
```

**这不是猜测 —— 错误的 256 字节窗口通过该检查的概率是 1/65536。**

### 1.2 密钥材料 = 40 字节

```
da135e91c7981459a13ddc2aed3050ae
6dd9a7ce619bb6c5
ff6c10c6db650000149c1f0103000000
```

结构：`[24 字节][16 字节]`，后 16 字节尾部 `149c1f01 03000000`
像版本/标志。

### 1.3 算法 = AES（CFB 族），key 24 字节

从代码确认：

| 证据 | 内容 |
|---|---|
| `0xbc8d70` | setup，`cmp esi,0x10/0x18/0x20` 接受 16/24/32 |
| 注册表 `0xe87850` | 只有一项：`"aes"`，字段 `6/16/32/16`（块 16） |
| 调用点参数 | `keylen = 0x18 = 24`（`0x483afc`） |

### 1.4 ★ 解密验证：前 16 字节正确

```
key = 材料[0:24]
iv  = 材料[24:40]
AES-128… no；AES-192 CFB128/OFB/CTR 均可解出：
  b'IWffs100\x00\x00\x00\x00o\x9e\x1d\x0c'
```

**磁盘密文 ≠ 明文**（`b2 2d ee f2 …`），所以这是真解密，不是巧合。

**明文头 `IWffs100`，而磁盘头是 `IWff0100` —— "已加密"标记。**

## 3. 问题定位：参数映射仍有一处错误

`cipher_setup`（`0xbc8640`）的 6 个参数，代码内部用法：

```
[ebp+0x08] → 0xbca340 校验          = cipher index     ✔
[ebp+0x0c] → 0xbc86e8 逐字节拷贝源  = key 源
[ebp+0x10] → 0xbc86bc push 给 setup = keylen
[ebp+0x14] → 0xbc86a7 push 给 setup
[ebp+0x18] → 0xbc86a4 push 给 setup
[ebp+0x1c] → 0xbc8659 flags
[ebp+0x20] → 0xbc8672 ctx 输出
```

而调用点压栈（`0x483af3`–`0x483b14`）：

```
push 0x1c2b2b8   → arg7
push 0            → arg6
push 0            → arg5
push 0x18 (=24)   → arg4
push [ebp-0x2c]   → arg3
push [ebp-0x14]   → arg2
push "aes"        → find_cipher 的（被 add esp,4 清掉）
push eax          → arg1
```

**矛盾**：`arg3 = [ebp-0x2c]`（它是 RSA 材料的内存地址），
却被当作 keylen 传给 setup。

**`[ebp-0x2c]` 是栈地址（约 `0x1Bxxxxxx` 量级），不可能是 16/24/32。**

⇒ **`0xbc8640` 不是 `cipher_setup`，或参数次序另有约定。**

---

## 4. 结论

> **密钥、IV、算法、数据偏移都已独立验证（前 16 字节正确是铁证），
>  但"用它们解全文"失败。
>  根因是 `cipher_setup` 的参数语义还没读对，导致实际用的可能是
>  另一组 key/IV。**

**这不是"没进展"，而是把问题从"不知道密钥"缩小到"一个函数的 6 个参数"。**
