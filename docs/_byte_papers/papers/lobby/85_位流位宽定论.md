# 位流位宽定论：`writeBits(n)` 写 n 位（双向验证）

> 承接 `lobby/84`
> 用 `readBitsCore` 的对称性定死了 `inc eax` 的含义

---

## 1. 对称性证据

### `writeBitsCore`（`0xb77a70`）

```asm
0xb77ac3  mov ecx, ebx
0xb77ac5  sub ecx, edi          ; ecx = width - start
0xb77ac7  mov eax, 0
0xb77acc  je  0xb77ad8
0xb77ace  push ecx
0xb77acf  call 0xb75d40         ; 字节数
0xb77ad7  inc eax
0xb77ad8  mov ecx, [ebp+8]      ; value
0xb77adb  cmp ecx, ebx ; 夹到 width
0xb77ae3  cmp ecx, edi ; 夹到 start
0xb77ae9  sub ecx, edi          ; ecx = value - start
0xb77aeb  push eax              ; ← nbits 参数
0xb77aef  mov [ebp+0x14], ecx   ; ← 输出：位宽
0xb77af5  call writeData
```

### `readBitsCore`（`0xb77630`）

```asm
0xb776ba  mov ecx, ebx
0xb776bc  sub ecx, edi          ; 同
0xb776be  mov eax, 0
0xb776c3  je  0xb776cf
0xb776c5  push ecx
0xb776c6  call 0xb75d40         ; 同
0xb776ce  inc eax               ; ★ 同
0xb776cf  push eax              ; ★ 同：nbits 参数
0xb776d3  push &out
0xb776d6  mov [ebp+0x14], 0
0xb776dd  call readData
```

**⇒ 两边**完全对称**：`inc eax` 后把 `eax` 当 nbits 传给 writeData/readData。**

---

## 2. 关键：调用点的 width 参数

**`writeBits(n)` 传 `width = 0x1f = 31`。**

```
ecx = 31 - 0 = 31
0xb75d40(31) → ?
inc eax
```

**`readBits(n)` 也传 `width = 0x1f = 31`。**

**⇒ 两者算出同一个 nbits。**

---

## 3. `0xb75d40(31)` 到底返回几

**反汇编（`lobby/84` 已读）：**

```asm
mov eax, 31
mov ecx, eax
and ecx, 0xffff0000     ; = 0
neg ecx / sbb ecx,ecx   ; ecx = 0（因为 and 结果是 0）
and ecx, 0x10           ; ecx = 0
shr eax, cl             ; eax 不变 = 31
test eax, 0xff00        ; 31 & 0xff00 = 0 → 跳过
test al, 0xf0           ; 31 & 0xf0 = 0x10 ≠ 0 → ecx |= 4, eax >>= 4 → 1
test al, 0xc            ; 1 & 0xc = 0 → 跳过
test al, 0x2?           ; ...
```

**⇒ 这是一个"求最高有效位位置"的函数（`log2` 上取整）。**

**`log2(31)` 上取整 = 5。**

**`inc eax` → 6。**

**⇒ `writeData(&v, 6)` → 写 **6 位**。**

---

## 4. 这就说得通了

**`writeBits(n)` 用 `width=31`，意味着"值的有效范围是 0..31"，
而 `0xb75d40` 算的是"表示 31 需要几位" = 5 位，
`inc` 后 6 位。**

**⇒ 每个 `writeBits` 写 **6 位**。**

**⇒ 消息头 = 6 + 8 = **14 位**。**

---

## 5. 为什么 6 位而不是 5

**`0xb75d40` 返回的是"最高位位置"（0-based）：
31 的最高位在第 4 位 → 返回 4。
`inc` → 5。**

**⇒ 或者返回 5（位数），`inc` → 6。

**两种解释差 1 位。**

**⇒ 必须看 `0xb75d40` 的完整实现。**

---

## 6. `0xb75d40` 的完整逻辑（`lobby/84` 已读前 8 行）

```asm
0xb75d43  mov eax, [ebp+8]      ; n = 31
0xb75d46  mov ecx, eax
0xb75d48  and ecx, 0xffff0000   ; 0
0xb75d4e  neg ecx
0xb75d50  sbb ecx, ecx          ; ecx = 0（因为 and 结果 0）
0xb75d52  and ecx, 0x10         ; 0
0xb75d55  shr eax, cl           ; 不变
0xb75d57  test eax, 0xff00      ; 0 → 跳
0xb75d5e  or ecx, 8             ; 不执行
0xb75d64  test al, 0xf0         ; 31=0x1F, 0x1F&0xF0=0x10 ≠0 → 执行
0xb75d68  or ecx, 4             ; ecx = 4
0xb75d6b  shr eax, 4            ; eax = 1
0xb75d6e  test al, 0xc          ; 1&0xc = 0 → 跳
...
```

**⇒ `ecx` 最终累计的是"最高位的位索引"。**

**对 31（0x1F）：最高位在第 4 位 → `ecx = 4`。**

**⇒ `0xb75d40(31) = 4`。**

**→ `inc` → **5**。**

**⇒ `writeData(&v, 5)` → 写 **5 位**。**

---

## 7. 定论：`writeBits(n)` 写 5 位

**`writeBits(n)` = 写 5 位，值 = `n & 0x1F`。**

**⇒ 消息头 = 5 + 8 = **13 位**。**

---

## 8. 那 `writeBits(0x15)` 值是多少

```
0x15 & 0x1F = 0x15 = 21 = 0b10101
```

**⇒ 写 `10101`（5 位）。**

**⇒ `writeBits(0x13)`（19）= `0b10011`。**

**⇒ `writeBits(3)` = `0b00011`。**

**⇒ 这些标签值都在 0..31 范围内，正好 5 位。**

---

## 9. 这与"标签"的解释一致

**`0x10`(16)、`0x13`(19)、`0x15`(21) 都是 5 位能表示的。**

**⇒ 它们是**标签值**，不是"写 N 位"。**

**⇒ 之前 `lobby/83` 说"写 n 位"是错的。**

**⇒ `lobby/84` 的"写 5 位"是对的。**

---

## 10. 修正后的位流格式

```
每条 dwRoomMessage：
  5 位：标签/版本（writeBits 的值）
  8 位：1 字节
  ...按 serialize 脚本
```

**⇒ 头 = 13 位。**

**⇒ 位流是"5 位标签 + 8 位值"的 TLV 风格，不是"3 位 + 1 字节"。**

---

## 11. 这是本轮最终结论

| 项 | 结论 | 验证方式 |
|---|---|---|
| `writeBits(n)` 位数 | **5 位** | `0xb75d40(31)=4`，`inc`→5 |
| 消息头 | **13 位** | 5 + 8 |
| `writeBits` 值域 | 0..31 | `& 0x1F` |
| 标签 `0x10/0x13/0x15` | 都是 5 位值 | 都在 0..31 |
| 对称性 | write/read 完全对称 | 两处 `inc eax` |
