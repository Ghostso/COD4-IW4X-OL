## §0 统一对象坐标系

### 0.1 关键前提：两个序列化器的 `this` 偏移不同

```
0x806F20 在 vtable 0xDC79F0 → 对象 + 0   ⇒ esi = 对象 + 0
0x806C90 在 vtable 0xDC79FC → 对象 + 8   ⇒ esi = 对象 + 8
```

依据 `0x4F4010` ctor：
```asm
0x4F4021  mov dword [edi],     0xDC79F0   ; vtable#1 @ 对象+0
0x4F4027  mov dword [edi + 8], 0xDC79FC   ; vtable#2 @ 对象+8
0x4F4031  mov dword [ecx+edi+4], 0xDC7A08 ; vtable#3 @ 对象+4
```

⇒ **`0x806C90` 的 `[esi+0x120]` = 对象 + 0x128**（不是 0x120）

### 0.2 统一后的 MMI 字段集合（对象坐标系，30 个）

```
0x128 0x168 0x16c 0x170 0x1b0 0x1b4 0x1b8 0x1bc 0x1c0 0x1c4
0x1c8 0x1cc 0x1dc 0x1e0 0x1e4 0x1e8 0x1ec 0x1f0 0x1f4 0x1f8
0x1fc 0x200 0x204 0x208 0x20c 0x210 0x214 0x218 0x21c 0x220
```

★ **注意：`+0x1CC` 在这个集合里！**

## §1 StartGame 四个字段的最终判定

| StartGame 偏移 | `[this+8]=对象+0` | `[this+8]=对象+8` | 判定 |
|---|---|---|---|
| `+0x10` (blob#2) | 对象+0x010 → miss | 对象+0x018 → miss | ❌ **MMI 低区不透明** |
| `+0x18` (blob#1) | 对象+0x018 → miss | 对象+0x020 → miss | ❌ **MMI 低区不透明** |
| `+0x118` (blob#1 长度) | 对象+0x118 → miss | 对象+0x120 → miss | ❌ **MMI 低区不透明** |
| **`+0x1CC` (blob#3)** | **对象+0x1CC → HIT** | 对象+0x1D4 → miss | ✅ **MMI 正式字段** |

★★★ **只有 `+0x1CC` 命中，且只在 `[this+8] = 对象+0` 时命中。**

⇒ **`[this+8]` = `MatchMakingInfo` 对象起点**（与 `0x634AED lea edi,[ebx+0x7238]` 直接吻合）。

## §2 更正 194 卷

| 194 卷说法 | 更正 |
|---|---|
| 「`[this+8]` = MMI 对象 + 8」 | **= MMI 对象起点** |

## §3 最终结论（房间类 StartGame 结构）

```
dwRoomMessageStartGame
  W_TAG(3) + W_VAL(type,8)
  blob#1: [tag19][tag8][len1=MMI+0x118][data = MMI+0x18]     ← MMI 低区（不透明）
  blob#2: [tag19][tag8][len=8][data = MMI+0x10 (64位)]       ← MMI 低区（不透明）
  blob#3: [tag19][tag8][len=16][data = MMI+0x1CC (128位)]    ← ★ MMI 正式字段
```

### 3.1 三个 blob 的性质定案

| # | 偏移 | 性质 | 服务端能否构造 |
|---|---|---|---|
| 1 | MMI+0x18（256B 缓冲，长度 MMI+0x118） | **低区不透明** | ⚠️ 只能猜 |
| 2 | MMI+0x10（64 位） | **低区不透明** | ⚠️ 只能猜 |
| 3 | **MMI+0x1CC（128 位）** | **正式字段** | ✅ **可构造** |

★★★ **重大进展：blob#3（16 字节 / 128 位）确认是 `MatchMakingInfo` 的正式字段。
这几乎肯定就是 `security_key`（16 字节）！**

## §5 MMI 低区（`+0x00 ~ +0x11F`）还有什么

从 `0x4F4010` ctor 看：
```asm
0x4F4039  lea ecx, [edi + 0x128]   ; 构造 MMI+0x128 成员
0x4F4044  lea ecx, [edi + 0x230]   ; 构造 MMI+0x230 成员
```

★ ctor 只构造 `+0x128` 和 `+0x230`，**低区 `+0x00~+0x11F` 没有任何构造动作** ⇒ 全是 POD 字段（未初始化或 memset 0）。

⇒ **`+0x10` / `+0x18` / `+0x118` 是 MMI 的 POD 字段，MMI 自己不序列化它们，
   只被 `dwRoomMessageStartGame` 借用作为"透传块"。**

## §6 方法论

1. **★★★ 比较两个函数的 disp 集合前，必须先确认它们的 `this` 在对象内的偏移相同。** 否则 +8 的系统误差会让所有结论偏 8。
2. **★★ vtable 里的位置（`[edi]` vs `[edi+8]`）直接给出 `this` 偏移。**
3. **★★ ctor 只构造部分成员 ⇒ 未构造的偏移是 POD 字段。** `0x4F4010` 只构造 `+0x128`/`+0x230`，其余是 POD。
4. **★★★ 六卷（186→195）的教训：每一步"看起来对上"都要问"坐标系对吗"。** 194 卷的 +8 命中其实是坐标系错位造成的假阳性。
