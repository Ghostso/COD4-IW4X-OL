# 174 探讨 · "16 个候选写点"里有 11 个根本不存在的指令

## 一、我在 172 卷说了一句很没底气的话

> 「`[obj+0x21]` 运行时取值：16 个候选写点，无一可静态归属」

写这句话的时候我自己也奇怪：**一个结构体偏移，怎么会有"16 个候选"还定不下来？**

这一轮先做了一件很基础但上一轮跳过的事：**验证这 16 个是不是真的指令。**

## 二、11 个是假的

做法是：对每个候选地址，先找回它所在的函数起点（往前找 `CC CC CC` 填充后的第一条），**从函数起点开始反汇编**，再看候选地址是否落在某条指令的起始处。

结果：

```
0x004BF002  [Y] mov byte ptr [eax+0x21], cl
0x007343F5  [Y] mov byte ptr [eax+0x21], dl
0x00A6A72E  [Y] mov byte ptr [eax+0x21], cl
0x00B291D1  [Y] mov byte ptr [eax+0x21], bl
0x00C1A418  [N] 不在合法指令边界
0x00C1CA99  [N] 不在合法指令边界
0x00C4AE13  [Y] mov byte ptr [eax+0x21], 0xa
0x0197B226  [N] ...
0x0198313E  [N] ...
0x01987E5A  [N] ...
0x01EB2867  [N] ...
0x01EB3287  [N] ...
0x0359B63F  [N] ...
0x03C65364  [N] ...
0x03D5FF19  [N] ...
0x03D892A0  [N] ...
```

11 个是**错位反汇编出来的假指令**。原因很简单：我上一轮是在整个镜像上扫字节 `88 4x 21` / `C6 4x 21`，这种扫法会命中"某个立即数恰好等于这些字节"的地方。

而且剩下 5 个真指令里，`mov [eax+0x21]` 用的是 `eax`，而位流写器的 ctor 用的是 `esi`。**这 5 个不是我想要的那个类。**

所以答案不是"16 个候选里挑一个"，而是**"这 16 个全都不是"**。

## 三、换维度：按类找，不按偏移找

上一轮我是这么想的：「要找写 `+0x21` 的地方」。

这一轮改成：「**位流写器这个类是哪个？它的构造函数在哪？**」

线索来自 `0xB77B6E` 的 `mov [esi], 0xD59838` —— 这是 vtable 赋值，紧跟着就是 ctor 的返回。但 `0xB77B30` 里没有 `+0x21`。

于是我找 `0xD59834`（相邻的 vtable）：**`mov [esi], 0xD59834` 出现在 `0xB77924`**，而那个函数是 `0xB778E0`。

读下去：

```asm
0xB77917  mov  eax,[ebp+8]        ; 参数 1 = 位容量
0xB77924  mov  [esi],0xD59834     ; vtable
0xB7793D  call 0xB74220           ; alloc ceil(bits/8)
0xB77948  mov  al,[ebp+0xC]       ; ★ 参数 2
0xB7795B  mov  [esi+0x21], al     ; ★★★ 就是这里
```

**`+0x21` 是构造函数的第二个参数。** 一句话解决。

## 四、然后去看谁调它

两条房间入队路径：

```asm
; 0x62C380（族 A）
0x62C3A8  push 0
0x62C3AA  push 0
0x62C3AE  call 0xB778E0        ; ctor(this, 0, 0)

; 0x62C5A0（房间动作专用）
0x62C5EF  push ebx             ; ebx=0
0x62C5F0  push ebx
0x62C5F3  call 0xB778E0        ; ctor(this, 0, 0)
```

**都是 0。**

于是 `0xB77B10`（`cmp [ecx+0x21],0 / je ret`）在房间路径上**永远走 `je` 分支，什么都不写**。

169 卷说的"那个 `WriteBits(8)` 什么都不写"，**在房间路径上是对的** —— 它当时结论对、理由错（理由是"永远不写"，实际是"这个类在这个调用点传 0"）。

## 五、顺带多出来的一个发现

`0xB778E0` 里还有这一段：

```asm
0xB7795B  mov [esi+0x21], al      ; al = 参数2
0xB77962  cmp al, bl              ; bl = 0
0xB77964  je  0xB77970
0xB77969  ... mov byte [ebp-0xD], 0xFF   ; 非 0 → 写 0xFF
0xB77973  ... mov byte [ebp-0xE], 0x00   ; 为 0 → 写 0x00
0xB77977  call 0xB777C0           ; WriteBits(1, ...)
```

**`+0x21` 不是"零填充开关"，是"这一位写 0xFF 还是 0x00"的模式位。** 而且 ctor 自己就把这一位写进去了。

这说明 `0xD59834` 这个类比 `0xD59838` 多一个"布尔字段头"。房间路径用的是后者，所以没有这个头。

## 七、方法上真正学到的

**"候选太多、定不下来" 这个现象本身就是错误的信号。**

如果一个问题真有 N 个候选，通常说明：
- 要么 N 个里有 N-1 个是假的（这次就是）
- 要么我的查找维度错了（按偏移找 vs 按类找）

**先验证候选的存在性，再谈候选的取舍。** 上一轮我把 11 个不存在的指令当成了"候选"，然后说"无一可归属"—— 那句话听起来像严谨，实际上是没有验证。
