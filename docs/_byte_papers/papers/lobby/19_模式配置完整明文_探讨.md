## 三、转机：playlist 不是二进制

在 `CODOL_LOCAL_CHAIN_V2\publisher_files\` 找到了
`mp_playlists_shipRetail_1.0.0.info`（21,412 字节）。

开头两个字节：`78 9C`。

**这是 zlib 头。**

```python
zlib.decompress(data)  →  112,664 字节
```

**解出来的是文本，不是二进制。**

**这是游戏开发者的内部配置文件，连"改了要通知 Andre 或 Dan"都写在注释里。**

## 五、为什么这解决了核心问题

因为这里面有：

### `catinfo` —— 模式按钮表

```
catinfo 3   1   0  ""   "团队竞技"  "Team Deathmatch"
catinfo 5   1   0  ""   "人质模式"  "Hostage Mode"
catinfo 21  0   0  ""   "英雄行动"  "Hero Ops"
catinfo 30  0   4  ""   "塔防之战"  "Tower Defence"
...
```

- `Group` = 1 → 显示在 PvP 栏
- `Group` = 0 → 显示在 PvE 栏
- `Flag` = 1/2/4/8 → 推荐/内测/新品/轮换

**这就是"加按钮/删按钮"的开关。**

### `gametype` —— 模式定义

```
gametype tdm
name MPUI_TEAM_DEATHMATCH
script war
teambased
rule scr_game_playerwaittime 20
```

**`script war` = 这个模式调用哪个 GSC 脚本。**

## 六、这代表什么

| 用户要求 | 能否做到 | 怎么做 |
|---|---|---|
| 新增模式 | **能** | 加 `catinfo` + `gametype` |
| 删除模式 | **能** | 删 `catinfo` 行 |
| 添加按钮 | **能** | 加 `catinfo` |
| 删除按钮 | **能** | 删 `catinfo` 行 |
| 自定义页面 | **部分** | `catinfo` 控制模式列表；完整页面布局在 `ui_mp.ff`（加密） |

**最关键的四项（模式的增删改）全部不需要 AES 密钥。**

## 七、还剩什么不确定

### 不确定 1：磁盘 `.ff` 会不会覆盖服务端 `.info`

磁盘上有一个 `mp_playlists.ff`（49KB，AES 加密）。

如果客户端**优先读磁盘**，那改服务端就没有效果。
如果客户端**优先读服务端**，那改服务端就够了。

**这是一次实验就能确定的。**

### 不确定 2：`script war` 指向的脚本在哪

在 `code_post_gfx_mp.ff` 里（加密）。

**所以：改"模式列表和参数"不需要密钥，改"模式玩法逻辑"需要。**

---

## 八、方法论收获

> **"加密"往往是分层的。**
> 一份数据里，元信息（有哪些模式）可能是明文，内容（模式怎么玩）才是加密的。

我在 `.ff` 层卡了很久，因为那里确实全是 AES。

**但"有哪些模式、叫什么、怎么分组"这些元信息，走的是另一条路 —— playlist 配置。**

而 playlist 是 zlib 压缩的纯文本。

**这提醒我：不要假设"整个系统用同一种保护"。**
