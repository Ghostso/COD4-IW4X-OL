# 房间对象创建点 · 探讨：第一次追到"一个资源 ID"

> 对应：`lobby/45_房间对象创建点.md`

---

## 一、这一轮拐了一个大弯

**起点：** 想控制房间。

**中途：** 找到 25 个房间命令，发现它们都依赖一个空对象。

**终点：** 找到了创建这个对象的代码，以及它的**触发条件**。

```
0x639d03  push 0x3a128
0x639d08  call 0xc3e9f5      ; 查找
0x639d14  je   0x639d25      ; 没找到 → 存 0
0x639d19  call 0x62c000      ; 创建
0x639d1e  mov  [0x82e13fc], eax
```

**那个 `0x3a128` 是关键。**

---

## 二、为什么这个发现重要

**项目里有三条"对象为 0"的记录：**

1. `[0x82E1518]`（dwRoomMatchUber）
2. `MyEventHandler` 实例
3. `[0x82e13fc]`（房间对象）

**前两条都是"上层"。**

**这一条（`0x82e13fc`）是**最底层**：**

```
房间对象不存在
  ⇒ 房间成员/事件都不存在
  ⇒ dwRoomMatchUber 不会创建
  ⇒ MyEventHandler 不会实例化
```

**⇒ 修好这一个，上面两个可能自动解决。**

---

## 三、`0x3a128` 可能是什么

**从代码形态看：**

```
push 0x3a128
call 0xc3e9f5
test eax, eax
je   <跳过>
```

**这是"查找某个东西，找到才继续"的经典模式。**

**`0x3a128` = 241,960（十进制）。**

**可能性：**

1. **资源 ID**（在 zone 里的 asset 索引）
2. **字符串 ID**（本地化表索引）
3. **某个表的条目索引**

**第 1 种最可能：CoD 的 asset 系统用 32 位索引。**

---

## 四、如果这个资源缺失

**那说明：`.ff` 里少了一个 asset。**

**而 `.ff` 全都加密（`lobby/38`）。**

**⇒ 可能的原因链：**

```
.ff 解密失败
  ⇒ asset 0x3a128 不加载
  ⇒ 0xc3e9f5 返回 0
  ⇒ 房间对象不创建
  ⇒ 所有房间功能失效
```

**这是一条完整的因果链，把"`.ff` 加密"和"房间不可用"连起来了。**

---

## 五、但也可能有别的解释

**`0x3a128` 也可能不是资源，而是"某个标志检查"。**

**例如：**

```
if (某配置项 0x3a128 != 0) create_room_object();
```

**那 `0x3a128` 就是个 dvar 编号。**

**和前文的 `2486/2489/2500/2574/3265/2810` 同族。**

---

## 六、怎么区分

**`0xc3e9f5` 的实现：**

```asm
0xc3e9fa  sub esp, 0x10
0xc3e9fd  jmp 0xc3ea0c
0xc3e9ff  push [ebp+8]
0xc3ea02  call 0xc4b5b4
0xc3ea07  pop ecx
0xc3ea08  test eax, eax
0xc3ea0a  je  0xc3ea1b
0xc3ea0c  push [ebp+8]
0xc3ea0f  call 0xc3d280
0xc3ea14  pop ecx
0xc3ea15  test eax, eax
0xc3ea17  je  0xc3e9ff
```

**两个调用：`0xc3d280` 和 `0xc4b5b4`。**

**它们交替调用，直到某个返回非零。**

**这是"遍历一个容器，找匹配项"的形态。**

**不是 dvar 查表（那会是一次 strcmp）。**

**⇒ 更可能是"在资源表里找 asset 0x3a128"。**

---

## 七、方法论收获

> **追根因时，不要停在"对象不存在"，要问"谁该创建它"。**

项目里已经记录了三次"对象为 0"。

**但只有这次，往上追到了"创建代码 + 触发条件 + 具体参数"。**

**这个 `0x3a128` 是第一条可以动手验证的线索。**

---
