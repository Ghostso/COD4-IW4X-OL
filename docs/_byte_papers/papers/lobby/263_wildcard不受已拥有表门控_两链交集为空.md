# 263 · wildcard 不受"已拥有表"门控：两条消费链交集为空（闭合 259 的野生项）

> 卷次：263（第九轮·大厅黑箱扫荡）
> 承接：`259`（wildcard 表 `0x8269C60` 定名 + 遗留项 #5）/`253`（槽位解锁判据 `0x5E3550`）
> 方法：全库直接调用映射（`E8` 索引）+ 函数体可达性 + 调用者集合求交（带分母）

## §0 结论

**259 遗留的「wildcard 物品 `60178..60185` 是否会因不在已拥有表 `0x8269FC8` 而被锁」——
本卷以"两条消费链的调用者集合交集为空"给出否定答案（对该路径）。**

1. **★★★★★ 交集为空**：检查物品可用性的 `0x5E3760` 的调用者函数 = **54 个**；
   访问 wildcard 表 `0x8269C60` 的访问器（`0x80BD50`/`0x80BD80`）的调用者函数 = **5 个**
   （`0x5E4340` / `0x698D90` / `0x7DCEC0` / `0x7DD000` / `0x810EC0`）；
   **两者交集 = ∅**。⇒ **没有任何"物品可用性判定"函数碰 wildcard 表。**
2. **★★★★ wildcard 消费链做的是"索引 ↔ item"和"item → 角色分类"**，与"是否拥有"无关：
   - `0x80BD50(idx)→item`、`0x80BD80(item)→idx`（表 `0x8269C60`）；
   - `0x5E4340(item)` = 按物品类别 `[边+5] ∈ 0..13` 的**跳表分派**（跳表 `0x5E4768`，14 项）；
   - `0x80A450` = **`GetCurrentCharacterIndex()`**（读 cvar **`currentCharacterIndex`**，调用者 **123** 处）。
3. **★★★★ 修正 259 的担心方向**：`60178..60185` 不在 `0x8269FC8` **不通过这条路径造成锁定**。
   ⇒ 259 §3 的"槽位解锁"判据（`0x5E3550 → 0x8269FC8`）**不覆盖 wildcard**。
4. **★★ 由此得一个更一般的判据**：`0x5E3550`/`0x8269FC8` 只被 **`0x5E3760` 的 54 个调用者**使用；
   凡**不调用 `0x5E3760`** 的槽/物品类型，其"锁不锁"**不由已拥有表决定**。

| # | 证据 | 强度 |
|---|---|---|
| ① | `set(callers(0x5E3760) 的函数) ∩ set(callers(0x80BD50/0x80BD80) 的函数) = ∅` | ★★★★★ |
| ② | `0x80A450` 内 `push 0xDCAB98` = `"currentCharacterIndex"` | ★★★★★ |
| ③ | `0x5E4340` 跳表 `0x5E4768` 14 项（case 0..13） | ★★★★ |

## §1 ★★★★★ 交集为空（带分母）

```powershell
python -I _rev_analysis/_p259/a53_intersect.py
```
```
0x5E3760 caller funcs: 54
wildcard accessor caller funcs: ['0x5e4340','0x698d90','0x7dcec0','0x7dd000','0x810ec0']
intersection: []
```

**分母齐备**：不是"没找到"，而是**两个集合各列出全部成员，交集机械为空**。
这与 253 卷「徽章表 4 读点 / 已拥有表 18 写点，地址区间零重叠」是**同一类机械判据**
（"用集合运算代替形状猜测"）。

### 1.1 为什么这直接回答 259 的遗留项

259 §3 已定：**「该槽位解锁」⟺「所需 item 已拥有」**，落到
`0x5E3550(item) → 0x80A5E0(item) → 0x8269FC8`。
259 遗留项 #5 担心：wildcard 的 item（`60178..60185`）**不在 `0x8269FC8`**，
那它们会不会被"同一条判据"锁掉？

**答案：这条判据的入口函数是 `0x5E3760`。wildcard 的消费链一次都不进 `0x5E3760`
（交集 ∅）⇒ 它根本没走到那条判据 ⇒ 不会因此被锁。**

## §2 ★★★★ wildcard 消费链到底做什么

| 访问器/函数 | 行为 | 调用者 |
|---|---|---|
| `0x80BD50(idx)` | 表 `0x8269C60`：**索引 → item** | `0x698D90` `0x7DCEC0` `0x810EC0` |
| `0x80BD80(item)` | 表 `0x8269C60`：**item → 索引**（未找到返 8） | `0x5E4340` `0x698D90` `0x7DCEC0` `0x7DD000` |
| `0x80BDC0()` | 单条 `0x8269FBC`（`defaultknife_mp`，item 12243） | `0x61A2C0` |
| `0x5E4340(item)` | 按 `[item+5] ∈ 0..13` **跳表分派**（`0x5E4768`） | `0x698D90`（+自身） |
| `0x80A450()` | **`GetCurrentCharacterIndex()`**（cvar `currentCharacterIndex`） | **123** 处 |
| `0x80BBF0(...)` | 从源表（`0x8269B6C`/`0x8269F80`/`0x826A974`）批量解码 item | `0x61A2C0` |

**⇒ 链语义 = "wildcard 索引 ↔ item ↔ 当前角色 → 归类"，全程不读已拥有表。**
调用者字符串也印证：`0x7DCEC0` 含 `onboard_ch_equip_wld`（角色装具/wildcard）、
`0x810EC0` 含 `secondary`/`let2` —— **都是"装备/角色配置"面，不是"拥有/购买"面。**

## §3 ★★★★ `0x5E4340` = 物品类别分派；`0x80A450` = 当前角色号

```asm
0x5E4340  movzx eax, byte [eax + 5]    ; 物品类别字节
0x5E4370  cmp   eax, 0xd / ja 出口
0x5E4379  jmp   [eax*4 + 0x5E4768]     ; ★ 14 项跳表（case 0..13）
```
跳表 `0x5E4768` 逐项：`0→0x5E4380（默认/主武器族）`，`1→0x5E46E0`，`2/3→0x5E44A2`，
`4→0x5E44B2`，`5..13→0x5E4568/45AD/45E9/4625/4681/4694/46A7/46BA/46CD`。
**⇒ `0x5E4340(item)` = 「该 item 属于哪个角色/装备类别」**（14 类），
每个 case 用 `0x80A450()`（当前角色号）做匹配。

```asm
0x80A450  mov ecx,[0xE567C0]           ; 缓存值
0x80A456  push esi
0x80A457  mov esi,[0x849B62C]
0x80A45D  cmp ecx,-1 / jne 0x80A4A5
0x80A462  push 0 ; push 0xDCAB98       ; ★ "currentCharacterIndex"
0x80A469  call 0x512120                ; cvar 查询
0x80A473  mov [0xE567C0],ecx           ; 缓存
```
**⇒ `0x80A450()` = `GetCurrentCharacterIndex()`（带缓存，123 个调用者）。**

## §7 方法论

1. **★★★★★ 「交集为空」要带分母。** 本卷不是"我没找到同时调两者的函数"，
   而是**两个调用者集合各列全成员、机械求交 = ∅**。**"没找到"与"证明没有"的差别，
   就在于有没有把两边的全集摊开。**
2. **★★★★ 一个判据的"覆盖范围 = 它的入口函数的调用者集合"。** 253 定的解锁判据
   入口是 `0x5E3760`；**它的适用边界就是这 54 个函数**，不在这 54 个里的槽类型
   不能套用该判据。**判据要连同"它管哪些调用点"一起交付，否则会被外推。**
3. **★★★ 函数身份靠"它读的常量"定。** `0x80A450` 读字符串 `currentCharacterIndex`
   ⇒ 名字立刻确定；**在无符号的函数里，内嵌 cvar/dvar 名字字符串是最省力的身份锚。**
