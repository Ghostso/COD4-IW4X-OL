## 「正式副本」是个陷阱

任务说「核验是否已在正式副本落地」。一查才发现：
- `REF_LOBBY_KIT`（AGENTS.md 里点名的受保护 kit）：21 字段，**没落地**。
- 在修谱系（跑到一半的 kit）：19 字段，**已落地**。
- `CODOL_VERIFIED_GOLDEN_20261019`（`run_frozen_chain_once.py` 的默认启动 kit）：**文件都没有**。

所以「落地了吗」这句话，不指明副本就没有答案。这正是大厅线当前最大的工程隐患：**没有一个被所有工具认为是"当前版本"的副本**。

## 三条告警里最要命的是第三条

哈希过期（4.1）和三方版本（4.2）都只是「乱」；第三条（GOLDEN 缺 market_skus.py）是「默默坏」：
`run_frozen_chain_once.py` 复制 CORE 文件时用 `if (kit/n).is_file()`，**缺文件不报错**。于是一份「看起来完整」的启动 kit，实际上 `import market_skus` 会失败。这类「白名单里有、目录里没有」的缺口，靠日志很难发现（表现为 SKU 页静默回兜底）。

**建议**：把「CORE 文件是否都存在」做成 `run_frozen_chain_once.py --verify-only` 的一部分（现在只验受保护哈希，不验 CORE 齐全）。
