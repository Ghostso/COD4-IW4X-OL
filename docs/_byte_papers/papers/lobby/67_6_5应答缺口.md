# `6/5` 的应答缺口：服务端从未返回过排队消息

> 承接 `lobby/66`
> 这一卷把"位流通道"的推论落到服务端实现上核对。

---

## 1. 服务端现状（`lobby_server.py`）

**`service == 6` 的处理：**

```python
if service == 6:
    if task in (5, 14, 18):
        body = plain or b""
        if re.search(rb"mmbook[^\x00]{0,120}", body):
            # 推 "mmbook accepted"
        m = re.search(rb"mmstart[^\x00]{0,512}", body)
        if m:
            # 记录 map/gametype
        ...
```

**`6/5` 的实际处理：**

```python
if task == 5:
    return ack("0B/5 publishChannelMessage 空应答")
```

**⇒ `6/5` 返回**空 ACK**，从不返回队列内容。**

---

## 2. 这是一个纯粹的"功能缺失"

**`6/5` 的请求是明确的：**

```
(offset=0, maxResults=20, consume=true)
```

**⇒ 客户端在问："给我从 offset 0 起的最多 20 条排队消息。"**

**服务端回答：`00`（空）。**

**⇒ 客户端会认为"队列为空"。**

---

## 3. 结合位流通道的推论

**`lobby/66` 发现两套序列化：**

| 体系 | 格式 |
|---|---|
| ByteBuffer | TLV（`08`/`13`/`10`） |
| 位流 | 3 位类型 + var |

**`dwRoomMessage` 系列用位流。**

**⇒ 如果 `6/5` 应该返回排队消息，它的应答体应该是**位流**，不是 TLV。**

**⇒ 当前服务端回 `ack(...)`（空 TLV），格式就不对。**

---

## 4. 正确的应答应该是什么

**根据 `dwRoomMessageManifold::serialize`（`0x625520`）：**

```
3 位   类型码（写死 3）
8 位   [obj+4]
8 位   字段标签
32 位  [obj+0x10]
1 位   链表非空
       → 遍历链表
```

**⇒ 一条 `6/5` 应答应该是一个 Manifold 位流，
里面装着 N 条 `dwRoomMessage`。**

---

## 5. 但我们还不知道两件事

### 未知 1：`8 位` 的字段标签是什么

**`Manifold` 写死 `8`，`StartGame` 在第二个字段用的是 `0x13`。**

**⇒ 这个字段是"字段类型码"，不同消息不同。**

**⇒ 需要反汇编几条不同的 serialize 才能确定编码表。**

### 未知 2：位流的容器格式

**`writeBits` 写入的是"位"，最终怎么变成字节？**

**⇒ 需要看 `0xb77b10` 的实现和它的 flush。**

---

## 6. 这一条链的完整状态

| 环节 | 状态 |
|---|---|
| 客户端请求 `6/5` | 完全解出（13 字节） |
| 服务端处理 | **空 ACK（缺失）** |
| 应有格式 | **位流 + Manifold** |
| Manifold 序列化 | 已解出（`0x625520`） |
| 位流写入器 | 已定位（`0xb77b10`） |
| 消息类型码表 | **未知** |
| 位流容器/flush | **未知** |

**⇒ 从"完全不知道"到"缺两张表"。**

---

## 7. 这两张表的获取方法

### 类型码表

**反汇编 `dwRoomMessage::deserialize`（`0x627ce0`）——
它是基类的读取器，会有类型分派。**

### 位流容器

**反汇编 `0xb77b10` 及其调用者，
看写满一字节/一段后如何处理。**
