## §1 根因：2 个插入字段使后续全部错位

### 1.1 三张表逐字段对照

| # | 权威 `SKU_AS_FIELDS` | 旧 `_sku_obj`（21） | `probe._v1`（19, tested_ok） |
|---|---|---|---|
| 1 | name (String) | name | name |
| 2 | id (int) | id | id |
| 3 | promoSkuId | promoSkuId | promoSkuId |
| 4 | cp | cp | cp |
| 5 | cc | cc | cc |
| 6 | duration | duration | duration |
| 7 | **stackable (Boolean)** | **`b.u8(0)` ← 多插！** | stackable |
| 8 | productId | stackable | productId |
| 9 | requirementLevel | productId | requirementLevel |
| … | …（全部后移 1 位）… | … | … |
| 16 | **couponEnable** | currency | couponEnable |
| 17 | ignoreEntitlement | couponEnable | ignoreEntitlement |
| 18 | **indexInProduct (uint)** | **`b.u32(0)` ← 多插！** | indexInProduct |
| 19 | ignoreDiscount | ignoreEntitlement / indexInProduct / ignoreDiscount | ignoreDiscount |

★ **第一个插入使 #7..#17 全部后移一位；第二个插入使 #18..#19 再后移一位。**

### 1.2 为什么这会「打挂整个服务」

DML 编码是 `[tag][value]` 逐值流，客户端**逐值做类型检查**（`codol_crypto.py:260` 已有实证：把 I32(0x07) 写成 U32(0x08) 会被拒）。

字段一错位，**后面每个位置的 tag 都对不上预期类型**。160 卷记录的实测现象：

> 只发 3 条自编 SKU 就把整个 marketplace 服务打挂：仓库/商城全变红色叹号、角色被锁、所有按钮点不动。

### 1.3 两个插入为什么没有依据

旧代码自己的注释写的是：

```python
b.u8(0)   # extra u8 in CODOL bdMarketplaceSku! (0x03)
b.u32(0)  # extra u32 in CODOL bdMarketplaceSku! (0x08)
```

**"CODOL 比 MW19 多两个字段"这句话是对的**（160 卷也提过），但**插入位置是凭推测的**——`_sku_schema_as.SKU_AS_FIELDS` 说得很明确：这个客户端认的就是 **19 个字段**，`pos` 值 130..713，没有空位。

★ **"多两个字段"与"19 字段表"矛盾时，应以**内存实测的 19 字段表**为准。**

## §2 修复

### 2.1 `market_skus._sku_obj()`：21 → 19

删除两个插入字段，字段顺序严格回到 `_sku_schema_as.SKU_AS_FIELDS`。类型映射：

| AS3 类型 | DML tag | 字段 |
|---|---|---|
| String | `0x10` | name |
| int | `0x07` | id, requirementLevel, requirementPrestige |
| uint | `0x08` | indexInProduct |
| Boolean | `0x01` | stackable, purchasable, couponEnable, ignoreEntitlement, ignoreDiscount |
| （语义推定为 u8） | `0x03` | currency |
| （其余数值） | `0x08` | promoSkuId, cp, cc, duration, productId, requirementUnlockFlag, originalPrice, price |

### 2.2 `lobby_server.py`：去掉「强制回退空页」

旧代码在 `marketplace-skus.on` 存在时仍**强制回空页**，除非额外存在 `marketplace-skus-allow-unsafe.on`：

```python
# 旧
if os.path.exists(...allow-unsafe.on):
    ...发 SKU 页...
return ack("...SKU 页已禁用(上次自编格式打挂服务)")
```

修复后：`marketplace-skus.on` 存在即发 19 字段页，数量由 `marketplace-skus-count.txt` 控制（本次保守 = 1）。

**回滚**：删除 `kit/marketplace-skus.on` 立即回到空页行为。

## §7 方法论

1. **★★★★★ 「多两个字段」这类说法必须落到位置。** 数量对、位置错 = 全错。`_sku_schema_as.SKU_AS_FIELDS` 的 `pos` 序列（130,156,177,…）连续无空位，直接否证了"中间还有两个字段"。
2. **★★★★ 同一个仓库里存在两份编码实现时，先找出哪份有验证标记。** `probe._v1` 带 `.tested_ok`，`_sku_obj` 没有——**证据权重不同**。
3. **★★★ 修复必须带「旧版对照组」。** 校验器能判旧版错，才说明它有用。
4. **★★ 「修复」与「验证」要分开声明。** 本卷做到了"字段不再错位"（可验证），**没有**做到"UI 能渲染"（不可验证，缺样本）。
