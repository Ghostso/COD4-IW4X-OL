# 房间命令 handler 链 · 探讨：又是同一个"对象不存在"

> 对应：`lobby/44_房间命令handler链.md`

---

## 一、我以为找到了一条新路

发现 13 个 `room.*` 命令，我第一反应是：

> "如果能在 UI 脚本里 `exec room.changemap`，不就能绕过大厅 UI 了吗？"

**然后我追了 handler：**

```asm
room.startgame:
    mov ecx, [0x082e13fc]     ← 房间对象
    mov eax, [ecx]
    jmp [eax+0x38]

room.changemap:
    mov ecx, [0x082e13fc]     ← 同一个
    mov eax, [ecx]
    jmp [eax+0xC0]
```

**两条命令都依赖同一个全局指针。**

---

## 二、那个指针是 0

```
[0x082e13fc] = 0x00000000
```

**⇒ 调用会解引用空指针。**

---

## 三、这和项目已有的结论撞上了

项目里已经有一条记录（`codol-myhandler-never-created-root-cause`）：

> `dwRoomMatch::Init` 的 MyEventHandler 实例数 = 0
> ⇒ 建房回调永不触发

还有一条（`codol-dwroommatchuber-never-created`）：

> `[0x082E1518] = 0`

**现在是第三个独立的 0：`[0x082e13fc] = 0`。**

**三个不同的地址，指向同一件事：房间子系统从未初始化。**

---

## 四、这次的价值：多了一条路径的证据

**之前的证据都是"回调没触发"、"对象没实例化"。**

**这次是"命令存在、handler 正确、但对象为 0"。**

**⇒ 即使你直接调命令，也会崩。**

**这是一条被排除的"绕过路径"。**

---

## 五、真正的瓶颈

**整个项目卡在同一个点：**

```
房间对象不存在
  ⇒ 房间命令不能用
  ⇒ 房间事件不会来
  ⇒ 建房回调不触发
  ⇒ 自动开局链不跑
```

**所有具体表现（大厅卡、剧情不开始、room.startgame 无效）
都是这一个根因的分支。**

---

## 六、302 处引用

```
[0x082e13fc] 被 302 处代码引用
```

**这是"中心对象"的标志。**

**⇒ 找到"谁写它"，就找到了整个房间子系统的入口。**

**这也是下一轮房间逆向最该做的事。**

---

## 七、诚实地说

这一轮：
- ✅ 找到了 25 个房间/队伍命令
- ✅ 提取了 4 个 handler 地址
- ✅ 证明了它们都依赖同一个空对象
- ❌ 没有找到"谁应该创建这个对象"

**但"排除一条绕过路径"本身是有价值的：
它说明不能靠调命令绕过，必须修好初始化。**
