## 4. 两个日志格式串（重要）

### `MatchMakingJoin`

```
MatchMakingJoin|%s|%u|%d|%llu|%llu|%llu|%d|%d|%d|%d|%d|%d|%d
```

**12 个字段：**

| # | 格式 | 推测 |
|---|---|---|
| 1 | `%s` | 事件名 |
| 2 | `%u` | ？ |
| 3 | `%d` | ？ |
| 4-6 | `%llu` ×3 | 三个 64 位 ID |
| 7-12 | `%d` ×6 | 六个 32 位 |

**与 `mmstart` 的 6 个数字 dvar（2486/2489/2500/2574/3265/2810）
数量完全一致！**

**⇒ 那 6 个数字很可能就是这 6 个 `%d`。**

### `MatchMaking`

```
MatchMaking|%s|%u|%llu|%llu|${CODOID(%llu)}|%d|%s|%d|%d|${ZONE...
```

**含 `CODOID` 和 `ZONEID` 模板，是给日志系统的。**

## 7. ★ 这些命令怎么用

**它们是**控制台命令**（`Cmd_AddCommand` 注册）。**

**调用方式（按项目已有记录）：**

1. **游戏内控制台**（需要开启，本 build 无 `sv_cheats`）
2. **UI 脚本内置函数**（`0x00DAA400` 表里的 `exec`）
3. **UI 脚本的 `open` / `setdvar`**

**⇒ 如果能在 UI 脚本层面调 `room.changemap`，
就能绕过大厅 UI 直接换地图。**

## 9. 对"完全控制房间"的意义

**这 13 个 `room.*` + 8 个 `party.*` + 4 个 `room.match.*`
构成了一套完整的房间/队伍操作 API。**

**如果能调用它们（例如通过 UI 脚本），
就能：
- 直接建房间（绕过 UI）
- 直接换地图
- 直接开始游戏
- 直接管理成员**

**这是比"改 playlist"更底层的控制。**
