## §1 为什么要做这一步

144 卷我做的是**读内存**：从 dump 的 regions 里挑地址读字段。这不是脱壳。

**脱壳的定义**：产出一个可被静态工具完整加载的模块镜像。

| | 144（读内存） | 146（脱壳） |
|---|---|---|
| 产物 | 若干字段值 | **一个 230 MB 的 PE 文件** |
| 可复用性 | 每次都要写读取脚本 | 任何工具直接加载 |
| 覆盖 | 按需读取 | **模块镜像 100%** |
| 节表 | 不涉及 | 已修正 `RawSize := VSize` |

### 2.2 铺数据

按 `DUMP_20261031_194250` 的 381 个 regions，把每块数据写到 `img[base - ImageBase]`。

**结果：铺入 230.3 MB / 230.3 MB（100.0%）。**

每段 `SizeOfRawData := align(VirtualSize, 0x200)`，`PointerToRawData` 重新排布。

**⇒ 内存态被"冻结"成文件态，RVA 映射保持 1:1。**

## §6 诚实边界

1. **导入表未重建** —— 节表已修正，但 `.idata2` 的 IAT 仍指向原位置；
   若要 IDA/Ghidra 完整识别，还需重建 IAT 与重定位。
2. **`.tp3#3` 的熵只有 1.276** —— 大部分是 0（BSS 未初始化区），
   不是"没解开"，而是"本来就没数据"。
3. **脱壳 PE 依赖特定进程的运行时状态**（如 `0x84ABB14 = 0x397D4FD0`），
   **不是"干净的"静态镜像**——全局变量里是那次运行的堆地址。
4. **未做 OEP 识别** —— 这是"内存镜像冻结"，不是"从入口点开始的重建"。
5. **`.reloc` 段在磁盘 exe 里没有**（7 段里无 `.reloc`），
   重建时未处理重定位。

## §8 方法论

1. ★★★★★ **"读内存"≠"脱壳"** —— 脱壳的产物必须是一个可加载的完整 PE。
2. ★★★★ **先评估覆盖率再动手**：`99.6%` 说明 dump 足够，`4.57%` 说明不够。
3. ★★★★ **磁盘 exe 的 PE 头可以复用**，只需改节表 RawSize/RawPtr。
4. ★★★ **熵 + `0xCC` 比例是"解没解包"的机械判据**：7.140/0.22% vs 6.761/3.57%。
5. ★★★ **重建后必须与已有镜像逐字节比对**，确认没有搬错。
