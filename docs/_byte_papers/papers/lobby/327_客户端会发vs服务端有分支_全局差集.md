## §1 方法：参数顺序是怎么定死的（不是抄旧卷）

### 1.1 `0xBA72C0 = TaskBuilder`（4 个栈参 + ecx=this）

入口反汇编（s1_prologue.py）：

```
00BA72C0  push ebp / mov ebp,esp / ...             ; SEH 帧
00BA72E6  mov esi, ecx                             ; esi = this
00BA72EB  mov ecx, [ebp+0x10]
00BA72EE  mov edi, [ebp+0x14]
00BA72F3  mov [esi+4], ecx
00BA72F6  mov [esi+8], edi
00BA7306  mov dl, [ebp+0x8]      ; ★ 参数1（第 2 个实参）
00BA7309  mov [esi+0x1c], dl     ;   -> +0x1C
00BA730C  mov dl, [ebp+0xc]      ; ★ 参数2（第 3 个实参）
00BA7318  mov [esi+0x1d], dl     ;   -> +0x1D
```

**调用约定 = 4 个栈参、从右往左压**，故调用点压栈顺序为
`push a4; push a3; push task; push service; lea ecx,<this>; call`。

**已知样本定标**（`0xB86AE8`，232/233 卷记的 svc80/task70）：

```
00B86AEE  push 0x80000     ; a4
00B86AF3  push 0x400       ; a3
00B86AF8  push 0x46        ; = 70  -> task
00B86AFA  push 0x50        ; = 80  -> service
00B86AFC  lea  ecx,[ebp-0x48]
00B86AFF  call 0xBA72C0
```

⇒ **`svc = 最后一个立即数 push`，`task = 倒数第二个`**。定标通过。

### 1.2 `0xB78C10 = WriteTaskHeader`（cdecl，3 个栈参）

```
00B78C14  mov esi,[ebp+8]      ; holder
00B78C17  mov ecx,[esi]
00B78C19  push 1
00B78C1B  lea  eax,[ebp+0xc]   ; &参数1
00B78C1E  push eax
00B78C1F  call 0xB75E00        ; 原始追加：[ebp+0xc] 按原样写 1 字节
00B78C24  mov ecx,[ebp+0x10]   ; 参数2
00B78C27  push ecx
00B78C28  mov ecx,[esi]
00B78C2A  call 0xB76620        ; DML 标签写
```

`0xB76620` 内部：`push 3` → `0xB75F30(3)`，然后
`mov al,[ebp+8](=参数2) / mov [ebp+0xb],al / call 0xB75E00`。
而 `0xB75F30(3)` 在 `[ecx+0x18] != 0` 时以值 **3** 调 `0xB75E00`。

⇒ **参数1 = 原始字节（= task，无标签）；参数2 = DML 标签 3 的 u8（= service）**。
调用点压栈 `push task; push service; push holder; call`——**同样 `svc=最后一个立即数 push`**。

### 1.3 两个函数的差异（这是本项目"口径统一"的关键）

| 函数 | 签名 | 栈参个数 | `svc` 位置 | `task` 位置 |
|---|---|---|---|---|
| `0xBA72C0` TaskBuilder | `(this, svc, task, a3, a4)` | 4 | 最后立即数 push | 倒数第二 |
| `0xB78C10` WriteTaskHeader | `(holder, task, svc)` | 3 | 最后立即数 push | 倒数第二 |

**两者在"最后/倒数第二"这一层上同口径**——因为 TaskBuilder 的 `svc` 是**第 2 个实参**
（`[ebp+8]`），而 WriteTaskHeader 的 `svc` 是**第 3 个实参**（`[ebp+0x10]`），
都恰好是"倒数第一个被压的立即数"。这个巧合不能外推，只能靠逐函数读入口确定（§4 方法论）。

### 2.1 4 处必须手工解的点（全给了机器指令）

**① `0xB89BA6`（svc 71, task 双分支 3|7）** —— 指令流从中间起解会错位，必须从 `0xB89B6A` 读：

```
00B89B88  cmp byte ptr [ebp+0x14], 0
00B89B91  sete al
00B89B9C  lea  eax,[eax*4+3]     ; eax=0 -> 3 ; eax=1 -> 7
00B89BA3  push eax               ; task
00B89BA4  push 0x47              ; service = 71
00B89BA6  call 0xBA72C0
```
⇒ **`71/3` 与 `71/7` 同源一条指令**，靠 `[ebp+0x14]` 真假二选一。

**② `0xB84824` / `0xB849B4` / `0xB84DB4`（svc 9，task 由 `bl` 二选一）**

`0xB84824`: `00B847FD mov bl,0xc` → `00B8480C mov bl,0x20`（条件）→ `00B8481E push edx` → `00B8481F push 9`
⇒ task ∈ **{12, 32}**。
`0xB849B4`: `mov bl,0xe` / `mov bl,0x21` ⇒ task ∈ **{14, 33}**。
`0xB84DB4`: `mov bl,5` / `mov bl,0x1e` ⇒ task ∈ **{5, 30}**。

**③ `0xB8DAB8`（svc 93，task `neg/sbb/and 0x7f/add 4`）**

```
00B8DA91  neg bl / sbb bl,bl / and bl,0x7f / add bl,4
00B8DAA0  movzx ecx,bl
00B8DAA8  push ecx       ; task
00B8DAA9  push 0x5d      ; service = 93
00B8DAB8  call 0xBA72C0
```
`bl=0` ⇒ `neg 0`(CF=0) `sbb bl,bl`=0 ⇒ `0+4` = **4**；
`bl≠0` ⇒ `neg`(CF=1) `sbb` ⇒ `0xFF`，`and 0x7f`=0x7F，`+4` = **0x83 = 131**。
⇒ **93/4 与 93/131 同源**。

**④ `0xBA0151`（svc 29，task 动态 `[ebp-0x1c]`）** —— 已标 `29/0` 为占位，
**这一条我明确标"低置信"**：`push [ebp-0x1c]` 才是 task，值不在本函数内定，需要追上游调用者。

### 2.2 已知的两个"自转发"点（不计入服务面）

`0xBA4AF5` 与 `0xBA7415` 是 `0xBA72C0` 自身的 ctor/dtor 路径里回头调 `0xB78C10`
`(holder=[esi], task=[esi+0x1d], svc=[esi+0x1c])` —— 即"把已建好头的对象再刷一遍"，
**不产生新的 `(svc,task)` 组合**，从集合里剔除（否则会把 `[esi+0x1c]` 的任意值当成服务号）。

## §8 方法论（本卷新增/复核的教训）

1. **「最后立即数 push」不能当通用规则**：TaskBuilder 的 svc 是第 2 实参、WriteTaskHeader 的
   svc 是第 3 实参，**只是因为压栈从右往左才看起来一致**。必须逐函数读 `[ebp+8/0xc/0x10]`
   的落地字段（`+0x1c`/`+0x1d`）。
2. **反汇编窗口不能"往前取 N 字节"**：s4b 第一版全部失败，因为 `md.disasm(blob[st:x])`
   **不含 x 本身**，窗口末条永远不是 call。改成 `blob[st:x+6]` 后 86/88 立刻解出。
3. **指令流中间起解会产生假指令**（`0xBA4AF5` 处出现 `sal byte ptr [esp+ebx-0x7d]`）——
   这正是 `0xB89BA6` 一开始 `noseq` 的原因。**凡 `noseq` 一律换更早起点重解，不放弃**。
4. **我在 §6 曾把 `28/4` 和 `80/150` 混为一谈**（两个都是 `push 0x96 / push 0x50` 附近），
   写清站点号后才分开。**教训：差集表的每一条必须带"站点地址"，不能只带 `(svc,task)`**——
   本卷所有数字都可由 `client_send.json` 的 `detail` 逐站点回查，已满足该要求。
5. **校验方向要双向**：只统计"实测 ⊂ 静态"不够（可能静态集过大），
   必须同时报"静态集里哪些**本轮真发了**"——本卷 39/39 与 20 对实发都列了分母。
