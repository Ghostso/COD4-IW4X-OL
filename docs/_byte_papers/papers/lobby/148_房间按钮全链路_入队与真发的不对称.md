# 148 · 房间按钮全链路：从 Flash 到「入队 vs 真发」的不对称

> 前序：147（消息泵 this=srpc）、146（真脱壳）、136（62 个 Flash 回调）
> 性质：**用脱壳 PE 做的前端（出站）全链路分析**。本卷首次打通
> **「用户点按钮 → 客户端构造消息 → 送往何处」**，并发现**两条路径的不对称**。

---

## §0 十二条结论

1. ★★★★★ **房间动作的 `AS_*` 回调全部存在**（33 个相关），包括
   `AS_SetReadyState` / `AS_ChangeTeam` / `AS_VoteMap` / `AS_StartMatch` /
   `AS_ChangeRoomInfo` / `AS_ChangeRoomOptions` / `AS_CurrentPlayerCanVote`。
   **⇒ 按钮不是"没回调"。**
2. ★★★★★ **按钮路径完整打通**（以"准备"为例）：
   ```
   Flash 按钮
    → AS_SetReadyState handler 0x7CF850
       0x7CF859  mov ecx,[0x82E13FC]     ; ★ 房间对象
       0x7CF865  mov eax,[eax+0x84]      ; vt[33]
       0x7CF86C  call eax
    → dwRoomImp::vt[33] = 0x6301A0
       0x6301AE  type = 0x10             ; dwRoomMessageReady
       0x6301B5  vtable = 0xDC7624
       0x6301BF  call 0x62C5A0           ; ★ 入队
   ```
3. ★★★★★ **`[0x82E13FC]` = `dwRoomImp` 实例**（vtable `0xDC7274`，
   RTTI `.?AVdwRoomImp@@`），**三个 dump 全部非 0**。
4. ★★★★ **`AS_ChangeTeam` 有短路**：`0x630778 cmp/je` —— **新阵营 == 当前阵营则不发送**。
5. ★★★★★ **`0x62C5A0` 是「入队」**：`add edi, 0x3A098` → `0x654CD0` 查容器 →
   分配 0x24 → `0x62C63D` 调消息自己的 `vt[0]` 序列化 → `0x654BF0` 插入。
6. ★★★★★ **`0x62C870(kind=4)` 是「真发」**：内部 `0x62C93D → 0x7E8300`（网络）。
7. ★★★★★ **★★ 两条路径不对称 ★★**：
   | 消息 | 路径 | kind |
   |---|---|---|
   | 房间动作（Ready 0x10 / ChangeTeamRequest 0x15）| `0x62C5A0` | **入队** |
   | 状态广播（StartGame 0x3 / MemberInfoAdd 0xA）| `0x62C870` | **4 = 真发** |
8. ★★★★ **`0x6345xx` 是「房间状态广播」函数**：遍历 `+0x7470` 的 MatchMakingInfo 数组，
   构造 `dwRoomMessageStartGame`（vtable `0xDC751C`）、
   `dwRoomMessageMemberInfoAdd`（vtable `0xDC7540`），用 `kind=4` 真发。
9. ★★★★ **`0x6330xx` 遍历 `dwRoomImp+0x3A098`**，对每条消息用 `byte[+0x10..0x13]`
   算 **FNV-1a（`0x1000193`）** 查桶表（`+0x3A0A8`，容量 `+0x3A09C`）—— **本地分发**。
10. ★★★ **`dwRoomImp` 有三组容器**：`+0x3A098`（入队哈希表）、`+0x3A0D4/0x3A0D8`（链表）、
    `+0x3A100..0x3A118`（另一组，含时间戳队列）。
11. ★★★ **`0x6331BD` 之后处理 `+0x3A118`**：带时间戳、环形缓冲 `0x400/条`、
    容量 `0x200`，溢出时打 `EXE_ERR_CLIENT_CMD_OVERFLOW`。
12. ★★★ **`0x62C5A0` 全镜像只有 4 个调用者**：`0x630127` / `0x6301BF` / `0x63078F` / `0x63088F`
    —— **全部是 `dwRoomImp` 的"房间动作"虚函数**。

## §2 按钮路径逐字节（"准备"为例）

### 2.1 Flash → handler

```asm
0x7CF850  push ebp / mov ebp,esp
0x7CF853  mov edx,[ebp+8]              ; 参数（AS 的 this）
0x7CF856  mov edx,[edx+0x10]
0x7CF859  mov ecx,[0x82E13FC]          ; ★★★ 房间对象
0x7CF85F  movzx edx, byte [edx+0x10]   ; 准备状态
0x7CF863  mov eax,[ecx]                ; vtable
0x7CF865  mov eax,[eax+0x84]           ; ★ vt[33]
0x7CF86C  call eax
```

### 2.2 dwRoomImp::vt[33] = `0x6301A0`

```asm
0x6301A6  mov al, byte [ebp+8]          ; 准备状态
0x6301AE  mov dword [ebp-8], 0x10       ; ★ type = 0x10 (Ready)
0x6301B5  mov dword [ebp-0xC], 0xDC7624 ; ★ vtable dwRoomMessageReady
0x6301BC  mov byte [ebp-4], al
0x6301BF  call 0x62C5A0                 ; ★★★ 入队
```

### 2.3 `AS_ChangeTeam` handler `0x7CFB80`

```asm
0x7CFB86  mov ecx,[eax+0x10]
0x7CFB89  mov eax,[ecx+0x10]
0x7CFB8C  test eax,eax / jns           ; 阵营值归一化
0x7CFBA6  mov ecx,[0x82E13FC]          ; ★ 同一个房间对象
0x7CFBAF  mov eax,[edx+0xB0]           ; ★ vt[44]
0x7CFBB5  call eax
       ↓
0x630760  mov esi,ecx
0x63076B  mov edx,[eax+0xAC]           ; vt[43] = 取当前阵营
0x630771  call edx
0x630776  cmp ecx,eax
0x630778  je  0x630794                 ; ★★ 相同阵营 ⇒ 不发送
0x63077E  mov dword [ebp-8], 0x15      ; ★ type = 0x15 (ChangeTeamRequest)
0x630785  mov dword [ebp-0xC], 0xDC7654
0x63078F  call 0x62C5A0                ; ★★★ 入队
```

## §3 入队 vs 真发（本卷核心）

### 3.1 入队 `0x62C5A0`

```asm
0x62C5B4  mov edi,[ebp+8]              ; 消息对象
0x62C5BF  add edi, 0x3A098             ; ★ 容器基址
0x62C5D4  call 0x654CD0                ; 查/插入
0x62C5E1  push 0x24; call 0xB74220     ; 分配 0x24
0x62C632  mov edx,[esi]                ; 消息 vtable
0x62C63D  call edx                     ; ★ vt[0] = 自身序列化
0x62C651  call 0x654BF0                ; 插入容器
```

**⇒ 只入本地容器，不碰网络。**

### 3.2 真发 `0x62C870(kind=4)`

```asm
0x62C93D  ...                          ; 内部调用
0x7E8300  ★ 网络发送（全镜像唯一调用者在此）
```

**调用者 `0x634626`（房间状态广播，`kind=4`）与 `0x62CA74`（`kind=2`）。**

### 3.2b 第二个入队函数 `0x62C800`

```asm
0x62C815  mov edx,[ebx]                ; 消息对象
0x62C817  mov edx,[edx]                ; vt[0]
0x62C825  call edx                     ; 序列化
0x62C82A  mov ecx,[eax+0x3A0D8]        ; room+0x3A0D8
0x62C830  add eax, 0x3A0D4             ; ★ 另一个容器
0x62C83A  call 0x656A10                ; 插入链表
0x62C869  ret 0x10
```

**⇒ `+0x3A0D4/0x3A0D8` 是第二个入队容器（链表），与 `+0x3A098`（哈希表）并列。**

★ **三处 `add eax, 0x3A0D4`（`0x62C72E` / `0x62C82F` / `0x62CA1D`）全是入队，没有一处是发送。**


### 3.3 `0x6345xx` 房间状态广播（真发侧）

```asm
0x6345E2  lea eax,[edx+ebx+0x7470]      ; 遍历 MatchMakingInfo 数组
0x634606  mov dword [ebp-0x244], 0xDC751C   ; vtable dwRoomMessageStartGame
0x634610  call 0x62ABF0                 ; 构造
0x63461B  push 4                        ; ★ kind = 4
0x634626  call 0x62C870                 ; ★★★ 真发

0x63463B  mov dword [ebp-0x1E0], 0xDC7540   ; vtable dwRoomMessageMemberInfoAdd
0x634656  lea esi,[ebx+0xE368+n*0x1D0]      ; 成员记录
0x634668  rep movsd                     ; 复制 0x74 dwords
0x634677  call 0x62C380                 ; kind = 4 真发
```

### 3.4 不对称总结

| 谁 | 函数 | 路径 |
|---|---|---|
| 用户点"准备" | `0x6301A0` → `0x62C5A0` | **入队** |
| 用户点"改阵营" | `0x630760` → `0x62C5A0` | **入队** |
| 服务端要的 StartGame | `0x6345xx` → `0x62C870(4)` | **真发** |
| MemberInfoAdd | `0x6346xx` → `0x62C380(4)` | **真发** |

★★★ **同一个 `dwRoomImp`，出站消息走了两条不同路径。**

## §4 本地分发 `0x6330xx`

```asm
0x6330C7  lea eax,[ebx+0x3A098]        ; ★ 入队容器
0x6330CD  call 0x654D60                ; 取一条
0x6330D8  movzx eax, byte [ecx+0x11]
0x6330DF  movzx edx, byte [ecx+0x10]
0x6330E3  imul edx, 0x1000193          ; ★ FNV-1a
0x633103  mov edx,[ebx+0x3A09C]        ; 桶容量
0x633109  dec edx; and edx,eax
0x63310C  mov eax,[ebx+0x3A0A8]        ; 桶数组
0x633112  mov edi,[eax+edx*4]
0x633121  cmp ecx,[edi+0x10]           ; 比对 key
0x633176  dec dword [ebx+0x3A098]      ; 计数递减
0x633181  lea eax,[ebx+0x3A098]; call 0x654D60   ; 下一条
0x63318C  cmp dword [ebp-0x54],0 / jne 0x633015  ; 循环
```

**⇒ 入队的消息被**本地分发**（FNV 哈希 → 链表 → 匹配）。**

## §5 `dwRoomImp` 三组容器

| 偏移 | 内容 | 访问点 |
|---|---|---|
| `+0x3A098` | 入队哈希表（count/cap/buckets）| `0x62C5BF`(入队)、`0x6330C7`(分发) |
| `+0x3A09C` | ↑ 桶容量 | `0x633103` |
| `+0x3A0A8` | ↑ 桶数组 | `0x63310C` |
| `+0x3A0D4` / `+0x3A0D8` | 链表头/尾 | `0x62AD61` / `0x633085` |
| `+0x3A100` / `+0x3A104` / `+0x3A108` | 另一组链表 | `0x6331F1` / `0x633249` / `0x633268` |
| `+0x3A118` | 带时间戳的队列 | `0x6331BD` |

## §6 诚实边界

1. **「入队 → 真发」的桥接点未找到**。已证：
   - 房间动作入队（`0x62C5A0`）
   - 状态广播真发（`0x62C870(4)`）
   - 本地分发遍历入队容器（`0x6330xx`）
   **但没找到"把入队消息转给 `0x62C870(4)`"的位置。**
2. **`0x6330xx` 的完整函数边界未定**（起始点可能在 `0x632F00` 之前）。
3. **`0x62C48A` 附近的 `+0x3A0D4` 三处 `add eax, 0x3A0D4`（`0x62C72E` / `0x62C82F` / `0x62CA1D`）
   未逐条分析** —— 它们与 `0x62C870` 的 kind 分支可能相关。
4. **dump 时未进房间**（`clientState = 0`），**无法验证房间内这些容器是否有数据**。

## §8 方法论

1. ★★★★★ **前端接口先枚举，再谈"没反应"** —— 33 个房间回调全在，排除了"缺少处理器"。
2. ★★★★ **`AS_*` handler 与实现分离**：`AS_X` 是接口，`handler` 是 `[0x693DD0][handler][typeinfo]` 结构里的第 2 项。
3. ★★★★ **同一个类的出站可能有多条路径** —— 必须逐条查 kind 参数，不能假定"都是发网络"。
4. ★★★ **容器基址是算出来的（`add reg, imm32`）**，只搜 `lea` 会漏。
5. ★★★ **`bytes.find` 比逐字节循环快 ~100 倍**，230 MB 镜像必须用它。
