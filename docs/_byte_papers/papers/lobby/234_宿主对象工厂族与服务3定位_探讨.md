## 一、一个常量省掉一轮全库扫描

对比 `0xB80D90` 和 `0xB81250` 时，我注意到两件事：

```asm
0xB80D95  push 0xC8B753      ; 0xB80D90 的 SEH cookie
0xB81255  push 0xC8B753      ; 0xB81250 的 SEH cookie
```

**同一个值。**

这不是巧合。MSVC 的 SEH cookie 是**每个函数独立生成**的（`_security_cookie ^ 函数地址` 之类），两个不同函数用同一个立即数，只有一种解释：**它们是同一个模板函数被实例化两次**，或者干脆是同一段代码的两次内联展开。

前 24 条指令逐字节相同也印证了这点。

### 这为什么有用

要找"还有多少个这样的函数"，不需要理解它们的语义 —— **只要扫 `push 0xC8B753` 出现的所有位置**，就能一次拿全一整族。

这比 233 卷的教训（我猜"兄弟函数在附近"，实际相隔 190KB）强得多：**cookie 是全库唯一的，不受地址邻近影响。**

★ **方法论**：**同一段模板代码的多个实例，共享的不只是"形状"，还有 SEH cookie / 异常处理表的常数量。这类常量的值域小、唯一性强，是最好的族识别指纹。**

## 二、三段式结构：我这次终于猜对了

231 卷我从商城反推出这个结构：

```
0x803830 (srpc 单例) → 0xB7A670()==2 (认证) → 0xB81250(空串) (取宿主) → 构造 → 0x7FAA20 (出口)
```

234 卷在服务 3 上得到的是：

```
0x803830 (srpc 单例) → 0xB7A670()==2 (认证) → 0xB80D90(空串) (取宿主) → 0xB92140 → 0xB7A330 (提交)
```

**骨架完全相同，只有两个"零件"换了：宿主 getter 和提交函数。**

| 环节 | 服务 80 | 服务 3 |
|---|---|---|
| srpc 单例 | `0x803830` | `0x803830` ✅ 同 |
| 认证 | `0xB7A670()==2` | `0xB7A670()==2` ✅ 同 |
| 宿主 getter | `0xB81250` | `0xB80D90` ⬅ 不同 |
| 构造 | `0xB86A40`/`0xB86D10` | `0xB92140` ⬅ 不同 |
| 提交 | `0x7FAA20`/`0x7FABE0` | `0xB7A330` ⬅ 不同 |

★ **所以「任何未知 svc 都能按这个三段找」不是猜测，是两个独立样本验证过的骨架。**

这也解释了为什么 `0xB7A670()==2` 会在房间类（172/173 卷）、商城（231 卷）、服务 3（本卷）**三个完全不同的子系统里反复出现** —— 它是**所有 srpc 服务的公共前置**，不是某个子系统的私有闸门。

## 三、我踩过的一个判断错误

看到 `0x7FF57F push 0x3A`，我第一反应是"这是 svc 58"。

**但它和 `0xB9753E` 的 svc 58 不在同一个函数里。** `0x7FF500` 是服务 3 的封装层，`0x3A` 在这里更可能是：
- 某个数组下标
- 某个通道号
- 某个后续调用（`call 0x7FD660`，`0x7FF56C mov esi, 0x7FD660`）的参数

**我没验证就拿它当 svc 58 写进了论文，然后在 §5 边界 4 里自己标了"需核"。**

★ **这是本轮我唯一没做完的推理，必须明确标出来，不能让它混进结论。** 记忆里 227 卷的教训（"参数==自己字段 ⇒ 该门恒真"）就是没读完整上下文导致的。

## 四、「同构服务」这个词要慎用

我写「服务 3 是一组同构查询服务：24 个 task 结构相同」。

**证据强度其实只有两条：**
1. 24 个构造函数在 `0xB92xxx` 区连续排列，模板相同（`push 80000/400/task/svc; lea ecx; call 0xBA72C0`）
2. 语料里 `3/46`(24B) / `3/48`(29B) / `3/53`(19B) 三个 payload 长度相近、字段同族

**这两条都不足以证明"24 个都同构"。** 我只反汇编了 `0xB92140`（task 30）一个。另外 23 个只看了 call site 处的 push 立即数。

★ **正确表述**：「24 个构造点共享同一模板（已验 1 个），语料里 3 个样本字段同族 ⇒ **倾向同构，未全验**」。

这个区别很重要 —— 231 卷我因为没读构造函数就把 `+0x44` 判成"条数"，写进论文后才发现是事务号。**同一类错误不能在 24 个未验样本上重演。**
