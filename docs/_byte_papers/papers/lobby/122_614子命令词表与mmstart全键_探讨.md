# 122 探讨 · 把"命令串"当表格读：15 个键，一个都不能漏

> 配套：[122 · `6/14` 子命令词表收口 + `mmstart` 全键值域](122_614子命令词表与mmstart全键.md)
> 性质：方法论复盘。**主题：明文命令串的穷举读法。**

---

## 一、这条为什么一直没人做完

`6/14` 的 mmstart 我们看过很多次（`108` 卷、`118` 卷），每次都**只抽我们关心的那几个字节**：

- `108` 想知道"服务端不用猜地图" → 只看了 `map` 字段；
- `118` 想收口数字 dvar → 只看了 `2486/3265/…` 那 5 个。

**没有人把整条命令串的每一个 `键 值;` 全部列出来。** 所以 `g_difficulty` 和 `2654` 一直在眼前，却从没被当成"键"登记过。

**这就是"部分看"的代价：你找什么就只看到什么。**

## 二、这次的做法：正则扫全串，然后按"键"计数

我写的是一个很笨的扫描：

```
对每条 mmstart，用正则 rb"([A-Za-z_]\w*|[0-9]+)\s+([^\s;]+);" 把所有 `键 值;` 抓出来，
按键名计数、按值域统计。
```

结果 15 个键全部现形，`g_difficulty` ×41、`2654` ×31。

**这个正则里那个 `|[0-9]+` 分支是关键**——数字键（`2486`/`3265`/`2654`/`2810`）不是字母开头的名字，**只用 `[A-Za-z_]` 会整批漏掉**。这与记忆 `codol-demonware-layer.md` 那条"`[A-Za-z_]` 锚定 pattern 漏掉 `?AU?$…@@` 模板层"是**同一类错误：正则的字符类决定了你能看见什么。**

## 三、`2654` 的惊喜：不是 dvar 数字，是客户端标识

我原以为 `2654` 跟 `2486` 一样是"数字命名的 dvar，值是 0/1"。结果值是 **`M7-E8S6Client`**——一个 9 字符的字符串。

**这立刻改变了对它的定性**：`2654` 是"**名字叫 2654、装在会话客户端标识**"的字段，不是开关。

★ 而 `M7-E8S6Client` 在 `111` 卷已经从 `10/21` 里认出来了（会话客户端标识，×211）。**同一个串在两个地方出现，互相印证**——`10/21` 里它是独立的字符串字段，`6/14` 里它是某个数字 dvar 的值。**两处一合，"M7-E8S6Client = 客户端会话标识"就成了双来源结论。**

## 四、`g_difficulty`：我自己修的自己的错

`118` 卷我从"同池邻居"推断 `2486` 是"难度相关 bool，紧邻 `g_difficulty`"。当时标了"中"可信度。

**本卷发现 `g_difficulty` 自己就是 mmstart 里的一个独立键**（×41，值 0/1）。

⇒ 我在 `118` 里说"2486 紧邻 g_difficulty"这句话，**字面**没错（字符串池相邻），但**性质**错了：以为是"2486 挨着难度这个 dvar"，实际是"2486 和 g_difficulty 在同一命令串里各自赋值"。**它们是并列的两个键，不是一个套一个。**

**⇒ `2486 ≠ g_difficulty`，这是本卷给 118 的硬修正。** 2486 的语义**仍然未知**。

**"邻居不是绑定"是 118 自己写的规矩，本卷又用它修正了 118 自己。** 规矩要对所有卷一视同仁，包括订规矩的那一卷。

## 五、`mmbook` 的 base64：又一个"字节串 vs 数值"的例子

`mmbook 796 iHdmVUQzIhE= 0`，b64 解出 `88 77 66 55 44 33 22 11`。

数值上读是 `0x8877665544332211`；大端读是 `0x1122334455667788`（魔数 C）。

**这两个数是同一个东西。** 我又一次看到"同一个字节串，两种数值外衣"——这正是 `118` 卷教训的现场复现。

★ **`mmbook` 的 id 只有两种**：`0x0100000000000000`（新建，×107）和 `0x8877665544332211`（复用魔数 C，×20）。**这个二元分布本身说明 mmbook 就是"预约房间"：要么新开一个，要么用现成那个。**

## 六、诚实的部分

- `2486` / `2489` / `2574` / `2500` / `2810` 的**精确语义仍未定**。本卷只给了值域，没给名字。要名字得读 dvar 表（内存转储，ACE 挡）。
- `start_map_rotate_once` 的 `1..7` 我标"地图轮换起始"，是**字面直译推测**，没有对照地图表验证。
- `sv_post_options` 的 base64 长串我只贴了原文，**没解码**（`AAAA…AQAAAAAA==` 像是全零 + 末位 1 的位图，但没验证）。

**我没有因为这些是"数字键盘"就给它们编名字。** 值域 ≠ 语义。**能写值域就写值域，不能写名字就留空。**

## 七、方法论（可迁移）

1. **明文命令串要"整串穷举"读，不能只抽关心的字段。** 找什么就只看到什么。
2. **正则的字符类决定你能看见什么。** `[A-Za-z_]` 会漏掉数字键；数字键常是被忽略的一整类。
3. **同一个串在两处出现 = 双来源结论。** `M7-E8S6Client` 在 `10/21` 和 `6/14` 都有，合起来才定性。
4. **规矩对所有卷一视同仁，包括订规矩的那一卷。** "邻居不是绑定"用它修正 118 自己。
