# 174 · `[obj+0x21]` 定案 = 位流写器的"调试/跟踪"开关，房间路径恒为 0

> 卷次：174（房间类 · 最后一项闭合）
> 方法：不按偏移 grep，改按**类**（vtable `0xD59834`/`0xD59838`）找 ctor，再读它的参数
> 结论：`[obj+0x21]` 是构造函数的**第 2 个参数**，房间两条入队路径都传 **0** ⇒ `0xB77B10` 恒空转，**169 卷的位流位数结论成立**。

---

## §0 结论

1. **`[obj+0x21]` 的来源找到了：`0xB778E0` 是位流写器的真 ctor，`0xB77948 mov al,[ebp+0xC]` → `0xB7795B mov [esi+0x21], al`。** 即 `+0x21` = **ctor 的第 2 个参数（`fastcall` 下的 `edx` 侧 / `thiscall+2 参`）**。

2. **房间动作的两条入队路径都传 0：**
   ```asm
   ; 族 A / 0x62C380
   0x62C3A8  push 0
   0x62C3AA  push 0
   0x62C3AC  mov  ecx, eax
   0x62C3AE  call 0xB778E0        ; ctor(this, 0, 0)

   ; 房间动作专用 / 0x62C5A0
   0x62C5EF  push ebx             ; ebx = 0（0x62C5C5 xor ebx,ebx）
   0x62C5F0  push ebx
   0x62C5F1  mov  ecx, eax
   0x62C5F3  call 0xB778E0        ; ctor(this, 0, 0)
   ```

3. **⇒ `[obj+0x21] == 0` ⇒ `0xB77B10` 恒为空操作 ⇒ 169 卷「那个 `WriteBits(8)` 什么都不写」在房间路径上是正确的。**

4. **172 卷那句「16 个候选写点，无一可静态归属」作废。** 16 个里 11 个是错位反汇编产生的假指令，真指令只有 5 个，且都不属于位流写器类。真正的写点是 `0xB7795B`，从来不在候选里 —— 因为它是 `mov byte [esi+0x21], al`，不是我 grep 的那种 `mov byte [reg+0x21], imm8/reg8` 里能区分出来的。

## §1 位流写器的两个类（vtable 表）

```
0xD59830: 0x00000000
0xD59834: 0x00B77790   <- 前一个 DWORD 当 COL 指针（实际是 .rdata 边界，RTTI 已剥离）
0xD59838: 0x00B77C20   <- vtable[0] = 析构
0xD5983C: 0x00B77BB0   <- vtable[1] = 首帧初始化
0xD59840: "Address is poolback: %s - -Ad H..."   <- 分配器诊断串
```

★ **RTTI 已被剥离**（`0xD59834` 不是合法 COL，`.rdata` 边界），所以这两个类的名字拿不到。
但 `0xD59840` 的分配器诊断串说明它们属于**内存池分配族**，`0xD59834`/`0xD59838` 是两个相关的位流缓冲类。

| 类 | ctor | 说明 |
|---|---|---|
| `0xD59834` | `0xB778E0` | **有 3 个参数**：`(this, u32 bits, u8 debug_flag)`，会 `alloc((bits+7)/8)` 并**立即写 1 位存在 + 1 位值** |
| `0xD59834` | `0xB779A0` | 另一个 ctor 变体，也写 `[esi+0x21]`（`lea edi,[esi+0x21]` + `mov [edi],al`） |
| `0xD59838` | `0xB77B30` | **无参数**，只写 vtable + 基类，**不碰 `+0x21`** |

★★ **这解释了 172 卷为什么找不到**：房间代码用的是 `0xD59838` 的无参 ctor，它的 `+0x21` 保持分配时的随机/零值；而只有 `0xD59834` 的 3 参 ctor 才会设置它。

### 1.1 `0xB778E0` 完整（关键 8 行）

```asm
0xB77917  mov  eax,[ebp+8]        ; 参数 1 = 位容量
0xB7791A  test al,7
0xB7791C  mov  ecx,ebx            ; ecx = 0
0xB7791E  setne cl                ; cl = (bits%8 != 0)
0xB77921  shr  eax,3              ; eax = bits/8
0xB77924  mov  [esi],0xD59834     ; vtable
0xB77930  mov  [esi+0x10],ebx     ; +0x10 = 0（容量）
0xB77933  add  eax,ecx            ; eax = ceil(bits/8)
0xB77935  mov  [esi+0xC],eax      ; +0xC = 字节数
0xB7793C  push eax / call 0xB74220 ; alloc
0xB77945  mov  [esi+8],eax        ; +8 = 缓冲
0xB77948  mov  al,[ebp+0xC]       ; ★★★ 参数 2
0xB77958  mov  byte [esi+0x20],bl ; +0x20 = 0
0xB7795B  mov  byte [esi+0x21],al ; ★★★ +0x21 = 参数 2
0xB77962  cmp  al,bl / je
0xB77969  ... mov byte [ebp-0xD],0xFF ; 若 +0x21!=0 则写 0xFF
0xB77973  ... mov byte [ebp-0xE],0    ; 否则写 0
0xB77977  call 0xB777C0           ; 立即 WriteBits(1, 0xFF 或 0)
0xB7797E  mov  [esi+0x1C],1
```

★★ **注意 `0xB77969`：`+0x21` 非 0 时，ctor 自己就会 `WriteBits(1, 0xFF)`。** 而 `+0x21` 为 0 时写 `0x00`。
所以 `+0x21` 不是一个"零填充开关"，而是**一个会附带写入 0xFF 标志位的模式位**。

## §5 方法论

1. **★★★ 按偏移 grep 会撞上错位反汇编。** 16 个候选里 11 个是假的。必须verify每条指令在函数起点的合法边界上。
2. **★★★ 找不到写点时，换个维度找：按「类」找 ctor，而不是按「偏移」找 mov。** `0xB7795B` 用的寄存器是 `esi`，与其它 16 个用 `eax/ecx/edx` 的完全不同族。
3. **★★ ctor 的参数就是字段的初值。** `[obj+0x21] = 参数2` 一句话把"运行时状态"变成"静态已知"。
4. **★★ 追调用点要追到 push 序列。** `push 0; push 0; call ctor` 三行看完，比推演整条链可靠。
