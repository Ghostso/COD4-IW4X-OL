# 251 探讨 · 我猜"组合包带多个 SKU"，语料说不是

> 配套：`251_背包总数5_购买帧单SKU_组合包走资产.md`

---

## 一、248 卷的那个猜测

248 卷 Q1 我写：

> `parse_purchase()` **只取 `vals[1]` 一个 SKU**；若组合包帧携带多个 SKU，**其余被丢弃**。

**这是一个"如果"开头的猜测。** 我把它写进了论文的判定依据里，用来说明"为什么组合包买不了"。

**这一卷我去查了语料里真实的购买帧**：

```
93/131  #1: ... 08 4a 59 00 00 ...    → 唯一 SKU = 22858
93/131  #2: ... 08 f1 00 00 00 ...    → 唯一 SKU = 241
80/154  #1: ... 08 ad 70 00 00 ...    → 唯一 SKU = 28845
```

**三条帧，三条都只有一个 SKU 字段。** 58 字节的固定骨架里根本没有第二个 SKU 的位置。

★ **"组合包带多个 SKU"这个猜测，被样本直接否掉了。**

---

## 二、样本只有 3 条，够吗

`93/131` 2 条 + `80/154` 1 条 = **3 条**。

**3 条能否掉一个猜测吗？**

能 —— 因为**帧骨架是定长的 58 字节**，且三条的字段序列**逐字节同构**（只有 SKU 值和末位 u32 不同）。如果存在"多 SKU 变体"，它必须在骨架里有位置；而骨架里**每个字段都已被识别**（`str/u32/bool/u64/u8/TERM`），**没有剩余空间**。

★ **否证的力度来自"结构已完全解释"，不是"样本数量多"。** 这一点我在论文里没有强调，但它才是关键。

## 三、那组合包到底卡在哪

语料说：客户端发**一个 SKU**。catalog 说：**Category 7（组合包类）= 0 条**。

```
28845 -> Item 20468  (Cat 0)
22858 -> Item 10080  (Cat 0)
241   -> Item 121    (Cat 0)
```

**服务端目录里一个"包"都没有。**

而 `WL_EquipLoadoutBundleInSlot`（组合包装备）走的是 **XAsset 资产解析**（步进 0x1C），**不是商品路径**。

**⇒ 组合包在客户端是"资产"，在服务端目录里却是"空的"。**

这块我**没有闭合** —— 论文 §4 边界 1 明确写了「组合包 SKU → 哪个 Item 才是"包"，未定位」。

## 四、一个顺手拿到的确定值

`WL_GetMaxNumLoadouts` 的实现是：

```asm
0x7D740A  mov dword ptr [esi + 0x10], 5
```

**常量 5。** 不需要任何推断。

**⇒ 背包一共 5 个，4 号/5 号就是最后两个扩展位。**

249 卷我推出「index 3 → 4 号、index 4 → 5 号」，这一卷补上了"为什么只有这两个"—— **因为最大值就是 5**。

★ **常量返回值是最好用的语义锚。** 一整卷的推断，一个 `mov ..., 5` 就钉死了。

## 五、差点又踩的坑

四个函数（`WL_GetMaxNumLoadouts` / `WL_GetUnlockedMPLoadoutNum` / `WL_GetPick10LoadoutCount` / `AS_IsLoadoutUnlocked`）的**包装代码完全一样**：

```asm
shr ecx, 6 / test cl, 1 / je ...
mov dword ptr [esi + 0x10], <值>
mov dword ptr [esi + 0xc], 3
```

**看起来是同一个模板。** 如果我看第一个就下结论"这四个都返回常量"，就会错两个（一个动态调用 `0x7DE610`，一个是 bool）。

★ **形态相同 ≠ 语义相同。必须逐个读 `<值>` 的来源。**

这次我没踩，因为我把四个都打印出来了。**但这是运气，不是习惯** —— 我本来是只打算看 `MaxNumLoadouts` 的。
