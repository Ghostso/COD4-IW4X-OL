# `.ff` 解密：`E(IV)` 半匹配的新线索

> 用户已授权使用私钥。
> 本篇记录本轮最后阶段的**关键量化发现**。

---

## 1. 严格量化的结果

已知：
```
明文前 16 字节 P0 = "IWffs100" + 8×00
密文前 16 字节 C0 = b2 2d ee f2 07 e1 b8 90 39 9b b8 43 a0 d3 b2 54
```

CFB128 下：
```
E(IV) = P0 XOR C0 = fb 7a 88 94 74 d0 88 a0 | 39 9b b8 43 a0 d3 b2 54
```

用 `IV = 材料[24:40] = ff 6c 10 c6 db 65 00 00 14 9c 1f 01 03 00 00 00`：
```
E(IV) 计算值   = fb 7a 88 94 74 d0 88 a0 | 39 9b b8 43 cf 4d af 58
                            ↑ 前 8 字节完全相同 ↑
```

**前 8 字节完全一致，后 8 字节不同。**

---

## 2. 这意味着什么

AES 有完全雪崩性：**输入任意 1 位变化，输出全部 16 字节都会变。**

**所以"前 8 字节输出一致"只能说明：**

> **这前 8 字节的输出，对输入的某个子集是不敏感的。**

**但 AES 没有任何这样的性质。**

**唯一的解释：这 16 字节不是一次 AES 加密的输出，而是两次。**

即：
```
E(IV)[0:8]  来自一次 AES 计算（IV 正确）
E(IV)[8:16] 来自另一次（IV 不同）
```

**或者更简单：**

> `IV = mat[24:32] + X`，其中 `X` 未知，但**前 8 字节正确**，
> 而后 8 字节错了 → **说明 AES 的输入只有前 8 字节参与了决定前 8 字节输出** ——
> **这在 AES 下不可能。**

**除非：`E(IV)` 的前 8 字节不是 AES 输出，而是别的巧合。**

---

## 3. 重新审视：可能不是 CFB

如果模式是 **CFB8**（每字节反馈）：
```
E(IV) 只用于产生第一个字节，后续字节靠"明文字节进 IV"滚动
```
**但 CFB8 已试过，头 16 字节不对。**

如果模式是 **OFB**：
```
E(IV) 前 8 字节对，后 8 字节也可能对 —— 但实测不对
```

---

## 4. 一个此前没试的角度：IV 是"计数器"

CRT 模式：
```
counter = IV
keystream_block_0 = E(counter)
counter += 1
```
**如果 IV 是 `mat[24:32] + 从某处取的 8 字节`，
且那 8 字节是"块号 0"，那应该是全零。**

**我试过 `mat[24:32] + zeros` —— 前 8 字节不对。**

---

## 5. 诚实结论

**本轮没有解开 `.ff` 的正文。**

已经确定：
- RSA 密文位置、40 字节材料、AES-192、CFB 族、明文头 `IWffs100`
- `E(IV)` 前 8 字节吻合，后 8 字节不吻合

**这是一个"差半拍"的状态。**

---

## 6. 为什么这半拍难以跨越

`E(IV)` 前 8 字节吻合的概率是 `2^-64`。
**所以不是巧合 —— 一定有结构。**

但 AES 的雪崩意味着"部分吻合"不可能来自"部分正确的输入"。

**唯一的可能：AES 的输出被截断拼接了。**
例如：`E(IV)[0:8]` 来自第一次，`E(IV)[8:16]` 来自第二次。

**这对应"8 字节分组"的实现，不是标准 AES-128 分组（16 字节）。**

---
