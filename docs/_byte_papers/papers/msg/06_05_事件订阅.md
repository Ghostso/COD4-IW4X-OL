## 字段语义

### 字段 1：`u32 = 0`

在 160 条样本里恒为 0。

从位置看（第一个字段），它很可能是**订阅的类型或子通道**。
值 0 表示"默认/主通道"。

**证据强度：弱**（只有"恒为 0"这一条观测）。

### 字段 2：`u32 = 20`

**这是本报文最有价值的一个字段。**

160 条里恒为 20。

`lobby_server.py` 的注释把它解释为"客户端订阅了 20 个事件"。
但这是**服务端作者的解读**，不是字节自证的。

独立的佐证来自 `_byte_papers/papers/13_按service语义分区.md`
里的缺口分析：

> 客户端订阅了 20 个事件，服务端一个都没推。

也就是说：20 这个数，在业务上对应"客户端关心的房间事件种类数"。

**证据强度：中**（数值与业务描述吻合，但无外部锚点）。

### 字段 3：`bool = true`

订阅的动作位 —— 发起订阅。

**证据强度：中**（值域 {0,1}；位置在最后，像"提交标志"）。

## 为什么这条报文重要

它是**当前大厅功能最大的缺口所在**：

1. 客户端调用 `6/5` 订阅房间事件（20 种）
2. 服务端只回空 ACK
3. 客户端**不重发**（说明它认为订阅成功了）
4. 但服务端从不推送任何事件
5. 结果：客户端永远收不到"房间已建立/状态更新/开始倒计时"等事件

**字节层面已经完全清楚**（13 个字节全部有归属）。
**问题在服务端是否实现了推送**，不在报文格式。
