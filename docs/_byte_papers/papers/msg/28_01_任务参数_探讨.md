# 报文 `28/1` · 探讨：一次成功的可证伪推断

> 对应：`msg/28_01_任务参数.md`

这一篇记录本卷集合里**第一个"从假说到字节级验证"完整闭环**的案例。

---

## 一、假说的来源

`lobby_server.py` 的注释：

> `28/1` 特别标注 —— 它是"任务参数"，实测在 `mmstart` **之前**到达，
> 很可能带着"玩家选了哪一关"的线索。
> 如果能在这一步就拿到关卡/地图，就能让 `21/5` 一次回对图。

**这是一个来自项目内的假说**（服务端作者写的）。
但它当时是"感觉"，不是证据。

---

## 二、把它变成可证伪的断言

假说说"28/1 带着关卡信息"，但没说在哪个字节。

我把它拆成三个可检验的断言：

**断言 1**：`28/1` 的尾部 u32（M）是某个 ID。

**断言 2**：如果 M 是"关卡 ID"，那它必须落在"关卡 ID 表"里。

**断言 3**：关卡 ID 表就是 `28/4` 的数组内容（127 个 0..262 的值）。

**如果三条成立，则"选关"假说被支持；
如果 M 大量不落在表里，假说被削弱。**

---

## 三、验证过程

### 提取 `28/4` 的 ID 表

```
127 个值，范围 0..262
[127, 0, 1, 2, 3, 9, 10, 12, 14, 18, 20, 21, ...]
```

### 提取 `28/1` 的全部 M 值

9 种形态，M 分别为：0, 1, 9, 131, 190, 203, 214, 4, 5。

### 比对

| M | 在表里 |
|---|---|
| 0 | ✓ |
| 1 | ✓ |
| 9 | ✓ |
| 131 | ✓ |
| 190 | ✓ |
| 203 | ✓ |
| 214 | ✓ |
| **4** | **✗** |
| **5** | **✗** |

**7/9 命中。2 个不命中。**

---

## 四、不命中的两个恰恰说明了更多

如果只看"7/9 命中"，可能会说"大致吻合"。

但**看那两个不命中的样本，它们是完全不同的形态**：

```
N=8, M=4, data = 02 00 00 00 00 00 00 00
N=8, M=5, data = 02 00 00 00 00 00 00 00
```

数据的第一个 u32 是 **2**，不是 1。

而所有 M 命中表里的样本，数据的第一个 u32 都**是 1**。

**这太干净了，不可能是巧合。**

---

## 五、修正后的结论

原来的假说"`28/1` 带关卡信息"是对的，但**不完整**。

完整的规律是：

> `28/1` 的数据是个数组，**第一个元素是类型码**。
> - 类型 1 → 尾字段 M 是**关卡 ID**
> - 类型 2 → 尾字段 M 是**别的 ID**

**这个结论比原假说强得多**，因为它给出了判定条件。

---

## 六、对实现的价值

服务端现在可以：

```python
def parse_28_1(payload):
    n = u32(payload, 2)
    data = payload[6:6+n]
    kind = u32(data, 0) if n >= 4 else 0
    M = u32(payload, 6+n)
    if kind == 1:
        return {"level_id": M}
    elif kind == 2:
        return {"other_id": M}
```

**这就能在 `21/5` 之前知道玩家选了什么。**

这恰好解决了 `lobby_server.py` 注释里描述的问题：
"不用靠上一轮记住、这一轮才对上"。

---

## 七、方法论收获

> **可证伪的断言要能被"部分失败"检验。**

如果我只说"28/1 带关卡信息"，那验证就是"是/否"。
但如果我把它拆成"**M 应该落在某个已知的 ID 集合里**"，
就能得到一个**可量化**的结果（7/9）。

而"7/9 而不是 9/9"这个结果，恰恰揭示了类型码的存在。

**完美的 100% 反而会掩盖结构。
"几乎全中但有规律地不中"才是有信息量的。**

---

## 八、还剩什么

2. `N=8` 时数组的第二个 u32（都是 0）是什么
3. 类型码是否还有 3、4…
   —— 目前只见到 1 和 2
