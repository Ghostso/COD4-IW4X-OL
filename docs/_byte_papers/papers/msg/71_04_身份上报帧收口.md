> 证据：`_byte_papers/nqlo_ctx.txt`、`nqlo_refs.txt`、`disasm714.txt`、`disasm714b.txt`、`v31902622*.txt`、`confirm714.txt`

## §0 结论

| 字段 | 71/4 旧卷猜测 | 本卷定论 | 证据 |
|---|---|---|---|
| blob1 = `nQloP0oCVWR6RDJS` | 「会话 ID / 会话令牌」（随机） | **客户端 EXE 里的硬编码字符串常量**，4×u32 从 `.rdata` 读取 | 反汇编 `0x4A6385` |
| blob2 = `++++++++++++++++` | 「同长度占位符」 | **硬编码 `0x2B2B2B2B` 常量**（`mov eax, 0x2B2B2B2B`） | 反汇编 `0x4A63AC` |
| u32 = `31902622` | 「会话时间/ID/毫秒计时器」 | **运行时计算/下发的值**；全镜像**无立即数**（LE/BE/32/64 全 0 命中），非哈希、非时间戳 | `v31902622*.txt` |

★ **一句话**：`71/4` 不是「随机会话上报」，是**一个结构写死的身份上报模板**——16 字节常量 ID + 16 字节 `+` 填充 + 一个运行时值 + MAC。**前 32 字节在二进制里就是常量，一个字都不会变。**

## §1 反汇编证据：71/4 序列化函数（VA `0x4A6280` 入口）

`tools/disasm_714.py`，E 运行时镜像（VA = file + `0x400000`），函数体 `0x4A6385` 起：

```asm
0x4A6385  mov  edx, dword ptr [0x00DB6B68]   ; "nQlo"  ← .rdata 常量
0x4A638B  mov  eax, dword ptr [0x00DB6B6C]   ; "P0oC"
0x4A6391  mov  ecx, dword ptr [0x00DB6B70]   ; "VWR6"
0x4A6397  push 0x0849B504
0x4A63A5  mov  edx, dword ptr [0x00DB6B74]   ; "RDJS"
0x4A63AC  mov  eax, 0x2B2B2B2B                ; "++++"  ← 立即数常量
0x4A63B4  mov  [ebp-0x14], eax               ; 存 4 个 + 槽
0x4A63BC  mov  [ebp-0x10], eax
0x4A63C4  mov  [ebp-0x0C], eax
0x4A63CC  mov  [ebp-0x08], eax               ; 共 4×0x2B2B2B2B = 16 字节 '+'
...
0x4A63E0  call <serialize blob>              ; 写出 2 个 16 字节 blob
```

**逐项对上 71/4 报文：**
- `0xDB6B68` = `n Q l o`（4 字节），`0xDB6B6C` = `P 0 o C`，`0xDB6B70` = `V W R 6`，`0xDB6B74` = `R D J S` ⇒ 拼成 **`nQloP0oCVWR6RDJS`**，来自 `.rdata` 常量区（不是运行时生成）。
- `mov eax, 0x2B2B2B2B` 写 4 次到栈槽 ⇒ **`++++++++++++++++`** 是编译期常量，不是「客户端没值所以填 +」。

★★ **这直接推翻旧卷的「会话 ID」猜测**：会话 ID 会是随机的、每次登录不同；而这里是 `.rdata` 里的固定字节，**任何一次运行、任何一台机器都是这 16 个字符**。

### 1.1 该常量在磁盘 EXE 与运行时镜像里位置一致

`tools/find_31902622_img.py` / `ctx_nQlo.py`：

| 镜像 | `nQloP0oCVWR6RDJS` 文件偏移 | 上下文 |
|---|---|---|
| E 运行时镜像（241 MB） | `0x9B6B68` | 紧邻 `"Mutiple login error!"`、`@SF_UI_LOGON_FAILURE_DEFAULT` |
| 磁盘 EXE | `0x6A2B68` | **同一段字符串池，偏移差 `0x313000`** |

★ 磁盘 EXE 里也有 ⇒ 这是**发布版就带的常量**，不是某次调试注入。

### 1.2 它的邻居说明了用途

`nQlo` 紧邻的字符串（`nqlo_ctx.txt`）：


★ 它**夹在「登录错误」与「登录失败 UI」之间**，说明这是**登录/会话流程**里的一个固定标识（很可能是一个**内置的默认会话/调试账号标识**，或某个 title 的固定握手串）。**但它是常量，不是动态令牌。**

## §2 `31902622` 的边界（诚实：未定名，但已收窄）

`tools/deep_31902622.py` / `deep_31902622b.py` / `find_31902622_img.py`：

| 检验 | 结果 |
|---|---|
| 跨 run 恒定 | ✅ 160 条 / **83 个 run 全 = 31902622**（机器级常量，非会话级） |
| 在全镜像作立即数（LE `<I`/`>I`/`<Q`/`>Q`） | ❌ **全部 0 命中** ⇒ 运行时计算/下发，非硬编码 |
| 是 `nQlo` 的哈希（md5/sha1/sha256/sha512/crc32/adler32/fnv1/fnv1a/djb2/djb2x/java/sdbm × 多种拼接 × 两种端序） | ❌ **全不中** |
| 是 MAC `D4-93-90-18-55-10` 的哈希或字节算术 | ❌ 不中（`sum=628`、`xor=138`、各 u32 都不等） |
| 是 Unix 时间戳 | ❌ `1971-01-05`（太早）；`/1000` = `1970-01-01`（无意义） |
| 与 build `1649370` / titleId `1004` / zoneId `83886082` 的算术 | ❌ 无整数关系 |

★★ **判定**：`31902622` 是**运行时由服务端或本地机器信息产生的账号/会话级 ID**，全语料 160 次、83 run 恒定说明它是**绑定这台测试机的稳定值**（换机器可能不同，但语料只有一台机器，无法证伪）。**本地静态无法定名——这是与 115/116 卷同一条诚实边界：需要「换一台机器抓包」或「读服务端下发逻辑」才能定。**

★ 注意：`0x01E6CB9E` 的 `>>16 = 486`、`&0xFFFF = 52126` 均无结构意义，**不要再尝试从数字本身猜**（这是 112 卷「先算术枚举再起名」的反面：枚举穷尽后仍无解，就诚实地标「运行时值」）。

## §4 为什么这条收口有意义（对「改大厅」的价值）

1. **`71/4` 不需要服务端回任何东西**（旧卷已证空 ACK 安全），它是纯身份上报。**改大厅、改模式都不依赖它。**
2. **`nQlo` 是常量 ⇒ 服务端若要做「客户端识别」，不能拿它当唯一指纹**（所有客户端都一样）。真正的识别位是 `31902622`（机器级）+ MAC。
3. **`++++` 常量 ⇒ 说明协议里有「固定长度的可选字段」约定**：客户端宁可填 16 个 `+` 也要占满长度，而不是省略字段。这与 111 卷「空串 `10 00` 占位」是同一条**占位约定**的又一例证。
