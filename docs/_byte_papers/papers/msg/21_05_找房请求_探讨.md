# 报文 `21/5` · 探讨：两种形态与一个恒定的负数

> 对应：`msg/21_05_找房请求.md`

---

## 一、两种形态说明存在两条 UI 路径

`21/5` 只有 35 字节和 75 字节两种长度。

| 形态 | 条数 | 特征 |
|---|---|---|
| A | 129 | 3 个 u32 + 1 个 i32 + 数组 |
| B | 30 | 3 个 u32 + 9 个 i32 + 数组 |

**B 比 A 多 8 个 i32。**

这不是"可变字段"，而是**两种完全不同的请求**：

- 形态 A：简单查询（无过滤条件）
- 形态 B：带过滤条件的查询

---

## 二、那 8 个 i32 的猜测

```
0, 255, 1, 0, 412, 123, 8, 0
```

如果这是"搜索条件"，可能的映射：

| 值 | 可能含义 |
|---|---|
| 0 | 起始值 |
| 255 | 上限 / 全掩码 |
| 1 | 最小等级？ |
| 0 | 某个开关关闭 |
| 412 | 最大等级？ |
| 123 | 某个 ID |
| 8 | 数量上限 |
| 0 | 结束 |

**注意**：`0, 255` 和 `1, 412` 成对出现，很像 min/max 范围。

**但这只是猜测。**

---

## 三、`-695030357` 是唯一稳定的东西

两种形态都有它，位置都在第 4 个字段。

**这反过来说明**：它是 `21/5` 的**必填字段**（不是可选的过滤条件）。

一个必填的、恒定的、值看起来像 hash 的 i32……

**最可能是"查询类型标识"**，由客户端硬编码。

`0xD692ADAB` 作为 hash 值，没有任何可读性。
但如果它是某个字符串的 hash（例如 `"findSessions"` 的 FNV hash），
就能解释了。

**可以试算**：如果你有 Python，可以算出 `FNV1a("findSessions")` 看是否等于 0xD692ADAB。
这是**可验证的猜测**，值得做。

### ★ 实测结果：不是常见 hash

已跑过：

- FNV-1a / FNV-1 / CRC32 对 12 个候选串（`findSessions`、`session`、
  `matchmaking`、`room`、`dwRoom` 等）—— **无一命中**
- MD5 / SHA1 的前 4 字节在任意偏移 — **无一命中**

**结论：`-695030357` 不是"字符串 hash"这种简单形态。**

**这篇的断言可以升级**：从"可能是 hash"变成
"**不是常用 hash 算法对常见候选串的结果**"。

新的可能：

1. 某个**结构化配置表**里的固定 ID（例如从 `.info` 文件读的）
2. 客户端某处硬编码的**魔数**
3. 多个字段**打包后的位模式**（例如一个有符号的复合编码）

**这些都无法用语料区分。**

---

## 四、为什么这条报文对项目关键

`21/5` 是 **findSessions** —— 找房。

如果它的字段不对，客户端就找不到房，或者连到错的战斗服。

项目历史上有过这类问题：
"猜错地图客户端就不去连战斗服"（`lobby_server.py` 注释）。

**字节层面已经解出 100%（结构）。**
但"`-695030357` 是什么"仍未定，
这是"语义未解"的典型例子。

---

## 五、方法论收获

> **跨形态恒定的字段，是最重要的字段。**

比较 A 和 B 两种形态：

- 变化的：8 个 i32（可选的过滤条件）
- **不变的：`-695030357`（必填的查询标识）**

**变的是什么，说明什么是可配置的；
不变的是什么，说明什么是协议的一部分。**

这比单独看一种形态信息量大得多。
