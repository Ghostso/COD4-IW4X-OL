| 字段 | 形态 A | 形态 B |

**关键发现**：

1. **`-695030357` 在两种形态里都出现**，且位置都在第 4 个字段 —
   这是**跨形态恒定**的。
2. **形态 B 多了 8 个 i32**，且第一个 u32 从 1 变成 3，
   第三个 u32 从 10 变成 50。

**这些 8 个 i32 很像"搜索过滤条件"**：
```
0, 255, 1, 0, 412, 123, 8, 0
```

- `255` = 全位掩码
- `412`、`123` = 可能是等级/分数范围
- `8` = 可能是一组数量

## `-695030357` 到底是什么

它在两种形态里都在同一位置。

`0xD692ADAB`。

**观察**：`AD AB` 在低 16 位，`D6 92` 在高 16 位。
字节序是 `ab ad 92 d6` → 逻辑值 `0xD692ADAB`。

这个值跨 83 个 run、159 条样本恒定。

**最可能**：某个固定的查询类别标识（query type hash），
由客户端硬编码。

## 数组 `[1]`

两种形态都用 `0x6b` 数组，内容都是 `u32 = 1`，尾字段都是 0。

与第 11 卷的结论一致：`0x6b` 的数据恒为 1。
