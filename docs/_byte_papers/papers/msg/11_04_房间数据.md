## 逐字节拆解

| 偏移 | 字节 | 解释 |
|---|---|---|
| 0x00 | `0a` | u64 标签 |
| 0x01–0x08 | `88 77 66 55 44 33 22 11` | 值 = `0x1122334455667788` |
| 0x09 | `13` | blob 标签 |
| 0x0a | `08` | 长度字段的类型 |
| 0x0b–0x0e | `10 00 00 00` | 长度 = 16 |
| 0x0f–0x1e | `0c 00 00 00 02 02 00 00 00 08 00 00 00 80 08 00` | 16 字节 blob 内容 |
| 0x1f | `08` | u32 标签 |
| 0x20–0x23 | `01 00 00 00` | 值 = 1 |
| 0x24 | `00` | 终止符 |

## ★ blob 内容本身是 TLV

注意：16 字节的 blob 内容 **本身就是一串合法的 TLV**：

```
0c                       ← 标签？未知
00 00 00                 
02                       ← u8 标签
02                       ← 值 2
00 00 00                 
08                       ← u32 标签
00 00 00 80              ← 值 0x80000000
08                       ← u32 标签
00                       ← ...
```

**这推翻了我之前的一个判断**：
第 12 卷说"`0x13` 的嵌套在实测中未使用"。

**这里就是嵌套的实例** —— `11/4` 的 blob 里装着 TLV。

但内容不完全对得上（开头 `0c` 是未知标签）。
可能有偏移，也可能是另一个文法。

**这是本卷集合里第一个"嵌套"实例，需要单独立卷分析。**

## 字段语义

### 字段 1：`u64 = 0x1122334455667788`

**测试哨兵常量。**

`88 77 66 55 44 33 22 11` 是 `11 22 33 44 55 66 77 88` 的字节反转。

261 条样本、跨 83 个 run，全部相同。

**结论**：客户端在"房间 ID"字段上用了固定哨兵值。
这既有好处（可识别）也有风险（不是真的房间 ID）。

**证据强度：强**（形态本身可识别为人工构造）。

### 字段 2：16 字节 blob

内容见上，本身是 TLV。

长度 16 是 128 位，可能是：
- 房间的 security key
- 房间状态的哈希

**证据强度：弱**（内容未解）。

### 字段 3：`u32 = 1`

恒定。

可能是"房间成员数 = 1"或"房间状态 = 1"。

`lobby_server.py` 的注释提到 `11/13` 回 `memberCount=0` 会导致问题，
说明成员数是一个敏感字段。这里 `11/4` 的 `u32=1` 可能就是成员数。

**证据强度：中**（数值与业务语义吻合）。
