# 第 2 卷 · 布尔标签 `0x01`

> 覆盖：`0x01` 标签及其 1 字节载荷
> 证据：`_byte_papers/evidence/ev_value_stats.txt`（tag 01 段）
> 复跑：`tools/lobby_value_stats.py`

---

## 1. 结论

```
0x01 <1 字节>
```

值域实测：

| 值 | 次数 |
|---|---|
| `01` | 326 |
| `00` | 3 |

**只有 0 和 1。** 无一例外。

值域 {0,1} 且载荷恰 1 字节 —— 这是布尔。

---

## 2. 判定过程

### 第一步：宽度

对 `0x01` 之后能步进多少字节做穷举。
把"宽度 = 1"代入 v5 解析器，全量语料 6848 条 **无一条因此失败**；
换成宽度 4（当成 u32）时，多条报文的后续标签全部错位。

宽度 = 1 被确立。

### 第二步：值域

只用宽度还不够——1 字节可能是有符号 8 位、u8 枚举、或 bool。
统计全部 329 个 `0x01` 实例的载荷：

```
01 → 326
00 → 3
```

**distinct = 2，仅 {0,1}。**

对比同样 1 字节的 `0x03`（第 3 卷）：它的值域是 {0,1,2,3}，
明显不是布尔。两者标签不同、值域不同，说明客户端确实在区分
"布尔"与"小整数"两种类型。

---

## 3. 出现位置

| (svc/task) | 值 | 次数 |
|---|---|---|
| 6/5 | 01 | 160 |
| 80/70 | 01 | 83 |
| 29/10 | 01 | 83 |
| 93/131 | 00 | 2 |
| 80/154 | 00 | 1 |

分布的特征：**`01` 占 99.1%**。

这不是"客户端随便写的"，而是"客户端在这几处传了一个几乎总是真的开关"。

`6/5` 出现在全部 160 个样本里且恒为 `01` —— 这个 task 是
配对的"事件订阅"请求（`lobby_server.py` 的注释：
`08 00 00 00 00 | 08 14 00 00 00 | 01 | 01 00`），
其中 `01` 很可能就是订阅的动作位。

---

## 4. 与第 3 卷（u8）的辨析

两个都是 1 字节标签，为什么不是同一个？

**反例来源**：`102/1` 的报文

```
08 00 00 00 00  08 01 00 00 00  03 03  0a <u64>  00
                                 ↑↑
                              这里 u8 = 3
```

而同一报文别处 `03 01 ... 03 02`，值是 1 和 2。

如果 `0x03` 是 bool，值 3 无法解释。
所以 `0x03` ≠ bool，`0x01` ≠ u8 —— 它们是两个不同的类型。

这也反过来证明：**客户端用的是强类型序列化**，
标签决定读多少字节、以及值的合法范围。

---

## 5. 字节覆盖

| 字节 | 语义 | 证据强度 |
|---|---|---|
| `0x01` | 布尔标签 | 强（宽度 + 值域双证） |
| 载荷 `00` | false | 强（3 例） |
| 载荷 `01` | true | 强（326 例） |

**盲区**：载荷 `00` 只有 3 个样本，且都出现在
`93/131`、`80/154` 这两个低频 task 上。
"false 的写法恒为 `00`"这条，样本量偏小，
不排除客户端对 false 有别的编码（例如只在特定路径写 false）。

**待办**：需要让客户端在这三条路径上走到"选否"分支才能验证。
