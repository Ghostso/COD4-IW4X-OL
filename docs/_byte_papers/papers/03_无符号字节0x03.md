# 第 3 卷 · 无符号字节标签 `0x03`

> 覆盖：`0x03` 标签及其 1 字节载荷
> 证据：`_byte_papers/evidence/ev_value_stats.txt`（tag 03 段）
> 复跑：`tools/lobby_value_stats.py`

---

## 1. 结论

```
0x03 <1 字节 uint8>
```

值域实测（18970 个实例）：

| 值 | 次数 | 主要来源 |
|---|---|---|
| `01` | 18760 | 102/7（18550）、68/3（146）、102/1（45）、102/5（19） |
| `03` | 127 | 102/1 |
| `02` | 80 | 102/1（45）、68/3（16）、102/5（19） |
| `00` | 3 | 102/7 |

**值域 {0,1,2,3}，且 1 字节。** 这是无符号小整数。

---

## 2. 与 `0x01` 的判别（本卷的核心）

两个都是 1 字节标签，值域都小。为什么不能合并？

因为 **`0x03` 的取值集合包含 2 和 3**，而 `0x01` 从不出现这两个值。
如果它们是同一个类型，客户端不会用两个不同标签写同一个语义。

所以必须分开：

- `0x01` = bool（值域 {0,1}）
- `0x03` = u8（值域 {0..255}，实测只用到 0..3）

## 3. 典型报文逐字节

### 3.1 `102/1`（两种形态）

**形态 A（22 字节，127 样本）**

```
偏移  字节                          解释
00    08 00 00 00 00                u32 = 0
05    08 01 00 00 00                u32 = 1
0a    03 03                         u8  = 3          ← 版本/类型
0c    0a <8 字节>                   u64
15    00                            终止
```

**形态 B（33 字节，45 样本）**

```
00    08 00 00 00 00                u32 = 0
05    08 02 00 00 00                u32 = 2
0a    03 01                         u8  = 1
0c    0a <8 字节>                   u64
15    03 02                         u8  = 2
17    0a <8 字节>                   u64
20    00                            终止
```

**关键观测**：形态 A 里 u32=1 且 u8=3；
形态 B 里 u32=2 且 u8=1。

这正是我最初把 `0x03` 误判为"分组容器"的地方 ——
`03 03` 看起来像"3 个元素的组"。
但按"组"解析会要求后面有 3 个元素，而实际只有 1 个 u64 就终止了。
**长度闭环把"分组"假设直接证伪**（详见探讨篇）。

### 3.2 `102/5`（10 字节，19 样本）

```
00    08 02 00 00 00          u32 = 2
05    03 01                   u8  = 1
07    03 02                   u8  = 2
09    00                      终止
```

两个 u8 紧挨着，分别是 1 和 2。

### 3.3 `102/7`（556 字节，371 样本，全部同形）

```
00    08 32 00 00 00          u32 = 50
05    03 01                   u8  = 1
07    0a 00 00 00 00 00 00 00 00    u64 = 0
10    03 01                   u8  = 1
12    0a 01 00 00 00 00 00 00 00    u64 = 1
1b    03 01                   u8  = 1
1d    0a 02 ...               u64 = 2
...
```

模式是 `(u8=1, u64=N)` 重复，N 从 0 递增到 49。
开头的 `u32 = 50` 就是重复次数。

**这是一个被完全解析的报文**：50 个 `(键, 值)` 对，
键恒为 u8=1（类型标记），值为递增 u64。

## 4. 出现位置的分布含义

| (svc/task) | u8 值 | 次数 |
|---|---|---|
| 102/7 | 1 | 18550 |
| 68/3 | 1 / 2 | 146 / 16 |
| 102/1 | 3 / 1 / 2 | 127 / 45 / 45 |
| 102/5 | 1 / 2 | 19 / 19 |

`102` 这一族（1、2、5、7）全部使用 `0x03` 作为"小状态码"。
`68/3` 也用它。

结合 `102` 的业务位置（`lobby_server.py` 里 102/7 的处理注释是
"storage 102/7 回显 50/50 个字段"），
这个 u8 很可能是**存储字段的类型/版本标识**。

但**这是推断，不是实证** —— 语料只能证明"这里有个 u8 且取值是 1"，
证明不了"它的语义是版本"。语义归属留到第 13 卷。

---

## 5. 字节覆盖

| 字节 | 语义 | 证据强度 |
|---|---|---|
| `0x03` | u8 标签 | 强（18970 例，宽度闭环） |
| 载荷 `01` | 最常见值 | 强 |
| 载荷 `02` / `03` | 其它取值 | 中（各 80 / 127 例，都只来自少数 task） |
| 载荷 `00` | 出现 3 次 | 弱（仅 102/7） |

**盲区**：值域上限未知。
实测只到 3，但 `0x03` 是 1 字节标签，
理论上可以到 255。**不能假定它永远 ≤ 3。**
