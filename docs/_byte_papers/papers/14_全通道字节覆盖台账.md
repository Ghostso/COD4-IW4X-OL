## 2. 每个字节的归属

在一个 payload 里，任意一个字节必然属于以下之一：

| 归属 | 判定方法 |
|---|---|
| 标签字节 | 按文法步进时落在标签位置 |
| 定长载荷 | 紧跟在 `01/03/06/07/08/09/0a` 之后 |
| 字符串内容 | 在 `10` 之后、下一个 `00` 之前 |
| 字符串终止 NUL | `10` 内容的最后一个字节 |
| blob 长度字段的类型标签 | `13/6b/6c` 后第一个字节，恒 `08` |
| blob 长度值 | 上述之后 4 字节 |
| blob 内容 | 长度值指定的 N 字节 |
| 数组尾部 u32 | `6b/6c` 数据之后的 4 字节 |
| payload 终止符 | 末尾 1~9 个 `00` |

**没有"无法归属"的字节类别。**

## 5. 与外部参照的关系

按 AGENTS.md 的权威序：

1. **本地逆向（本卷）** —— 最高。本卷所有结论都来自真实客户端字节。
2. IW4X —— 本卷不涉及（它是战斗服参照，不是大厅协议）。
3. CoD4X —— 同上。
4. ol-mod —— **本卷未引用任何 ol-mod 常量**。

**特别声明**：`0x01/0x03/0x06/0x07/0x08/0x09/0x0a/0x10/0x13/0x6b/0x6c`
这套标签表，与项目内 `codol_crypto.py` 的对照表**一致**。
但 `codol_crypto.py` 的注释写明它是"照抄 ByteBuffer.cpp"（外部项目）。

本卷的独立性在于：
- **所有宽度、值域、结构都是从 6848 条真实字节独立验证出来的**
- `codol_crypto.py` 的对照表只作为**事后的交叉检查**
- 若两者冲突，以本卷的实测为准

**唯一的不一致点**：`0x09`（i64）在对照表里存在，但本卷语料 0 例。
本卷据此**不确认 `0x09` 在本 build 上可用**。

## 7. 台账的边界

**这份台账覆盖的是"客户端 → 服务端"方向的 55 个 task。**

不覆盖：

1. **服务端 → 客户端方向**（应答与推送）——
   应答格式已在 `codol_crypto.py` 里实现，但**没有像本卷这样的字节级台账**。
2. **客户端从未发出过的 task** —— 无法从语料得知。
3. **帧头**（`u32 declared | 0x86 | service | 0x03 | task`）——
   已在 `lobby_server.py` 注释里说明，但本卷未独立验证。
4. **加密/压缩/CRC 层** —— 属于传输层，不属于 payload 结构。

**这四项是下一步的明确目标。**
