# 第 6 卷 · 探讨：`1649370` 是这一卷的锚

> 对应论文：`06_无符号整型0x08.md`

---

## 一、为什么这一卷比别的卷"硬"

前几卷（`0x01`、`0x03`、`0x06`）的结论主要靠**宽度 + 值域**，
属于"形态证据"。这类证据能确定结构，但确定不了语义。

`0x08` 不一样：它里面出现了一个**能独立识别业务含义的值** ——
`1649370`。

这个数字对本项目有特殊意义：

- AGENTS.md 第一行：`3.19 / build 1649370`
- 项目所有 fixture 文件名都带它（`mp_playerdata.def.1649370.bin`）
- 它是本次逆向的**目标版本号**

当这个值在报文里出现 88 次，且它所在的标签是 4 字节无符号整数 时，
可以做出一个**双向可验证的断言**：

> 「客户端在这个字段里上报自己的 build 号，
>   而本客户端就是 build 1649370，所以该值恒为 1649370。」

如果实测成立 → 类型 + 语义同时被锚定。
如果实测不成立（例如出现 1649371）→ 说明这一版不是目标版本。

实测：**88 次，全部是 1649370，无一例外。**

（修正记录：我最初把"出现 88 次"笼统算作 u32。
用解析器区分标签后才发现，1649370 在语料里一共出现 619 次，
其中 **272 + 259 次是竖线日志串里的文本**（`71/7`、`71/3`），
只有 **88 次是真正的 u32 字段**（`71/18`）。
这个纠正很重要 —— 否则会把"日志里打印了版本号"误当成"协议里有版本字段"。）

---

## 二、这个锚定带来的连锁价值

### 价值 1：验证了"客户端自报版本"这条链路

如果客户端在某个 task 里上报 build 号，那服务端的应答就应该
按这个 build 号来选择行为。这解释了为什么 `lobby_server.py`
里有大量"本 build / 不是 ol-mod 的 build"的注释 ——
**服务端确实能读到客户端的版本号。**

### 价值 2：确定了字节序

`1649370` = `0x00192ADA`。

**小端**存储 = `da 2a 19 00`
**大端**存储 = `00 19 2a da`

`71/18` 的实测字节是：

```
08 da 2a 19 00
```

`da 2a 19 00` —— **严格小端。**

这是本卷唯一一处**字节序可以直接读出、不依赖同族推定**的地方。
`0x06`（第 4 卷）的字节序只能靠"同族都是小端"推定，
现在有了 `71/18` 这个锚点，那条推定也从"惯例"升级为"有直接旁证"。

### 价值 3：提供了"值 - 语义"对照表

逆向最缺的就是"这个数是什么"的对照。有了 `1649370 = build 号`，
就能反推其它值的量级：

- 比 1649370 大得多（31902622）→ 可能是时间戳或被乘过的值
- 700 / 932 / 2000 → 可能是 ID
- 10 / 20 / 50 / 100 → 可能是数量

## 三、被排除的解释

### 解释 F1：1649370 是"恰好等于 build 号"的巧合

**排除理由**：88 次全部相同，且这个数字在本项目里有特殊含义。
如果是任意数，为什么恰好是目标版本号？

### 解释 F2：1649370 是每会话随机的

**排除理由**：跨 83 个 run（跨越 3 天）全部相同。
随机值不可能这么稳定。

### 解释 F3：1649370 出现在"客户端 → 服务端"以外的方向

**排除理由**：语料只记录**客户端发出的** payload（服务端解密后落盘）。
所以它确实是客户端写出来的。

## 四、方法论收获

> **找一个有外部语义锚点的值，用它来校准整个字段的读法。**

在逆向里，"纯结构分析"能走很远，但走不到语义。
真正能突破的是：**某个值在报文外有独立定义**。

本例中：
- `1649370` 在 AGENTS.md 里有定义
- 它在报文里出现 → 报文里的那个字段就是 build 号
- build 号是 `0x08`（4 字节无符号）→ 该标签的类型被锚定

这个"外部锚点 → 内部字段"的对应，比任何长度分析都可靠。

**推广**：以后遇到任何已知常量（端口 3074、地图名、协议版本），
都值得搜一遍语料，看它落在哪个标签下。

## 五、尚未解决

### 31902622 是什么

160 次出现，恰好与 `20` 同频。在 `21` 族里。
0x1E6D51E —— 不像任何常见常量。

有可能是：
- 某种 hash
- 某种"会话类型"编码
- 时间戳（但 31902622 秒 ≈ 1 年，太短；
  31902622 毫秒 ≈ 8.9 小时，不像）

**列为待办。**

### 值 932

352 次。0x3A4。可能是某个 ID，也可能是"最大玩家数类"的值。
无更多线索。

### 低频值

129 个 distinct 里，有大半只出现 1~2 次。
这些很可能是个体 ID / 时间戳分片 / 随机种子。
在没有更多会话数据前无法区分。
