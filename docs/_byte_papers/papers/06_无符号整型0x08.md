# 第 6 卷 · 无符号整型标签 `0x08`

> 覆盖：`0x08` 标签及其 4 字节载荷
> 证据：`_byte_papers/evidence/ev_value_stats.txt`（tag 08 段）
> 复跑：`tools/lobby_value_stats.py`

---

## 1. 结论

```
0x08 <4 字节小端 无符号 uint32>
```

语料中出现 **6369 次**，是除字符串外最高频的标签。

值域：**129 个不同值，全部 ≥ 0，最大 2082033314。**

### ★ 关键值：`1649370`

这是**本项目的目标 build 号**（AGENTS.md 首行：
"3.19 / build 1649370"）。

实测定位（用 v5 解析器区分标签类型后统计）：

| 出现形式 | 位置 | 次数 |
|---|---|---|
| **u32（`0x08`）** | **71/18** | **88** |
| 字符串（`0x10`） | 71/7（日志行） | 272 |
| 字符串（`0x10`） | 71/3（日志行） | 259 |

**只有 `71/18` 那 88 次是真正的整型字段**，其余是竖线分隔的日志串里
打印出来的版本号文本。

`71/18` 的 88 条样本，全部同形（11 字节）：

```
偏移  字节                    解释
00    08 01 00 00 00          u32 = 1
05    08 da 2a 19 00          u32 = 0x00192ADA = 1649370   ← build 号
0a    00                      终止
```

**这是"客户端自报 build 号"最干净的一处实证** ——
不是从日志里抠出来的，而是结构化字段。

### 关键值：`31902622`

出现 160 次，与 `20` 的出现次数一致（都是 160）。
`31902622` 的十六进制是 `0x1E6D51E` —— 不构成明显的常量。

## 3. 报文逐字节

### 3.1 `6/5`（13 字节，160 样本）

```
00    08 00 00 00 00      u32 = 0
05    08 14 00 00 00      u32 = 20
0a    01 01               bool = true
0c    00                  终止
```

`14 00 00 00` = 20。
在 `lobby_server.py` 的注释里，`20` 被解释为
"客户端订阅了 20 个事件" —— 与 `0x08` 作为无符号计数的用法一致。

### 3.2 `11/13`（createRoom 应答的请求，1 字节，66 样本）

```
00    00                  终止
```

只有终止符 —— 空请求。

### 3.3 `102/7` 的头部

```
00    08 32 00 00 00      u32 = 50
```

`50` = 后续 50 个 `(u8, u64)` 对的个数。
**这是"计数字段用 `0x08`"的直接实证**。

---

## 4. `0x08` vs `0x07`（与第 5 卷对照）

判据（第 5 卷已详述）：

- `0x07` 有负值（407 例）
- `0x08` 无负值（0 例）
- `0x08` 的最大值 2082033314 < 2^31 —— 作为 uint32 完全正常
- 两者不能互换（客户端逐值类型检查）

**结论**：`0x08` 是无符号，`0x07` 是有符号，客户端区分使用。

---

## 5. 值分布的语义线索

低值占绝对多数：0、1、100、50、10、932、2000、20、12、101 ——
这些像**枚举值、数量、配置项**。

出现频次与"计数"语义高度吻合：

- `102/7` 头部的 50 = 后续元素个数
- `6/5` 的 20 = 订阅事件数
- `21/5` 的 10 = 某个数量

**这是 `0x08` 作为"计数器"的强证据，**
而不是"任意数值"。

但这只是统计倾向，不支持"`0x08` 一定是计数" ——
`1649370`（build 号）就不是计数。

## 6. 字节覆盖

| 字节 | 语义 | 证据强度 |
|---|---|---|
| `0x08` | u32 标签 | 强（6369 例） |
| 载荷 4 字节小端 | 无符号 | 强（0 负值 + 与 0x07 对照） |
| 值 1649370 | 客户端 build 号 | **很强（与项目目标版本完全一致，88 例）** |
| 值 50（102/7） | 元素个数 | 强（语义与结构自洽） |
| 值 20（6/5） | 订阅事件数 | 中（依赖服务端注释） |

**盲区**：

1. `31902622`（160 次）语义未解 —— 这是出现频次第 8 高的值，
   值得单独追踪。
2. `932`（352 次）语义未解。
3. `0x08` 的 129 个 distinct 值里，有很多只出现 1~2 次的偶发值，
   尚不清楚它们是个体 ID 还是临时状态。
