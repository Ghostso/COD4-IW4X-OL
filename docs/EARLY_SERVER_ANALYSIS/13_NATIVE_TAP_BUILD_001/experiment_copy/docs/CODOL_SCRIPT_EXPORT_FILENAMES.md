# Reference source filename corrections

The native source loader now has two exact, last-resort filename mappings for
the alpha0022 IW4 export. Overlay, base/mp and canonical base paths retain
precedence; malformed or unreadable canonical sources still fail rather than
falling through. No reference files are edited and no general fuzzy matching
is performed.

| Canonical module filename | Reference export filename under base |
| --- | --- |
| character/mp_character_us_army_lmg.gsc | character/charactermp_character_us_army_lmg.gsc |
| character/mp_character_us_army_smg_b.gsc | character/character_us_army_smg_b.gsc |

The first export contains a duplicated directory prefix. Its main/precache
bodies use `mp_body_us_army_lmg`, `alias_us_army_heads`, `viewhands_us_army`
and the American voice. The second filename omits `mp_`, but its body explicitly
selects/precaches `mp_body_us_army_smg_b` with the same multiplayer head/viewhand
setup. These bodies support the exact requested character identities. Python's
`gsc/loader.py` has no corresponding fallback; this is a native reference-source
integration fix, not a claim that Python already handled the filenames.

Linux ASan/UBSan passed the source-loader test with both corrections, canonical
precedence, binary-source rejection and unknown-name rejection. The Windows
build passed (`/tmp/sh1x-source-alias-final-win32.log`). The first isolated Bog
probe progressed from LMG to missing SMG-B; after both corrections, the final
probe on UDP 17764 progressed to bad syntax in
`xmodelalias/alias_opforce_militia_heads_wht.gsc:3`. Its home was
`%TEMP%/sh1x-source-alias-final-20260908-083023`. Both probes were stopped, and
C1/Python remained responsive. Full vendor compilation is still incomplete.

Two further export defects are literal periods in place of whitespace:
`xmodelalias/alias_opforce_militia_heads_wht.gsc` and
`xmodelalias/alias_seal_soccom_heads_mp_blk.gsc`. Each contains the full body
`main().{..a[0] = "<head>";..return a;.}` after the autogenerated header,
with `head_militia_a_wht` and `head_seal_soccom_da`, respectively. The native
reference loader replaces the punctuation with spaces only when the exact
filename AND entire known damaged body match. Length and existing line breaks
are preserved. Other body revisions and overlay content are not rewritten.
This is an export repair, not support for periods as GSC whitespace.

The source test checks the exact repair and leaves a different malformed body
unchanged; Linux ASan/UBSan and the Windows build passed
(`/tmp/sh1x-source-repair-final-win32.log`). The final isolated vendor probe on
UDP 17766 passed both alias files and reached missing method `isItemUnlocked`
in `maps/mp/gametypes/_teams.gsc:629`. Its home was
`%TEMP%/sh1x-source-repair-final-20260908-083336`. The probe was stopped;
C1 and Python remained responsive. Native vendor-script compilation and client
match entry are still incomplete.
