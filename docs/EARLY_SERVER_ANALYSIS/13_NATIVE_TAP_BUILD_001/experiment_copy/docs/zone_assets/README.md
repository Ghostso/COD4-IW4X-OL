# CoDOL 1.1.1.13 zone asset listing

Generated by `tools/codol_zone_assets.py` from the fastfiles in `client_shipRetail/chinese/` (the only zone directory the client mounts; the `ff00xx.ff` files at the game root are PE executables, not zones).  Regenerate with:

```
python tools/codol_zone_assets.py            # all zones
python tools/codol_zone_assets.py mp_rust    # one zone, then rebuild indexes
```

Needs numpy and the alpha0022 Python server dir (env `CODOL_ALPHA0022`, default `D:\CoD\CODOL Builds\...\alpha0022`) for its measured fastfile reader `zone_assets.py`.  First run inflates every zone (~4 min); the inflated copies are cached under `%TEMP%\codol_zones`.

## Files

* `<zone>.txt` -- every asset in that zone's directory, `type<TAB>name`, sorted by type then name.  An optional third column flags `~` = name recovered from a de-duplicated reference without a corroborating run (usually right, not proven -- see 'Name location' below) and `!` = unresolved/unnamed (placeholder in the name column).
* `ALL_<type>.txt` -- merged per-type index, `name<TAB>zone[<TAB>flag]`, one line per (name, zone) pair; a name in several zones appears once per zone.
* `ALL_animtree.txt` -- rawfiles ending in `.atr`.
* `COUNTS.tsv` -- full per-type-per-zone matrix (every type).

Names are the exact bytes in the zone (latin-1); GSC/native code must match them case-insensitively with `/` and `\` equivalent, which is what the engine does.

## Asset type numbering

Type ids are the 32-bit `type` field of each 16-byte directory entry in the inflated zone (`XAssetList` at +0x28).  The names are the IW4 enum; ids 36 (rawfile) and 37 (stringtable) are proven by struct decode and by `BG_TryLoadAnimList` in C1.exe, the rest are confirmed by content (xanim names at 2, xmodel at 4, material at 5, techset at 9, image at 10, sound aliases at 11, the five per-map world assets at 15/16/18/20/21, localize at 27, weapon at 28, fx at 30, leaderboarddef 38, structureddatadef 39, tracer 40, vehicle 41, addon_map_ents 42, weaponattach 43).

Name location per type: the struct's first field is the name pointer (localize: value pointer then name pointer; image: name pointer at +32).  `0xFFFFFFFF` = inline name after the fixed struct, whose size is: physpreset=68, phys_collmap=72, xanim=88, xmodelsurfs=48, xmodel=360, material=96, techset=204, sound=12, sndcurve=136, loaded_sound=48, com_map=16, game_map_mp=84, fx_map=116, lightdef=16, font=24, menufile=12, menu=400, weapon=3068, fx=32, impactfx=8, rawfile=16, stringtable=16, leaderboarddef=24, structureddatadef=12, tracer=112, vehicle=788, addon_map_ents=36, weaponattach=12, image=36.  Any other value is a de-duplicated block-3 reference (C1.exe 0x004B6FD9) to a string written earlier in the zone (xmodels of common_gametype_mp are named by cells of mp/cocharitems/*.csv, sound aliases by the sound fields of the first weapon using them, the world assets of a map by its com_map name).  The tool does not replay the loader's block allocation; it recovers the file offset of the referenced string from the fact that block 3 is bump-allocated in stream order (file offset - block-3 offset is nearly constant for strings written back to back and only grows between blobs), fitting runs of consecutive references and keeping the maximum-weight monotone chain of runs, with candidates restricted to the character classes the type's inline names use.  Names from a run of >= 3 references, from a unique candidate or from the com_map anchor are unflagged; the rest carry `~`.  The IW4OL native loader (src/codol/assets/codol_load_blocks.c) is the authority when a `~` name matters.

Not covered: assets that only live *inside* another asset (e.g. XModels inlined in a GfxWorld or a weapon's attachments) have no directory entry and are not listed; the IW4OL native loader's alias catalogue (`codol_load_blocks.c`) is the authority for those.
