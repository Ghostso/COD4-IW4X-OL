# 14 — D：最小验证计划（分阶段、独立授权）

> 任务：`EARLY-NATIVE-TAP-TOOLCHAIN-001`（为 `EARLY-NATIVE-TAP-BUILD-001` 准备可复现构建环境）
> 边界：本文件**只制定计划**。本任务**未执行**下列第 4–6 步，也**未执行**第 1–3 步中的任何编译动作；第 1–3 步中的“身份/版本/架构”类只读检查已在阶段 A 完成（仅限只读查询）。
> 状态词：CONFIRMED / STRONG_CANDIDATE / CANDIDATE / UNKNOWN / NOT_OBSERVED / INSTRUMENTATION_BLOCKED / REFUTED。

## D.0 设计原则

1. **逐级放行**：每一步都必须在前一步通过后才允许进入下一步；任一步失败即停止并回到上一级。
2. **最小权限**：早期步骤只做只读身份核验与最小编译探针，不触碰原始树、不链接、不覆盖部署二进制。
3. **隔离执行**：所有会写文件的动作都在**独立临时副本**中进行，绝不写入原始源码树、实验副本（`13_NATIVE_TAP_BUILD_001\experiment_copy`）、候选补丁目录或大厅基线。
4. **不越权**：每一步都需要**单独授权**；本文件不构成任何执行授权。
5. **不冒充验证结果**：环境盘点结论（`14_A`/`14_B`）不得被当作编译验证结果；只有第 5 步的实际执行才能产生编译结论。

## D.1 六步验证顺序

### 第 1 步：工具链身份与版本（只读）

| 项 | 内容 |
|---|---|
| 目的 | 确认候选工具链确为目标身份，而非同名/新版替代 |
| 动作 | 只读执行 `gcc -v`、`g++ -v`、`nasm -v`、`windres --version`、`make --version`；记录 `--version` 与目标三元组（`gcc -dumpmachine`） |
| 通过判据 | 三元组为 `i686-w64-mingw32`；GCC 标识包含 `posix-dwarf`（与既有产物 `i686-posix-dwarf-rev0` 一致）；版本可明确记录 |
| 不通过 | 三元组为 x86_64、MSVC 目标或线程/异常模型不符 → 停止 |
| 写操作 | 无 |
| 状态 | **NOT_EXECUTED（本任务未执行）** |

|---|---|
