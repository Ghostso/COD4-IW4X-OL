# CODOL 大厅字节级逆向论文体系（BAP）

> 工程目录：`CODOL-LOBBY-BYTE-ATLAS-057`
> 建立日期：2026-10-29
> 目标对象：`E:\codol_re\client_image_20261027.bin`（241,537,024 字节，解包后内存镜像）

---

## 0. 为什么需要"论文体系"而不是"报告"

过去 055/056 轮的问题是：**结论以散点形式散落在几十份 Markdown 里，
每个结论背后没有可复现的字节坐标，导致每换一个功能点就要重新搜索一遍**。
于是"解决一个点 → 冒出新黑箱"。

本体系把每一条结论强制绑定到：

1. **字节坐标**（VA 区间，精确到单字节）
2. **原始字节**（hex dump，可复核）
3. **判据强度**（见 §3 的 E 级）
4. **可复现脚本**（`TOOLS/ba*.py`，只读、参数化）

没有这四项的结论一律不写入论文。

## 1. 覆盖率的可计量保证

241,537,024 字节不可能喂给任何模型逐字节"理解"。所以覆盖率的保证
**不靠人工读完，靠账本（ledger）**：

`TOOLS/ba01_byte_ledger.py` 把镜像每一字节标记成唯一归属种类：

| 归属种类 | 含义 | 论文层 |
|---|---|---|
| `PE_HEADERS` | PE 头 + 节表 + 目录项 | A |
| `SECTION_VALUE` | 节的原始/虚拟区间 | B |
| `CODE_FUNCTION` | 线性反汇编得到函数体 | A/B |
| `CODE_UNWALKED` | 可执行节内反汇编走空但有字节 | **强制 A** |
| `RTTI_TD` | TypeDescriptor | A |
| `RTTI_COL` | CompleteObjectLocator | A |
| `VFTABLE` | 由 COL 反推的虚表 | A |
| `ASCII_STRING` | ≥6 可打印串 | A/B |
| `UTF16_STRING` | UTF-16 串 | B |
| `PADDING` | 0xCC / 0x00 游程 | B |
| `DATA_BLOB` | 节内其它非结构字节 | B |
| `UNCLASSIFIED` | 无规则认领 | **禁止存在** |

**铁律：`UNCLASSIFIED` 必须收敛到 0。** 任何非零量按区间列在
`DATA/ba01_unclassified.txt`，并转为下一批论文的 A 级任务。
这就是"没有黑箱"的可验证定义：不是"我读完了"，而是"每个字节都有归属，
每个归属都有论文编号"。

## 2. 论文分层与命名

### 2.1 正论文（分析）

`PAPERS/BAP-<NNNN>_<slug>.md`

内容固定六段：

1. **范围** — 精确 VA 区间 `[start, end)`，字节数
2. **原始字节** — hex + ASCII 双栏，每行 16 字节，带偏移
3. **逐字节解析** — 表格：偏移 / 宽 / 值 / 字段名 / 判据 / 备注
4. **语义推导** — 这个字节干什么，为什么这么判断
5. **引用关系** — 谁读它、谁写它（xref VA + 反汇编片段）
6. **置信度** — E 级 + 反证尝试记录

### 2.2 探讨论文（二阶）

`PAPERS/BAP-<NNNN>D_<slug>.md`

同一区间的**自我审问**，固定五段：

1. **我的判断可能错在哪** — 列出 2–5 个替代假设
2. **每个替代假设的反证/支持证据**
3. **如果判断成立，下游会怎样** — 影响哪些现有结论
4. **如果判断错误，最小可证伪实验是什么** — 不需要启动游戏的那种
5. **本次讨论改变了什么** — 正论文是否已修订

**为什么要单独一篇**：055/056 的教训是判断一旦写进文档就被当成事实沿用
（例如"memberCount 是闸门"、"HTTP 走 CEF"）。二阶论文强制对同一批字节
再做一次敌对审视，避免单点错误扩散。

## 3. 判据强度分级（E 级）

| 级 | 名称 | 定义 | 例子 |
|---|---|---|---|
| E1 | 字节直读 | 字节值本身即结论 | `0x014C` = i386 |
| E2 | 结构解析 | 按已证实的结构解析出字段 | PE 可选头字段 |
| E3 | 交叉一致 | 两处独立字节互相印证 | 节 raw 尾址 = 磁盘文件大小 |
| E4 | 反汇编语义 | 指令流给出明确数据流 | `mov eax,[0xB779A0]` |
| E5 | 行为印证 | 活进程/抓包观测 | 快照 run=4 位实测 |
| — | 推测 | 无字节支撑 | **不得写入结论段** |

055/056 中被推翻的结论，绝大多数是"推测当 E4 用"。

## 5. 执行纪律

1. **只读镜像**。任何扫描不得写回 `client_image_20261027.bin`。
2. **不启动游戏**（除用户明确要求的实机验证）。
3. 每篇论文的"原始字节"段必须是**从镜像实际读出**的内容，不允许手抄记忆。
4. 论文中出现的每个 VA 必须可在镜像中找到对应字节。
5. 结论段只允许 E1–E5。推测放探讨论文。
