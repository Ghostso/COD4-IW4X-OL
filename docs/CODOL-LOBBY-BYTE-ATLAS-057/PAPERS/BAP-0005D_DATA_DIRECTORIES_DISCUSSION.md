# BAP-0005D — 讨论：TLS 回调为空、`.idata2` 冲突、以及"骨架描述符"这个说法

对应正论文：`BAP-0005_DATA_DIRECTORIES.md`

本篇要处理三个可能让结论失效的问题。第二个直接与
**本项目的历史记忆冲突**，必须当面对质。

---

## 1. 我的判断可能错在哪

### 断言 A：TLS 回调数组首项 = 0 ⇒ 无 TLS 回调

正论文据此说"运行时不会调用任何 TLS 回调"。

**替代假设 H1：转储时机太早，回调表还没被填充。**

`AddressOfCallBacks = 0x00CADA3C`（VA）→ file_offset `0x008ADA3C`。
若真实客户端在这张表填好后才有内容，而我们抓的是"填充前"，
就会读到 0。

**反证尝试**：`0x008ADA3C` 位于节 0（代码段，`0x1000`–`0x8A789A`）。
**回调表本该在数据节**。它落在代码段这件事本身就可疑。

两种可能：
- (a) TLS 目录的 `AddressOfCallBacks` 被加壳器写成**假值**，
  和 `SECURITY` 一样是悬空指针。
- (b) 该 VA 在运行时指向别处（加壳器重定位）。

**进一步反证**：读 `0x008ADA3C` 后续字节
`f6 85 c5 00 21 c7 c5 00 3c d0 c3 00`。
若按 VA 解释：`0x00C585F6` / `0x00C5C721` / `0x00C3D03C` —— 都在镜像外
（文件只到 `0x0E659000`，但 `0x00C585F6 − 0x400000 = 0x008585F6` 在文件内）。
若按 RVA 解释：`0x008585F6` / `0x0085C721` / `0x0083D03C` —— 也在文件内。

⇒ **三个连续的非零值，很像一张真实的 4 字节指针表**，
但首项是 0 意味着"表在这里结束"。

**H1 的最强形态**：这些 `0x00C5xxxx` 值是**其他表**，恰好紧邻
`AddressOfCallBacks` 之后。TLS 回调数组 = `[NULL]`，长度 1，正常终止。

**结论**：断言 A 在"静态字节层面"成立（E1）；
但"运行时也无回调"是**推测**，应降级。已回填正论文 §5 的判据。

### 断言 B：`dir[12]`(IAT) = 0 与"隐藏 IAT 在 `.idata2`，已升级为 dir[12] 实测"冲突

历史记忆（`codol-pe-layout-and-false-findings`）写道：

> 隐藏 IAT 在 `.idata2`（21 DLL / 748 槽，**已升级为 dir[12] header 实测**）

本论文实测：`dir[12].RVA = 0`，`dir[12].Size = 0`。

**这两条不能同时为真**，除非它们说的是**不同的文件**：

| 对象 | 大小 | 节名 | dir[12] |
|---|---|---|---|
| 磁盘原始 EXE | ~7.8 MB | `.text`/`.idata2`/… | 记忆称非零 |
| 本内存镜像 | 230 MB | 全 `.tp3` | **0** |

**替代假设 H2：它们是两个不同的 PE 形态，不应互相引用。**

这正是记忆里已经写过的一句：
> EXE 是另一套形态（无 `.idata2`、dir[12] ABSENT）

⇒ 记忆本身就已经把两者分开了。本论文的 `dir[12]=0` 与
"EXE 侧另一形态"是**一致的**，不构成冲突。

**但正论文 §7 的措辞"推翻了记忆"是过头的**，应改为
"确认了记忆里'EXE 是另一套形态'这一分支"。已修订。

### 断言 C：导入描述符是"骨架"，`FirstThunk` 无意义

**替代假设 H3：我的 `IMAGE_IMPORT_DESCRIPTOR` 偏移算错了。**

`IMP = 0x0E5DC635`。20 字节结构：

```
+0x00 OriginalFirstThunk : 0x0E5DC65D
+0x04 TimeDateStamp      : 0
+0x08 ForwarderChain     : 0xFFFFFFFF
+0x0C Name               : 0x0E5DC66D
+0x10 FirstThunk         : 0x0E5DC665
```

`Name` 指向的 `0x0E5DC66D` 处确实是 `"codoMP_client_shipRetailBase.dll"`。
**这是 H3 被反证的最强证据**（E3）：偏移对，Name 对。

但 `OFT = 0x0E5DC65D` 与 `FT = 0x0E5DC665` **相差 8 字节**。
标准 PE 里 `OFT` 和 `FT` 是两个独立数组，通常指向不同区段
（磁盘上的 ILT 在 `.rdata`，IAT 在 `.idata`），差值不会是 8 且
两个地址可能非常接近。

**实测**：

```
0E5DC65D: 80 00 00 00 00 2C 58 90 | 5E 00 00 00 00 63 6f 64
```

若 `OFT = 0x0E5DC65D` 是 thunk 数组首项：`0x00000080` = 
`IMAGE_ORDINAL_FLAG` 未置位，是 RVA `0x80` → 但 `RVA 0x80` 在 PE 头里，
不是 `IMAGE_IMPORT_BY_NAME`。

⇒ **OFT 也不是有效 thunk 数组**。

**结论 C 成立（E3）**：整个描述符是骨架，
`OFT`/`FT` 都无效，只有 `Name` 有效。

### 替代假设 H4：这个"导入表"其实是加壳器的**诊断/标记结构**，
不是给 loader 用的

有可能 `0x0E5DC635` 处根本不是导入表，而是一段加壳器自己的数据，
恰好长得像导入描述符。

**反证**：`dir[1].RVA` 精确等于 `0x0E5DC635`，且 `Name` 字段精确指向
一个合法 DLL 名。两个巧合叠加的概率极低。

**但 H4 的一个弱形式值得保留**：加壳器**刻意构造**这个结构
让 `dir[1]` 有值（避免某些反调试检查发现 IMPORT=0）。
**这与"骨架"说法等价**，只是动机不同。

## 2. 每个假设的证据

| 假设 | 关键证据 | 结果 |
|---|---|---|
| H1 TLS 回调被转储太早 | 首项严格为 0；表在代码段内 | **静态度量成立，运行时待验** |
| H2 `.idata2` 与本镜像不冲突 | 记忆本身已区分两形态；本镜像全 `.tp3` | **不冲突** |
| H3 描述符偏移算错 | `Name` 精确命中合法 DLL 名 | **反证** |
| H4 是加壳器标记而非真导入表 | `dir[1]` 精确指向它 | **与"骨架"等价** |

## 3. 若判断成立，下游会怎样

### 3.1 TLS 无回调的后果（重要）

若本镜像**真的**没有 TLS 回调：

- 全局 C++ 对象的构造**不依赖它**（MSVC CRT 用 `_initterm`）⇒ 无影响。
- 但某些第三方库（如 Boost.Thread、部分 OpenSSL 版本）用 TLS 回调
  做线程清理 ⇒ 若缺失，会有轻微资源泄漏，但**不阻断启动**。
- **对大厅逆向无直接意义**。这条可以降为"归档事实"。

### 3.2 导入 = 单个 `Base.dll` 的后果（**重大**）

这是本篇真正的收获。它意味着：

1. 我们的"客户端网络栈全在 EXE 里"这类旧结论**需要重新审视**：
   若 EXE 只导入 `Base.dll`，那么 socket / CEF / 平台调用
   **可能全部经 `Base.dll` 转发**，或 EXE 用**延迟加载/手动解析**。
2. 记忆里"B 大洞：Base.dll = CEF/平台层"由此得到**结构性支持**。
3. 若要做"给游戏喂包"这类工作，**必须理解 `Base.dll` 的导出面**。

⚠ 但 §1 H3/H4 提醒：这个描述符是**骨架**，
真实的运行时导入可能远多于此。**不能据此断言"EXE 只依赖 Base.dll"**。
正确措辞：**"静态导入表中仅声明了 Base.dll 一个名字。"**

### 3.3 `dir[12] = 0` 的后果

- 若 loader 按标准处理，不会对 IAT 做写保护 ⇒ IAT 可被运行时改写。
  这与加壳器自填充 IAT 的需求吻合。
- 对我们而言：**搜索 IAT 必须靠"值是镜像内地址的 4 字节槽"模式，
  不能靠目录。**

## 4. 最小可证伪实验

### E1（不需要启动游戏）：磁盘原件对比

读磁盘 `codoMP_client_shipRetail.exe`（7.8 MB）的：
- `dir[1]` / `dir[2]` / `dir[4]` / `dir[9]` / `dir[12]` 的 RVA 与 Size
- TLS 回调表（若有）

若磁盘版 `dir[1].Size != 0` 且有多项描述符 ⇒ "骨架"是本镜像特有，
说明转储过程中被剥离。
若磁盘版也是 1 项 ⇒ 加壳器原始设计如此。

### E2（不需要启动游戏）：确认无 TLS 回调

在镜像里搜"形如 `[ptr, 0]` 且 ptr 指向合法代码"的 8 字节序列，
统计有多少。若极多 ⇒ 0 号位的 0 不能作为"表终止"的判据。

### E3：`0x008ADA3C` 是否被别处引用

若镜像内无任何代码引用 `0x00CADA3C`（TLS 目录除外），
则它更像加壳器写的假值。若有代码读它，则是真表。
