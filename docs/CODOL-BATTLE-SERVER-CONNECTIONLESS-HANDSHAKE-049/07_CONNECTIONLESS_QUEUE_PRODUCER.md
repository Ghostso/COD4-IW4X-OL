# 07 — D2:连接无关泵队列与生产者链(含 D0 地址口径修正)

**目标:** 围绕 048 记录的连接无关泵队列消费者,确认数据结构、写入者、上游 socket 生产者,
并判断它与 in-match P5 路径是否独立。
**证据:** `evidence\d50..d58`、`evidence\049_analysis.json` → `d0_address_convention_audit` / `d2_connectionless_queue`。

---

## D0. 首先修正 048 的一处地址口径错误(重要)

048 `04` §4 与 `evidence\s130_621E50.txt` 把泵队列消费者记为 **`0x621E50`**,并 dump 了
文件偏移 `0x621D90..0x622100`。本轮复核:

```
泵 0x0F8FB0 内:
007F9075  e8 d6 8d 12 00     call 0x621E50   ; op_str 是 VA
rel32 = 0x00128DD6
target file_offset = 0x0F9075 + 5 + 0x128DD6 = 0x221E50   ; RVA
```

| 项 | 值 |
|---|---|
| 调用站点 | RVA `0x0F9075`(字节 `e8d68d1200`) |
| op_str 目标(VA) | `0x00621E50` |
| **真实目标 RVA(== 文件偏移)** | **`0x221E50`** |
| 真实目标 prologue | `55 8B EC 81 EC A8 00 00 00`(合法函数入口) |
| 048 dump 区域 `0x621E50` 的字节 | `c6 5e 5b 5d c2 08 00 8b`(**函数尾/中段**,非入口) |

**裁定:**
- 048 的 `0x621E50` 是**VA**,其 RVA 为 `0x221E50`;
- 048 的 `s130_621E50.txt` dump 的是**错误区域**(文件偏移 `0x621D90`),**不是**出队函数;
- 出队函数的正确位置是 **RVA `0x221E50`**(`evidence\d52_dequeue_real_221E50.txt`)。
- 本修正不改变 048 的**结论方向**(泵 → 解析 → 分派),但改变其**地址证据**。

## 1. 连接无关泵与队列消费者(修正后)

```
0x0F8FB0  连接无关泵
  0x0F9075  call 0x221E50      ; 取下一个已入队报文
  0x0F9135  call 0x1C1EE0      ; 连接无关解析器
  0x0F913D  jmp  0x0F9060      ; 循环
```

- 泵在 `0x0F9060..0x0F913D` 循环:取包 → 组装 `msg_t` → `0x1C1EE0` 解析 → 回到循环。
- **已证实:** 报文 → `0x1C1EE0` → `0x1C13A0` → 各命令 handler(继承 048)。

## 2. 出队函数 `0x221E50`(修正后)

```
00221E50  push ebp; mov ebp,esp; sub esp,0xA8
00221E6C  push 0x81A5558        ; 资源/锁名字符串 VA
00221E77  call [0xCA819C]       ; 加锁
00221E82  call 0x643300         ; 取队列对象
00221E91  call 0xBAC600         ; 转接口
00221EA7  call eax              ; 虚调用: 状态检查 (vtable+0x20)
00221ED3  call edx              ; 虚调用: 出队 (vtable+0x2C)
...
00221FF1  mov [edi+0x14], edx   ; 写回 datalen
00222022  call [0xCA8190]       ; 解锁
```
- **输入侧**:`0x221E50(arg1=dst, arg2=?, arg3=?)` 通过 `[0xCA819C]`/`[0xCA8190]` 临界区加锁,
  对队列对象做两次虚调用(状态检查 + 出队)。
- **注意**:`0x81A5558` 是 **VA**,其 RVA `0x7DA5558` **超出**恢复映像(0xA65000)→
  该字符串在不可读区,仅能记录"存在该引用",不能解码其内容。

## 3. 泵的直接调用者(本轮新闭合)

| 项 | 值 |
|---|---|
| 泵 `0x0F8FB0` 的直接调用者 | **仅 `0x1BF3BC`** |
| 出队 `0x221E50` 的调用者 | `0x0F8F25`、`0x0F9075`(两者都在函数 `0x0F8D6D` 内 —— 该函数包含泵循环 `0x0F8FB0`) |

```
0x1BF300  (驱动器)
  0x1BF3A6  call 0x1BF1C0      ; 生产者/入队助手
  0x1BF3B0  call esi           ; (间接,时间/锁原语)
  0x1BF3BC  call 0x0F8FB0      ; 连接无关泵
```
`0x1BF300` 的调用者:`0x1BF52D`、`0x37976B`、`0x37C2F5`。

## 4. 生产者/入队助手 `0x1BF1C0`

```
001BF1C0  push ebp; mov ebp,esp; sub esp,0x854
001BF1F5  push 0x30; push 0; lea eax,[ebp-0x854]; call 0xC42DE0   ; 初始化消息缓冲
001BF20D  [ebp-0x84C] = buf;  [ebp-0x844] = 0x800                 ; 缓冲 + 上限
001BF274  call 0x66EA90  (×3)                                     ; 追加字段
001BF2DD  call 0x675310                                          ; 组帧/入队(VA 0x00675310 → RVA 0x275310)
```
- `0x1BF1C0` 的调用者:**仅 `0x1BF3A6`**(即驱动器 `0x1BF300` 内)。
- `0x675310`(VA)的真实 RVA 是 **`0x275310`**;它是组帧/写入助手(有 `0x800` 栈缓冲、
  格式串 `0xDC28FC` 等)。
- **未证实:** `0x1BF1C0` 的 `buf` 来源之上,哪个函数从 socket 收到字节并调用它。
  `0x1BF300` 自身没有直接 `recv`/`recvfrom` 调用。

## 5. 与 in-match P5 路径是否独立?

| 判据 | 连接无关路径 | P5 路径 |
|---|---|---|
| 收包原语 | `recvfrom`(未连接 socket,048 §3) | `recv`(`0x873A00`→`0x876ED0`) |
| 解析器 | `0x1C1EE0` → 分派 `0x1C13A0` | `0x7765A0` 读字节 → 分支 |
| 泵/循环 | `0x0F8FB0`(泵) | `0x7A41D0`(消费循环) |
| 调用者 | `0x1BF3BC` | `0x7838A0`(per-tick driver) |

- 两条链在**函数层面无共享节点**:`0x0F8FB0` 与 `0x7A41D0` 互不调用;
  `0x1C13A0` 的唯一调用者是连接无关解析器 `0x1C1EE0`。
- **未证共享**:未发现两者共用同一全局队列或同一缓冲;但也**未排除**它们共用底层
  消息/缓冲基础设施(本轮未找到该共享边界,故不下"独立"的强结论)。

## 6. 最后已证实节点 / 第一个未证实节点

| 链 | 最后已证实节点 | 第一个未证实节点 |
|---|---|---|
| 连接无关泵 | 泵 `0x0F8FB0` ← **唯一调用者 `0x1BF3BC`**(在 `0x1BF300` 内) | `0x1BF300` 的 socket 生产者(其调用者 `0x37976B/0x37C2F5/0x1BF52D` 之上) |
| 队列生产者 | `0x1BF1C0`(入队助手)← `0x1BF3A6` | 谁用 `recv` 结果填充 `0x1BF1C0` 的 `buf` |
| 队列消费者 | 出队 `0x221E50`(RVA 修正后) | 队列对象/结构地址(`[0xCA819C]` 保护的全局)未定性 |

**最小未闭环边:** 连接无关队列的 **socket 生产者**(把 `recv` 结果交给 `0x1BF1C0` 的函数)。

## 7. 口径纪律

- 修正 048 地址时,只改**地址证据**,不改 048 的结论方向;并保留"048 记录的符号名"以便对照。
- `0x81A5558`(VA)超出映像时,只记"存在引用",**不**猜测其内容。
- 未把"泵只被 `0x1BF3BC` 调用"写成"泵只被一个模块使用";仅陈述**已检查映像范围内**的直接调用者。
