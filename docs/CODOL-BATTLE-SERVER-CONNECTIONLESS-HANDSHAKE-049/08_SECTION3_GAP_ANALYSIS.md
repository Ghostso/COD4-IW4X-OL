# 08 — D3:第 3 节区映像缺口身份与覆盖分析

**目标:** 复核 048 记录的第 3 节区缺口,确认缺的是**文件数据 / 恢复过程产物 / 工具无法解码**,
并检查工作区是否已有可用的其他恢复映像或原始 PE 证据。
**证据:** `evidence\049_analysis.json` → `d3_section3_gap`;`01` §4/§5。

---

## 1. 第 3 节区几何(重新核验)

### 1.1 磁盘 EXE(S-EXE,`36997674…b537`)

| 项 | 值 |
|---|---|
| 节名 | `.tp3` |
| VA | `0x00A16000` |
| VSize(声明) | `0x0DBB1CC0` |
| PointerToRawData | `0x00702000` |
| **SizeOfRawData** | **`0x00062000`** |

### 1.2 恢复映像(S-IMG,`17cef6e0…f045`)

| 项 | 值 |
|---|---|
| 映像总长 | `0x0A65000` = 10,899,456 |
| 第 3 节 Raw 起点(=VA) | `0x00A16000` |
| 映像实际覆盖到 | `0x0A65000` |
| 第 3 节在映像中的 present 字节数 | `0x0A65000 - 0x00A16000` = **`0x4F000`** |
| 第 3 节声明 VSize | `0x0DBB1CC0` |
| **缺失字节数** | `0x0DBB1CC0 - 0x62000` ≈ **229.6 MB**(VSize 口径) |

- 映像恰好覆盖到第 3 节 **RawSize(`0x62000`)的前 `0x4F000` 字节**;
  声明 RawSize 本身只有 `0x62000`,远小于 VSize。
- `0xA78000` 之后无任何字节(`evidence\049_analysis.json` → `after_section3_raw_nonzero = 0`)。

## 2. 缺的是文件数据、恢复产物,还是工具无法解码?

**结论:缺的是文件数据(第 3 节被壳压缩/截断),不是工具解码能力问题。** 依据:

1. **磁盘 EXE 的 RawSize 就只有 `0x62000`**。第 3 节在磁盘上是 `.tp3` 压缩存储,
   解压后的 VSize(`0x0DBB1CC0`)从未以明文形式落在文件里。
2. **恢复映像长度 `0x0A65000` 恰好等于**第 3 节 Raw 起点 `0xA16000` + `0x4F000`。
   即抓取过程在第一节 `.tp3` 的 Raw 边界附近停止,并没有把第 3 节的其余部分展开写出。
3. **同一构建的字符串/代码在同一映像中可正常解码**(capstone 逐字节反汇编无误),
   说明工具链能解码 present 区域;缺的是**数据本身**,不是解码器。
4. `0x81A5558`(VA,RVA `0x7DA5558`)等引用的目标**超出映像长度** → 目标数据不在文件里。

**裁定:第 3 节区缺口 = 缺文件数据(壳压缩 + 恢复过程未展开),不是工具无法解码。**

## 4. run2 是否可用?(比较后才决定)

| 对比项 | 结果 |
|---|---|
| 大小 | 与基准相同(10,899,456) |
| 第 3 节 present 窗口(`0xA16000..0xA65000`,0x4F000 字节)与基准 | **不相等**(3,167 字节差异) |
| 泵 `0xF8FB0` / 出队 `0x221E50` / P5 循环 `0x7A41D0` / 分派 `0x1C13A0` 首字节 | 全部**与基准不同** |
| 16 字节块相等 | 113,572 / 681,216 |
| 全文件差异 | 8,671,354 字节 |

**裁定:run2 不可用。** 它既**没有**补上第 3 节区,又与基准代码段不一致;
用它替换基准会改变所有地址证据的语义。仅保留其哈希与差异记录作为身份证据。

## 6. 对 in-match 主链的影响

- 第 3 节区缺失**只影响**"解析器/生产者可能位于第 3 节"这一替代解释;
  它**不**影响本轮已证实的第一节内证据(P5 循环、`recv`、泵、出队、连接无关层)。
- 因此 `10` 的 050 优先目标**优先选择**可在 present 区域内闭环的边(P5 `recv` 缓冲 →
  `0x7765A0`),而不是依赖第 3 节区补全。
