## 2. 为什么"离线复算"不能充当原始响应（三重理由，全部可复核）

### 2.1 复算产物 ≠ 客户端实收字节

`build_task_reply_objects` 使用 **`os.urandom(16)` 作为 IV**（`codol_crypto.py:715`）：

```
00715  iv = os.urandom(16)
00716  enc = cbc_encrypt(aes_in, iv, bytes(plain))
```

**⇒ 每帧密文都不同。复算只能复现"布局"，绝不可能复现"当日那一帧的字节"。**

### 2.2 复算的会话对象长度与代码声明不符

| 来源 | 长度 |
|---|---|
| 当日日志 | **236 B** |
| 本次用当前代码复算（同参数） | **236 B**（可复现） |
| **代码内注释声明的普通布局** | **237 B** |

**⇒ 相差 1 B ⇒ 当日实际走的分支/参数与当前代码不完全一致。**
（已列为 CAPTURE_PLAN §1.3 的限制性发现。）

### 2.3 复算无法回答核心问题

即使知道响应字节，**A/B 仍取决于客户端如何解析**——
而该解析逻辑是 NEXT-001..007 未闭合的部分
（NEXT-007 已证：A/B 只随整条 `0x238` 记录被整块写入，不存在字段级写入）。

**⇒ 三者叠加：不能用复算替代采集。**（遵守任务"不把服务端生成的数据冒充客户端实际收到的原始响应"）
