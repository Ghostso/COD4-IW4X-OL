# 使命召唤OL 项目核心铁律与唯一基线规范

## 铁律一：没有逆向就没有成果

1. **绝对禁止无逆向依据的猜测与盲目修改**：
   - 本项目走到今天，所有重大突破（解密门解锁、Demonware 握手、KDF 密钥派生、重定位越界修复、BSP 碰撞与 Pmove 对齐）全部是基于“动态转存内存静态镜像、字节逐位对照、反汇编交叉验证”的逆向成果堆出来的。
   - 严禁任何凭空猜测、循环脚本自动化盲跑，每一次启动都必须是单次、受控、有确凿证据的。

2. **逆向标准操作流（SOP）写死**：
   - **第一步**：确定运行期绝对基址（ImageBase / ActualBase）及相对默认基址的偏差（Delta）。
   - **第二步**：转存运行期物理/虚拟内存为静态二进制镜像（Memory Dump）。
   - **第三步**：对比磁盘文件原始字节与运行期内存字节，定位每一个差异字节（Delta DIFF）。
   - **第四步**：核对 PE 结构（节区、导出表、重定位表 `.reloc`、导入表 IAT），查明写入指令的绝对来源（是 NTDLL 重定位引擎、壳解密泵、还是钩子注入）。
   - **第五步**：形成唯一确证结论后，方可进行最小化精确修补（严禁大面积覆写）。

## 逆向确证案例归档：RVA 0x4D51 崩溃（D1 / 85 错位写入）

### 1. 现象
- 磁盘字节：`90 90 90 89 04 24`
- 运行期字节（Base=0x00810000）：`90 D1 90 89 04 24`（多出 `D1`，指令变为 `rcl` 崩溃）
- 运行期字节（Base=0x00350000）：`85 90 89 04 24`（变为 `85`，指令变为 `test` 崩溃）

### 2. 静态与运行期镜像对比证据（DEDRUN_RUNTIME_0x810000.bin）
```text
Preferred Base: 0x00400000, Actual Base: 0x00810000, Delta = +0x00410000
Offset    RVA     Disk Bytes  Dump Bytes  Difference
------    ------  ----------  ----------  ----------
0x00414F  0x4D4F  0xC0        0xC0        MATCH
0x004150  0x4D50  0x90        0x90        MATCH
0x004151  0x4D51  0x90        0xD1        DIFF: 0xD1 - 0x90 = +0x41 (+0x00410000!)
0x004152  0x4D52  0x90        0x90        MATCH
0x004153  0x4D53  0x89        0x89        MATCH
```

### 3. 根因
重定位表（`.reloc`）文件偏移 `0x4D2E00` 处残留幽灵条目 `0x3D4F`（Type 3 HIGHLOW，指向 RVA `0x4D4F`）。
当年修改者将 5 字节指令改为 `31 C0 90 90 90` 时未清理重定位表。Windows 加载器在映像映射期对 `0x4D4F` 起始的 DWORD 执行 `+ Delta`，导致第 3 字节（RVA `0x4D51`）被加上了 Delta 高位（`0x41` 或 `0x85`），导致整条指令错位。
- 为什么 CDB 的 `ba w4` 挂上后抓不到：因为修改发生在 NTDLL 映像重定位阶段，早于用户态调试器硬件断点生效时间点。
- 根治：将文件偏移 `0x4D2E00` 的 2 字节从 `4F 3D` 覆写为 `00 00`（`IMAGE_REL_BASED_ABSOLUTE` 空项）。
