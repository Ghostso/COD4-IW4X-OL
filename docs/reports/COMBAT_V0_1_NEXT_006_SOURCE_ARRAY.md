## 0. 结论先行（回答问题 2、3）

> **Q2：EAX 指向的数组由谁创建和填充？**
>
> **答：未闭合，但本次把"谁生产"精确定位为"谁调用泵"。**
>

> ```
> 0x7FA800 的【调用者】          ← ★ 源数组真正的提供者（未定位）
>    └─ 0x7FA800 定时器泵         : 把自身入参原样搬进条目（§2.2，逐条入参映射）
>         └─ 回调 0x6379E0        : 取 [ebp+0x18]（= 条目内某字段）

## 2. `eax`（源数组）的实际来源 —— 逐级判定

| 层级 | 事实 | 等级 |
|---|---|---|
| L1 | `0x637950` 的 `eax` = 转发器 `0x6379E0` 的 `[ebp+0x18]` | **CONFIRMED**（`0x6379ED mov eax,[ebp+0x18]`） |
| L2 | `0x6379E0` 的 `[ebp+0x18]` = 回调第 **6** 个参数 | **CONFIRMED**（cdecl 参数序） |
| L3 | 回调被 `0x7FA9B0 call dword ptr [ebp-0x20]` 调用，**只压了 2 个参数**（`0x7FA9AA push 0`、`0x7FA9AC push ecx`） | **CONFIRMED** |
| L4 | ⇒ **参数 3–6 不在栈上**，只能来自**调用约定隐含的寄存器**（`esi`/`edi` 等，`0x7FA9B0` 前 `esi` = 条目指针 `[ebp-0x50]`） | **HIGH** |
| L5 | ⇒ 源数组**必须在条目结构内部或条目指向的对象内**，且偏移未判定 | **UNKNOWN** |
| **L6** | ⇒ **数组的生产者（网络解析 / 缓存 / 静态表）仍未知** | **UNKNOWN** |

### 2.1 `0x7FA9B0` 处寄存器的实测状态

| 寄存器 | 值 | 证据 |
|---|---|---|
| `esi` | 条目指针（`[ebp-0x50]`） | `0x7FA8D1 lea edi,[ebp-0x50]` 之后 `esi` 与 `edi` 同源（`0x7FA9B6 lea esi,[ebp-0x50]` 为**调用后**重设） |
| `edi` | `[ebp-0x50]`（`0x7FA8D1`） | 逐指令 |
| `ebx` | `1` | `0x7FA8B4 mov ebx,1` |
| `[ebp-0x20]` | **回调函数指针**（条目 `+0x20` 的副本） | NEXT-005 §1 |

**⇒ 在 `0x7FA9B0` 之前，`esi`/`edi` 都指向条目结构；
因此转发器的 `[ebp+0x18]` 极可能来自 `esi`/`edi` 基址的某个偏移。
该偏移未判定 ⇒ 数组来源未闭合。**

## 2.2 ★ 关键机制：`0x7FA640` 是**直通**（no transformation）

本次逐条比对 `0x7FA640`（条目填充）的两个调用点，确认**泵不生产数组，只转发**：

**`0x7FA640` 的入参映射（由函数体读取的偏移确定）：**

| 入参 | 写入目标 | 证据 |
|---|---|---|
| `[ebp+8]`（eax） | `[esi+0x00]` | `0x7FA65A mov eax,[ebp+8]` → `0x7FA663 mov [esi],eax` |
| `[ebp+0xC]` | `[esi+0x28]`（引用计数对象） | `0x7FA6F6`/`0x7FA6F9`/`0x7FA70C` |
| `[ebp+0x10]` | `[esi+0x30]` | `0x7FA70C mov edx,[ebp+0x10]` → `0x7FA715 mov [esi+0x30],edx` |
| `[ebp+0x14]` | `[esi+0x34]` | `0x7FA70F` → `0x7FA71B` |
| `[ebp+0x18]` | `[esi+0x38]` | `0x7FA718` → `0x7FA721` |
| `[ebp+0x1C]` | `[esi+0x3C]` | `0x7FA71E` → `...` |
| `[ebp+0x20]` | `[esi+0x40]` | `0x7FA724` |
| `[ebp+0x24]` | `[esi+0x44]` | `0x7FA72A` |
| `[ebp+0x28]` | `[esi+0x18]` | `0x7FA69B mov ecx,[ebp+0x28]` |
| `[ebp+0x2C]` | `[esi+0x2C]` | `0x7FA712 mov ebx,[ebp+0x2c]` |
| `[ebp+0x30]` | byte 标志 | `0x7FA647 mov bl,[ebp+0x30]` |

**调用点 A（`0x7FA866..0x7FA8A8`）的 11 个 push 正是上表的 11 个入参，
且**它们就是 `0x7FA800` 自己的同名参数**（`[ebp+0x10]`、`[ebp+0x14]`、`[ebp+0x18]`、
`[ebp+0x1C]`、`[ebp+0x20]`、`[ebp+0x24]` 等，`0x7FA866..0x7FA882` 逐条可见）：

```
007FA866  mov ecx,[ebp+0x20]
007FA869  mov edx,[ebp+0x1c]
007FA86C  push edi / push ebx / push eax
007FA86F  mov eax,[ebp+0x24] / push eax
007FA873  mov eax,[ebp+0x18] / push
007FA876  push ecx
007FA877  mov ecx,[ebp+0x14]
007FA87A  push edx
007FA87B  mov edx,[ebp+0x10]
007FA87E  push eax / push ecx / push edx / push ecx
007FA882  mov ecx,[ebp+0xc]
```

**⇒ 机制结论（CONFIRMED）：`0x7FA800` 把【自己的调用者】传进来的参数
原样搬进定时器条目，不做任何加工。**

**因此：源数组既不由泵创建、也不由泵填充 ——
它由 `0x7FA800` 的**调用者**提供，经"泵 → 条目 → 回调"三层原样传递。**

## 4. 唯一剩余缺口（精确到可执行动作）

> ### 缺口 U2-G1⁽⁵⁾
>
> **待答**：`0x7FA9B0` 调用回调时，转发器 `0x6379E0` 的 **`[ebp+0x18]`（arg6）**
> 由哪个寄存器/偏移提供？
>
> **闭合所需的静态证据（三条，任选其一）：**
>
> 1. **确定该回调的完整调用约定**：
>    `0x62DE90` 把 `0x6379E0` 作为 `0x6292B0` 的处理器注册；
>    跟踪 `0x7FA640` 把该指针存入条目 `+0x20` 时，
>    **同时存入的其它字段**（`+0x2C`..`+0x48`，共 5 个 dword 参数）
>    ——其中应有一项就是源数组。
>    判据：`0x7FA9B0` 前 `esi`/`edi` = 条目基址，故 `[ebp+0x18]` 必来自条目内偏移。
>
> 2. **确定 `0x62DE90` 的虚调用入口**（主 vtable +0x024）：
>    谁在什么条件下调用它，即可知道它注册定时器时**打算传入什么数组**。
>
> 3. **反查 `0xE4E20C` 索引表的填充者**：
>    该表把 `id → 条目` 映射；填充者通常也是"设置数组"的那一方。
>
> **若三条均无法闭合，则唯一剩下的证据是配对抓包（见 §5）。**
