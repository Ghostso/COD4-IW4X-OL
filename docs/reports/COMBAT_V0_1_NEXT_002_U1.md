| 问题 | 结论 | 等级 |
|---|---|---|
| 字段是"字节"还是"dword"？ | **字节**。读取点是 `cmp byte ptr [esi+0x278], 0`；写入点用 `mov byte` / `mov word` | **CONFIRMED** |
| 置 1 的位置 | **`0x62B640`（函数体 `0x62B640`）在 `0x62B653 mov byte [esi+0x278], 1`** | **CONFIRMED** |
| 置 1 的**前置条件** | **`0x63735F` 通过 ID 比对：`[ebp-8]==[esi+0x1c] && [ebp-4]==[esi+0x20] && vtable+0x60()==0`** | **CONFIRMED** |
| 置 0 / 复位 | **`0x62F454` 族：`0x62F473 mov word [edi+0x278], bx`（`bx=0`）**，同时清零 `+0x27A`/`+0x288`/`+0x105D8`，并把索引 `+0xE360` 置 `0xFFFFFFFF` | **CONFIRMED** |
| 首次清零 | **`0x62C04E mov [ebx+0x278], edi`**（构造/初始化路径） | **CONFIRMED（写点）** |
| 其它字节宽写点 | `0x62B653`（置 1）、`0x62F474`（置 0）；其余同偏移写点均为 **dword**，属**其它对象布局** | **CONFIRMED** |
| 该字段的**业务含义** | **"预约/接受流程已就绪"的使能位**：它是 `0x632680` 与 `0x63735F` 的共同入口条件 | **HIGH（由两处相同用法支撑）** |
| handler 入口是否要求它 != 0 | **是**。`0x63268D cmp byte [esi+0x278],0 / je 0x6328EB` 直接返回 | **CONFIRMED** |

> 而 `0x62C04E` 是**清零**、`0x62F473` 是**复位**、`0x62DF08` 属其它对象。

## 1. 字段宽度与语义边界（工作二.1）

### 1.1 全部同偏移访问（`disp32` 形式，共 60 处）

按**访问宽度**分类（`p1_278.py` 全量输出）：

| 宽度 | 访问点 | 说明 |
|---|---|---|
| **byte 读** | `0x62FD80 mov al,[ecx+0x278]` / ret | **独立 getter**（`0x62FD7F` 仅 7 字节） |
| **byte 读** | `0x6373D8 mov cl,[esi+0x278]` | `0x63735F` 内的闸门 |
| **byte 读** | `0x63268D cmp byte ptr [esi+0x278],0` | **accepted handler 入口闸门** |
| **byte 写 = 1** | `0x62B653 mov byte [esi+0x278], bl` (`bl=1`) | ★ **开闸** |
| **byte 写** | `0x62B653` 同处 `0x62B659 mov byte [esi+0x27A], bl` | 相邻字节一并置 1 |
| **word 写** | `0x62F473 mov word [edi+0x278], bx` (`bx=0`) | ★ **关闸**（同时覆盖 `+0x278` 与 `+0x279`） |
| **byte 写 = 1** | `0x62F467 mov byte [edi+0x285],bl` / `0x62F46D [edi+0x27A],bl` | 复位族的一部分 |
| dword 读/写 | 其余约 50 处（`0x461F1A`、`0x509D3A`、`0x8CAE*`、`0x92D7*` …） | **不同对象**：这些是各自结构里偏移恰好也是 `0x278` 的**4 字节字段**，与战斗链无关（无一处与匹配对象 `0x62xxxx`–`0x63xxxx` 的 vtable 上下文相交） |

⇒ **该字段是 1 字节**。把它当 dword 会比较到相邻字节（`+0x279`），是错的。

### 1.2 为什么可以断定 dword 访问点与本题无关

匹配对象由 `0x62CD30` / `0x637720` 初始化，二者只初始化：
`+0x7230`、`+0xE360`、`+0x7470..+0x7470+0x6EF0`。
**`+0x278` 属于对象的低偏移区**（`0x278 < 0x7230`），
其初始化必定发生在构造函数 / 首次使用路径；
而 byte 读点 `0x63268D`、`0x6373D8`、`0x62FD80` 与 byte 写点 `0x62B653`、`0x62F473`、`0x62C04E`
**全部落在 `0x62B640`–`0x6373D8` 这一连续区间**，上下文互通。

## 2. 开闸：`0x62B640`（工作二.2）

### 2.1 函数体（本次新增证据）

```
0062B640  55              push ebp
0062B641  8bec            mov  ebp, esp
0062B643  83ec10          sub  esp, 0x10
0062B646  53              push ebx
0062B647  bb01000000      mov  ebx, 1            ; ★ 常量 1
0062B64C  57              push edi
0062B64D  8d8e28070100    lea  ecx, [esi + 0x10728]   ; 一个锁/容器（0xB75D80/0xB75D90 族）
0062B653  889e78020000    mov  byte ptr [esi + 0x278], bl   ; ★★ 开闸
0062B659  889e7a020000    mov  byte ptr [esi + 0x27A], bl   ; 相邻字节
0062B65F  e81ca75400      call 0xB75D80
0062B664  8b06            mov  eax, [esi]        ; vtable
0062B666  8b90a8000000    mov  edx, [eax + 0xA8]
0062B66C  8bbe10060100    mov  edi, [esi + 0x10610]
0062B672  8bce            mov  ecx, esi
0062B674  ffd2            call edx
```

**特点**：无参数（`__thiscall`，`esi` = 匹配对象），
把 `+0x278` 与 `+0x27A` 同时置 **1**，并在一个 `[esi+0x10728]` 临界区上成对调用 `0xB75D80`/（后续大概率 `0xB75D90`），
最后走 `vtable+0xA8`。

### 2.2 调用者：`0x637488` 与 `0x637573`（本次新增证据）

```
00637440  84c9              test cl, cl
00637442  0f858e000000      jne  0x6374D6            ; 若 cl!=0 -> 直接返回（不置位）
00637448  3955f8            cmp  dword [ebp-8], edx      ; ★ ID 低半
0063744B  7549              jne  0x637496
0063744D  3945fc            cmp  dword [ebp-4], eax      ; ★ ID 高半
00637450  7544              jne  0x637496
00637452  8b06              mov  eax, [esi]
00637454  8b5060            mov  edx, [eax + 0x60]
00637457  8bce              mov  ecx, esi
00637459  ffd2              call edx                     ; vtable+0x60()
0063745B  84c0              test al, al
0063745D  751a              jne  0x637479
0063745F  8bce              mov  ecx, esi
00637461  c7867c02000003000000 mov dword [esi+0x27C], 3   ; 相邻状态
0063746B  e8007fffff        call 0x62F370               ; 复位族
00637470  ... ret 8
00637479  8b461c            mov  eax, [esi + 0x1c]
0063747C  8b4f18            mov  ecx, [edi + 0x18]
0063747F  894820            mov  [eax + 0x20], ecx      ; 复制 ID 低半
00637482  8b571c            mov  edx, [edi + 0x1c]
00637485  895024            mov  [eax + 0x24], edx      ; 复制 ID 高半
00637488  e8b341ffff        call 0x62B640               ; ★★ 开闸
```

**开闸的完整条件（CONFIRMED）：**

```
cl == 0
AND dword [ebp-8] == edx          &&  dword [ebp-4] == eax
AND [esi]vtable+0x60() != 0
  -> 把 [edi+0x18]/[edi+0x1c] 复制到 [esi+0x1c]+0x20/0x24
  -> call 0x62B640  => [mk+0x278] = 1
```

> 其中 `edx`/`eax` 在 `0x6373B8` 附近来自 `[esi+0x1c]`（`0x6373BB mov ecx,[esi+0x1c]`）
> 的 `+0x20`/`+0x24`，即 **一个 64-bit ID 的校验**。
> 也就是：**只有传入的 64-bit ID 与本对象记录的 ID 匹配时，才把闸门打开。**

### 2.3 第二个调用者 `0x637573`

## 3. 关闸与复位（工作二.3）

### 3.1 `0x62F454` 族（复位）

```
0062F467  889f85020000      mov byte [edi+0x285], bl     ; bl=0
0062F46D  889f7a020000      mov byte [edi+0x27A], bl
0062F473  66899f78020000    mov word [edi+0x278], bx     ; ★ 关闸（+0x278/+0x279 一起清）
0062F47A  66899f88020000    mov word [edi+0x288], bx     ; accepted 闩锁一并清
0062F481  889f87020000      mov byte [edi+0x287], bl
0062F487  899fd8050100      mov dword [edi+0x105D8], ebx
0062F48D  c78760e30000ffffffff mov dword [edi+0xE360], 0xFFFFFFFF   ; 索引 = -1
0062F497  889f11870300      mov byte [edi+0x38711], bl
0062F49D  889f8a020000      mov byte [edi+0x28A], bl
0062F4A3  e8087fecff        call 0x4F73B0
0062F4A8  8db718a10300      lea  esi, [edi + 0x3A118]
```

**生命周期要点**：
- 复位把 **`+0x278`（闸门）**、`+0x27A`、`+0x288`（accepted 闩锁）、`+0x105D8`、
  **`+0xE360`（当前槽索引 = -1）** 一次性清成"未预约"状态。
- `+0xE360 = 0xFFFFFFFF` 与 `0x6326AA cmp [esi+0xE360],edi / jl` 完全对应：
  **索引为 -1 时，accepted handler 在闸门 3 就退出**，根本走不到 A/B 比较。

### 3.2 `0x62C04E`（初始化路径清零）

```
（函数 ~0x62C080 附近）
  0x62C04E  mov dword [ebx+0x278], edi     ; edi=0 -> +0x278..+0x27B 全清
  0x62C0C7  lea esi, [ebx+0x7470]          ; 预约槽数组
  0x62C0E8  mov dword [ebx+0xE360], 0xFFFFFFFF
```
⇒ 与 §3.1 同族，属**构造/重置**语义。

### 3.3 `0x62F370`（另一处复位）

`0x63746B call 0x62F370` 出现在**ID 不匹配**的分支（`0x63745D jne` 之后走的是 `0x637479`；
不匹配则 `0x637496`；而 `0x63745F` 是 vtable+0x60()==0 的分支）。

## 4. accepted handler 的入口要求（工作二.4）

### 4.1 入口闸门（重录，逐字节）

```
0063268D  80be7802000000    cmp byte ptr [esi + 0x278], 0
00632695  0f8450020000      je  0x6328EB             ; == 0 -> 返回
0063269B  833db046640703    cmp dword [0x76446b0], 3
006326A2  0f8d43020000      jge 0x6328EB             ; 全局状态 >=3 -> 返回
006326A8  33ff              xor edi, edi
006326AA  39be60e30000      cmp dword [esi + 0xE360], edi
006326B0  0f8c37020000      jl  0x6328ED             ; 索引 < 0 -> 返回
```

**入口要求（CONFIRMED）：**
1. `[mk+0x278] != 0`（预约流程已使能）
2. `[0x76446B0] < 3`（尚未进入战斗连接状态 —— 即**握手还没开始**）
3. `[mk+0xE360] >= 0`（有有效预约槽）

### 4.2 与 `0x63735F` 的**相同闸门**（交叉证据）

`0x6373D8` 处：`mov cl,[esi+0x278]` / `test cl,cl` / `je 0x637448`。
`0x637440` 处：`test cl,cl` / `jne 0x6374D6`。
⇒ **同一个字节在两个不同子系统里都作为"是否继续预约/接受处理"的开关**，
这是把该字段判定为"预约/接受流程使能位"（HIGH）的主要依据，
但**其确切业务命名仍是 UNKNOWN**（无字符串或 UI 文本直接绑定）。

### 4.3 完整生命周期（本次闭合）

```
[构造/重置]  0x62C04E  [mk+0x278] = 0     ; 4 字节清
             0x62F473  [mk+0x278] = 0     ; 2 字节清
             同处      [mk+0xE360] = -1
                    |
                    |  收到匹配事件（64-bit ID 匹配 + vtable+0x60()!=0）
                    v
[开闸]       0x637488 -> 0x62B640
             0x62B653  [mk+0x278] = 1
             0x62B659  [mk+0x27A] = 1
             0x63746B(否)  0x62F370 = 复位族
                    |
                    |  accepted handler 被调用（唯一路径：0x7F153F 分派）
                    v
[使用]       0x63268D  cmp byte [mk+0x278], 0  -> je 静默返回
             0x63269B  cmp [0x76446B0], 3        -> jge 静默返回
             0x6326AA  cmp [mk+0xE360], 0        -> jl  静默返回
             0x6326B9/0x6326C8  比较 A/B（见 U2 报告）
                    |
                    |  任何一次连接尝试 / 结束
                    v
[关闸]       0x62F473（复位族）或 0x62C04E（重建）
```

**这是本任务对 U1 的最终结论：入口条件已闭合。**

### 5.1 对"入口条件"的必要限定

可以确定的是**判定式与生命周期**；可以确定**不是**：
- ❌ "该字段由 accepted 响应置 1" —— accepted handler **只读**它（`0x63268D`），全程无写；
- ❌ "该字段是全局开关" —— 它是**对象成员**（`[esi+0x278]`），每个匹配对象各有一份；
- ❌ "该字段的 4 字节整体有意义" —— 只有**最低字节**被读；`0x62C04E` 的 4 字节清
  说明高位字节是别的标志（`+0x279`/`+0x27A`/`+0x27B`，其中 `+0x27A` 与它同步置 1）。
