## 1. 工作三：失败路径风险核实（`0x637930`）

### 1.1 `0x637930` 的触发条件（NEXT-004/006 已证，本次复核）

```
[注册] 0x632728 / 0x62F951 / 0x62FBD7
         push 0x637930          ; 回调
         push 0x27              ; timer id = 0x27
         call 0x6292B0          ; 注册

[触发] 0x6292B0 内（消息 0x27 发送器）
        0062932F  call 0x7F44B0      ; 发送
        00629337  test al, al
        00629339  jne  0x629351      ; ★ 发送成功 -> 跳过
        0062933B  test ebx, ebx / je
        00629343  push 0 / push 0 / push 0 / push 0
        0062934C  call ebx           ; ★★ 发送失败 -> 以 4 个 0 + edx 调用回调
```

### 1.2 风险判定

| # | 问题 | 结论 | 证据 |
|---|---|---|---|
| R1 | 失败时写入的**记录内容**是什么？ | **4 个 0 参数 + edx**。edx = `[0x7ACE410]+0xC` 经 `or 0xD692ADA0` / `xor` 混合后的值（`0x6292EA`..`0x6292F9`） | `0x629343`..`0x62934C` |
| R2 | 该路径**是否写预约槽**？ | **是** —— `0x637930` → `0x637720` → `memcpy(dst=mk+0x7470, …)` | `0x637746` + `0x637752` |
| R3 | 成功路径与失败路径**是否共享同一个槽**？ | **是** —— 两者都经 `0x637720`/`0x637590` 写入同一个 `mk+0x7470` 数组，索引均为 0（`0x63776A mov [esi+0xE360], 0`） | 逐指令 |
| R4 | 失败记录**是否包含 A/B 的全 0 值**？ | **取决于 edx 的长度**。`0x637720` 按 `[esi+0x7230]`（槽计数）与入参 memcpy；若入参缓冲区未填满，**槽内容可能含 0**。**本次未逐字节判定失败记录的 A/B 具体取值** | **UNKNOWN** |

**⇒ 结论（CONFIRMED + 一处 UNKNOWN）：**
**失败路径确实会写入同一个预约槽（R2/R3 = CONFIRMED），
因此"把失败路径的全零记录误认为正常会话数据"是一个真实存在的风险。
其 A/B 的具体取值本次未判定（R4 = UNKNOWN）。**

**⇒ 对实现的影响**：即使 accepted 回传了正确的 A/B，
**必须同时确认客户端走的是发送成功分支**（`0x629339 jne 0x629351` 之后），
否则失败/超时路径会用另一份记录覆盖同一槽。
