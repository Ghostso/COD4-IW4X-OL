# 07 — 客户端交叉引用影响 / CLIENT XREF IMPACT

> 任务要求：解码后内容是否改善了函数边界或交叉引用的可信度；是否新增通往客户端 opcode 分派或 Configstring body 的直接证据。
> 等级：`VERIFIED` / `STATIC-INFERENCE` / `NO-NEW-EVIDENCE` / `BLOCKED`

---

## 1. 本轮最重要的方法学修正：Capstone 线性扫描会**提前停止**

### 1.1 问题

单次 `md.disasm(code, base)` 在遇到**第一个无法解码的字节**时**立即结束**。在 `.text` 中这发生得很早，导致：

| 方式 | 最后解码 RVA | 覆盖率 |
|---|---|---|
| 单次 `disasm()`（旧） | `0xD95806E`（在 `.tvm0` 内！说明 `.text` 很早就停） | ≈0.01% |
| **带重同步扫描**（本轮） | `0x7AD9FD`（= `.text` 节尾） | 覆盖到节尾 |

**带重同步的扫描**共解码 `.text` **2,892,767** 条指令。

### 1.2 修正前后对照（同一问题，两种答案）

| 问题 | 旧（单次 disasm） | **新（重同步）** |
|---|---|---|
| `.text` `call` 进入消息解析簇（0xA0000–0xAFFFF） | **0** | **685**（224 个不同目标） |
| `.text` `call`/`jmp` 进入 `.tvm0` | 51 | **3,755**（784 个不同目标） |
| `.text` `call` 到 `0xA2E50` | 0 | **0** |
| `.text` `call` 到 `0xA2D90` | 0 | **0** |

**结论：** 旧的"0 命中"是**工具假象**，必须废弃。这条修正由 `F-06` 记录。

---

## 2. 消息解析簇（RVA 0xA0000–0xAFFFF）的真实可达性

**修正后结果：`685` 次指令级 `call` 进入该簇，224 个不同目标。**

Top 目标：

| RVA | 次数 |
|---|---|
| `0xAFAB0` | 131 |
| `0xA50F0` | 24 |
| `0xACB50` | 22 |
| `0xAD240` | 20 |
| `0xAF090` | 12 |
| `0xA5130` | 10 |
| `0xA8B40` | 10 |
| `0xA86E0` | 10 |
| `0xAF3D0` | 9 |
| `0xA5060` | 9 |

**含义（重要）：** 该簇是**活跃代码**，且**有真实上游调用者**。

**但** `0xA2E50` 与 `0xA2D90` **仍是 0 次** —— 即使扫描已覆盖整节、且解析簇整体可达。

## 3. `0xA2E50` 的状况（关键目标的最终判定）

| 搜索面 | 完备性 | 结果 |
|---|---|---|
| `.text` 指令级 `call`（重同步，覆盖到节尾） | **高** | **0** |
| `.text` 指令级 `jmp` | 高 | **0** |
| `.tvm0` 指令级 `call` | 低（入口对齐 0%） | **0** |
| `.rdata` 对齐指针（30,895 个 →`.text` 中） | 高 | **0** |
| `.data` 已初始化区（2,375 个 →`.text`） | 高 | **0** |
| `.data` BSS 尾 | 按定义**不可能**含已初始化指针 | 不适用 |
| `.tvm0` 解包内容中的 u32 == VA/RVA | — | **0** |
| 末节 `.tp3` 解包（TenProtect 载荷） | 已解出 | **0**（非游戏逻辑） |

**需要特别说明的对照：** 同一簇内的其他函数（如 `0xAFAB0`）**有** 131 个调用者；而 `0xA2E50` **一个都没有**。这说明"该簇可达"成立，但"`0xA2E50` 可达"**不成立**。

**裁定：`0xA2E50` 在当前已恢复的静态镜像中不可达（高完备搜索面为 0）。**
**但仍不是 `REFUTED`（客户端绝对没有该路径）**，因为：
- `.tvm0` 无法线性解码（入口对齐 0%），其中可能含间接分派；
- 运行时可能通过 VEH/回调/自修改代码进入。

## 4. `.tvm0` 与客户端分派的关系

| 观察 | 值 |
|---|---|
| `.text` → `.tvm0` 指令级 `call` | **3,755**（784 个不同目标） |
| 最热入口 | `0xD9AB8AC`（601 次） |
| 入口代码形态 | `push imm32` + 压寄存器 + `jmp 远`（栈混淆） |
| 从节首线性解码能否命中入口 | **否（对齐率 0%）** |
| 解包内容内是否引用 `0xA2E50`/VA | **0 / 0** |

**裁定：**
- `.tvm0` 是**被大量调用的代码区**（不是死数据）；
- 但其核心是**混淆/VM 风格**，**无法**从中线性导出到 `0xA2E50` 的分派；
- 本轮**未**在其中找到通往 opcode 分派的证据。

## 5. 是否新增通往 **opcode 分派** 的直接证据？

**答：没有。**

- 没有 `0xA2E50` 的调用者；
- 没有 `0x02` 的比较/跳转表通向它；
- `.tvm0` 内无对它的引用。

**但本轮显著**改善**了相关判断的可信度**：现在可以**确证**"`0xA2E50` 在 `.text` 全节指令级不可达"，而不再受工具提前停止的影响。

## 6. 是否新增通往 **Configstring body** 的直接证据？

**答：没有。**

- Configstring body（`_CODOL2697_WriteConfigstrings` 侧）是**服务端**已知问题（RVA 0xA0807..0xA0997）。
- 本轮焦点是**客户端镜像**，未触及该写入循环的位编码。
- 解包的 `.text` 与恢复镜像**逐字节相同**，故**不产生**新的客户端侧 Configstring 消费证据。

## 7. 函数边界与交叉引用可信度的改善

| 项 | 改善前 | 改善后 |
|---|---|---|
| `.text` 指令覆盖率 | ≈0.01%（假象） | **覆盖到节尾**（2,892,767 条） |
| `.text`→解析簇调用 | 假 0 | **685（可信）** |
| `.text`→`.tvm0` 调用 | 假 51（字节扫描 3,871） | **3,755（指令级）** |
| `0xA2E50` 可达性 | "未知/工具限制" | **"高完备面为 0，且解析簇整体可达"** |
| `.tvm0` 性质 | "虚拟化容器"（未定） | **aPLib 压缩的原生混淆代码**（格式 VERIFIED / 语义 PARTIAL） |
| `.data` 缺口 | "99.86% 缺失" | **"208 MB BSS，非缺失"** |

## 8. 末节 `.tp3` 对 xref 的影响

- 该节解出的是 **TenProtect/TesSafe 反作弊载荷**（12 个 PE）。
- **不包含**游戏消息解析器。
- 因此：把"该节未恢复"当作"解释不了客户端分派"的理由，**不再成立**。

## 9. 结论

| 问题 | 回答 |
|---|---|
| 解码是否**改善**函数边界/交叉引用可信度？ | **是**：`.text` 现在全节可扫，存在大量此前被漏掉的调用（685 / 3,755） |
| 是否新增通向 **opcode 分派**的直接证据？ | **否** |
| 是否新增通向 **Configstring body**的直接证据？ | **否** |
| `0xA2E50` 是否可达？ | **在已恢复镜像的高完备搜索面内：不可达**（但仍非 `REFUTED`） |
| 未闭合项 | `.tvm0` 的**混淆控制流**（入口对齐 0%，无法线性解码） |
