# 07 — E-13 总裁定 / VERDICT

> 只读静态分析。样本哈希与冻结基线一致（见 `01` §0），原始样本未修改。

## 1. 七个最终决策问题

### Q1. 9 个收包函数中，哪些可以通过已证调用边进入 `0x3524F0`？

**没有任何一个。**

在 9 个收包函数各自 3 层静态调用图（并集 179 个函数）内：
- 到 `0x3524F0` 的已证调用边：**0**
- 对环形缓冲全局（`0x743DE9C`/`+0x30AF2C`/`+0x30AF30`/`+0x8048`）的引用：**0**

（限定范围表述，非全局排除。）

### Q2. 哪些只进入临时缓冲、队列或其他写入点？

| 函数 | 去向 |
|---|---|
| `0x602430`、`0x775A50`、`0x775AB0` | **纯透传**（无内部复制，无下游） |
| `0x6B4DE0` | 错误码分派（`jmp [ecx*4+0xAB4F50]`） |
| `0x784F60` | `0x784B40` → `0x3622AC`（错误/清理） |
| `0x1B0430` | 通用 socket 事件处理（30+ IAT 间接） |
| `0x6029A0` | `0x602760` → `0x60E5B0` **协议状态机**（跳转表 + 函数指针） |
| `0x605220` | `0x606650`/`0x5FB510` → `0x6104D0` → `0x672460` |
| `0x78772D` | 多状态处理，含 `.tvm0` 调用 |

### Q3. `0x3524F0` 是否可以认定为实时网络数据的应用层缓冲？

**不能（REFUTED）。**

- `0x3524F0` 的**唯一**调用者是 `0x351D00`，其**唯一**调用者是 `0x34FD80`，其**唯一**调用者是 demo 分派器 `0x350170`。
- `0x351D00` 的指令序列是**序列化本地状态 → 写入环形缓冲 → 提交发送**（`0x753A40`/`0x756760`）。
- 因此 `0x3524F0` 是**发送/序列化暂存**，方向为**出站**。

**缺少什么证据才能改判为接收缓冲：** 需要一条从任一收包函数到 `0x3524F0` 的已证数据流边，且该边的 `src` 参数来自 `recv`/`recvfrom` 的输出缓冲。本轮未发现。

### Q4. `[+0x89244]` 的 3 处写入是否能建立实时消息处理入口？

**不能（REFUTED）。**

3 处写入的值为 `0x752570`（环形缓冲读侧）和 `0x74F090`（demo 读取器）——**均非消息解析器**。写入者 `0x3512A0` 与 `0x356580` 的上游均为 demo 控制流（`0x34E7C0` = `cl_demo_jumptostart`）。

### Q5. 是否发现独立于该环形缓冲的实时数据路径？

**未闭合（BLOCKED）。** 有 4 个 INFERRED 候选：

| 候选 | 证据 | 状态 |
|---|---|---|
| `0x6029A0` → `0x60E5B0` 状态机 | `jmp [edx*4+0xA026D0]` + 20+ 函数指针 | INFERRED（BLK-13-1） |
| `0x605220` → `0x606650` → `0x672460` | `call ebx` | INFERRED |
| `0x1B0430` socket 事件处理 | 30+ IAT 间接 | INFERRED |
| `0x78772D` → `.tvm0` | `call 0xDBEF28A` | BLOCKED（BLK-13-2） |

### Q6. 当前能否将实时收包连接到某个 Gamestate `0x03` 消费者？

**不能（BLOCKED）。** 实时收包与 demo 分派链在静态调用图上不相交；`0x03` 消费者仅在 demo 链中被定位（`0x34FD80(1)`）。

### Q7. 下一步最小调查范围？

| 优先级 | 范围 | 目标 |
|---|---|---|
| 1 | `0x60E5B0` 入口前 100 字节 + 调用者 `0x602760` | 解出 `[ebp-0xd2c]` 函数指针来源（BLK-13-1） |
| 2 | `.rdata 0x898588`/`0x898590` 虚表 + 其构造者 | 解出 `0x775A50`/`0x775AB0` 的实例化路径（BLK-13-3） |
| 3 | `0x605220` 下游 `0x6104D0`/`0x672460` | 确认是否为独立协议处理 |
| 4 | 不扩大 `.tvm0`（BLK-13-2，停止条件） | — |

## 4. 对 E-12 的修订

| E-12 表述 | E-13 修订 |
|---|---|
| “收包函数 → 环形缓冲写侧的调用边 BLOCKED” | **升级为 REFUTED（限定范围）**：3 层闭包内无任何边，且环形缓冲全局在闭包内 0 引用 |
| “`0x3524F0` 是环形缓冲写侧” | 补充：它是**发送序列化暂存**，不是接收缓冲 |
| “环形缓冲 → Gamestate 业务解析 BLOCKED” | 补充：读侧 `0x352570` 无队列语义；读取器指针不指向解析器 |

## 5. 对实时 Gamestate 消费者定位的影响

- 排除了一条候选假设：**实时收包不经过该环形缓冲**（限定范围）。
- 剩余候选集中在 `0x6029A0`/`0x605220`/`0x1B0430`/`0x78772D` 四条间接分派路径。
- **未**定位实时 `0x03` 消费者。
