# 06 负证据与边界

## 1. 已执行的搜索

| # | 搜索 | 范围 | 方法 | 结果 | 边界 |
|---|---|---|---|---|---|
| N1 | `BDDATA` / `CLIENTCHAL` 立即数 xref | 2697 恢复镜像 `.text` 全节 | 32-bit LE 立即数扫描 | 各 **1** 处 | 覆盖 `.text` 全节；**未覆盖 `.tvm0`（VM 段）** |
| N2 | `HMAC mismatch` / `Bad recv counter` / `Bad frame/payload size` | 同上 | 同上 | 1 / 1 / **0** | `Bad frame/payload size`（`0xC5B120`）无立即数引用，可能由表偏移/间接访问 |
| N3 | `expandKey` 调用者枚举 | `.text` 全节 rel32 调用图 | E8 解析 | 恰好 **2**（`0xAAB8CF`、`0xAAB911`） | 不含 `call [reg]`/`FF 15` 间接调用 |
| N4 | SHA-1 初值常量 | `.text` 全节 | 立即数扫描 | 4 组（`0xA2DD98`、`0xA53438`、`0xAC920B`、`0xACF6EB`） | 优化可能内联；算法身份另由 `sha1` 名表证实 |

## 2. 盲区（不得据此断言存在/不存在）

| 盲区 | 说明 |
|---|---|
| `.tvm0` VM 段 | `.tvm0`（VA `0xD955000`，VS `0x2B9000`）为可执行 VM 保护段；本轮立即数与调用图扫描覆盖 `.text`，**未解析 `.tvm0` 内的间接分派** |
| 间接调用 | 扫描不含 `call [reg]`、`call [mem]`、vtable 分派；`0xAAC0C0` 分派器本身即通过间接调用进入部分子处理函数 |
| 加壳打包客户端 | `.tp3` 为虚拟/压缩段，无法在打包镜像中就地核对旧 VA |
| 运行时密钥装载 | codec 输出（`obj+0x5F9/+0x60D`）-> provider（`+0x5F0/+0x5F4`）的最终数据流尚需继续跟踪 |
| 线上真实服务端 | 不在冻结样本内 |
| 1.1.1.13 / 3.3.3.3 客户端 | 未在本轮核对，不得用其余构建地址推断 2697 |

## 3. 措辞边界（必须遵守）

- 可以：“2697 客户端的 `CLIENTCHAL`/`BDDATA` 派生链位于 `0xAAB310`（VA）/ `0x6AB310`（RVA）。”
- 可以：“2697 客户端在派生值之上存在参考对端未实现的 codec 层。”
- 可以：“参考对端的算法族、标签、长度、切分、帧布局、MAC 覆盖与 2697 客户端一致。”
- 不可：“2697 客户端与参考对端不兼容。”（缺口尚未定为冲突）
- 不可：“`0x9CE310` 不成立 => 另一构建 => 协议不同。”（地址口径错位，不构成协议证据）
- 不可：“2697 无 AES。”（S-box 未连续命中不构成否定证据）

## 4. 与 E-27 负证据的关系

E-27 的 N1–N7（2697 服务端生态不含 Demonware）为**服务端侧**结论，本轮**不改动**，仍成立。
本轮否定项均在**客户端侧**，且已逐条标注扫描范围与盲区。
