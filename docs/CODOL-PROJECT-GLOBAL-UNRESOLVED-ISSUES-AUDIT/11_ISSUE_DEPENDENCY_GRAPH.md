# 11 — 问题依赖图与关键路径

> 由 `MASTER_ISSUES.json` 的 `depends_on` 字段生成。箭头 `→` 表示"左边不解决，右边无法验收"。
> 依赖只表达**验证上的先后**，不表达"必须等"——很多问题可以并行写代码，
> 但**无法并行验收**。

---

## 1. 根节点：三条独立的断链

```
                    ┌──────────────────────────────────────┐
   【A】房间线      │ ISSUE-0009 准备按钮无上行             │
                    │ ISSUE-0010 下行格式未定               │
                    │ ISSUE-0011 信封路由未定               │
                    │ ISSUE-0012 dwRoomMatch::Init 未调用   │  ← 上游
                    │ ISSUE-0013 自动开局状态机停在状态 1   │
                    └──────────────────────────────────────┘
                                     │
                                     ▼
                    ┌──────────────────────────────────────┐
   【B】连接线      │ ISSUE-0020 战斗服零收包               │  ★ 最高优先级
                    │ ISSUE-0021 mmstart 无 map            │
                    │ ISSUE-0074 102/7 回全 0               │
                    │ ISSUE-0054 mmbook (A,B) 未定位        │
                    └──────────────────────────────────────┘
                                     │
                                     ▼
                    ┌──────────────────────────────────────┐
   【C】对局线      │ ISSUE-0025 位置推不动                 │
                    │ ISSUE-0024 实体不可见                 │
                    │ ISSUE-0029 写死地面                   │
                    │ ISSUE-0030 命中非射线                 │
                    │ ISSUE-0032 模式/投射物未接线          │
                    └──────────────────────────────────────┘
```

三条线**彼此独立**：A 不通也可以让 B 通（10-26 的 8 轮就是从 PvE 入口绕开 A 直接进 B）。

## 4. 关键路径（最短到"可操控游戏画面"）

```
ISSUE-0021 (mmstart 带 map，S)
      ↓
ISSUE-0074 (102/7 单变量回归，S)
      ↓
ISSUE-0020 (战斗服收到第一个包，M)     ★ 唯一必须串行的关键节点
      ↓
ISSUE-0025 (位置/实体是否被客户端采纳，L)
      ↓
ISSUE-0024 (实体可见，L)
      ↓
ISSUE-0032 (模式/投射物接线，L)
      ↓
完整对局（INMATCH 六门槛）
```

**关键路径的最窄处是 ISSUE-0020**：在它之前，后面所有关于"客户端行为"的结论都是空的。
