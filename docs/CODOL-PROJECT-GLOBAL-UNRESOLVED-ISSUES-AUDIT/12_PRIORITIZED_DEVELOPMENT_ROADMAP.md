# 12 — 按优先级排列的开发路线

> 三条路线对应三种目标。同一 Issue 可能出现在多条路线里，但**只有一处是"必须"**。
> 不给出工期估计——依据不足以支撑。

---

## 路线 A：最短进入可操控画面

**目标**：同一个 PID 内出现"客户端连上战斗服 → 收到 gamestate → 进入地图 → 能走动"。

**前置条件**（全部是环境事实，不是 Issue）：
- 游戏本体可启动（`enable_iips=1`，ISSUE-0007 已解决）
- 提权 agent 在线（ISSUE-0008）
- 冻结 kit 可复制（`run_frozen_chain_once.py` 的令牌未被消费）

| 顺序 | Issue | 动作 | 可并行 | 验收 |
|---|---|---|---|---|
| A1 | **ISSUE-0021** | 让 `mmstart` 携带 `map <本地图>; g_gametype coop`（复制 10-26 成功形态） | G2/G5 可并行 | `lobby_srv.log` 里 mmstart 解析出 map，不再是 `?` |
| A2 | **ISSUE-0074** | 102/7 恢复"不处理"，其余保持；单变量回归 | 同上 | 与 A1 一起跑 |
| A3 | **ISSUE-0020** | 跑一轮，看战斗服是否收到 NAT/DTLS/getchallenge | 同上 | `_battle_out.txt` 出现 `TX_NAT_REPLY` 或 `KEY_EXCHANGE_OK` |
| A4 | 新增 | 一旦连上，**立刻抓包**（记录 `TX_GAMESTATE`、`RX_GAMESTATE_PROGRESS`、`TX_SNAPSHOT`、`RX_CLIENT_GAME_HEADER`） | — | 有完整一轮的日志与字节 |
| A5 | **ISSUE-0078** | 用 A4 的抓包补上"官方握手"的字节证据 | — | 握手可以逐字节复用 |
| A6 | **ISSUE-0025** | 在能连上的配置下，重做"位置是否被采纳"实验（此时才有意义） | G3 并行 | 客户端位置随快照变化 |
| A7 | **ISSUE-0024** | 实体可见（需要模型索引 + 正确实体号） | — | 出现一个原来不存在的可见实体 |
| A8 | **ISSUE-0032** | 把模式状态机/投射物接进 tick | 纯服务端，可全程并行 | 出现 spawn→kill→score 日志链 |

**主要风险**：
- A3 可能仍然失败（10-27 之后同样形态也全灭）⇒ 需要回到 `BATTLE_CONNECT_DIVERGENCE §五` 的三步二分
- A4 抓包需要工具在正确时刻采集；若 ACE 影响不到网络层则可行（网络字节不受 ACE 限制）

**路线 A 的最小根阻塞集合**：`{0020, 0021, 0074}`。

> ★ 注意：A6 之后的所有事都建立在一个尚未证明的前提上——
> "连上之后客户端会听我们的"。10-26 的 8 轮只证明连上了，没证明进图了。

## 路线 B：完整战斗服务器

**目标**：在 A 完成后，做出多人、有玩法、能结算的对局。

**前置条件**：路线 A 全部完成 + ISSUE-0023（TX 缓冲/分片）已完成。

| 顺序 | Issue | 动作 |
|---|---|---|
| B1 | ISSUE-0023 | 扩 TX 缓冲到 ≥16 KB + 实现下行分片 |
| B2 | ISSUE-0033 | per-client 状态移进 assoc |
| B3 | ISSUE-0034 / 0040 | per-peer stats；统一会话重置 |
| B4 | ISSUE-0029 → 0030 → 0031 | 真实 clipmap → 真实 trace → 可重复靶子 |
| B5 | ISSUE-0067 | 命中盒几何 / 护甲 / 穿透 / 后坐力 |
| B6 | ISSUE-0032 | 模式/投射物/回合/结算接线 |
| B7 | ISSUE-0064 | gamestate 尾部与 configstring 完整化 |
| B8 | ISSUE-0061 / 0063 | netField 语义补全（逐字段 A/B） |
| B9 | ISSUE-0055 / 0060 | 开火位与按键位表 |
| B10 | ISSUE-0022 | 多地图支持 |

**验收标准**：`INMATCH_COMPLETENESS_GAP_MATRIX` 的六条硬门槛全部满足，
且每条都有同一 PID 的实机证据。

**主要风险**：
- 多人同步可能受客户端限制（当前连"客户端是否采纳服务端位置"都未证）
- 武器/配件的原生还原度可能需要远超预期的逆向量

## 三条路线的关系

```
C（工程化）──── 可全程并行，且提升 A/B 的可信度
A（可操控）──── 关键路径，唯一必须串行的是 ISSUE-0020
B（完整对局）── 全部依赖 A
```

**建议执行顺序**：`C1–C5 立刻做` → `A1–A5` → `C6–C11 随做随补` → `A6–A8` → `B1–B10`。
