# 10 — 跨报告矛盾与"假闭合"

> 本文件回答一个问题：**哪些"已解决"其实是假的？**
> 每条给出「当时怎么说 / 后来怎么样 / 现在的判定」。

---

## 一、九个最典型的假闭合

### 1. `codol_battle_service_bind_world` "已接线"

- **当时**：`INMATCH_COMPLETENESS_GAP_MATRIX_20261023.md` §"静态闭合轮"写
  "battle_service 已通过 `bind_world/apply_usercmd` 把真实输入推进 world.players/entities"，
  并把该轮标为 22/22 全绿。
- **后来**：`HANDOFF_20261025_BINARY_BISECT.md §16` 查明该函数**从未被调用**，
  `svc->world` 恒 NULL，`ensure_damage_target()` / `apply_test_hit()` 第一句就 return。
- **现在**：已接线（2026-10-25，一行），离线证据 `probe_world_damage` 有
  damage=33 / 位移 89.1 / trace fraction=0.292。
- **教训**：**"代码写好了" ≠ "代码被调用"**。grep 那个 setter 的调用点。

### 2. `Phase 3 Snapshot codec DONE / 141 B byte-exact`

- **当时**：`docs/PHASE3_SNAPSHOT_CODEC_DONE_20261023.md` §3 标 DONE。
- **后来**：该编码经 `CODEC_SPEC §8` 改成"按表宽 7 位"，导致客户端卡"等待玩家数据"；
  改回 4 位后进图。
- **现在**：`INMATCH_COMPLETENESS_GAP_MATRIX` 已降为 PARTIAL。
- **教训**：**"与参照逐字节一致" ≠ "客户端接受"**。141 B 在本客户端上是已知死路。

### 3. 准备按钮 "AS_* 未实现"

- **当时**：`docs/READY_BUTTON_NO_IMPL_20261028.md` 结论
  "`AS_SetReadyState` 这个 Scaleform 回调在当前构建里没有实现"。
- **后来**：`READY_BUTTON_ROOT_CAUSE_CLOSED_20261028.md §一` 自己推翻：
  "这个判断不完整"——房间 UI 不走 `UiCpp*View`，走 `dwRoomMatch` 自己的事件系统；
  另有 `dwRoomMatch::Init` 未调用（MyEventHandler 零实例）这条更上游的解释。
- **现在**：两条解释并存，**都未被证实在本 build 成立**（ISSUE-0009）。
- **教训**：**"名字存在但无 COL" ≠ "功能未实现"**。可能是注册用哈希/ID 而非名字。

### 4. "Gamestate / configstring DONE"

- **当时**：`PHASE2_GAMESTATE_CONFIGSTRING_DONE_20261023.md` 标 DONE（765 槽样本对拍）。
- **缺口**：该文档 §5 自述"客户端接受未证"，§6 说"尾部 44 字节未解析"。
- **现在**：仍只到字节往返一致（ISSUE-0064 / ISSUE-0044）。
- **教训**：DONE 的判据是"编解码自洽"，不是"客户端消费"。

### 5. "战斗传输握手 DONE"

- **当时**：`INMATCH_COMPLETENESS_GAP_MATRIX_20261023.md` 首表第一行。
- **后来**：2026-10-28 起所有 BOT 房间轮次战斗服零收包；`STAGE1_CRYPTO_DONE.md §五`
  自述端到端只对 `e2e_client.py` 验证过。
- **现在**：官方客户端只在 2026-10-26 的 8 轮里连上过，且**没有落盘抓包**（ISSUE-0078）。
- **教训**：**模拟客户端通过 ≠ 官方客户端通过**。

### 6. "实体段客户端接受"

- **当时**：`HANDOFF_20261025_BINARY_BISECT.md §17.2`：ack 速率 83.02→83.05/s，比值 1.00，
  结论"格式风险解除"。
- **缺口**：同文档 §17.5 自己写"**没有**证明客户端真的建了实体或渲染了"，
  且 §17.5 第 1 条提出"畸形对照"至今未做。
- **现在**：`ack 不变` 可能意味着"被接受"，也可能意味着"整段被忽略"（ISSUE-0024）。
- **教训**：**"不判废" ≠ "被解析"**。

### 7. "FAT 分片已实现"

- **当时**：`HANDOFF_20261024_FAT_REASSEMBLY_PLAN.md` 离线 7 项全绿。
- **后来**：`HANDOFF_20261025_BINARY_BISECT.md §8.2`：修好索引编码后客户端消息
  稳定在 174~371 字节，永远到不了 1154 阈值 ⇒ **实机从未触发**。
- **现在**：保留代码，标注"离线已验证、实机未验"（ISSUE-0065）。

### 8. "出生点可以使用 (48,-572,-116)"

- **当时**：`battle_service.c` 的注释（含 2026-10-25 版）。
- **后来**：
  - 用户实测"还是在房顶"
  - `CLIPMAP_EXTRACTION_20261026.md`：该点落在所有碰撞体之外
  - `§13`：三个坐标 × 两种频率全部无效
- **现在**：服务端推不动客户端（ISSUE-0025）；该值只作为初始值存在。

### 9. "运行时可读（早期句柄窗口）"

- **当时**：`docs/GATE_B_INIT_PATH_20261027.md`：t+15.23s 拿到句柄、读 1630 MB / 0 失败块。
- **后来**：`docs/ACE_BLOCKS_EVERYTHING_20261028.md`：t+0.01s 就 err=5，ALL_ACCESS 也一样。
- **现在**：**矛盾未解**（ISSUE-0045）。两次都自称实测。
- **教训**：同一类结论在不同运行里可以不同。**必须记录每次的启动路径与 ACE 版本。**

## 五、如何避免再次假闭合（本审计的建议规则）

1. **区分四种"完成"**：`impl` / `offline` / `simclient` / `official`。
   任何状态表必须写清是哪一个。
2. **区分四种"客户端行为"**：发出 / 收到 / 解析 / 状态改变。
   只有第 4 种能称为"客户端兼容"。
3. **地址一律 `(module, rva)`**：本语料至少有 4 起 VA/RVA 混用造成的假结论。
4. **阴性结果必须记录作废条件**：例如"FAT 未触发"是因为阻断点消失，
   而不是因为实现不存在。
5. **每次运行记录启动路径**：否则"实测"不可复核（ISSUE-0045 的核心）。
6. **参照不等于可用**：本项目的参照在"对齐真机"上改过多轮，
   但没有一轮是实机验证过进图的。
