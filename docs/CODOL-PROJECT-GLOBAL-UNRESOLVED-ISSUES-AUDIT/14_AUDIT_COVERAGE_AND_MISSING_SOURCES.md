## 四、本次审计的方法与限制

### 4.1 方法
1. 三层扫描：目录 → 报告（摘要+verdict）→ 源码（逐行）。
2. 并行三个子扫描器分别处理 E 系列 / 启动大厅地图 / 战斗快照语料，各自输出到 `_work/`。
3. 本审计独立复算了**所有能复算的数字**：基线哈希、构建产物哈希、ctest 结果、文件尺寸。
4. 所有问题条目要求至少一条 `evidence` 路径。

### 4.2 限制
- **没有启动任何客户端**（遵守 AGENTS.md 与任务约束）。
- **没有修改任何源码或 kit**。
- 未能逐篇读完全部 4,963 个 `.md`；按"与当前主线相关"分层抽取。
- 三个子扫描器各自给出的 issue 条目数（77 / 98 / 86 = 261 条原始条目）与本台账的 92 条**不是一一对应**：
  本台账做了跨语料去重（见 `02_ALL_HISTORICAL_ISSUES.md §六`），
  并剔除了"只是描述同一缺陷的另一种叫法"。子扫描器的原始清单保留在 `_work/` 供追溯。

### 4.2.1 去重口径（261 → 92）

| 处理 | 数量 | 说明 |
|---|---|---|
| 子扫描器原始条目 | 261 | 三份 `_work/hist_*.md` |
| 合并为一条（同一缺陷的多种叫法） | −约 120 | 例如"零收包"在三个语料里各有 3–4 条 |
| 归入 OBSOLETE / WRONG（已作废但有历史价值） | 保留 5 条为 OBSOLETE | 其余并入 `02_ALL_HISTORICAL_ISSUES.md` 的 O/W 表 |
| 归入"外部包/ol-mod/C# 线"且不再投入 | 保留 6 条（P3/NONE） | 不删除，但标注不处理 |
| **最终主台账条目** | **92** | 含 6 条 NONE（已作废/已解决对照） |

> 去重的判据是**根因相同**，不是"名字相似"。凡根因不同、只是现象相同的，仍分别登记
> （例如 ISSUE-0020 零收包 与 ISSUE-0021 mmstart 无 map 是两个不同的根因，不合并）。
