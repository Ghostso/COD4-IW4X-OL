# F6 — 下一步最小研究动作

> 客户端样本 SHA-256：`353754047dbbfe3afbf6c7d97de3faca785b3d5d5e34a9053c820ee78814d6e1`  
> 静态恢复镜像 SHA-256：`24b4ef2502d3661df178f557192534098c714353cf8c2a00a2ffb26af2bb97e4`  
> ImageBase：`0x400000`；本文地址基准：`0xA2E50`/`0xA2D90` 为映像 RVA，函数内部 E8 目标为 VA（VA - ImageBase = RVA）。


## 1. 最优先动作

**定位 `0xA2E50` 的调用来源，而不是继续重复全文件扫描。**

具体做法：

1. 把恢复镜像按节还原为可在 IDA/Ghidra 中加载的 PE（当前已有静态恢复镜像，可直接载入）。
2. 在反汇编器中查看 `0xA2E50` 的交叉引用，重点看：
   - 是否有函数在调用它前读取 opcode 从消息中取出的字节；
   - 是否有 vtable/对象构造函数写入其地址；
   - 是否有通过 `[reg+disp]` 间接调用的包装器。
3. 如果反汇编器同样没有 xref，转向 `.tvm0` 保护层：分析这两条 `.tvm0` 命中所处的解码单元，确认它们是否是运行时才生成的跳板。
4. 对 `0xA2D90` 使用同一流程；两者若不是同一家族，不要强行合并结论。

## 2. 次优先动作

- 在 `.text` 的 18 个读取核心调用者中，优先分析 `0x1AC670`、`0x1AD3A0`、`0x1B1370`、`0x34FD80`，它们位于低位地址且可能是 Msg 方法族的真正入口。
- 用“读取核心调用者 + 0x1..6 常量”联合筛选，而不是单独扫描 cmp 常量。

## 3. 需要的外部条件

- 若反汇编器无可解析 xref，需要一份**运行时解包后的客户端内存 dump**（同 SHA-256 客户端、同版本），或 TenProtect 运行阶段的干净镜像，才能确认恢复镜像与运行时映射等价。
- 在此之前，所有负面搜索结果只能表述为“在当前恢复镜像中未找到”。

## 4. 停止条件

- 不启动游戏/服务端，不注入，不补丁，不编译。
- 不在没有调用链的情况下把字段形状匹配升级为 opcode 一致。
- 所有互通结论保持 `NOT-OBSERVED`，直到有真实运行时观测。
