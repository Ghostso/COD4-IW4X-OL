# F2 — 客户端 opcode 分派来源追踪

> 客户端样本 SHA-256：`353754047dbbfe3afbf6c7d97de3faca785b3d5d5e34a9053c820ee78814d6e1`  
> 静态恢复镜像 SHA-256：`24b4ef2502d3661df178f557192534098c714353cf8c2a00a2ffb26af2bb97e4`  
> ImageBase：`0x400000`；本文地址基准：`0xA2E50`/`0xA2D90` 为映像 RVA，函数内部 E8 目标为 VA（VA - ImageBase = RVA）。

> 目标：确认是否存在 `opcode 0x02 → 分派 → 0xA2E50`。

## 1. 已搜索的内容

1. 在 `.text` 内扫描所有 `cmp` 与立即数 1..6，过滤出可能的 opcode 比较。
2. 扫描所有 **间接跳转/跳转表**：`jmp dword ptr [reg*4 + ...]` 以及相关表基址加载。
3. 对读取核心 `0x5AC1D0`（VA）/ RVA `0x1AC1D0` 的全部调用者做函数分组。
4. 检查读取核心调用者中是否有函数同时调用 `0x4A2E50`。
5. 检查 `0xA2E50` 的错误字符串引用是否来自外部分派点。

## 2. 结果

### 2.1 opcode 常量比较

在 `.text` 中没有找到“读取消息字节 → `cmp` 1..6 → 跳转表/分支 → 0xA2E50”形式的可复现控制流。该搜索只找到一般数据/数值比较，没有通向 0xA2E50 的分支。

### 2.2 跳转表

发现多张真实跳转表，例如：

| 指令 RVA | 分派表 VA | 分派目标范围 | 与 0xA2E50 |
|---|---|---|---|
| `0x26C8` | `0x40271C` | `0x4026CF–0x402712` | 无 |
| `0x5FEE` | `0x406D00` | `0x405FF5–0x406866` | 无 |
| `0xE455` | `0x40E6A8` | `0x40E45C–0x40E5FE` | 无 |
| `0xE752` | `0x40E9FC` | `0x40E759–0x40E93D` | 无 |
| `0xEAA5` | `0x40EC68` | `0x40EAAC–0x40EC38` | 无 |

这些表的分派目标都在低位小节内，与 `0xA2E50` 无关。**当前镜像未发现任何跳转表项指向 `0xA2E50`。**

### 2.3 读取核心调用者

`0x5AC1D0`（VA）在 `.text` 中有多组调用者，分组后包括：
`0x49D80`、`0x6D340`、`0x6E060`、`0xA1BF0`、`0xA2660`、`0xA2D90`、`0xA2E50`、`0xAA430`、`0xAAD80`、`0xB4EC0`、`0x1AC670`、`0x1AC800`、`0x1AC850`、`0x1AC8A0`、`0x1ACAA0`、`0x1AD3A0`、`0x1B1370`、`0x34FD80`。

其中：

- `0xA2660`：先读 2 字节计数，循环读 0x0D/10 字节并维护 `+0x1DD7` 表，更像表/状态更新解析器。
- `0x6D340`：读取 4 字节索引、检查 `0x7FFC`，再读 1 字节长度并复制；属于另一套内部消息/delta 解析器。
- `0x6E060`：读取 short 并循环读 short/long，属于另一套快照/块解析。
- 这些函数与 `0xA2E50` 位于不同的解析族，均没有调用 `0xA2E50`。

### 2.4 错误字符串交叉引用

`0xA2E50` 内的报错字符串 `0xCB83E0`、`0xCB83E8` 只有它自身的代码引用，没有外部分派点。也就是说：即便客户端定义了该错误信息，也没有找到外部 opcode 分派器通过该字符串间接确认该函数。

## 3. 结论

**F2：没有找到 `opcode 0x02 → 分派 → RVA 0xA2E50` 的完整静态证据链。**

缺失环节：

1. 没有消息字节 opcode 的读取点与 `cmp/shl-jump` 分派；
2. 没有任何跳转表或绝对指针指向 `0xA2E50`；
3. `0xA2E50` 只有一条 `.tvm0` 未对齐字节命中，不能作为调用者；
4. 读取核心调用者均为其他解析族（0x6D340、0x6E060、0xA2660 等），没有一条调用 `0xA2E50`。

现有可辩护的结论是：**`0xA2E50` 的字段形状（long+short+payload）与服务端 E3 的 0x02 负载匹配，但 opcode 绑定为 STATIC-INFERENCE，分派为 BLOCKED，运行时互通为 NOT-OBSERVED。**
