# G4 — 阻塞点与决策

> 样本哈希：客户端 `353754047dbbfe3afbf6c7d97de3faca785b3d5d5e34a9053c820ee78814d6e1`；恢复镜像 `24b4ef2502d3661df178f557192534098c714353cf8c2a00a2ffb26af2bb97e4`。

## 1. 直接回答

### 1. 当前恢复镜像能否支持可靠的负面搜索结论？

**不能支持“原版客户端绝对不存在某调用/分派”的负面结论。**

只能支持：“在当前候选恢复镜像的已解析范围内未找到”。理由：
- 原始最后 `.tp3` 高熵保护区未覆盖；
- `.rdata` 指针被 `.rimp` 改写；
- 存在非线性/不可线性解码的代码岛；
- 没有运行时映射等价性证据。

### 2. 是否找到内部消息类型到 `0xA2E50` 的控制流？

**否。**

未找到：
- opcode 读取点；
- 条件/跳转表分支；
- 到 `0xA2E50` 的直接或间接调用；
- 接收缓冲与 `0xA2E50` 的 Msg 对象同一性证明。

### 3. 当前最主要的证据缺口是什么？

按重要性：
1. 原始最后 `.tp3` 保护区缺失，无法证明分派逻辑不在那里；
2. `.rdata`/vtable/函数指针被 `.rimp` 修复，静态 xref 不再可信地代表运行时；
3. `0xA04860`、`0x9FA070` 等非线性代码岛无法线性追踪；
4. 缺少同版本客户的运行时解包内存 dump；
5. 未建立接收缓冲 → 内部 Msg → opcode → parser 的层级关系。

### 4. 下一步是否仍值得继续静态分析？

**建议暂停“继续扩大线性扫描”这条分支。** 现有盲区是结构性的，继续扫描同一 `.text/.tvm0` 字节范围只会重复已排除的工作。

仍有两个有价值的后续方向：

- **首选：获取运行时解包后的同 SHA-256 客户端内存 dump**，或在受控环境中记录 `0xA2E50` 调用栈/回调注册。该任务目前的安全边界不允许执行。
- **次选且仍属静态：重建 `.rimp` 指针修复格式，恢复未修复的 `.rdata` 指针表并重新解析 vtable/xref。** 这是唯一可能利用现有样本继续闭合的静态动作；如果无法恢复原始指针表，应停止并保留 BLOCKED。

## 2. 已排除的方法

- 全映像 E8/E9 到 `0xA2E50`：0 命中。
- 绝对 VA `0x4A2E50` 指针：0 命中。
- 裸 RVA `0xA2E50` 指针：0 命中。
- 已解析跳转表项到 `0xA2E50`：0 命中。
- libcurl/SOCKS、QoS、QoS vtable 及辅助 DLL 路径：均未形成到 `0xA2E50` 的控制流。
- 原始客户端最后 `.tp3`：未恢复，不能纳入候选镜像的 xref 结论。

## 3. 剩余盲区

- 原始 VA `0xDC11000` 起的最后 `.tp3` 全部内容。
- `.rimp` 修复覆盖的 1536-byte `.rdata` 指针表。
- 非线性代码岛 `0xA04860`、`0x9FA070` 及同类目标。
- 运行时注册的回调/函数指针。
- 接收缓冲层的实际对象创建和回调注册。

## 4. 决策

- 当前 `opcode 0x02 → 分派 → 0xA2E50`：`BLOCKED`。
- 客户端 `0xA2E50` 字段读取格式：`VERIFIED`。
- 两端 opcode 语义绑定：`STATIC-INFERENCE`。
- 运行时互通：`NOT-OBSERVED`。

**结论：暂停该静态分支的扩大扫描；若继续，优先处理 `.rimp`/指针表恢复，否则等待运行时 dump。**
