## 1. 服务端已验证编码

- 新 reliable command：`0x02 | long | short(length) | payload[length]`，写入点 RVA `0x8612E`；`0x02` 由 `_SV_WriteReliableCommand` 正返回分支写入。
- 旧 reliable 回退：`0x01 | long | NUL-terminated string`。
- 旧版兼容分支与 `CODOL2697_PROFILE_WIRE=text`、2697 archives 激活状态有关。
- gamestate/configstrings 新路径使用 `0x03/0x04`，以 `0x06` 结束；legacy 路径使用 `0x02/0x03`，以 `0x05` 结束。
- snapshot 外层结束标记由 `_SV_EndClientSnapshot` 选择：未激活 `0x05`，激活 `0x06`。

等级：VERIFIED（服务端指令）。

## 2. 客户端已确认字段读取

- `0xA2E50`：读取 `long(4) + short(2) + payload`，长 `<=0x3FC`，随后更新全局槽。
- `0xA2D90`：同样以 `long(4)` 为索引，但后续走固定 `0x400` 字节字符串路径；不能仅因相邻就认定同协议职责。
- 两者调用读取核心 `0x5AC1D0`（VA；RVA `0x1AC1D0`）并共享 `[msg+0x14/+0x18/+0x1c]` 游标布局。

等级：VERIFIED（指令）；协议角色 STATIC-INFERENCE。

## 3. 未定位的客户端环节

| 环节 | 状态 | 原因 |
|---|---|---|
| server-message 类型字节读取 | BLOCKED | 未把接收缓冲和内部 Msg 游标连起来 |
| 条件/跳转表分派 | BLOCKED | 未找到到 `0xA2E50` 的可复现分支 |
| `0xA2E50` 直接/间接调用者 | BLOCKED | E8、绝对 VA、裸 RVA、已解析表均未命中 |

## 4. 恢复镜像对负面结论的限制

以下为已证实限制，不是推测：

1. 原始最后 `.tp3`：VA `0xDC11000`，VSZ `0x3214000`，RAW `0x336800`，熵 `7.8837`；恢复镜像同址只有 `.rimp` VSZ `0x2964`。
2. 恢复镜像 `.rdata` 有 1536 字节被改写为指向 `.rimp` 的指针/表项；`.rimp` 是记录表而非普通代码。
3. `.text` 正常代码直接调用无法线性解释的目标 `0xA04860`、`0x9FA070`；这是受保护/虚拟化/特殊解码岛的候选。
4. 未找到 aplib 恢复脚本、运行时 dump 日志或映射证明。

因此“恢复镜像全镜像未找到 xref”只能说明：
**在当前恢复产物的已解析范围内未找到**；
不能说明原始客户端运行时不存在该调用。

## 5. 可检验/可证伪假设

### H1：分派器位于未恢复的原始最后 `.tp3` 或运行时生成的 VM 代码中

- 支持：原始最后段高熵、大体积、未覆盖；存在非线性直接调用目标。
- 需要证据：同 SHA-256 客户端的运行时解包内存 dump；或完整恢复最后 `.tp3` 并验证解码。
- 证伪条件：在完整运行时映射的 `0x1000–0xDC14000` 范围内仍找不到任何到 `0xA2E50` 的回调/分派。

### H2：`.rdata` 指针/表项被 `.rimp` 修复，破坏了 vtable/函数指针 xref

- 支持：`.rdata` 差异全部是指针表样式；`.rimp` 记录含 `.rdata/.rimp` 地址。
- 需要证据：原始重定位/导入修复表，或在未应用 `.rimp` 修复的镜像上重新解析 vtable。
- 证伪条件：恢复未修复指针表后，所有 vtable/表项仍无 `0xA2E50`。

### H3：`0xA2E50` 由运行时注册的间接回调调用

- 支持：无静态函数指针和直接调用；当前客户端平台层存在动态加载/回调模式。
- 需要证据：运行时调用栈或回调注册观察。
- 证伪条件：在运行时未观察到 `0xA2E50` 被调用。

### H4：`0xA2E50` 是未使用/旧路径

- 支持：当前恢复镜像所有已解析直接/指针/表引用均为 0。
- 需要证据：运行时断点命中计数。
- 证伪条件：一次实际运行时命中即推翻该假设。

目前 H1/H2/H3 都比“客户端已支持 0x02”更符合现有证据；H4 尚未被证伪，但也不能仅凭恢复镜像确认。
