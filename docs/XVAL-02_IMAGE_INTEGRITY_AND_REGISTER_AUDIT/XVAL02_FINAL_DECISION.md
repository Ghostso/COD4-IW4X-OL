## 一、三个必答问题

### Q1. XVAL-01 的"99.86% 缺失"结论是否成立？

**不成立（REFUTED），但其中"字节一致性"部分成立。**

| 子命题 | 裁决 | 依据（字节级/PE 结构） |
|---|---|---|
| "`.data` 存在 99.86% 结构性缺失" | **REFUTED** | 99.8624% = 1 − `SizeOfRawData`/`VirtualSize`（300,544 / 218,481,696）。差额 218,181,152 B 是 **BSS 隐式零填充尾部**，**打包件自身也同样"缺"**（VS/Raw 逐位相同）。 |
| "`.data` 原始字节在打包件与恢复镜像中一致" | **PROVEN** | 两者 `.data` raw 各 300,544 B，SHA-256 同为 `661843e274a5c0a8551ded427f5214b15ffa29c2ca8521ea8fe7e356f915462f`，逐字节相等。 |
| "该缺口是客户端 BLOCKED 的结构性根因" | **部分降级** | 根因应为"**BSS 尾部不可静态获得** + `.tvm0` 语义未分析 + 中间接分派"，而非"资料缺失"。 |
| "末节 `.tp3` 未恢复" | **成立** | 打包末节 VS 0x03214000（52.5 MB）vs Raw 0x00336800；恢复镜像同址为 `.rimp` 10,752 B，49,141,760 B 虚拟尾部未落盘。 |
| "`.tvm0` 未解码" | **表述更正** | `E-06` 已解压（本任务 strict 复现 2,853,888 B）；准确说法是"**未完成指令级语义分析**"。 |

**正确表述（应替代原结论）：**
> 客户端恢复镜像的 `.text`、`.rdata`、`.tls`、`.rsrc` **已完整恢复且经验证**；`.data` 的**初始化数据（300,544 B）与打包件逐字节一致**，其后的 **218.18 MB 是 BSS 零填充尾部（原程序即不落盘）**，静态不可分析属结构性（而非丢失）；末节 `.tp3` 的 **49.14 MB 虚拟尾部未恢复**（是否含游戏代码未证）；`.tvm0` 已解压但语义未分析。

**未复核项（如实声明）：** `.rdata` 头部 1,536 B 与打包件不一致（成因 `BLOCKED`）；末节 `.tp3` 是否承载代码 `BLOCKED`。

### Q2. 当前静态阴性证据哪些仍可信？

**以下仍可信（输入镜像经 aplib 逐字节验证，或在其 `.text`/`.rdata`/`.data` 初始化区内）：**

| ID | 仍可信的阴性结论 |
|---|---|
| N-01 | `.text` 中无 `E8/E9` 调用 `0xA2E50`（本任务独立复算 E8=0, E9=0） |
| N-02 | `.rdata`/`.data` 中无指向 `0xA2E50` 的指针对（aligned + any-offset 均 0） |
| N-03 | `0xA2E50` 无可验证调用者（**因 `.data` 无缺失而更强**） |
| N-04 | 收包函数 3 层闭包内不引用环形缓冲全局 |
| N-05 | 9 个收包原语 8/9 有非游戏归属 |
| N-06 | TLS 链无明文外传、无游戏分派 |
| N-07 | `0x6ABBC0` 闭包内无游戏解析候选（**单源 E-19，未独立复核**） |

**必须降级/更正：**

| 原结论 | 更正 |
|---|---|
| "`.data` 99.86% 缺失 → 搜索空间不完备" 作为 0 命中的**理由** | **降级**：`.data` 无缺失；0 命中应解释为"直接引用确不存在，需查间接/BSS/`.tvm0`" |

| "`.rdata`/`.data` 指针表部分存在部分缺失" | 更正为"`.rdata` 完整（头部 1,536 B 待定）、`.data` 初始化区完整" |

**仍受限制、不得据此断言"客户端不支持"：** 间接分派、BSS 运行时构造、`.tvm0` 语义、末节 `.tp3`、`.rdata` 头部差异。
