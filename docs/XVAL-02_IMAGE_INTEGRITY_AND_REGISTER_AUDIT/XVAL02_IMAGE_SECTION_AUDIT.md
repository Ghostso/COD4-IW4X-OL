## 0. 被复核的原始主张（XVAL-01 C-037）

> XVAL-01 主张：*"客户端恢复镜像 `.data` 存在 99.86% 结构性缺失"*，并据此把全部客户端侧 `BLOCKED` 归因为"搜索空间不完备"。

**本任务结论（先给答案）：该主张在字面上与 PE 事实不符，必须降级为 `REFUTED`。**

理由（详见 §3）：`.data` 的**磁盘原始大小 300,544 B 在打包件与恢复镜像中逐字节完全一致**；所谓"99.86%"是 **`VirtualSize`(218,481,696 B) 与 `SizeOfRawData`(300,544 B) 之比**，其差额是 **BSS 隐式零填充尾部** —— 这部分**在原始程序中从来就不存在于磁盘**，不是"恢复失败丢失的数据"。

## 3. `.data` 的逐项算术（本次复核的核心）

| 项 | 数值 | 说明 |
|---|---|---|
| `VirtualAddress` | 0x008F1000 | 映射起点 RVA |
| `VirtualSize` | 0x0D05C420 = **218,481,696 B** | 映射空间（含零填充尾巴） |
| `SizeOfRawData` | 0x00049600 = **300,544 B** | **磁盘上真实存在的字节** |
| `PointerToRawData` | 0x008EF800 | 文件偏移 |
| 映射范围 VA | 0xCF1000 .. 0xDD4D420 | 218,481,696 B |
| 磁盘字节范围 VA | 0xCF1000 .. 0xD3A600 | 300,544 B |
| **虚拟尾部（不在磁盘）** | **218,181,152 B** | 0xD3A600 .. 0xDD4D420 |
| Characteristics | 0xC0000040 | 可读写、已初始化数据类 |
| **Raw/Virtual 比** | **0.1376%** | — |
| 1 − 比值 | **99.8624%** | ← 即 XVAL-01 引用的"99.86%" |

### 3.1 该 99.86% 是什么？——BSS 隐式零填充尾部

按 PE/COFF 语义与 Windows 加载器行为：节的映射长度为 `VirtualSize`；若 `SizeOfRawData < VirtualSize`，则文件内只提供前 `SizeOfRawData` 字节，**其余尾部由加载器在映射时补零**（"隐式 BSS 尾部"）。

- `.data` 尾部 218.18 MB 属 **BSS 零填充**，**在原始程序中也不存在于磁盘**。
- 佐证：本任务实测 `.data` 磁盘原始 300,544 B 中 **44.52% 为零字节**，熵 **4.7553 bit/byte**（初始化数据形态）；而"未恢复的加密/压缩内容"应呈高熵（≈7.9，见 §4 的 `.tp3`/`.tvm0`）。
- 另外，E-06 的原始结果文件本身**也**记录了这一事实（`.data ... Ch=0xC0000040 ... tail(BSS)=0xD012E20 bytes`），但 XVAL-01 把它提炼成了"99.86% 缺失"。

### 3.2 打包件自身是否也"缺失 99.86%"？

**是——完全相同。** 打包件 `.data` 的 `VirtualSize`/`SizeOfRawData` 与恢复镜像**逐位相同**，Raw/Virtual 比同为 0.1376%。

> 因此"99.86%"**不是恢复造成的缺口**，而是该二进制**设计如此**的 BSS 结构。把它表述为"资料缺失"属于**PE 语义误用**（任务书 §A.4 明令禁止的"以节区大小比例单独证明内容缺失"）。

## 4. `.data` 字节一致性 —— 复核 E-15 的历史结论

字面问题：*"E-15 关于打包 EXE 与恢复镜像 `.data` 字节一致的历史结论"*。

本任务对两者 `.data` 的**磁盘原始 300,544 B** 做逐字节比对：

| 项 | 值 |
|---|---|
| 打包件 `.data` raw SHA-256 | `661843e274a5c0a8551ded427f5214b15ffa29c2ca8521ea8fe7e356f915462f` |
| 恢复镜像 `.data` raw SHA-256 | `661843e274a5c0a8551ded427f5214b15ffa29c2ca8521ea8fe7e356f915462f` |
| 逐字节一致 | **是**（300,544 / 300,544） |

**裁定：历史结论成立。** E-06 已记录该事实（`commonBytes=300544/300544`、`recover_ratio=1.000`），E-15 沿用。本任务独立重算一致。

**补充（本任务新增，历史未记录）：** 同批比对发现 **`.rdata` 并非严格逐字节一致** —— 前 0x6DC 字节内有 1,536 B 差异（25 个连续区间，如 VA 0xBAE000 处 `0x008EEF8A` → `0x0DC11176`，两侧均为 VA 形态），其余 1,319,936 B 一致（99.88%）。该差异集中在 `.rdata` 头部，**形态与恢复阶段的指针重写一致**，但**本任务不足以判定其具体成因**（无恢复工具源码/日志）→ 标 `BLOCKED`。E-06 "identical sizes AND byte-identical → copied verbatim" 对 `.rdata` 的措辞**过强**。

## 5. `.data` 结论的五类区分（任务书 §A.4 逐条）

| 类别 | `.data` 是否属于 | 依据 |
|---|---|---|
| 磁盘字节缺失（恢复失败丢失） | **否** | 打包件与恢复镜像 disk 字节同一；原始不存在更多字节 |
| 节区虚拟尾部 | **是** | VS − Raw = 218,181,152 B |
| BSS（加载器零填） | **是** | Char 0xC0000040 + 只读磁盘初始化数据 + 尾部仅以虚拟空间存在 |
| 未恢复的加密/压缩内容 | **否** | 若如此应高熵；实测 raw 熵 4.755，且与打包件同一 |
| 分析工具无法解析的区域 | **部分是** | BSS 尾部**运行时才有意义**，静态磁盘分析天然不可及 |

## 7. aplib 保真性 —— 恢复镜像可信度的硬证据（本任务新增）

对打包件 `.text` 节（软压缩块）做独立解码：

| 项 | 值 |
|---|---|
| AP32 header（+4 前缀后） | header_size=0x18, packed_len=3,752,773, orig_len=8,047,104 |
| 声明 orig CRC32 | 0x76992F27 |
| `aplib.decompress(..., strict=True)` 输出长度 | **8,047,104**（=恢复镜像 `.text` 大小） |
| 输出 CRC32 | **0x76992F27**（=声明值） |
| 输出 SHA-256 | `c7841257f789a77064381891e81db8d2998937bcd7c6b7f5b10bfad918b46a22` |
| 恢复镜像 `.text` SHA-256 | `c7841257f789a77064381891e81db8d2998937bcd7c6b7f5b10bfad918b46a22` |
| **逐字节相等** | **是** |

同法验证 `.tvm0`（打包 1,115,648 B → 解出 2,853,888 B，orig CRC 0x0EE5F3D3=249,950,707 通过，与恢复镜像逐字节相等）。

> **意义：** 这**不是**"信任某工具"，而是**双锚定**——(a) 恢复镜像独立存在（既有产物），(b) aplib 解码输出与恢复镜像 `.text`/`.tvm0` **逐字节相同**且 **orig CRC 通过**。因此**对 `.text` 的静态结论其输入数据可信**。（注：本任务初次解析时曾把该节 4 字节前缀偏移算错，导致读出 `comp_len=0x18`/`orig_len=0xBBAC1898` 的错误值；已更正为"前缀 4B + AP32 头"口径，即 `comp_len=0x394345, comp_crc=0xBBAC1898, orig_len=0x7ACA00, orig_crc=0x76992F27`。E-06 原始记录本身是正确的。）

## 8. 对 XVAL-01 C-037 的最终裁定

| XVAL-01 原表述 | XVAL-02 裁定 |
|---|---|
| ".data 存在 99.86% 结构性缺失" | **REFUTED** —— 该比例为 BSS 隐式尾部的 VS:Raw 比，非恢复缺口 |
| ".data 只有 0.14% 在文件内" | **成立但需正确表述**：0.14% 是"初始化数据的磁盘占比"，其余为 BSS 零填 |
| ".data 原始字节与恢复镜像一致" | **成立**（本任务字节级复核，300,544/300,544） |
| "'99.86% 缺失'是客户端 BLOCKED 的结构性根因" | **部分降级**：根因收窄为 **BSS 尾部不可静态获得**（而非"资料缺失"） |
| 末节 `.tp3` 未恢复 | **成立**（49,141,760 B 虚拟尾部未落盘），但**代码有无未证** |
| `.tvm0` 未解码 | **部分降级**：`E-06` 已解压；XVAL-01 曾用"未解码"措辞过强 —— 准确说法是"**未完成指令级语义分析**" |
