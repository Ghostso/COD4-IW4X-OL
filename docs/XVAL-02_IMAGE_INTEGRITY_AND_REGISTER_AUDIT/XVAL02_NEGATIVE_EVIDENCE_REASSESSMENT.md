# XVAL02_NEGATIVE_EVIDENCE_REASSESSMENT — 静态阴性证据重估

> 任务书 §A.6：重新评估历史静态搜索的阴性证据，指出哪些结论仍有效、哪些需因输入镜像差异降级。
> 判据来源：`XVAL02_IMAGE_SECTION_AUDIT.md`（PE 结构 + 字节比对 + aplib 保真性）。
> 纪律：**不得因"镜像缺调用引用"断言客户端不支持**（沿用 atlas 15 §3）。

---

## 0. 一句话

XVAL-01 把"客户端搜索空间不完备"的**理由**建立在错误的 `.data` 缺失框架上；XVAL-02 证明 `.data` 无缺失（其尾部是 BSS）。因此：

- **凡是在 `.text` / `.rdata` / `.data`(300,544 B 初始化区) 上做出的阴性证据，其输入镜像可信，结论仍有效**（`.text` 已由 aplib 逐字节验证）。
- **凡是依赖"`.data` 大面积缺失"来解释 0 命中的论证，必须降级**（理由不再成立）。
- 由于初始化 `.data` 本就只有 300,544 B，`0xA2E50` 的调用者/分派**若存在，应在 `.text`/`.rdata`/该 300,544 B `.data` 内出现**；其"0 命中"反而是**更强的发现**（但仍受中间接分派/运行时构造限制，见 §3）。

---

## 1. 重新缩放的"地址空间去向"（替代错误的 99.86%）

以恢复镜像（映射空间 230,768,640 B）为准，按"是否可从磁盘静态分析"重排：

| 区域 | 大小 | 磁盘可分析？ | 备注 |
|---|---|---|---|
| `.text` | 8,047,104 B | ✅ 是（aplib 逐字节验证） | 代码主体，E8 可靠性 81.1% |
| `.rdata` | 1,321,472 B | ✅ 基本是（头部 1,536 B 存疑） | 30,895 个 →`.text` 指针（实测） |
| `.data` 初始化区 | 300,544 B | ✅ 是（与打包件同一） | 2,375 个 →`.text` 指针（实测） |
| `.tls`/`.rsrc` | 512 / 36,352 B | ✅ 是 | 非协议 |
| `.tvm0` | 2,853,888 B | ⚠ 已解压但**未做指令级语义** | 真正的盲区之一 |
| `.data` BSS 尾部 | 218,181,152 B | ❌ **否（运行时零填）** | 唯一"结构上静态不可及"的区域 |
| `.rimp` | 10,752 B | ✅ 是（格式未完全还原） | 指针修复表 |
| 末节 `.tp3` 虚拟尾部 | 49,141,760 B | ❌ 否（未落盘） | 是否含代码未证 |

**净结论：** 静态不可及区域 ≈ **267 MB**（`.data` BSS 218 MB + 末节 `.tp3` 尾部 49 MB），是 XVAL-01 所指缺口的**主要**部分——但它的**性质是"运行时/BSS/受保护"，不是"恢复失败的磁盘缺失"**。

## 3. 仍受限制的阴性证据（不得升级为"客户端不支持"）

即使输入镜像可信，以下机制仍会**隐藏**真实分派，故阴性结论只能保持 `BLOCKED`：

| 机制 | 说明 |
|---|---|
| **间接分派 / 运行时填表** | 分派表项可能在运行期写入 BSS 尾部（静态为 0） |
| **`.tvm0` 指令级语义未分析** | 已解压 ≠ 已理解；非线性/混淆代码未逐指令追踪 |
| **末节 `.tp3` 未恢复** | 该虚拟尾部若含代码，静态不可见 |
| **中间接跳转** | 表项可能来自更深的间接层，未被指针扫描覆盖 |
| **`.rdata` 头部 1,536 B 差异** | 成因未定（BLOCKED），可能影响该处指针引用 |

## 4. 对 XVAL-01 主张表的修正影响

| XVAL-01 Claim | 影响 |
|---|---|
| C-037（`.data` 99.86% 缺失） | **REFUTED**（见镜像审计 §8），改立 C-X01"BSS 尾部不可静态获得" |
| C-009（`0x02`→`0xA2E50` 绑定 BLOCKED） | 结论**不变**，但**理由加强**：其 0 命中不再是"搜索空间缺 99.86%"，而是"直接引用确实不存在，需查间接/BSS/`.tvm0`" |
| C-025（`0x6ABBC0` 单源） | 不变（E-19 未独立复核） |
| C-038（"缺失引用 ≠ 不支持"） | 方法学**维持**，措辞应由"镜像缺 99.86% 数据"改为"存在 BSS/运行时/保护盲区" |

---

## 5. 结论

1. **可信的阴性证据：** 全部建立在 `.text`（aplib 逐字节验证）与 `.rdata`/`.data`(初始化 300,544 B) 的搜索——N-01…N-07。这些**不因 mirror 差异降级**，反而因证明 `.data` 无缺失而**更强**。
2. **必须降级的证据：** 任何以"`.data` 缺 99.86%"为**前提**的解释（N-08/N-10 的表述、C-037）。
3. **仍 BLOCKED：** 间接分派、BSS 运行时构造、`.tvm0` 语义、末节 `.tp3`、`.rdata` 头部差异。
4. **纪律：** 未把任何阴性结果升级为"客户端不存在对应逻辑"。
