### 1.1 "114 / 133 / 142" 从何而来（任务书 §B.5）

同一轮出现两个分母，源于**任务书模板中的"旧总权重"抄用了上一轮自报值，而非上一轮真实末值**：

| 轮次 | 真实末值（复算） | 摘要中出现的"旧总权重" | 差异 | 说明 |
|---|---|---|---|---|
| E-16 | 103 | 103 | 0 | 正常 |
| E-17 | **122** | 114 | −8 | E-17 摘要写"旧总权重 103 → 新总权重 114"，但 103 + (Q-20..Q-23 权重 3+3+5+8=19) = **122** |
| E-18 | **142** | 133 | −9 | E-18 摘要写"旧 122 → 新 133"，但 122 + (3+3+5+1+8=20) = **142** |
| E-19 | **163** | 142 | −21 | E-19 摘要写"旧 142 → 新 163"，但 142 + (5+5+3+8=21) = **163** |

- **性质：** 这是**同一轮内自相矛盾**（其"新总值"才是与逐项累加一致的），**不是**权重定义变更。
- **裁定：** `BLOCKED（历史账目）` —— 双方保留（见 `XVAL-01 CONFLICT-REGISTER CONF-X07/X08`，本任务 §4 延续）。**权威口径以"逐项累加的真实末值"为准（122/142/163）。**

## 5. "问题库解决率" 不是 "协议互通完成率"（任务书 §B.7）

**明确声明：**

1. **口径不同。** 本解决率是"问题权重 × 证据解决度"的**加权和**，度量的是**认知完备度**，不是"协议是否跑通"。
2. **互通完成的唯一判据**是端到端可复现的运行证据（客户端↔服务端真实字节流），本项目**至今为零**（`2697 ↔ C-2697` = NOT-OBSERVED）。
3. **存在反例证明两者不可等同：** 若允许把 REFUTED/闭合项计为 1.0，理论解决率可被人为抬高；本任务因此**拒绝**该映射（见 §6）。
4. **正确表述模板：** "问题库加权解决率 = X%（分母 N，口径 E-15 权重，时点 Y）；**协议互通状态 = 未验证**。" 二者**不得**合并为单一百分比。
