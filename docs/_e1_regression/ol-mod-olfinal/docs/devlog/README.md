# ol-mod 开发历程

这里记录 CODOL 恢复过程中值得复盘和分享的开发历程。它面向人类读者，重点解释问题如何被认识、方案为什么改变，以及证据怎样推动项目越过一个真实边界；它不是 commit log、Agent 运行日志或另一套技术权威文档。

## 写什么

一篇完整记录通常回答这些问题：

- 我们当时想恢复什么，为什么这一步重要；
- 最初如何理解问题，手里有哪些证据；
- 尝试过哪些真正影响方向的做法，它们各自暴露了什么；
- 最终如何解决，哪条证据使结论可信；
- 当前还缺什么，哪些成功不能被扩大解释。

正文使用自然、完整的中文，以正常开发者的叙述方式组织，不为了压缩字数牺牲可读性。函数、协议、地址和工具名保留英文。可以重写和润色旧段落，让文章随新结论变得更准确，不必保留已经被证伪的叙事痕迹。

## 不写什么

- 不逐条抄命令、工具输出、等待过程和普通编译修正；
- 不记录 Agent 的上下文错乱、幻觉、措辞失误或没有影响项目判断的失败操作；
- 不把尚未验证的临时猜测写成故事转折；
- 不复制 `.agents/modules/`、pipeline 或 handoff 的稳定事实；需要细节时链接到权威位置；
- 不为了让故事显得完整而补造动机、对话或时间线。

## 记录节奏

核心开发优先，不要求每轮都停下来写长文。出现以下内容时，先在 [`notes.md`](notes.md) 留一至五行素材即可：新的已验证边界、改变方向的失败方案、能长期节省人工的工具链改进、值得保留的关键截图，或用户明确提出的复盘主题。

到达一个里程碑、旧叙述因新证据需要重写，或用户明确要求整理时，再把素材扩成文章。若某次实现没有形成可复用认识，就不必记录。这样既保留线索，也避免文档工作持续打断调试链路。

## 图片与运行材料

只保留能解释状态变化、故障特征或证据边界的少量图片。文件名包含日期和主题；写入前检查是否带有账号、玩家数据、密钥或无关桌面信息。重复帧、临时日志、完整 trace 和可再生成截图继续留在 `.runtime/`，不进入 Git。

## 文档边界

- `.agents/modules/*.md`：当前稳定模块事实的唯一权威；
- `.agents/pipelines/*.dot`：跨模块状态与责任索引；
- `.agents/research/*.md`：带来源和时间语境的证据快照；
- `docs/devlog/*.md`：经过取舍的开发过程、方法和心得。

开发历程文章可以引用 module 和运行证据，但不得成为实现当前状态的唯一记录。反过来，module 也不复制文章中的叙事。
