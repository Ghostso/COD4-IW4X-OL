## 2. 缺失范围阻断的关键调用边

- **BE-01(socket/recv -> 读包原语 `0x87BE00`)**:
  `0x87BE00` 通过 `call dword ptr [0x0CA84E8]`(主路径,带 overlapped 参数 + 超时)
  与 `call dword ptr [0x0CA84E4]`(降级路径)完成读。
  **槽值 = API 名/函数地址,不在文件内 -> 无法静态判定是 `ReadFile`、`RecvFile` 还是 `WSARecv`。**
- 次要:`0x87ED70` 的 `[0x0CA8330]` 取池槽;`0x87EDD0` 的 `jmp [0x0CA8510]`(纯 IAT thunk)。

## 3. 现有静态材料为什么不能替代

044 已尝试全部可行的静态替代,均失败:

1. **绝对 dword 引用扫描**(整个 present 映像,含数据区):对
   `0x87C110/0x87D5A0/0x87BE00/0x87BA50/0x87A890/0x85E6F0/0x87ED70/0x87EDB0`
   **命中数 = 0**。既无函数指针表项,也无绝对地址引用。
2. **E8/E9 全量扫描**:`0x87BE00` 的 E8 调用者 = 0(只经 `E9` thunk `0x87BA50`);thunk 调用者 = {`0x85D96E`,`0x85E71A`}。
3. **indexed 间接跳转扫描**(`[reg*4+disp]`,1278 处):解码器区域内仅 2 处间接(`0x87ED85` IAT call、`0x87EDD0` IAT jmp),
   无一指向被审计函数;扫描到的 12 处 `0x87xxxx` 候选表基址**全部证伪**为"乘 4 索引位移落在指令体内"(见 05)。
4. **跨镜像复用**:工作区**全部 12 份** `image_best.bin`(4 个构建)在原文件偏移 `0x0CA84E8` 处**均不存在有效字节**
   (文件长同为 0x0A65000,`OOB`) -> 其它既有镜像**无法替代**。
5. **PE 导入目录**:`Size = 0`,无导入名可解析。
6. **字符串旁证**:本镜像内 ASCII `recv`(`0x935406`)、`select`(`0x8BBD9C`)分别属于
   `"Socket not ready for send/recv"`(SSH/curl 层)与 `"selectMultiple"` —— **非 socket 接收 API**,不可用于命名 IAT 槽。

-> **结论:slot 值不在任何现有静态材料内,且不可由现有材料推出。**

## 4. 新增证据预计能验证什么 / 不能验证什么

| 能验证 | 不能验证 |
|---|---|
| `0x0CA84E8`/`0x0CA84E4` 到底是哪个 API(ReadFile / WSARecv / recvfile) | 该 API 的**调用者链上游业务语义** |
| `0x87BE00` 是"文件/重叠读"还是"套接字读" | 应用层 opcode <-> 语义映射 |
| 收包缓冲与 `{data,len}` 的**生产-消费**连接(填充 BE-01/BE-07) | 是否另有未覆盖/受保护节的业务入口 |
| `0x0CA8330` 取池槽 | `.tvm0` 内逻辑 |

> **可最小化**:只需"覆盖 `RVA 0x0CA8400..0x0CA8700` 的只读快照 + 该槽的符号/导入名"即可闭合 BE-01,
> **不需要**完整内存转储、不需要动态调试/hook。
