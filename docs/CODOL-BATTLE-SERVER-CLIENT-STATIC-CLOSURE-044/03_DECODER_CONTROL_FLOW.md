## 2. `0x87C110`(解码器 #1)

### 2.1 真实"类型/种类"字段与取值域

全函数对 `[ebx+8]` 的引用**只有 2 处**(与 043 一致,044 复验):

| # | 位置 | 指令 | 判据 | 目标 |
|---|---|---|---|---|
| 1 | `0x87C767` | `cmp dword ptr [ebx+8],1` | `>1` 用 `[ebx+0x14]` 作基址;`<=1` 用 `[ebx+0x78][idx+0x130]` | `0x87C774 / 0x87C77B` |
| 2 | `0x87C794` | `mov eax,dword ptr [ebx+8]` 后 `cmp eax,1`(`0x87C797`) | 见下 | 分派 |

### 2.2 由**直接指令**证明的分派

```
0x87C797  cmp eax, 1
0x87C79A  jle 0x87CEB1                 ; 类型 in {0,1}  -> 专门处理
0x87C7A0  sub eax, 0x15                ; 21
0x87C7A3  je  0x87CBC8                 ; 类型 == 21     -> 字符串(char)路径
0x87C7A9  dec eax                      ; 22
0x87C7AA  je  0x87C994                 ; 类型 == 22     -> 宽字符串(wchar)路径
0x87C7B0  (default)                    ; 其余全部
```

- **可直接证明已处理的具体取值:** `0, 1, 21, 22`。
- **默认(其余全部)** 按"元素数组"处理:`[ebx+0x18]` 为单位字节数(`imul` @ `0x87C7B9`),
  再按 `[ebx+0x1C]` 作**元素宽度分类** `1 / 2 / 4 / 8`(`dec/sub` 级联 @ `0x87C813/0x87C81A/0x87C821/0x87C82A`),
  超过 `0x40` 元素走 `memcpy`(`0x87C978`,`call 0x8427F0`)。
- **类型 0 与 1** 走 `0x87CEB1`:先 `cmp [esp+0x38],0x20`,再按 `[ebx+0x64]`(2/4/8 宽度)读源,
  `imul ...,0xb4`(`0x87CF32`)与 `lea [..+0x134]/+0x114` 计算结构步长。

### 2.3 可达类型集合的三档口径(严格区分)

| 口径 | 内容 | 依据 |
|---|---|---|
| **A. 直接指令证明** | `{0,1,21,22}` 有专属分支 | `cmp/sub/dec` 链 |
| **B. 控制流推导可达** | `[ebx+8]` 任意 32 位值都进入某路径(默认分支无上限检查) => 可达集 = `{0,1,21,22} + 其余全部` | 默认分支无界 |
| **C. 仅由字符串/上下文推测** | 21="串",22="宽串",0/1="结构体/指针类",默认="POD 数组" | 诊断串 `0x99EF50/0x99EE98` + 搬运宽度;**仍是猜测** |

> **不得**把 `{0,1,21,22}` 当作整个网络协议的完整类型枚举 —— 它只是该描述符字段在**本函数内**被显式比较的值。
> 取值范围由**驱动数据**的 `[ebx+8]` 决定;调用者(TQOS)如何填 `[ebx+8]` **不在本镜像可证范围内**。

## 3. `0x87D5A0`(解码器 #2)

### 3.1 与 #1 的结构差异

- `[ebx+8]` 在 #2 中**不是**类型字段(所有 `+8` 引用都是 `[ebp+8]`,即 arg1 描述符偏移)。
  真正的类型字段是 **`[ebp+8]`**(`ebp` = arg1)。
- 参数:**两对 `{data,len}` + context**(`[ebx]`/`[ebx+4]` 与 `[edi]`/`[edi+4]`)+ 第 4 参数(`[esp+0x182c]`)。

### 3.2 由**直接指令**证明的分派

```
0x87DD3E  cmp eax, 0x15   ; 21
0x87DD41  je  0x87DD4D
0x87DD43  cmp eax, 0x16   ; 22
0x87DD46  je  0x87DD4D
          ...             ; 其余 -> 走 [ebp+0x18]

0x87DE58  cmp eax, 1
0x87DE5B  jle 0x87E65F            ; 类型 in {0,1}
0x87DE61  sub eax, 0x15           ; 21
0x87DE64  je  0x87E30F            ; -> 字符串(char)
0x87DE6A  dec eax                 ; 22
0x87DE6B  je  0x87E07A            ; -> 宽字符串(wchar)
0x87DE71  (default)               ; 其余全部 -> 元素数组
```

- **可直接证明的具体取值:** `0, 1, 21, 22`(21/22 在两处被一并处理)。
- 默认分支宽度分类与 #1 **同形**:`dec/sub` 级联 @ `0x87DEED/0x87DEF4/0x87DEFB`,
  元素搬运循环 `0x87DF10..0x87DFC1`(回边 `0x87E5DD`)。

| 口径 | 内容 |
|---|---|
| A. 直接指令 | `{0,1,21,22}` |
| B. 控制流可达 | 任意 32 位值(默认无界) |
| C. 推测语义 | 同 #1;#2 把 21/22 作为一族成对比较(#1 用 `sub` 分离) |

## 4. 公共核心候选的真实语义(043 描述过于笼统)

### 4.1 `0x87ED70` — 临时/池缓冲获取

```
0x87ED70  cmp dword[0x196c7e8],0      ; 池是否已初始化
0x87ED77  push esi / mov esi,0x196c7f0
0x87ED7D  je 0x87ED91                  ; 未初始化 -> 用静态缓冲 0x196c7f0
0x87ED7F  mov eax,[0x196c7ec] / push eax
0x87ED85  call dword[0xca8330]         ; IAT 槽(镜像外)
0x87ED91  cmp byte[esi+0x3FF],0        ; 0x400 = 1024 字节
0x87ED9C  mov byte[esi+0x3FF],0
0x87EDA4  ret                          ; eax = 缓冲指针
```

- 无参数;**返回一个 1024 字节(0x400)scratch 缓冲**;首字节由调用方清零(`0x87C158` `mov byte[eax],bl` 等)。
- `0xCA8330` 槽值 **OUT-OF-IMAGE -> BLOCKED**(仅"取池" API,不影响本函数语义)。

### 4.2 `0x87EDB0` — 有界 UTF-16 长度计数(`wcsnlen` 语义)

```
0x87EDB0  mov edx,[esp+8]      ; 上限
0x87EDB4  mov ecx,[esp+4]      ; 指针
0x87EDB8  xor eax,eax
0x87EDC0  cmp word[ecx],0      ; UTF-16 终止符
0x87EDC6  inc eax / add ecx,2 / cmp eax,edx / jb loop
0x87EDCE  ret                  ; eax = 字符数
```

- **E8 调用者在整段 present text 中只有 1 处:`0x87C9B7`**(解码器 #1,类型 22 宽串路径)。
- 043 记"两者都调用 `0x87EDB0`" —— **044 无法复现**:节区 #0 全量 `E8` 扫描对 `0x87EDB0` 只返回 `0x87C9B7`。
  **044 判 043 此处为误记**(见 09 勘误 C2)。
