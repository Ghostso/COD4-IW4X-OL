## C1. `0x87EDB0` 被两个解码器共同调用 —— **无法复现**(重要性:中)

- **043 原文**(`03_CALLER_AND_DATAFLOW_AUDIT.md` §4):
  ```
  0x87C110  -- call --> 0x87EDB0  (x1)   UTF-16 长度计数
  0x87D5A0  -- call --> 0x87EDB0  (xN)  同上
  ```
- **044 实测:** 节区 #0(唯一代码节)全量 `E8` rel32 扫描,指向 `0x87EDB0` 的调用点
  **只有 `0x87C9B7` 一处**,位于解码器 #1 的类型 22 分支。
  指向 `0x87EDB0` 的 `E9` / absolute-dword 引用均为 **0**。
- **证据:** `scripts/c02_focus.py` 输出、`evidence/c02_focus.txt`;`a01_identity.py` 的 E8 扫描段。
- **裁定:** 043 的 `0x87D5A0 -> 0x87EDB0 (xN)` 一行**无机器码支撑**,判为**误记/证据不足**;
  043 的**共享辅助**结论本身仍成立(两者都调用 `0x87ED70`)。

## C2. `0x87ED60` 未被 043 登记(重要性:低)

- 044 在 `0x87D5A0` 与 `0x87ED70` 之间发现 3 指令函数 `0x87ED60`:
  ```
  0087ed60  8b442404   mov eax, dword ptr [esp + 4]
  0087ed64  a380c79601 mov dword ptr [0x196c780], eax
  0087ed69  c3         ret
  ```
  即 `void set(GLOBAL* p)`。不是解码核心,但会影响任何「函数边界列表」的完整性。
- **证据:** `evidence/dis_full_87D5A0.txt`(尾部)、`b01_cfg.txt`。

## C3. 「共享核心 `0x87ED70`/`0x87EDB0`」的措辞(重要性:低)

- 043 在 `02` 结论表中把两者并列为「共享核心」;044 证明二者语义不同且调用面不同:
  `0x87ED70` = 取 0x400 scratch(两解码器都大量调用);`0x87EDB0` = 有界 UTF-16 长度计数(仅 #1 一次)。
- **建议措辞:** 「共享辅助」,不称「(公共)核心/分派核心」。**不影响** 043 的 `COMMON_CORE` 归纳(两者确实共享 `0x87ED70`)。

## C4. `0x87BE00` 语义(补充,非错误)

- 043 称 `0x87BE00` 为「读包原语」,**未**指明是文件还是套接字。044 补一条**支持文件/重叠读**的证据:
  标准 `mov eax,0x10624DD3; imul; sar 6`(`0x87BE4D..`)是 `ms/1000` 与 `ms%1000` 的魔数除法
  (除 1000),结果被压入 `OVERLAPPED`(`0x87BE76..0x87BE83`),再 `call [0x0CA84E8]`;
  失败码过滤 `0x2714`/`0x2733` 属 Win32 等待错误族(非 WSAGetLastError 族)。
- **裁定:** 该原语**更像 ReadFile/ReadFileEx 类重叠读**;这与 042/043 隐含的「socket 收包」叙事**存在张力**,
  但**未到证否**程度(slot 值不可读)。**保持 `UNKNOWN`,并新增「更像文件读」这一竞争假设。**
- **证据:** 反汇编见 03 与 06/BE-01;`evidence/c02_focus.txt`。
