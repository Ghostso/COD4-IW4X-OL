# 04 — 环形缓冲读侧与回调审计 / READER & CALLBACK AUDIT

> 原始输出：`_data/out_readerptr.txt`、`_data/out_writer_audit.txt`

## 1. `0x352570` 的可读长度逻辑（DIRECT）

**边界：** `0x352570..0x3525EC`。

```asm
352574  mov ebx,[ebp+0xc]             ; len（调用者传入）
352578  mov edi,[0x743DE9C]
35257E  mov eax,[edi+0x30AF30]        ; read cursor
352584  lea ecx,[eax+ebx]             ; read + len
352587  cmp ecx,0x300000
35258D  jl  0x7525C6
35258F  push esi
352590  mov esi,0x2FFFFF
352595  sub esi,eax                   ; 剩余容量
35259B  lea edx,[eax+edi+0x8048]      ; src = ring + read
3525A8  call 0xB4FF60                 ; memcpy（第一段）
3525AD  add [edi+0x30AF30],esi
3525BB  mov dword [edi+0x30AF30],0    ; 回绕
3525C6  mov ecx,[edi+0x30AF30]
3525D0  lea edx,[ecx+edi+0x8048]
3525D9  call 0xB4FF60                 ; memcpy（第二段）
3525E1  add [edi+0x30AF30],ebx
3525E8  mov eax,ebx                   ; 返回 len
```

**关键（DIRECT）：** `0x352570` 的可读长度**完全由调用者传入的 `len` 决定**。它

- **不读取** `+0x30AF2C`（写游标）
- **不计算** `write - read`（可读字节数）
- **不检查** 缓冲区是否有足够数据
- 只是无条件从 `read` 位置复制 `len` 字节并推进读游标

**结论：** 该函数**不是**一个带流量控制的消息队列消费者；它是**按调用者指定长度的裸复制器**。

## 2. 双游标读写关系（DIRECT）

| 游标 | 偏移 | 写入者 | 读取者 |
|---|---|---|---|
| 写游标 | `+0x30AF2C` | `0x3524F0`（+4 处）、`0x356580`（重置） | `0x3524F0`、`0x351D00` |
| 读游标 | `+0x30AF30` | `0x352570` | `0x352570` |

**关键（DIRECT）：** 写侧**不读**读游标，读侧**不读**写游标。两侧**互不感知**。

**含义：** 这不是生产者-消费者队列，而是**两个独立指针在同一块 3 MB 暂存区上滑动**。生产者/消费者的同步由**外部调用顺序**保证，而非结构内同步。

## 3. 读取器指针 `[+0x89244]` 的 3 处写入（DIRECT）

全 `.text` 中该偏移的写入仅 3 处：

| # | 站点 | 写入值 | 所属函数 | 执行条件 |
|---|---|---|---|---|
| W1 | `0x35141E` | `0x752570` | `0x3512A0` | 网络/实时分支 |
| W2 | `0x3515D9` | `0x74F090` | `0x3512A0` | demo 分支（同一函数内切换） |
| W3 | `0x356701` | `0x74F090` | `0x356580` | demo 装载 |

### W1 上下文（`0x3512A0`）

```asm
35141E  mov dword [ecx+0x89244],0x752570
351428  mov eax,[esi+0x308048]
351433  push 4
35143C  call 0x752570                 ; 立即用刚装的读侧读 4 字节
```

**注意（DIRECT）：** W1 之后立即用 `0x352570` 读 4 字节——这说明 `0x3512A0` 期望环形缓冲中**已有数据**。但 `0x3512A0` **本身不调用 `0x3524F0`**（写侧）。

### W2 上下文（同一函数尾部）

```asm
3515D9  mov dword [eax+0x89244],0x74F090   ; 切成 demo 读取器
3515E3  ...
3516EA  call 0x48F1D0                       ; 进 demo 驱动
```

### W3 上下文（`0x356580`）

```asm
356701  mov dword [esi+0x89244],0x74F090
35670B  mov edx,[eax+0x89244]
356711  push 0x8020 / push ecx / call edx
356722  call 0x48F1D0
```

## 4. 读取器指针是否指向候选解析函数

| 候选 | 是否为 `[+0x89244]` 的取值 | 裁定 |
|---|---|---|
| `0x350170` | 否（3 处写入均非此值） | **REFUTED** |
| `0x3547D0` | 否 | **REFUTED** |
| `0xA2660` | 否 | **REFUTED** |
| `0x352570`（环形缓冲读侧） | **是**（W1） | PROVEN |
| `0x74F090`（demo 读取器） | **是**（W2/W3） | PROVEN |

**纪律：** 读取器指针**从未**指向任何消息解析器；它只指向**两个数据来源**（环形缓冲读侧 / demo 文件）。

## 5. 调用者与执行条件（DIRECT）

| 写入 | 调用者 | 调用者是否在收包闭包内 |
|---|---|---|
| W1/W2（`0x3512A0`） | `0x34E7C0`（`cl_demo_jumptostart`）、`0x3519F0`、`0x351A10` | **否** |
| W3（`0x356580`） | `0x34E7C0` | **否** |

**`0x3512A0` 的上游全部属 demo 控制流**（E-12 已证）。

## 6. 裁定

| 项 | 裁定 |
|---|---|
| `0x352570` 边界与逻辑 | **PROVEN** |
| 可读长度由调用者决定（无队列语义） | **PROVEN** |
| 双游标互不感知 | **PROVEN** |
| `[+0x89244]` 3 处写入的值与上下文 | **PROVEN** |
| 读取器指针指向解析器 | **REFUTED** |
| 3 处写入能否建立实时消息入口 | **BLOCKED**（写入者均为 demo 链；无收包侧调用者） |
