# 04 — 终止符位边界 / TERMINATOR BIT ALIGNMENT

> 任务 C：沿服务端写入路径累计位数；查明是否字节对齐；对齐发生在何处；客户端是否独立可证。
> 等级：`DIRECT` / `INFERRED` / `BLOCKED`
> 模型与输出：`_tools\c08_authoritative.py`、`_data\out_c08.txt`、`out_c09.txt`

---

## 1. 两个游标（服务端 msg 结构）

| 偏移 | 语义 | 谁更新 | 证据 |
|---|---|---|---|
| `[msg+0x00]` | 缓冲区指针 | — | 0x994E2 |
| `[msg+0x04]` | **字节计数** `used` | `MSG_WriteData`（`add [ebx+4],eax` @0x994DD） | 0x9949B |
| `[msg+0x08]` | 容量 | — | 0x994AE |
| `[msg+0x10]` | **位位置** `bitpos` | **仅 `MSG_WriteBits`** | 0x995FE |
| `[msg+0x14]` | 溢出标志 | 越界路径 | 0x994C8 |

## 2. 关键机制：位游标在字节边界处**强制重同步**

`MSG_WriteBits` 的增长块（`0x9960A`..`0x99635`）：

```asm
09960A  test byte ptr [edi + 0x10], 7   ; bitpos % 8 == 0 ?
09960E  jne  0x4995DC
099610  mov  eax, [edi + 4]             ; eax = used（字节计数）
09961F  lea  edx, [eax*8]               ; edx = used * 8
099626  mov  [edi + 0x10], edx          ; ★ bitpos = used * 8   —— 强制重同步
09962E  mov  [edi + 4], ecx             ; used += 1
099631  mov  byte [edx + eax], 0        ; 追加 0 字节
```

**含义：** 每当 bitpos 落在字节边界，写位器就**丢弃任何"落后于 `used*8` 的位偏移"，直接把 bitpos 拉到 `used*8`**。
（原始二进制：`f6 47 10 07 75 cc 8b 47 04 3b 47 08 73 b5 3d ff ff ff 1f 77 ae 8d 14 c5 00 00 00 00 89 57 10 ...`）

## 3. `MSG_WriteData` 与 A1 字符串**不**更新位游标

`MSG_WriteData`（0x9949B）只做：容量检查 → `memcpy(buf+used, src, len)` → `used += len`。
**全程无 `[msg+0x10]` 的读或写。**

`WriteLenStr`（0x99651，A1 字符串写入器）**完整字节**（0x3E 字节）：

```
55 89 e5 53 83 ec 0c 8b 5d 0c 85 db 74 23 89 1c 24 e8 d9 c0 2c 00 83 c0 01
89 44 24 08 89 5c 24 04 8b 45 08 89 04 24 e8 1e fe ff ff 8b 5d fc c9 c3 ...
```

反汇编确认**不存在**对 `[msg+0x10]` 的写入（脚本自检 `out_c09.txt`：`result: False`）。

**结论（DIRECT）：** A1 的字符串字节是**裸字节写入**，`used` 前进而 `bitpos` **不动**。

## 4. 因此：A1 字符串**不是**位流的一部分

这直接改变对"body 是位流"的理解：

- A1 的字符串**不占位**（在 bitpos 意义下）；
- 下一个位字段开始时若 bitpos 处于字节边界，重同步会跳到 `used*8`，即**自然跳过刚写入的字符串字节**；
- 因此 **`bitpos` 在 body 内始终不大于 `used*8`，且每次边界都对齐到 `used*8`**。

## 5. 累计位数计算（模型可复算）

按 `_tools\c08_authoritative.py` 的权威模型：

| 场景 | `0x06` 起始 bitpos | 写入后 used(bytes) |
|---|---|---|
| A1=[] A2=[] A3=[] | 44 | 7 |
| A1=[(0,'')] | 53 | 8 |
| A1=[(0,'a')] | 61 | 9 |
| A1=[(0,'a')] A2=[(0,1)] | **72** | 10 |
| A1=[(0,'a')] A2=[(0,1),(1,2)] A3=[(0,1023,127,[4095,1])] | 129 | 18 |

**观测：**
- `0x06` 的起始 bitpos 在不同输入下**模 8 余数不同**（44≡4, 53≡5, 61≡5, 72≡0, 129≡1）；
- 即 **`0x06` 通常不是字节对齐的**，但**可以**是（例如第 4 行恰为 72 ≡ 0）。

## 6. 客户端侧的终止处理（独立追踪结果）

对客户端消费路径（`0xA2660`）逐块追踪：

| 段 | 客户端读取 | RVA |
|---|---|---|
| count1 | `MSG_ReadData(...,2)` | 0xA26B2 |
| A1 循环 | 13-bit 索引 + `0xA25F0`（字符串按 NUL 扫描，**非位读**） | 0xA26F4 / 0xA2751 |
| A2 循环 | 11-bit count → (13-bit 索引 + 10-bit) | 0xA276C…0xA2879 |
| A3 循环 | 10-bit count → (13-bit 索引 + `0xA2480`（10/7/4/12）） | 0xA2879…0xA28E0 |
| 结束 | `dec [ebp-0x10C]; jne` → `ret` @ **0xA2975** | 0xA295F |

**关键观察（DIRECT）：** `0xA2660` 在**读完 A3 段的计数循环后直接返回**，**没有**读取 `0x06` 的指令。
（`0xA25F0` 用 `mov cl,[eax]; test cl,cl` 按 **NUL 终止**处理字符串，同样是**字节**语义，与位流无关。）

**因此：**
- 服务端 `0x06` 的**写入**：`WriteByte(6)` @ `0xA0997`（**DIRECT**）；
- 客户端 `0x06` 的**读取**：**未在本函数内定位** → 应在**外层消息分派器**（尚未定位）中；
- 端到端终止语义：**BLOCKED**。

## 7. 三处 `0x06` 必须分开（任务 C 第 5 条）

| 上下文 | 写入点 | 读取端 | 裁定 |
|---|---|---|---|
| **Configstring 终止** | `WriteByte(6)` @ **0xA0997** | **未定位**（不在 0xA2660 内） | **BLOCKED（写入端 DIRECT）** |
| Gamestate 尾 | `0xA22F8`（E1） | 未定位 | **BLOCKED** |
| Snapshot 内部标记 | `0xA4CAF`（E2；其后仍继续写） | 未定位 | **BLOCKED（且已知非消息终止）** |
| Snapshot 外层选择器 | `0x87104`（按 archives 激活选 0x05/0x06） | 未定位 | **BLOCKED** |

**禁止跨上下文等同**：本报告不主张四者语义相同。

## 8. 裁定

| 问题 | 回答 | 等级 |
|---|---|---|
| 服务端从 body 起点到 `0x06` 的累计位数是否可算？ | **可算**（模型逐指令构建，见 §5） | **DIRECT（机制）/ INFERRED（具体值依赖输入）** |
| 写入原语是否执行字节对齐？ | **是**：`MSG_WriteBits` 在 `bitpos%8==0` 时**强制 `bitpos = used*8`** | **DIRECT** |
| 对齐发生在哪个调用点？ | 增长块 `0x9961F..0x9962E`（每次进入新字节时） | **DIRECT** |
| A1 字符串是否占位？ | **不占**（`MSG_WriteData` 不动 bitpos） | **DIRECT** |
| `0x06` 是否总在字节边界？ | **不总在**（例：bitpos 44/53/61/129）；**可以**在（例：72） | **DIRECT（模型）** |
| 客户端 `0x06` 读取/终止条件 | **未定位** | **BLOCKED** |
| 端到端终止语义 | **不可标 PROVEN**（客户端侧缺证） | **BLOCKED** |

**结论：任务 C 在服务端侧**闭合**（写入位置、位对齐机制、字符串不占位、bitpos 可算）；在客户端侧**保持 BLOCKED**。
因此按任务规定"只有写入路径与读取路径都得到证据支持才算 PROVEN"，**终止语义不得标为 PROVEN**。

## 9. 最小新增证据（若要把该 BLOCKED 转为 PROVEN）

1. 定位外层消息分派器（读取 `0x04`/`0x06` 的 switch）——**纯静态可继续**；
2. 或取得一条原始 configstring 帧，核对 `0x06` 的实际位偏移与是否对齐——**需授权**。
