### 3.3 裁定

**`CONDITIONAL GO（放宽）`** —— 相对 E-08 的裁定：

- **解除**两项工程约束：
  1. `count1` **不再需要参数化**（固定 2 字节小端）；
  2. configstring body **可按已证规格直接实现**（不再视为"未知结构"）。
- **保留**两项约束：
  1. **不得**在 BLK-6/7/8 解除前宣称互通；
  2. configstring 的**分帧/终止**必须按"待验证"处理（建议编码器在 body 后按服务端规则写 `0x06`，但**不得**宣称客户端会正确识别）。

## 4. 建议开工顺序（更新）

1. **M2-a**：按已证规格实现 configstring body 编码器（count1 = 2 字节小端；索引增量；A1/A2/A3）。
2. **M2-b**：用 E-08 的 V-A/V-B/V-C 做单元测试（**候选向量，仅自洽**）。
3. **M2-c**：把 `0x02` reliable / gamestate / snapshot 一并参数化实现。
4. **优先解除 BLK-7**：定位外层消息分派器（**纯静态可继续**）——这是打通"configstring 分帧"的关键。
5. **不得**在 BLK-6 未解除前进入"客户端连通性验收"。

## 5. 为何这次放宽是安全的（证据强度说明）

| 判据 | 强度 |

| BLK-1 | 两侧**逐字段**（顺序+宽度+上界+区间规则+格式化串）一致；**非**形状匹配 |
