# 05 — 三大阻断项证据矩阵 / THREE-BLOCKER EVIDENCE MATRIX

> 汇总 22_SERVER_START_GATING_AUDIT 的三个阻断项（BLK-1/2/3）在 E-09 后的裁定。
> 等级：`PROVEN` / `REFUTED` / `PARTIAL` / `BLOCKED`

---

## 1. 总表

| 阻断 | 内容 | E-08 状态 | **E-09 裁定** | 关键证据 |
|---|---|---|---|---|
| **BLK-1** | 客户端 Configstring body 字段消费顺序 | BLOCKED | **PROVEN** | 客户端 `0xA2660` 与服务端 `0xA0468` **逐字段一致**（`01`/`02`） |
| **BLK-2** | `count1` 实际编码宽度 | SOURCE-CONFLICT（8 vs 16） | **PROVEN = 2 字节（16 位）**；8 位 **REFUTED** | `0x994FC` 三重用法 + 客户端 `MSG_ReadData(...,2)` + `movsx word`（`03`） |
| **BLK-3** | `0x06` 的位边界、对齐与终止语义 | BLOCKED | **服务端 PARTIAL（已闭合写入侧）/ 客户端 BLOCKED** | 位游标重同步机制 DIRECT；客户端 `0x06` 读取**未定位**（`04`） |

---

## 2. BLK-1：客户端 body 消费顺序 —— **PROVEN**

| 字段 | 服务端写入（RVA） | 客户端读取（RVA） | 一致 |
|---|---|---|---|
| `0x04` | `WriteByte(4)` @ 0xA07F8 | **未定位（外层）** | ⚠ 外层 |
| count1 | `WriteShort` @ 0xA0807 | **`MSG_ReadData(...,2)` @ 0xA26B2** | ✔ |
| A1 索引 | `WriteIndexDelta` @ 0xA0400（连续=1b；否则 0+13b） | **13-bit @ 0xA26F4** + 连续性判定 @ 0xA26E2 | ✔ |
| A1 索引上界 | `cmp esi,0x1DD6` @ 0xA053E | **`cmp edi,0x1DD7` @ 0xA2702** | ✔ |
| A1 索引区间 | 紧凑表 + 跳过 0x12 | **`mov cl,[edi+0x2BD0A40]` + `cmp cl,0x14` + `cmp cl,0x12` @ 0xA2728** | ✔ |
| A1 字符串 | `WriteLenStr` @ 0xA0840（`strlen+1` 字节） | `0xA25F0`（NUL 扫描）@ 0xA2751 | ✔ |
| A2 计数 | `WriteBits(...,0xB)` @ 0xA085F | **11-bit @ 0xA276C** | ✔ |
| A2 值 | `WriteBits(...,0xA)` @ 0xA08A0 | **10-bit @ 0xA27D7** | ✔ |
| A3 计数 | `WriteBits(...,0xA)` @ 0xA08BF | **10-bit @ 0xA2879** | ✔ |
| A3 记录 | 10b/7b/4b/n×12b @ 0xA091D–0xA0974 | **`0xA2480`**：10b@0xA2490、7b@0xA249B、4b@0xA24A7、n×12b 内联 @0xA24DE+ | ✔ |
| `0x06` | `WriteByte(6)` @ 0xA0997 | **未定位（外层）** | ⚠ 外层 |

**判定：** 字段**顺序 + 宽度 + 上界 + 区间规则**四项全部两侧对应 → 远超"形状匹配"，为 **PROVEN**。
**未获证部分：** `0x04`/`0x06` 的**外层框架读取**（属消息分派层，不在 `0xA2660` 内）。

## 3. BLK-2：count1 宽度 —— **PROVEN（16 位）**，8 位 **REFUTED**

| 证据 | 指向 |
|---|---|
| `0x994FC`：`ecx` 同时用作 (a) 拆字节循环次数、(b) `WriteData` len、(c) `>>8k` 步长 | **字节数** |
| `0x99566` 全服务端**仅**用于写此类计数 | 无歧义 |
| 客户端 `push 2` → `MSG_ReadData` | **2 字节** |
| 客户端 `movsx eax, word ptr [...]` | **16 位有符号** |
| 8 位假设的来源 `"* %u"` | 经复核为 **`snprintf` 调试/文本用途**，非线格式位宽 |
| 8 位假设与客户端 `push 2` | **直接矛盾** |

**判定：** 16 位 **PROVEN**；8 位 **REFUTED**。
**工程影响：** 不再需要按"未定"参数化；可固定为 2 字节小端。

## 4. BLK-3：`0x06` 位边界与终止 —— 服务端 **PARTIAL**，客户端 **BLOCKED**

| 子问题 | 裁定 | 证据 |
|---|---|---|
| 服务端 `0x06` 写入点 | **PROVEN**：`WriteByte(6)` @ 0xA0997 | 指令 |
| 位游标与字节游标分离 | **PROVEN**：`[msg+0x10]`（位）vs `[msg+4]`（字节） | 0x995FE / 0x994DD |
| 位游标在字节边界强制重同步 | **PROVEN**：`bitpos = used*8` @ 0x9961F–0x9962E | 指令 + 原始字节 |
| A1 字符串不占位 | **PROVEN**：`0x99651` 无 `[msg+0x10]` 写入 | 全函数字节核对 |
| `0x06` 起始 bitpos 可计算 | **PARTIAL**：机制已定；具体值**依输入**而定 | 模型：44/53/61/**72**/129 |
| `0x06` 是否总字节对齐 | **REFUTED**（不总对齐；可因输入而对齐） | 模型 |
| 客户端 `0x06` 读取/终止 | **BLOCKED** | `0xA2660` 循环结束即 `ret`（0xA2975），无 `0x06` 读取 |
| 端到端终止语义 | **BLOCKED**（缺读取侧证据） | — |

**判定：** 服务端写入侧 **PARTIAL→已闭合**；客户端读取侧 **BLOCKED**；端到端 **不得标 PROVEN**。

## 5. 三阻断项对"服务器最小闭环"的残余影响

| 阻断 | 是否仍阻断闭环 | 说明 |
|---|---|---|
| BLK-1（body 顺序） | **不再阻断** | 两侧逐字段一致，编码器可实现并接受 |
| BLK-2（count1 宽度） | **不再阻断** | 已裁定 2 字节 |
| BLK-3（`0x06` 终止） | **仍阻断（部分）** | 服务端可正确写出；**客户端如何定位终止**未知 → 若客户端按字节边界定位，则服务端必须补位对齐（**未证实**） |

**新增/转移的阻断项：**

| ID | 内容 | 来源 |
|---|---|---|
| **BLK-7（新）** | **外层消息分派器未定位**（读取 `0x04`/`0x06`） | E-09 `01`/`04` |
| **BLK-8（新）** | `0x06` 是否为"位流内 8 位常量"或"需字节对齐的外部标记" | E-09 `04` §5–§6 |

## 6. 结论

| 问题 | 回答 |
|---|---|
| 三个阻断项是否都已升级？ | BLK-1 → **PROVEN**；BLK-2 → **PROVEN(16b)**；BLK-3 → **服务端已闭合 / 客户端 BLOCKED** |
| 是否有假设填补？ | 否。全部结论附指令地址；未闭合处保留 BLOCKED |
| 是否把构造向量当 Golden？ | 否（`05_TEST_VECTOR_SPEC.md` 沿用 E-08 的**候选**标注） |
| 是否因找不到就宣布不支持？ | 否。`0x06` 读取端明确记为"未定位"，非"不存在" |
