# E22 混淆与 BSS 边界

## 重大更正

E21 将 `0xA85AD0`、`0xAAB260`、`0xAAB310` 标记为 `.tvm0`，该标注不成立。

| 地址 | 实际节区 | 磁盘可见 | 说明 |
|---|---|---|---|
| 0xA85AD0 | .data | 否 | BSS 虚拟尾部 |
| 0xA85BE0 | .data | 否 | BSS 虚拟尾部 |
| 0xA85640 | .data | 否 | BSS 虚拟尾部 |
| 0xA87830 | .data | 否 | BSS 虚拟尾部 |
| 0xA878A0 | .data | 否 | BSS 虚拟尾部 |
| 0xAAB1C0 | .data | 否 | BSS 虚拟尾部 |
| 0xAAB260 | .data | 否 | BSS 虚拟尾部 |
| 0xAAB310 | .data | 否 | BSS 虚拟尾部 |

`.data` 的 VirtualSize 为 `0x0D05C420`，RawSize 为 `0x00049600`。上述地址均在 RawSize 之外，静态文件没有对应字节。

## 边界结论

- 这些地址不属于 `.tvm0`，也不属于可反汇编的 `.text`。
- 它们可能是加载期由 BSS 初始化、重定位或运行时代码生成的函数指针目标。
- 不能使用线性反汇编解释这些地址。
- 不能把 BSS 虚拟尾部当作“磁盘代码丢失”；它本来就是未初始化零区。

## 最小缺失证据

1. 这些 BSS 地址是否在加载期被 `.rimp`、TLS 回调或初始化函数写入。
2. 写入来源是哪一个 `.text` 初始化器。
3. 若为运行时代码生成，需要观察加载后的内存布局（本轮禁止）。

在获得上述证据前，`0xA85AD0` 及同区地址一律视为 `BLOCKED`。
