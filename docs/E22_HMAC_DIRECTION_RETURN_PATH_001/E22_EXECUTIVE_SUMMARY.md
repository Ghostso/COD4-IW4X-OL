# E22 执行摘要

## 一句话结论

定向分析表明：`0x6AAE70` 是入站侧的 **HMAC/会话计数器校验路径** 的强推断，但 `0x6AC0C0` 的调用栈属于发送/接收共用的 Demonware 会话泵；本轮不能把任一方向单独升级为 `PROVEN`。

## 关键事实

1. `0x6AC0C0` 是 `thiscall`，返回 `bool`，栈参数为两个输出指针：
   - `[ebp+8]`：输出状态字节
   - `[ebp+0xC]`：输出对象指针
2. `0x6AC0C0` 的直接调用者是 `0x6AC3D0`，后者只是 `jmp 0x6AC0C0` 的跳板。
3. `0x6AC3D0` 的直接调用者是 `0x68EEF1` 和 `0x68F02C`，位于一个会话处理循环中。
4. `0x6AAE70` 的唯一调用点是 `0x6AC2F0`，调用约定为 `thiscall` + 5 个栈参数，`ret 0x14`。
5. 调用 `0x6AAE70` 前，`[ebp-0x14]` 是从入站缓冲解析出的消息码，`0x84` 走 `0xAA9690`，`0x85` 进入 `0x6AAE70`。
6. `0x6AAE70` 内部：
   - 读取 `[edi+0xAC]` 帧长和 `[edi+0xB0]` 缓冲对象；
   - 读取 `[edi+0x5D0]` 接收计数器，递增后与消息携带值比较；
   - 使用 16 字节比较循环，失败时设为 `HMAC mismatch`；
   - 计数器不匹配时设为 `Bad recv counter`；
   - 失败路径调用 `0x43A7C0`（日志）和 `0xAAA770`（置连接状态 4）。
7. `0xA85AD0` 不是 `.tvm0`：它位于 `.data` BSS 虚拟尾部，磁盘无字节，静态不可反汇编；E21 的 `.tvm0` 标注在这里被更正。

## 方向判定

| 假设 | 结论 |
|---|---|
| H1 入站 HMAC 验证 | **INFERRED（强）**：入站帧码 0x85、接收计数器、HMAC mismatch |
| H2 出站 HMAC 签名 | 弱支持：0x6AC0C0 属于会话泵，不能排除发送前签名 |
| H3 收发共用会话/计数器管理 | **INFERRED（强）**：计数器和连接状态在共用对象上 |
| H4 其他用途或证据不足 | 不能排除 |

## 阻塞项

`0xA85AD0`、`0xA85640`、`0xA85BE0` 位于 `.data` BSS，磁盘无字节；`0xA87830`/`0xA878A0` 同样不可静态反汇编。方向不能提升为 `PROVEN`，最小缺失证据是这些 BSS 函数的运行时入口或加载期初始化来源。
