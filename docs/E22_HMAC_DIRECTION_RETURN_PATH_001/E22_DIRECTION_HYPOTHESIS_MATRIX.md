# E22 方向假设矩阵

| 假设 | 支持证据 | 反证/未覆盖 | 置信等级 |
|---|---|---|---|
| H1 入站 HMAC 验证 | 0x6AAE70 由入站帧码 0x85 路径调用；读取 recv counter；16 字节比较；HMAC mismatch；失败置状态 4 | 0x6AC0C0 是共享会话泵；0xA85AD0 在 BSS 不可见 | INFERRED（强） |
| H2 出站 HMAC 签名 | 0x6AC0C0 有发送/连接状态逻辑；成功路径使用 0x5F4 虚表调用 | 没有直接证据显示 0x6AAE70 对发送缓冲做签名；计数器语义偏向接收 | WEAK_INFERENCE |
| H3 收发共用会话/计数器管理 | 同一对象字段 0xC8/0xAC/0xB0/0x5CC/0x5D0 被同一函数读写；失败统一转状态 4 | 无法区分每个消息码属于入站还是出站 | INFERRED（强） |
| H4 其他用途或证据不足 | BSS 目标、间接虚表调用未解析 | 无 | BLOCKED |

## 详细说明

### H1 入站验证

支持：
- `0x6AAE70` 读取 `[edi+0x5D0]` 并递增，属于 recv counter。
- 字符串 `Bad recv counter` 在计数失败时设置。
- 字符串 `HMAC mismatch` 在 16 字节比较失败时设置。
- 失败路径置连接状态 4，符合认证失败断开。

未覆盖：
- 无直接调用 `recv`，因此“入站”来自帧码/计数器语义推断，不是调用边证明。

### H2 出站签名

支持：
- `0x6AC0C0` 的调用链位于 Demonware 会话泵，可能包含发送。
- 成功路径调用 `[edi+0x5F4]` 虚表方法，可能是输出处理。

未覆盖：
- 没有证据表明 `0x6AAE70` 写入发送缓冲或调用 send。
- `HMAC calculation` 更接近验证前计算，而非签名输出。

### H3 共用

支持：
- 同一 `this` 对象维护连接状态、帧长、载荷对象和计数器。
- 多个消息码（0x81/0x83/0x84/0x85）走同一分派器。

裁定：H1 与 H3 均为 `INFERRED（强）`；H2 为 `WEAK_INFERENCE`；H4 为 `BLOCKED`。不得将任一方向单独标为 `PROVEN`。
