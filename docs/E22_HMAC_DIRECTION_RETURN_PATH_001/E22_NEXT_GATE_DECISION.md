# E22 下一门禁决策

## 决策

维持 **CONDITIONAL GO**，但停止沿 `0xA85AD0` 的静态线性扩展。

## 已获收益

1. 精确恢复 `0x6AC0C0` 调用约定与两个输出参数。
2. 精确定位 `0x6AAE70` 唯一调用点 `0x6AC2F0` 和 `ret 0x14` 五参数约定。
3. 证明 HMAC 路径与接收计数器 `+0x5D0`、连接状态 `+0xC8`、消息码 `+0x5CC` 直接相关。
4. 纠正 E21 的 `.tvm0` 定位错误：相关目标实际在 `.data` BSS。

## 停止条件已触发

`0xA85AD0`、`0xA85BE0`、`0xA85640`、`0xA87830`、`0xA878A0` 均在 `.data` RawSize 之外，磁盘无字节，无法静态反汇编。继续沿该地址扩展会变成无证据猜测。

## 下一步唯一建议

转向**可静态闭合的另一条证据缺口**：定位并分析 `.data` 初始化器/TLS 回调/`.rimp` 写入者，查清这些 BSS 地址在加载期是否被初始化；若不能确认，则保留 `BLOCKED` 并结束 HMAC 对象的静态追踪。

不建议：
- 全客户端扩展扫描；
- 将 BSS 虚拟尾部当作丢失代码；
- 在没有方向证据时实现服务器端 HMAC 编码。
