# 10 — mmstart 与战斗服交接边界

> 任务书要求：本任务不研究战斗服内部，但**交接边界**必须证明。

---

## 1. mmstart 是什么

| 项 | 值 |
|---|---|
| 通道 | `6/14`（文本） |
| 方向 | **客户端 → 服务端** |
| 作用 | 客户端对服务端下的**开局指令** |
| 服务端应答 | 10-26：**空应答**；10-28 起：额外推 `dwRoomMessageStartGame`(109 B) |

**注意方向**：mmstart 是**客户端发出的指令**，不是服务端下发的开局通知。

---

## 2. 两种形态

### 2.1 路径 A（PvE，唯一成功形态）

```
mmstart sv_resetServer; 2486 0; 3265 18; 2489 0; 2574 0; 2500 0;
        g_gametype coop;  g_difficulty 1; ;
        map coop_train_mp_firingrange;2654 ; roomChatChannelID 0;
```

### 2.2 路径 B（房间，从未成功）

```
mmstart sv_resetServer; 2486 1; 3265 6; 2489 1; 2574 2;
        playlist 37; start_map_rotate_once 4; roomChatChannelID 1234605616436508552;
```

### 2.3 字段差异表

| 字段 | 路径 A | 路径 B | 说明 |
|---|---|---|---|
| `map <name>` | **有** | **无** | 最关键差异 |
| `g_gametype <name>` | **有** | **无** | — |
| `g_difficulty <n>` | 有（1） | 无 | — |
| `playlist <n>` | 无 | **有**（37） | — |
| `start_map_rotate_once <n>` | 无 | **有**（4/7） | — |
| `roomChatChannelID` | `0` | `roomId` | = 是否在房间里 |
| `2486` | `0` | `1` | 语义 UNKNOWN |
| `3265` | `18` | `1` / `6` | 语义 UNKNOWN |
| `2489` | `0` | `0` / `1` | 语义 UNKNOWN |
| `2574` | `0` | `0` / `2` | 语义 UNKNOWN |
| `2500` | `0` | `0` | 语义 UNKNOWN |
| `2654` | 空 | `M7-E8S6Client` | 客户端实例名 |

**`2486/3265/2489/2574/2500/2654` 这 6 个编号键的语义全部 UNKNOWN。**

## 3. 交接边界：客户端在哪一刻决定连战斗服

### 3.1 已证明的部分

| 事实 | 证据 |
|---|---|
| 地址在 `21/5` 应答里就给到客户端 | 280 B 对象含 67 B 地址块；成功/失败轮对象都是 280 B |
| `mmstart` 之后客户端才发包 | 10-26：mmstart @22:09:15，战斗服 `TX_NAT_REPLY` 紧随其后 |
| `mmstart` 之后**不一定**发包 | 路径 B 全部零 RX |

### 3.2 第一条未闭合边

```
[客户端解析 mmstart 的服务端应答]
        ↓
[客户端创建 UDP socket 指向 67 B 地址块里的 IP:port]
        ★★★ 这就是断点
```

- **入站部分**已证：客户端确实把 mmstart 发出来了（服务端收到了）。
- **出站部分**未证：为什么有的 mmstart 之后建 socket、有的不建。

### 3.3 关键反证：服务端在 mmstart 后的行为不影响结果

| kit | mmstart 后做什么 | 结果 |
|---|---|---|
| 10-26（78 KB） | **什么都不做**（空应答） | ✅ 连上 |
| 10-27（88 KB） | 什么都不做 | ❌ 未连 |
| 10-28+ | 额外推 StartGame(109 B) | ❌ 未连 |

⇒ **"服务端推不推 StartGame" 与 "客户端连不连" 无关**（至少不是充分条件）。

## 4. 交接边界的候选解释

| # | 解释 | 支持 | 反对 | 状态 |
|---|---|---|---|---|
| H1 | mmstart 缺 `map` ⇒ 客户端不知道去哪张图 ⇒ 不连 | 唯一成功的八轮都带 map；失败的都带 playlist | 路径 B 的 mmstart 也确实发出了，说明客户端认为命令完整 | **高可信（相关）** |
| H2 | 在房间里（`roomChatChannelID ≠ 0`）⇒ 客户端走"等房间开始"分支 | 成功轮 `roomChatChannelID 0` | 无法分离（与 H1 共线） | **高可信（相关）** |
| H3 | `mmstart` 之后的 StartGame 推送让客户端等错了东西 | 10-28 加了推送后更差 | 10-27 没推也没连 | 低 |
| H4 | 客户端在 mmstart 里解析 `3265` 等编号，值不同导致分支不同 | 数值确实不同（18 vs 1/6） | 语义未知 | UNKNOWN |

**H1 与 H2 在历史数据里 100% 共线，无法分离。**

## 5. 要做一次什么实验才能分清

| 实验 | 做法 | 判据 |
|---|---|---|
| **E2** | PvE 入口 + `coop_map.txt` 换成非 firingrange 的图 | 若零 RX ⇒ 地图是根因（H1） |
| **E3** | 房间入口 + 让 mmstart 带 `map <图>` | 若仍零 RX ⇒ 房间路径本身是根因（H2） |
| **E3'** | 房间入口 + `roomChatChannelID` 仍为 roomId 但 mmstart 补上 map | 区分"在房间" vs "缺 map" |

## 6. 结论

| 问题 | 答案 |
|---|---|
| mmstart 是什么 | 客户端发给服务端的**开局指令**（文本，6/14） |
| 地址在哪一步给 | **`21/5 findSessions` 的应答对象里**，早于 mmbook/mmstart |
| 交接边界断在哪 | 「客户端解析 mmstart 应答 → 创建 UDP socket」 |
| 服务端该做什么 | **10-26 的成功轮证明：什么都不做也能连上** |
| 未闭合的证据链 | 为什么同样的 mmstart 指令，路径 A 连、路径 B 不连 |
