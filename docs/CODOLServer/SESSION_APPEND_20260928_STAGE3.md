# 第一档推进：步骤③前置条件与两次否证（2026-09-28 深夜）

承接 `HANDOFF_20260928_LOBBY_PROTOCOL.md`。本文件只记录新增的实测结论，
不重复手册第 3 节已确证的部分。

## 1. 新增确证（可直接依赖）

### 1.1 `[req+0x5FC]` 的来源已定死

唯一写入点是 `0xBA1F3C`：

```asm
BA1EF2  call 0xBA13D0      ; 生成 8 字节凭据（模板 0xD5A4E8）
BA1F24  call 0xB78350      ; 同样 8 字节写进正在发出的帧
BA1F3C  mov [ebx+0x5FC], edx   ; 并存到 this+0x5FC
BA1F42  mov [ebx+0x600], eax
```

即：**这 8 字节由客户端自己生成**，先存 `this+0x5FC`，再写进它发出的帧。
服务端既无法预测也无法构造，只能在收到客户端帧后原样回显。

### 1.2 `0x83` 回显值的准确位置

对比两份独立的客户端 `0x82` 帧（`ok_20260928_214622`、`tk_20260928_215148`，
均 153 字节）：

```text
offset   0..143  : 逐字节完全相同
offset 144..151  : 8 字节不同          <- 就是 this+0x5FC 的凭据
offset 152       : 1 字节不同（尾）
```

**因此 `0x83` 的回显值 = 客户端 `0x82` 帧末 9 字节的前 8 字节。**
（此前“取 body 前 8 字节”的假设已否证。）

### 1.3 状态机 `9C` 闸门全貌（`0xBA41D0`）

```text
9C=0 -> 初始化，置 9C=1
9C=1 -> 调 0xBA3FB0 读 4 字节长度前缀
9C=2 -> 调 0xBA20A0 收完整帧，成功后置 9C=3
9C=3 -> 取结果对象，成功后置 9C=4
9C=4 -> 0xBA4440 才读 opcode 并调用 0x81/0x83/0x85 处理器
```

`0xBA3FB0` 的长度校验：

```asm
BA401C  [req+0xAC] = u32 长度
BA403D  cmp [req+0xAC], [req+0x98]
BA4043  ja  -> 报错 0x11 并 0xBA3420 中止
```

### 1.4 `0x81` 处理器的读入顺序（`0xBA3C70`）

```text
BA3CBC  u32  -> 魔数，必须 ∈ [0xD2,0xDC]
BA3CEB  u64  -> [this+0x638] / [this+0x63C]
BA3D25  8 字节（0xB78430，仅推进游标）
BA3D83  0xBA1850 组回帧 -> 0xBA2F20 入队 -> [req+0x5E8] = 2
```

## 2. 两次否证（不要再走）

### 2.1 否证：直接把 `[req+0x5E8]` 改成 2 就能验证 0x83

观察到 `5E8` 与 `9C` 都满足条件、同步机制成功送达 `0x81` 帧（204 字节，
`c8 00 00 00 | 00 | 81 | d2 00 00 00 | 8877665544332211`，缓冲区原文可见），
但：

```text
638/63C 从未被写入  ->  0xBA3C70 根本没有执行
C8=4, 5E8=0         ->  走失败清理路径
```

结论：`5E8` 不是唯一前置条件；缺 `this+0x5FC` 时即便发 `0x83` 也必然
`memcmp` 失败。

### 2.2 否证：强行写 `[req+0x9C]=4` 可以跳过收帧

实测把 `9C` 写成 4（`s9c=1 -> 4`，`ok=True`）后：

```text
37.28 .. 38.17  持续 C8=2 / 9C=4
b0 = 0          读入器从未建立
b4 = 0          结果对象从未建立
探针在发送 0x81 后直接 conn_error
```

客户端此后不再推进收发，进入人为造成的静默死状态，`DW_LOBBY_CONNECTED`
也不再出现。**该写入不是有效绕过手段，已废弃。**

## 4. 仍未闭合的一步

`0xBA20A0` 完成收帧、建立 `b0`（读入器）与 `b4`（结果对象）的过程，
仍未能被观测到。20 ms 采样始终错过该窗口，与手册第 5 节结论一致。

下一步应继续用 `CODEC_TRANSITION` 通道，在 `b0` 从 0 变为非 0 的瞬间
整块落盘（而不是只采样），以确认读者缓冲区的真实写入过程。
