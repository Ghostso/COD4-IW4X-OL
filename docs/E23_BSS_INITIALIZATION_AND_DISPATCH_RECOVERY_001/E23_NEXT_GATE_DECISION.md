# E23 下一门禁决策

## 1. 决策

**维持 CONDITIONAL GO**，并**解除** E-22 对五个目标施加的"BSS 不可静态分析"停止条件；证据缺口从"五个未知目标"收敛为"一个已定位对象 + 其调用时机"。

## 2. 本轮获得的确定性收益

1. **基准纠正（决定性）**：五个目标为 `.text` 函数（VA→RVA），不是 `.data` BSS。E-22 的停止条件建立在错误的地址基准上。
2. **调用关系闭合**：354 个直接调用点（边界对齐验证通过），无间接/表项引用。
3. **函数语义恢复**：
   - `0xA878A0`/`0xA87830`：Range/Advance + `memcpy`（含日志 `0x43A7C0`）。
   - `0xA85BE0`（`ret 4`）/`0xA85640`（`ret 8`）：thiscall 字段分派至 `.tvm0` 入口 `0xDF6F97C`。
   - `0xA85AD0`：`0xA878A0` 的簿记封装。
4. **`[edi+0x5F4]` 闭合**：写入者 `0x6AB9B3`/`0x6AB9E7`；构造器 `0xA87BA0`（vtable `0xC5A31C`）；成功路径 slot+3 = `0xA87D50`，参数 `(this, buf, buf, len)`。
5. **负向机制排除**：TLS 回调为空、`.rimp` 0 命中、无向五地址的写入。

## 3. 已解除的停止条件

| E-22 停止条件 | 现状 |
|---|---|
| "五地址在 .data RawSize 之外，无法静态反汇编" | **解除**：它们可反汇编，已反汇编 |
| "需要运行时入口或加载期初始化来源" | **解除**：非数据目标，无需初始化 |
| "不能把 BSS 虚拟尾部当作丢失代码" | 保留（该原则本身正确），但**不适用于本五地址** |

## 4. 剩余最小缺失证据

1. **`[edi+0x5F4]` 协商对象何时被创建**：需定位 `0x6AB9D8` 所在函数（起点 `0x6AB310`）的调用者。当前 rel32 搜索得 0 —— 说明它可能经跳板/间接调用，需解析跳板（如 `0x6AC3D0` 形态）或 vtable 分派。
2. **`0xA87D50` slot+3 的缓冲参数与握手阶段映射**。
3. **消息码 0x81/0x83/0x84/0x85 的方向绑定**（入/出站）。

## 5. 下一步唯一建议

**解析 `0x6AB310`（含 `0x6AB9D8` 调用）的入口路径**：先用全 `.text` 定位所有 `E9` 跳转到 `0x6AB310` 的跳板、以及可能承载其函数指针的 vtable 槽，从而确定 `[edi+0x5F4]` 对象的创建时机与触发条件。这是唯一能在静态范围内把"对象已识别"推进到"对象何时/为谁创建"的边界。

不建议：
- 以 VA/RVA 混用为前提继续任何寻址；
- 把五个 `.text` 辅助函数继续当作 BSS 目标追踪；
- 在方向未闭合时实现服务器端 HMAC 编码；
- 全客户端无边界扫描。
