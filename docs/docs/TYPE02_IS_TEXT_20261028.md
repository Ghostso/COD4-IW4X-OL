# type 0x02 假设已否掉（2026-10-28 第十三轮）

## 一、结论

**`type 0x02` 不是"通用消息分发"，它是 `dwRoomMessageText`（文本/聊天）。**
"服务端推消息要用 0x02 包装"这个假设**不成立**。

## 二、证据链

### 1. `0x02` 的 handler 构造的是 Text 对象

`0x63495A` 里 `call 0x625940`，后者实测：

```asm
00625946  mov dword ptr [esi], 0x00DC7BE0   ; dwRoomMessage 基类 vtable
0062595E  mov dword ptr [esi], 0x00DC7504   ; ★ dwRoomMessageText vtable
00625964  call 0x625A20                     ; dwRoomMessageText::deserialize
```

RTTI 清单确认：
- `0x00DC7BE0` = `?AVdwRoomMessage@@`
- `0x00DC7504` = `?AVdwRoomMessageText@@`（vfuncs = `0x625970` serialize / `0x625A20` deserialize）

### 2. handler 的其余动作是"文本消息投递"

```asm
00634962  lea edx,[ebx+0x10798]    ; 房间对象内的成员容器
00634969  call 0x4A3AF0            ; 遍历查匹配（0x4A3AF0 实测：计数+数组比较）
0063499A  cmp dword ptr [0x76446B0], 0xA   ; 全局状态 == 10 ?
006349AD  call 0x62BBF0 / call 0x62BAD0    ; 两个分支，都在动 [0x84ABB08] 玩家对象
```

⇒ 典型的"把一条文本消息投递给房间成员"。

### 3. 上行 body 不经 `0x634870` 的位流读取

`0x634870` 入口：

```asm
006348AA  push 3;  call readBits   ; 5 位必须 == 3
006348C2  push 8;  call readData   ; type
006348D8  mov esi,[eax*4+0x82E1458]
006348E7  je 0x63494A              ; 表项为 0 -> 跳转表
0063494A  cmp eax,0x2e
00634953  jmp [eax*4+0x636F3C]
```

对客户端真实上行 body 逐位验证（`tools/walk_client_body.py`）：

| 样本 | bit0 处 readBits | bit8 处 | bit13 处 |
|---|---|---|---|
| 16B `0202...` | 2 | 2 | 0 |
| 12B `0202...` | 2 | 2 | 0 |
| 26B `0204...` | 2 | 4 | 0 |
| 59B `0206...` | 2 | 6 | 0 |
| 17B `181c...` | 24 | 28 | 16 |

**没有任何一个偏移能读出 `readBits == 3`。**
⇒ 上行 body **不经过**这条位流读取路径。

### 4. 前置拦截表 0x82E1458 在四个快照里全空

```
snap_001 (29.2s)  非零 0 / 47
snap_002 (60.9s)  非零 0 / 47
snap_003 (89.3s)  非零 0 / 47    ← createRoom 之后
snap_004 (118.3s) 非零 0 / 47
```

⇒ 它要么不是注册表，要么寻址方式与我理解的不同。**该假设作废，不当依据。**

## 三、排除掉的路线汇总

| 假设 | 状态 |
|---|---|
| type 0x02 = 通用分发，服务端推消息要用它包装 | **否**（是 Text） |
| 上行 body 走 `0x634870` 位流读取 | **否**（穷举偏移，无 tag==3） |
| 0x82E1458 是 type→处理器注册表 | **否**（四快照全空） |
| 上行 body 是 protobuf | **否**（field number 全 0，tag 误读） |
| 上行 body 是 Demonware 位流 | **否**（前 5 位恒为 2） |
| 下行 body 是上行那种容器 | **否**（下行由 deserialize 读位流） |

## 四、仍成立的部分

- 下行 body = `writeBits(3)` + `writeData(type,8)` + 字段（已按此重编，离线对拍全过）
- 下行 L2 **无** `<u32 len-4>` 前缀（`0x637000` 的 `0xB779A0` 直接按 `(ptr, len*8)` 建流）
- 外层信封 = `instant_push_body(kind=11)`（与客户端缓冲区共同前缀 23 字节）
- 上一轮实机出现可观测差异（任务数 85→71、`11/4` 6→4 次）

## 五、未解释

- 客户端上行 body 的确切编码仍未知（`02 <sub> 00 00 00 <u32 len> <payload>`）
- 战斗服零收包是独立问题，与房间消息格式无关
