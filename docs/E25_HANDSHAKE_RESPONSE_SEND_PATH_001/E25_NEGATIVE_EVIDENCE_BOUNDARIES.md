# E25 负向证据与边界

> 纪律：静态搜索未命中 ≠ 全局不存在。每条注明范围与未覆盖区域。

## 1. 已执行的否定搜索

| # | 搜索 | 范围 | 结果 | 边界声明 |
|---|---|---|---|---|
| N1 | `send`/`sendto` IAT 引用 | 会话区间 `0x6A9000..0x6AD000` | **0 命中** | 覆盖该窗口全部反汇编指令 |
| N2 | 转向发送包装器（`0x775A22/0x775AA4/0x6028F0/0x6B4C94`）的 rel32 | 会话区间 | **0 命中** | 说明会话对象不直接调 socket 包装 |
| N3 | `0x6AA230` 内的 send/sendto 引用 | 函数体 0x100 字节 | **0 命中** | 反证"`0x6AA230` 即发送函数" |
| N4 | `0x6AA230` 全部静态调用者 | 全 `.text` E8 扫描 | **2 处**（`0x6AA465`、`0x6ABAFC`） | 无其他入口 |
| N5 | 入队 `0x0DF806F2` 的全部调用者 | 全章节 E8 扫描 | **2 处**（`0x6AA2D0`、`0x6AADE6`） | 队列有两个生产点 |
| N6 | `0x783B50`（send 包装）的调用者 | 全 `.text` E8 扫描 | **3 处**（`0x6A9B6E`、`0x6AA88D`、`0x6B3343`） | 已覆盖；其中 `0x6AA88D` 属本论 |
| N7 | `0x784E40`（→send）的调用者 | 全 `.text` E8 扫描 | **1 处**（`0x783B5E`） | 唯一入口 |
| N8 | `[+0xB8]` 写点 | 会话区间反汇编 | 初始化 `0x6AA613`、入队 `0x6AA2D0`（经 `lea`）、出队 `0x6AA8DF` | 未覆盖 `mov [reg+0xB8],[reg]` 的间接写 |

## 2. 未覆盖区域（盲区）

1. **`.data` BSS 运行时布局**：`0x6A9xxx` 段依赖的 BSS 容器/统计字段（含 `+0x508` 环形缓冲之外的运行时表）磁盘无字节，静态不可解析。
2. **`.tvm0` 内部**：`0x0DF9AA45`（分配）、`0x0DF806F2`（入队）、`0x0DF37227`（释放）、`0x0DF16878`（状态）仅确认调用形态与参数，未逐指令解码其内部实现。
3. **`[esi+0x628]` 传输对象的 slot0**：`0x6AA7C6 call edx` 的目标由运行时 vtable 决定，静态不可得。
4. **线上载荷逐字节一致性**：未比对 `[ebx+0xC]` 内容与 `send` 第二参数实际字节（需运行时）。
5. **`0x6B3343` 与 `0x6A9B6E`**：另两条使用 `0x783B50` 的路径未展开。

## 3. 反证记录

| 主张 | 裁定 |
|---|---|
| "`0x6AA230` 是发送函数" | **REFUTED**：函数体内无 send/sendto；其职责为克隆入队 |
| "该队列为握手应答专用" | **REFUTED**：`0x6AAA320`（阶段 1 建立）同样入队 |
| "E-24 的 `[edi+0x5F4]` 是应答数据的接收者" | **更正**：应答数据进 `[edi+0xB8]` 队列；`[edi+0x5F4]` 只在 `0x6AAE70`（0x85）被使用 |
| "E-24 建议的『应答→socket』边不确定" | **已证实**：`0x6AA88D → 0x783B50 → 0x784E40 → ws2_32!send` |

## 4. 不得用作补足的方式

- 不得因 `0x784E40` 与 `0x775A22` 都调用 `ws2_32!send` 就断言二者等价（前者参数 `(fd,buf,len)`，后者 `(this,buf,len)` 且经不同对象）。
- 不得把"数据到达 send"表述为"协议握手已验证通过"。
- 不得把认知完备率与实时互操作混为一谈。
