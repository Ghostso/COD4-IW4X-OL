# E25 下一门禁决策

## 1. 决策

**维持 CONDITIONAL GO**。本轮首次把"握手应答数据 → 网络发送 API"的静态链路完整闭合（五层全 PROVEN），但**仍无端到端运行证据**，实时互操作继续为 `NOT-OBSERVED`。

## 2. 本轮获得的确定性收益

1. **发送链闭合（决定性）**：`0x6ABAFC`(入队) → `0x6AA7B0`(泵) → `0x6AA88D`(递交) → `0x783B50`(send 包装) → `0x784E40`(IF 包装) → `ws2_32!send`，逐跳有指令地址与参数传播证据。
2. **职责澄清**：`0x6AA230` 是"克隆 + 入队 + 驱动泵"，**不是**发送函数；发送在泵内完成。
3. **队列模型**：`[+0xB8]` 为侵入式链表头，节点 0x1C 字节，`[+0xC0]` 计数，构造器零初始化，泵按 `[+0xC8]==2` 循环消费。
4. **套接字来源**：`socket(AF_INET,SOCK_STREAM,IPPROTO_TCP)`（`0xB84950`）→ `[+0xC4]` 持有者 → `closesocket`（`0xB84B00`）。
5. **时序**：组装 → 入队 → 写 `[+0x5CC]` → 下一次泵驱动时发送。

## 3. 停止条件核对（任务书 §7）

| 停止条件 | 状态 |
|---|---|
| "数据流到达明确发送接口" | **已触发** → 已闭合 `0x783B50 → ws2_32!send` 的数据指针与长度来源 |
| "只到达发送队列" | 不适用（已越过队列到 API） |
| "`0x6AA230` 只是本地处理函数" | **部分适用** → 已如实记录其非发送职责 |
| "间接分派阻塞" | 见 §4 剩余项 |

## 4. 剩余最小缺失证据

1. **`send` 第二参数（缓冲）与 `0x6AB310` 组装缓冲的逐字节一致性**：需运行时内存（本轮冻结约束禁止）。
2. **`[+0x628]` 传输对象的 slot0 目标**：运行时 vtable。
3. **线上帧的协议字段序**：序列化器 `0xDAB40` 与 `0xDF6F97C` 的字段布局未逐字段解码。
4. **服务器端对等实现**：本论仅客户端侧；服务端 `codol_dedrun.exe` 未作对等分析。

## 5. 下一步唯一建议

**转向服务器端对等分析**：在服务端镜像（`80816711…`）中定位与 `0x6AB310`/`0x6AA230` 对应的接收/发送对等实现，确认服务端是否以相同标签（`CLIENTCHAL`/`BDDATA`）与相同消息码（`0x81..0x85`）应答。这是唯一能把"客户端单侧静态链路"推进到"双侧协议对应"的边界；若服务端存在对应实现，则首次具备端到端静态证据的候选；否则应记录服务端缺口并停止。

不建议：
- 在无运行时证据时断言"握手可通过"；
- 把认知完备率当作互通完成率；
- 全客户端无边界扫描。
