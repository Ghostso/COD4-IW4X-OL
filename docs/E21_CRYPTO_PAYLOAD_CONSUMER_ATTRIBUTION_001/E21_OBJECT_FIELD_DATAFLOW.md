# E21 对象字段数据流

## 对象构造器

`0x6A84E0` 构造对象并写 vtable VA `0xC5B0A4`。构造函数接收参数：
- `[ebp+8]`：长度或容量参数
- `[ebp+0xC]`：标志/模式字节

对象字段在构造器中的初始化：

| 偏移 | 写入 | 证据 |
|---|---|---|
| +0x00 | vtable 0xC5B0A4 | 0x6A8545 |
| +0x04 | 0 | 0x6A8511 |
| +0x08 | 0 | 0x6A8517 |
| +0x0C | 0 | 0x6A851A |
| +0x18 | 参数 [ebp+0xC] | 0x6A851D |
| +0x19 | 参数 [ebp+0xC] | 0x6A8520 |
| +0x1A | 0 | 0x6A8523 |
| +0x10/+0x14/+0x1C/+0x20/+0x24/+0x28 | 0 | 0x6A8526..0x6A8535 |

构造函数随后调用 `0x6A8370`。该函数分配/保存内部缓冲区，是对象字段填充的关键调用边。

## 第二个对象

`0x6A9720` 接收三个参数：对象指针、长度、类型字节。它写 vtable VA `0xC5B0E0`，保存引用计数和长度，并在 `0x6A9810` 读取参数对象的 `+0x0C` 字段。`0x6A9720` 的静态调用者：
- `0x6A9920`（E-19 状态 2 处理器）
- `0x6AAA10`（第二调用者，待展开）

## 所有权与释放

`0x6ABE99` 状态 0 reset 路径释放 `[esi+0xB0]` 和 `[esi+0xB4]`，使用 `operator delete` 和虚析构。`0x6A9920` 在替换旧对象前也执行相同释放逻辑。因此对象所有权明确属于 `this` 会话对象，而不是全局单例。

## 数据流结论

对象字段填充和释放路径可证；HMAC 校验/加密的具体读写语义因下游 `.tvm0` 边界未闭合，标记 `BLOCKED`。
