# E21 下一门禁决策

## 决策

维持独立 Demonware/加密协议边界，停止对该对象的无边界扩展。

## 理由

1. 已证对象构造、vtable 布局、字段初始化、释放路径。
2. 已证 HMAC 四个错误字符串由 `0x6AAE70` 直接引用。
3. 已证该对象与 `0x6ABBC0/0x6ABE80` Demonware 状态机直接相连。
4. 未找到通向任何 CODOL 实时游戏解析候选的直接/静态调用边。
5. 下游关键函数 `0xA85AD0`、`0xAAB260`、`0xAAB310` 位于 .tvm0/VM 混淆边界，线性反汇编不可靠。

## 继续条件（唯一推荐）

只有获得 `.tvm0` 的指令级解码或 `0x6AC0C0` 中 `0xA85AD0` 调用的参数/返回语义，才值得继续该对象；否则应转向其他证据缺口。

## 最小新增证据

- `0x6AAE70` 调用的 `0x6878A0`、`0x6A8BF0`、`0xA85AD0` 的准确参数与返回语义。
- `0x6AC0C0` 的 `[esi+0x5CC]` 分支是入站验签、出站签名还是双向会话管理。
- vtable 槽位 1–4 的运行时目标来源。
