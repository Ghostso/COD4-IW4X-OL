### 3.1 为什么撤回 044 的补充证据请求

044 认为"BE-01 需覆盖 `RVA 0x0CA8400..0x0CA8700` 的只读快照"。045 证明该范围**已在本机 S-IMG 内**,

### 3.2 为什么是"继续静态调查"而非"进入下一阶段交叉验证"

- 六方矩阵已**启动**(交付),但仅达**原语级**可比;业务级证据缺位。
- 在"客户端是否真正消费 gamestate/configstring/snapshot/opcode"闭合前,任何跨项目协议结论都只能停在 `ARCHITECTURAL_ANALOGY`/`NAME_ONLY`。
- 强行进入实现阶段会以服务端假设填补客户端空缺 → 违反任务纪律。

### 3.3 为什么不是"申请最小补充证据"

- A-01 已关闭;A-02/A-09 的剩余缺口的**根因不是镜像缺失**,而是**尚未在已覆盖的 `.text` 内完成语义归类**。
- 其余 A 类(gamestate/configstrings/snapshot/opcode)的下一步是**静态定位客户端消费点**,不是取新样本。
- 唯一仍可能**真的需要新样本**的是 A-07(样本身份 `E3823FD6`),属**工程裁决**而非取证,除非工程方判定必须比对 QA 3.3.3.3 构建。

## 6. 勘误记录(编号 045-C*,不改写 040–044 历史交付物)

### 045-C1(高). 040–044 的读 API 槽"超出 EOF"结论 → **推翻**

- **040/041/043/044 原文:**"读 API IAT 槽 `0x0CA84E8` 落在镜像未覆盖节区","file 0xA65000 < RVA 0xCA84E8"。
- **045 实测:**`0x0CA84E8` 是**绝对 VA**;`RVA = 0x8A84E8 < 0xA65000` → **在文件内**。
- **证据:**`evidence/a01_identity.txt`、`b11_slotresolve.txt`、`c02_iat_link.txt`、`c04_resolve.txt`。
- **影响:** A-01/BE-01 关闭;BE-02/BE-04 根因消失。

### 045-C2(高). 044 "`0x87BE00` 更像 ReadFile/重叠读" → **推翻**

- **044 原文(C4):**"更像 `ReadFile`/`ReadFileEx` 类重叠读";支持证据:除 1000 魔数压入 `OVERLAPPED`、失败码属 Win32 等待错误族。
- **045 实测:**同魔数构造的是 `select` 的 `struct timeval`;失败码 `0x2714/0x2733` 是 `WSAEINTR`/`WSAEWOULDBLOCK`,
  且前置指令 `call [0xCA853C]` = `WSAGetLastError`。**该原语是 `select`+`recv`,不是文件读。**
- **证据:**`02 §2-§3`;`evidence/t01_select_recv_proof.txt`、`z01_identity_and_pe.txt`。

### 045-C3(中). 042 的 TQOS `0x85E6F0` 是"唯一可复核调用者"表述 → **收窄**

- **042/043 原文:**net-buffer 解码器的唯一可复核调用者为 TQOS。
- **045 实测:**`0x87D5A0` 的 E8 调用者为 `{0x85D3DB,0x85D418,0x85D9B5,0x85D9F7}`;其中 `0x85D9B5/0x85D9F7` 位于
  **已闭合的接收链**内,与 TQOS 的 `0x85D3DB/0x85D418` **并列**,并非"唯一 TQOS"。
- **证据:**`evidence/m01_callers.txt`、`q01_receive_to_decode.txt`。

### 045-C4(低). 043/044 的"运行期全局不可解析"表述

- 部分运行期全局(如 `/GS` cookie `0x0E3F240` → RVA `0xA3F240`)在文件内**可读**(值 `0xA430C027`)。
- "不可解析"只对**超出文件长**的少数地址成立;不应表述为整类不可解析。
