```
◆ CC-1 (WEAK)

 │    └─ ✗ 未找到：EV-C-2697-Dispatch-Blocked
 │       （E8/E9 0 命中、VA 指针 0 命中、RVA 指针 0 命中、跳转表 0 命中）
```

## 6. 关键路径：哪条依赖一旦满足，收益最大？

```
✗ ○ 运行时解包 dump（同 SHA-256）
      │ 满足后同时解除：
      ├─→ CC-8（镜像等价性）
      │      └─→ CC-1
      │      └─→ CC-5
      ├─→ CC-1（分派可见性）
      └─→ 全部客户端侧 BLOCKED 结论

✗ ○ .rimp 指针修复格式还原（纯静态）
      │ 满足后解除：
      └─→ CC-1 的"分派路径"依赖（若不依赖 VM）

✗ ○ 2697 战斗通道抓包
      │ 满足后解除：
      └─→ CC-1 的"字节样本"依赖 → 可产生真正独立黄金向量

✗ ○ 2697 注册 5 字段语义 + +0x78F4 写入者
      │ 满足后解除：
      └─→ CC-2 的 OPEN 部分 → 打开 gamestate 总线
```

**结论：** **运行时解包 dump 是单点收益最大的证据**；`.rimp` 还原是**唯一不依赖授权的**高价值静态路径。

## 7. 依赖图结论

1. **CC-1 是最脆弱的结论**（4 个未满足依赖），也是**最关键的兼容性问题**。
2. **血统类结论（CC-3/CC-4/CC-7/CC-8）依赖已满足**，可视为稳固有据。
3. **服务端侧结论普遍强于客户端侧结论**：服务端有源码/符号；客户端有包装/恢复缺口。
4. **重复引用不构成独立验证**：E1–E4 均为两个二进制的派生报告，独立来源实际只有 2 个（S-2697、C-2697/C-2697-Rec）。
5. **单点最大收益：** 同 SHA-256 客户端运行时解包 dump。
