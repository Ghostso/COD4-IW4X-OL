# 04 — 客户端/服务端字段矩阵 / CLIENT-SERVER FIELD MATRIX

> 任务约束 6：**不因字段形状相似就宣称协议兼容。**
> 等级：`DIRECT` / `CROSS` / `SHAPE-ONLY`（仅形状匹配）/ `BLOCKED`

---

## 1. 逐字段矩阵

| 字段 | 服务端写入（RVA） | 客户端读取 | 匹配判定 | 等级 |
|---|---|---|---|---|
| 外层标识 `0x04` | `WriteByte(4)` @ 0xA07F8 | **未定位** | 无法比较 | **BLOCKED** |
| `count1` | `WriteShort` @ 0xA0807（2 字节 LE） | **未定位** | 无法比较 | **BLOCKED** |
| 索引增量编码 | `WriteIndexDelta` @ 0xA0400（连续=1bit；否则 0+13bit） | **未定位** | 编码规则已在服务端闭合；客户端**未**独立证实 | **BLOCKED** |
| A1 字符串长度 | `strlen+1`，随后按字节写（0x99651） | **未定位** | 无法比较 | **BLOCKED** |
| A1 字符串数据 | `WriteData` 逐字节（含 NUL） | **未定位** | 无法比较 | **BLOCKED** |
| A2 计数 | `WriteBits(count2, 10)` @ 0xA08AD | **未定位** | 无法比较 | **BLOCKED** |
| A2 值 | `WriteBits(v, 10)` @ 0xA08A0 | **未定位** | 无法比较 | **BLOCKED** |
| A3 计数 | `WriteBits(count3, 10)` @ 0xA08BF | **未定位** | 无法比较 | **BLOCKED** |
| A3 字段 A | `WriteBits(v, 10)` @ 0xA091D | **未定位** | 无法比较 | **BLOCKED** |
| A3 字段 B | `WriteBits(v, 7)` @ 0xA0934 | **未定位** | 无法比较 | **BLOCKED** |
| A3 数量 n | `WriteBits(n, 4)` @ 0xA094B | **未定位** | 无法比较 | **BLOCKED** |
| A3 extras | `n × WriteBits(v,12)` @ 0xA0974 | **未定位** | 无法比较 | **BLOCKED** |
| 终止标识 `0x06` | `WriteByte(6)` @ 0xA0997 | **未定位** | 无法比较 | **BLOCKED** |

**这是本表最重要的结论：** 除**位序与位原语**外，**没有任何一个字段**拿到了客户端侧的独立读取证据。全部为 `BLOCKED`。

## 2. 唯一获得"两侧证据"的层：**位序与位原语**

| 项 | 服务端 | 客户端 | 判定 | 等级 |
|---|---|---|---|---|
| 位序 | LSB-first（`shl mask, (p&7)`，0x995FA） | LSB-first（`shl edx,cl`，0xA07F2） | **同构** | **DIRECT** |
| 位索引 | `byte = p>>3`，`bit = p&7` | 同 | **同构** | **DIRECT** |
| 越界处理 | 置 `msg+0x14=1` 并返回 | 客户端读取器**无**等价置错（返回 0/1） | **不同** | **DIRECT** |
| 原语复用度 | 3 个宽度包装（1/2/4B）+ WriteBits | **115 个调用者**共用 1 个 ReadBit 函数 | — | **DIRECT** |

**裁定：** **位层（bit order + 位索引）是唯一"两侧独立同构"的层**。这**不**构成字段级兼容证据，但它是字段级兼容的**必要条件**，且**已满足**。

## 3. 为什么字段级无法闭合（BLOCKED 的三重原因）

1. **客户端无符号表**（COFF 符号 0；仅 22 导出）→ 无法按名字定位 `ConfigString` 相关函数。
2. **位读取器是共享原语**（115 个调用者）→ 它被**所有**位流消息共用（gamestate、snapshot、configstring…），**不能**用它反推"哪个调用者解析 configstring"。
3. **无运行时**（任务约束 2）→ 无法观测哪条路径在 configstring 消息到达时被进入。

**替代路径（本轮已尝试，均未闭合）：**

| 尝试 | 结果 |
|---|---|
| 搜索 `cmp x,4` + `cmp x,6` 附近含位读取的函数 | 10 个候选（0x1A07E7 / 0x234040 / …）；**均为通用位流解析器**，无法区分消息类型 |
| 搜索 `movzx word ptr` + `cmp x,4` | 156 处；过于宽泛 |
| 搜索客户端 `configstring` 字符串 | 0 命中（仅 13 个 `CS_` 片段，且不足以定位） |
| 用 `.tvm0` 入口反推 | entry 对齐率 0%（E-06 结论），不可线性解码 |

## 4. 服务端侧已闭合的字段（可作为**规格**，但非兼容性证明）

| 字段 | 编码 | 上限 |
|---|---|---|
| 索引 | 连续=1bit；否则 0+13bit（首索引 -1） | ≤ 0x1DD6 |
| 索引合法性 | 0..0x13（跳过 0x12）区间校验 + 去重 | — |
| A1 字符串 | `len+1` 字节（含 NUL） | len ≤ 0x1FFF |
| A1 字符黑名单 | 拒绝 `0x25`、`0x92` | — |
| A2 | 10-bit 计数 + 每项 {索引, 10-bit} | — |
| A3 | 10-bit 计数 + 每项 {索引, 10-bit, 7-bit, 4-bit n, n×12-bit} | 记录步长 0x4C |

## 5. 兼容性判定（严格）

| 问题 | 回答 |
|---|---|
| 服务端字段写入顺序与客户端读取顺序是否一致？ | **无法判定**（客户端侧未定位） |
| 哪些字段可以确认？ | **仅位序/位索引**可两侧确认（DIRECT）；**字段级全部 BLOCKED** |
| 哪些字段仅有形状匹配？ | 无 —— 本轮**没有**任何"形状匹配"被升级为证据。先前"`0xA2E50` 形状匹配"属 E4 结论，**不在本表**（那是 reliable command，不是 configstring） |
| 是否因此宣称协议兼容？ | **否**（任务约束 6 明令禁止） |

## 6. 与既有档案的差异

| 项 | 既有（E1） | 本轮 |
|---|---|---|
| `count` 宽度 | u16（short） | **确认 2 字节**（`mov ecx,2`；与 E1 一致） |
| body 位编码 | `BLOCKED` | **已闭合**（索引增量 / A1 / A2 / A3 全部指令级） |
| body 客户端消费 | `BLOCKED` | **仍 BLOCKED**（但已确定位序同构） |
| `configstring` 目标 RVA | 视作客户端 | **更正**：0xA0807/0xA0997 属**服务端**函数体 |
