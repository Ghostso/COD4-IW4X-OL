# E24 下一门禁决策

## 1. 决策

**维持 CONDITIONAL GO**。本轮把 E-23 留下的"协商对象入口未知"缺口**闭合到调用点与触发条件**，但应答缓冲到传输层的最后一条边仍缺失，协议语义命名仍不可证。

## 2. 本轮获得的确定性收益

1. **入口闭合（决定性）**：`0x6AB310` 唯一直接调用者 `0x6AC192`，条件为 `[+0xC8]==2 && [+0x5CC]==1 && msgcode==0x81`。无跳板、无函数指针、无 TLS/`.rimp` 参与。
2. **对象生命周期闭合**：`[edi+0x5F4]` 的构造（`0xA87BA0`，vtable `0xC5A31C`）、赋值（`0x6AB9E7`）、换新前释放（`0x6AB9B3`）、析构删除（`0x6AA16F`）全部定位。
3. **握手阶段机恢复**：`[+0x5CC]` 的 6 个写点构成 0→1→2→3 序列，与 0x81/0x83/0x84/0x85 的分派一一对应。
4. **缓冲语义确定**：`0xA87D50`（thiscall+4 栈参+`ret 0x10`）→ `0xACE180`（16 字节定长拷入 `this+0x14` + 长度守卫）→ `0xACE1B0`（长度校验 + cipher 表驱动变换）。
5. **协商标签发现**：`0x6AB310` 应答组装使用 `CLIENTCHAL`（VA `0xC5B144`）与 `BDDATA`（VA `0xC5B13C`）。

## 3. 已解除的停止条件

| E-23 停止条件 | 现状 |
|---|---|
| "`0x6AB310` 入口未找到，可能经跳板/间接调用" | **解除**：唯一直接调用者 `0x6AC192` |
| "`[edi+0x5F4]` 创建时机未知" | **解除**：阶段 1 → 2 的成功收尾处创建并换入 |

## 4. 剩余最小缺失证据

1. **应答→传输层的边**：`0x6AB310` 组装的应答缓冲去向（是否经 `0x6AA230` 入队）未闭合。
2. **cipher 描述符表**：`.data 0xD48F48` / `0xD48F64` 位于 BSS 尾部，磁盘无字节，静态不可解析。
3. **产生侧**：0x83/0x84/0x85 三码的构造点未定位（由入站帧解析产生）。
4. **语义命名**：阶段 1/2/3 与 `CLIENTCHAL`/`BDDATA` 的对应关系无独立证据。

## 5. 下一步唯一建议

**解析 `0x6AB310` 应答缓冲的接收方**：从 `0x6ABAAA`/`0x6ABABB` 写入 `[esi+8]`/`[esi+0x10]` 与 `[ebp-0x38]` 的数据块出发，追踪 `0x6AA230(this, data0, data1)` 的参数去向，确认是否经 `0x6AA320`/`0x6AA7B0` 进入发送队列。若该边闭合，则 0x81 应答的信令路径可端到端描述；若不能闭合，保留 `BLOCKED` 并停止。

不建议：
- 继续把 0x83/0x84/0x85 的产生侧当作可静态闭合的缺口（它依赖 `.tvm0` 与入站解析）；
- 在方向未闭合时实现服务器端 HMAC 或握手编码；
- 全客户端无边界扫描。
