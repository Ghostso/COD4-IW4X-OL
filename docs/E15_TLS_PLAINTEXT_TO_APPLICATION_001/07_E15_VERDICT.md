# 07 — E-15 总裁定 / VERDICT

> 只读静态分析。冻结基线哈希本轮复核一致，原始样本未修改。

---

## 1. 八个最终问题

Q1. 0x602BC0、0x612E80 与 TLS 读取链的关系是什么？

| 函数 | 关系 | 裁定 |
|---|---|---|
| 0x602BC0 | 连接对象状态重置/清理函数；0x602DD9 处调用 0x605220 只是其属性 getter 簇的一个分支 | PROVEN（非 TLS 读取） |
| 0x612E80 | 与 0x602BC0 同模块（共享深度 3 上游 0x5F9070）；同为就绪探测 | INFERRED |

两者都不是"调用 TLS 读取并处理明文"的函数。

Q2. TLS 读取的输出缓冲区在哪里？

| 调用点 | 输出缓冲 | 容量 |
|---|---|---|
| 0x6104E3 | [ebp+0xb]（栈上 1 字节） | 1 |
| 0x67F5F0 | 调用者栈参数 | 调用者指定（无可靠边界） |

PROVEN：0x6104D0 的输出缓冲是 1 字节栈局部，函数返回即失效。

Q3. 明文长度和缓冲区游标如何传递？

未发生传递。0x6104D0 只把返回值（1/0/-1）传给调用者，1 字节数据从未被读取、保存或转发（02 第2节）。

Q4. 是否找到应用层分帧或消息分派器？

未找到游戏协议分派器。找到的是 HTTP/1.x 分帧（libcurl）："GET %s HTTP/1.1..."、"Content-Length"、"libcurl error"。

Q5. 是否能连接到任何已知实时消息解析器？

否（REFUTED）。0x605220 六层闭包内不出现 0xA2660、0x3547D0、0x350170、0x34FD80、0xA2E50。

Q6. 是否能连接到 Gamestate 0x03 消费者？

否（BLOCKED）。链在更新模块中止。

Q7. 若不能，最小阻塞点是什么？

最小阻塞点：游戏协议的传输栈归属。已知：
- 客户端有明文 UDP 栈（recv/recvfrom + 9 收包函数）；
- 客户端有 TLS 栈，但属 libcurl 更新模块（down-update.qq.com）。

未定位的是：游戏协议走哪一条（明文 UDP？另一 TLS 会话？）。

Q8. 下一轮应追踪哪个具体函数、对象字段或调用边？

| 优先级 | 目标 | 理由 |
|---|---|---|
| 1 | 0x1B0430 的事件分支（0x1B086D / 0x1B0991 / 0x1B0A25 / 0x1B0ADF） | 唯一无调用者的通用 socket 事件函数 |
| 2 | 0x78772D（0x1B0430 同类） | 剩余第二候选 |
| 3 | 0x67F5F0 的真实函数边界 | 解出通用 SSL_read 的唯一游戏侧调用者（BLK-15-1） |
| 不扩大 | .tvm0 | 停止条件 |

## 2. 对 E-14 的修订

| E-14 结论 | E-15 修订 | 依据 |
|---|---|---|
| "0x605220 到 0x6104D0 到 0x672460 是 TLS 读取路径" | 更正为 1 字节就绪探测（peek） | 01 第3节 |
| "TLS 解密后的明文" | REFUTED：无明文外传 | 01 第3节、02 第2节 |
| "TLS 明文到应用层分派到 Gamestate" 假设 | 起点即被否定 | 04 第5节 |
| OpenSSL 0.9.8p 存在 | 维持 PROVEN | 但归属更新模块（libcurl） |

新增 PROVEN：客户端内联 libcurl + OpenSSL，服务 HTTP 更新（http://down-update.qq.com/）。
