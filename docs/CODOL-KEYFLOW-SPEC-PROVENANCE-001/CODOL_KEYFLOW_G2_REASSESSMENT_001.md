## 3. 关键发现对判定的影响

### 3.1 SRC-05（独立测量谱系）为何不能解锁 G2

`CODOLServer` 谱系是一份**真正独立于 ol-mod** 的测量路径（运行时内存转储 + 观察器，
与 SRC-01 无文本交叉引用），且独立复现了若干**结构规则**（MAC 覆盖 `frame[:-8]`、8B 截断、
seq 单调、帧头 `AB 85`）。**但是**：

- 其目标构建为 `36997674b18f…`（7,841,344 B，PE ts 2021-05-08），
  而非冻结的 2.6.9.7（`353754047dbb…`，9,964,656 B，PE ts 2015-05-05）。
- 其 KDF 结构（`SHA1(frame)` + `transform(conn+0xD9, const24)` + codec）与本构建的
  `expandKey` 计数器结构**不同**；`CLIENTCHAL`/`BDDATA` 位于不同 VA，且其自身曾把
  `CLIENTCHAL` 误判为协议字段后又撤回。
- 唯一可迁移的是**帧层规则**（覆盖范围、截断、序列号单调），且这些规则在两种构建中
  **字段偏移不同**。

⇒ 它是**跨构建的独立证据**，**不能**作为 2.6.9.7 结构规范的独立佐证。它反而证明：
**该私有协议的 KDF 结构随构建变化**，因此"跨构建复用"本身就是一个未决风险。

### 3.2 公开密码学标准为何不能解锁 G2

FIPS 180-4 / RFC 2104 / FIPS 197 / SP 800-38A 仅定义**原语内核**。Keyflow 的
标签、长度、counter 起点、20/20/16/16 切分、transcript 组成、secret 参数序、codec 层、
帧布局、MAC 覆盖/截断、序列号语义**均不在**这些标准中。
把"原语有公开标准"当成"私有协议结构有独立规范"是明确的推理错误，本任务予以拒绝。

### 3.3 未被获取的外部谱系（s1x / T5M / T5-DemonWare / OpenIW8 / dwd3）

这些名称仅出现在 `dw3_feasibility.md` 的**文字引用**中，工作区内**不存在**对应 artifact。
即使获取，仍需逐一核验其是否实现同一 20/20/16/16 结构与同一 KDF，**不能预先假定独立**。
