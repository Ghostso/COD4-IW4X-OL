**任务**：`CODOL-BATTLE-SERVER-REVERSE-COVERAGE-001` 第五阶段
**方法**：对每个 `UNKNOWN` / `PARTIALLY_CONFIRMED` / `CONFLICTED` 项做必要性评估。
**分类**：`BLOCKS_MVP`（不解决无法实现第一阶段战斗功能）· `BLOCKS_FEATURE`（仅阻塞特定功能）· `IMPROVES_COMPATIBILITY`（改善不阻塞）· `DEFERRED`（当前阶段无需研究）。

## A. BLOCKS_MVP

### T-01 定位 configstring **外层消息分派器**（BLK-7）
- **①待定位**：2697 客户端消费 `0x04` 的外层 svc 分派器（`0xA2660` 的上层调用者）。
- **②证据**：服务端 `_WriteConfigstrings 0xA0468` + body `0xA0807..0xA0997` 已闭合；客户端 body 消费者 `0xA2660` 已定位且逐字段一致；**缺失**：谁把 `0x04` 分派到 `0xA2660`。
- **③方法**：从 `0xA2660` 反向 xref/调用者分析；`.text` 可搜；`0xA2660` 是已定位常量，优先于全量扫描。
- **④产物**：`svc 0x04 → outer dispatch → 0xA2660` 调用链（RVA + 分支 + 缓冲来源）。
- **⑤验收**：能给出 opcode 读取点、比较分支、以及到 `0xA2660` 的调用/间接调用。
- **⑥解决障碍**：configstring 无法被证明"客户端能读"。

### T-02 定位客户端 `0x06` 读取/终止分支（BLK-8）
- **①待定位**：客户端对 `0x06` 的读取与终止判断（EOF/EOS vs 子段/阶段标记）。
- **②证据**：服务端写入侧闭合（位游标字节边界强制重同步）；**缺失**：客户端终止分支与 `0x06` 性质。
- **③方法**：在 `0xA2660` 及外层分派器内搜索 `0x06` 比较；结合位读取器 `0x1AC670` 的调用点。
- **④产物**：`0x06` 客户端处理路径说明（内含/外层分工）。
- **⑤验收**：能区分 `0x06` 是 message EOF 还是子段结束，并给出读取点 RVA。
- **⑥解决障碍**：gamestate/configstring/snapshot 的正确分帧与终止。

### T-03 定位客户端 opcode `0x02` 分派（BQ-21，最高业务价值）
- **①待定位**：`opcode 0x02 → 客户端 0xA2E50` 的控制流。
- **②证据**：服务端 `0x02|long|short|data`（上限 0x3FC）↔ 客户端 `0xA2E50` 字段形状一致；**缺失**：绑定控制流。`.text` 线性扫描 0 命中（可靠性 95.1%）；`.tvm0` 未解码；`.data` 99.86% 缺失。
- **③方法**：**先解码 `.tvm0`**（RVA 0xD958000）再在解码指令流中搜索分派；或从运行时 dump 取 `0xA2E50` 调用栈/回调注册。
- **④产物**：`0x02 → 0xA2E50` 绑定证据（RVA + 字节 + 分支）。
- **⑤验收**：找到 opcode 读取点、比较/跳转、到 `0xA2E50` 的调用（直接或间接）。
- **⑥解决障碍**：usercmd/可靠命令的实际消费（M4）。

### T-04 取 snapshot 帧边界与 delta 基准（BLK-5/BQ-17）
- **①待定位**：2697 snapshot 完整帧边界、delta 基准、首个 snapshot 的 EOF/子段语义；客户端解码 `0x6E060`/`0x6D340`。
- **②证据**：服务端写入链 `0xA4FA0→0xA4860` + 区域拼接常量；3.3.3.3 抓包快照 29/29 字段对齐、124B/帧；**缺失**：帧边界与客户端 delta 绑定。
- **③方法**：取一条真实 snapshot 帧作边界判据；或从客户端解码函数反向还原字段范围。
- **④产物**：snapshot 帧布局规格 + 帧边界判据。
- **⑤验收**：首个 snapshot 可被解析并回读玩家原点/状态；至少一个实体更新与一组 delta 通过；无 overflow/错误终止。
- **⑥解决障碍**：M6 世界状态同步。

### T-05 取得 2697 战斗通道**真实字节样本**（BLK-6/黄金向量）
- **①待定位**：同 SHA-256（`35375404…`）客户端的一条 configstring/snapshot 帧。
- **②证据**：无任何真实 2697 字节（`09_RUNTIME_EVIDENCE_INVENTORY.md` §4）；**影响全部互通类里程碑**。
- **③方法**：**受权**的真实互通/抓包；或在客户端 socket 层做只读采集。
- **④产物**：golden vector（configstring body + snapshot + 一条 usercmd）。
- **⑤验收**：字节帧可复算、可被服务端编解码器往返一致。
- **⑥解决障碍**：一次性解除 BLK-1/2/3/5/6 的字节级证据缺口。

### T-06 取得同 SHA-256 客户端**运行时解包 dump**
- **①待定位**：`35375404…` 客户端的运行时映射镜像（PE 头 + `.text`/`.rdata`/`.data`）。
- **②证据**：恢复镜像 `.data` 声明 218 MB 仅 0.14% 在文件内（BQ-33）；`.tvm0` 扫描可靠性 0.0%；ACE ~10s 后内存读取失效；Frida 附加失败×2。**缺失**：运行时 dump。
- **③方法**：受权动态采集（先解决 Frida/反作弊窗口）；或在进程内只读读取模块头与目标 RVA 字节。
- **④产物**：运行时 dump + 与恢复镜像的差异报告。
- **⑤验收**：能证明恢复镜像 ≡ 运行时映射，或量化差异。
- **⑥解决障碍**：所有客户端侧静态结论的结构性上限（BQ-05）。

### T-07 booking / DedicatedControl 接线验证（G-06）
- **①待定位**：6/14 mmbook/mmstart → DedicatedControl → booking accepted 的完整字段与流程。
- **②证据**：DedicatedControl 协议已完整定义（ProtocolVersion 2、28961/28962、`OLDC`、24B 头、MessageType 1–20）；ol-mod 源码已到位；**缺失**：与冻洁大厅基线（REF_LOBBY_KIT）的接线与实机验证。
- **③方法**：在**副本**（非 Golden）新增 booking/DedicatedControl 接线；用 `battle_selftest.py` 做离线回归。
- **④产物**：`BOOKING_PROTOCOL_SPEC-001.md`（先出规格，不改 Server）+ 接线实现。
- **⑤验收**：客户端停止 5s 重试；`battle_srv.log` 出现 `RX #1 16B`；valid room/session。
- **⑥解决障碍**：Lobby→Booking→Battle 第一条闭环（M2）。

### T-08 定位"对局地址"真实下发来源（U-7/CS-D10）
- **①待定位**：客户端从哪里取得战斗端点；为何送 `101.67.36.18:10035`。
- **②证据**：端点来自 21/5 session 对象（258B + 16B securityKey）；实测客户端送外部腾讯地址、28960 出现 0 次。
- **③方法**：隔离运行 + 抓包；必要时用客户端 socket 钩子 `[edi+0x1B8]`/`0xAD6D7F` 接管。
- **④产物**：端点下发链路 + 接管点。
- **⑤验收**：客户端对局流量到达我方监听的 28960（且非离线自测写入）。
- **⑥解决障碍**：M2→M3 客户端真正连上我方战斗服。

### T-09 解除 ol-mod L1 引擎绑定宿主身份门禁（G-08）
- **①待定位**：`EngineBindings.cpp:3647-3667` 三条静默早退点（`:3656/:3660/:3666`）中的哪一条。
- **②证据**：期望 `SizeOfImage=0x0E5D6000`+`TimeDateStamp=0x6096930A`（去壳 `out.exe`）；实测加壳件 `0x0E659000`；三次 `engine binding failed` 无 stage 日志；`out.exe` 全盘 0 命中。
- **③方法**：取得 `out.exe`；或经授权在插件内**只读**读取自身模块头 + `0x0FEA20`(5B `55 8B EC 56 57`)/`0x8371A`(8B `83 7C 24 08 01 0F 94 C0`) 字节（**先取证、后判门禁**）。
- **④产物**：运行时映像身份报告 + 分支裁定。
- **⑤验收**：确定失败分支；判定 R-A（取得 out.exe）还是 R-B（受控实验 + 目录移植）。
- **⑥解决障碍**：ol-mod 线帧循环与 28960 监听（M1）。

### T-10 解码 `.tvm0`（BQ-34，方法学前置）
- **①待定位**：`.tvm0`（RVA 0xD958000）的指令流解码。
- **②证据**：原始字节 E8/E9 扫描可靠性 0.0%，是噪声；**必须解码后**再搜索。
- **③方法**：静态解码 `.tvm0` 格式；在解码指令流中重跑 `0x02` 分派搜索。
- **④产物**：`.tvm0` 解码器 + 解码指令流。
- **⑤验收**：解码后分派搜索可靠（非噪声）。
- **⑥解决障碍**：T-03（0x02 分派）的搜索空间不完备问题。
