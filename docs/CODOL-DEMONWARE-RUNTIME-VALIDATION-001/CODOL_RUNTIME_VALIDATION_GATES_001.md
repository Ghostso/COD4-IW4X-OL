# CODOL Demonware 运行时验证门槛（G0–G5）

> 任务：CODOL-DEMONWARE-RUNTIME-VALIDATION-001（承接 CLIENT-DEMONWARE-CODEC-KEYFLOW-001）
> 性质：**交付物为验证门槛定义**，不是测试结果。全部验收状态在本轮均为 **NOT-EXECUTED / NOT-OBSERVED**。
> 纪律：未达到的门槛一律保持"未通过"，不得用推断、静态等价或参考实现自洽替代实测。

## 0. 门槛总览

| 门槛 | 名称 | 主题 | 本轮状态 |
|---|---|---|---|
| G0 | 证据与基线完整 | 输入冻结、外层清单校验、登记注册 | **已通过**（见 §1，本轮实际执行） |
| G1 | 静态调用链及关键数据流可追踪 | KDF/Codec/AES/帧/MAC/序列号全链定位 | **已通过**（静态；见 §2） |
| G2 | 独立实现之间的固定测试向量一致 | TC-01..TC-11 等 KAT 一致 | **未通过**（未执行） |

| G4 | 获得可归档的真实运行时交互证据 | 授权隔离环境运行并归档 | **未通过**（NOT-OBSERVED） |

## 1. G0 — 证据与基线完整（本轮已通过）

**通过条件**
1. 正式证据包目录与外层 SHA-256 清单已定位，且清单覆盖包内全部文件。
2. 逐文件校验：命中数 == 清单行数，缺失 0、失配 0。
3. 冻结输入（客户端打包件、恢复镜像、服务端）已记录路径/大小/版本/SHA-256，复算值与既有记录一致。
4. 已有审计报告与去重/登记材料被登记为本轮输入（`CODOL_DEMONWARE_RUNTIME_VALIDATION_PLAN_001.md` §2）。

**失败条件**
- 任一清单条目缺失或哈希失配；
- 输入文件大小/哈希与既有冻结记录不一致且未记录差异；
- 未把既有报告纳入输入登记。

**所需证据**
- 外层清单校验记录（本轮实测：94/94 OK）；
- 四份内层子包清单校验记录（本轮实测：8/8、8/8、12/12、12/12 OK）；
- 冻结输入哈希复算记录。

**允许作出的结论**
- 可声明"输入基线完整且可复算"。
- 不可声明任何协议或互通结论。

**本轮实测结果**：**通过**。外层 94/94，内层 40/40，冻结输入 4/4 复算一致。详见 `CODOL_DEMONWARE_RUNTIME_VALIDATION_PLAN_001.md` §3。

## 2. G1 — 静态调用链及关键数据流可追踪（本轮已通过，静态）

**通过条件**
1. KDF：SHA-1 / HMAC-SHA1 / expandKey 三原语均定位到客户端函数，参数长度与标签字面为立即数证据。
2. Codec A/B：入口、常量表、置换表、方向分支、输出缓冲均定位；净效果可证。
3. AES：两个 provider 对象、vtable、setKey(16B)、四个消费点方向均定位。
4. 帧：`u32len|AB|85|seq|iv16|ct|tag8` 逐字段写入点定位。
5. MAC：覆盖范围、8B 截断、比较逻辑定位。
6. 序列号：收发计数器读写点与严格递增语义定位。
7. 每项均有 `claim_id` 级映射（见 `CODOL_KEYFLOW_EVIDENCE_TRACE_001.csv`）。

**失败条件**
- 任一链路存在未定位的关键跳转或字段；
- 结论依赖未还原的 `.tvm0` 语义；
- 无法区分"客户端二进制观测"与"参考实现同源代码副本"。

**所需证据**
- 证据追踪表（20 条 KF-* 条目）；
- 独立性与限制列（区分 ARTIFACT-INDEPENDENT / NONE / SOURCE-SHARED）。

**允许作出的结论**
- 可声明"静态调用链与关键数据流已闭合"；
- 可声明 `K_client,consumed = K_reference,derived` 为**静态 bit-exact**。
- **不可**声明已实现互通、不可声明运行时可复现。

**本轮实测结果**：**通过（静态）**。边界保留：`.tvm0` 完整语义未还原（Q-111 BLOCKED），codec 等价性的运行时段位比对待做。

## 3. G2 — 独立实现之间的固定测试向量一致（未通过）

**通过条件**
1. 至少**两个来源独立**的实现（不使用同一份源码副本）对同一固定向量给出逐字节一致结果。
2. 覆盖 KDF 全链（TC-01..TC-06）与 Codec（TC-07..TC-11）。
3. 差异定位能力可用（不一致时输出首个差异偏移）。

**失败条件**
- 所谓"两个实现"实为同源代码副本（例如 `ol-mod` C++ ↔ `codol_crypto.py` ↔ C# `DecodeKey` 同源）；
- 仅内部自洽（同一实现自比）；
- 向量输入未固定（依赖随机 IV / 运行时内存）。

**所需证据**
- 独立实现清单与来源声明（每条注明与原点的派生关系）；
- 固定向量输入 / 期望输出 / 实测输出三方并列；
- 差异报告（若有）。

**允许作出的结论**
- 可声明"两个独立实现在给定向量上一致"。
- 仍**不可**声明与**真实 Demonware 服务端**兼容。

**独立性现状（本轮判定）**：现有参考材料**不满足**独立性要求。
`ol-mod` C++（`Crypto.cpp`）、`REF_LOBBY_KIT` Python（`codol_crypto.py`）、C#（`CodolLocalLobbyServer.cs`）
三者互为**同源派生**（Python 自述"依据三方 CodolLocalLobbyServer.cs 照抄"；C++ 与 Python 共用同一组 KAT）。
因此 G2 需要**新引入一份与被测客户端无派生关系的实现**（例如独立重写的参考实现/独立密码库），否则不得判通过。

**本轮实测结果**：**未通过（未执行）**。

## 4. G3 — 帧编码、解码和认证行为通过测试（未通过）

**通过条件**
1. 帧往返（TC-16..TC-18）逐字节一致。
2. MAC 正确/错误/截断/覆盖边界（TC-19..TC-23）全部按预期。
3. 序列号正常/重复/跳号/回绕（TC-24..TC-27）全部按预期且行为已记录。
4. 长度异常/短帧/截断帧（TC-28..TC-32）全部按预期拒绝且无越界。

**失败条件**
- 任一用例失败或行为与反汇编判定不一致；
- 出现越界读写、崩溃或不确定行为；
- 用例通过但输入非固定（不可复现）。

**所需证据**
- 逐用例执行日志（输入/期望/实测三元组）；
- 失败分类（框架见测试矩阵"失败分类"列）；
- 越界/健壮性检查记录。

**允许作出的结论**
- 可声明"帧编解码与认证行为在**本地测试环境**通过"。
- **不可**声明"原始服务器兼容性"——本轮无真实原始服务器样本。

**重要限定**：本轮**没有**任何真实原始服务器帧样本。
因此 G3 最多证明**内部一致性 / 参考实现兼容性**，不得包装为真实服务端验证。

**本轮实测结果**：**未通过（未执行）**。

## 5. G4 — 获得可归档的真实运行时交互证据（未通过）

**通过条件**
1. 在**有权限的本地或隔离**测试环境内实际运行客户端（与/或参考对端）。
2. 采集到可归档的运行时证据：进程/模块身份、时间戳、原始字节流或内存转储、操作步骤。
3. 证据可复算：给出哈希、捕获方式、环境快照。
4. 运行时数据**非伪造**，来源可追溯。

**失败条件**
- 在无权限或不可控环境运行；
- 证据无法复算或来源不明；
- 以静态推断冒充实测；
- 采集跨越未授权网络。

**所需证据**
- 运行环境清单（隔离边界、授权依据）；
- 原始捕获文件 + SHA-256 + 采集脚本；
- 时间线日志（启动/握手/帧收发）。

**允许作出的结论**
- 可声明"已获得真实运行时交互证据"。
- 是否构成"互通"仍取决于 G5 的重复性。

**本轮实测结果**：**未通过（NOT-OBSERVED）**。本轮为纯静态/离线，未启动客户端或服务端，未注入，未读取运行时内存，未连接网络。

## 6. G5 — 端到端互通可重复复现（未通过）

**通过条件**
1. 真实 2.6.9.7 客户端与目标服务端（或参考对端）完成完整握手与至少一次任务往返。
2. 同一流程在**受控重复次数**下全部成功（次数需在测试前声明）。
3. 每轮均有独立归档证据，且逐轮哈希可核。
4. 失败轮次一并记录，不得只保留成功轮次。

**失败条件**
- 仅单次成功、无法重复；
- 成功依赖未记录的隐式状态；
- 部分环节用模拟/桩替代却声称真实端到端。

**所需证据**
- 逐轮捕获 + 哈希 + 结果；
- 一致性统计（成功/总轮次）；
- 反例与失败模式记录。

**允许作出的结论**
- 只有 G5 通过后，才可声明"端到端互通可重复复现"。

**本轮实测结果**：**未通过（NOT-OBSERVED）**。

## 7. 门槛依赖与晋升规则

```text
G0 ──> G1 ──> G2 ──> G3 ──> G4 ──> G5
 |      |      |      |      |
 |      |      |      |      └─ 需授权隔离环境；不得跳级
 |      |      |      └──────── 本地用例；无原始服务器样本 => 仅内部一致性
 |      |      └─────────────── 需至少两条非派生实现
 |      └────────────────────── 静态；不得用于声明互通
 └───────────────────────────── 完整性前置
```

- 门槛**不得跳级**：G3 未通过时不得进入 G4 的"互通"结论。
- 每个门槛的"未通过"必须在最终报告中原样保留。
- 任何因后续证据推翻的历史结论，按登记簿纪律**新增条目**记录，不删除原文。

## 8. 禁止声明清单（贯穿全部门槛）

- 不得把静态等价 / 参考实现自洽 / 真实端到端互通视为同一结论。
- 不得把同源代码副本或重复报告当成独立证据。
- 不得在缺乏原始输入输出证据时声称已实现互通。
- 不得因发现后续证据而删除历史失败结论。
- G3 的内部一致性测试**不得**命名为"原始服务器兼容性测试"。
