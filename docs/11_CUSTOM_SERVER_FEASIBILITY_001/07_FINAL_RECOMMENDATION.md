# 07 — 最终建议

> 结论日期：2026-10-12。仅基于现有静态报告，不代表客户端已实际连通。

## 1. 是否值得开始自建服务器？

**值得，但应作为“协议兼容 + 最小战斗服 MVP”工程，而不是从零重建完整 CODOL。**

理由：
- 已有完整旧服务端源码底座（B1/B2）；
- 已有可构建的独立 C# 战斗服（B3）；
- 已有 2697 原生服务端作为协议事实源；
- 已有 runtime-assets、scripts、GSC 和数据表；
- 真正缺的是 2697 客户端消费链和少量关键协议冲突，而不是所有基础设施。

## 2. 优先验证 2697 原生服务端，还是改造旧版源码？

**优先采用 B3 + B1/B2 参考的混合路线，同时把 2697 原生服务端作为协议 oracle。**

不建议二选一：
- 路线 A（原生 2697）价值最高，但受注册/资源/激活门控和不可维护性限制。
- 路线 B（旧源码）骨架最完整，但 1.1.1.13/3.3.3.3 与 2.6.9.7 版本不一致。
- 最稳的做法是：B3 先做可重复离线/传输实验，B1/B2 提供算法参考，2697 原生服务端提供字段与分支真值。

## 3. 可以直接复用的模块

- C# `UdpTransport`、`CodolProtocol`、`MotionSnapshot`、`SessionDescriptor`、`ServerHost`、`ClientLogic`、离线 selftest。
- B1 `netchan.c`、`msg.c`、`sv_main.c`、`sv_client.c`、`sv_snapshot.c`、`codol/net/*` 的结构与算法。
- B2 `game_server/server_mp`、`qcommon`、backend/Demonware 的模块划界与测试设计。
- 2697 runtime-assets、scripts、script-overlay、附件注册表、客户端 loopback 审计数据。

## 4. 第一个可验证的技术里程碑

**M0 + M1 + M2：先冻结 2697 协议规格并建立离线黄金向量。**

具体唯一优先任务：
1. 从 E1/E2/E3 的 RVA 和现有字节向量中整理 2697 消息字段；
2. 用 C# `CodolProtocol`/旧 `msg.c`/B1 源码做独立编码-解码；
3. 对已知向量逐字节测试；
4. 明确 0x01/0x02、0x03/0x04、0x05/0x06 的边界；
5. 把未验证字段单独标记 BLOCKED。

此阶段不需要启动客户端/服务端，也不需要安装工具。

## 5. 当前最可能阻止客户端进入大厅的三个问题

1. **客户端 opcode 0x02 分派链缺失**：`0xA2E50` 字段读取匹配，但无 opcode→函数控制流证据。
2. **0x06 客户端语义未知**：服务端写 `0x06` 已确认，但客户端读取/终止判断未定位。
3. **2697 原生注册/资源激活门控未闭合**：`+0x6408`、资源 `+0x78F4` 和 target archive 激活条件缺少可复现配置路径。

附加风险：会话描述符/securityKey 与客户端大厅版本不匹配。

## 6. 已有直接证据 vs 需进一步调查

已有直接证据：
- 2697 服务端 reliable/gamestate/configstring/snapshot 的多个 RVA 和写入格式；
- 客户端 `0xA2E50` 的字段读取和 0x3FC 上限；
- 旧 EXE 哈希、旧源码存在和版本；
- C# 战斗服离线构建/自测；
- 2697 runtime-assets/scripts 清单。

仍需调查：
- 2697 客户端的 opcode 分派、0x06 和 gamestate 消费；
- 2697 注册合法运行路径；
- 1.1.1.13/3.3.3.3 字段到 2.6.9.7 的映射；
- 2697 大厅/会话描述符与客户端版本关系；
- 2697 原生服务端的实际初始化/连接行为。

## 7. 风险与许可

- B3 目前声明未复制上游源码；后续可保持独立实现路线。
- 任何注册/认证/保护绕过都不属于本项目 MVP 范围。

## 8. 最终建议

**启动 Phase 1：Codec + 离线黄金向量 + 2697 协议规格。**

在 M2 完成前，不进入 M4/M5/M6 的运行级实现；在客户端 opcode 分派和 0x06 语义闭合前，不宣称自建服务器可进入大厅或可玩。
