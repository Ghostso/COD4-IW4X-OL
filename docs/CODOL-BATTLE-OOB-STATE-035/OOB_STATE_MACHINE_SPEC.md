## 1. 状态门来源与地址表达（TASK-035 第一项要求的核实）

**问题：** `[0x76446B0]` 是"何种地址表达"，对应"何种存储对象"？

**核实结果（`evidence\confirm_state_gate_address.out.txt`）：**

| 项 | 结论 |
|---|---|
| 指令形式 | `A1 B0 46 64 07` = `mov eax, dword ptr [0x076446B0]`（**绝对地址、无基址寄存器、无索引**） |
| 地址表达 | 该值是**映像内绝对 VA**（不是 `[reg+disp]` 结构体字段，也不是 RVA） |
| 落点节区 | 位于 `.tp3`（`VA 0x00A16000..0x0E5C7CC0`）内 |
| 原始文件 | **超出 raw 文件长度**（`file size 0x00A65000`，`offset 0x072446B0 > 0x00A65000`）⇒ 属**未初始化数据段**，加载时零填充 |
| 引用密度 | 全镜像对该 VA 的绝对引用共 **193** 处（`A1` 17 处、`8B0D` 7 处、`8B15` 2 处、`8B1D` 5 处、`833D` 153 处、`C705` 5 处、`3905` 4 处） |
| 立即数写入点 | **5 处**：`0x70467→3`、`0x1BE90A→7`、`0x1BEA8B→4`、`0x37C343→0`、`0x413D34→7` |
| 对象性质 | **进程级全局变量**（无对象基址） ⇒ 属于**客户端自身状态**，不是某个会话对象的字段 |

**推论（本轮采取的实现立场）：**
- 这是**客户端侧**的进程全局状态。
- 服务端实现**不得**直接复制该变量，而应**复现已证实的客户端可观察行为**（何种状态下发出何种 OOB）。
- 因此模块把 `clientState` 建模为**一个整数输入参数**，并**明确不导出**该全局。

**⚠ 记录差异：** TASK-034 的报告文字表述为"客户端状态门 `[0x76446B0]`"，
并沿用 009 的"全局 `0x076446B0`"。本轮核实**其实际编译期地址为 `0x076446B0`**
（即 `0x76446B0` 的 `0` 前缀写法），两者是**同一地址**。
本规格统一写作 `0x076446B0`，并在实现注释中保留原写法。

## 2. 已证实的值域与门

### 2.1 值域

**`CONFIRMED`（`0x1C0635..0x1C0647`）：** 允许值集合 = **`{3, 4, 5, 6}`**；其余值直接返回（`jne 0x1C0F1B`）。

**旁证（本轮新增）：** 该全局的立即数写入点包含 `3`、`4`、`7`、`0`。
- `4` 与 `3` 在允许集内 ⇒ 与门一致。
- `7` 与 `0` 在允许集内 ⇒ 与门一致（这两个状态下 OOB 不发送）。
- **`5` 与 `6` 未发现立即数写入点** ⇒ 必由**寄存器写入**（如 `mov [0x76446B0], reg`）或计算写入，本轮未定位。
  **这使"状态 5/6 的进入条件"仍为 `UNKNOWN`。**

### 2.2 三级门

| 门 | 条件 | 目标 RVA | 等级 |
|---|---|---|---|
| 门 1 | `state ∈ {3,4,5,6}` | `0x1C0635..0x1C0647` | `CONFIRMED` |
| 门 2 | `ecx != 0` 且 `ebx != 0` 且 `[ebx+0x100260] != 1` | `0x1C064D..0x1C065C` | `CONFIRMED`（条件）；`[ebx+0x100260]` 语义 `INFERRED`="进行中/占用" |
| 门 3 | 见 §3 节流表 | `0x1C0693..0x1C06DF` | `CONFIRMED`（值与应用）；语义 `UNKNOWN` |

门 3 的**双时间源**（`CONFIRMED`）：
```
ecx = [0x0C7AF6A8] - [ebx+0x08]     ; 用于 100 / 500
eax = [0x0C7AF6A8] - [ebx+0x30]     ; 用于 3000
```
`[0x0C7AF6A8]` 是**同一时刻读数**（两条 `sub` 之前只读一次），因此两个差值来自同一"当前时间"。

## 3. 节流规格（值已确认，语义未确认）

| 状态 | 比较 | 立即数 | 目标 RVA | 抑制条件 |
|---|---|---|---|---|
| 3 | `cmp eax, 0xBB8` | **3000** | `0x1C06B3` / `j l 0x1C0F1B` @ `0x1C06B8` | `delta([ebx+0x30]) < 3000` |
| 4 | 同上（复用同一比较） | **3000** | 同上 | 同上 |
| 5 | `cmp ecx, 0x64` | **100** | `0x1C06C9` / `j l` @ `0x1C06D9` | `delta([ebx+0x8]) < 100` |
| 6 | `cmp ecx, 0x1F4` | **500** | `0x1C06D3` / `j l` @ `0x1C06D9` | `delta([ebx+0x8]) < 500` |

**放行后的记账（`0x1C06E9` / `0x1C06F2`）：**
```
若 state ∈ {3,4}:  inc dword [ebx+0x34] ; mov [ebx+0x30], [0x0C7AF6A8]
```
即状态 3/4 放行时刷新 `[ebx+0x30]` 并自增 `[ebx+0x34]`。

**本轮不做的语义标注（任务书 §二明确禁止）：**
- **不**把 3000 标注为"状态驻留时间"。
- **不**把 100 标注为"挑战重试间隔"。
- **不**把 500 标注为"心跳周期"。
- 三者仅作为**数值阈值 + 适用状态**记录。

**⚠ 记录差异：** TASK-034 报告写作"状态 3/4 节流 3000 ms；状态 5 节流 100；状态 6 节流 500"。
本轮**确认了这三个数值及其适用状态**，并**新增确认了守卫结构**（`evidence\oob_branch_throttle.out.txt`）：

```
0x1C06A9  cmp esi, 3                ; esi = state
0x1C06AC  je  0x1C06B3
0x1C06AE  cmp esi, 4
0x1C06B1  jne 0x1C06BE              ; 仅 state 3/4 走 3000 分支
0x1C06B3  cmp eax, 0xBB8            ; (now - [ebx+0x30])
0x1C06B8  jl  0x1C0F1B              ; < 3000 -> 抑制

0x1C06BE  mov eax, [ebp-0x1150]     ; 重新载入 state
0x1C06C4  cmp eax, 5
0x1C06C7  jne 0x1C06CE
0x1C06C9  cmp ecx, 0x64             ; (now - [ebx+0x8]) , 仅 state 5
0x1C06CC  jmp 0x1C06D9
0x1C06CE  cmp eax, 6
0x1C06D1  jne 0x1C06DF              ; 非 5/6 -> 跳过该比较
0x1C06D3  cmp ecx, 0x1F4            ; 仅 state 6
0x1C06D9  jl  0x1C0F1B              ; 抑制
0x1C06DF  ...
```

即：**每个阈值都被自己的状态比较守卫**（3000 由 `esi∈{3,4}`；100 由 `eax==5`；500 由 `eax==6`），
而**不是**"对所有状态执行再筛选"。因此实现必须**按状态选用唯一阈值**，
并且**不得**把三个阈值合并成"取最小值"之类的简化。

## 5. 接收/解析（`CONFIRMED` 识别；分支体 `UNKNOWN`）

函数 `0x1C13A0` 是一串**独立的确切字符串比较**（helper `0x3745E0`，bound `0x7FFFFFFF` = 比到 NUL）：

| 比较点 RVA | 令牌 | 目标 VA |
|---|---|---:|
| `0x1C1684` | `challengeResponse` | `0x00DBFEE8` |
| `0x1C1755` | `connectReject` | `0x00DBFEFC` |
| `0x1C17B4` | `connectResponse` | `0x00DBFF0C` |
| `0x1C18B5` | `heartbeatresponse` | `0x00DBFF1C` |
| `0x1C1963` | `statResponse` | `0x00DBFF30` |
| `0x1C1B0A` | `disconnect_ack` | `0x00DBFF40` |
| `0x1C1B4A` | `echo` | `0x00DBFF50` |

**比较语义（`evidence\string_helpers.out.txt`）：** `0x3745E0` 逐字节比较，不等时对**两侧**的 `0x41..0x5A`
执行 `+0x20` 折叠后再比较 ⇒ **ASCII 大小写不敏感**，但**不是前缀匹配**（须比到 NUL 且终止符在缓冲内）。

**未证实：** 每个匹配分支之后的行为、以及入站是否带信封/前缀。因此分类器**只返回令牌**，不产生任何状态变更。

## 7. 客户端状态 vs 服务器状态（**强制分离**）

| | 客户端 | 服务器 |
|---|---|---|
| 载体 | **进程全局** `[0x076446B0]`（客户端自身） | 模块自定义枚举 `ServerClientState` |
| 值域 | `{3,4,5,6}`（已观测）+ `0`、`7`（写入点） | `None / ChallengeIssued / Connected / Closed` |
| 语义命名 | **`UNKNOWN`**（仅以数字引用） | 服务器自有 |
| 禁止 | 不得把 `3..6` 映射为 Free/Connected/ClientLoading/Active | 不得把服务器枚举喂给客户端状态门 |

模块中 `OobSendStateMachine.Decide(int clientState, …)` 的 `clientState` **只接受数字**，
`ServerClientState` 是**另一个类型**，编译期不可互换（`SelfTest` 中 TV-03/Robustness 显式断言该分离）。
