## 1. 阻止"宣称真实客户端兼容"的未知项（按严重度）

| 编号 | 未知项 | 为何阻止兼容性声明 |
|---|---|---|
| **U-03** | 状态 3/4/5/6 的**业务语义** | 我们只知道"值 → 命令"的映射，**不知道**这些值何时由客户端置位。服务端无法在正确时机驱动 OOB。 |
| **U-05b** | 状态 **5/6 的进入条件** | 5 与 6 **没有**立即数写入点（写入点只有 3/4/0/7），其状态写入路径未定位 ⇒ 无法确认服务端行为能否让客户端进入 5/6。 |
| **U-01/U-02** | 3000 / 100 / 500 的**作用** | 数值与适用状态已确认，但**语义未确认**；无法判断服务端的应答频率是否会触发客户端预期之外的抑制或放宽。 |
| **U-06** | 接收分支**匹配之后的行为** | 分类器只返回令牌。**不知道**客户端在收到 `challengeResponse` / `connectResponse` 后做什么（是否校验、是否改变状态、是否发下一包）。 |
| **U-07** | 入站报文**信封/前缀** | 不知道回复是否包裹在某个前缀/长度中；若服务端按错误分帧发送，客户端将无法识别任何令牌。 |
| **U-09** | 报文**长度与分隔规则** | 没有任何目标证据给出长度字节或终止约定 ⇒ 无法构造**可信**的出站报文。 |
| **U-10** | `getchallenge` 的**种子串生成** | 种子是注入参数；其真实生成（`0x26C9B0` / `0x83C740` 区域）未追踪 ⇒ 服务端可能无法生成客户端接受的种子。 |
| **U-04** | 状态 4 的**字段→值映射** | 键的**身份与顺序**已确认，但每个键**如何取值/如何引用**未确认 ⇒ 无法构造可用的 `connect`。 |
| **U-08** | `cancelConnect` 的具体副作用 | 只建模了"关闭本会话"；不知道客户端期望的后续状态 ⇒ 可能与会话清理流程不符。 |

> **结论：** 即使本模块 84/84 全绿，也**只能**说明"已确认子集被正确实现"。
> **不能**说明真实客户端会接受我们的报文。
