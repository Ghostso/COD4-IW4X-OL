## 3. 移动方向：服务端**严格**按当前 yaw（17139 条输入日志）

`log_inputs.on` 打开后逐条记录 usercmd，统计全部 `move != 0` 的条目：

```
yaw=  4.04  move=1(前进)    dir=  4.05   dir-yaw=  0.00
yaw=-42.42  move=1          dir=-42.43   dir-yaw=  0.00
```

→ **前进 = yaw、横移 = yaw±90、后退 = yaw+180，误差 0.00**。

## 5. ★★ 根因：**"谁来算移动"这个架构与真机不同**

```
真机对局:   客户端自己的 Pmove 算移动（视角为前方 + 碰撞 + 重力 + 加速度/摩擦）→ 服务端只校验
我方现况:   客户端**不跑 Pmove**，只是跟随我们每帧下发的 origin
            ⇒ 移动方向、碰撞、重力、加速度 全是"我方服务端的粗积分"
```

三次对照实验即可定死（位置发送方式 → 结果）：

| 位置发送 | 出生点 | 移动 |
|---|---|---|
| 全省略 | ❌（探针读到 origin=`0 0 0`） | ❌ 完全不能动 |
| **每帧钉成固定点** | ✅ 正确 | 🟡 能动能开枪，但被拽回 |
| 只首帧 + 其余省略 | ❌ | ❌ 不能动 |

→ **客户端依靠服务端的 `origin` 推进**。所以"正常 FPS 的视角前方移动"不会自动出现，
必须让**客户端的 Pmove 结果算数**。

## 9. ★★ B 路线落地：**镜像客户端自己的预测态**（本轮最大突破）

### 9.1 关键发现：客户端内存里有**两份** playerstate

用 `--ps-probe` 扫到的众多同类结构里，**有一个是客户端自己预测出来的**（带重力、带自己的碰撞）：

```
预测态: origin z=-99.63  vel=(-95, 0, -166)  pm_flags=0x2020  f2c=4   commandTime 最新
权威态: origin z=-116.00 vel=(我们下发的值)   pm_flags=0       f2c=0
          × 31 份（"回声我们快照"的历史环）
```

参考产物自己的 dump 也证实这一点（`predicted` 与 `snapshot` 的 origin/velocity 不同，
predicted 的 `velocity=[0,0,-43.0]` = 正在受重力）。

**判据**：`f2c != 0` 或 `pm_flags ∉ {0, 0x10}`，并加严 `pm_flags < 0x10000 且 f2c < 0x10000`
（`0x10` = 我方 idx20 的开镜位；加严是为了排除假结构，见 §11.3）。
**首选**：候选里"z 离群"的那个（权威副本的 z 恒等于我们下发的常量，预测态是客户端自己算的）。

### 9.2 实现

| 侧 | 做了什么 |
|---|---|
| `nt10.py` | 命中后**定点轮询**该地址（`tick_hz.txt`，128Hz），写 `predicted.bin`（`<6f>`origin+vel + `<I>`seq）；同时写 `pred_trace.txt` 高速轨迹 |
| `battle_server.py` | `mirror_predicted.on` 时，快照的位置/速度**回发该预测态**（带过期保护 + 前导补偿） |
| 启动日志 | `位置: ★镜像客户端预测态 (mirror_predicted.on), 前导补偿 0 ms, 探针 128 Hz, 快照 128 Hz` |

### 9.3 四次对照实验的结果

| # | 配置 | 出生点 | 移动方向 | 重力/爬箱 | 抖动 |
|---|---|---|---|---|---|
| 1 | 镜像 + 40Hz + lead 50ms | ✅ | ✅ 视角前方（但"有几率和延迟"） | ✅ 能爬箱落地 | ❌ 上下抖 |
| 2 | 镜像 + 128Hz + lead 25ms | ✅ | ✅ | ✅ | ❌（z 峰峰 82.7） |
| 3 | **镜像 + 128Hz + lead 0** | ✅ | ✅ | ✅ | 🟡（z 峰峰 23.7，−71%） |
| 4 | 镜像 + **10Hz** + lead 0 | ❌ | ❌ | ❌ | — |

⇒ **结论 1**：镜像确实让移动变成"客户端自己的 Pmove"——**方向 = 视角前方、重力、落地、爬箱子全部成立**。
⇒ **结论 2**：**快照频率不能低**（#4：降到 10Hz 客户端就"饿死"：跳不起、爬不上、出生点也不对）
—— 与 §5"客户端靠服务端 origin 推进"一致。
⇒ **结论 3**：前导补偿（lead）是我人为加的外推，**在 128Hz 下只会引入误差**（lead=0 让 z 抖动降 71%）。

### 9.4 跳跃现状

**有跳跃动画、但位移不完整** —— 预测态里确实出现 `vz` 由负转正（起跳），
但我们的回发是"上一 tick 的值"，起跳的那一两 tick 会被抹平。属于 §10 同一类问题（延迟/打架）。

## 10. 128 tick 级定量分析（抖动 / 穿墙的量化）

`pred_trace.txt`（每 tick 一条 `t x y z vx vy vz`）+ 一次性分析脚本 `_an_trace.py`：

| 指标 | lead=25ms | **lead=0** | 说明 |
|---|---|---|---|
| z 峰峰 | 82.66 | **23.66** | 地形起伏 + 抖动 |
| 平均 \|dz\| | 6.337 | **1.260** | **−80%** |
| 最大单 tick z 下冲 | −42.75 | **−18.00** | 10ms 内掉 18~42 单位 |
| x/y 单 tick 位移 >30 的次数 | 61 | 90 | **异常** |
| 采样间隔 | — | 中位 10.2ms | ≈100~128 tick |

**判读**：正常移动 = 190 u/s ⇒ **1.9 单位/10ms**；实测出现 **20~70 单位/10ms（≈2000~7000 u/s）**
且**成对反向**（`t=130.13 dy=-67.8` → `t=130.15 dy=+69.5`）⇒ 比正常高**三个数量级**，
是**位置被来回拉扯**（橡皮筋），不是手感问题。

**机理**：镜像回发的是"上一 tick 的客户端预测值"（延迟 10~20ms）⇒ 客户端拿它重新播种预测
⇒ 与我们/它自己的新值互相拉扯。**lead 只是让这个拉扯更糟**（已归零）。
彻底解见 §13。

## 11. 三次事故与修复（都是本轮踩的坑，全部已修）

### 11.1 一个 `⚠` 把战斗服打死（表现为"客户端卡在等待连接"）

`run_all` 启动战斗服时把 stdout **重定向到文件**，控制台代码页是 **GBK**；
日志里一个 `⚠`(U+26A0) 编不出 ⇒ `print()` 抛 `UnicodeEncodeError` ⇒ **战斗服启动即崩**。
（我手跑时 stdout 是终端 UTF-8，所以没暴露。）

**修复**：① 去掉该字符；② `log()` 加固（先往 `sys.stdout.buffer` 写 UTF-8，再退 ascii/replace）；
③ `main()` 开头 `sys.stdout/stderr.reconfigure(encoding="utf-8", errors="replace")`；
④ 补上一直缺失的 `import sys`。

### 11.2 上一轮残留的 `predicted.bin` 播种了错误出生点

过期判据原来只看"`seq` 有没有变" ⇒ 残留文件的 seq 谁都没见过 ⇒ **被当成新数据用满 1 秒**，
而**出生点正是那第一秒决定的**，错了再也回不来（现象：出生点在别处、跳不起、爬不上、朝向乱）。

**修复**：① 判据改成**看文件自身 mtime**（>0.5s 一律不采信）；② **启动即删除** `predicted.bin`；
③ 拿不到数据时明确告警并回落：`[!] mirror_predicted.on 但 predicted.bin 不可用 -> 已回落服务端积分`。

### 11.3 锚点误收别的结构（探针整轮 `★=0`）

锚点判据是 **OR**（`速度==190` **或** `实体索引==2047`）⇒ 误收了"碰巧也是 800/190"的别的结构：

```
origin=(-303.90, -2471.10, 64.86)  vel=0,0,0  pm_flags=0x18004000
```

⇒ 32 份候选全一样、"z 离群"也落空 ⇒ 镜像整轮无数据（幸亏 §11.2 的告警把它暴露了）。

**修复**：锚点加严 —— `gravity==800 且 speed==190` 之外，再要求
`pm_flags < 0x10000`、`origin` 在 `|x|,|y|<8192 且 |z|<4096` 内、
`+0xc0 cameraEntity` 或 `+0x1fc groundEntity` 至少一个是 `2047`；`_is_predicted` 同步加严。

## 12. 怎么判断"某一轮实验是否有效"（复核清单）

4. `pred_trace.txt` + `python _an_trace.py`：抖动率 / 瞬跳次数 / 落地事件 / 最大下冲。
