# MESSAGE_ENTRY_SPEC — 消息入口规格（已确认与未确认）

## 1. 已确认的局部规格

### 1.1 OOB 层（目标 EXE / image_best.bin）

| 项 | 值 | 证据 |
|---|---|---|
| OOB 发送器 | RVA `0x1C05F0` | 034 |
| OOB 接收器 | RVA `0x1C13A0` | 034 |
| 状态门 | `[0x076446B0] ∈ {3,4,5,6}` | 034/035 |
| 状态 3 命令 | `getchallenge 0 "%s"` | 034 |
| 状态 4 命令 | `connect` + 28 键 userinfo | 035 |
| 状态 5 命令 | `stats` | 035 |
| 状态 6 命令 | `heartbeat` | 034 |
| 节流 | 3000 / 100 / 500 | 034/035 |

这些是 **OOB 命令文本分派**，不是连接内应用层 opcode。

### 1.2 客户端状态更新分派（EXE）

| 项 | 值 | 证据 |
|---|---|---|
| 函数入口 | RVA `0x2000A0` | 直接调用点 `0x200F10`、`0x200F34` |
| 读取 | `mov eax,[ebx+0xBC]` | `0x20057C` |
| 范围 | `cmp eax,0x19; ja` | `0x200582` |
| 表 | 索引表 VA `0x60077C` → RVA `0x20077C`；跳表 VA `0x600744` → RVA `0x200744` | `0x20058B/0x200592` |
| 分支 | 26 个（0..25），多路目标 | `evidence/opcode_dispatch_dump.txt` |
| 语义 | 客户端对象状态/动画更新，不是 netchan/应用层消息 | 调用者遍历 `[ebx+0x120]` |

### 1.3 增量字段类型分派（EXE）

| 项 | 值 |
|---|---|
| 函数入口 | RVA `0x5F830` |
| 索引减法 | `edx = [ebp+0x40] - 5` |
| 范围 | `cmp edx,0x139; ja` |
| 索引表 | VA `0x460550` → RVA `0x460550` |
| 跳表 | VA `0x46040C` → RVA `0x46040C` |
| 第二分支 | RVA `0x600000` 区域，表 VA `0x4606E4` / `0x46068C` |

这是 **snapshot/entity 增量字段类型分派**，与 OOB 命令和应用层 opcode 必须分开。

## 2. 未确认的入口

| 项 | 状态 | 说明 |
|---|---|---|
| netchan 重组缓冲入口 | `UNKNOWN` | EXE 与 DLL 中均未绑定到可复核的序列号/分片/重组结构 |
| 应用层消息头 | `UNKNOWN` | 未定位 opcode 读取指令及其依赖的消息边界 |
| opcode 宽度/位序/偏移 | `UNKNOWN` | 没有直接指令证据 |
| opcode→分支映射 | `UNKNOWN` | 无一组映射能绑定目标 netchan 上下文 |
| 消息长度/终止标记 | `UNKNOWN` | 未定位读取位置 |
| 解析失败/截断路径 | `UNKNOWN` | 未定位 |
| 主 DLL `.tvm0` 内协议逻辑 | `UNKNOWN` | 未解码，不能按 x86 直接反汇编 |

---

## 3. 禁止拼接

本规格**不**给出完整的应用层消息格式。任何“完整 opcode 表”“完整消息头”在当前证据下都必须是猜测。后续任务必须从**主 DLL**的缓冲读取/序列号处理候选重新建立调用链。
