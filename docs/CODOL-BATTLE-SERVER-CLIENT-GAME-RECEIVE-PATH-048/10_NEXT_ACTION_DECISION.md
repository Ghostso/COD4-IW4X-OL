# 10 — 下一任务的唯一优先目标与可执行步骤

## 0. 结论

in-match「接收 → 解析 → 分派 → 消费者」链未闭环,断点集中在 **P5 客户端消费循环
`0x7A41D0` 之上 / 连接无关泵队列的 socket 生产者**。因此下一任务应把全部精力压在
**一个**目标上:定位 in-match netchan 的收包入口与第一条消息分派。

---

## 1. 唯一优先目标(049-T1)

**在官方客户端中定位 in-match(连接建立之后)网络收包入口,并证明其缓冲区进入
「读 opcode → 分支」的指令点。**

**判定为完成的验收(二选一):**

- A. 给出 `socket recv/recvfrom 调用点 → 缓冲区 → opcode 读取 → 分支表` 的**完整指令链**,
  每个节点带 RVA、参数寄存器/栈变量、缓冲区指针来源;或
- B. 给出「在已恢复映像范围内,in-match 收包入口**不在** P4/P5,而在 X 区域」的
  带地址负证据(含被检查范围与替代解释)。

**禁止:** 仅凭地址接近、字符串相邻、函数名相似断言链闭合;禁止猜测 opcode。

## 2. 为什么是这个目标

- `04` §6 明确:最后已证实节点是 P5 `recv` 的缓冲直通;第一个未证实节点是其上游。
- `06` 表明:除握手层外,所有模块都卡在同一条缺失边上。
- 一旦这条边闭合,opcode/gamestate/configstring/snapshot 四个模块可并行开展。

## 3. 可执行步骤(按顺序)

### 步骤 1 — 补全第 3 节区映像(解锁范围,最高性价比)

- 输入:S-IMG。第 3 节 `VA=0xA16000,VSize=0xDBB1CC0,RawSize=0x62000`,映像仅含前 0x4F000。
- 动作:用 040–046 已有的只读 dump 流程,对 `0xA16000` 之后按页抓取(若已有更好快照优先复用)。
- 产物:`image_best_full.bin` + 新 SHA-256;若无法获得,标记 `BLOCKED` 并跳过到步骤 2。

### 步骤 2 — vtable / 函数指针注册追踪(针对 P5 循环启动者)

- 目标:RVA `0x7A41D0` / `0x7A20A0` 的启动者。
- 动作:
  1. 在映像中搜索写入 `0x7A41D0`/`0x7A20A0` 的**数据流**(`mov [reg+imm], imm32`,
     `push imm32` 后存入 C++ 对象);
  2. 搜索 `CreateThread`/`_beginthreadex` 的 IAT 调用点,检查其回调参数;
  3. 若命中,向上追到会话创建点。
- 产物:`evidence/049_T2_vtable_launch.json`。
- 验收:给出启动者地址,或说明「该循环由已初始化的全局对象驱动、其构造在不可读区」。

### 步骤 3 — OOB 泵队列的 socket 生产者

- 目标:找出向 `0x0F8C50/0x0F8CF0/0x0F8D70` 之后、被 `0x621E50` 消费的队列写入字节者。
- 动作:定位队列结构地址(`0x621E50` 读取的全局/成员),对其做写入点扫描(数据流)。
- 产物:`evidence/049_T3_queue_producer.json`。
- 验收:给出把 `recv` 结果 `enqueue` 的函数,或负证据。

### 步骤 4 — 把结果回灌 047

- 若步骤 1–3 任一给出真实 opcode 读取点:在 `Protocol\OpcodeDispatcher` 中
  `RegisterProvenOpcode(opcode, handler, evidenceId)` 注册(必须带证据 id)。
- 若无:保持表为空,只更新 `ProtocolModuleReadiness` 的 `MinimumMissingFact`。

## 4. 明确不要做的事(避免重复劳动)

- 不要重查 TQOS(`0x85Dxxx`/`0x87xxxx`)—— 已两次定性为平台层。
- 不要重查 `EXE_LOSTRELIABLECOMMANDS` 的 13 个上游 —— 本轮已定性为错误上报。
- 不要用移动资料宽度表推官方线格式(`N-3`)。
- 不要把 `0x1C13A0`(连接无关)当作 in-match opcode 分派。

## 5. 前置授权与约束

- 步骤 1 若需新的只读快照,沿用已有只读流程(不启动客户端则需要单独授权)。
- 步骤 2/3 纯静态,无需授权。
- 步骤 4 的代码变更继续在 047 独立分支;禁止把猜测写进 `RegisterProvenOpcode`。

## 6. 交付判定

049 的完成标准:

1. P0 至少有**一个**可复核产物(步骤 1 或 2 或 3)。
2. 若定位到 opcode 读取点 → 必须给出完整指令链并注册到分派器;
   否则 `ProtocolModuleReadiness` 的断点描述更新为更精确的地址。
3. 构建 + 测试 + 历史不可变性仍全绿。
