# BLOCKERS — 目标客户端追踪阻塞项

**任务：** CODOL-TARGET-GAME-IDENTITY-008
**日期：** 2026-10-13（Asia/Shanghai）

---

## 0. 总体情况

目标游戏目录已核验，目标客户端身份已确认（**3.19.26.22 / 构建 1649370**）。
阻塞不再来自“找不到客户端”，而来自：**用户既定目标版本（3.9.9.7）与目标目录实际版本（3.19.26.22）不一致**，以及目标客户端的消费链尚未做函数级闭合。

---

## 1. 阻塞清单

### BLK-008-01 — 目标版本标签与用户既定目标不一致（P0，需用户裁定）

- 事实：用户指定目标目录 `COD OL` 的实际实例为 **3.19.26.22 / 1649370（2021-05-07）**；用户既定目标版本为 **3.9.9.7**。
- 证据：PE `VS_FIXEDFILEINFO FileVersion=3.19.26.22`；`TCLS\mmog_data.xml` `<Version>3.19.26.22</Version>`；WER `version: 3.19.26.22, time stamp: 0x6096930a`；`IIPS\IIPSFilelist.ini` 构建标签 `1649370.2021-05-07`。
- 影响：在裁定前，任何“目标版本协议字段”的定义都不确定；跨版本套用会产生错误实现。
- 最小解除证据：用户明确裁定目标版本（3.9.9.7，或确认采用目标目录实际版本）。

### BLK-008-02 — 本机不存在 3.9.9.7 客户端样本（P0）

- 事实：全工作区与目标目录中，`3.9.9.7` 字符串命中数为 0；无任何 3.9.9.7 版本资源、清单或样本。
- 影响：若目标确为 3.9.9.7，则无法开始目标客户端函数级分析。
- 最小解除证据：取得一个可复核的 3.9.9.7 客户端映像（含来源说明 + 完整 SHA-256）。

### BLK-008-03 — 目标客户端初始化链未做函数级闭合（P0）

- 事实：目标目录自建分析（`COD OL\docs`、`COD OL\scripts`）集中在 PE 结构、TVM0 解包、网络承载者识别与 socket 普查，**未**闭合“连接建立 → 初始化状态机”。
- 影响：无法确定目标客户端进入战斗的初始化条件。
- 最小解除证据：目标 DLL 上“收包入口 → 消息分派 → 初始化状态”调用链的指令级定位。

### BLK-008-04 — gamestate / configstring 消费入口未定位（P0）

- 事实：目标目录内无 gamestate（`0x03`）或 configstring（`0x04`）消费函数的定位证据。
- 影响：服务端 gamestate/configstring 写入无法与目标客户端读取对应。
- 最小解除证据：目标 DLL 中 gamestate/configstring body reader 的指令级定位。

### BLK-008-05 — snapshot 读取 / entity / delta 解码未定位（P0）

- 事实：目标目录内无 snapshot 消费链、entity 表或 delta 解码的分析。
- 影响：无法实现目标版本的 snapshot 帧边界、baseline、细增与实体增删。
- 最小解除证据：目标 DLL 中 snapshot 解码函数与字段读取顺序。

### BLK-008-06 — 目标客户端逐帧抓包绑定缺失（P1）

- 事实：仅有目标客户端族的 `pktmon.pcapng`（大厅/入口会话），无“具体帧 → 客户端函数”的绑定。
- 影响：无法把网络字节可靠映射到客户端解析函数。
- 最小解除证据：一次带函数级断点的抓包会话。

### BLK-008-07 — 客户端加壳导致静态字节不可直接当作运行时映射（P1）

- 事实：目标 EXE 被 TenProtect 加壳（`.tp3`×5 + `.tvm0`），主 DLL 亦含 `.tvm0`。
- 影响：磁盘文件字节 ≠ 运行时映射；静态 RVA 核验需在运行时镜像上进行。
- 最小解除证据：目标 EXE/DLL 的运行时解包镜像（EXE 目前无运行时镜像，仅主 DLL 有）。

### BLK-008-08 — 既有证据的版本归属需逐条重标（P1）

- 事实：007 及更早文档把目标目录客户端标为“3.3.3.3 族”，本轮已推翻。
- 影响：旧文档中“3.3.3.3”的 RVA/字段结论若被继续引用，会引入版本错误。
- 最小解除证据：对现有 RVA/函数表逐条标注其真实构建（1649370 vs 3.3.3.3）。

## 3. 解除顺序（建议）

1. **先解除 BLK-008-01**：由用户裁定目标版本与目标目录的关系。
2. **若目标为 3.9.9.7：解除 BLK-008-02**（取得目标样本）；否则以目标目录实例继续。
3. **再解除 BLK-008-07**：取得目标 EXE 的运行时镜像。
4. **再解除 BLK-008-03 / 04 / 05**：在运行时镜像上做初始化 → gamestate → snapshot 的函数级定位。
5. **最后解除 BLK-008-06 / 08**：逐帧绑定与旧证据重标。
