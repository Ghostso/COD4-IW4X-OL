**任务性质：** 对用户指定目标游戏目录 `D:\BaiduNetdiskDownload\使命召唤OL\COD OL` 的只读身份核验与文件关联。
**日期：** 2026-10-13（Asia/Shanghai）
**首要证据来源：** `D:\BaiduNetdiskDownload\使命召唤OL\COD OL`（用户指定）
**代码修改：** 无。正式服务器源码、FREEZE-005、原始游戏文件、既有逆向证据均未改动。新产物仅写入本目录。

## 1. 核心结论（必须先读）

1. **`COD OL` 目录存在且完全可读。** 递归实测 **2,973 个文件 / 139 个子目录 / 26,290,152,161 字节（≈24.5 GiB）**，扫描失败项 **0**。
2. **目标游戏版本可以确认，但它不是 3.9.9.7。** 该目录自身携带的版本证据一致指向：
   - 客户端 EXE 的 `VS_FIXEDFILEINFO FileVersion = 3.19.26.22`
   - `TCLS\mmog_data.xml` 的 `<Version> = 3.19.26.22`
   - Windows 错误报告（WER）对该二进制的记录为 `version: 3.19.26.22, time stamp: 0x6096930a`
   - `IIPS\IIPSFilelist.ini` 的 974 条资源 URL 全部指向构建标签 `Release2/1649370.2021-05-07.14-11-50`
   - PE 字符串资源 `FileVersion = 1649370`（构建号）
3. **目标客户端映像 SHA-256：**
   - 入口 EXE：`36997674b18f2896de5e9d755686f6922af10708f355175714058d0a0172b537`（7,841,344 B）
   - 主引擎 DLL：`ef75220de1d6973f34c7069f5bf211b11bd61520c6c0de1882f7359fa5bc6a20`（60,327,992 B）
4. **`3.9.9.7` 在目标目录中不存在任何证据。** 对全部 2,973 个文件、以及每一个 EXE/DLL（含 >4MB 文件的前 4MB）做 ASCII 与 UTF-16 子串扫描，**`3.9.9.7` 命中数为 0**。
5. **新发现此前未登记的客户端文件：** 目标目录中存在与主 DLL 同名但 **SHA-256 不同**的第二个 DLL 变体（`3d2b338d…`，与主 DLL 仅差 6 字节），位于 `.exe.local` / `.dll.local` 搜索顺序重定向目录内。
6. **对 007 结论的修正：** 007 将 `36997674…`/`ef75220d…` 标为 `PROBABLE`（3.3.3.3 族）。本轮判定：**哈希一致（保持成立）**，但 **“3.3.3.3 族”这一版本归属被推翻**——目标实例自身证据指向 **3.19.26.22 / 构建 1649370（2021-05-07）**，与 2015-06-15 的 3.3.3.3 QA 构建不同。

## 4. 八项验收标准回答

1. **`COD OL` 是否存在、是否可读、检查了什么？**
   存在且完全可读。递归检查了 2,973 个文件（含 570 个 PE、974 个 IFS 资源、659 个文本、10 个 .ff、31 个 demo），逐文件计算 SHA-256，并对全部 EXE/DLL 读取 PE 头与版本资源。

2. **是否找到此前没有登记的客户端映像？**
   **是。** 发现 007 未登记的主 DLL 变体 `3d2b338d…`（与已登记的 `ef75220d…` 同名、同大小、仅差 6 字节），位于 `.exe.local` / `.dll.local` 目录。入口 EXE 本身与 007 的 `36997674…` 逐字节一致（非新增）。

3. **目标游戏实际版本是否能够确认？依据是什么？**
   **能够确认。** 目标实例版本为 **3.19.26.22**（构建号 **1649370**，发布标签 **2021-05-07**）。直接依据：PE `VS_FIXEDFILEINFO FileVersion=3.19.26.22`、`TCLS\mmog_data.xml` 明文 `<Version>3.19.26.22</Version>`、WER 事件 `version: 3.19.26.22, time stamp: 0x6096930a`、`IIPS\IIPSFilelist.ini` 构建标签 `1649370.2021-05-07`。

4. **目标客户端的 SHA-256 是什么？**
   - EXE：`36997674b18f2896de5e9d755686f6922af10708f355175714058d0a0172b537`
   - 主 DLL：`ef75220de1d6973f34c7069f5bf211b11bd61520c6c0de1882f7359fa5bc6a20`
   - DLL 重定向变体：`3d2b338da69f2544fe29db8d3da3b3c2de92f5de9e8b5a9fb085a4c4ecc20dfd`

5. **现有逆向证据中，哪些可以可靠关联到该客户端？**
   - （已建立）`COD OL\docs\*.md`：对该目录 DLL 的 PE 结构 / 网络承载者分析（含 `protocol.md` 的精确节表）。
   - （已建立）`COD OL\scripts\*`：针对该 DLL 的反汇编/数据流脚本与输出。
   - （已建立）`run_codol_001\runs\vsd_callsite_20260929\codoMP_client_shipRetailBase.image.bin`：主 DLL 的运行时镜像（按模块名+尺寸+时间戳关联，非同哈希）。
   - （已建立）`run_codol_001\runs\...\pktmon.pcapng`：该族客户端的真实抓包。
   - （未建立）针对该客户端的初始化 / gamestate / configstring / snapshot 消费函数级定位。

6. **此前 007 的结论哪些保持成立，哪些需要修正？**
   - 保持：哈希登记一致；2.6.9.7 / 1.1.1.13 的 CONFIRMED 归属；3.9.9.7 无样本的总体结论。
   - 修正：007 把 `36997674…`/`ef75220d…` 判为 `PROBABLE`、并暗示“3.3.3.3 族”。本轮以目标目录自身证据将其 **升级为 CONFIRMED**，并把版本归属修正为 **3.19.26.22 / 1649370（2021）**，**推翻 3.3.3.3 标签**。

7. **是否已经具备继续追踪目标客户端初始化和 snapshot 的证据条件？**
   **部分具备。** 已具备：目标 EXE/DLL 身份、运行时镜像 dump、真实抓包、该 DLL 的 PE/节区与部分网络分析。仍缺少：目标客户端的初始化与 gamestate/configstring/snapshot 消费函数级定位（无目标版本的静态反汇编工程已闭合证据）。

8. **下一项最小工作是什么？**
