## 3. 证据不足原因

### 3.1 为什么不能直接实现 gamestate/configstring

- 目标只有解析函数族存在性证据。
- 字段宽度、顺序、索引编码、终止条件均未确认。
- 服务器已有 2697 写入链来自 2697 服务端证据，不是本目标客户端证据。
- 034 明确否定 `0x25/0x92` 禁用字节规则适用于目标。

### 3.2 为什么不能直接实现 snapshot

- 目标无 frame boundary、delta baseline、entity list、entity id 映射证据。
- TASK-009 的 snapshot RVA 列表已确认不适用于目标镜像。
- 现有 legacy 位流来源为旧抓包链路，不能冒充目标格式。
- 2697 snapshot 默认禁用是当前**正确**的保守处置。

### 3.3 为什么不能升级 OOB 状态机为 E2E

- 035 只实现了已确认子集。
- U-07 入站信封、U-09 报文长度仍未闭合。
- 3000/100/500 业务语义未确认。
- 未与真实客户端通信。

## 4. 最小验证方法（按优先级）

1. 复核 034 目标镜像哈希与地址约定。
2. 解析 `0x20059B` 的直接调用关系，定位所在函数入口。
3. 从该入口向上找调用者，向下找应用层消息分派。
4. 对 269 个 6 项跳表逐一验证是否绑定解析族。
5. 对 `0x6D060..0x6E0A0` 逐函数建立调用者/参数绑定。
6. 定位消息长度/终止条件；无证据部分保持 `UNKNOWN`。
7. 只在入口闭合后，重新评估 gamestate/configstring 或 snapshot 的下一步。

## 5. 当前可安全使用的结论

- 目标 EXE/DLL 哈希与固定基线一致。
- 目标 OOB 状态门、命令字面量、节流数值已有直接证据。
- 目标存在 configstring 解析族与增量类型表结构。

- gamestate、configstring、snapshot 的目标格式仍未闭合。
