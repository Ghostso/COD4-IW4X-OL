# NEXT_TASK_RECOMMENDATION — 下一任务唯一推荐项

**任务编号建议：** `CODOL-BATTLE-SERVER-APP-MSG-ENTRY-038`  
**目标版本：** CODOL 3.19.26.22 / Build 1649370  
**性质：** 只读静态逆向 + 独立离线测试夹具；不启动游戏，不做 E2E。

---

## 1. 唯一推荐

> **闭合目标版本“连接内应用层消息入口与 opcode 证据链”。**

即：

1. 从已确认的 `0x5F830 ← 0x208380 ← 0x1FF820` 调用链出发，向上定位 `0x20059B` 所在函数入口。
2. 以该入口为锚，定位 netchan 重组缓冲到应用层消息的分发点。
3. 定位服务端消息 opcode 的分派表（034 已扫描 269 个 6 项跳表，均未绑定；038 必须给出正面定位或明确反证）。
4. 把 gamestate、configstring、snapshot 的入口候选分别绑定到具体 RVA、调用者、参数与消息边界。
5. 输出可离线测试的“消息入口规格”和“边界测试夹具”。

**不**在本任务中实现新的 gamestate、configstring 或 snapshot 编码。  
**不**在本任务中启动游戏或做真实客户端 E2E。

---

## 2. 为什么选它

| 方向 | 证据成熟度 | 结论 |
|---|---|---|
| 连接建立后初始游戏状态编码 | 目标有明显解析族，但入口/字段未闭合 | 依赖消息入口 |
| configstring / gamestate 目标格式 | 只有函数存在与调用骨架 | 依赖消息入口 |
| snapshot/delta 边界与字段 | 只有类型表结构；帧边界/基线/实体全未知 | 依赖消息入口与类型语义 |
| 现有传输层与协议模块集成 | 服务器已接线；目标传输入口未证 | 传输入口可并列推进，但不直接产生“可解析游戏状态” |
| **应用层消息入口与 opcode** | `0x1FF820` 链已定位，是唯一贯穿各层的证据锚点 | **首选** |

选择依据：

- 它直接服务于本地战斗服务器目标。
- 它有明确的目标客户端证据入口：`0x1FF820`、`0x208380`、`0x5F830`、类型表 A/B。
- 它能在独立目录实施，不破坏 FREEZE-005。
- 它有确定输入、输出与离线验收标准。
- 它不依赖猜测字段，只做证据定位与边界夹具。
- 它是 gamestate/configstring/snapshot 实现的前置条件。

## 4. 实施范围

### 4.1 必须做的静态工作

1. **复核锚点**
   - `0x5F830` 入口、两张类型表、`cmp idx, 0x139` / `cmp idx, 0x87`。
   - `0x208380`、`0x1FF820` 入口与读写字段。
2. **向上定位**
   - 解析 `0x20059B` 的直接调用关系，找到所在函数入口与调用者。
   - 解析该函数参数来源，判断是否来自 netchan 重组缓冲区。
3. **向下绑定**
   - 定位 netchan 重组缓冲区到应用层消息入口。
   - 定位应用层消息 opcode 比较/跳转表。
   - 对候选表逐项验证合法目标是否在函数序言。
4. **入口函数语义**
   - 为 `0x6D060 / 0x6D360 / 0x6DAE0 / 0x6DCF0 / 0x6E030 / 0x6E0A0` 建立调用者/被调用者与参数绑定。
   - 判定哪些属于 gamestate、哪些属于 configstring；无法判定必须标 `UNKNOWN`。
5. **边界证据**
   - 消息长度字段、终止符、下一消息起点。
   - 字段读取顺序、位宽、默认值；无证据不得填。
6. **负结论**
   - 明确记录哪些猜测被排除（例如 TASK-009 RVA 列表）。

### 4.2 明确不做

- 不实现 gamestate/configstring/snapshot 编码。
- 不修改正式服务器。
- 不启动游戏。
- 不新增抓包。
- 不用合成数据宣称兼容性。
- 不把形式相似当作版本相同。

## 6. 验收标准

以下全部满足才算完成：

1. `0x20059B` 所在函数入口被定位，或给出“无法定位”的系统性反证与已排除范围。
2. 应用层消息入口与 netchan 重组缓冲之间的绑定有目标 RVA 证据。
3. opcode 分派表被正面定位，或对所有候选给出逐项排除证据。
4. `0x6D060 / 0x6D360 / 0x6DAE0 / 0x6DCF0 / 0x6E030 / 0x6E0A0` 至少完成调用者/被调用者绑定；能确认的语义升格，不能确认的保持 `UNKNOWN`。
5. 消息边界规格中的每一项都能追溯到目标二进制字节或 034 原始输出。
6. 离线测试覆盖：地址约定复核、类型表边界、调用链、入口绑定、反证清单。
7. 所有测试有命令、退出码、原始输出。
8. 未修改 FREEZE-005、正式服务器、原始资产。
9. 明文声明“未做真实客户端 E2E”。
10. 下一任务可直接据此选择“gamestate/configstring 目标格式实现”或“snapshot 边界实现”。

## 7. 阻塞条件

出现以下任一情况，任务应阻塞而不是猜测：

- 目标镜像哈希与 034 不一致。
- `0x20059B` 所在区域无法恢复函数边界，且无替代证据链。
- opcode 分派表需要动态观测才能定位，但未获授权。
- 关键字段只能通过其他版本惯例推断。
- 需要启动游戏或真实客户端抓包才能继续。
