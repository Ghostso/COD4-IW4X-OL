| 字段 | 偏移 | 原始字节 | 值 |
|---|---|---|---|
| `schemaVersion` | `0x19..0x1B` | `31` | **1** |
| `titleId` | `0x22..0x25` | `31 30 30 34` | **1004** |
| `gameVersion` | `0x38..0x39` | `34 32` | **42** |

### ★★ 关键字节事实

1. **`zoneId = 83886082`** → `0x05000002`
   ```
   83886082 = 0x05000002
              └─ 高字节 0x05 = 5
                 └─ 低 24 位 0x000002 = 2
   ```
2. **`platformUserId` 是**文本 16 字符**不是二进制 8 字节**：
   ```
   30 31 31 30 30 30 30 31 44 45 41 44 43 30 44 45
   '0' '1' '1' '0' '0' '0' '0' '1' 'D' 'E' 'A' 'D' 'C' '0' 'D' 'E'
   ```
   ★ **ASCII 十六进制串**，不是 `01 10 00 01 DE AD C0 DE`。
   **所以 `int(x, 16)` 才能得到 `0x01100001DEADC0DE`。**
3. **换行全是 `0A`（LF），无 `0D`** —— 该文件是 **LF 换行**
4. **末尾 `0A` 后无内容** —— 文件以换行结尾
5. **`titleId` 与 `zoneId` 的关系**：
   ```
   titleId   = 1004 = 0x03EC
   zoneId    = 83886082 = 0x05000002
   ```
   ★ **`0x03EC` ≠ 1002（`0x03EA`）** ——
   **`preflight.ps1` 写的 `dwauth.ini` 里那个 `0x03EA` 与此无关！**

## 九、换行符的完整对照表（★★ 逐字节发现的重要事实）

| 文件 | 大小 | 换行 | 末尾换行 |
|---|---|---|---|
| `Platform.json` | 256 | **LF (0A)** | ✓ |
| `Identity.json` | 34 | **LF (0A)** | ✓ |
| `selected_playlist.txt` | 17 | **无** | ✗ |
| `broadcast.info` | 23 | **无** | ✗ |
| `activities_v1.info` | 2 | **无** | ✗ |
| `market-down.info` | 90 | **CRLF (0D 0A)** | ✗ |
| `whitelist_tester.info` | 93 | **CRLF (0D 0A)** | ✗ |
| `tlogconfig.info` | 154 | **CRLF (0D 0A)** | ✗ |

★★★ **三种风格并存**：
```
.json  → LF，有末尾换行
.txt/.info（短） → 无换行
.info（INI 形态） → CRLF，无末尾换行
```

★ **说明这些文件来自**不同的生产者**：
- JSON 由 Python/PowerShell 生成（LF）
- 短文本由手写或 C++ 常量（无换行）
- INI 由 **Windows 侧**生成（CRLF）

★★ **这是"客户端不校验换行"的间接证据** ——
**否则混用会导致某一类文件失效。**

## 十一、`zoneId = 83886082` 的拆解

```
83886082 = 0x05000002
                ║  ║
                ║  └── 0x0002 = 2
                └───── 0x05 = 5
```

★★ **字节序（大端读）**：`05 00 00 02`
★★ **字节序（小端读）**：`02 00 00 05` = 33554437

★ **CODOL 的 zoneId 语义未知**，但 `0x05xxxxxx` 形态暗示：
- 高字节 = 区域类型/版本
- 低位 = 具体 zone 编号

★ **`titleId = 1004 = 0x03EC`** 与 `zoneId` 无直接算术关系。

## 十二、报告 016 的 `0x03EA` 疑问已解

报告 016 问："`dwauth.ini` 的 `0x03EA` = 1002 vs `titleId` 1004"。

**逐字节对照**：
```
Platform.json:  titleId = 1004 = 0x03EC
preflight.ps1:  dwauth.ini 第三行 = 0x03EA = 1002
```

★★ **差 2** —— 但不是同一个字段。
★ **`dwauth.ini` 的 `0x03EA` 可能是**另一层 ID**（zone/app id），
与 `titleId` 无必然关系。**

★★ **结论：不是矛盾，是不同字段。报告 016 的"待验证"可以关闭。**

## 十三、这一块（逐字节）的结论

### 已确证（实测字节）

1. **`platformUserId` = ASCII 文本 `"01100001DEADC0DE"`（16 字符）**，不是 8 字节二进制
2. **`zoneId = 83886082 = 0x05000002`**
3. **`titleId = 1004 = 0x03EC`**（与 `dwauth.ini` 的 `0x03EA` **无关**）
4. **`Identity.json` = `{"username":"Alwaysoffline"}`** ⇒ **交付包实际名字是 `Alwaysoffline`**
5. **换行三种风格并存**（LF / 无 / CRLF）⇒ 客户端不校验换行
6. **`activities_v1.info` 是 2 字节空格**，不是 0 字节
7. **`market-down.info` 的时间窗口是 2019-09-27 30 分钟**（早已过期 = 商城冻结）
8. **`broadcast.info` 的时间戳是 2019-10-05**（过期公告）
9. **白名单三个 u64 userid**（最大 20 位十进制，仍在 u64 范围内）
10. **`tlogconfig.info` 有一个小数 `dwdsmm_slope=1.9`**
