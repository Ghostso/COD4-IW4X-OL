## 二、★★★ 三个独立的初始化标志（按地址排序）

### 实测的 `C6 05 <addr> <val>` 写入点（全文搜索）

```
file 0x0C3DB8  →  RVA 0xC49B8    mov byte [0x1069703C], 0x00
file 0x0C8C84  →  RVA 0xC9884    mov byte [0x1069703C], 0x00
file 0x0C9D7F  →  RVA 0xCA97F    mov byte [0x1069703C], 0x01    ← ★
file 0x1EC5CA  →  RVA 0x1ED1CA   mov byte [0x10697028], 0x01    ← ★
file 0x21208D  →  RVA 0x212C8D   mov byte [0x10697029], 0x00
file 0x216F2C  →  RVA 0x217B2C   mov byte [0x1069702A], 0x01    ← ★（本报告新增）
```

★★★ **六个写入点覆盖四个不同地址：**

| 地址 | 写入值 | 位置 | 用途 |
|---|---|---|---|
| `0x10697028` | `1` | RVA `0x1ED1CA` | 标志 D |
| `0x10697029` | `0` | RVA `0x212C8D` | 标志 E（清零） |
| **`0x1069702A`** | **`1`** | **RVA `0x217B2C`** | **★★★ 本报告发现** |
| `0x1069703C` | `0`/`0`/`1` | RVA `0xC49B8`/`0xC9884`/`0xCA97F` | 标志 F |

★★★ **注意：`0x10697027`（报告 031/032 说的就绪标志）**没有**出现在这个搜索里** ——
**因为它**只读不写**（`cmp byte ptr [10697027h], 0`）。**

★★ **⇒ `0x10697027` 由**别的方式**写入（可能是 `mov [mem], al` 的寄存器形式）。**

## 六、结论

### 1. ★★★ 初始化是**分层的**，不是单一布尔

```
[0x10697027]  外层：整个 Init 是否跑完
[0x10696770]  内层 A：第一步（call 0x63D60）是否成功过
[0x1069702A]  内层 B：配置读取（call 0xE3963）是否跑过
```

★ **⇒ 换战斗服时，这些标志的语义必须一致，否则重复初始化或跳过初始化。**

### 2. ★★★ 6 个模式字符串是关键未知

```
0x1051CA30 / 0x51C9C8 / 0x51CA9C / 0x51CAAC / 0x51CABC / 0x51CAD0
```

★★ **读它们就能知道外部战斗服支持哪 6 种模式。**

★ **这直接回答"换战斗服要支持哪些 gametype"。**

### 3. ★★ `0x10805098` 配置块是"模式 × 参数"的落点

★★ **8 字节：4 字节模式号 + 1 字节标志 + 2 字节 + 1 字节。**
