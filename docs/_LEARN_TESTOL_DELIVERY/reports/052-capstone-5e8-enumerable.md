# 学习报告 052 — capstone 扫描：`0x5E8` 只有 6 处引用（可穷举）

**方法**：全内存搜 `[reg+disp32]` 且 `disp32 ∈ {0xC8, 0x5E8}` + capstone 回解
**性质**：权威反汇编 + 全内存扫描
**★★★ 本报告确立了 `0x5E8` 是**可穷举**的 LSG 状态字段**

---

## 一、★★★ `0x5E8`（LSG state）—— **只有 6 处**

```
00598361  8b81e8050000    mov eax, [ecx + 0x5e8]       ← 读
006E1246  89bee8050000    mov [esi + 0x5e8], edi       ← 写
006F42FB  899ee8050000    mov [esi + 0x5e8], ebx       ← 写
00BA2984  899ee8050000    mov [esi + 0x5e8], ebx       ← 写
00BA3251  00c7            add bh, al                   ← 假命中
00BA44E8  8b86e8050000    mov eax, [esi + 0x5e8]       ← 读
```

★★★ **⇒ 真实引用 **5 处**：2 读 + 3 写。**

### ★★ 已知的写入点（报告 051 已见）

```
0xBA3460  mov [esi+0x5E8], 0   ← 清理（state = 0）    ★ 报告 051 已见，但未在此列表？
0xBA3C47  mov [esi+0x5E8], 3   ← P4 成功（state = 3）  ★ 报告 051 已见
```

★★ **但本次扫描只找到 `0xBA2984` / `0x6E1246` / `0x6F42FB`。**

★★★ **⇒ `0xBA3460` 和 `0xBA3C47` 用的是**另一种编码**（`c786...` 带 imm32），
我的扫描模式（`89 /r` 且 `mod=10`）**只覆盖了寄存器源**，没覆盖立即数源。**

★★ **⇒ 需要补扫 `C7 /0 mod=10`（`mov [reg+disp32], imm32`）形式。**

## 三、★★★ 补齐扫描：`C7 /0` 立即数形式

### 已知的两个（报告 051 反汇编）

```asm
00BA3456  c786c800000004000000   mov dword ptr [esi + 0xC8], 4
00BA3460  c786e805000000000000   mov dword ptr [esi + 0x5E8], 0
00BA3C47  c786e805000003000000   mov dword ptr [esi + 0x5E8], 3
```

★★★ **⇒ 这三个是**立即数写**，编码是 `C7 86 <disp32> <imm32>`（7+4 = 11 字节）。**

★★ **我的扫描模式（`89 /r`）**漏掉了它们**。**

★★★ **⇒ 完整的 `0x5E8` 写入点应该是 5 处**：
```
0x6E1246  mov [esi+0x5e8], edi          （寄存器）
0x6F42FB  mov [esi+0x5e8], ebx          （寄存器）
0xBA2984  mov [esi+0x5e8], ebx          （寄存器）
0xBA3460  mov [esi+0x5e8], 0            （立即数）★ 清理
0xBA3C47  mov [esi+0x5e8], 3            （立即数）★ P4 成功
```

### ★★ 加上 2 处读

```
0x598361  mov eax, [ecx+0x5e8]
0xBA44E8  mov eax, [esi+0x5e8]
```

★★★ **⇒ `0x5E8` 全生命周期只有 **7 处访问**（5 写 + 2 读）。**

## 四、★★★ 这 7 处构成了完整的 LSG 状态机

### 写入点分析

| 地址 | 值 | 上下文 |
|---|---|---|
| `0x6E1246` | `edi` | 待查（可能 `0x6E458B` 同函数） |
| `0x6F42FB` | `ebx` | 待查 |
| `0xBA2984` | `ebx` | ★ 与 P4 同区（`0xBAxxxx`） |
| `0xBA3460` | **`0`** | ★ 清理（`0xBA3420`） |
| `0xBA3C47` | **`3`** | ★★★ P4 成功 |

### ★★ 读点分析

| 地址 | 用途 |
|---|---|
| `0x598361` | 待查 |
| `0xBA44E8` | ★ 与 P4 同区，可能是状态查询 |

★★★ **⇒ `0xBA2984` / `0xBA3460` / `0xBA3C47` / `0xBA44E8` 全在 `0xBAxxxx` 区
⇒ 同一类的方法。**

★ **`0x6E1246` / `0x6F42FB` 在 `0x6Exxxx` 区** —— **另一组代码（可能是网络层）。**

## 五、★★★ 这对"换战斗服"的直接意义

### 结论 1：★★★ `0x5E8` 是**唯一可穷举**的 LSG 状态字段

★★★ **⇒ 如果我们自己实现战斗服，必须正确设置这 5 个写入点的语义。**

★ **但**换战斗服不需要碰 LSG 状态**（那是 `Alwaysoffline` 的职责）。**

★★ **⇒ 这个字段与我们的任务**解耦**。**

### 结论 2：★★★ `0xC8` 无法穷举（通用偏移）

★★ **⇒ 不要试图通过 `0xC8` 定位 svc。**

★ **用 `0x8269774`（svc 指针）+ 上下文筛选。**

### 结论 3：★★ 扫描方法需要扩展

★★ **`89 /r` 只覆盖寄存器源；`C7 /0` 覆盖立即数源。**
**必须两种都扫。**

## 七、结论

### 1. ★★★ `0x5E8` 全生命周期只有 **7 处**访问（5 写 2 读）

```

0x6F42FB  ← ebx（待查）
```

★★ **⇒ 需要查前三个的 `edi`/`ebx` 实际值。**

★ **必须结合 `0x8269774` 上下文。**
