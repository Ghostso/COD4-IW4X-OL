## 二、`--apis` 的 `zN` 占位机制（行 1357-1361）

```python
apis = [x for x in a.apis.split(",") if x and not re.fullmatch(r"z\d+", x)]
for d in a.direct.split(","):
    if d.strip():
        apis.append("@" + d.strip())
```

**`z1`、`z2` 这类名字会被过滤掉**（`re.fullmatch(r"z\d+", x)` 匹配则排除）。

**为什么需要 zN**：注释说"只为把代码洞/cnt 槽位预留出来，不当 hook 装"。

★ **这暗示一个重要事实**：代码洞和计数器槽位是**按 apis 列表的顺序分配的**。
如果列表里少了几个，后面所有 hook 的槽位就前移了。
**`zN` 是用来保持槽位编号稳定的占位符。**

`--direct` 里的项会加 `@` 前缀，走"直接地址"路径。

## 三、注入开关 —— 本段最重要的发现（行 1373-1374）

```python
_inject = (os.environ.get("NT10_INJECT") == "1") or os.path.exists(
    os.path.join(os.path.dirname(os.path.abspath(__file__)), "inject_ayria.on"))
```

### 判定逻辑

**两个条件任一成立即注入**：
1. 环境变量 `NT10_INJECT == "1"`
2. **同目录存在 `inject_ayria.on` 文件**

### ★★ 交付包里的实际情况

`bundle\` 目录里**没有** `inject_ayria.on`（我第一轮就验证过），
`run.cmd` 也**没有设** `NT10_INJECT`。

**⇒ 默认不注入。**

### 但注释说了为什么需要注入（行 1367-1371）

> **为什么需要**：游戏服务端是注入式插件 `Ayria\Plugins\CodolGameServer.Localnet32`，
> **不注入就不会加载** ⇒ 靶场卡「等待链接」。

### 这是一个矛盾

| 事实 | 结论 |
|---|---|
| 注释说"必须注入，否则卡等待链接" | 注入是必需的 |
| 代码默认 `_inject = False` | 默认不注入 |
| 包里没有 `inject_ayria.on` | 不会注入 |

**可能的解释**：
1. 包的设计者认为**某些场景**不需要注入（比如只观察网络，不打对局）
2. **漏掉了**这个文件（打包时遗漏）
3. 有别的路径会创建这个文件（比如 `launch_chain.py` 的某个分支）

★ **需要继续读 `launch_chain.py` 确认它是否创建 `inject_ayria.on`。**
这是理解包能否正常工作的关键。

## 四、注入后的 PID 问题（行 1370-1371）

> 注意：注入后 **pid 必须重新按进程名找** —— 注入器的 pid 不是游戏 pid，
> 而后续 TAS 注入 / 内存读会话密钥都依赖**真游戏 pid**。

★ **这是注入式启动的核心陷阱**：
- `subprocess.Popen([Injector32.exe, ...])` 返回的 `p.pid` 是**注入器**的 pid
- 真正的游戏进程是注入器**创建**的，pid 不同
- 所有后续操作（`OpenProcess`、`ReadProcessMemory`）都指向错误的进程 → 全部失败

**解法**：调 `tasklist`/`CreateToolhelp32Snapshot` 按**进程名**找真正的游戏进程。

## 五、坏启动重试（行 1363-1364）

> 这台机器上"坏启动"(`0xC0000005` @ t≈2s)概率约 **20-40%**，
> 只要在启动后 **4s 内**就退出，就直接重新拉起。

★★ **这是一个重要的实测数据**：
- 崩溃率 20-40%
- 崩溃时间点 t≈2s
- 判定标准：4 秒内退出

**这与我的经验不符** —— 我跑的时候是稳定 27 秒后退，不是 2 秒崩溃。
说明**我跑的环境和作者的环境不同**（可能是 ACE 状态、客户端的 `.tp3` 解壳状态等）。

★ 也可能：作者说的"坏启动"是**早期**问题，后来修好了（这个版本的注释是 2026-10-05 的）。

## 六、这一块的结论

1. **`--mutex` 是 Global 命名空间**，与客户端的多开保护相关。
2. **`zN` 占位符保持槽位编号稳定** —— 代码洞按顺序分配。
3. **注入默认关闭**（需要 `inject_ayria.on` 或 `NT10_INJECT=1`），
   但注释说**不注入插件就不加载** ⇒ **包可能缺这个文件**。
4. **注入后必须重新找真游戏 pid**，这是核心陷阱。
5. **坏启动率 20-40%，t≈2s** —— 与我实测的 27s 退出不同，需要解释。
