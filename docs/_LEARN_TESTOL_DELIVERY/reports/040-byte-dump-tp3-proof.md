**★★★ 本报告用 5 份独立转储坐实了 `.tp3` 加密假说**

## 三、★★★ 完整的解壳对比

### 磁盘（`.tp3` 节，加密态）

```
0x8370E: 00
0x8370F: 83 C4 04           add  esp, 4
0x83712: E8 15 14 78 00     call ...
0x83717: 00                 （填充/null）
0x83718: D9 45 10           fld  dword ptr [ebp+10h]    ← ★ 看起来像浮点
0x8371B: 8B 4D 08           mov  ecx, [ebp+8]
0x8371E: 8B 55 0C           mov  edx, [ebp+0Ch]
```

### 运行时（解壳后）

```
0x48371A: 83 7C 24 08 01     cmp  dword ptr [esp+8], 1   ← ★★★ 真实指令
0x48371F: 0F 94 C0           sete al
0x483722: 33 F6              xor  esi, esi
0x483724: 89 35 9C B2 C2 01  mov  [0x1C2B29C], esi
```

★★★ **两段**几乎完全无关** —— 磁盘上是 `fld`/`mov`，运行时是 `cmp`/`sete`/`xor`/`mov`。**

★★ **⇒ `.tp3` 不是简单的字节置换（XOR/ROT），是**真正的加密段**（压缩/加密后解壳）。**

## 五、★★★ 补丁的最终定案

### 目标函数（`0x48371A` 之前的某处）

```asm
...                         ; 函数序言 + 前面逻辑
0x483713:  call <something>
0x483718:  add  esp, 4
0x48371A:  cmp  dword ptr [esp+8], 1     ← ★ 原指令（模式 B）
0x48371F:  sete al
0x483722:  xor  esi, esi
0x483724:  mov  [0x1C2B29C], esi
```

★★ **`[esp+8]` 是**第一个参数**（因为 `add esp,4` 刚清掉一个）。**

★★★ **⇒ 这是一个接收 1 个参数的函数，返回布尔值（`al`）。**
**逻辑：`return (arg0 == 1);`**

### 补丁后

```asm
0x48371A:  mov  al, 1        ← B0 01
0x48371C:  nop; nop; nop; nop; nop; nop   ← 90 ×6
```

★★★ **⇒ 无条件 `return 1;`**

### ★ 但注意后续指令

★★ **补丁只覆盖 8 字节（到 `0x483722`），
`0x483722` 的 `33 F6`（`xor esi,esi`）**仍然执行**。**

★★ **然后 `0x483724` 的 `mov [0x1C2B29C], esi`（写 0）也执行。**

★★★ **⇒ 补丁后的语义是**：
```c
al = 1;                    // 返回值恒真
x = 0;                     // 副作用仍发生
*(0x1C2B29C) = 0;
return al;                 // → 1
```

★ **⇒ **副作用保留，返回值强制。** 这是**最小侵入**的补丁设计。**

## 七、结论

### 1. ★★★ `.tp3` 加密假说获得**字节级铁证**

★★★★ **同 5 份独立转储、同一 VA、磁盘与运行时完全不同 ⇒ 确定性解壳。**

### 2. ★★★ 所有客户端静态分析的正确方法

```
✗ 读 codoMP_client_shipRetail.exe（.tp3 是加密的）
✓ 读 mem_000.bin（运行时解壳后）
   VA - 0x400000 = 文件偏移
```

★★★ **⇒ 这条规则必须写入记忆，避免以后重复踩坑。**

### 3. ★★★ 补丁语义定案

```
原语义： return (arg0 == 1);
补丁后： al = 1; （跳过判断）; 保留后续副作用
```

★ **这是 `OLMOD_ALLOW_UNSIGNED_FASTFILES` 的一个子步骤，
与换战斗服无关。**

### 4. ★★ 插件能正常工作**正是因为**它读运行时内存

★★ **如果它读磁盘文件，会被 `.tp3` 加密挡死。**
**⇒ 这也说明外部包作者**已经知道** `.tp3` 的存在。**
