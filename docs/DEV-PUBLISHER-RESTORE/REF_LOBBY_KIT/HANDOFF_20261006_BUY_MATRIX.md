# 购买成败矩阵 —— 2026-10-06 实测

## 一句话

**能不能买，只取决于该 SKU 在不在 `marketplace-catalog.json` 里。**
和类别(武器/名片/道具)、货币(CP/GP)都无关。

## 实测矩阵

同一次会话里, 用户连续点了多件。服务端日志(带库存件数变化):

**"武器能买、名片道具不能买"的真正原因不是类别, 而是:**
用户点的那批武器 SKU 恰好在 exe 目录里, 那批名片/道具 SKU 恰好不在。

## 编号体系是一致的(排除"两套编号"的猜测)

exe 目录 SKU 范围 1 .. 49605, 按 5000 分段都有大量条目:

```
    0- 4999 : 1414 条
 5000- 9999 :  566 条
10000-14999 : 4581 条
15000-19999 : 4510 条
20000-24999 : 4450 条      ← 成功购买的 22251/22255 在这段
25000-29999 : 4482 条
30000-34999 : 4488 条      ← 成功购买的 31726/31847 在这段
35000-39999 : 4599 条      ← 失败的点 37116/37251/37253 也在这段(但不在目录)
40000-44999 : 4491 条
45000-49999 : 4034 条
```

失败的 SKU 和成功的 SKU **落在同一批区间里**, 不是编号错位。
而且 `39115` 这种被点过的 SKU **就在目录里** —— 说明不是整体缺失。

## 因此

`marketplace-catalog.json`(exe 反射提取的 37615 条)**覆盖面不够**:
它包含 29315 条 Category=1(外观) 和 4283 条 Category=3(武器),
但**缺少用户实际能点到的那些 SKU**(37116/37251/16096/19428/31184/...)。

这些 SKU 是**真实 SKU**(购买帧格式与成功帧逐字节相同),
只是不在 exe 内嵌目录里 —— 与之前的结论一致:
**exe 目录是旧版/不完整版本, 与客户端实际使用的商城有差异。**

## 下一步

只剩一条可走的路: **拿到客户端实际使用的商城目录**。
客户端内部用 `AS_GetProductIDFromSKU` / `AS_GetItemIDsFromProduct` 查,
这两个函数的数据源就是**客户端运行时加载的商城表**。

可选路径:
1. 运行时挂钩 `AS_GetItemIDsFromProduct`, 抓 SKU → itemID 的真实映射
   (最直接, 且能顺带确认 Category)
2. 或找到客户端加载商城表的位置, 直接在内存里 dump 整张表
