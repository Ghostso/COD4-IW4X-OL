## 02. 问题的精确定义

**预期行为**
服务端能构造出被客户端解析、并据以更新房间状态的下行消息。

**实际行为**
- 消息确实发出（推送帧 `0x85` body=68/64/68 → 后为 106/130/54）
- 客户端**无报错、无断连**
- 出现过一次可观测行为差异（大厅任务数 85→71、`11/4` 上行 6→4 次、20 B 批次消失）
- 但**房间 UI 是否点亮未确认**，战斗服仍零 RX

**偏差**
"有反应"≠"被正确解析"。目前连"是否被解析"都未证。

**失败边界（逐层）**

| 层 | 结论 |
|---|---|
| 服务端是否构造 | ✅ |
| 是否发送 | ✅（推送日志） |
| 客户端是否收到 | ✅（TCP 不断） |
| 客户端是否解析 | **UNKNOWN**（没有日志、内存不可读） |
| 客户端状态是否转换 | **UNKNOWN**（UI 需人眼） |
| 是否影响连接 | ❌ 零 RX |

## 03. 历史发现过程（四次反转）

| 轮次 | 结论 | 依据 | 被谁推翻 |
|---|---|---|---|
| 第 1 轮 | 房间消息走 **Demonware 位流**（离线 5/5 通过） | `RoomMessage::serialize` 反汇编 | 第 9 轮 |
| 第 9 轮 | 房间消息**不走位流** | 7 条上行样本 × 160 bit 偏移穷举，零命中 | 第 11 轮（**只对上行成立**） |
| 第 11 轮 | **上行≠下行**：上行容器、下行走位流 | `0x637000` 用 `(ptr,len*8)` 直接建流 | 第 13 轮 |
| 第 13 轮 | `type 0x02` 是 `dwRoomMessageText`，不是通用分发 | `0x63495A` → `0x625940` → vtable `0x00DC7504` | — |

**当前定论**：
- **上行**：`02 <sub> 0000 <u32 len>` / `18 …`。不是位流。**已用穷举证否**。
- **下行**：由各 `RoomMessage::deserialize` 读**位流**。`0x637000` 实测按位建流。

**但下行是否被客户端接受，仍未证。**

## 09. 根因分析

| Hypothesis | 解释 | 支持 | 反对 | 状态 |
|---|---|---|---|---|
| **H1** 下行格式正确，但内容字段不足以点亮按钮 | 缺客户端从没发过的字段 | 客户端确实处理了（行为差异） | 未确认 | 中可信 |
| **H2** 下行格式仍有错，客户端读出垃圾但静默忽略 | 位宽/字段序错 | 4 次反转说明这块很难 | 离线对拍 5/5 | 中可信 |
| **H3** 信封路由键不对（`obj+8`≠roomId） | 见 ISSUE-0011 | 信封仍未定死 | 行为差异说明至少部分被处理 | **高可信（与 H1 并列）** |

**裁决**：H1/H3/H4 三个都无法排除，且它们指向完全不同的修复方向。

## 18. 最终技术结论

**当前状态**：`CONTRADICTORY_EVIDENCE`。上下行格式已区分清楚，但下行是否被接受未证。

**已经证明的事实**：
1. 上行不是位流（穷举 160 bit 偏移零命中）。
2. 下行走位流（`0x637000` 按位建流）。
3. type 0x02 是 Text（vtable `0x00DC7504`）。
4. 改回位流后出现过一次可观测行为差异。

**尚未证明的事实**：客户端是否成功解析了我们发的下行消息。

**第一条未闭合证据链**：`0x637000` 建流之后 `readBits(3)==3` 是否成立。

**当前最可信根因**：**无法给出**。H1（内容不足）/H3（信封路由）/H4（回声忽略）并列。

**下一步最小实验**：**E8 畸形对照**。

**最小修复条件**：E8 的结果。

**完成验收标准**：§16。

**是否可以交给开发 Agent 直接修复：NO**
必须先完成：**E8**。在此之前所有格式调整都是盲调——这正是 10-28 一天内反转四次的原因。
