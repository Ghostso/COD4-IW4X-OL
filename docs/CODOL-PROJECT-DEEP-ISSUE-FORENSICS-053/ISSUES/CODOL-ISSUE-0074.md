## 02. 问题的精确定义

**预期行为**
客户端用 `102/7` 批量读 playerdata 字段（0..49），服务端回显**客户端真实的选择状态**
（PvE 关卡、PvP 模式、根索引等），客户端据此在 UI 上保持"已选中"。

**实际行为**

| 尝试 | 应答 | 客户端反应 |
|---|---|---|
| 第 1 次（2026-10-27 早） | 解析错，回 0 字段（2 B） | 每 5 秒重发 |
| 第 2 次（2026-10-27 20:24） | 解析对，回 50/50 字段**值全 0**（555 B） | **仍然每 5 秒重发** |
| 第 3 次（2026-10-28 起） | 改为"保持不处理"（空 ACK） | 不再每 5 秒重发；仍零 RX |

**偏差**
服务端"回答"了，但回答的内容是"你什么都没选"。

**失败边界（逐层）**

| 层 | 结论 |
|---|---|
| 请求是否发出 | ✅ `102/7` 请求 556 B |
| 服务端是否收到 | ✅ |
| 服务端是否解析 | ✅（第 2 次起） |
| 响应是否生成 | ✅ 555 B |
| 客户端是否收到 | ✅（TCP 不断） |
| 客户端是否解析 | ❌ **"每 5 秒重发"= 客户端认为应答无效** |
| 客户端状态是否转换 | ❌ 未见 |

**失败边界一句话**：客户端**拒绝**了这份 555 B 应答（重发即证据），但服务端无从知道原因。

## 05. 源码级定位

**文件**：`CODOL_VERIFIED_GOLDEN_20261019/lobby_server.py`
**位置**：行 1181–1226

```python
# 102/7  08 <count> 然后重复 count 次: 03 01 0A <idx u32> <val u32>
...
cnt = ...
if cnt > 64: return [], "102/7 count=%d 太大" % cnt, []
out = bytearray()
for i in range(cnt):
    ...
return [bytes(out)], ("storage 102/7 ★ 回显 %d/%d 个字段(值=0) %dB" ...)
```

| 项 | 值 |
|---|---|
| 输入 | `102/7` payload（count + idx 列表） |
| 输出 | 一个 object（555 B） |
| 副作用 | 无 |
| 失败返回 | 格式不认识 / count 过大 → 空 ACK |
| 与 Issue 的关系 | 它是"回显 0"的实现；**它把 `val` 恒写 0** |

**关键缺陷（源码级）**：实现里 `val` 恒为 0，**没有任何从客户端真实状态读值的路径**。
也就是说，即便回显 50/50 字段，也等价于"全部未选"。
