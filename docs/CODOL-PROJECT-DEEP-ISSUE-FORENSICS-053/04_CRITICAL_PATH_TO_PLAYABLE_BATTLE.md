# 04 — 通往可玩战斗的最短关键路径

---

## 1. 目标定义

**可玩战斗**（沿用 `INMATCH_COMPLETENESS_GAP_MATRIX` 的门槛）：
同一客户端 PID 内完成 进图 → 移动 → 开火 → 命中 → 受伤 → 死亡 → 复活 → 计分 → 结束。

**本文件只关心前两步**：进图 + 移动。
因为后面的全部依赖它们。

---

## 2. 当前所在位置

```
[1] 客户端启动                ✅ 可复现（iips.ini + 冻结 kit）
[2] 进大厅                    ✅ 可复现
[3] 建房对象出现              ✅ 可复现（memberCount=1）
[4] 客户端连战斗服            ❌ ← 当前卡在这里
[5] UDP 握手                  ✅ 协议可用（10-26 证明）
[6] GameState 下发            ✅ 发送可用；消费只到 C-bytes
[7] Snapshot 被接受           ✅ C-state（历史）
[8] 进图                      ✅ 历史（10-24/25，run 目录已不在盘上）
[9] 移动被服务端看到          ✅ usercmd 19022 条
[10] 位置由服务端决定         ❌ ISSUE-0025
[11] 实体可见                 ❌ ISSUE-0024
```

**关键**：第 8 步曾经成立，但它们是在**第 4 步成立**的前提下发生的。
现在第 4 步不成立，所以第 5–9 步都**无法复现**。

---

## 3. 最短路径（三步）

### 第 1 步：恢复第 4 项（客户端连战斗服）

```
E1（复刻成功条件）→ E2（换地图）→ E3（换入口）
```

判据见 `INVESTIGATION_PACKAGES/CODOL-ISSUE-0020/EXPERIMENT.md`。

**这是唯一的关键节点。在它之前没有任何别的事值得做。**

### 第 2 步：让"移动"变成服务端权威

依赖 ISSUE-0025（位置推不动）。但注意：
- 当前的 `omit=1` 配置下，**客户端自己能动**（用户历史上确认过能走）
- 所以"能走两步"其实不需要服务端权威

⇒ **第 2 步对"出现可操控画面"不是必需的。** 它是"服务端能不能控制"的问题。

### 第 3 步：让"看得到东西"

依赖 ISSUE-0024（实体不可见）。
单机靶场里，地图装饰由客户端自己生成，所以**只是"看不到我们发的东西"**，
不影响"能走"。

⇒ **第 3 步对"能走两步"也不是必需的。**

---

## 4. 修正后的最短路径

```
E1/E2/E3  →  第 4 项恢复  →  客户端进图（客户端自己跑物理）  →  ✅ 可操控
```

**只需一个实验序列，就能回到 10-24/25 的状态。**

这一点很重要：**项目距离"能走两步"只差一次成功的连接**。
