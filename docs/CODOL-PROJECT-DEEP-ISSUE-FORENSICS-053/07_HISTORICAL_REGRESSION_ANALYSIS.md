## 2. 回归风险清单

| 改动 | 会破坏什么 | 风险等级 | 缓解 |
|---|---|---|---|
| 改 `mmstart` 处理逻辑 | 若破坏了 `map+gametype` 的识别，PvE 入口也会失效 | **高** | E1 回归 |
| 改 `findSessions` 选图 | 若回错图，B3 复现不了 | **高** | 保留 `coop_map.txt` 自校正 |
| 改 `memberCount` | `dwRoomMatchUber` 会消失，房间线全断 | 中 | 已实测 0→1 有效 |
| 改房间下行格式 | 目前无正向效果，但若改坏可能让客户端断连 | 中 | 每次改后跑一轮 |
| 改快照索引编码 | **会直接破坏 B3**（7 位 vs 4 位的历史事故） | **极高** | 不动 `bw_index` |
| 按参照重写快照 | **已验证会卡住**（`REFENCODER_*`） | **极高** | 不照参照改 |
| 改 idx61 | 2046 → 飞行模式 + 开镜失效 | 高 | 保持 2047 |
| 改 `--map`/clipmap | 会改变服务端碰撞，但当前是常数地面 | 中 | 无正向依赖 |
| 把 `102/7` 改回回显 | 可能引入 5 s 重发 | 低 | 保持不处理 |
| 接线未使用模块 | 可能改变快照内容 | 中 | 需重新验 ack 速率 |

## 5. 回归测试的最低要求（新增建议）

当前 22 个 ctest 全部是离线单测，**没有一个能发现"连不上"这类回归**。

建议新增一个 run 级断言脚本：

```
断言 1：_battle_out.txt 出现 TX_NAT_REPLY
断言 2：出现 KEY_EXCHANGE_OK
断言 3：出现 RX_OOB cmd='getchallenge
断言 4：出现 RX_CLIENT_GAME_HEADER
断言 5：无 REJECT_USERCMD 连续 100 次
```

没有这组断言，"连接是否正常"只能靠人读日志。
