## 2. 三条链的独立性

| | 链 A | 链 B | 链 C |
|---|---|---|---|
| 是否阻塞"可操控画面" | 间接（只影响房间入口） | **直接** | 间接（影响"能否解释现象"） |
| 能否绕开 | ✅ 走 PvE 入口 | ❌ | — |
| 是否可通过服务端修 | 部分（下行格式） | ✅（如果找到自变量） | ❌（取证） |
| 当前最便宜动作 | 无 | **E2/E3 差分** | E9（需 E 转储） |

**关键**：链 A 不通**不等于**链 B 不通。10-26 的 8 轮成功正是绕开链 A 直接打通链 B 的例子。

## 5. 三条链之间不存在"修 A 就解 B"的关系

这是本审计最重要的结论之一：

- 修好链 A（房间可用）**不会**自动让客户端连接——区间 B/C 证明有地图仍失败。
- 修好链 C（能读客户端内存）**不会**自动让客户端连接——它只是让你能**诊断**。
- 只有链 B 的自变量被分离，连接才会恢复。

因此**不要把资源投在链 A 上期待连接恢复**。
